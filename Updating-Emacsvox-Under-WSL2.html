3.4 Updating An Existing WSL2 Installation ¶

The guided installer recompiles the source in the checkout; it does not fetch newer source. Keep the current speaking Emacsvox session open while updating. Run these commands from M-x shell RET in that session or another accessible WSL terminal: 

cd ~/src/emacsvox
git status --short
git branch --show-current
git pull --ff-only
./bin/emacsvox-wsl-install --check
./bin/emacsvox-wsl-install

Replace ~/src/emacsvox if you chose another Linux-filesystem location. Check that this is the intended branch before pulling. The fast-forward-only pull does not create a merge commit. If Git reports local changes, divergence, or another error, stop and review the checkout; do not reset or discard files to complete an update.

Rerunning the installer reuses supported Emacs and verified cached downloads, installs a newly pinned Omnivox release when necessary, rebuilds Emacsvox byte-code from scratch so files from the previous source revision cannot survive, and repeats the launch checks. These operations change files on disk but do not stop the Emacsvox process already providing speech. If the update fails, leave that session running while inspecting the error and named log.

After the installer succeeds and you hear its final check, start a second, isolated process from the updated checkout without closing the old one: 

cd ~/src/emacsvox
./bin/emacsvox

The old session remains the known-good source of speech while you test its replacement. The new process cannot retain Lisp loaded from the previous version. Confirm its ready message and ordinary buffer reading. In the new session, M-x emacsvox-speak-version RET reports the Emacsvox version and M-x tts-speak-version RET reports the live speech-server version. Only after these checks pass should you save work in the old session and exit it.

Continue in the isolated session or start Emacsvox through your normal customised entry point. If the new session does not speak, close it but leave the old session running while inspecting the diagnostic and installer logs.

To update Emacsvox without rerunning the guided installer, replace the two installer commands after git pull --ff-only with: 

make check-emacs
make bytecode-rebuild
./bin/emacsvox --diagnose
./bin/emacsvox --check

All four commands must succeed, and the final check must produce both tone and speech, before the second-session test above. This manual procedure rebuilds Emacsvox but does not download or select a newly pinned Omnivox release. When Omnivox also needs an independent update, follow Manual Release Installation in Installing An Omnivox Windows Release Under WSL2, then repeat the diagnostic and audible check.
