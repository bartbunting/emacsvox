2.4 Updating An Existing WSL2 Installation ¶

The guided installer recompiles the source already present in the Emacsvox checkout, but it does not fetch newer source itself. Keep the current speaking Emacsvox session open while updating. Run the commands from M-x shell RET in that session, or from another accessible WSL terminal: 

cd ~/src/emacsvox
git pull --ff-only
./bin/emacsvox-wsl-install --check
./bin/emacsvox-wsl-install

Replace ~/src/emacsvox if you chose another Linux-filesystem location. The fast-forward-only pull does not create a merge commit. If Git reports local changes, a divergent branch, or another error, stop and review that checkout; do not reset or discard files merely to complete an update.

Rerunning the installer reuses supported Emacs and verified cached downloads, installs a newly pinned Omnivox release when necessary, rebuilds Emacsvox byte-code from scratch so files from the previous source revision cannot survive, and repeats the launch checks. These operations change files on disk but do not stop the Emacsvox process already providing speech. If the update fails, leave that session running while using it to inspect the reported error and the named log file.

After the installer succeeds and you hear its final check, leave the old Emacsvox session open and start a second, isolated process from the updated checkout: 

cd ~/src/emacsvox
./bin/emacsvox

Running both sessions temporarily is deliberate: the old session remains the known-good source of speech while you test the replacement. The new process cannot retain Lisp loaded from the previous version. Confirm that it speaks the ready message and ordinary buffer contents. In the new session, use M-x emacsvox-speak-version RET to hear the Emacsvox version and M-x tts-speak-version RET to hear the live speech-server version. Only after these checks pass should you save work in the old session and exit it. You can then continue in the isolated session or start Emacsvox through your normal customized entry point. If the new session does not speak, close it but leave the old session running while you inspect the diagnostic and installer logs.

For an Emacsvox-only manual update, keep the current session running and replace the two guided-installer commands after git pull --ff-only with: 

make check-emacs
make bytecode-rebuild
./bin/emacsvox --diagnose
./bin/emacsvox --check

All four commands must succeed, and the final check must produce both its tone and speech, before performing the second-session test above. This manual route rebuilds Emacsvox but does not download or select a newly pinned Omnivox release. When Omnivox also needs to be updated independently, follow the Manual Release Installation subsection in Install An Omnivox Windows Release Under WSL2, then repeat the diagnostic and audible check above.
