Review or remove an existing precise changePresentation OverridesIts recorded scope
Try rules only in the current work bufferCurrent Buffer RulesLife of that buffer

6.5.1 Guided Change This Feedback ¶

  1. Move to a representative item, press C-e H, then c. This captures Current item. For feedback that has already happened, use Home’s H, select a Recent Feedback record, and press C. A record containing several parts asks which part to change. Truncated history cannot supply a complete original/proposed comparison.
  2. Press c to choose a component change. Available choices include the content voice, adding a sound or tone, adding a spoken label, replacing an existing sound, changing a tone, or suppressing one component. You can add a cue when the original has none. The choices use the facts and components supplied by the integration; they cannot add missing semantic distinctions.
  3. Press P to hear the proposed change before choosing how long to keep it. O plays the frozen original example; S stops. Proposed preview resolves the selected example with current rules and its captured buffer context. It does not apply your draft to live feedback.
  4. Press m for What should match. Review the actual facts, states, events, and occasion. When available, the object-kind choice omits events and occasion and therefore affects more presentations. These are rules for every matching item, not an edit to one object.
  5. Press l for How long: the source buffer’s lifetime, this Emacs session, or a saved personal rule. A buffer rule affects every matching item in that buffer. Review the spoken summary of target, change, matching criteria, and lifetime.
  6. Press a or C-c C-c to apply or save. e instead opens the prepared rule in the Advanced editor. q hides the guided draft; Home’s Resume unfinished changes brings it back. Aborting a choice or leaving before Apply does not change live rules. Failed saves retain the draft and report failure.

Replacing or suppressing a sound targets its identity in its before- or after-content phase, retaining other components. Existing rule data can insert only at the beginning or end of a phase; replacing a middle component therefore asks which edge to use and includes that placement in the summary. Ambiguous components require the Advanced editor. Current-item changes recheck their captured source before applying; a changed or killed target must be inspected again. Historical changes remain tied to the selected frozen example.

6.5.2 Remap One Item At Point ¶

  1. Move to a representative object and press C-e E so you know what currently controls it.
  2. Press C-e H. Use r to remap its voice or R to remap one exact earcon.
  3. Choose the scope deliberately:
    • a personal override persists across Emacs sessions;
    • a session override lasts until this Emacs exits; and
    • a buffer override affects only the remembered live buffer.
  4. Review the generated rule in the editor. It is initially unwritten. Use the editor’s ? help, preview when offered, and press w only when the target, scope, and change are correct.
  5. Return to the source, repeat the action, and use C-e E again to confirm which rule now wins.

In the rule editor, n and p move between rules. N adds a rule, P previews it, and S stops. These replace the former lowercase Add and Preview keys. Saving announces whether the rule was saved or applied temporarily. q asks before discarding an unfinished draft.

Open Presentation Overrides to manage these changes together. There, P previews the complete current result, t temporarily disables or enables a rule, and d removes it. Disabling or deleting an override restores the next weaker behavior; it does not leave a copied default behind.

6.5.3 Try A Presentation Option ¶

Presentation Options are maintained additions such as richer heading feedback or integration-specific cues. From Aural Home, open Presentation Options:

  1. Use TAB or RET on a collection to expand it.
  2. Move to an option and press P to preview it composed with the current configuration. Press C-u P to preview it in isolation.
  3. Press t to enable or disable it. Press a to hear enabled options in their exact weakest-to-strongest order.
  4. Return to the source and test the original task. Personal, session, and buffer overrides remain stronger than an enabled option.

Avoid reordering options merely to solve one exceptional object. A narrow override usually expresses that intention more clearly.
