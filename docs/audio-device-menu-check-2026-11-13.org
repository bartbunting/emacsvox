* Scope and result

Physical output selection uses Transient under =C-e H o n D/M=. Press =d=,
browse with arrows and press Enter to select a candidate. Apply and Save remain
separate. Main and notification outputs keep their independent device choices,
including the existing refusal to fall back from an unavailable explicit device.

Command-error feedback now uses the notification submission lane without
replacing the real main-process binding. Notification submissions use the
existing guarded notification helper. Repeated Quit messages after notification
failure no longer create abandoned main workers or consume recovery capacity.

Windows listening was accepted on 2026-11-13: switching Left/Right repeatedly
and choosing different physical devices for main and notifications worked well.
The [[*Listening acceptance][listening record]] identifies the tested candidate and scope.
The original notification startup timeout was observed but not reproduced in
the fresh checks. Its cause remains unresolved.

* Observed session

In the native Windows test, the main speech worker kept running when the
notification worker exited with status 1. The guard recorded a creation or
handoff timeout and Windows pipe error 232. Notification dispatch 3 failed
before onset. Each of the next three Quit messages created a main worker whose
reference was lost when the temporary binding unwound. The original main
worker and the three new ones occupied all four native-owner slots. Two
subsequent recovery attempts reported that all slots were still occupied.
