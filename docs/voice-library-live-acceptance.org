* Limits and next work

These checks establish loading, eligibility, process cleanup and control flow.
They do not establish audible acceptance. The complete Emacs Apply interaction
was tested on Linux and WSL-to-Windows; Mac CI covers the native provider and
helpers, not a graphical Mac Emacs session.

A fresh Emacsvox session is required to load the new client interfaces. Import
currently registers validated files at their existing paths. Catalogue-backed
downloads, managed copying and a friendlier validation/import screen remain
separate work. Unknown cleanup or commit outcomes stay blocking and visible;
automated reconciliation and additional crash/power-loss hardening are deferred.

* Local earcon regression follow-up

The initial launcher readiness check missed a playback regression in owned
local workers. Their shared remote-worker flag also selected the remote
restriction on audio file paths. A local earcon therefore rejected its whole
mixed request, including speech. The development session's main and
notification logs confirmed this failure, explaining why plain speech and
tones could work while buffer-boundary announcements disappeared.

Omnivox =9c7692f50581f0a58c52ca7a206e0267a22d801f= gives local children a
separate ownership flag. START admission and EOF cancellation remain shared;
local file access and remote restrictions remain distinct. The permanent
=omnivox-cli/tests/check_local_earcons.py= regression reproduced the failure
before the fix. It passes against the complete Linux and Windows payloads,
including the check that remote workers still reject local file earcons.

* Starting the checked local development session

The maintainer's per-user launcher selection still points to the installed
Omnivox 1.10.0 release. Staging a development runtime does not replace that
selection. On this machine, open the /Emacsvox Development/ Windows desktop
shortcut, or run its per-user wrapper from WSL:

#+begin_src sh
/home/bart/bin/emacsvox-development
#+end_src

The wrapper uses the maintainer's normal Emacsvox profile, selected Emacs 31
toolchain and the verified =2f55382a9dc1125b= native runtime. The wrapper and
desktop shortcut are local installation files, not distributed launchers.

Open =C-e H=, /Speech engines/, an engine's details, then /Installed voice
library/. =e= changes desired enablement; =a= reviews and applies the changes;
=r= shows the result. =b= explicitly includes built-in Flite SLT for a first
library configuration. Applying both providers uses only their enabled
installed entries, so review unavailable voices before confirming an empty
or partial library. This command does not terminate any existing session.
