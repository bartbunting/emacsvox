* Status and intended outcome

The first milestone was authorized on 2026-09-28: shared logical operations for
Agent Shell, Markdown and Org, explicit activation in editable source buffers,
and vertical exits to adjacent prose. The implementation and automated
verification are complete; listening acceptance remains a separate check in
a fresh Emacs.
Later application adapters and their open decisions remain separate work.
The accepted first-milestone contract below takes precedence over the earlier
inventory and candidate choices. It does not change personal settings.

The established Agent Shell baseline is committed:

- =dde32aed0=: link navigation combines the label and action in one utterance,
  filtering the cursor sensor's duplicate notification.
- =1cd130e0a=: Up/Down and Control-Meta-Up/Down speak the complete destination
  table row while retaining the current column.
- =0cbaf5aa5=: the maintained guide and generated manuals describe those changes.

The desired outcome is one learnable set of table-reading operations, consistent
speech, and access to the original document or application. Reading must preserve
document text, editable prompts, and each mode's editing capabilities.

** Markdown

[[file:../lisp/emacsvox-markdown.el][The Markdown integration]] provides table-aware line speech, but no equivalent
of Agent Shell's contextual cell/row/column navigation. Markdown Mode's Tab and
Shift-Tab move between cells; Return moves to the next row. These are editing
operations: they can align a table or create a row.

Emacsvox generally presents the resulting line. Its reading mode removes pipes
and other markup and treats separator rows specially; it does not retain cell
boundaries or announce column titles as a logical table reader would. The
=emacsvox-markdown--speak-table-row= helper currently has no callers. Its simple
pipe splitting is not a suitable parser for escaped pipes, code, or blank cells.

Automatic Markdown reading mode was disabled in the inspected session. The
existing =C-c C-s r= toggle changes speech cleanup, not table-navigation keys or
editing protection.

** Org

[[file:../lisp/emacsvox-org.el][The Org integration]] speaks after native field and row movement. Tab/Shift-Tab
move between fields, Return moves down, and Emacsvox binds Shift-Return to
previous-row movement. Plain Up/Down remain ordinary line movement.

=emacsvox-org-table-after-movement-function= defaults to current-cell speech;
that was also the inspected session's setting. Alternatives speak row headers,
column headers, or headers with the cell. Header commands use the first column
and first row. Empty current cells are called "space", whereas Agent Shell
uses "blank". There is no matching full-row/full-column reading interface here.

Org's table editing, formula, and inspection commands have separate speech
support. Native movement can realign, recalculate, or extend a table. Those
commands should not be reused blindly for non-mutating reading. Meta-Up/Down
are editing commands that can reorder rows.

** Agent Shell

[[file:../lisp/emacsvox-agent-shell.el][The Agent Shell integration]] reads logical cells from rendered-table metadata
and Markdown source. Its contextual map provides full-row vertical navigation,
modified horizontal cell movement, cell/row/column inspection and copying,
position and dimensions, header preferences, and table exit. Logical cells are
read in full even when their display wraps. Entry announces dimensions and the
current cell; vertical movement beyond an embedded table can leave it.

Table navigation is scoped to rendered transcript content. Navigation letters
remain literal input in live prompts and viewport editors, including while the
agent is busy. See the [[file:manual/chapters/agent-shell.org][maintained Agent Shell guide]].

** Other table consumers

- [[file:../lisp/emacsvox-table.el][The existing table model]] and [[file:../lisp/emacsvox-table-ui.el][table browser]] support CSV and extracted data,
  cell navigation, coordinates, headers, searching, copying, and row/column
  filters. Movement normally speaks a cell through a configurable function.
  Left/Right move between cells; =r= and =c= mean header plus cell, not whole
  row and column. The model normally treats the first row/column as headers.
- [[file:../lisp/emacsvox-tabulated-list.el][Tabulated-list support]] binds arrows to cell-oriented movement and =.= to
  current-cell speech. Application-specific maps and presentations may override
  that base behavior. For example, selected-cell navigation is an explicit
  existing requirement in the [[file:aural-interface-consolidation-plan.org][Aural interface delivery contract]].
- [[file:../lisp/emacsvox-eww.el][EWW]] has its own DOM-based cell and row commands on Meta-arrows and can open
  a table in the separate table browser. Its current implementation explicitly
  limits support to plain, non-nested tables; merged-cell handling needs review.
- [[file:../lisp/emacsvox-etable.el][table.el support]] and [[file:../lisp/emacsvox-ses.el][SES spreadsheet support]] are additional adapters to
  inventory before claiming coverage across Emacsvox. Their editing and formula
  semantics must remain available.

** Conflicts that constrain the implementation

| Context | Existing binding | Constraint on the shared reader |
|---------+------------------+---------------------------------|
| Agent Shell transcript | =r= quotes a region upstream; the current table map reads a row. | Preserve the existing table-only override; quoting remains available outside the table and through its named command. |
| Agent Shell viewport | =r/c/a= reply, continue and reply again upstream; the current table map reads a row/column and selects speech settings. | Keep these overrides scoped to tables. Exit restores view actions; the upstream named commands remain available. |
| Agent Shell viewport | =t= selects thought level upstream; Emacsvox already uses =t/T= for transcript table discovery. | Preserve the established override and document =M-x agent-shell-viewport-set-session-thought-level= as the displaced action. |
| Agent Shell transcript | =k= discovers source blocks; inside a table it prefixes copying. | Preserve =k k/k r/k c= and ensure map precedence cannot turn the prefix into block navigation. |
| Editable prompts | Printable navigation keys must insert text, including while busy. | Use the actual editable-input boundary, not only the buffer's read-only flag. |
| Org table | =M-Up/M-Down= move rows; =TAB/RET= invoke native editing-aware commands. | Shared reading must use its own non-mutating movement and restore normal editing immediately on exit. |
| Markdown and Org | =C-M= arrows have inherited structural movement; letters and Space insert text. | Within supported tables, =C-M= arrows enter reading and move. Outside tables, preserve effective bindings. Structural commands remain on =C-M-f/b/u/d=. Character arrows stay character movement. |
| Table browser | =r/c= speak a header plus cell, =T= goes to the top, and =k= copies to its table clipboard. | Defer this adapter's key migration; do not install the Agent Shell map globally. |
| Tabulated lists | Vertical movement presents the selected cell; =.= reads that cell. | Preserve application-specific cell navigation until that adapter's reviewed slice. |

The global table prefix is not mostly empty. Although
[[file:../lisp/emacsvox-keymap.el][emacsvox-keymap.el]] initially adds only =f= and comma, loading
[[file:../lisp/emacsvox-table-ui.el][emacsvox-table-ui.el]] installs the browser's complete map there as well.
It also replaces =f= (find file) with filtered row speech. Reusing =r/c/k/T=
for the new operations would change an existing global interface and introduce
load-order problems. First-milestone proposal: add an unused entry under the
existing prefix, =C-e C-t C-r=, to enter or leave shared table reading, and
unused =[ / ]= entries there for previous/next table discovery. Do not rebind
the existing browser commands as part of this slice. The actual speech prefix
can be customized; the =C-e= spelling describes its default.

Permission buttons retain their supplied action keys and =RET=. Inline links
and fragments retain activation/toggle actions. Transient menus must retain
their own keys while active. The first implementation needs effective-binding
checks for these contexts as well as ordinary table movement; the batch baseline
above does not establish every future map interaction.

** Accepted first-milestone behavior

- Agent Shell keeps automatic contextual table reading and its existing public
  commands and preferences. Editable Markdown/Org enter reading through a
  Control-Meta arrow inside a table or the existing prefix toggle; leaving
  the reading context restores ordinary editing. A first arrow enters and
  moves with one spoken result. Outside tables, arrows retain their effective
  bindings. The maintainer approved this entry policy on 2026-09-28.
- Up/Down and Control-Meta-Up/Down move by logical row, preserve the column and
  read the whole row. Control-Meta-Left/Right move by cell; plain Left/Right
  retain character inspection. Space reads the cell and =r/c= read row/column.
- Vertical boundaries leave an embedded table and speak the adjacent prose,
  matching Agent Shell. Horizontal boundaries stay put and announce the edge.
  A missing cell in a shorter row stays put and reports the missing cell,
  preserving the current Agent Shell behavior. The maintainer approved
  vertical exits on 2026-09-28.
- A separator is structural, not a data row. Distinguish a recognized header
  from data rather than assuming every first row is a title. Keep separate
  header-row announcements, one-based data coordinates, and the common word
  "blank". Initial automatic detection covers a single clearly marked header
  row; complex or explicitly selected headers need their later contract.
- Copy logical plain text: tabs between row cells, newlines between column
  cells. Exact markup and formula copying remain host-mode operations.
- Preserve existing Agent Shell title/data-order choices. Shared defaults for
  new readers do not rewrite Org's native editing-feedback preferences or
  application-specific cell-reading settings.
- Extract shared operations and formatting behind mode-specific recognition,
  source-position and presentation adapters. Retain existing Agent Shell and
  Org Aural roles/facts so personal presentation rules keep matching. Reading
  produces one main-lane submission; adapters do not add transport stops.
- Keep the original document as the navigation surface. Refresh source mapping
  after edits or streamed replacements, and reject unavailable/stale cells
  rather than navigating using invalid positions.

The first milestone retains =C-e C-t C-r= for entry/exit and adds contextual
Control-Meta arrows for entry with movement. It uses
=C-e C-t [ / ]= for discovery, respecting a customized speech prefix. Inside
source-table reading, =q= exits, Tab/Shift-Tab move by cell without editing,
and Return reads the cell. Other native edits end the reading context.
Markdown's markup-stripping speech option remains independent. Other open
decisions remain attached to the adapter or feature they govern.

* Proposed common interaction

These are candidate bindings in an active table-reading context, not changes to
ordinary editing maps. A shared prefix should also make operations available
without taking over printable keys. Emacsvox already has a table prefix under
its speech prefix; audit and extend it rather than assuming it is unused.

| Key | Proposed operation |
|-----+--------------------|
| Up/Down; C-M-Up/Down | Move by logical row, retain the column, read the complete row. |
| Left/Right | Move by character for exact inspection. |
| C-M-Left/Right | Move between columns and read the destination cell. |
| Space | Read the current cell. |
| r / c | Read the whole row / column. |
| . / = | Announce position / dimensions. |
| a | Select header announcements and data/header order. |
| w; k k / k r / k c | Copy the cell; cell / row / column. |
| t / T | Move to the next / previous table in a reading context. |

Skip structural separators, identify blank cells consistently, and retain full
logical content despite display wrapping. Navigation never creates rows,
realigns source, evaluates formulas, or changes document text. Copying should
produce useful cell values without renderer padding or decorative borders.

The proposed activation policy is automatic in suitable read-only views and
explicit in editable Markdown/Org buffers. Do not infer read-only status solely
from =buffer-read-only=: Agent Shell combines a transcript with editable input,
and applications can contain writable fields inside otherwise protected views.
Markdown's existing speech-cleanup reading mode remains independent.

One action should produce one replaceable main-lane announcement, with its cues
and context submitted together. Apply [[file:adr/0009-foreground-and-notification-speech-lanes.org][ADR 0009]]: adapters describe navigation to
Aural policy instead of sending their own transport stop/play sequences.
Suppress duplicate navigation hints narrowly; preserve asynchronous notifications.

* Decisions still to make

Resolve decisions before the implementation slice that depends on them.
Independent inventory and fixtures can proceed without settling every later
adapter. Record selections, rationale, and affected integrations here.

** RESOLVED D1 for the first milestone. Activation and return to editing

Markdown and Org use table-scoped reading, entered with Control-Meta arrows
or the speech table prefix. The speech table prefix
=C-r= and =q= restore normal keys; source edits or movement outside the table
also end reading. Prefix =[ / ]= discover tables from prose, while =t/T= are
contextual inside the reader. Agent Shell keeps its automatic rendered-table
context and existing prompt guards. Future application adapters still require
their own activation review.

** PARTLY RESOLVED D2. Shared keys and compatibility

The accepted first-milestone map is implemented for Agent Shell, Markdown and
Org, including contextual Control-Meta arrow entry in source tables. Their
binding audits and regression checks are complete. The following decisions
apply to the remaining application adapters.

Approve the candidate map after a complete conflict audit. Existing conflicts
include Org Meta-arrows, generic table-browser =r/c/T/k= meanings, tabulated-list
=.=, and the old Left/Right cell commands. Control-Meta arrows also have inherited
structural-navigation bindings outside tables. Decide which legacy bindings stay
as aliases, which need migration, and how displaced commands remain accessible.
Do not silently change global or ordinary editing bindings.

** OPEN D3. Full-row defaults in application tables

The maintainer explicitly requested full-row Up/Down in Agent Shell. Decide
whether that becomes the default everywhere or only within explicit table
reading. Recommended starting point: full-row movement in the shared reader,
while preserving application-specific selected-cell navigation until reviewed.
This includes the Aural editors and applications derived from tabulated-list.

** PARTLY RESOLVED D4. Headers, coordinates, and blanks

The first milestone recognizes a single separator-marked header row, uses
one-based data coordinates, announces empty cells as "blank", and suppresses
duplicate header/value text. Remaining adapters need an explicit policy where
their source supplies no reliable header metadata.

Choose how headers are detected or explicitly selected, including tables without
headers, multiple header rows, row titles, and mid-table separators. Do not
assume every first row is a heading. Decide how header rows contribute to row
numbers and dimensions, whether "blank" becomes the common empty-cell word,
and how duplicate header/value announcements are avoided.

** RESOLVED D5 for the first milestone. Boundaries and irregular tables

Vertical moves beyond a table leave for adjacent prose; if no surrounding
content exists, announce that boundary and stay. Horizontal boundaries and
missing ragged-row cells keep point unchanged. Counts may be zero or negative.
Meta-Up/Down exit only in the reader, preserving Org's ordinary editing keys.
Hidden-row and standalone application-table policies remain future work.

** PARTLY RESOLVED D6. Shared implementation and source positions

~emacsvox-table-reader.el~ now provides common formatting, copying and movement
decisions. Markdown and Org supply fresh source snapshots; Agent Shell retains
its rendered-position adapter. Source edits end explicit reading. The remaining
work is adapting application data and display positions to this boundary.

Choose how much of the existing table model/UI to reuse, extend, or wrap. Its
vector data and first-row/column header assumptions do not by themselves model
live source positions, optional headers, or merged cells. Recommended direction:
shared operations and presentation, with mode-specific adapters for table
recognition, logical values, headers, positions, and capabilities. Reuse the
implemented shared reader when adding the remaining adapters.

Specify source/display mapping, cache invalidation after edits or streamed
updates, and how a stale position is reported. Preserve the existing browser's
filtering/searching features. Prefer navigating in the source; a detached table
view should not become a requirement for reading Markdown or Org.

** PARTLY RESOLVED D7. Preferences and migration

Markdown and Org share title/data-order defaults and buffer-local overrides;
Agent Shell retains its established settings. Browser filters and application
preferences still need a compatibility policy for their own migrations.

Choose shared defaults and per-buffer/mode overrides for headers, data order,
row versus cell feedback, and filtered reading. Map existing Org, Agent Shell,
and table-browser settings without losing explicit user choices. Decide how
existing commands and Aural facts remain compatible during migration; current
integrations have different roles and metadata, not just different strings.

** PARTLY RESOLVED D8. Copying and rich cell content

The first milestone copies logical plain text, uses tabs between row cells and
newlines between column cells, and preserves full wrapped values. Links use
their labels and inline code its literal text. Remaining work concerns other
adapters' rich content and formula values.

Decide whether shared copy commands return displayed text, source markup, or
formula values, and how links and inline code are represented. Recommended
default: logical plain-text values, tabs between copied row cells, and newlines
between copied column cells. Keep exact source/formula copying available through
the host mode. Reading a row must not silently shorten wrapped content.

** OPEN D9. Complex tables and rollout scope

Confirm rollout order and define handling of HTML spans, nested tables, and
spreadsheet-specific cells. Recommended first milestone: Agent Shell, Markdown,
and Org; next the table browser/CSV and tabulated lists, then EWW, table.el, and
SES. Unsupported structures need truthful capability feedback, not invented
coordinates or silent flattening. Do not advertise universal coverage before
each adapter has acceptance evidence.

* Acceptance and verification

- Equivalent simple tables produce matching navigation and speech across the
  first three adapters: full row vertically, one cell horizontally, and no
  duplicate announcements. Cell/row/column inspection and copying also agree.
- Cover headers and no headers, blanks, ragged rows, separators, escaped pipes,
  inline code/links, wrapped cells, multiple tables, and both movement directions.
  Confirm full logical content and the selected column, not only rendered text.
- Check entry, exit, edges, prefix counts, source updates, and stale positions.
  Confirm commands outside a supported table fail clearly without changing text.
- Verify source text and modified state remain unchanged during reading. Reading
  must not add rows, align, recalculate, reorder data, or steal editable prompt
  input. Test ordinary editing immediately after leaving the reading context.
- Exercise effective bindings with mode/minor/overlay/text-property maps, real
  cursor sensors, and both idle and busy Agent Shell prompt editors. Test repeated
  setup/reload and late package loading for duplicate advice or stale maps.
- Use the shared Aural submission path; verify rapid movement replaces old
  navigation speech and does not duplicate cursor hints or suppress unrelated
  notifications. Obtain listening acceptance for clarity and interruption.
- Run affected suites and applicable gates under [[file:../AGENTS.md][the repository workflow]].
  Compile before fresh compiled verification; public-interface or macro changes
  require the prescribed byte-code rebuild. Include real graphical checks for
  wrapping, overlays, and focus, and report skipped checks separately.
- Update generated documentation through the established targets and run
  =make docs-release-check=. This planning document alone does not require Lisp
  compilation or new behavioral tests.
