#+title: ADR 0019: Voice Library and Explicit Activation
#+date: 2026-09-15
#+startup: content

* Status

Accepted on 2026-09-15 with Omnivox ADR 0012.

* Context

The [[file:../engine-management-design.org][engine-management design]] now has working engine details, scoped voice
browsing, typed local runtime paths and external Flite file load switches.
Piper downloads and general per-voice enablement need stable identities and
an enforceable load set before the UI can promise useful memory control.
Main and notification speech run independently and can observe different
configuration unless activation establishes evidence from both.

* Decision

Adopt the authoritative =docs/voice-library-contract.org= in the Omnivox
repository, paired with its ADR 0012. Omnivox owns storage formats, native
validation and the reusable download, installation and storage service.
Downloaded files belong to the user; Omnivox manages their lifecycle.
Emacsvox owns the reviewed catalogue, accessible interaction and coordination
of its main and notification speech processes.

Keep installed, enabled and loaded states separate. New downloads start
disabled; compatible updates preserve enablement. Both lanes use one desired
enabled set, but residency is reported independently. Disabled references
remain in palettes and are unavailable to selectors, fallback and exact
preview. Existing engine disablement continues to override voice eligibility.

Use immutable per-user package revisions and runtime generations outside
executable releases. Imported files remain user-owned. Stable Piper IDs
include the model identity and native speaker index, with explicit adoption
preserving an existing default-speaker ID. Flite retains its native voice IDs.

Offer explicit Apply after showing the voice and restart impact. Preflight
the actual target and companions, retire the invoking session's old pair,
start both lanes on one candidate, and require matching negotiated generation
and eligibility evidence before committing the active pointer. Partial failure
rolls back the pair; failed rollback remains visible. Other Emacs sessions keep
their pinned generations. A manager crash does not silently restart speech.

Existing explicit file settings retain precedence. Show overrides and resolve
those affecting an activation plan before retiring working speech. Keep
legacy startup and older-server discovery usable; feature negotiation governs
the new status request. No model installation or path management is added to
the remote speech socket.

* Consequences and existing decisions

Piper holds at most one resident model per lane; switching models can add
latency. Enabling several speakers sharing a model does not require several
model copies. Confirmed process exit establishes release; byte savings need
measurement. Flite initially applies the load set at helper restart.

Preserve all accepted ADRs 0001–0018: documentation and release policy,
per-user/module ownership, readiness, lane/platform boundaries, palette
ownership, exact preview and per-choice tuning. The first activation provider
is the bundled WSL-to-Windows local launcher; native-direct and remote
management remain separate delivery work. This decision does not approve
catalogue entries, model redistribution, MBROLA dependencies or publication.

* Implementation status

The maintainer accepted the contract and ownership split and authorized
implementation in slices. This acceptance commit changes no runtime behavior
or live session. Implement and verify the contract in small backend and client
commits before exposing downloads.
