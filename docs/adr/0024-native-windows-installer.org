#+TITLE: ADR 0024: Per-user native Windows installer
#+AUTHOR: Emacsvox contributors
#+DATE: 2026-09-20

* Status

Accepted direction following the maintainer's request for an installer that
includes Emacs and Omnivox without requiring administrator privileges.
The offline development bundle is implemented, including a fresh native GUI
check and the maintainer's confirmation of both spoken announcements on
2026-09-20. The second slice adds the Inno Setup development executable.

* Decision

Use Inno Setup for the eventual Windows setup executable, configured for
per-user installation without elevation. Target native Windows x64 first.
WSL installation remains an independent route under ADR 0005; native
support and the Emacs minimum remain as specified by ADRs 0012 and 0014.

Reuse the native PowerShell installer for acquisition, byte-code preparation
and fresh graphical speech checks. Add an explicit =-DownloadEmacs= choice
for the checksum-pinned complete GNU Windows ZIP. Preserve existing explicit
Emacs selections and the opt-in source build. Runtime versions and Omnivox
archive identities remain canonical in =etc/wsl-install.conf=; only the
Windows Emacs artifact identity is added to =etc/windows-install.conf=.

Prepare offline payloads on the build machine. =-Offline= refuses network
acquisition and verifies the required cached archives before installation.
Install Emacs with its bundled libraries and notices, verify its version and
required features, and record the archive identity. No compiler, Git or WSL
is required on the destination machine for the bundled route.

Keep application sources, Emacs and Omnivox in separate versioned directories
under the user's installation root. Keep the profile and logs outside those
directories; downloaded voices remain Omnivox-owned under ADR 0019. Copy
source-only Emacsvox payloads and compile with the selected Windows Emacs.
Never reuse Linux or stale checkout byte-code. Refuse unknown or modified
application trees instead of overwriting them.

The initial development ZIP includes verified archives, source hashes,
the originating commit, an offline PowerShell entry point and a command-file
entry point. Its identity includes uncommitted payload changes. It is explicitly
labelled development and does not invoke or replace the release gates.

** Setup ownership and activation

The development executable has a distinct application identity and installs
with the display name =Emacsvox Windows= and a versioned wizard title.
Its development AppId remains stable for upgrades. Its default directory is
=LocalAppData/Emacsvox/Desktop Dev=. It uses Inno Setup's standard wizard
controls, a Start menu group and an optional desktop shortcut. The finish
page offers a speech test and an optional application launch.

The build machine verifies and expands the offline bundle's pinned runtime
archives. Inno records the resulting explicit file payload for uninstall;
this avoids untracked runtime extraction on the destination machine. The
native installer still validates both runtimes and compiles Emacsvox locally.
The pinned Inno compiler is a build-machine tool, not a user dependency.

Store versioned payload manifests and use them to reject unknown or edited
files before replacement. Repair may restore missing owned files. A stable
launcher reads an atomically replaced active-build record; switch it only
after configuration and byte-code checks complete. Existing versions remain
recorded in Inno's accumulated uninstall log. Do not automatically terminate
Emacs or its speech workers: reject installation or removal while this
installation has running processes.

Configuration completes before replacing the shared launcher and helpers.
The final manifest is an external-file entry whose source callback rejects
configuration errors; Inno catches ordinary =BeforeInstall=/=AfterInstall=
exceptions and would otherwise continue. Exercise actual rollback in native
acceptance tests. Activation runs after installation has committed, so an
activation failure retains the installed files and previous selection,
reports failure in the wizard and process exit code, and allows a later repair.

Uninstall removes only recorded files and explicitly named generated files.
Remove generated directories only when empty. Never recursively delete the
installation root or shared voice directories. By default, retain profile,
logs, user-added files and a small ownership marker so reinstallation can
recognize its destination. Runtime folders added by other installation routes are not
adopted by this installer.

** Personal data and first use

The maintainer approved optional personal-data cleanup and a welcome screen.
Uninstall offers separate, initially unchecked choices for this installation's
Emacs profile (including the welcome preference), its logs and archive cache, and
unused downloads in the shared Omnivox voice library. Silent uninstall keeps
all personal data. Shared Emacsvox settings outside this profile remain
user-owned and are retained. Review sizes before selection, recheck running processes
before removal, refuse linked directories, and report retained data.

Only Omnivox's existing reviewed removal service can delete managed voice
packages. Active generations, other profiles and live sessions remain
protected; imported originals and system voices are never candidates. This
is not a promise to purge all shared voices. Disable and Apply before uninstall
when active downloads are to be removed. No native service/protocol or release
pin changes are needed. Installation-owned logs/cache and profile cleanup use
bounded traversal of those exact directories, never the whole installation.

The setup welcome names the pinned Emacs, Omnivox and Emacsvox versions.
Completion explicitly says installation succeeded, explains Start menu launch
without a desktop shortcut, and describes uninstall. Keep speech testing and
launch as separate finish choices. A focusable summary makes the instructions
available to screen readers. Only this installation needs closing for repair.

Emacsvox also provides a keyboard-accessible welcome buffer on desktop
platforms. Offer it after startup and speech readiness, only before user input
and when no file or other working buffer is open. Automated checks skip it.
Store the show/hide choice as inert data under the current Emacs profile,
independent of application versions. Reopen it through Help or a command.
Use existing speech, voices, output settings, tutorial and manual commands;
announce a short introduction rather than reading the whole screen.

** Continuous integration

Build and test the development installer in the main CI workflow on a native
Windows x64 runner, after isolated packaging fixtures pass on Linux. Cover
installation, shortcuts, running-process refusal, repair, failed-upgrade
rollback and uninstall preservation. Native helper tests cover the optional
cleanup rules. Keep compiler provenance, manifests, checksums and test logs
as CI evidence, including for failed runs. Audio, interactive screen-reader
acceptance and successful second-build upgrades remain separate checks.

Do not upload installer executables or offline bundles until the matching
source-publication work below is complete. CI build evidence is not a release
gate or permission to tag, publish or sign a release.

* Remaining release work

Complete screen-reader acceptance of the wizard and broaden upgrade/failure
testing across clean Windows machines. Default-preservation and optional cleanup need lifecycle coverage alongside
installation and repair.

Before redistributing bundled binaries, assemble and publish the corresponding
Emacs and dependency sources and required notices, alongside Omnivox's source
and notices. Add the installer to the existing clean-source release gates;
the local development bundle does not establish release readiness. Decide
Windows executable signing separately from the Git tag policy in ADR 0006.
