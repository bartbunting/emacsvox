#+title: Voice-style consumer coverage
#+date: 2026-09-09

* Scope and outcome

This maintenance audit follows portable voice settings through editing,
preview, persistence, compilation and speech requests.  It completes the
bounded consumer-coverage backlog item and supplies regression protection for
the [[file:voice-editor-design.org][voice editor]]. Later implementation added the common editor and contextual
inspection described below. These checks do not establish that different physical
engines sound alike.

Two Workbench defects were found and corrected:

- Gain and pan previews divided levels by nine, although tuner and normal
  speech use a piecewise scale with level five exactly neutral at 0.5.
  Workbench now uses the existing effect normalization function.  Independent
  expectations cover nil and levels 0, 4, 5, 6 and 9, including both sides of
  the neutral point.
- A saved custom =bolden= style was resolved by normal speech from the legacy
  personality =voice-bolden=, but Workbench could miss that entry and omit its
  adjustments.  Workbench now uses the compiler's existing palette resolver
  and includes the resolved palette name in its alias display.  Unchanged
  personality aliases retain their existing lookup fallback.

* Boundaries retained

Family selection and engine capabilities remain adapter policy.  A portable
field being valid does not imply support by every engine.  Unsupported
dimensions and old preview protocols remain visible through existing
degradation reporting.

Legacy absolute =:rate= stays loadable but is not applied as a new rate.
Explicit nil over a preset retains its characterized compiler behavior; this
audit does not settle a new inheritance or reset contract.  Nil effect values
remain omitted, and filter amount zero is called neutral, not a guaranteed
hardware bypass.

These checks establish preservation and conversion of requested settings.
They do not measure audible equivalence across DECtalk and Eloquence or test
live device availability. The common save workflow is implemented; optional
tuning for each fallback choice and live spoken acceptance remain pending.

When adding a field, review each boundary above and add independent expected
values or explicit degradation checks.  Keep normalization, UI amount policy
and backend support outside the field metadata table.

* Individual fallback consumer audit

The follow-up [[file:../test/omnivox-choice-consumer-tests.el][ordinary-consumer contracts]] exercise public producers through real
source preparation, rule resolution, compilation and captured final wire. They
substitute adapter command generation and pipe writes; they do not predict which
physical voice will play. Runtime receipt tests cover that separate boundary.

| Consumer | Observed behavior with the negotiated bundle |
|----------+---------------------------------------------|
| =tts-speak= with an owned name or personality alias | Layered span retains logical identity and an empty context; shared and individual values come from the frozen registry. |
| =tts-notify= | Uses the notification lane's registry. An older lane emits version 3 with shared adjustments, including supported relative rate. |
| Contextual rules and spoken before-actions | Full producer path retains sparse overrides, zero and explicit effect default operations. It does not flatten the shared style into context. |
| Word spelling | Uses ordinary preparation. Contextual voices remain layered; the existing capital-letter =animate= cue is layered when that voice is owned. |
| Compound personality list | Version 4 labels the span legacy. Individual tuning is not claimed. |
| Raw =tts-speak-using-voice= queue | Still emits legacy commands. Mixing it with prepared speech makes the whole transaction fall back to the legacy queue. |
| Isolated character review | Still sends =l {B}=, without a layered request or choice receipt. |

The raw queue and isolated-letter tests characterize remaining limitations;
their passing status does not mean those consumers support individual tuning.
The source audit also confirms maintained producers do not directly call
=tts-speak-using-voice= outside =tts-speak.el=; the existing static aural audit
guards that boundary. External callers and compatibility formatting still matter.

The raw command helper queues text without dispatching it. Replacing it with
=tts-speak= would change its contract. The current transaction finalizer can
replace a legacy queue only when all entries are structured-compatible; otherwise
even captured layered runs use the legacy projection. A fix must preserve mixed
command order and whole-submission cancellation, and must not silently claim
that individual adjustments were applied.

Isolated character review has a different server contract: immediate interruption,
character rate, lowercased synthesis and a separate capital pitch cue. These
behaviors are visible in Omnivox's =CommandId::Letter= handling and
=process_letter= pipeline. They are not reproduced merely by sending a one-letter
ordinary text span. No listening or server behavior change was performed here.
