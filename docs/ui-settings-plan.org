* Discovery gaps and design decisions

The current [[file:../lisp/ui/emacsvox-settings-integrations.el][integration catalogue]] covers Shell/comint, Agent Shell, EAT,
Org, Markdown, Info, Notmuch and EWW. Before adding controls, identify an
existing command and its owner, scope and persistence. A useful advanced link
may be enough; a missing suffix does not itself establish missing functionality.

- Gnus and ERC: review discovery for punctuation, large articles, notices,
  room monitoring and participant controls. Vterm and eterm also need a
  contextual-discovery review; preserve native terminal actions.
- Which-key and Hydra: consider routes to their existing speech/help toggles.
  Hydra's help variable is owned upstream, not a new Emacsvox saved default.
- PDF conversion, OCR, media, books and feeds: select useful specialist links
  rather than duplicating application commands in the root settings menu.
- Desktop events and brightness: first inspect service availability and
  timer ownership. Discovery must not start monitoring or change the display.
- Spelling: consider exposing =emacsvox-ispell-max-choices=. Review ownership
  of =emacsvox-flyspell-correct= before changing or removing that selector;
  link package-owned dictionaries and languages. Org SRS is outside this task.

These candidates come from the [[https://github.com/bartbunting/emacsvox/blob/975d382d90f9309f97e61a4c52354b4f5ba49677/docs/ui-settings-plan.org#L3322][integration inventory]] and
[[https://github.com/bartbunting/emacsvox/blob/975d382d90f9309f97e61a4c52354b4f5ba49677/docs/ui-settings-plan.org#L310][discovery audit]]. Items 1–7 of that audit and its later Unicode,
header-line and MIME-limit additions have implementations; do not schedule
those again as discovery gaps.

Other deferred choices need a concrete use case before implementation:

- Extend substring matching to other selection prompts only after deciding
  where configured completion styles and aliases should remain authoritative.
  Finding a row, selecting a voice and running an action have different effects.
- Decide which remaining controls need a dedicated preview or useful scopes;
  keep advanced options in Customize or their specialist editor where suitable.
- Review adjustable duration-coded indentation, dictionary draft/Apply behaviour,
  cross-store Changed settings reconciliation and Muggle context rules as
  separate designs. None is authorised merely by appearing in this plan.
- Retaining question-heading context for expired Agent Shell forms is a known
  interaction gap. Reproduce it and define read-only navigation separately
  from activating a live question; the active-question path is already accepted.
- Parent and sibling tree navigation remain proposals; the existing tree
  reading and settings work does not imply those commands are implemented.

* Keeping this plan useful

Update an entry only when an active milestone, unresolved decision, coverage
gap or acceptance task changes. Give it a concrete next action and a link to
its primary evidence. Keep proposed work, implementation and listening
acceptance distinguishable without maintaining a second commit ledger.

Remove completed entries once their durable outcome is recorded in the issue,
commit, manual or ADR. Do not append routine bug fixes, test logs, process IDs,
sockets, personal paths or live-session reload records. Keep detailed temporary
investigation evidence outside this plan. Git preserves earlier versions.

Use the checks required by [[file:../AGENTS.md][AGENTS.md]] for the actual change. A plan-only update
does not require Lisp compilation, new runtime tests or manual regeneration;
the documentation review gate still applies before review.
