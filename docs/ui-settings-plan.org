* Purpose and status

Living delivery plan for the =ui-experiments= branch, agreed on 2026-10-14.
Extend the Transient proof of concept into a discoverable settings interface
covering everyday feedback, voices, sounds, rules, integrations, and recovery.
Record new settings and interaction findings here as they are discovered.

This is an internal plan. Proposed menu layouts and controls are not claims
that those interfaces already exist. Inventory status describes coverage in
the new interface; many underlying commands and editors already work.

The [[file:developer/ui-experiments.org][UI experiments record]] retains the earlier research and implementation
history. This document owns the forward plan and settings inventory. The Home
menu entry is retired after listening acceptance. The compatibility decision
requires Transient 0.13.3 or newer while keeping the Emacs 30.2 minimum.
Planning an item does not authorize unrelated refactors, dependency changes,
personal configuration changes, or publication.

** Settings discovery source audit, 2026-10-28

Audited =master= at =acd0e9292=. Scanned 385 tracked Lisp files, including
248 literal =defcustom= declarations and interactive commands/minor modes.
Compared candidates with the settings and action catalogues, focused menus,
advanced Customize routes, the table preference indirection, and this plan.
These counts describe the source scan, not a count of missing controls.
Generated switches and ordinary variables need separate ownership checks;
absence of a literal variable name from UI code does not establish a gap.

New findings beyond the earlier Which-key, Hydra, ERC and spelling proposals:

1. Table search selects the wrong control for repeated headings.
   =emacsvox-settings--destinations= labels one result "Table coordinates and
   repeated headings" but targets =c=, the coordinates chooser. Repeated titles
   has its own =r= chooser. Entry detail (=e=) and vertical-edge behaviour (=v=)
   are implemented but lack named search destinations. Split the combined
   result and add specific discovery terms for these existing controls.
2. Notmuch field separators are missing from named search and focused controls.
   =emacsvox-notmuch-search-field-separator= and
   =emacsvox-notmuch-show-field-separator= join the spoken fields. Both are
   already reachable through Advanced Notmuch settings; expose that route
   under useful search terms before considering a dedicated editor.
3. Agent Shell status wording is likewise advanced-only.
   =emacsvox-agent-shell-status-speech-labels= changes speech copies of rendered
   status icons without changing their display. It belongs to the existing
   advanced Agent Shell group but has no named search entry.
4. Agent Shell out-of-turn speech delay is advanced-only.
   =emacsvox-agent-shell-speech-delay= coalesces unsolicited streamed messages.
   It does not control when a normal submitted response is spoken. Any label
   or Help must preserve this distinction.
5. EWW outline selection is absent from settings discovery.
   =emacsvox-eww-shr-outline-toggle= switches between SHR-aware and native
   outline handling; EWW already binds it to =0=. This is an existing session
   command, not a Custom option found through Advanced EWW settings.
6. EWW browser identity has no settings route.
   =emacsvox-eww-masquerade= and =emacsvox-eww-masquerade-as= control a global
   filter on =url-http-user-agent-string=. Their scope extends beyond one
   EWW buffer. These ordinary variables are not exposed by the EWW Custom group.
   Discover the existing switch only with explicit scope and persistence Help.
7. The training explanation voice is not named in settings discovery.
   =emacsvox-aural-training-voice= selects the palette-aware voice used for
   training speech. The training on/off control does not expose that choice.
   A route must distinguish changing this assignment from editing the shared
   named voice itself; generic advanced Customize remains available.
8. PDF conversion settings have no named discovery route.
   =emacsvox-wizards-pdf-to-text-options= defaults to =-layout= and affects
   =emacsvox-wizards-pdf-open=. Link the existing Wizards Custom option as
   specialist configuration; the executable path is a separate ordinary variable.
9. Desktop-event subscriptions lack settings discovery.
   =emacsvox-dbus-udisks-enable/disable= and
   =emacsvox-dbus-upower-enable/disable= control storage/device announcements;
   sleep/resume registration has its own enable/disable commands. These are
   service-dependent runtime registrations, not saved Custom booleans. Inspect
   actual services before proposing controls; do not activate them on discovery.
10. Brightness alerts and automatic blanking lack settings discovery.
    =emacsvox-brightness-alert-toggle= owns a timer, while
    =emacsvox-brightness-autoblack= is a Custom default. The brightness Muggle
    adjusts the display but does not expose these monitoring policies. A route
    must distinguish monitoring from the automatic-blanking choice and require
    the existing platform support.

Additional advanced gaps: Notmuch MIME node/depth inspection limits have an
Advanced Notmuch route but no named search terms. The Unicode advanced editor
lists replacement and name-transformation options but omits
=tts-unicode-untouched-charsets=. The Emacsvox header-line toggle is also
absent from discovery; it changes the current buffer's header and needs clear
scope. These are lower-priority candidates, not automatic new root-menu items.

False positives removed: common table variables are reached indirectly through
=emacsvox-table-reader--options=, and several voice/backend options have existing
specialist editors. Generic Customize coverage is not the same as a named search
result. Org SRS remains outside the previously accepted spelling scope.

Proposed first slice: correct table search destinations and make the existing
Agent Shell and Notmuch advanced options discoverable by name. No runtime code,
bindings, defaults, or live sessions changed during this audit. Source inspection
does not establish listening acceptance or native-service availability.

no terminal input; no hooks, advice or timers are installed.

Investigation only: no implementation or live configuration changed.
The exact failing key and whether the reported prompt is current or historical
remain to be confirmed. A possible fix is to relax the field boundary only
for explicit word navigation in Eat line mode, preserving editing and deletion
protection. That behaviour is proposed, not implemented or accepted.

* Interaction contract

Use focused Transient menus for actions and repeated adjustments. Use
searchable, sortable lists for inventories such as voices, palettes, rules,
and sound packs. Use expandable Outline details for explanations, inheritance,
effective settings, and diagnostic evidence.

- Up/down selects items. Plain left/right changes menu sections.
- Shift-left/right adjusts a selected numeric control. Enter activates a
  choice or edits an exact value. Announce bounds and unavailable controls.
- Announce menu and section names on entry or section changes. Repeated
  adjustments speak the new value promptly and replace obsolete feedback.
- Show effective values, available choices, scope, and where a value comes
  from: a buffer override, mode policy, global default, palette, or engine.
- Offer only scopes the underlying setting supports. Explain when a global
  operation also changes the originating buffer.
- Make saving, applying, selecting a palette, and restarting speech distinct
  actions. Menu entry and preview must not silently persist changes.
- Provide representative previews and a reliable stop action. Audit existing
  keys before assigning preview, stop, or save keys in another interface.
- Return to the originating menu or list with its selection, filters, source
  context, and draft intact. Preserve existing editor decisions about keeping
  or discarding unsaved work. Whole-stack exit remains available.
- Validate the captured source item before contextual edits. Handle changed
  text, closed buffers, unavailable voices, and missing capabilities clearly.
- Explain what Reset restores: an inherited value, a mode policy, a standard
  value, or an engine default.

***** Accepted enable, disable and save contract

Accepted on 2026-10-18. Disabled means no managed entry keys or deferred
activation, while deliberate =M-x= use of an existing command remains possible.
This follows ordinary Emacs command/minor-mode separation and preserves public
entry commands. It is not a security or package-unloading switch. Direct
command invocation is deliberately retained.

Enable changes the requested session state. When dependencies and context are
usable, it activates only that entry's managed bindings; it never enters the
menu or performs its commands. Missing dependencies leave the request visible
with an explanation and install nothing. Disabling withdraws owned bindings
and closes that entry's active menu through its normal exit path. Commands
already completed, text edits, playback, folding and intentional option changes
remain. Enabling again does not rerun any previously invoked action.

Use owned minor-mode maps where practical. Keep registration separate from
loading a module or enabling bindings. Any necessary direct-map installation
records the previous binding and restores it only if the current binding is
still ours. Deferred callbacks recheck current requested state before acting.
Repeated enable/disable is harmless. Package loading and major-mode changes
must not revive an explicitly disabled entry.

An enabled entry can be available by =M-x= while an entry key is blocked by a
conflict. Report the actual conflicting command. Do not overwrite it, create
an incompatible prefix, invent another key, or present the binding as active.
Known legacy replacements such as yank and Info need explicit adoption with
their displaced action explained. Package-specific maps, including Agent Shell
prompt and viewport maps, require their own effective-binding checks before
installing keys in those contexts.

Treat current requested state, runtime availability and persisted startup
preferences as separate information. The list should show, for example,
"Enabled here, not saved; key blocked by my/org-navigation/body" or
"Disabled; saved enabled". It must distinguish missing dependencies,
unsupported context and binding conflicts. Opening the list, selecting a row
and asking for Help change nothing. Enable and Disable take effect for the
session; explicit Save persists the choices through Customize. No separate
Muggles data store is needed. Context rules and arbitrary predicates remain
deferred.

***** Proposed defaults and compatibility migration

New installations enable no Muggles implicitly. Keep both public collection
features and current command names. An explicit load of a legacy collection
continues to request its historical members, but an explicit per-entry saved
or session Disabled choice takes precedence. Model preferences as per-entry
overrides so absence and explicit Disabled are different; an empty list cannot
ambiguously mean both "use legacy defaults" and "disable all".

Convert collection members incrementally. When an entry is extracted, its old
location delegates definition and activation to the managed module rather than
defining it twice. Unconverted members remain visibly legacy-managed and retain
their existing implementation; do not imply they already have working switches.
The new browser may list all 19 records, but only converted entries offer
Enable/Disable. Loading the browser must not load either collection.

For converted entries, collision protection takes precedence over historical
last-loader-wins binding replacement. This is a deliberate proposed migration
change, not unchanged behavior. Document it, show the conflict, and offer the
existing =M-x= command. Do not automatically edit personal configuration or
write Customize merely because a collection was loaded. An explicit Adopt
action for displacing known bindings belongs in a later migration slice if
needed; the pilot can leave conflicting keys blocked.

**** Problem and existing controls
