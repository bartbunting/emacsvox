* Findings and changes

Experimental structured questions previously arrived without semantic speech;
moving through their controls did not announce selections or required status.
The integration now announces question requests, control values and states,
edits, previews, submission, decline, and cancellation. Shell and viewport
navigation resolve values from the owning session. Automatic feedback follows
the session speech level; explicit actions still speak in quiet mode. A blocked
prompt distinguishes a question from a permission request. The upstream
experimental feature remains disabled by default.

Configuration reads use the public getter and readiness API when available.
The 0.85.3 fallback checks the initialization pipeline rather than treating the
initial handshake as completed setup. Startup defaults stay quiet and later
setting changes receive one confirmation. Compatibility branches predating
0.85.3 were removed where the supported API now suffices.

The upstream binding comparison covered shell, viewport view and edit maps,
Shell Maker inheritance, permission and question controls, inline actions,
transients, and Emacsvox navigation, speech, table, and repeat maps. Existing
upstream bindings were unchanged; new question maps introduce no additional
Emacsvox override. Effective-binding tests cover transcript and table use,
viewport navigation, and literal input while idle and busy.

Upstream queue-loss confirmation and fork/resume behavior passed targeted
checks. Declining a buffer-kill confirmation preserves the buffer and queue;
a failed fork load retains the fork and reports failure. No additional runtime
changes were needed for these flows.

The maintained manual, developer guide, NEWS, and generated references were
updated. Regenerating the aural reference also restored the missing entry for
the already-registered =command-terminal-bell= cue.
