#+title: Native Emacs UI Experiments
#+date: 2026-10-14
#+startup: content

* Status and purpose

The Transient settings workflows have passed listening acceptance. The
=C-e H h= fallback is retired under
[[file:../adr/0027-transient-settings-entry.org][ADR 0027]]. Transient 0.13.3 or newer is required; Emacs 30.2 needs a
separately installed package because its bundled version is too old.
Dedicated editors and =M-x emacsvox-aural= remain available.

The sections below preserve the prototype's research and implementation history.
Earlier Home routes and open listening checks describe those checkpoints; the
[[file:../ui-settings-plan.org][living settings plan]] owns current status and remaining work.

The original proposal for the =ui-experiments= branch was to replace
the =C-e H= Aural Home menu with a Transient. The first implementation adds
the linked indentation path, Feedback for this item, and a route to the
existing Home. The tuning prototype now uses Shift-left/right to adjust
indentation tone volume. Sounds and output adds the five existing global
volume controls and the sound-pack browser. Speech settings now includes
rate, punctuation, and explicit default saving. The remaining action coverage
and broader settings work are tracked in the
[[file:../ui-settings-plan.org][living settings and voice interface plan]].

The aim is to make settings and actions easier to discover through familiar
Emacs interactions, with concise speech and direct shortcuts. Feedback from
this experiment will determine whether more Emacsvox interfaces should use
Transient.

* First target: C-e H

Use Transient for the top-level menu itself. Group related actions and use
submenus where they make the choices easier to understand. Support navigation
through the menu as well as direct shortcut keys.

Build the interface from linked Transients. For example, =C-e H= opens the
main menu, /Speech settings/ opens a focused Transient, and its /Indentation/
entry opens the existing indentation Transient. Keep =C-e d I= as a direct
route to that same menu. Each focused menu can also be opened independently;
reuse it wherever the same settings are relevant.

Keep the originating buffer and applicable settings scope through these
transitions. Provide predictable navigation back to the parent menu and a
way to leave the menu sequence. Verify that returning to a parent refreshes
its displayed values. Exact grouping and keys remain part of the experiment.

Start by mapping the actions in
[[file:../../lisp/emacsvox-aural-home.el][Aural Home]] to the proposed menu. These include voices and engines,
speech settings, feedback inspection and changes, presentation profiles,
sound packs, and diagnostics. Reuse the existing commands and preserve their
source-buffer and source-item context.

The first prototype should rebind =C-e H= on this branch while opening
existing editors and review buffers. Keep the current Aural Home available
through =M-x emacsvox-aural= during testing. Its implementation and the =h=
return command in existing editors remain available for comparison. Keep
ordinary commands available through =M-x=.

* Settings and tuning

- Show current values and selected choices in menu descriptions.
- Use toggles and selectors for suitable settings. Obtain dynamic choices,
  such as available voices, from the existing data sources.
- Keep tuning menus open while values are adjusted and previewed. Up/down
  selects controls, plain left/right changes sections, and Shift-left/right
  adjusts values. Check shared changes with Magit as well as Emacsvox menus.
- Provide clear speech for the selected control, changed value, and preview.
  Test rapid changes so stale previews do not obscure the current value.
- Make local and global scope explicit where the underlying setting supports
  both. The indentation menu is the starting example, not a requirement to
  add both scopes to every setting.
- Use Customize to save settings that are Emacs options. Preserve existing
  save, apply, and draft behaviour for voices, profiles, and other managed
  data; opening a menu must not silently save changes.

* Implementation steps

1. Inventory the current menu actions, shortcuts, context requirements, and
   persistence behaviour. Read all accepted ADRs before implementation.
2. Propose a compact top-level Transient and map every existing action to an
   entry or submenu. Identify shortcut conflicts and changes explicitly.
3. Implement the entry menu and a Speech settings submenu using the existing
   Transient speech support. Link the existing indentation menu from it.
   Verify direct entry, parent navigation, refreshed values, and commands
   acting on the originating buffer or item.
4. Prototype one focused tuning interaction, then evaluate its navigation,
   previews, scope, and saving before extending the pattern.
5. Compare the prototype with the current interface and gather feedback.
   Record accepted architectural decisions in an ADR and document adopted
   behaviour in the user manual.

* Evaluation and open questions

Can you find an unfamiliar action without knowing its shortcut? Can you use
known shortcuts quickly? Are the current value, scope, and effect of saving
clear? Does speech make menu navigation and repeated adjustments easy to
follow? Does closing or reopening a menu preserve the expected source context?

Check keyboard operation and speech in a real graphical Emacs, including
entering and leaving submenus, changed or unavailable dynamic choices, and
returning to the source buffer. Automated checks should cover context,
settings, and key behaviour; listening feedback is also needed.

Ask whether people like this style of interaction, whether it feels natural
in Emacs, and which other interfaces would benefit. The exact grouping,
shortcuts, adjustment keys, and next tuning target remain open.

Org or outline buffers remain a separate possibility for detailed feedback
and other structured information. They are not the proposed replacement for
the =C-e H= menu in this experiment.

** Linked menus and source context

Transient supports calling a prefix command from another prefix and retaining
the parent on a stack. In the tested versions, =q= bound to
=transient-quit-one= returns from Indentation to Speech settings; =C-g= also
quits one level, and =C-q= closes the whole stack. A normal action can exit
the entire sequence or return to its parent according to its definition.
Use explicit behaviour for actions that open editors so a restored parent
menu does not unexpectedly cover the editor.

See the upstream [[https://docs.magit.vc/transient/Transient-State.html][Transient state]] and
[[https://docs.magit.vc/transient/Defining-Transients.html][prefix definition]] documentation. Dynamic descriptions refreshed correctly
when returning from Indentation to its parent in the graphical probe.

Scope is not inherited automatically. A parent opened with a global flag did
not pass it to the child. Transient's =scope= slot carries application data;
it does not itself mean buffer-local or global settings. Pass the source
context and any applicable settings scope deliberately. The existing
indentation menu stores a source buffer and global flag in its own scope.

[[file:../../lisp/emacsvox-aural-inspection.el][Inspection context]] also includes a marker and a guard for the captured
source item. Merely calling Home helpers from the ordinary source buffer
would use its current point instead of the captured location. The prototype
needs an adapter that preserves the marker and guard, rejects a dead or
changed source, and passes that context to existing editors. Do not rely on
the last globally remembered source when navigating nested menus.

** Navigation and speech

The existing [[file:../../lisp/emacsvox-transient.el][Transient integration]] uses up/down for choices, left/right for
sections, and =C-j= to activate. It forces a single column and announces
menu openings, values, unavailable choices, section changes, and shortcuts.
It already distinguishes redisplay from a newly opened menu.

Two disposable graphical prototypes worked:

1. Existing navigation with =+= and =-= for repeated tone-volume changes.
2. Up/down selects a control; left/right adjusts the selected numeric value;
   =M-n= and =M-p= move between sections. Non-adjustable choices give a short
   explanation instead of changing a value.

The second prototype changed only temporary maps in an isolated Emacs. It
shows feasibility, not an accepted binding design. A shared implementation
should identify adjustable controls explicitly, including their step, bounds,
setter, and preview operation. Update the spoken navigation hint to match
the chosen bindings. Decide whether ordinary command menus keep section
arrows or adopt another consistent convention, then check real Magit menus.

Both prototypes refreshed values and emitted one captured value announcement
per adjustment. This does not establish audible preview timing or cancellation
under rapid changes. Those need a listening trial with the actual speech
backend before selecting the interaction.

** Persistence and preview boundaries

| Control | Existing behaviour to preserve |
|---------+--------------------------------|
| Indentation | Immediate local changes or global defaults; explicit Customize save for defaults and tone volume. |
| Output volumes | Global Customize options with setters that update the appropriate live speech process. |
| Speech rate | Existing command requires a live speaker; prefix changes the default and current local value. |
| Preferred engine | Global session preference; prefix explicitly saves in the active routing profile. |
| Named voice tuning | Existing editor owns drafts, private previews, and palette saving. |
| Presentation profiles | Existing manager distinguishes current values, saved snapshots, and explicit restore/write actions. |
| Punctuation and engine settings | Existing editors retain their own saving, apply, and restart rules. |

Transient's own Save command saves its argument values; it is not a generic
Customize save for Emacsvox settings. Use clearly labelled application save
commands and do not promise one save operation for all these data types.
Likewise, a prefix argument does not mean global scope for every existing
command: for the preferred engine it means save.

Keep voice-preview and storage contracts in
[[file:../adr/0016-complete-voice-preview.org][ADR 0016]], [[file:../adr/0017-per-fallback-voice-tuning.org][ADR 0017]], and
[[file:../adr/0018-unified-voice-palette-model.org][ADR 0018]]. Native parameter bounds and choices come from the engine catalogue
under [[file:../adr/0022-engine-described-voice-parameters.org][ADR 0022]]. A new menu must not turn a private draft preview into an
implicit live voice change.

** Recommended first implementation

Rebind =C-e H= to an experimental prefix on this branch, retaining
=M-x emacsvox-aural=. Add Speech settings with a link to the existing
Indentation menu and keep =C-e d I= working directly. Add Feedback for this
item as the first source-sensitive action, preserving its marker and guard.
Keep an obvious route to the existing Home for the remaining actions.

Use that small path to compare the two adjustment styles through speech.
Then extend the menu coverage table incrementally. No runtime bindings,
shared Transient support, or live settings changed during this research.

* First implementation: linked entry menus

=C-e H= now invokes =emacsvox-aural-menu=. Its first three destinations are
=s= Speech settings, =x= Feedback for this item, and =h= Aural Home with all
existing actions. =C-e H s i= opens the existing Indentation Transient;
=C-e d I= still opens it directly. =M-x emacsvox-aural-menu-speech= also opens
Speech settings directly. =M-x emacsvox-aural= retains the original Home.

The entry and speech menus share their source context and settings scope.
=C-u C-e H= starts with global defaults. =g= in Speech settings or Indentation
changes the shared scope without modifying values. Returning to a parent
refreshes its labels. =q= or =C-g= returns one level; =C-q= closes the stack.
The existing +/- volume controls and section-navigation arrows are retained
for this first comparison. Alternative arrow tuning is still a separate step.
Volume adjustments speak just the percentage. Their submissions replace
pending main speech and interrupt current main speech, so rapid adjustments
do not queue announcements of obsolete values. The menu retains the full
control description for navigation.

Contextual actions validate the captured marker and source-item guard, run
at that location, and restore the source cursor and narrowing. Feedback
Details owns a return continuation that restores the menu over its live
source buffer, retaining the captured item and settings scope. Reopening
the report directly clears this continuation. Its existing draft, preview,
and saving behaviour is unchanged. Transient Help keeps its native return
path; its temporary suspension does not open the Emacsvox menu browser.
The menu delegates its complete fallback to Aural Home; existing editors'
=h= commands continue returning there.

The new code is [[file:../../lisp/emacsvox-aural-menu.el][emacsvox-aural-menu.el]], with
[[file:../../test/emacsvox-aural-menu-tests.el][context and graphical regression tests]]. The indentation setup helper
allows linked parents to share its source/scope pair. No global Transient
bindings or personal settings are changed by loading the prototype.

All Transient feedback now uses replaceable, interruptible main-lane
submissions, including scope toggles and other state changes. The shared
policy also handles cue-only feedback. Item announcements retain their key
without the repeated word "shortcut" or the section name. Section names
are spoken when navigation enters a section. Volume adjustments retain
their concise percentage announcement.

Verification used Emacs 31.0.90. All 67 menu, indentation, Transient, and
keymap tests passed in fresh graphical sessions with both bundled Transient
0.13.3 and installed Transient 20261001.1359. The menu and indentation code
used current byte-code. Core checks passed 971 tests, with 17 graphical or
native-service tests skipped in batch. The wider focused suite passed 236
tests and skipped ten graphical tests; its disabled-rule inventory test
failed identically in a clean archive of the starting commit. That existing
failure remains outside this experiment. Header, byte-code, and documentation
checks passed. Live listening remains to be checked; graphical tests capture
speech submissions rather than playing audio.

* Focused tuning: shifted arrows

The Indentation menu retains up/down item navigation and left/right section
navigation. Shift-left/right adjusts the selected Volume control by five
percentage points within 0 to 100. Other items give brief guidance without
changing their values. Enter edits Volume directly; Space previews the current
indentation settings. Existing +/- shortcuts remain available for comparison.

Temporary menu maps override shifted-arrow movement only in menus with
adjustable controls. Numeric input prompts and the source buffer keep their
normal bindings. Speech settings adjusts rate; Indentation and Sounds and
output adjust volume. Third-party Transients retain their existing maps.

Volume remains global in either settings scope. Adjustments use the existing
Customize setter and replaceable main-lane percentage announcement. Saving
remains explicit; opening, adjusting, previewing, and closing the menu do not
write personal settings files. Listening checks accepted the shifted-arrow
adjustment and Sounds and output interactions on 2026-10-14.

* Sounds and output

=C-e H o= opens the five global output volume controls. Shift-left/right
adjusts the selected control by five percentage points; Enter reads an exact
value and restores focus to that control. Existing Customize setters apply
the change to the appropriate output. =S= explicitly saves all five volumes.

=p= suspends the menu stack and opens the existing sound-pack browser. Its
=q= restores Sounds and output with Browse sound packs selected. The next
=q= returns to the main menu with its captured source and scope. A one-shot
buffer-local continuation owns the suspended stack; opening the browser
directly clears that continuation and retains ordinary dismissal behaviour.

The focused menu, shared interface, and sound-pack checks passed 39 tests
with compiled code in fresh graphical Emacs sessions using bundled and
installed Transient. Listening confirmed the browser return path.

* Speech rate and punctuation

Speech settings applies rate through the existing live speech setter, using
the selected buffer/global scope and configured step. Omnivox adjustments
are bounded to 0 through 100. Exact input restores focus to the selected
control. Punctuation exposes built-in levels, negotiated named profiles, and
reset to the automatic buffer policy. Scope remains shared with parent menus.

Explicit Save persists the displayed rate through the selected adapter's
startup option and punctuation through Customize. Saving punctuation alone
leaves the saved rate unchanged. Mode policies and buffer overrides retain
their precedence. Opening, adjusting, and closing menus do not save defaults.

Twenty-five focused checks passed with compiled code in fresh graphical
Emacs using bundled and installed Transient. A separate Emacs startup loaded
the saved rate and named punctuation profile before adapter setup and verified
that both survived initialization. These checks capture speech and do not
establish listening acceptance in a normal profile.

* Voice browsing and shared tuning

=C-e H v= links the existing engine/voice browser, palette manager, and Voice
Workbench. Browser exits restore the suspended menu and focused suffix after
unwinding child views. Direct entry clears the menu continuation. Shared
interface dismissal preserves staged-policy warnings even when the return
continuation announces the destination. Engine preference has separate
session, save, and restore actions, independent of the speech-settings scope.

The named-voice editor's =m= command opens a focused shared-tuning menu.
[[file:../../lisp/emacsvox-aural-voice-menu.el][emacsvox-aural-voice-menu.el]] owns menu focus and concise adjustment feedback;
the common editor still owns the draft, private preview, comparison, and save
coordinator. Every operation checks the captured editor and context identity
and rejects a changed fallback or engine-controls scope. Relative rate, pitch,
pitch range, and gain use the existing field metadata and validation.

Shifted arrows adjust and Enter reads an exact value. Plain arrows retain
section navigation. Pure label reads leave menu rendering untouched; actions
preserve the editor field and restore popup focus after minibuffer prompts.
The menu suppresses automatic samples only during its own adjustment, then
restores the editor preference. Explicit preview and comparison use the same
private paths and sample text as the editor. Leaving the menu stops its owned
sample, removes the temporary exit hook, and retains the draft.

The browser and shared-interface checks passed 51 tests; the tuner and editor
checks passed 57 tests. Both sets used current compiled code in fresh graphical
Emacs 31.0.90 with bundled and installed Transient. They cover return paths,
retained filters and drafts, explicit saving, adjustment bounds, cancelled
input, changed-scope rejection, comparison, and preview stopping. Browser
interaction was accepted on 2026-10-14. The automated tuner checks capture
speech and preview requests; a complete listening and restart task remains
open in the [[file:../ui-settings-plan.org][living plan]].
