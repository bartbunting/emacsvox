* Ordered capture and complete compatibility output

** Capture source intent, not an early transport decision

Add an ordered private capture journal to the existing delivery transaction.
Journal records identify their exact original command range and contain one of:

- a concrete run contribution, with its existing raw request and provenance;
- an inspectable named queue contribution, with the unevaluated name, copied
  text and its original compatibility commands;
- a trusted state/sync command, with its actual command and typed state value;
- an ordinary producer's end-of-speech dispatch intent; or
- an explicit low-level dispatch or opaque command at its original position.

The original command entries remain the compatibility representation. Do not
duplicate their strings or retain text in process-wide proof records. A journal
may use indices or object references to connect commands and runs; it must not
reconstruct their ordering from two independent unpositioned lists.

Bound added journal records by the existing timeline span/action limits plus
the 128-owner limit, and added retained text/request metadata by 16 MiB per
capture. Reuse references to already owned immutable data rather than copying
the compatibility queue again. Check additions before retaining them; exhaustion
is a preparation failure, never a reason to select legacy output.

Record an ordinary dispatch intent when =tts--speak-transaction= finishes its
speech preparation, regardless of the current value of
=emacsvox-aural-structured-delivery-pending-p=. The intent captures callback
identity and whether the producer requests plain, tracked or marked delivery.
Only finalization decides whether that intent becomes a timeline or a legacy
dispatch. A later opaque command cannot erase it.

An explicit =tts--protocol-dispatch*= call is a hard boundary. Calls made to
implement an ordinary producer's recorded intent use an explicit private origin
tag; they must not be mistaken for an external explicit flush.

Queue-only calls do not acquire a dispatch intent. In particular,
=tts-speak-using-voice= keeps its signature, queue-only behavior, inaudible and
empty-text handling. Preserve its original compatibility code/text/reset output
when no promotion is selected. Do not implement it by invoking =tts-speak=.

Retain the existing implicit finalization for a pure concrete-plan transaction
whose caller relies on it. Do not infer a legacy dispatch for a bare concrete
queue call that never requested one merely because another entry later makes
that transaction incompatible. The lost-dispatch repair restores recorded
producer intent; it does not redefine every queue function as a speak function.

** Select one representation for the whole capture

Emit at most one structured document from this finalizer. Promote only when:

1. Every speech contribution is represented by concrete runs or an inspectable
   owned name, and every accompanying command is a trusted representable entry.
2. The complete capture has one effective closing dispatch and no queued tail.
   Adjacent callback-free ordinary contributions may retain existing coalescing
   when no low-level queue/control boundary intervenes and sync values agree.
3. There is at most one callback owner. A final explicit dispatch can close a
   queue-only prefix; an explicit dispatch followed by more speech remains a
   boundary and prevents whole-capture promotion.
4. All sync values that would move before the document are identical. Differing
   rate, punctuation, split-caps or capitalization state retains legacy order.
5. Additional promotion of named queue entries passes the queue proof below
   and the lane has the complete acknowledged choice-tuning bundle.

Otherwise render the original compatibility entries, restoring each recorded
ordinary dispatch at its position and preserving every explicit dispatch.
Do not append one final =d= as a general repair: that would also speak an
unsealed queue-only tail. Do not coalesce dispatches merely because their
callbacks or voice values compare equal.

Multiple explicit flushes, opaque commands, unsealed tails and state transitions
therefore retain compatibility output in A. This is deliberate: splitting them
into several replaceable timelines under the same key could cancel an earlier
part of the same submission. The current =emacsvox_tx= grammar also rejects
nested timelines and tracked/marked commands. Do not bypass those constraints.
Validate the selected compatibility framing as well as the timeline framing
before policy interruption. An unsupported command cannot be hidden in an
=emacsvox_tx= frame. Use an unframed packet only where the selected delivery
policy permits it; otherwise report an admission failure. Do not add a Stop,
drop callback ownership, or silently change delivery policy to make it fit.

Examples, with Q a named queue-only call, N ordinary speech, D an explicit flush:

| Input | Required outcome |
|-------+------------------|
| Q only | Queue only; no dispatch or timeline. |
| Q, N | One layered timeline when the full proof succeeds. |
| Q, D | One layered timeline when the full proof succeeds; D remains the closing flush. |
| N, N with equal state and no callbacks | One ordinary timeline, as today. |
| N, Q | Legacy N then its dispatch, followed by queued Q; Q is not spoken early. |
| N, Q, D | Legacy N/dispatch then Q/D; the low-level queue boundary is retained. |
| Q, D, N | Legacy Q/D then N/dispatch; preserve both flushes. |
| N, opaque code | Legacy N/dispatch followed by the opaque code. |
| N at rate 100, N at rate 200 | Preserve both sync/dispatch pairs; do not apply the last rate to both. |

* Named voice projection

Before evaluating a personality variable or generating inline commands, retain
the supplied symbol and resolve it with the existing owned palette compiler.
Only a single inspectable owned name or alias is eligible. Compound personalities,
unresolved names and opaque definitions retain compatibility output.

A direct named queue call supplies no new contextual rule application. Its
layered context is empty; its shared definition and choices come from the frozen
acknowledged registry. Existing concrete runs retain their original sparse
context and provenance. Never flatten an effective style into the new context,
infer it by comparing numbers, or silently run text preprocessing/rules again.

Build the timeline with the existing compiler, span projection and effect-mode
boundary rules. The name resolved by compilation must identify an acknowledged
layered definition in the same palette/registration snapshot. A pending or changed
registration remains an admission error; it is not an old-server fallback.

The compatibility alternative retains the old helper's actual commands. It is
not a new guarantee that arbitrary old personality commands implement every
saved palette field. Normal concrete speech on older servers continues to use
its existing shared-style projection. Both limitations exclude individual tuning.

* Bounded knowledge of the server's legacy pending queue

** Scope and state

The new proof gates only promotion that replaces named legacy queue entries.
Already-structured ordinary speech retains its existing independent admission;
it does not become an implicit flush of an older server pending queue.

Keep one constant-size record per managed speech process: record identity,
process generation, local/remote mode, queue state (=empty=, =pending= or
=unknown=), framing (=boundary= or =unproven=), a sticky unusable flag, mutation
serial and one outer-write identity/overlap flag. Absence, malformed state,
a changed generation, partial writes or retirement mean unknown. Require both
empty and a usable input boundary for promotion. Do not retain queued text,
decoder tails, historical registries or a list of earlier submissions.

Initialize empty only for a freshly owned local server or authenticated fresh
remote worker, with observation installed before speech writes are exposed.
Attaching to an existing process starts unknown. Capability/registry replies,
playback completion and a new client capture do not establish queue emptiness.

** Observe actual writes

The [[file:voice-editor-queue-proof-review.org][completed boundary refinement]] specifies the precise transitions, effect
composition, coding/reader limits, observer coverage and birth handoff. It refines
this section: queue uncertainty and unfinished input are different facts. A typed
clear is effective only when it starts at a proven command boundary. Otherwise
its first line can restore local framing while leaving the queue unknown.

Use a small private observer at =process-send-string= for managed speech
processes, plus invalidators for =process-send-region= and =process-send-eof=.
Use a private typed writer for TTS, aural delivery, Omnivox control/state output
and remote auth/heartbeat output. Resolve alternate primitive process arguments
and verify coverage nearest the primitive. Other processes are untouched. Do not
derive queue effects by parsing arbitrary command strings or install a Lisp
interpreter for inline engine codes.

A trusted write carries an exact process/string identity, checked content
fingerprint and a one-use effect token. Consume that token before forwarding to
the primitive; nested writes must not inherit its classification. The observer
records uncertainty before I/O, commits the declared effect only after a complete return, and retains
unknown/unproven on error, quit, throw or any same-process overlapping write.
Keep observer bookkeeping short, without user callbacks, speech or blocking work
of its own.

Direct unclassified writes invalidate the proof. Known control-envelope requests
and authenticated remote heartbeats can be marked queue-neutral by their actual
constructors; arbitrary state-command helper arguments are not trusted merely
because they passed through a helper with a familiar name.

These effects require complete validated records beginning at a usable boundary:

| Successful typed write | Queue effect |
|------------------------+--------------|
| Queue text, code, tone, silence or icon | Empty becomes pending; unknown stays unknown. |
| Unframed plain/tracked/marked dispatch | Empty after the pending batch is consumed or its poison is cleared. |
| Stop or reset | Empty; retain their existing separate cancellation behavior. |
| Isolated letter or immediate say | Preserve pending state; these do not clear the server pending batch. |
| Structured timeline, known control, heartbeat or nonqueue state command | Preserve pending state; successful playback is not evidence that an older queue drained. |
| Unknown command, partial/nonlocal write outcome or interleaving uncertainty | Unknown. |

Increment the mutation serial for every queue-affecting or unclassified write,
including a complete batch that leaves the queue empty. Letter and immediate
say also increment it because they interrupt speech, even though they preserve
the pending queue. Queue-neutral control/heartbeat/timeline writes leave it
unchanged. In-flight bookkeeping separately prevents a temporary unknown state
from being mistaken for a completed boundary.

For a replaceable =emacsvox_tx= packet, join the state for the payload executing
with the state for it being rejected/coalesced away. For example, an empty queue
remains empty if a fully closed batch either executes or is skipped. A final
dispatch inside a possibly skipped frame cannot prove that an earlier pending
queue was emptied. Stop/reset inside such a frame are not a permitted shortcut.

Queue effects apply at actual delivery, including an idle-scheduled send, rather
than capture time. A typed complete legacy packet can summarize its ordered
effects without storing a second copy of its commands. Compose fixed six-row
queue/framing transfer tables in original entry order. Adjacent partial entries
can absorb a later typed clear; concatenation is not proof of command separation.

A bounded successful local UTF-8 Unix write ending LF restores framing even after
a rejected record, but only a later valid typed clear establishes empty. Remote
validation covers each entire actual packet with its stricter inclusive line
limit, UTF-8/NUL and reserved-prefix rules. Across-write fragments, errors and
overlap latch remote proof unusable until fresh connection ownership. EOF does
so for either mode. Never manufacture a repair command or reconnect for proof.
Birth scopes must cover factory writes; public generation assignment preserves
the provisional record's observed state, and remote ready alone cannot reset it.

** Admission and reentrancy

Require known empty, boundary, usable, no in-flight write, the same live process
generation and the unchanged acknowledged registration when choosing new named
promotion. Check again before policy interruption and immediately before the
first output write. A body can recursively send speech while copying or framing;
its earlier queue-state sample is not a permanent grant. Retain the mutation
serial with the proposal and require it to match at both checks; even a later
legacy dispatch that restores empty invalidates the earlier proof.

Do not optimistically use an intended future Stop to justify promotion from
pending/unknown. Choose compatibility output in that case; a successfully sent
Stop at a proven boundary can establish empty for the next capture. This keeps
validation before Stop and avoids rebuilding a failed proposal after an
irreversible output action.

The existing exact own-stop allowance remains valid. Its private typed Stop
write may update the proposal's expected serial exactly once, immediately after
that clear succeeds at a valid boundary without overlap, before owner cleanup
and stop hooks run. Bind the permission to the exact ready preparation and write
token; do not use a dynamically inherited flag.
After the hooks, recheck empty/boundary/usable/serial/generation/registration.
A complete ordinary timeline or heartbeat from a post-write Stop hook may preserve
empty and need not cancel the outer request. A nested queue-only/opaque/legacy-
dispatch/letter write invalidates promotion before it is sent. Public Stop still cancels the preparation and must
not gain the own-stop exemption.

Once representation and owners are prepared, a failed admission recheck aborts
the submission. Do not reproject or replay it as legacy after policy effects.
If any same-process nested write breaks the proof during the write itself, treat the
delivery as an ambiguous send failure: retire owners, retain unknown, commit no
success/history effects, and do not replay. Already transmitted bytes cannot be
recalled. Even a heartbeat can join an unfinished line during I/O; it must not
inherit a clear token or be allowed to publish empty proof. Independent lanes
remain independent.

* Callback identity and metadata

Reserve a callback owner's ID when a captured tracked/marked dispatch intent is
created, using the existing bounded preparation scope. Both low-level explicit
dispatch and ordinary =tts-speak-tracked=/=tts-speak-marked= then retain that ID.
This also prevents a nested tracked ordinary call from failing simply because
its parent capture has not yet finalized. Reservation remains inactive, not
evidence that the server accepted or played the speech.

Finalization binds that same owner to the selected representation. Add a private
one-shot semantic-binding operation and an explicit prepared/bound flag. Existing
owner constructors with complete semantics remain bound. Deferred owners cannot
arm until binding is complete. Binding nil for legacy is a completed binding,
distinct from not having bound anything.

Copy and size the final semantic map before the critical section, recheck the
scope and owner, then update the map, bound flag, owner charge and process charge
together. Roll back on nonlocal exit. Charge only the delta from the original
reservation; use the existing 128-owner and 32-MiB metadata limits. Scope unwind
must release a reservation even if binding fails before the helper returns.
Attach choice context afterward using the existing atomic sidecar service.

A single eligible document reuses its reserved owner, or allocates one at final
projection for callback-free speech. Several callback owners force compatibility
delivery with their original dispatches. They are never merged into one callback
or abandoned merely to replace them with a new timeline ID.

Keep the existing packet writer, arm-before-write, deferred callback drain,
publication and last-reference release. Serialize all compatibility dispatch
commands and owner associations before policy interruption. Early server events
and failed writes keep the existing lifecycle semantics.

Any reserved callback owner makes delivery immediate, even after the dynamic
callback binding of a nested producer has ended. Do not put such an owner into
the idle scheduler and abandon it when the preparation scope closes. Callback-free
compatibility delivery retains the existing scheduler and cancellation rules.

* Visible limits and bounded diagnostics

Keep the last successful delivery's compatibility reason per lane when captured
owned names could not use individual tuning. Use bounded data: generation,
submission identity, reason, at most 32 logical IDs with the existing 128-byte
ID limit, and a truncation flag. Retain no text, callbacks or buffers. Update it
only for the proposal actually sent; an old completion cannot clear newer state.

Distinguish unsealed tail, explicit multiple flushes, opaque commands/definitions,
state transition, cross-call pending/unknown queue, unproven input boundary,
remote proof unusable until fresh ownership, and old-server support. Do not
overwrite a historical consumed-playback receipt with a prediction or a send
limitation. Configuration application and the route used by a particular
submission remain separate facts.

The editor/runtime explanation will expose these limits and the separate
character-review behavior. Routine speech must not repeat a warning on every
submission. Keep broader cross-call queue tuning explicitly deferred in the
backlog. No claim of complete editor delivery precedes that explanation and the
remaining preview/control/acceptance work.
