#+title: Transient menu audit for 2026.11.0
#+date: 2026-11-10

* Release assessment

All confirmed Emacsvox defects from this audit have corrections and regression
coverage. These include Enter activation, return focus, two unusable choice
actions, misleading linked-tone Help and repeated Agent Shell questions.
The compiled menu suite passes with both tested Transient versions. This is
ready for review and the short listening check below, not a release approval.

The installed Magit Git module still fails from byte-code before its menu
opens. Its matching source passes. Rebuilding that package and deciding which
optional packages to pin for a repeatable menu gate are the two deferred
decisions. Neither has been silently folded into the Emacsvox fixes.

Tree listening remains accepted on 2026-11-10. This audit does not reopen that
acceptance. Changes to menu wording need a short listening check of their own.

* Findings and corrections, in priority order

The reproduction steps and quoted failures below describe the original
behaviour. The corrections are recorded in the same commit as this report.
The verification table records the tests separately from listening acceptance.

** T1. High: Enter fails in nine Emacsvox menus

The explicit Enter-binding list in
[[file:../lisp/integrations/emacsvox-transient.el::(defun emacsvox-transient--settings-enter-binding][the Transient adapter]]
omits the four reading workflow menus, the three wrapped-line menus, Markdown
and Info. Real graphical key events reproduce this with both tested Transient
versions, from source and compiled code.

From =C-e H=, open =s R=, =s R a=, =s R f=, =s R s=, =s R w=,
=s R w 1= or =s R w m=. Browse to an action and press Enter. The selection
does not activate. Speech says, “Enter is not available here. Control G closes
this menu.” =C-j= activates it. Focused =C-e S= entry in Markdown and Info has
the same failure. The underlying Enter bindings remain =newline=,
=markdown-enter-key= or =Info-follow-nearest-node=.

Add the missing owned menus to Enter registration. Verify actual activation
through the keyboard, including choices and focused entry. Keep third-party
action bindings intact. The manual's Enter contract is correct; weakening it
would conceal the failure. Listening is needed only for concise confirmation.

** T2. Medium: numeric shortcuts restore the wrong control

In settings search, choose “Agent line navigation limit”. Highlight =f=, then
press =a=, enter 500 and accept. Focus returns to =f= instead of =a=. The
setting itself changes correctly, but the next Enter activates a different
control. Named voice tuning has the same problem: highlight Shared settings,
press =p= and enter a pitch; focus returns to Shared settings.

Returning from numeric entry also exposed a shared Transient issue: a refreshed
suffix can have an equal but separately allocated key string. Transient's
button lookup compares their identity and can leave point before the first
button. The shared reader now matches the displayed command and key contents.

The integration limit reader and voice editor bridge remember the highlighted
item instead of the action that opened the prompt. Reuse the shared prompt
wrapper, which also restores focus after cancellation and keeps settings
prompts readable while speech is quiet. Cover direct shortcuts, Enter,
invalid input, cancellation and source preservation in graphical tests.

** T3. Medium: the voice inheritance action cannot be browsed and activated

Open a named voice's fallback tuning menu, browse to “Use shared value for
selected adjustment”, then press Enter. It raises “Choose a numeric adjustment
first”. The action works only as a shortcut while a number remains highlighted.
The existing test exercises only that shortcut.

When no numeric control is selected, ask which adjustment should inherit, as
the default-reset action already does. Keep direct shortcut use on a selected
number. Proposed label: “Use shared value for an adjustment”. Help must explain
that this removes the fallback's override without changing shared tuning.

** T4. Medium: scope selection offers an impossible inheritance action

Open =C-e H s R w g=. The displayed “Follow wider settings for this preference”
action is available, but =i= or =C-j= always raises “Scope cannot inherit”. A
scope is a destination, not an inheritable preference. Hide this action when
choosing scope; retain it for actual preferences. Verify the remaining choices
and cancellation through real keys.

** T5. Medium: tone Help contradicts the parent draft contract

At =C-e H s Y l T=, repeated item reading produces:

- “Use tone in Trees draft. Apply this draft using the destination’s scope;
  SAVE also persists it. capital A.”
- “Use tone in Trees draft. Save and apply this cue through its destination’s
  persistence mechanism. capital W.”
- “Play pending root tone. Play the currently applied tone alone for comparison
  with Space’s draft. capital C.”

The provider keeps A and W in the Trees draft; neither applies rules nor saves
them. C compares with the parent draft. Wrapped-row tones have the same linked
draft distinction. The menu overview also describes W as persistent without
explaining these exceptions. Existing tests verify parent drafts and separate
saving; this is a confirmed wording error, not an unintended write.

Provide destination-specific summaries and Help. For Trees A and W, use
“Enable the draft's depth tone; apply or save it later in Trees.” For C, explain
that Space plays the private editor draft for comparison and neither action
applies settings. Give wrapped-row controls equivalent saving guidance.
Preserve the distinction between saving a
named tone preset and saving the cue's configuration.

** A1. Medium: Agent Shell repeats a question when selecting its answer

Live reproduction was confirmed by listening. In buffer
=Codex 3 Agent @ emacsvox=, the diagnostic session =20261108T235721Z-1546=
records =agent-shell-elicitation-act= at point 6424483, UTC
=2026-11-09T18:21:55.116Z=. Submission 20295, dispatch 29243, contains 185 characters and includes the entire
question before “Yes, the question repeats, selected”. The preceding movement
submission contains only the choice. Omnivox request 29243, protocol generation
33722, admits that request and starts Eloquence synthesis of the repeated
heading; Emacs observes its mixer source. This is submitted repetition, not an
inference from a running audio process.

The action advice omits the question-origin binding already used by navigation.
Bind the original control during the action, suppressing the heading only when
the result remains in the same question. Preserve headings when entering a
different question and explicit rereading. Test actual Enter in shell and
viewport buffers, selection, toggles and preview actions. Confirm the original
interaction through listening after the fix.

** T6. Low: numbers and explanations need clearer spoken wording

Wrapped-row volume displays its raw fraction, while exact entry and adjustment
use percent. Display percent consistently. Reading choices expose internal
values such as “inherit”; show the corresponding choice label and retain a
separate indication that the value is inherited.

Tone adjustments clamp at bounds without the “Minimum” or “Maximum” feedback
used by other numeric controls. Add that feedback without repeating the menu.
Several descriptions expose function arguments or implementation details,
including “DIRECTION”, “SAVE”, “change lifecycle” and “qualified engine
controls”. Replace these with the effect, scope and relevant dependency.

** T7. Low: exit explanations describe Transient internals

In Emacsvox menus, detailed descriptions and Help use the upstream quit
docstrings. “Without saving the transient stack” sounds like a statement about
settings, but it describes Transient's implementation. Closing a menu does not
save settings, and individual editors have different pending-draft policies.

Emacsvox-owned menus now explain Back and Close in terms of leaving menus,
retaining applied and saved changes, and each editor's stated draft policy.
The adapter changes neither application quit bindings nor third-party Help.
Search also retains old names as aliases and adds routes to tone editors and
wrapped-row volume through their proper parents. Browsing search results does
not apply settings.

* Test failures that are not confirmed menu defects

- The graphical voice runner selects editor tests and omits the broad menu
  suites. A release check needs an explicit graphical menu suite; a passing
  editor runner does not establish full menu coverage.
- The integration section test expects three sections even when Transient
  0.13.9 removes the empty first section. The actual two-section menu navigates
  correctly. Test visible sections and selected controls instead of assuming
  an empty section occupies a navigation step.
- The history test stubs text submissions but leaves minibuffer earcons active.
  Exact entry adds cue-only history records. Isolate that side effect before
  treating its expected count as a product failure.
- Installed Magit byte-code raises =void-variable $= while building status,
  before menu navigation. Loading the matching =magit-git.el= lets the graphical
  Magit navigation test pass. Keep this dependency verification separate from
  Emacsvox fixes; do not silently change the personal package installation.
- Two tree Help failures occurred with the inventory capture advice. They pass
  without it. The clean compiled suite also passes those tests. They are not
  evidence for withdrawing tree acceptance.
- One Notmuch test expects an old manual phrase, “no tree-specific row
  formatter”. The maintained text already says “no specialised row summaries”.
  Its expectation now matches that text; no Notmuch behaviour changed.

** Linked views and third-party ownership

The menus lead to Customize, the manual and Help, feedback details and rules,
recent feedback, presentation profiles, voice palettes, the named voice editor,
Voice Workbench, native engine controls, voice and recording libraries, sound
packs, dictionaries, notification history and diagnostics. Existing tests
exercise captured source/point, editor return, dirty drafts, explicit Save,
stale sources and asynchronous view identity. The separate graphical voice
runner covers native editor, catalogue and browser focus/return cases.

Magit's real Dispatch menu was exercised in all three navigation styles, with
section-only and item-only announcements, word/character review, repeat and
unchanged application bindings. Its installed Git module's byte-code fails
before opening status; loading the matching source permits this check. This
is not a claim that the installed compiled Magit package passed. Other
third-party menus are covered by shared keymap and ownership tests, not an
exhaustive audit of every third-party application action.

** Effects and persistence checked

| Family | Immediate effect | Saving and return |
|--------+------------------+-------------------|
| Speech rate and punctuation | Buffer or global values; explicit source override preserved | Save displayed values as defaults; Back retains live changes |
| Capitalisation reading and interaction | Selected buffer/global scope; some phonetics controls global | Save displayed defaults; narrower overrides can remain |
| Capital beeps | Private retained cue draft | Apply global defaults; Save persists and handles old menu rules; Back keeps draft |
| Indentation | Buffer/global feedback and pitch mapping; shared volume global | Buffer tone Save is rejected; global defaults use Customize |
| Spelling | Global live switches and basic tone controls | Parent Save includes switches; tone editor Save saves tone fields only |
| Line and boundary cues | Private draft, then explicit session rules | Save personal rules; contextual rules can override; boundary identities affect all uses |
| Tone editor | Private draft; explicit preview | Provider-specific Apply/Save; presets are a separate saved collection |
| Wrapped rows | Private buffer/mode/global draft | Apply session scope; Save mode/global only; Back discards unapplied changes |
| Tables | Pending changed choices | Apply buffer; save changed mode/common choices; narrower values remain |
| Trees | Pending tree rules and component choices | Apply buffer/session or save personal rules; narrower rules remain |
| Output | Spatial changes live; route chosen for next restart | Save does not restart speech; explicit restart asks separately |
| Named voice tuning | Shared/fallback draft, private sample | Save/apply and save-to-collection remain distinct; Back retains the draft |
| Integration settings | Local session/terminal controls or stated global defaults | Parent Save excludes separate structured editors and temporary EWW outlining |
| Reading workflows | Session controls; ranges remembered by file or mode | Column ranges persist on ordinary Emacs exit; Undo restores this visit's state |
| History and switches | Changes live; lowering history limit deletes old records | Save history policy only; Voice Lock Save excludes earcon/local switches |

Intentional differences remain: section-only speech can select an unspoken item
that =C-c l= reviews; review leaves Enter's action unchanged. Wrapped-row library
return goes to Line reading, as its current test and manual specify. Turning
off inherited earcons also removes menu earcons. Save keys differ between
established parents and the common tone editor; labels and Help must explain
those differences rather than silently reassigning keys.
