* Status and intended outcome

Implementation authorized on 2026-09-13, in tested, committed slices. The
maintainer selected Emacs's existing emoji-name table as the initial data
source. Release publication remains outside this work.
The preceding voice-editor and graphical-test changes are already committed.
Implementation and automated verification are complete. The opt-in listening
trial found that a Workaway subject containing =🌱= still used eSpeak: naming
was disabled and seedling was absent from the six-symbol trial list.
On 2026-09-14 the maintainer requested full-table naming and enabling it in
the newest session, then confirmed that the Workaway row worked and requested
this behaviour by default for new users. Naming now starts enabled. The policy
below reflects those follow-ups; the original implementation evidence records
the earlier restricted trial.

The first acceptance example is =Forecast 🔮=: with the feature enabled,
speech preparation supplies =Forecast crystal ball=, allowing Eloquence to
keep speaking when the rest of the text and the selected route are compatible.
The buffer still contains the original emoji. Unsupported language text and
unknown sequences continue through the existing fallback path.

The first version names eligible emoji before engine selection. Its names
therefore also reach engines that could handle the original emoji. Naming only
when the actual preferred engine needs it is a possible later Omnivox design,
not part of this implementation.

* Evidence from the current implementation

- [[file:../lisp/tts-speak.el][tts-speak.el]] already implements Unicode character names and explicit
  character replacements. Its broad compatibility conversion can name letters
  as well as symbols; re-enabling it globally would undermine language fallback.
- [[file:../lisp/omnivox-voices.el][omnivox-voices.el]] disables that broad conversion after every live speech
  process advertises =text_repertoire_routing_v1=. Preserve that negotiation.
- Omnivox filters engine candidates by the text each engine can encode, per
  synthesis chunk. This does not mark Eloquence unhealthy; a later compatible
  chunk can return to it. The new feature changes the prepared speech text,
  not Omnivox's repertoire declarations or fallback rules.
- The inspected Emacs 31.0.90 provides =emoji-labels.el= and an =equal= hash
  table named =emoji--names=. Exact lookups returned =crystal ball= for =🔮=,
  =woman technologist= for =👩‍💻=, and =thumbs up: medium skin tone= for =👍🏽=.
  The same trial names were subsequently verified on Emacs 30.2.
- Normal speech applies pronunciation entries in a temporary speech buffer.
  Complete voice previews construct their own text requests in
  [[file:../lisp/emacsvox-aural-voice-editing.el][voice-editing.el]]. A change only in the ordinary speech cleanup would
  leave previews inconsistent.

* Proposed policy for the first listening trial

** Scope and controls

Start enabled by default, with a global default and buffer/mode overrides.
An explicit nil setting still disables naming globally or in a source buffer.
Use the remembered source buffer's policy when opening a preview from an aural
screen. Freeze the policy for each submitted item or preview operation.

Provide an optional sequence restriction, a maximum count, and custom spoken
names. Default the restriction setting to =t=: every complete sequence with
an exact Emacs emoji name or a custom name is eligible, including flags and
keycaps. Preserve explicit lists for users who want a restricted set and for
previously captured policies. This replaces the original six-symbol trial list.

Initially allow two eligible emoji occurrences per captured speech item.
Repeated occurrences count separately. Count before any replacements and before
transport chunking; do not let backend chunk size decide the policy. If the
count exceeds the limit, skip automatic emoji naming for the whole item.
Explicit pronunciation entries retain their existing behaviour independently.
Assess the abrupt boundary at the third emoji during spoken acceptance before
making this limit a lasting default. Define which current source/preview unit
constitutes an item in the first implementation slice.

** Names and boundaries

Use explicit pronunciation entries first. For remaining eligible sequences,
use a custom emoji name if present, otherwise an exact lookup in Emacs's table.
Do not silently add full Unicode-name expansion for arbitrary characters.
Automatic naming inserts a spoken description; omission requires an explicit
user pronunciation choice.

Match complete emoji sequences. A recognised component inside an unknown
joined sequence must not be replaced on its own. Handle presentation selectors,
skin-tone modifiers, flags and joined emoji as complete units, including when
text properties divide their components. Establish conservative behaviour for
such property boundaries before implementation. Accept only verified spelling
variants; do not strip joiners or variation selectors indiscriminately.

Leave foreign-language letters, combining accents, unnamed symbols and
unknown sequences unchanged. An item may therefore contain a named eligible
emoji and still require fallback for its remaining text. Do not assume every
English label is ASCII or encodable by every legacy engine; existing repertoire
routing remains the final check.

* Implementation slices

** DONE 1. Verify the data adapter and preparation boundaries

Load =emoji-labels= lazily behind one private Emacsvox lookup function. Validate
the table's type and require exact string keys. Do not modify Emacs's table or
depend on its emoji picker and font-availability filtering. Avoid calling an
internal name helper that falls back to naming only the first character of an
unknown sequence.

Verify the table and sequence segmentation on Emacs 30.2 and the selected newer
Emacs, using separate checkouts for any compatibility builds. A missing table,
unexpected table shape or missing entry must leave the original text usable
through existing fallback, with a bounded diagnostic when naming is requested.
Do not fail ordinary speech or download replacement data. Record the loaded
data path and Emacs version because emoji coverage can differ between versions.

Trace ordinary, notification, retained-feedback and voice-preview preparation.
Choose the item boundary and the common helper's insertion points from those
actual call paths. Preserve literal character inspection. Record how source
policy reaches a preview and where it is frozen for comparison and replay.

** DONE 2. Implement deterministic matching and conversion

Build a helper that accepts original text plus an explicit policy snapshot and
returns prepared text and replacement evidence. Evidence must associate each
complete source sequence with its spoken name and source/output boundaries.

Perform recognition and threshold decisions on the unmodified item. Preserve
unmatched text exactly; prevent word concatenation around replacements. Bound
custom-name expansion and reject invalid configuration before using it. Apply
conversion once, without recursively matching generated names. Keep existing
pronunciation precedence and make the new automatic step optional.

Test this helper without an audio process. Avoid making the matching layer
depend on the selected engine, font rendering or changes to personal palettes.

** DONE 3. Integrate speech, previews and explanation

Use the helper in normal speech on both lanes and in fresh preview preparation,
including named-voice, individual-choice and contextual previews. Opening and
playing a preview must not select a palette or change the source's settings.

Preserve voice runs, semantic facts, positioned cues and speech markers across
length-changing substitutions. The existing replacement helper preserves some
properties, but that alone does not prove correct boundary mapping; test actions
before, within and after a replaced sequence explicitly.

Original replay must use the retained prepared presentation, not re-expand it
with today's settings. Fresh simulations/proposals use the applicable captured
policy and label their substitutions. Feedback Details should expose original
sequence and spoken name without suggesting that the buffer was edited or that
the inferred engine was actually heard.

Keep cancellation, nested preparation, reconnect and main/notification ownership
unchanged. Carry the effective policy with an asynchronous operation so later
buffer or settings changes cannot alter an in-flight request. Reuse existing
transport; no Omnivox protocol or helper changes are planned.

** DONE 4. Complete regression and compiled verification

| Case | Required result |
|------+-----------------|
| Feature disabled | Identical prepared text and existing fallback behaviour. |
| =Forecast 🔮=, enabled | =Forecast crystal ball=; original buffer unchanged. |

| Three eligible occurrences | No automatic emoji substitutions at the trial limit of two. |
| Approved compound emoji | One complete name and one occurrence, never separate component names. |

Run the focused source suites, then =make check-emacs= and =make bytecode=.
Use =make bytecode-rebuild= if the implementation changes macros or public
interfaces. Verify actual loaded paths in fresh compiled Emacs processes.
Keep Emacs 30.2 evidence separate. Test generated English labels and permitted
sequence variants from the real table as well as boundary-focused fixtures.

* Deferred work and design risks

No separate CLDR package, dataset download, copied Emacs data or runtime network
lookup is needed for this version. Localised names and identical coverage across
Emacs versions may justify revisiting that choice later. Naming only after an
actual engine repertoire rejection belongs to a separate Omnivox design.

The largest implementation risks are sequence boundaries, text-position mapping,
and independently prepared previews. The private Emacs table is a bounded
compatibility risk, handled through one adapter and conservative missing-data
behaviour. Use High for ordinary implementation. Recommend Xhigh only if the
preparation audit leaves a consequential cross-component question unresolved;
this plan imposes no automatic model switch or handoff stop.

* Implementation evidence

** Slice 1: adapter and boundary audit

Both Emacs 30.2 and 31.0.90 provide all six trial names, as well as complete
joined and skin-tone examples. The adapter records the loaded data file and
version, validates the equal hash table, and reports missing data as a bounded
symbol. It never falls back to a component name.

The item boundary is the planner's presentation object, before transport
chunking. A standalone preview sample is one item; comparison labels are
separate items. Source context captures the effective naming policy. Exact
retained replay bypasses fresh preparation.

Emacs's display-oriented =string-glyph-split= splits the unknown =🔮‍🚀= into
components on both versions. Matching will use conservative sequence scanning:
combining characters, selectors, modifiers, tags and joined bases remain
attached. A property change inside a candidate prevents replacement. Positioned
properties at its start belong only to the first output character.

** Slice 2: deterministic preparation

The pure helper implements the disabled default, six approved trial sequences,
two-occurrence threshold, bounded custom names, immutable policy snapshots,
complete sequence matching and source/output evidence. Nine focused tests pass
on Emacs 30.2 and 31.0.90. A sequence split by styles or an internal positioned
cue remains unchanged; a cue at its start stays on the first output character.
Pronunciation-produced text and already prepared expansions carry opt-out
properties. No speech path uses the helper until the integration slice.

** Slice 3: speech and preview integration

Ordinary and notification speech use captured source policy after explicit
pronunciations, before Unicode cleanup and transport chunking. The original
object count is frozen before cleanup, so shrinking or pronouncing an item
cannot bypass the limit. Names and diagnostics are attached to cloned plans;
source plans, semantic facts and source buffers remain unchanged.

Named, individual-choice and contextual previews share preparation before
asynchronous submission. Naming metadata stays on Emacs request snapshots and
is removed before backend requests. Fresh concrete simulations are prepared;
retained replay and rule proposals retain the captured prepared text and
naming evidence, including custom expansions containing emoji.

Focused source and fresh compiled emoji checks pass (21 batch tests; one
additional graphical-only case). Six isolated graphical checks pass, including
explanation visibility and the voice editor's final Save actions. The whole
unit suite exposed older palette/queue expectations and incomplete startup
inventory. These are tracked separately from emoji regression evidence.

** Full-table follow-up, 2026-09-14

The newest session's main Omnivox log explicitly reported =U+1F331= (seedling)
as the reason for rerouting the Workaway subject from Eloquence to eSpeak.
The source's captured policy had naming disabled, and the default trial list
did not contain that emoji. An exact Emacs lookup supplied =seedling=.

Enabled naming now uses the full Emacs emoji table by default. Explicit
restriction lists still work, including captured historical policies. Both
the original-item count and speech preparation use the same exact eligibility
check. Missing tables produce one bounded diagnostic; custom names still work.
Unknown joined sequences, foreign-language letters and style/cue boundaries
retain their previous protections. The default occurrence limit remains two.

The pure helper's 12 tests pass on Emacs 30.2 and 31.0.90, including flags,
keycaps, seedling, full-table counting and explicit restrictions. Fresh compiled
aural parity passes. The mail regression uses a synthetic subject with the
same seedling character at the normal speech and preview boundaries.

After the full byte-code rebuild, all 26 nongraphical emoji checks pass in a
fresh Emacs loading the compiled helper, planner and preview code. The
graphical-only explanation check is excluded from this batch selector; this
follow-up does not change graphical layout.

The maintainer started a newer profile during verification. That session
already had the updated helper; naming was enabled there and saved in the
personal profile's Custom file. A silent preparation check in the Notmuch
source buffer expands the original subject's seedling and leaves no non-ASCII
characters. Buffer point and both speech processes are preserved. A fresh
navigation/listening trial is still needed to establish the actual route and
what the maintainer hears; retained recordings keep their original policy.
