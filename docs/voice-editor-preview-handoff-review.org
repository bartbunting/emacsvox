* One owned operation for every Omnivox sample

Use one private coordinator for complete v2, shared-only v1 and legacy individual
auditions, including picker and experiment previews. Preserve existing generic
entry forms and callbacks. Add a distinct private layered entry/service for the
editor; do not reinterpret =:selectors= or route a customized draft through the
old projector. Keep the generic non-Omnivox queued-only guarantee explicit.

An operation owns a frozen foreground process and its lifecycle generation, a
unique token, a view/session token, draft and context revisions, the complete
validated sequence, entry cursor, one control reservation, one timer, one Stop
observer and bounded terminal evidence. Every continuation checks both operation
and entry identity. No step consults a replacement =tts-speaker-process= to send
the next entry. Notification-lane Stop cannot cancel the foreground operation.

Preflight is a pure phase before superseding current playback: deep-copy strings,
lists and vectors, validate all labels and samples in both comparison halves,
selectors/IDs, context, capabilities and encoded bounds. Reject malformed or
unsupported input before any Stop, request reservation or speech. No partial
comparison is allowed merely because its first half was valid.
Capture process/lifecycle/configuration identity at preflight entry and recheck
it before interruption; preflight must not silently switch connections either.

After preflight, install an owned operation under unwind protection /before/
interruption. Retire the previous token and detach its resources first. Startup
uses an explicit private own-Stop grant; every public/reentrant Stop remains
cancellation, including one called inside the startup Stop's observers. Recheck
ownership after every hook and before reserving or sending an entry. A newer
preview started by a callback wins; the superseded outer startup sends nothing.
The grant is tied to this particular invocation and consumed once, never an
ambient boolean inherited by arbitrary callbacks. Adapt the existing private
interrupt/preparation helpers narrowly; do not weaken public Stop semantics.

Control submission needs a reservation before writing, with its ID known to the
operation before the sender can call a filter. A response arriving during that
write is validated and latched, not delivered recursively. Only a successful,
non-overlapping complete write may advance the sequence or invoke callbacks.
An error, quit or throw retires the reservation, timer and hook exactly once,
discards pending advancement and never retries via legacy preview. Propagate a
nonlocal exit after cleanup; cleanup itself cannot invoke client code prematurely.
Callbacks run outside the enclosing ordinary speech capture/preparation scope.

At timeout or local cancellation, first mark terminal, detach pending work and
retire ownership. If an interrupt is needed, complete it against that owner
/before/ notifying user code. Check for intervening replacement before sending
any interrupt; a stale timeout must never stop new playback. A callback error,
quit or new preview cannot undo cleanup. Process death/reconnect ends the old
operation without replay. Leaving/killing a view or cancelling its picker retires
only that view's token; it cannot stop another view's newer sample.

* Framing, bounds and comparison sequencing

A preview explicitly requests foreground interruption. It may start with a
framed pending legacy queue, clear it once, and then submit the private request.
Unlike ordinary named-queue promotion, this does not require the queue to have
been empty before the requested Stop. It does require a proven command boundary,
usable process/coding identity, no write in flight and intact observer coverage.
Reject unproven framing before sending anything; never add a repair newline or
an extra Stop, reconnect automatically, or use a legacy audition to bypass it.

Add a narrowly scoped startup receipt for this case: capture boundary/process/
serial identity without asserting empty, observe the exact typed Stop through
the actual write, and require resulting empty/boundary proof with its matching
serial after observers return. Intervening queue, dispatch, letter, unrelated
Stop or overlapping heartbeat invalidates startup. This is a new private
admission helper, not permission to relax the existing ordinary empty-queue guard.
Subsequent requests use the existing empty-queue guard without a registry
dependency: the request contains the full private voice. Check capabilities and
captured settings at each send. A neutral control write still needs intact
framing and non-overlap. Ambiguous transport failure ends the comparison without
repair/replay and follows existing process/proof retirement rules.

Keep wire bounds unchanged: 16 KiB UTF-8 text per entry, 32 choices, 256 KiB
decoded control envelope, 32 accepted identities and 1024-byte diagnostic text.
Use an explicit client sequence limit of 64 entries (label plus sample for all
32 rows); paired original/edited comparison uses four. Bound cumulative prepared
wire bytes at 16 MiB, including later =expected_base_rate= and maximum u64 request
ID space; reject before Stop. Freeze normalization inputs as well as raw values.
Only one entry is outstanding; no speculative submission of the edited half.

Keep per-entry label/sample and original/edited tags. The first valid completed
entry captures base rate and effective disabled-engine union. Subsequent entries
send that exact expected rate and compare returned disablement as a set. Changed
metadata stops further comparison; retain already verified evidence as evidence
for the captured sample, with the mismatch explained. The existing protocol does
not provide an expected-disablement admission guard, so a changed union can only
be detected after that entry's response; do not claim it never spoke.

Retain at most one result per bounded entry, one independent last-started summary
for sample entries, and one last operation result per retained editor context.
Do not build request histories or unbounded late-response tombstones. Release
prepared strings and callbacks on completion. Local cancellation/timeout gets
one terminal callback; late server replies are ignored. If no validated terminal
arrived, playback is /unconfirmed/, not proof that no audio started. Evidence from
earlier completed entries may remain, labelled with their frozen input revision.

* Projection without flattening the cascade

Build each v2 request directly from the snapshot: a complete shared style plus
ordered records =id/selector/adjustments=, sparse context and explicit placement.
Use the already tested =omnivox--choice-style-json=, =--choice-records-json= and
=--choice-patch-json= conversions. Never derive a patch by subtracting shared
values from an effective style. Normalize once, including pitch contrast and
the tuner's existing low-pass stored/display conversion.

Choice omission means use shared; choice nil means adapter default; zero is an
explicit set operation. Contextual ACSS nil retains the existing no-reset
behavior; contextual rate/effect nil clears that field. Preserve these raw
distinctions in inspection even where the audible context patch omits ACSS nil.
A context value equal to shared still masks a different row-specific value.

The contextual resolver must return the chosen unflattened base snapshot and
the winning sparse context separately, alongside requested values/provenance.
Resolve the same frozen facts/rules for original and edited snapshots. Preserve
preset-reset behavior, other-base selection and suppressed-content refusal.
The current voice-only context view continues to omit cues and spatial placement;
send =placement.pan=null= and state that limitation. Do not silently add spatial
audio to this editor in the guise of fixing sparse context.

Automatic preview sends the complete original chain and automatic selection.
Row audition also sends the complete chain, selecting its stable ID. Never move
that row to index zero or remove its siblings to audition it. Original/edited
row comparison looks up the same ID in each frozen chain, so reorder changes
the index and preserves identity. A newly added row has no original: explain
that comparison is unavailable, retaining edited audition and full-voice compare.
Do not select an original row by matching physical engine/voice IDs; duplicates
are valid distinct choices. Missing/deleted IDs reject before Stop.

* Strict response admission and truthful speech

Add v2 decoding alongside the old control path. Preserve JSON null/false/arrays,
reject duplicate/unknown/missing members and validate canonical Base64/UTF-8 and
bounds before correlation. Reuse the marker-3 audio-identity validators and
frozen-chain correlation rules; v2 has the existing control envelope 1, not a
marker envelope. An invalid response with a unique trustworthy request ID fails
that owned entry. An uncorrelatable record cannot consume any reservation and
leaves the ordinary deadline in force. Duplicate/late responses do not advance.
A valid correlated control error (for example, admission rejecting a changed
base rate) also ends the operation; it is not a fabricated v2 playback terminal.

Validate status, finite base rate, distinct bounded disablement, ordered distinct
accepted identities and boolean playback flags. Match row ID to its /original/
index and reason. A choice audition permits only that row; automatic policy
substitutes use null row IDs and their typed reason. Apply exact-selector checks
where justified; property/default selection is resolved by the server, not by
the client inventory. Bounds/correlation apply to failed/cancelled terminals too.

Validate =last_started= independently. Without truncation it must agree with a
started accepted identity; with truncation it may be absent from the acceptance
list. A started identity retained in that list must agree with the matching
flag. Never infer last-start order from first-acceptance order. Failed attempts
without committed PCM are not accepted audio; accepted audio alone is not started
audio. A null last-started identity cannot accompany a true playback-started
flag, even when truncated. A completed empty preview can have neither.

Status speech distinguishes /completed/, /cancelled/, /failed/ and /unconfirmed/.
Only =last_started= for a sample supports “Last sample playback started on …”.
Keep spoken-label evidence separately: hearing “Original” does not establish
that the following sample started. Show accepted-but-unconfirmed audio and
partial failure in Details. Use request-snapshot values to explain shared,
choice and context sources; receipts report actual identity and unsupported
dimensions, not measured pitch or acoustic output. Preview receipts never
overwrite ordinary lane playback receipts or compatibility reasons.

On input change, undo, save rebase, text change, context recapture, leave or kill,
invalidate current-view ownership before Stop or other callbacks can run.
Track a monotonic draft revision (not dirty-field equality: undo can return to
the same values), context/text revision and view incarnation. Retained historical
evidence is explicitly labelled as earlier; a late callback cannot refresh the
current result, clear a newer owner, or announce into a closed/reopened picker.
Successful save/apply acknowledgement and dirty status remain independent of
preview completion.

* Older servers and the optional controls

prefer v2 for the new editor's base, row and context previews. Without it, retain

An old exact audition is permitted only when its selected composition and

that decision from typed values and capabilities, not successful serialization

omission over a retained setting. If fidelity cannot be proved, explain the
limitation before Stop. Label permitted legacy auditions as such; their old
terminal is not a v2 row receipt. Preserve existing generic legacy degradation
reporting without using it to claim a faithful customized comparison.

toggle state speech, value-before-sample and the established low/high-pass

separately from last playback evidence.
