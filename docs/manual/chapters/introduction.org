* Introduction
:PROPERTIES:
:TEXINFO_NODE_NAME: Introduction
:DESCRIPTION: Understand the Emacsvox audio desktop.
:END:

#+cindex: Introduction

Emacsvox is an Emacs 31-or-newer audio desktop derived from Emacspeak.  It is
not a pixel-oriented screen reader.  It runs inside Emacs, where commands,
buffers, text properties, faces, modes, and application state are available as
structured information.  That context lets Emacsvox present the meaning and
result of an interaction rather than merely reading the visible display.

Application integrations adapt interactive commands and changing buffers to
produce spoken text, voice changes, auditory icons, tones, pauses, and spatial
feedback.  The core speech layer normalizes text and formatting and sends it
to the selected speech adapter.  Established direct speech paths remain
available for compatibility, while migrated integrations can submit a complete
Aural Presentation transaction.

** Aural Presentation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Aural Presentation separates semantic facts from their audible rendering.
An integration records what an object or event means; providers and rules
choose voices and actions; a planner and compiler produce a concrete ordered
presentation.  The fixed internal baseline preserves established Emacsvox
feedback.  Users can compose Presentation Options, profiles, palettes, sound
packs, spatial settings, and scoped overrides without replacing that baseline.

Open Aural Home with @@texinfo:@kbd{C-e H}@@ or
~M-x emacsvox-aural~.  Use @@texinfo:@kbd{C-e E}@@ to explain the presentation at
point.  The generated author and lifecycle reference is
~etc/aural-presentation-reference.org~ in the source tree.

** Speech Adapters And Omnivox
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Emacsvox retains standalone speech servers for engines such as eSpeak,
Eloquence, DECtalk, and SwiftMac.  Omnivox is the recommended multi-engine
server for new GNU/Linux, macOS, and WSL2 installations.  It negotiates
capabilities, reports live engine and physical-voice inventory, routes portable
logical voices, and accepts structured presentation timelines.  Keyed
replaceable timelines cancel only older work in the same replacement domain;
ordered and urgent work are not placed behind the replaceable coalescing
window.

@@texinfo:@xref{Speech Backends}@@, for Emacsvox's platform status, Omnivox installation,
selection, smoke test, and compatibility policy.  The Emacsvox
~Readme.org~ documents advanced portable voice routing.  Omnivox owns the
detailed control, helper, and presentation-timeline protocol contracts in its
own repository.  The legacy line protocol remains supported for standalone
and older speech servers; @@texinfo:@xref{TTS Servers}@@ explains the boundary between
those protocol families.

** Documentation Scope
:PROPERTIES:
:TEXINFO_NODE: no
:END:

This manual includes generated command documentation as well as inherited
Emacspeak essays and application guides.  Historical chapters are useful for
design context but may describe software and Web services from their original
period.  Current setup starts with @@texinfo:@xref{Installation}@@; rapidly changing
