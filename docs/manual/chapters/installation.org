* Getting Started: Installation and First Speech
:PROPERTIES:
:TEXINFO_NODE_NAME: Installation
:ALT_TITLE: Installation
:DESCRIPTION: Install Emacsvox and reach first speech.
:END:

#+begin_export texinfo
@c Generated from docs/manual/emacsvox.org; do not edit.
#+end_export

This chapter takes you from a fresh source checkout to a speaking Emacsvox
session.  You will prepare the speech server, build Emacsvox, check each layer,
and start an isolated session before changing your personal Emacs setup.

Commands shown before Emacsvox starts are entered in a terminal.  Keys written
with @@texinfo:@kbd{C-}@@ or @@texinfo:@kbd{M-}@@ are entered inside Emacs.  The same chapter is
available before installation at
[[https://bartbunting.github.io/emacsvox/Installation.html]].

** Before You Begin
:PROPERTIES:
:TEXINFO_NODE_NAME: Obtaining Emacsvox
:DESCRIPTION: Prepare the required tools and Emacsvox checkout.
:END:

Install ~git~ so you can obtain the Emacsvox checkout.  Emacsvox requires
[[https://www.gnu.org/software/emacs/download.html][Emacs 30.2 or newer]], but WSL2 users do not need to find a separate Emacs
package before beginning.  The guided installer below uses an existing
supported Emacs, suggests a suitable package, or offers an explicit source build.

On GNU/Linux and macOS, install Emacs 30.2 or newer and ~make~.  Omnivox 1.7.0
or newer is the supported speech-server baseline.  Installing its release
archive also requires ~curl~ and either ~sha256sum~ on GNU/Linux or ~shasum~
on macOS, plus ~tar~.  GNU Texinfo is needed only when building or editing the
documentation, not for an ordinary installation.

Ubuntu 26.04 provides Emacs 30.2 as a distribution package, which satisfies
this requirement. The same minimum applies to native Windows.
On Emacs 30, install ~lua-mode~ separately if you use Lua; on Emacs 31 it is
built in. Corfu on an Emacs 30 text terminal also needs ~corfu-terminal~;
Emacs 31 supports its terminal popup directly.

To check the Emacs found by your shell, run:

#+begin_example
emacs --version
#+end_example

The reported version must be 30.2 or newer.  If
the command is not found or reports an older version, install a supported Emacs
or locate its executable.  You can check a specific executable in the same way:

#+begin_example
/path/to/emacs-31/bin/emacs --version
#+end_example

The Linux x86-64 archive requires an Ubuntu 24.04-compatible glibc, libstdc++,
libgcc, and ALSA runtime.  If the archive does not match the host, the Omnivox
source route requires Rust, Python 3, a C and C++ toolchain, CMake, and Clang
with libclang.  It additionally requires ~pkg-config~ and ALSA development
headers on GNU/Linux or the Xcode command-line tools on macOS.  These are not
requirements for the recommended WSL2 binary route.  Docker and Windows .NET
Framework are needed only for the advanced reproducible source-build route in
@@texinfo:@ref{Building Omnivox For WSL2}@@.

Run the clone from a Linux or WSL terminal and keep the checkout on the Linux
filesystem.  The following concrete location works for an ordinary per-user
installation:

#+begin_example
mkdir -p ~/src
cd ~/src
git clone https://github.com/bartbunting/emacsvox
cd emacsvox
#+end_example

The Emacsvox checkout is the installation directory.  It builds in place and
does not create a second tree to copy elsewhere.  Do not put the ordinary WSL2
checkout below a Windows-mounted path such as ~/mnt/c~; Windows filesystem
semantics can interfere with Unix executable permissions and build tools.
Clone Omnivox beside Emacsvox only when following the Omnivox source-build or
reproducible WSL2 build route.

If this machine will send speech to another workstation, use
@@texinfo:@ref{Installing Remote Emacsvox}@@ instead of installing a local
speech server.  For a local WSL2 desktop, first ask the guided installer to inspect the machine without
changing it:

#+begin_example
cd ~/src/emacsvox
./bin/emacsvox-wsl-install --check
#+end_example

If Emacs is missing, the report checks the available apt version and suggests
~sudo apt install emacs~ only when that candidate satisfies 30.2. Older or
unavailable candidates are identified without being recommended. You can
refresh apt metadata and check again, or choose the pinned source build with
~./bin/emacsvox-wsl-install --build-emacs~. Add ~--check~ to inspect that
build's prerequisites first. The installer never begins a source build by default.

With Emacs selected, the report names it, the matching Omnivox Windows archive,
and the per-user installation paths. If source-build packages are missing, it
prints one ~apt~ command for you to review and run.  The installer never invokes
~sudo~ itself.  After resolving any reported prerequisite, run:

#+begin_example
./bin/emacsvox-wsl-install
#+end_example

If you chose ~--build-emacs~, it prepares the pinned stable Emacs for your user.
It then downloads and verifies the matching Omnivox 1.7.1 Windows archive, records its
path without editing a shell startup file, compiles Emacsvox, runs a diagnostic,
and plays the final speech-server check.  The Emacs build can take a while on
a fresh machine; later runs reuse it and the verified downloads.  Routine
compiler output is kept below ~$XDG_CACHE_HOME/emacsvox/logs~, normally
~~/.cache/emacsvox/logs~.  If a build fails, the installer shows its final log
lines and the complete log path.  Continue only after hearing both the final
tone and speech.  You can then skip to the last step in
@@texinfo:@ref{Quick Installation}@@ and start Emacsvox.

After the core installation works, optional speech engines are available from
@@texinfo:@kbd{M-x emacsvox-omnivox-manage-components RET}@@.  The same manager
is the /Omnivox engine modules/ row in Aural Home, opened with
@@texinfo:@kbd{C-e H}@@ and then @@texinfo:@kbd{I}@@.  It distinguishes engines
already included in the core, downloadable modules, and bridges that still
need a user-supplied runtime.  Press @@texinfo:@kbd{i}@@ on a downloadable row
to confirm, checksum-verify, install, and validate that module without =sudo=.
Press @@texinfo:@kbd{u}@@ on a manager-installed module to confirm and remove
it while retaining the verified download cache; press @@texinfo:@kbd{i}@@ to
reinstall it later.  The manager never removes core engines or separately
supplied runtimes.
@@texinfo:@xref{Optional Omnivox Engine Modules}@@ explains the choices and
licensing boundaries.

** Installing On A Remote Linux Host
:PROPERTIES:
:TEXINFO_NODE_NAME: Installing Remote Emacsvox
:DESCRIPTION: Prepare Emacsvox without installing local speech engines.
:END:

Use this route when Emacs runs on a Linux host and speech plays on your
workstation through an SSH reverse forward.  It also works for remote-only
Emacs under WSL, without Windows interoperability.  This is currently a
development feature: the workstation needs an Omnivox build with ~--serve~;
the published Omnivox 1.7.1 archive does not include that option.

After cloning Emacsvox on the Emacs host, run:

#+begin_example
cd ~/src/emacsvox
./bin/emacsvox-install --role remote-emacs --check
./bin/emacsvox-install --role remote-emacs
#+end_example

The first command reports prerequisites and paths without changing files.
The second reuses Emacs 30.2 or newer and compiles Emacsvox. If Emacs is missing,
it checks the local apt candidate and suggests ~sudo apt install emacs-nox~
when that version is suitable. To choose the source build instead, run
~./bin/emacsvox-install --role remote-emacs --build-emacs~. Add ~--check~ to
inspect build prerequisites first. The checksum-verified GNU Emacs 31.1 source
is built as a terminal-only installation under
~~/.local/opt/emacs-31.1-terminal~.  Other Linux distributions currently need
an existing Emacs 30.2 or newer.  A supported GUI Emacs can also be reused.
Explicit ~EMACS~ and ~local.mk~ selections are preserved; if they conflict or
select an unsupported version, resolve the reported setting first.

No local Omnivox, sound device, GUI build packages, or Windows speech tools
are required.  Missing Debian/Ubuntu build packages are reported as one
~apt~ command for you to review and run.  The installer never invokes ~sudo~
or changes a shell startup file.  Build logs are kept below
~~/.cache/emacsvox/logs~, or the corresponding ~XDG_CACHE_HOME~ location.

Installation can finish before the workstation is connected.  Follow the
/Remote workstation speech/ instructions in
@@texinfo:@ref{Supported Platform Routes}@@ to prepare its service, private
token, and SSH reverse forward.  Then run on the Emacs host:

#+begin_example
./bin/emacsvox --remote --diagnose
./bin/emacsvox --remote --check
./bin/emacsvox --remote
#+end_example

Diagnosis reports local configuration without connecting or reading the
token's contents.  The check connects both speech lanes, waits for workstation
inventory and voice registration, and speaks a short foreground announcement
followed by a notification announcement.  Confirm that both are audible.
The last command starts an isolated terminal Emacsvox session.

The default forwarded endpoint is ~127.0.0.1:6417~.  The token file defaults
to ~~/.config/omnivox/remote-token~, respecting ~XDG_CONFIG_HOME~ when set.
To select another forwarded port or private token path, supply environment
values to the same command:

#+begin_example
EMACSVOX_REMOTE_PORT=6418 \
EMACSVOX_REMOTE_TOKEN_FILE="$HOME/.config/omnivox/other-token" \
  ./bin/emacsvox --remote --check
#+end_example

~EMACSVOX_REMOTE_HOST~ accepts only ~127.0.0.1~ or ~::1~.  The token path
must be absolute; its contents stay in the private file.  Use the same
settings when starting the session.  Remote mode selects the Omnivox
transport and skips local speech executable and playback probes; leave
~TTS_PROGRAM~ unset or set it to ~omnivox~.

For updates, keep your speaking session open, pull the checkout with
~git pull --ff-only~, and rerun the remote installer.  It rebuilds byte-code
with the selected Emacs.  Perform the connected check while the workstation
service is free, and test the updated session before closing the known-good
one.  A single service admits only one Emacs session at a time: use a
separate test service or explicitly disconnect the old remote session before
connecting its replacement.

** Updating An Existing WSL2 Installation
:PROPERTIES:
:TEXINFO_NODE_NAME: Updating Emacsvox Under WSL2
:DESCRIPTION: Update the source checkout and rerun the guided installer.
:END:

The guided installer recompiles the source already present in the Emacsvox
checkout, but it does not fetch newer source itself.  Keep the current speaking
Emacsvox session open while updating.  Run the commands from
@@texinfo:@kbd{M-x shell RET}@@ in that session, or from another accessible WSL terminal:

#+begin_example
cd ~/src/emacsvox
git pull --ff-only
./bin/emacsvox-wsl-install --check
./bin/emacsvox-wsl-install
#+end_example

Replace ~~/src/emacsvox~ if you chose another Linux-filesystem location.  The
fast-forward-only pull does not create a merge commit.  If Git reports local
changes, a divergent branch, or another error, stop and review that checkout;
do not reset or discard files merely to complete an update.

Rerunning the installer reuses supported Emacs and verified cached downloads,
installs a newly pinned Omnivox release when necessary, rebuilds Emacsvox
byte-code from scratch so files from the previous source revision cannot
survive, and repeats the launch checks.  These operations change files on disk
but do not stop the Emacsvox process already providing speech.  If the update
fails, leave that session running while using it to inspect the reported error
and the named log file.

After the installer succeeds and you hear its final check, leave the old
Emacsvox session open and start a second, isolated process from the updated
checkout:

#+begin_example
cd ~/src/emacsvox
./bin/emacsvox
#+end_example

Running both sessions temporarily is deliberate: the old session remains the
known-good source of speech while you test the replacement.  The new process
cannot retain Lisp loaded from the previous version.  Confirm that it speaks
the ready message and ordinary buffer contents.  In the new session, use
@@texinfo:@kbd{M-x emacsvox-speak-version RET}@@ to hear the Emacsvox version and
@@texinfo:@kbd{M-x tts-speak-version RET}@@ to hear the live speech-server version.  Only
after these checks pass should you save work in the old session and exit it.
You can then continue in the isolated session or start Emacsvox through your
normal customized entry point.  If the new session does not speak, close it but
leave the old session running while you inspect the diagnostic and installer
logs.

For an Emacsvox-only manual update, keep the current session running and replace
the two guided-installer commands after ~git pull --ff-only~ with:

#+begin_example
make check-emacs
make bytecode-rebuild
./bin/emacsvox --diagnose
./bin/emacsvox --check
#+end_example

All four commands must succeed, and the final check must produce both its tone
and speech, before performing the second-session test above.  This manual route
rebuilds Emacsvox but does not download or select a newly pinned Omnivox
release.  When Omnivox also needs to be updated independently, follow the
/Manual Release Installation/ subsection in
@@texinfo:@ref{Installing An Omnivox Windows Release Under WSL2}@@, then repeat
the diagnostic and audible check above.

** Install And Check Omnivox
:PROPERTIES:
:TEXINFO_NODE_NAME: Building And Testing The Speech Server
:DESCRIPTION: Install the recommended server and hear its check.
:END:

If you used the guided WSL2 installer above, Omnivox is already installed and
checked.  Continue to @@texinfo:@ref{Quick Installation}@@.

On a matching GNU/Linux x86-64 or macOS host, follow
@@texinfo:@ref{Installing An Omnivox Release Binary}@@.  That procedure downloads and
verifies the published 1.7.1 archive, keeps its runtime data beside the
executable, and adds its versioned installation directory to ~PATH~.  Then run:

#+begin_example
omnivox --check
#+end_example

Use @@texinfo:@ref{Installing Omnivox From Source}@@ instead on Linux ARM64, an
incompatible Linux distribution, or a host whose security policy does not
permit the unsigned macOS archive.  No proprietary speech runtime is needed
for either GNU/Linux or macOS route.

For a manual WSL2 installation, or to understand exactly what the guided
installer verifies, see
@@texinfo:@ref{Installing An Omnivox Windows Release Under WSL2}@@.

The check plays a tone followed by speech.  When you hear both, the speech
server is ready.  If either is missing, use
@@texinfo:@ref{Backend Diagnostics And Ownership,Backend Diagnostics And Responsibilities}@@
before continuing.  @@texinfo:@xref{Speech Backends}@@ contains the complete platform
matrix, build details, and compatibility alternatives.  Native Windows Emacs
support remains a preview.  Its x64 PowerShell installer can build Emacs and
install Omnivox without WSL.  Evaluators can follow
@@texinfo:@ref{Trying Native Windows Emacsvox}@@; initial users should choose
the WSL2 route.

** Build And Start Emacsvox
:PROPERTIES:
:TEXINFO_NODE_NAME: Quick Installation
:ALT_TITLE: Quick Installation
:DESCRIPTION: Build Emacsvox and reach an isolated speaking session.
:END:

The guided WSL2 installer has already selected Emacs, compiled Emacsvox, and
run both checks below.  You may go directly to the final step and start the
isolated session.  The full sequence remains useful for GNU/Linux, macOS, a
manual WSL2 installation, or later diagnosis.

1. Enter the Emacsvox checkout:

   #+begin_example
   cd /path/where/you/keep/source/emacsvox
   #+end_example

1. Select Emacs 30.2 or newer.  If it is not the system ~emacs~, create the
   ignored local settings file:

   #+begin_example
   cp local.mk.example local.mk
   #+end_example

   Then set ~EMACS~ in ~local.mk~:

   #+begin_example
   EMACS=/path/to/emacs-31/bin/emacs
   #+end_example

   The earlier ~emacs --version~ command checks your shell's default.  Verify
   the executable selected by the Emacsvox build separately:

   #+begin_example
   make check-emacs
   #+end_example

   ~make check-emacs~ uses ~local.mk~ when present, prints the selected
   executable and version, and confirms whether Emacsvox supports it.

1. Compile Emacsvox:

   #+begin_example
   make bytecode
   #+end_example

   A successful build returns to the shell without an error.  Emacsvox must be
   compiled with the same supported Emacs selected in the previous step.

1. Run the non-audible launcher preflight from the Emacsvox checkout:

   #+begin_example
   ./bin/emacsvox --diagnose
   #+end_example

   This checks the checkout, Emacs, and speech server without playing audio or
   opening interactive Emacs.  A successful report names Emacs 30.2 or newer,
   the ~omnivox~ speech server, and an isolated ~-Q~ startup.  If it reports a
   path or version problem, correct that item and run the command again.

1. Check the complete launch path with sound:

   #+begin_example
   ./bin/emacsvox --check
   #+end_example

   The launcher prints what it selected, then plays a tone and speech.  Hearing
   both means the complete speech-server launch path is ready.

1. Start a clean Emacsvox session:

   #+begin_example
   ./bin/emacsvox
   #+end_example

   The launcher uses Omnivox and the selected Emacs, but does not load site
   files or your personal Emacs init file.  This gives you a known starting
   point without changing an existing Emacs setup.

If a command needs an explicit path, ~./bin/emacsvox --help~ describes the
~EMACS~, ~TTS_PROGRAM~, and ~EMACSVOX_DIR~ overrides.  Arguments after ~--~
are passed to Emacs.

** Confirming First Speech
:PROPERTIES:
:TEXINFO_NODE_NAME: Confirming First Speech
:DESCRIPTION: Verify the live adapter and basic feedback.
:END:

You will know the isolated start succeeded when Omnivox acknowledges the
initial engine inventory, routing policy, and logical voices, and Emacsvox
speaks:

#+begin_quote
Emacsvox is ready.
#+end_quote

An earlier introduction, overview key, version number, and startup auditory
icon may also be heard.  Those can change; the sentence above is the stable
first-speech checkpoint because it normally occurs after initial routing is
acknowledged and therefore uses the restored engine policy.  If routing does
not finish within five seconds, Emacsvox speaks the checkpoint through the
capability-ready fallback so a routing error cannot suppress it indefinitely.

You now have a working Emacsvox session.  Try these checks before connecting
it to your personal configuration:

1. Type @@texinfo:@kbd{M-x tts-speak-version RET}@@.  The live speech adapter should speak its
   version response.

1. Type @@texinfo:@kbd{C-h v tts-program RET}@@.  The displayed current value should name
   ~omnivox~.

1. Use @@texinfo:@kbd{C-n}@@ and @@texinfo:@kbd{C-p}@@ to move over lines and confirm ordinary spoken
   navigation.  Type @@texinfo:@kbd{M-x emacsvox-describe-emacsvox RET}@@ for the Emacsvox
   overview.  @@texinfo:@xref{Basic Usage}@@, for the tested starter commands.

If the initial speech is too fast, press @@texinfo:@kbd{C-e d -}@@ and then repeat
@@texinfo:@kbd{-}@@ to slow the current buffer, or use @@texinfo:@kbd{C-e d r}@@ to enter an exact
rate such as ~40~.  For individually echoed characters, use
@@texinfo:@kbd{C-e d f}@@ and try a multiplier below one, such as ~0.7~.  Put
@@texinfo:@kbd{C-u}@@ before the exact-rate or character-factor command to change the
global default rather than only the current buffer.

When these checks pass, continue to @@texinfo:@ref{Basic Usage}@@ for a short guided
first session, or use @@texinfo:@ref{Persistent Startup}@@ to connect Emacsvox to your
normal Emacs configuration.

** Recovering From No Speech
:PROPERTIES:
:TEXINFO_NODE_NAME: Recovering From No Speech
:DESCRIPTION: Diagnose the boundary at which speech failed.
:END:

If speech did not start, keep the isolated launcher as your known starting
point and find the first command below that did not work:

#+attr_texinfo: :indic asis :compact t
- ~./bin/emacsvox --diagnose~ fails ::

  No audio or interactive Emacs has started.  Under WSL2, begin with
  ~./bin/emacsvox-wsl-install --check~ and resolve the first item it reports.
  Otherwise, follow the launcher selection:
  set ~EMACS~, correct ~EMACS=~ in ~local.mk~, or install Emacs 30.2 or newer
  when the Emacs check fails.  When the speech server is not
  executable, finish installing Omnivox, put it on ~PATH~, or set
  ~OMNIVOX_PROGRAM~ to its absolute executable.  The guided WSL2 installer
  records the verified executable in a per-user configuration file; rerunning
  it repairs a missing installation or selection without requiring a shell
  startup edit.
- The diagnostic passes, but ~--check~ errors or is inaudible ::

  The speech server needs attention before Emacs configuration is relevant.
  Follow
  @@texinfo:@ref{Backend Diagnostics And Ownership,Backend Diagnostics And Responsibilities}@@ until the check produces both its tone
  and speech.
- The audible check passes, but ``Emacsvox is ready'' is absent ::

  Run ~./bin/emacsvox --diagnose~ again from the same checkout and shell.
  Remove an unintended ~TTS_PROGRAM~ override if the report does not select
  ~omnivox~.  Then request an Emacs startup backtrace with:

  #+begin_example
  ./bin/emacsvox -- --debug-init
  #+end_example

  An error saying ~Could not find speech server executable~ means the
  speech server visible during that start cannot be executed.  Correct the
  reported speech-server path rather than adding more init-file configuration.
  For an Omnivox process error, inspect the private log directory described
  below.
- The ready message is heard, but speech later stops ::

  If Emacs reports that an Emacsvox speech server exited, inspect the Omnivox
  session log and type @@texinfo:@kbd{M-x tts-restart RET}@@ after correcting the
  speech-server problem.  Logs are below ~$XDG_STATE_HOME/emacsvox/omnivox~, defaulting to
  ~~/.local/state/emacsvox/omnivox~.  Spoken text is omitted unless explicit
  text logging is enabled.
- The isolated launcher works, but a customized Emacs start does not ::

  Remove or comment out the Emacsvox environment and ~load-file~ forms from
  the personal init file.  This is the rollback: it leaves the checkout and the
  known-good ~./bin/emacsvox~ path intact.  Re-add the forms in the order
  shown in @@texinfo:@ref{Persistent Startup}@@; speech-server selection must happen before
  setup is loaded.

** Persistent Startup
:PROPERTIES:
:TEXINFO_NODE_NAME: Persistent Startup
:DESCRIPTION: Add Emacsvox to personal configuration safely.
:END:

After @@texinfo:@ref{Confirming First Speech}@@ succeeds, add these forms to your Emacs
init file, replacing the example path with the absolute path of the checkout:

#+begin_src emacs-lisp
(setenv "TTS_PROGRAM" "omnivox")
(load-file "/path/to/emacsvox/lisp/emacsvox-setup.el")
#+end_src

Keep the forms in this order: Emacsvox selects and starts the speech server while
loading setup.  A shell alternative is to export the server name before
launching Emacs:

#+begin_example
export TTS_PROGRAM=omnivox
#+end_example

Keep the explicit ~load-file~ form for a changing source checkout.  Its
setup entry point can warn and prefer source when newer Lisp would otherwise
be hidden by stale local byte-code.  A customized startup should speak the
same ready message as the isolated launcher.  If it does not, remove or
comment out the two init forms and return to the isolated launcher before
trying another change.
