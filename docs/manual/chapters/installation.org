* Getting Started: Installation and First Speech
:PROPERTIES:
:TEXINFO_NODE_NAME: Installation
:ALT_TITLE: Installation
:DESCRIPTION: Install Emacsvox and reach first speech.
:END:

#+begin_export texinfo
@c Generated from docs/manual/emacsvox.org; do not edit.
#+end_export

This chapter takes you from a fresh source checkout to a speaking Emacsvox
session.  You will prepare the speech server, build Emacsvox, check each layer,
and start an isolated session before changing your personal Emacs setup.

Commands shown before Emacsvox starts are entered in a terminal.  Keys written
with @@texinfo:@kbd{C-}@@ or @@texinfo:@kbd{M-}@@ are entered inside Emacs.  The same chapter is
available before installation at
[[https://bartbunting.github.io/emacsvox/Installation.html]].

** Before You Begin
:PROPERTIES:
:TEXINFO_NODE_NAME: Obtaining Emacsvox
:DESCRIPTION: Prepare the tools and source checkouts.
:END:

Install ~git~, ~make~, GNU Texinfo (which provides ~makeinfo~), and
[[https://www.gnu.org/software/emacs/download.html][Emacs 31 or newer]].  The recommended Omnivox speech server also needs the
Rust toolchain, Python 3, a C and C++ toolchain, CMake, and Clang with libclang.

To check the Emacs found by your shell, run:

#+begin_example
emacs --version
#+end_example

The first line should begin with ~GNU Emacs 31~ or a higher version number.  If
the command is not found or reports an older version, install a supported Emacs
or locate its executable.  You can check a specific executable in the same way:

#+begin_example
/path/to/emacs-31/bin/emacs --version
#+end_example

On GNU/Linux, install ~pkg-config~ and the ALSA development headers.  On
macOS, install the Xcode command-line tools.  WSL2 has additional Docker and
Windows requirements described in @@texinfo:@ref{Building Omnivox For WSL2}@@.

Choose a permanent parent directory and clone Emacsvox and Omnivox beside one
another:

#+begin_example
cd /path/where/you/keep/source
git clone https://github.com/bartbunting/emacsvox
git clone https://github.com/bartbunting/omnivox
#+end_example

The Emacsvox checkout is the installation directory.  It builds in place and
does not create a second tree to copy elsewhere.

** Install And Check Omnivox
:PROPERTIES:
:TEXINFO_NODE_NAME: Building And Testing The Speech Server
:DESCRIPTION: Install the recommended server and hear its check.
:END:

On GNU/Linux or macOS, build and install Omnivox from its checkout:

#+begin_example
cd /path/where/you/keep/source/omnivox
make build
make install
omnivox --check
#+end_example

~make install~ normally places the executable below ~~/.cargo/bin~.  Make sure
that directory is on ~PATH~ before running the check.  No proprietary speech
runtime is needed for the recommended GNU/Linux or macOS route.

Under WSL2, build the staged Windows runtime from a clean Emacsvox checkout:

#+begin_example
cd /path/where/you/keep/source/emacsvox
make windows-omnivox
./servers/omnivox --check
#+end_example

The check plays a tone followed by speech.  When you hear both, the speech
server is ready.  If either is missing, use
@@texinfo:@ref{Backend Diagnostics And Ownership,Backend Diagnostics And Responsibilities}@@
before continuing.  @@texinfo:@xref{Speech Backends}@@ contains the complete platform
matrix, build details, and compatibility alternatives.  Native Windows Emacs
support remains a preview; consult that matrix before choosing it for a first
installation.

** Build And Start Emacsvox
:PROPERTIES:
:TEXINFO_NODE_NAME: Quick Installation
:ALT_TITLE: Quick Installation
:DESCRIPTION: Build Emacsvox and reach an isolated speaking session.
:END:

1. Enter the Emacsvox checkout:

   #+begin_example
   cd /path/where/you/keep/source/emacsvox
   #+end_example

1. Select Emacs 31 or newer.  If it is not the system ~emacs~, create the
   ignored local settings file:

   #+begin_example
   cp local.mk.example local.mk
   #+end_example

   Then set ~EMACS~ in ~local.mk~:

   #+begin_example
   EMACS=/path/to/emacs-31/bin/emacs
   #+end_example

   The earlier ~emacs --version~ command checks your shell's default.  Verify
   the executable selected by the Emacsvox build separately:

   #+begin_example
   make check-emacs
   #+end_example

   ~make check-emacs~ uses ~local.mk~ when present, prints the selected
   executable and version, and confirms whether Emacsvox supports it.

1. Configure and compile Emacsvox:

   #+begin_example
   make all
   #+end_example

   A successful build returns to the shell without an error.  Emacsvox must be
   compiled with the same supported Emacs selected in the previous step.

1. Run the non-audible launcher preflight from the Emacsvox checkout:

   #+begin_example
   ./bin/emacsvox --diagnose
   #+end_example

   This checks the checkout, Emacs, and speech server without playing audio or
   opening interactive Emacs.  A successful report names Emacs 31 or newer,
   the ~omnivox~ speech server, and an isolated ~-Q~ startup.  If it reports a
   path or version problem, correct that item and run the command again.

1. Check the complete launch path with sound:

   #+begin_example
   ./bin/emacsvox --check
   #+end_example

   The launcher prints what it selected, then plays a tone and speech.  Hearing
   both means the complete speech-server launch path is ready.

1. Start a clean Emacsvox session:

   #+begin_example
   ./bin/emacsvox
   #+end_example

   The launcher uses Omnivox and the selected Emacs, but does not load site
   files or your personal Emacs init file.  This gives you a known starting
   point without changing an existing Emacs setup.

If a command needs an explicit path, ~./bin/emacsvox --help~ describes the
~EMACS~, ~TTS_PROGRAM~, and ~EMACSVOX_DIR~ overrides.  Arguments after ~--~
are passed to Emacs.

** Confirming First Speech
:PROPERTIES:
:TEXINFO_NODE_NAME: Confirming First Speech
:DESCRIPTION: Verify the live adapter and basic feedback.
:END:

You will know the isolated start succeeded when it speaks an introduction
ending with:

#+begin_quote
I am completely operational, and all my circuits are functioning perfectly!
#+end_quote

The preceding overview key and version number can change.  The sentence above
is the stable first-speech checkpoint.  A startup auditory icon may also play,
depending on the available audio support.

You now have a working Emacsvox session.  Try these checks before connecting
it to your personal configuration:

1. Type @@texinfo:@kbd{M-x tts-speak-version RET}@@.  The live speech adapter should speak its
   version response.

1. Type @@texinfo:@kbd{C-h v tts-program RET}@@.  The displayed current value should name
   ~omnivox~.

1. Use @@texinfo:@kbd{C-n}@@ and @@texinfo:@kbd{C-p}@@ to move over lines and confirm ordinary spoken
   navigation.  Type @@texinfo:@kbd{M-x emacsvox-describe-emacsvox RET}@@ for the Emacsvox
   overview.  @@texinfo:@xref{Basic Usage}@@, for the tested starter commands.

When these checks pass, continue to @@texinfo:@ref{Basic Usage}@@ for a short guided
first session, or use @@texinfo:@ref{Persistent Startup}@@ to connect Emacsvox to your
normal Emacs configuration.

** Recovering From No Speech
:PROPERTIES:
:TEXINFO_NODE_NAME: Recovering From No Speech
:DESCRIPTION: Diagnose the boundary at which speech failed.
:END:

If speech did not start, keep the isolated launcher as your known starting
point and find the first command below that did not work:

#+attr_texinfo: :indic asis :compact t
- ~./bin/emacsvox --diagnose~ fails ::

  No audio or interactive Emacs has started.  Follow the reported selection:
  set ~EMACS~, correct ~EMACS=~ in ~local.mk~, or install Emacs 31
  or newer when the Emacs check fails.  When the speech backend is not
  executable, finish installing Omnivox, put it on ~PATH~, or set
  ~OMNIVOX_PROGRAM~ to its absolute executable.  Under WSL2, rebuild or
  verify the staged runtime described in @@texinfo:@ref{Building Omnivox For WSL2}@@.
- The diagnostic passes, but ~--check~ errors or is inaudible ::

  The speech server needs attention before Emacs configuration is relevant.
  Follow
  @@texinfo:@ref{Backend Diagnostics And Ownership,Backend Diagnostics And Responsibilities}@@ until the check produces both its tone
  and speech.
- The audible check passes, but the isolated startup sentence is absent ::

  Run ~./bin/emacsvox --diagnose~ again from the same checkout and shell.
  Remove an unintended ~TTS_PROGRAM~ override if the report does not select
  ~omnivox~.  Then request an Emacs startup backtrace with:

  #+begin_example
  ./bin/emacsvox -- --debug-init
  #+end_example

  An error saying ~Could not find speech server executable~ means the
  backend visible during that start cannot be executed.  Correct the reported
  backend path rather than adding more init-file configuration.  For an Omnivox
  process error, inspect the private log directory described below.
- The startup sentence is heard, but speech later stops ::

  If Emacs reports that an Emacsvox speech server exited, inspect the Omnivox
  session log and type @@texinfo:@kbd{M-x tts-restart RET}@@ after correcting the backend
  problem.  Logs are below ~$XDG_STATE_HOME/emacsvox/omnivox~, defaulting to
  ~~/.local/state/emacsvox/omnivox~.  Spoken text is omitted unless explicit
  text logging is enabled.
- The isolated launcher works, but a customized Emacs start does not ::

  Remove or comment out the Emacsvox environment and ~load-file~ forms from
  the personal init file.  This is the rollback: it leaves the checkout and the
  known-good ~./bin/emacsvox~ path intact.  Re-add the forms in the order
  shown in @@texinfo:@ref{Persistent Startup}@@; backend selection must happen before setup
  is loaded.

** Persistent Startup
:PROPERTIES:
:TEXINFO_NODE_NAME: Persistent Startup
:DESCRIPTION: Add Emacsvox to personal configuration safely.
:END:

After @@texinfo:@ref{Confirming First Speech}@@ succeeds, add these forms to your Emacs
init file, replacing the example path with the absolute path of the checkout:

#+begin_src emacs-lisp
(setenv "TTS_PROGRAM" "omnivox")
(load-file "/path/to/emacsvox/lisp/emacsvox-setup.el")
#+end_src

Keep the forms in this order: Emacsvox selects and starts the speech server while
loading setup.  A shell alternative is to export the server name before
launching Emacs:

#+begin_example
export TTS_PROGRAM=omnivox
#+end_example

Keep the explicit ~load-file~ form for a changing source checkout.  Its
setup entry point can warn and prefer source when newer Lisp would otherwise
be hidden by stale local byte-code.  A customized startup should speak the
same acceptance sentence as the isolated launcher.  If it does not, remove or
comment out the two init forms and return to the isolated launcher before
trying another change.
