* Getting Started: Installation and First Speech
:PROPERTIES:
:TEXINFO_NODE_NAME: Installation
:ALT_TITLE: Installation
:DESCRIPTION: Install Emacsvox and reach first speech.
:END:

#+begin_export texinfo
@c Generated from docs/manual/emacsvox.org; do not edit.
#+end_export

This is the canonical first-use procedure for a source-checkout installation.
It starts before Emacsvox is available, establishes an audible acceptance
checkpoint, and delays personal configuration until an isolated session has
spoken successfully.  The same chapter is published for pre-installation web
access at
[[https://bartbunting.github.io/emacsvox/Installation.html]].

** Obtaining Emacsvox
:PROPERTIES:
:TEXINFO_NODE_NAME: Obtaining Emacsvox
:DESCRIPTION: Obtaining Emacsvox.
:END:

Before beginning, install ~git~, ~make~, GNU Texinfo (which
provides ~makeinfo~), and
[[https://www.gnu.org/software/emacs/download.html][Emacs 31 or newer]].
The Speech Backends chapter lists the additional platform prerequisites for
the recommended Omnivox server.

The maintained source is
[[https://github.com/bartbunting/emacsvox]].  Clone it into the permanent
directory where it will be used:

#+begin_example
git clone https://github.com/bartbunting/emacsvox
cd emacsvox
#+end_example

The checkout itself is the source-checkout installation.  The build operates
in place; it does not create a second directory to copy elsewhere.

** First Speech Checklist
:PROPERTIES:
:TEXINFO_NODE_NAME: Quick Installation
:ALT_TITLE: Quick Installation
:DESCRIPTION: Reach an isolated first spoken session.
:END:

1. Select Emacs 31 or newer.  If it is not the system ~emacs~, copy
   ~local.mk.example~ to the ignored ~local.mk~ and set ~EMACS~:

   #+begin_example
   EMACS=/path/to/emacs-31/bin/emacs
   #+end_example

   Verify the selection before diagnosing a compiler failure:

   #+begin_example
   make check-emacs
   #+end_example

1. Configure and compile the checkout:

   #+begin_example
   make all
   #+end_example

   Do not compile Emacsvox with an older system Emacs.  Tests prefer source and
   therefore do not prove that the byte-code used by a normal startup is current.

1. Install the recommended Omnivox speech server.  @@texinfo:@xref{Speech Backends}@@, for
   the supported platform matrix, exact prerequisite classes, source and WSL2
   build paths, and compatibility alternatives.

1. Run the non-audible launcher preflight from the Emacsvox checkout:

   #+begin_example
   ./bin/emacsvox --diagnose
   #+end_example

   It validates the checkout, Emacs, and backend without playing audio, creating
   an Omnivox session log, or opening interactive Emacs.  Before continuing,
   confirm that its report includes Emacs 31 or newer, the ~omnivox~ speech
   backend, and an isolated ~-Q~ startup.  Correct any path or version
   error that it prints.

1. Run the deliberately audible backend check:

   #+begin_example
   ./bin/emacsvox --check
   #+end_example

   The launcher prints its selections and explicitly announces that the audible
   check is starting.  Continue only after hearing both the tone and speech.  Do
   not diagnose Emacs configuration until this standalone Omnivox check passes.

1. Prove a clean Emacsvox start:

   #+begin_example
   ./bin/emacsvox
   #+end_example

   The launcher defaults to Omnivox, uses the selected Emacs 31 or newer, and
   loads the setup source by its absolute path.  The session uses ~-Q~: it
   loads neither site files nor a personal Emacs init file.  This makes first
   speech a reproducible installation proof rather than a side effect of
   existing configuration.

   ~./bin/emacsvox --diagnose~ prints the selected root, setup source,
   Emacs version, and backend without playing audio or starting interactive
   Emacs.  ~./bin/emacsvox --help~ documents explicit ~EMACS~,
   ~TTS_PROGRAM~, and ~EMACSVOX_DIR~ overrides.  Arguments after
   ~--~ are passed to Emacs.

** Confirming First Speech
:PROPERTIES:
:TEXINFO_NODE_NAME: Confirming First Speech
:DESCRIPTION: Verify the live adapter and basic feedback.
:END:

A successful isolated start speaks a versioned introduction ending with:

#+begin_quote
I am completely operational, and all my circuits are functioning perfectly!
#+end_quote

The preceding overview key and version number can change.  The sentence above
is the stable first-speech checkpoint.  A startup auditory icon may also play,
but it depends on optional audio support and is not part of acceptance.

Before changing personal configuration, make these checks in the isolated
session:

1. Type @@texinfo:@kbd{M-x tts-speak-version RET}@@.  The live speech adapter should speak its
   version response.

1. Type @@texinfo:@kbd{C-h v tts-program RET}@@.  The displayed current value should name
   ~omnivox~.

1. Use @@texinfo:@kbd{C-n}@@ and @@texinfo:@kbd{C-p}@@ to move over lines and confirm ordinary spoken
   navigation.  Type @@texinfo:@kbd{M-x emacsvox-describe-emacsvox RET}@@ for the Emacsvox
   overview.  @@texinfo:@xref{Basic Usage}@@, for the tested starter commands.

Only after these checks pass is the isolated first-use proof complete.

** Recovering From No Speech
:PROPERTIES:
:TEXINFO_NODE_NAME: Recovering From No Speech
:DESCRIPTION: Diagnose the boundary at which speech failed.
:END:

Do not add Emacsvox to a personal init file while recovering.  Start at the
first failing boundary:

#+attr_texinfo: :indic asis :compact t
- ~./bin/emacsvox --diagnose~ fails ::

  No audio or interactive Emacs has started.  Follow the reported selection:
  set ~EMACS~, correct ~EMACS=~ in ~local.mk~, or install Emacs 31
  or newer when the Emacs check fails.  When the speech backend is not
  executable, finish installing Omnivox, put it on ~PATH~, or set
  ~OMNIVOX_PROGRAM~ to its absolute executable.  Under WSL2, rebuild or
  verify the staged runtime described in @@texinfo:@ref{Building Omnivox For WSL2}@@.
- The diagnostic passes, but ~--check~ errors or is inaudible ::

  The failure is below Emacsvox.  Do not edit the Emacs init file.  Follow
  @@texinfo:@ref{Backend Diagnostics And Ownership}@@ until the check produces both its tone
  and speech.  A zero exit status without both audible signals is not success.
- The audible check passes, but the isolated startup sentence is absent ::

  Run ~./bin/emacsvox --diagnose~ again from the same checkout and shell.
  Remove an unintended ~TTS_PROGRAM~ override if the report does not select
  ~omnivox~.  Then request an Emacs startup backtrace with:

  #+begin_example
  ./bin/emacsvox -- --debug-init
  #+end_example

  An error saying ~Could not find speech server executable~ means the
  backend visible during that start cannot be executed.  Correct the reported
  backend path rather than adding more init-file configuration.  For an Omnivox
  process error, inspect the private log directory described below.
- The startup sentence is heard, but speech later stops ::

  If Emacs reports that an Emacsvox speech server exited, inspect the Omnivox
  session log and type @@texinfo:@kbd{M-x tts-restart RET}@@ after correcting the backend
  problem.  Logs are below ~$XDG_STATE_HOME/emacsvox/omnivox~, defaulting to
  ~~/.local/state/emacsvox/omnivox~.  Spoken text is omitted unless explicit
  text logging is enabled.
- The isolated launcher works, but a customized Emacs start does not ::

  Remove or comment out the Emacsvox environment and ~load-file~ forms from
  the personal init file.  This is the rollback: it leaves the checkout and the
  known-good ~./bin/emacsvox~ path intact.  Re-add the forms in the order
  shown in @@texinfo:@ref{Persistent Startup}@@; backend selection must happen before setup
  is loaded.

** Persistent Startup
:PROPERTIES:
:TEXINFO_NODE_NAME: Persistent Startup
:DESCRIPTION: Add Emacsvox to personal configuration safely.
:END:

Configure a normal customized start only after @@texinfo:@ref{Confirming First Speech}@@
passes.  Add these forms to the user's Emacs init file, replacing the example
path with the absolute path of the checkout:

#+begin_src emacs-lisp
(setenv "TTS_PROGRAM" "omnivox")
(load-file "/path/to/emacsvox/lisp/emacsvox-setup.el")
#+end_src

The order is significant: Emacsvox selects and starts the speech server while
loading setup.  A shell alternative is to export the server name before
launching Emacs:

#+begin_example
export TTS_PROGRAM=omnivox
#+end_example

Keep the explicit ~load-file~ form for a changing source checkout.  Its
setup entry point can warn and prefer source when newer Lisp would otherwise
be hidden by stale local byte-code.  A customized startup should speak the
same acceptance sentence as the isolated launcher.  If it does not, remove or
comment out the two init forms and return to the isolated launcher before
trying another change.

Emacsvox distributions contain the ~.el~ sources.  ~make all~
generates ignored ~.elc~ files locally in the checkout; those build
outputs are not distributed.  After an ordinary Lisp edit, run
~make bytecode~.  After switching branches, pulling, or changing Lisp
macros or public interfaces, run ~make bytecode-rebuild~.  The
non-mutating ~make bytecode-check~ verifies that local byte-code is
current and was produced by the selected Emacs.

** Building And Testing The Speech Server
:PROPERTIES:
:TEXINFO_NODE_NAME: Building And Testing The Speech Server
:END:

Speech-server launchers live in ~servers/~.  Build them through the
repository-root targets above so the selected paths and staging rules remain
consistent.

The Omnivox smoke test and its audible success condition are in
@@texinfo:@ref{Selecting And Checking Omnivox}@@.  The following protocol-level test is
only for retained direct Tcl-compatible servers.  Run one of those launchers
from the repository root, for example:

#+begin_example
./servers/espeak
#+end_example

Then enter:

#+begin_example
q {This is a test.}
d
s
#+end_example

The ~q~ command queues text, ~d~ dispatches it, and ~s~ stops
speech.  Type @@texinfo:@kbd{C-d}@@ to close the server.  Backend-specific READMEs may
provide stronger diagnostics and should take precedence over this generic
smoke test.

From Emacs, use ~M-x tts-speak-version~ to verify the selected adapter and
~M-x tts-restart~ after changing server configuration.  Omnivox also
records per-process diagnostic logs below
~$XDG_STATE_HOME/emacsvox/omnivox~, defaulting to
~~/.local/state/emacsvox/omnivox~; spoken text is omitted unless explicit
text logging is enabled.
