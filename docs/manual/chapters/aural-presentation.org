* Aural Presentation: Speech, Voices, And Sound
:PROPERTIES:
:TEXINFO_NODE_NAME: Aural Presentation
:ALT_TITLE: Aural Presentation
:DESCRIPTION: Understand and adjust how Emacsvox conveys meaning.
:END:

#+cindex: Aural Presentation

Aural Presentation is the Emacsvox system that decides /how/ information and
events should be heard.  It can combine spoken text, voice changes, auditory
icons, tones, pauses, and spatial cues in one ordered presentation.  The speech
server delivers that result; it does not decide what a heading, unread message,
completed command, warning, or other object means.

You do not need to configure Aural Presentation before using Emacsvox.  The
built-in baseline and application integrations provide useful defaults.  When
you do want a change, start from the object you heard and use Aural Home rather
than editing configuration data by hand:

#+attr_texinfo: :indic kbd :compact t
- C-e H ::

  Open Aural Home, the spoken control center for understanding, adjusting, and
  diagnosing presentation.

- C-e E ::

  Explain why the object at point received its voices, sounds, and other
  actions.

This chapter starts with a short listening task, then explains how to change
feedback and manage voices, sounds, and saved setups. You can follow it in
order or open a task directly from its Info menu. In an Aural interface,
@@texinfo:@kbd{C-c C-i}@@ opens the relevant manual topic;
@@texinfo:@kbd{q}@@ in Info returns to the interface. In interface Help,
@@texinfo:@kbd{i}@@ opens the same topic.

** Getting Started With Aural Home
:PROPERTIES:
:TEXINFO_NODE_NAME: Aural Home
:ALT_TITLE: Aural Home
:DESCRIPTION: Navigate the spoken presentation control center.
:END:

#+cindex: Aural Home

For a first listening experiment:

1. Press @@texinfo:@kbd{C-e H}@@, then @@texinfo:@kbd{/}@@, and choose
   /Browse installed voices/ from the searchable actions.
2. Select an available engine and press @@texinfo:@key{RET}@@ to list its voices.
3. Move to a voice and press @@texinfo:@kbd{P}@@ to hear a sample.
   @@texinfo:@kbd{S}@@ stops it. Browsing and previewing save no settings.
4. Press @@texinfo:@kbd{h}@@ to return to Home. From Home,
   @@texinfo:@kbd{C-c C-o}@@ returns to the item where you started.

If an engine is unavailable, its details explain why; try another available
engine. If no speech is available, start with
[[info:emacsvox#Recovering From No Speech][Recovering From No Speech]].

Open Aural Home from an ordinary buffer with @@texinfo:@kbd{C-e H}@@.  Emacsvox
remembers that source buffer and opening position so contextual actions such
as explanation and remapping operate on the object you were using.  Moving
the source cursor while Home is open does not change this target.  In Home,
@@texinfo:@kbd{C-c C-o}@@ returns to it.  To choose a new target, invoke
@@texinfo:@kbd{C-e H}@@ afresh from that item in an ordinary buffer.

Returning through Home or Help preserves the selected row and unfinished
edits.  Buffer rule editors retain separate drafts for each source buffer;
reopening a modified editor resumes its draft.  Reopening the same voice in
the voice editor likewise preserves its working settings.  If a prepared remap's
source item changes or disappears, Emacsvox asks you to prepare that change
again before applying it.

Aural Home begins with six task groups in one spoken table.  Press
@@texinfo:@key{RET}@@ or @@texinfo:@key{TAB}@@ to expand or collapse a group.
Each action names a destination, reports its current status, and describes
its purpose.  @@texinfo:@kbd{/}@@ searches all actions, including collapsed
groups; the matching group opens with your destination selected.

Expandable groups announce an open or close cue with their name when you
reach or toggle them. These cues follow the icon setting and sound pack.
For spoken state words, enable
/aural-panel-state-labels/ in /Presentation Options/.  This adds ``collapsed''
or ``expanded'' after the control through the normal presentation rules.
Key instructions remain available in Help.

Panel entry, return, selection, and warning cues accompany their spoken
feedback in one utterance.  Returning from a panel announces the destination
and any unfinished draft warning together.  These cues follow the icon
setting, sound pack, and cue remapping rules.
The voice editor uses the normal navigation voice for these announcements;
auditions still play the working voice.

In Home and other tables, the navigation controls are:

#+attr_texinfo: :indic kbd :compact t
- n, p, down, up :: Move by row, retaining and speaking the selected column.
  In the first column, settings lists announce the name and current state.
- left, right :: Move among the titled columns.
- . :: Speak the current column title and value.
- SPC :: Speak the complete current row.
- RET :: Open a destination, child list, or details.
- C-c C-a :: Choose an applicable action by name.
- N :: Create a new item where supported.
- P :: Preview in managers and editors; Home retains its profiles shortcut.
- S :: Stop the preview and its remaining samples.
- ? :: Display and speak help for the current Aural interface.
- h :: Return to Aural Home from a manager or editor.
- q :: Go back or leave; an editor may first offer to retain or discard changes.

The six groups are:

#+attr_texinfo: :columns 0.35 0.65
| Task group | Destinations |
| Understand and change feedback | Explain this item, Change this feedback, Recent aural feedback, contextual voice and sound changes, semantic vocabulary, and return to source. |
| Voices and speech | Voice palettes, Browse installed voices, Preferred speech engine, Speech rate, and Voice Workbench. |
| Sounds and output | Sound packs, Spatial settings, Notification output, Review notifications, and Stop notification speech. |

| Troubleshooting | Aural Doctor, Spatial capabilities, and Omnivox engine modules. |

The header identifies the captured source and the number of unfinished drafts.
Choose /Resume unfinished changes/ to visit the original rule editor, voice editor,
or Workbench engine settings.  The draft is still unsaved until you accept it there.
Presentation Profiles capture options, palette, sound pack, and spatial
settings. Physical choices and their adjustments belong to the selected
palette's named voices; shared engine settings are saved separately.

You can press @@texinfo:@key{RET}@@ on a row without memorizing its shortcut.  Aural
Home also provides direct keys for frequent routes, including @@texinfo:@kbd{x}@@ for
explanation, @@texinfo:@kbd{O}@@ for your feedback rules, @@texinfo:@kbd{H}@@ for recent feedback,
@@texinfo:@kbd{P}@@ for profiles, @@texinfo:@kbd{V}@@ for voice palettes, @@texinfo:@kbd{W}@@ for
Voice Workbench, and @@texinfo:@kbd{D}@@ for Aural Doctor.

The voice editor contains fields and buttons rather than table columns:
left/right changes a numeric value, and @@texinfo:@key{RET}@@ edits a field.
See [[info:emacsvox#Editing Named Voices][Edit a Named Voice]]. Keys are local to the view: for example,
@@texinfo:@kbd{w}@@ saves a voice in its editor but exports a palette in the
palette manager. Use @@texinfo:@kbd{C-c C-a}@@ to choose an action by name,
or @@texinfo:@kbd{?}@@ for that view's current keys.

** How Aural Presentation Works
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Model
:ALT_TITLE: Presentation Model
:DESCRIPTION: Follow meaning from an Emacs application to audible output.
:END:

#+cindex: presentation model

It helps to separate four questions that are often mixed together:

#+attr_texinfo: :columns 0.22 0.30 0.48
| Layer | Question | Example |
| Meaning | What happened or what is this? | A level-two heading was reached during navigation. |
| Presentation | What should convey that meaning? | Speak the heading in a named voice and play a section cue first. |
| Resources | Which voice and sound realize that request? | Find the named voice in the active palette and the cue in the active sound pack. |
| Output | What can this machine produce? | Route speech to an installed engine and apply supported spatial behavior. |

An Emacs mode or Emacsvox integration supplies facts about an object or event.
Facts can describe a role such as a heading, an event such as completion, a
state such as unread, or an attribute such as heading level.  Context also says
whether you are navigating, reading continuously, or receiving a state change.
This allows the same object to receive concise feedback during continuous
reading and more orientation when you move to it deliberately.

Presentation rules match those facts and context.  A rule can choose a voice,
add speech or a cue, insert a pause or tone, request spatial placement, or
suppress something that is unhelpful.  Several matching rules can compose; a
stronger, narrower rule need change only the relevant part rather than repeat
the complete presentation.

The user-visible configuration layers are:

1. A fixed internal baseline that preserves established Emacsvox behavior.

2. Automatic integration behavior supplied by the active mode or package.

3. Enabled /Presentation Options/ that add optional behavior in a stable
   weakest-to-strongest order.

4. Personal, session, and current-buffer rules. These are the strongest
   layers and are intended for precise changes. They are also called
   /overrides/ because they can replace weaker behavior.

A presentation profile is not another rule layer.  It records the
selected options, sound pack, voice palette, and spatial choices so you can
switch those choices together.

For example, an Org integration identifies a level-two heading. A rule asks
for ~bolden~ and a section cue. The active palette supplies ~bolden~'s voice
settings and physical choices; the active sound pack supplies the cue. The
speech backend plays what it supports. Changing the rule changes which
headings get that feedback. Editing ~bolden~ changes the voice wherever that
entry is used. Switching sound packs changes the cue's recording while
preserving its meaning.

When two rules change the same voice field, the stronger explicit value wins;
values are not added. Personal rules are weaker than session rules, which are
weaker than current-buffer rules. Rules can also add actions before or after
the content. Use Explain to see the actual contributors and winning values
rather than inferring them from the order in which you made edits.

*** What You Can Hear
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Modalities
:ALT_TITLE: Presentation Modalities
:DESCRIPTION: Recognize speech, voices, cues, tones, pauses, and spatial output.
:END:

#+cindex: presentation modalities

Aural Presentation can use one or more of these forms of feedback:

- /Speech/ conveys content, labels, prompts, results, and status.  Added speech
  should explain meaning that is not already clear from the content.

- /Voice/ changes characteristics of spoken content.  Named voices
  make distinctions such as headings, annotations, warnings, or quoted text
  portable across speech engines.

- /Auditory cues/, also called /earcons/ or /auditory icons/, are short sounds
  associated with events or objects. A sound pack supplies the recordings for
  those cue names.

- /Tones/ convey compact information using a named pitch and duration.  They
  are useful when a short distinction is preferable to speech or a sampled
  sound.

- /Pauses/ separate related parts of a presentation without adding words.

- /Spatial presentation/ can place speech or cues across supported output.
  When the selected backend cannot provide the requested placement, Emacsvox
  keeps the content audible using its documented fallback.

These forms can be ordered around the content.  For example, entering a section
might play a cue, speak the heading in a distinctive voice, and leave a short
pause before body text.  The presentation is one result, not several unrelated
notifications.

The precise sound may vary by speech engine, installed voices, sound pack, and
audio hardware.  The intended distinction should remain understandable even
when a simpler backend uses fewer voice characteristics or centered output.

** Understand Why Something Sounded That Way
:PROPERTIES:
:TEXINFO_NODE_NAME: Explaining Presentation
:ALT_TITLE: Explaining Presentation
:DESCRIPTION: Explain current or recently queued feedback.
:END:

#+cindex: explaining presentation

Use this workflow when feedback is surprising, unclear, or especially useful:

1. Leave point on the object and press @@texinfo:@kbd{C-e E}@@, or choose
   /Explain this item/ in Aural Home. Both open /Feedback Details/ with a brief
   announcement rather than speaking the complete explanation.

2. Read the explanation as a report of the object and occasion, matching
   presentation rules, selected actions, concrete voices and sounds, and any
   backend fallback or degradation.

3. Note the strongest rule that changed the part you care about.  This tells
   you whether to inspect an option, a personal or temporary rule, a named voice, a sound pack,
   or the Voice Lock compatibility layer.

When a retained presentation still matches the source buffer, position, and
unchanged source text, the explanation
describes the exact output that was queued, including its source location and
resolved resources.  It does not reinterpret that old output using your latest
settings.  Without an exact record, Emacsvox labels the explanation as a
simulation of what the current rules would produce at point. The simulation
uses captured source text and context; /Play simulation/ plays that baseline,
not a recording of something you previously heard. It supports the same field
review and draft previews as recorded feedback, and is never added to Recent
Feedback. Use a prefix argument with @@texinfo:@kbd{C-e E}@@ to choose a
simulated occasion explicitly. Press @@texinfo:@kbd{q}@@ to return to the
source position or Home row from which you opened the report.

To inspect something heard earlier, open Aural Home and choose /Recent Aural
Feedback/, or press @@texinfo:@kbd{H}@@ there.  Each row preserves a recorded presentation; the history has a size limit.
Moving through the Content column speaks the preview using its recorded voices,
including voice changes within an entry.  Column titles and the other fields use
the normal interface voice.
Useful commands in the feedback browser include:

#+attr_texinfo: :indic kbd :compact t
- RET or e :: Open a readable Feedback Details buffer for the selected presentation.
- P :: Replay its complete ordered presentation without adding a history entry.
- c :: Audition only its auditory cues.
- r :: Prepare a voice remap from the selected record.
- R :: Replace, suppress, or restore one exact earcon.
- L :: Change the bounded history limit for the current session.

/Feedback Details/ selects a separate, read-only buffer and announces only a
brief introduction. Its report stays attached to that recorded presentation
while new feedback arrives. Ordinary Help commands do not replace the report.
Press @@texinfo:@kbd{q}@@ to return to the same row and column in Recent Feedback.

The report groups consecutive voice spans into semantic fields where the
integration supplies them. In a Notmuch search result, for example, you can
visit /Authors/, /Subject/, /Date/, /Message count/, and /Tags/. Headings identify
the recorded voices. Collapsed fields show only their headings. Visibility is
conveyed through the selected aural presentation, using earcons or optional
spoken labels; the words /expanded/ and /collapsed/ are not inserted into the
heading text. Press
@@texinfo:@kbd{RET}@@ on a heading to reveal its text, playback and change
controls, voice source, sounds, and any backend limitations. Field content is
read in its recorded voices. Only fields with multiple spans show separate
span sections; a single-span field shows its text and controls once. Press
@@texinfo:@kbd{RET}@@ on the field heading again to collapse it.

#+attr_texinfo: :indic kbd :compact t
- n or p :: Move between headings. Collapsed fields speak only their heading; expanded fields also speak their content in the recorded voices.
- Up or Down :: Review individual lines without speaking the complete report.
- TAB or Shift-TAB :: Move between action buttons; RET activates an action or expands a field.
- O :: Play the original field or span at point, including its recorded actions.
- P :: Play the complete recorded presentation.
- C :: Open or resume a change to the selected field or distinguishable span.
- V :: Preview the complete presentation with all linked draft changes.
- S :: Stop playback.

For example, select /Subject/, press @@texinfo:@kbd{C}@@, and choose another
content voice. In that editor, @@texinfo:@kbd{P}@@ previews the changed field
and @@texinfo:@kbd{V}@@ previews it within the whole line. Return to the report
and select /Message count/ to add a sound /After content/. The sound is placed
once after the complete count, even when that field contains several voices.
The subject and count editors retain their drafts separately. Their matching
criteria identify the field, integration, mode, and occasion; inspect those
criteria before choosing a buffer, session, or saved personal lifetime.
Changing a field's voice mapping does not retune the shared named voice.

Original playback uses retained output; a simulated report labels its baseline
playback as simulated throughout the report and linked change editor.
Proposed playback uses current rules,
captured buffer context, and the linked drafts without applying them. A span
can be targeted separately only when its semantic field, a distinct named
face, or an explicit voice annotation identifies it. Truncated history cannot provide complete playback or a
comparable change preview. Older records missing preview inputs remain
readable and replayable when complete; navigate over the source again to
capture a new example before previewing changes.

Each expanded field explains where its voice and sounds came from, such as
a visual face or your personal override. These explanations use the captured
sources that actually contributed to that field. Limitations, such as an
unsupported voice family, appear beside the affected field.

/Debug details/ opens the raw snapshot in a separate read-only buffer for
troubleshooting. It contains all recorded facts, rule identifiers, resolved
voice properties, and backend diagnostics. Opening it speaks only a brief
announcement. Press @@texinfo:@kbd{q}@@ to return to the same place in Feedback
Details; the report keeps its expanded fields and linked drafts.

/Explain feedback as you navigate/, available from Aural Home, speaks concise semantic explanations
after normal presentations.  It can help while learning the vocabulary used by
an integration, but is intentionally more verbose than ordinary operation;
turn it off when you no longer need the additional labels.

*** Walkthrough: Change Headings In One Buffer
:PROPERTIES:
:TEXINFO_NODE_NAME: Heading Voice Walkthrough
:ALT_TITLE: Walkthrough: Change Headings In One Buffer
:DESCRIPTION: Try a heading voice, verify the scope, and undo the rule.
:END:

This example changes headings in a temporary Org buffer. It leaves your
palette definitions and saved rules alone.

1. Use @@texinfo:@kbd{C-x b}@@ to create a new buffer named ~*aural-practice*~. Run
   @@texinfo:@kbd{M-x org-mode}@@ and insert this short document:

   #+begin_example
   * Reading notes
   An ordinary paragraph.
   * Next steps
   Another ordinary paragraph.
   #+end_example

2. Move onto the first heading and press @@texinfo:@kbd{C-e E}@@. Find its current named
   voice and the facts identifying a heading. The explanation should tell
   you whether it describes recorded output or a simulation.

3. Open @@texinfo:@kbd{C-e H c}@@. Press @@texinfo:@kbd{c}@@, select /Content voice/, and choose
   ~annotate~ with @@texinfo:@kbd{RET}@@. If ~annotate~ is already the original, use
   ~bolden~ instead. @@texinfo:@kbd{O}@@ plays the original and @@texinfo:@kbd{P}@@ previews your choice.
   At this point the change exists only in the draft.

4. Press @@texinfo:@kbd{m}@@ to inspect /What should match/. Keep the Org module and
   heading role, plus heading level if shown. Leave other criteria as shown
   for this first example. Press @@texinfo:@kbd{l}@@ and choose /Current buffer, until it
   is killed/. This means every matching heading in this buffer, not just
   the heading you started from.

5. Review the summary, then press @@texinfo:@kbd{a}@@. Return through Home with @@texinfo:@kbd{h}@@,
   then @@texinfo:@kbd{C-c C-o}@@. Move between the two headings using the same navigation
   action. Both matching headings should use your chosen voice; the ordinary
   paragraphs should keep their previous presentation.

6. Press @@texinfo:@kbd{C-e E}@@ on a heading again. Check that the new buffer rule supplies
   the selected voice. If the sound is too similar to distinguish, the
   explanation still tells you whether the rule matched; compare voices in
   the palette or consult [[info:emacsvox#Presentation Troubleshooting][Troubleshooting]].

7. To undo, open Home's /Your feedback rules/ with @@texinfo:@kbd{O}@@. Find the new rule
   in the buffer scope and inspect its target. Press @@texinfo:@kbd{t}@@ to disable it or
   @@texinfo:@kbd{d}@@ to remove it, then revisit the heading. Killing this practice buffer
   also ends its buffer rules. Nothing from this example survives a restart.

For a permanent change, repeat the task on a representative item and choose
/Saved personal rule/ at step 4. Review the matching criteria carefully:
a permanent rule can affect future matching buffers too.

*** Guided Change This Feedback
:PROPERTIES:
:TEXINFO_NODE_NAME: Guided Feedback Changes
:ALT_TITLE: Guided Change This Feedback
:DESCRIPTION: Learn the controls and scope of this task.
:END:

1. Move to a representative item, press @@texinfo:@kbd{C-e H}@@, then
   @@texinfo:@kbd{c}@@.  This captures /Current item/.  For feedback that has
   already happened, use Home's @@texinfo:@kbd{H}@@, select a /Recent Feedback/
   record, and press @@texinfo:@kbd{C}@@.  A record containing several parts
   expands numbered parts in playback order.  Move with @@texinfo:@kbd{n}@@
   and @@texinfo:@kbd{p}@@ to hear their text in the captured voices;
   @@texinfo:@kbd{O}@@ replays the part at point.  Press @@texinfo:@kbd{RET}@@
   to select it.  Truncated history cannot supply a complete
   original/proposed comparison.

2. Press @@texinfo:@kbd{c}@@ to expand component changes in the panel.
   Move to a choice and press @@texinfo:@kbd{RET}@@.  /Content voice/ expands
   voice choices and identifies the original voice and proposed replacement.
   The original named voice comes first when available, followed by alternatives
   in alphabetical order.  Press @@texinfo:@kbd{RET}@@ on a voice to select it
   for the draft; the panel stays open for comparison.  Available changes
   include the content voice, adding a sound or tone, adding a spoken label,
   replacing an existing sound, changing a tone, or suppressing one component.
   You can add a cue when the original has none.  The choices use the facts
   and components supplied by the integration; they cannot add missing
   semantic distinctions.
   @@texinfo:@kbd{RET}@@ on /Parts/ reopens the parts; unfinished choices are
   retained separately when you switch between parts.
   Press @@texinfo:@kbd{q}@@ to go back one level: from a voice choice to
   /Content voice/, then to /Change/.  The section closes and focus returns
   to its parent, whose name and state are presented through the configured
   cues and optional spoken labels.  At the top level,
   @@texinfo:@kbd{q}@@ leaves the panel and preserves the unfinished draft.

3. Press @@texinfo:@kbd{P}@@ to hear the proposed change before choosing how
   long to keep it.  @@texinfo:@kbd{O}@@ plays the recorded original example;
   @@texinfo:@kbd{S}@@ stops.  Proposed preview resolves the selected example
   with current rules and its captured buffer context.  It does not apply
   your draft to live feedback.

4. Press @@texinfo:@kbd{m}@@ or @@texinfo:@kbd{RET}@@ on /What should match/
   to expand the matching criteria.  Each fact, state, event, and occasion
   shows whether it is included.  Press @@texinfo:@kbd{RET}@@ on a criterion
   to exclude or include it; excluded criteria stay available to restore.
   For example, exclude /state unread/ while keeping /role field/,
   /field kind authors/, and /module notmuch/ to match authors in both read
   and unread messages.  Keep at least one criterion.  The parent row shows
   the resulting match; @@texinfo:@kbd{m}@@ collapses the criteria again.
   These are rules for every matching item, not an edit to one object.

5. Press @@texinfo:@kbd{l}@@ for /How long/: the source buffer's lifetime,
   this Emacs session, or a saved personal rule.  A buffer rule affects every
   matching item in that buffer.  Review the spoken summary of target,
   change, matching criteria, and lifetime.

6. Press @@texinfo:@kbd{a}@@ or @@texinfo:@kbd{C-c C-c}@@ to apply or save.
   @@texinfo:@kbd{e}@@ instead opens the prepared rule in the Advanced editor.
   At the top level, @@texinfo:@kbd{q}@@ hides the guided draft; Home's /Resume unfinished
   changes/ brings it back.  Aborting a choice or leaving before Apply does
   not change live rules.  Failed saves retain the draft and report failure.

Replacing or suppressing a sound targets its identity in its before- or
after-content phase, retaining other components.  Existing rule data can
insert only at the beginning or end of a phase; replacing a middle component
therefore asks which edge to use and includes that placement in the summary.
Ambiguous components require the Advanced editor.  Current-item changes
recheck their captured source before applying; a changed or killed target
must be inspected again.  Historical changes remain tied to the selected
recorded example.

*** Remap One Item At Point
:PROPERTIES:
:TEXINFO_NODE_NAME: Choosing A Voice For An Item
:ALT_TITLE: Remap One Item At Point
:DESCRIPTION: Learn the controls and scope of this task.
:END:

1. Move to a representative object and press @@texinfo:@kbd{C-e E}@@ so you know what
   currently controls it.

2. Press @@texinfo:@kbd{C-e H}@@.  Choose /Choose a voice for this item/ with
   @@texinfo:@kbd{r}@@ to use a different named voice here, or /Edit the named voice used
   here/ with @@texinfo:@kbd{T}@@ to open the current named voice in the common voice editor.
   Tuning changes that voice wherever it is used in the palette; remapping
   changes which voice is used for the face or item.  For example, at a shell
   prompt you can assign another voice to the prompt face, or tune the voice
   currently used by prompts.  You do not need to hear the prompt first.

   In the remapping screen, move with @@texinfo:@kbd{n}@@ and
   @@texinfo:@kbd{p}@@ or the arrow keys.  Press @@texinfo:@kbd{RET}@@ on
   /Voice/ to choose a voice, /Preview original/ to hear the captured item, or
   /Preview change/ to hear your choice.  @@texinfo:@kbd{O}@@ and
   @@texinfo:@kbd{P}@@ also play these previews; @@texinfo:@kbd{S}@@ stops.
   Previewing does not save the mapping or retune the named voice.

   @@texinfo:@kbd{R}@@ in Home still remaps one exact earcon.

3. Choose /How long/ deliberately:

   - a /personal/ rule persists across Emacs sessions;
   - a /session/ rule lasts until this Emacs exits; and
   - a /buffer/ rule affects only the remembered live buffer.

4. Check /Applies to/, /Voice/, and /How long/, then activate /Save/ or press
   @@texinfo:@kbd{w}@@.  A face mapping affects matching uses of that face
   within the displayed module or mode and chosen lifetime.  /Advanced/
   opens the full rule editor when you need more detailed matching controls.
   At the top level, @@texinfo:@kbd{q}@@ hides the simple remapping screen and keeps its draft;
   /Resume unfinished changes/ in Home finds it again after a voice is chosen.

5. Return to the source, repeat the action, and use @@texinfo:@kbd{C-e E}@@ again to
   confirm which rule now wins.

*** Review And Remove Your Rules
:PROPERTIES:
:TEXINFO_NODE_NAME: Managing Feedback Rules
:ALT_TITLE: Review And Remove Your Rules
:DESCRIPTION: Inspect, change, disable, or remove personal and temporary rules.
:END:

In /Your feedback rules/, @@texinfo:@kbd{RET}@@ or @@texinfo:@kbd{e}@@
opens the selected rule's settings panel.  In the rule list, the same keys
open that panel.  Only the selected rule appears while its panel is open;
the other rules remain in the working draft.  @@texinfo:@kbd{n}@@ and
@@texinfo:@kbd{p}@@ move through the
visible settings; @@texinfo:@kbd{SPC}@@ reads the current setting and value.
@@texinfo:@kbd{RET}@@ expands /What should match/, /Content/, /Before content/,
or /After content/.  Matching criteria toggle between included and excluded.
Within /Content/, /voice/ and /speak/ expand their choices in place, showing

** Choose And Manage Voice Palettes
:PROPERTIES:
:TEXINFO_NODE_NAME: Voices And Routing
:ALT_TITLE: Choose And Manage Voice Palettes
:DESCRIPTION: Understand named voices, standard inheritance, and personal palettes.
:END:

#+cindex: voice palettes
#+cindex: acss-default
#+cindex: palette inheritance
#+cindex: voice aliases

A /named voice/ gives a reusable name, such as ~bolden~ or ~annotate~, to a
way of speaking. Some detailed views call it a /logical voice/. A /voice
palette/ is a collection of these named entries. Each entry includes its
shared adjustments, ordered physical voice choices, and any adjustments for
individual choices.

A /physical voice/ is a voice supplied by an installed /speech engine/.
The palette describes the intended choices; availability on your machine
and shared engine preferences determine which can be used. A presentation
rule chooses when to use a named voice. Editing that voice changes every use
that resolves to the entry; changing a rule changes which items use it.

Use this section to manage the collection. For pitch, physical choices, and
other voice settings, see [[info:emacsvox#Editing Named Voices][Edit a Named Voice]]. To hear installed voices or
change engine preference, see [[info:emacsvox#Installed Voices And Engines][Installed Voices and Engines]].

Use the /Voice Palettes/ manager to choose a palette or manage its named
voices. Press @@texinfo:@key{RET}@@ on a palette to browse its voices,
use @@texinfo:@kbd{P}@@ to audition the palette sequence before editing,
and use @@texinfo:@kbd{a}@@ in the palette manager to
activate a selected palette.  Built-in palettes remain intact; editing can
open an unsaved personal child in the common editor.

Opening the manager announces its selected palette.  Entering a palette
announces its name, voice count, selected voice and main keys.

The /Kind/ column distinguishes personal palettes, built-in palettes and the
standard default. /Parent/ names the palette used for inherited entries.
The read-only ~acss-default~ palette is the common root: a chain such as
~a -> b -> c -> acss-default~ is supported. It supplies the standard named
personalities declared by Emacsvox and loaded integrations; it is not a fixed
list of every custom voice you may create. Only the root has no parent.

Inheritance takes the nearest complete entry: its style, physical choice
order and each choice's adjustments stay together. It does not combine pieces
of the same voice from several parents. The voice list's /Source/ column names
the palette supplying that entry. Press @@texinfo:@kbd{O}@@ to open its source,
or @@texinfo:@kbd{u}@@ for Where Used. Where Used shows known loaded references,
declared aliases and affected descendants; it cannot inspect configuration
that has not been loaded. Editing an entry shared by descendants asks you to
review the affected palettes and known uses.

An /alias/ is a declared alternative spelling for a named voice, such as
~voice-bolden~ for ~bolden~. It uses the same entry. Aliases are maintained by
integrations, not edited as separate voices in the palette manager. Use Copy
Voice when you want a separately adjustable voice.

Press @@texinfo:@kbd{N}@@ in the voice list for New Voice or
@@texinfo:@kbd{c}@@ for Copy Voice. Both open an unsaved draft in the common
editor. Copy retains the complete effective voice, including fallback order and
individual adjustments. Editing or copying a built-in voice asks for a personal
child palette; saving adds only the requested direct entry to that child.
Opening or previewing the draft does not save it.

Press @@texinfo:@kbd{R}@@ to Reset a personal definition to its inherited
entry. The confirmation names the source that will become effective and rejects
a source changed during confirmation. Reset preserves other saved settings. Use
@@texinfo:@kbd{d}@@ to Delete a direct custom voice that has no inherited
replacement. Built-in and inherited entries cannot be deleted here. If deletion
would leave a known reference without a voice, remap that use first. Save or
discard unfinished voice edits before deleting. Press @@texinfo:@kbd{o}@@ to
return to the palette manager.

In the palette manager, New Palette with @@texinfo:@kbd{N}@@ creates a child
of the chosen parent. Copy Palette with @@texinfo:@kbd{c}@@ instead saves an
independent copy of all effective entries with ~acss-default~ as its parent.
Its local physical choices belong to the new palette. Use the summary and
parent action, @@texinfo:@kbd{E}@@, to review or change a personal palette's
parent; the manager rejects inheritance cycles.

To delete a whole personal palette, select it in the manager and press
@@texinfo:@kbd{d}@@. Children and known references, including saved profiles,
must be changed first, and unfinished voice edits must be completed or
discarded. Deleting an active palette returns to the standard baseline.

Activation with @@texinfo:@kbd{a}@@ lasts for this session. Press
@@texinfo:@kbd{f}@@ to follow the standard baseline palette again.
This clears the session's explicit palette selection; it does not delete
your saved palette or change the startup choice.
Use at Startup, @@texinfo:@kbd{U}@@, changes the palette in the selected saved
Presentation Profile while preserving its other saved fields. It does not
apply that profile to the current session. If no startup profile exists, the
action asks you to review a new profile captured from the current setup.
It checks voice references in saved rules and the profile's saved options;
session and buffer rules do not affect this startup check. An already open
Profiles view refreshes to show the saved choice.

*** Walkthrough: Make A Personal Reading Palette
:PROPERTIES:
:TEXINFO_NODE_NAME: Personal Palette Walkthrough
:ALT_TITLE: Walkthrough: Make A Personal Reading Palette
:DESCRIPTION: Create, edit, save, activate, and optionally select a palette for startup.
:END:

This example gives you a personal place to adjust standard voices. Use an
unused palette name; ~reading-demo~ below is an example. Note your current
palette before starting so you can return to it.

1. Open @@texinfo:@kbd{C-e H V}@@ for /Voice palettes/. Press @@texinfo:@kbd{N}@@, enter ~reading-demo~,
   give it a purpose such as ``My reading experiments'', and choose
   ~acss-default~ as its parent. Creation saves the new palette, but does not
   activate it. Its standard voices are inherited.

2. Press @@texinfo:@kbd{RET}@@ to enter the new palette. Find ~bolden~ and move to its
   /Source/ column. It should name ~acss-default~. @@texinfo:@kbd{.}@@ repeats the column
   title and value; @@texinfo:@kbd{SPC}@@ reads the whole row. @@texinfo:@kbd{P}@@ previews the voice.

3. Press @@texinfo:@kbd{e}@@ to edit ~bolden~ here. The editor identifies the destination
   palette and inherited source. Move to /Average Pitch/, press @@texinfo:@kbd{RET}@@,
   and enter ~6~ (or ~5~ if it is already six). @@texinfo:@kbd{B}@@ compares the opening
   voice with the edited voice using the same text. Unsupported adjustments
   are reported; see [[info:emacsvox#Voice Adjustments][Voice Adjustments]] if the contrast is unclear.

4. Choose /Save to collection without selecting/. Wait for the save result,
   then use @@texinfo:@kbd{q}@@ to return to the voice list. /Source/ should now identify
   ~reading-demo~ for ~bolden~. Other inherited entries still name their
   providers. Saving has created a complete local entry, not a pitch-only
   patch on the parent.

5. Press @@texinfo:@kbd{o}@@ to return to the palette manager and @@texinfo:@kbd{a}@@ on ~reading-demo~
   to activate it. Check its status, then revisit content that uses ~bolden~.
   This affects all uses resolving to your edited entry. Explanation at the
   source helps distinguish palette settings from additional contextual rules.

6. If you want this palette after restart, press @@texinfo:@kbd{U}@@ on it in the palette
   manager and review the startup proposal. It updates the palette selection
   in the saved startup profile. If no startup profile exists, review the
   proposed new profile's other settings too. Saving the palette and selecting
   it for startup are separate actions.

7. To return to your previous sound, activate the original palette. If you
   also changed startup, use @@texinfo:@kbd{U}@@ on that original palette to restore the
   startup selection. Your saved ~reading-demo~ remains available for later
   experiments. To remove only its ~bolden~ customization, follow the Reset
   example in [[info:emacsvox#Palette Inheritance Walkthrough][Inheritance, Aliases, and Reset]].

*** Walkthrough: Inheritance, Aliases, And Reset
:PROPERTIES:
:TEXINFO_NODE_NAME: Palette Inheritance Walkthrough
:ALT_TITLE: Walkthrough: Inheritance, Aliases, And Reset
:DESCRIPTION: Follow an entry to its parent and distinguish an alias from a copy.
:END:

Use ~reading-demo~ from the previous example, or another personal palette
with ~acss-default~ as its parent.

1. In the palette manager, create ~reading-child-demo~ with @@texinfo:@kbd{N}@@ and choose
   ~reading-demo~ as its parent. The chain is now
   ~reading-child-demo -> reading-demo -> acss-default~.

2. Enter the child and inspect ~bolden~'s /Source/. If ~reading-demo~ has a
   direct ~bolden~ entry, it supplies the child's whole entry. Otherwise
   ~acss-default~ supplies it. @@texinfo:@kbd{O}@@ opens the supplying palette; @@texinfo:@kbd{u}@@ shows
   Where Used, including known references, aliases, and affected descendants.

3. The alias ~voice-bolden~ refers to the same named voice as ~bolden~.
   It is an alternative spelling used by integrations, not another entry
   with independent settings. You do not create or edit aliases in this view.

4. Return to the child palette and copy ~bolden~ with @@texinfo:@kbd{c}@@. Give the copy an
   unused name such as ~reading-heading-demo~. Change its pitch, compare it,
   and choose /Save to collection without selecting/. You now have a separate
   named entry. A rule must select this new name before ordinary content uses
   it; copying alone does not remap headings.

5. For a Reset experiment, edit the child's inherited ~bolden~, change one
   field, and save to the collection. Its Source becomes the child. Back in
   the voice list, press @@texinfo:@kbd{R}@@ on ~bolden~. The confirmation names the parent
   entry that will take over. After confirming, ~bolden~ remains in the list
   and Source returns to that provider.

6. To remove the custom copy, select ~reading-heading-demo~ and press @@texinfo:@kbd{d}@@.
   This deletes it if there is no inherited replacement or known use. If you
   assigned it to a rule, remove or remap that rule first. Reset is for a local
   entry with an inherited replacement; Delete is for a removable custom name.

The standard root ensures standard voices remain available after Reset. It
cannot be deleted or edited here. A palette can contain additional custom
names; the standard list grows when loaded integrations register voices.
Copy Palette is different from New Palette: it copies all current effective
entries and stops following edits to the source palette, while still inheriting
new standard names from ~acss-default~. Definitions referring to an existing
personality still use that personality's settings. A copy is not a recording
of its sound.

*** Rename Voices And Palettes

Press @@texinfo:@kbd{r}@@ in the voice list to rename a custom voice
defined directly in that personal palette.  Enter the new name to save it;
the renamed voice keeps its settings, physical choices and individual tuning.
Save or discard unfinished voice edits first.  Standard Emacsvox voice names

** Edit A Named Voice
:PROPERTIES:
:TEXINFO_NODE_NAME: Editing Named Voices
:ALT_TITLE: Edit A Named Voice
:DESCRIPTION: Adjust a voice, compare it, and save the complete result.

#+cindex: voice editor
#+cindex: voice adjustments

From /Voice Palettes/, open a palette, select a voice, and press
@@texinfo:@kbd{e}@@ to edit it. From Aural Home, /Edit the named voice used here/
opens the named voice used by the captured source item. Editing an inherited
voice creates a complete entry in your destination palette when saved.
Editing a built-in palette asks for a personal child. Opening the editor
and previewing a draft do not change live feedback or save settings.

If you opened an experiment from an installed physical voice, these same
controls apply, but saving first asks for a destination. See
[[info:emacsvox#Keeping A Voice Experiment][Keep an Installed Voice Experiment]] for that sequence.

The editor uses the ordinary navigation voice for its labelled fields.
@@texinfo:@kbd{n/p}@@, up/down or Tab moves between fields. Left/right adjusts
a numeric field and moves between fields elsewhere; @@texinfo:@key{RET}@@
activates a button or enters an adjustment value. Press @@texinfo:@kbd{d}@@
on an adjustment to restore the adapter default; blank numeric entry does the
same. Zero is an explicit value, such as the lowest pitch or leftmost pan,
whereas adapter default leaves that setting to the speech adapter. They may
sound the same for some effects, but they are different settings.
/More adjustments and effects/ exposes filters,
gain, pan and other optional controls. Changed values say what they were before
editing; unsupported settings remain visible and are retained.
Field navigation stops at the first and last field without wrapping. Numeric
adjustments stop at their limits and announce the minimum or maximum.

@@texinfo:@kbd{P}@@ plays the edited voice. @@texinfo:@kbd{B}@@ compares the
captured original with the edited version using the same text, with spoken
labels. @@texinfo:@kbd{T}@@ changes that text; @@texinfo:@kbd{S}@@ stops.
An automatic sample follows each adjustment unless you turn off
/Automatic sample after adjustment/.
The new value precedes the sample text, for example ``1. The quick brown fox…''.
Toggling /Automatic sample after adjustment/ announces on or off with distinct
cues. /More adjustments and effects/ and /Fallbacks/ present their visibility
with open/close cues and optional spoken state labels, both when toggled and
when reached during field navigation.
Navigation stops an outstanding sample. @@texinfo:@kbd{u}@@ undoes an edit,
including a reset to adapter default. @@texinfo:@kbd{q}@@ dismisses the editor
and returns to its originating view, offering to retain or discard unsaved
changes.

Choose the /Physical voice/ field to search by engine or voice name. You can
audition a candidate with the working adjustments before accepting it. Cancel
keeps the previous choice and returns to the same field. Named voices also
have an expandable /Fallbacks/ section: replace, reorder, remove or individually
audition a choice, append another, or explicitly return to Automatic. Existing
unavailable, engine-default and property choices are preserved. Shared
adjustments apply to fields that a row inherits; /Customize this voice/ adds
optional individual settings.

For a named voice, @@texinfo:@kbd{w}@@ or @@texinfo:@kbd{C-c C-c}@@ saves and
applies the complete draft. /Save to collection without selecting/ saves an
inactive palette without changing the current selection. The header reports
unsaved changes, partial saves, applying, failures, or saved and applied.
Retry uses the pending proposal and retains successful persistence steps.
Changes made during an earlier apply remain unsaved when its acknowledgement
arrives. A changed file or destination requires fresh review rather than an
implicit merge.

Named-voice previews test the complete choice chain without selecting the
draft palette or changing live settings. They require an Omnivox server
advertising complete-voice preview. Older servers report this operation
as unsupported; individual physical auditions remain available. Playback
reports identify actual accepted audio when the server supplies that evidence,
including unsupported adjustments. They do not infer a successful fallback
from inventory or claim exact effective numeric parameter values.

@@texinfo:@kbd{q}@@ returns to the originating row and column. With unsaved
changes, choose to retain the draft, discard changes, or continue editing.
Retained drafts survive closing the view and can be reopened from Home's
/Resume unfinished changes/ during this Emacs session. They do not survive
restarting Emacs. Leaving does not undo a completed save.

/Save and apply/ selects the palette for this session. Use the
/Use at Startup/ action, @@texinfo:@kbd{U}@@ in Voice Palettes, to retain
that selection after restart. A save can involve more than one settings file.
The editor reports partial failures and retains the proposal for retry; see
[[info:emacsvox#Recovering Aural Changes][Recovering Unfinished Changes]].

*** Understand Voice Adjustments
:PROPERTIES:
:TEXINFO_NODE_NAME: Voice Adjustments
:ALT_TITLE: Understand Voice Adjustments
:DESCRIPTION: Understand the voice controls and their defaults.
:END:

Change one field at a time and compare with @@texinfo:@kbd{B}@@. These are portable
controls, not measurements in Hertz or decibels. Equal numbers can sound
different on different engines. Most numeric fields use integer levels from
zero through nine; Relative Rate is the exception.

- /Relative Rate/ ranges from -20 to 20. Negative values request slower
  speech, positive values faster speech, and zero leaves the base rate
  unchanged. The engine interprets those relative steps; they are not words
  per minute. A stronger contextual relative-rate value replaces this value
  rather than adding to it.
- /Average Pitch/ requests a lower or higher overall pitch. Start with a
  small difference between two voices intended to mark related content.
- /Pitch Range/ requests less or more pitch variation. A low range can make
  a supported voice more monotone; a high range makes intonation more varied.
- /Stress/ requests less or more emphasis. Its audible effect depends on how
  the engine implements stress.
- /Richness/ changes the voice's tonal character or fullness where supported.
  Compare samples rather than treating it as another volume control.
- /Gain/ changes output level. Five is unchanged; lower values reduce it and
  higher values increase it.
- /Pan/ places supported audio from left at zero, through center at five,
  to right at nine. Its effect also depends on your output arrangement.
- /Low-pass Amount/ and /High-pass Amount/ remove high and low frequencies,
  respectively. Both use zero for neutral and nine for strongest filtering.
- /Reverb/ adds a reverberant character, /Echo/ adds delayed repetitions,
  and /Chorus/ adds a doubled-voice effect. Zero disables each; higher levels
  increase the effect.
- /Portable Fallback Family/, where offered under additional adjustments,
  is a compatibility family hint. Use /Physical voice/ for an installed voice
  choice. Family is not part of the complete Omnivox voice preview.

In shared settings, @@texinfo:@kbd{d}@@ or blank numeric input requests /adapter default/;
@@texinfo:@kbd{u}@@ undoes that edit. In an individual physical choice, @@texinfo:@kbd{i}@@ instead means
/use the shared value/. Zero remains an explicit value in either view.
Thus ``standard default palette'', ``Automatic physical selection'', and
``adapter default adjustment'' answer three different questions: which
collection supplies the voice, who selects its physical voice, and who supplies
one adjustment value.

The voice editor presents /Low-pass Amount/ and /High-pass Amount/ from zero through
nine. Higher amounts mean more filtering: low-pass removes more high
frequencies, and high-pass removes more low frequencies. Zero is the neutral
cutoff; blank numeric entry requests the adapter default. The amount scale
applies to arrows and numeric entry in the common editor. Existing
saved styles retain their sound; stored low-pass cutoff values keep their
original meaning.

The voice editor names other neutral effect values instead of speaking an ambiguous number:
gain five is /unchanged/, pan five is /centre/, and reverb, echo, or chorus zero is
/disabled/.  Chorus adds a bounded doubled-voice modulation without changing
speech duration or marker positions.  It is applied by Omnivox to buffered
audio; the voice editor reports when the selected route cannot apply it.  These
portable levels are translated to the exact values required by the active
adapter.

The built-in ~acss-default~ palette also includes a ~telephone~ named voice.
It combines high-pass and low-pass filtering to give any buffered Omnivox
engine a narrow-band telephone sound while preserving its selected physical
voice, duration, and markers.  Preview it in /Voice Palettes/ or /Voice
Workbench/ before assigning it to content.  Adapters without post-synthesis
filtering preserve the portable style but do not apply the filters.

Omnivox average-pitch differences use the customizable
=omnivox-average-pitch-contrast=.  Its default value, =0.5=, keeps palette
distinctions while making them gentler.  Set it to =1.0= for the historical
contrast, or =0= to make average pitch neutral.  Values through =2.0= are
accepted.  Changing it refreshes logical-voice registration, and the same
setting applies to previews, structured speech, and legacy inline voices.

*** Choose And Tune Fallback Voices
:PROPERTIES:
:TEXINFO_NODE_NAME: Voice Fallbacks
:ALT_TITLE: Choose And Tune Fallback Voices
:DESCRIPTION: Order physical choices and customize their individual adjustments.
:END:

Shared settings provide the base for the whole voice.

Physical choices are tried in their displayed order, subject to availability,
engine policy, and synthesis failures. An empty explicit list means /Automatic/:
use the shared engine policy. Availability predicts a possible choice;
the last sample's result identifies what actually played.

There are two distinct kinds of inheritance. A parent palette supplies a
whole named entry. Inside that entry, an individual physical choice can
inherit each shared adjustment separately. For example, shared pitch six,
choice pitch four, and a matching contextual rule setting pitch seven result
in a requested pitch of seven. Without that rule, the choice requests four.
Returning the choice field to /Use shared value/ makes it request six.

Expand /Fallbacks/ to see which rows /use shared settings/ and which are
/customized/. A row's action
menu can audition that row or compare its original and edited versions.
Comparison follows the same row after reordering, including two rows mapped to
the same physical voice. A newly added row has no original to compare yet;
audition it or compare the complete voice instead. Replacing a customized
physical voice asks whether to keep its settings or return to shared settings.

Choose /Customize this voice/ in that row's menu for optional individual tuning.
The panel names the physical voice it edits. Each field says /use shared value/,
/custom value/, or /explicit adapter default/. =RET= offers all three states;
left/right sets a number, =d= restores adapter default, and =i= returns the field
to its shared value. Zero is an explicit setting. Later shared edits affect only
inherited fields. /More adjustments and effects/ reveals the additional controls.
Automatic samples speak the value or state before the sample and audition this
row. /Play whole fallback chain/ checks normal selection. Use /Return to shared
settings/ to leave individual tuning; all edits belong to the same voice draft
and the same Save action. Removing a row disables its controls until undo or a
return to shared settings.

With Omnivox's per-choice tuning support, complete previews retain the full
fallback chain and each row's settings. /Last sample playback started on …/
identifies the engine and physical voice whose audio started. Audio merely
accepted for playback, or the spoken label /Original/ or /Edited/, does not
confirm that the sample started. Stop and text, draft or context changes retire
pending previews; retained results are labelled /Earlier preview/. Saving and
application status remain separate from playback evidence.

/Details and last playback evidence/ explains the shared setting, actual row's
override and contextual override for each field in the last confirmed sample.
The context view offers /Where the last sample's settings came from/ after a
preview. Explanations use that sample's captured settings, even after editing,
and identify whether it was an original or edited sample. They distinguish
inherited values, explicit defaults, zero and unsupported requests. These are
requested settings, not measurements of the engine's native values or sound.

Older Omnivox servers retain shared-only previews. Customized complete previews
require per-choice support; an individual audition is available only when its
settings can be represented faithfully, including adapter defaults. Saving
remains available when that preview is unavailable.

*** Inspect Or Adjust A Voice In Context
:PROPERTIES:
:TEXINFO_NODE_NAME: Voices In Context
:ALT_TITLE: Inspect Or Adjust A Voice In Context
:DESCRIPTION: Learn the controls and scope of this task.
:END:

In the common named-voice editor, choose /Effective sound / Where settings
came from/. It uses the source item captured when you entered Aural Home or
the voice list. If none is attached, choose an ordinary buffer at its current
point. The item must have inspectable presentation facts or a valid retained
presentation. /Choose another source context/ selects a new item explicitly.

This is a simulation using captured facts and rules. It shows the selected named
voice, matching rules, requested values and each dimension's source. A rule
can override pitch while another supplies richness. A stronger pitch rule can
hide a base pitch edit; a rule selecting a different named voice can make the open
base voice irrelevant to this item. Rates follow precedence too: competing
relative-rate values do not add together.

@@texinfo:@kbd{P}@@ plays the edited voice in this context;
@@texinfo:@kbd{B}@@ compares original and edited using the same captured facts,
rules and text. These voice-only previews omit cues and spatial placement. Family remains a portable fallback outside full
preview. On a server with per-choice support, the actual fallback's settings
are applied before the captured context. An explicit rule value still overrides
that row when it happens to equal the shared value. Requested values are
separate from confirmed sample starts, accepted audio and
unsupported adjustments. A changed or deleted source is rejected. After saving
a rule, use /Refresh facts and rules from this source item/ to capture its new
contribution. @@texinfo:@kbd{q}@@ returns to the base editor.

/Adjust for this context/ presents the matching criteria and asks whether the
rule lasts always (personal), for this Emacs session, or for this buffer. Choose
one adjustment and its value. It opens the ordinary rule editor with that field
prepared; changing richness alone produces a richness-only patch and does not
select a different named voice. Review the rule's match with @@texinfo:@key{RET}@@,
use @@texinfo:@kbd{V}@@ to adjust another voice field, and save that scope with
@@texinfo:@kbd{w}@@. Palette definitions are unchanged. Existing unsaved work
in that rule editor must be completed before preparing another contextual rule.

In the scoped field control, /Inherit/ removes the field so weaker contributions
can supply its value. Removing the final voice field removes the voice patch.
Existing explicit default values are shown separately and preserved when you
edit another field. Use /Inherit/ to remove a contextual adjustment; zero is
a value, not a request to inherit. Some older explicit defaults cannot reset
an underlying voice setting on every backend. Check the preview and use the
explanation to identify that limitation. Contextual changes are saved as rules;
they do not replace the palette entry with the combined result. The
[[info:emacsvox#Integration Maintenance][Developer Guide]] explains the representation and compatibility details.

*** Experiment With An Installed Voice
:PROPERTIES:
:TEXINFO_NODE_NAME: Physical Voice Experiments
:ALT_TITLE: Experiment With An Installed Voice
:DESCRIPTION: Try physical voices without saving, then keep a useful experiment.
:END:

In /Browse installed voices/, select a physical voice and press
@@texinfo:@kbd{t}@@. This opens an experiment with that exact engine and
voice, adapter-default speech characteristics, the current base speech rate,
and neutral audio effects. Opening, adjusting and comparing write no settings.

The field navigation, adjustments and comparison controls are the same as
in [[info:emacsvox#Editing Named Voices][Edit a Named Voice]]. In an experiment, @@texinfo:@kbd{w}@@ first asks
where to use the result; it cannot save a voice without a palette destination.

To compare pitch on an installed voice:

1. From Home choose /Browse installed voices/, select an available engine,
   and press @@texinfo:@kbd{RET}@@. Select a physical voice and press @@texinfo:@kbd{P}@@. You can use
   @@texinfo:@kbd{B}@@ to compare it with another available voice, using the same sentence.
2. Press @@texinfo:@kbd{t}@@ on the physical voice to open an experiment. Move to /Average
   Pitch/, enter ~3~, and listen. Then enter ~7~ and listen again. If the engine
   cannot change pitch, the unsupported setting remains visible.
3. Press @@texinfo:@kbd{B}@@ for the labelled original and edited comparison. Here
   ``original'' means the experiment's captured starting voice, not the
   immediately preceding edit. @@texinfo:@kbd{u}@@ undoes an edit; @@texinfo:@kbd{d}@@ restores the
   adapter default for the current adjustment.
4. To finish without saving, press @@texinfo:@kbd{q}@@ and choose to discard the experiment.
   To keep it, use the following walkthrough instead.

For a physical experiment, @@texinfo:@kbd{w}@@ chooses a destination palette
and named voice. The default keeps /Physical voice and adjustments — this
choice/. You can instead keep only the physical voice, only the adjustments for
a selected row, or explicitly change shared settings for all inheriting choices.
A physical voice can replace a selected row, become preferred, or be appended
as a fallback. Row-level adjustments replace that row's tuning with the
experiment's values and adapter defaults. This prevents unrelated destination
shared settings from changing the experiment's base sound. Use =i= in the row's
individual adjustment panel for any field you want to inherit afterward.

Other rows and shared settings are retained during a row-level keep. Replacing
only the physical voice asks whether to keep or reset an existing row's custom
settings. Shared adjustment keeps affect inherited fields; custom row settings
still override them. An existing destination draft offers to add the chosen
changes or resume without adding. Other edits and pending save recovery remain.
The destination opens in the same editor; preview plays the proposed saved
combination, which may differ from the experiment because of the chosen scope
and destination fallback order. Choosing a destination has not saved anything yet.

*** Walkthrough: Keep An Installed Voice Experiment
:PROPERTIES:
:TEXINFO_NODE_NAME: Keeping A Voice Experiment
:ALT_TITLE: Walkthrough: Keep An Installed Voice Experiment
:DESCRIPTION: Place an experiment in a named voice and verify the saved combination.
:END:

This example keeps the physical voice and its tuning together. First create
~reading-demo~ as in [[info:emacsvox#Personal Palette Walkthrough][Make a Personal Reading Palette]], or choose an existing
personal destination. Note the active palette before beginning.

1. In the installed-voice browser, open an experiment with @@texinfo:@kbd{t}@@, adjust a
   field, and use @@texinfo:@kbd{P}@@ or @@texinfo:@kbd{B}@@ to listen. Press @@texinfo:@kbd{w}@@ when ready to keep it.
2. At /Destination palette/, choose your personal palette. At /Use for named
   voice/, choose ~bolden~. Select /Physical voice and adjustments — this
   choice/, then /Add as preferred/. These choices put the experiment first
   while retaining existing alternative physical choices.
3. The named-voice editor opens with the proposed combination. Nothing has
   been saved yet. Expand /Fallbacks/: the new first choice should be marked
   customized, with any previous explicit choices after it. @@texinfo:@kbd{P}@@ plays the
   whole proposed voice. Review the reported engine and physical voice after
   the sample; an unavailable preferred choice can cause a fallback.
4. Press @@texinfo:@kbd{w}@@ to save and apply. Wait for the editor's result. If it reports
   a partial save or failed application, keep the draft and follow
   [[info:emacsvox#Recovering Aural Changes][Recovering Unfinished Changes]]. A successful save selects the destination
   palette for this session. Use @@texinfo:@kbd{U}@@ in Voice Palettes only if you also want
   that palette at startup.

   After saving, reopen the named voice, expand /Fallbacks/, open the added
   choice's action menu with @@texinfo:@kbd{RET}@@, choose /Remove/, preview, and save.
   Removing that row retains the other choices and shared settings. Reactivate
   your original palette if you also want to restore the session selection.

To tune a fallback independently, open its action menu and choose /Customize
this voice/. Set one field, audition that choice, then select /Play whole
fallback chain/ to test normal selection. Its custom field replaces the shared
value only when that choice is used. @@texinfo:@kbd{i}@@ returns the field to the shared
value. Reordering a choice carries its adjustments with it.

** Sounds, Tones, And Spatial Cues
:PROPERTIES:
:TEXINFO_NODE_NAME: Sounds And Space
:ALT_TITLE: Sounds And Space
:DESCRIPTION: Audition sound packs and inspect spatial fallback.
:END:

#+cindex: sound packs

#+cindex: spatial presentation

Presentation rules refer to auditory cues by semantic name.  A sound pack maps
those names to concrete audio assets and can inherit missing cues from another
pack.  This separation lets you change the overall sound character without
rewriting every presentation rule.

Open /Sound Packs/ from Aural Home.  In the manager:

#+attr_texinfo: :indic kbd :compact t
- P :: Audition a representative cue without activating the pack.
- RET :: Browse the pack's individual cues and their source or fallback.
- P in the cue browser :: Audition the selected concrete cue; RET shows details.
- v :: Validate the pack and report missing or invalid resources.
- a :: Activate the selected pack.

Use a sound pack when you want to change a family of cues together.  Use
/Change a sound for this item/ or Your feedback rules when one semantic event needs
a different cue, suppression, or restoration.

Spatial requests are portable descriptions rather than assumptions about one
device.  Aural Home separates /Spatial Capabilities/, which reports what the
current route can provide and how it falls back, from /Spatial Settings/, which
controls output, separation, direction, speech, and cues.  Unsupported or mono
output remains audible at the center rather than silently losing content.

Named tones are another compact presentation resource.  They do not require a
sampled sound file and may be used independently of the active sound pack.

*** Adjust Spatial Presentation
:PROPERTIES:
:TEXINFO_NODE_NAME: Spatial Presentation Controls
:ALT_TITLE: Adjust Spatial Presentation
:DESCRIPTION: Check stereo support, adjust placement, and restore centered output.
:END:

From Home, open /Spatial capabilities/ under /Troubleshooting/ to inspect
what the current backend reports for speech and cues. Then open /Spatial
settings/ under /Sounds and output/. Speech and cues have separate enable
controls. Output can follow the backend capability or be declared mono.
Maximum separation ranges from zero (centered) to one (full separation);
direction can stay normal, reverse left and right, or center some or all

To try a gentler layout, note the existing maximum separation, set it to ~0.3~

compare. If all feedback remains centered, use Explain to check that the

the same action. Content should remain audible. Restore the values you noted
when finished. Use Customize's save action or capture the spatial choices in

and notification-device routing are separate settings.

*** Inspect And Maintain A Personal Sound Pack

** Speech Output And Notifications
:PROPERTIES:
:TEXINFO_NODE_NAME: Aural Speech Output
:ALT_TITLE: Speech Output And Notifications
:DESCRIPTION: Set speech rate and understand foreground and background output.
:END:

Speech rate and output settings control how speech reaches you, independently
of which presentation rule chose the content. /Speech rate/ in Home applies to
the captured source buffer; invoke that action with a prefix argument to set
the global rate. A named voice's relative rate adjusts its speech around the
applicable base rate. See [[info:emacsvox#Voice Adjustments][Voice Adjustments]].

#+cindex: speech streams

#+cindex: notification stream

#+vindex: tts-notification-device

Emacsvox assigns speech to one of two streams according to what caused it:

- The /main stream/ presents foreground information produced directly by your
  current interaction, such as movement, entering a buffer, or opening a
  message.  New navigation interrupts obsolete main-stream speech, and you can
  interrupt a longer entry announcement by navigating again.

- The /notification stream/ presents asynchronous events, such as completion
  of background work.  It does not stop main-stream speech, and normal
  navigation does not stop it, so both streams may be heard concurrently.  A
  notification cue and its associated speech are delivered together on this
  stream.

Open /Notification output/ in Home to choose the arrangement in Customize.
With Omnivox, /Automatic/ normally uses an independent notification process.
The left, right, and both choices select its output route.
/Use main output (notifications remain audible)/ sends notifications through
the main process instead. Navigation can then interrupt them; this setting
does not mute notifications. Other backends may use their configured device
or fall back to the main stream.

After changing the setting, initialize the arrangement with
@@texinfo:@kbd{C-e d C-n}@@. Use Customize's save action to retain the choice
across restarts. In Lisp, ~default~ or an empty string selects main output;
prefer the descriptive Customize labels for ordinary configuration.

/Stop notification speech/ in Home stops the current notification stream;
it is not a persistent mute. /Review notifications/ opens the notification
history so you can read an announcement you missed.

Stopping obsolete main speech is local to the main stream.  An explicit
~tts-stop~ command stops both main and notification speech.

** Save, Switch, And Share Your Setup
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Profiles
:ALT_TITLE: Presentation Profiles
:DESCRIPTION: Save selected settings and distinguish profiles from resource backups.
:END:

#+cindex: presentation profiles

A presentation profile records a coordinated setup: enabled Presentation
Options and their order, the sound pack, the voice palette, and portable
spatial settings.  This is useful for switching between focused work and
leisure reading, between quiet and information-rich feedback, or between audio
environments.

To save and use a profile:

1. Configure the live options, sound pack, voice palette, and spatial choices
   you want.

2. Open /Presentation Profiles/ from Aural Home or press @@texinfo:@kbd{P}@@ there.

3. Press @@texinfo:@kbd{N}@@ to save the current live configuration as a new named
   profile.

4. Later, select that profile and press @@texinfo:@kbd{a}@@ to apply
   its saved values.

5. If you deliberately change the live configuration and want the selected
   profile to adopt it, press @@texinfo:@kbd{w}@@.  If you instead want to discard the
   live differences, press @@texinfo:@kbd{a}@@ to restore the saved profile; Emacsvox
   asks before replacing the diverged values.

Only one profile identity is selected.  /Active/ means the selected profile's
saved values match the live configuration.  /Diverged/ means the same profile
is still selected but the live values differ; it is a status, not an unsaved
editor warning.

Profiles refer to palettes and sound packs by name; they do not make private
copies of their contents. Editing a palette affects every profile selecting
it. A profile is therefore a convenient selection of settings, not a backup.
Profiles do not capture engine policy, speech rate, or notification output.

Profiles do not copy presentation rules. Edit rules through Presentation
Options or /Your feedback rules/. They also do not capture buffer-local Voice Lock state or
current-buffer rules, because those belong to an individual buffer rather than
a global setup.

*** Choose What Persists
:PROPERTIES:
:TEXINFO_NODE_NAME: Saving And Startup
:ALT_TITLE: Choose What Persists
:DESCRIPTION: Distinguish previews, drafts, saved resources, activation, and startup.
:END:

#+cindex: saving aural settings
#+cindex: startup palette

These actions answer different questions:

- /Preview/ plays an example without saving or selecting the draft.
- /Retain draft/ keeps unfinished edits in this Emacs session only.
- /Save to collection without selecting/ saves the voice for later use.
- /Save and apply/ saves the voice and selects its palette for this session.
- /Activate/ selects an existing palette or sound pack now.
- /Use at Startup/ in Voice Palettes changes the palette selected by the saved
  startup profile; it does not apply that profile now.
- /Presentation Profiles/ save selected options, palette, sound pack, and
  spatial settings together. Their referenced resources remain shared.
- /Export/ and /Full backup/ create files to share or retain separately.

expire with their session or buffer. Saving a profile does not turn these
temporary rules or unfinished drafts into permanent settings.

*** Export, Back Up, And Import Palettes
:PROPERTIES:
:TEXINFO_NODE_NAME: Sharing Voice Palettes
:ALT_TITLE: Export, Back Up, And Import Palettes
:DESCRIPTION: Share portable voices or retain local choices in a backup.
:END:

For sharing, @@texinfo:@kbd{w}@@ exports effective portable entries and asks
before omitting machine-local physical choices. @@texinfo:@kbd{W}@@ creates a
full local backup containing the palette's ancestry and referenced local
choices. Import with @@texinfo:@kbd{i}@@ accepts either file and creates an
independent personal palette under an unused name; it does not replace the
original ancestry tree or activate the imported palette. Missing installed
voices are reported and retained for later replacement. A partial import keeps
its proposal available for Retry or Discard.

For example, select ~reading-demo~ in Voice Palettes and press @@texinfo:@kbd{w}@@ to
export a portable file. Review any omitted local choices. Import that file
with @@texinfo:@kbd{i}@@ under an unused name such as ~reading-import-demo~. Enter the
imported palette and preview its voices before activating it. A retained
unavailable choice is a request to review, not evidence of successful audio.
Delete the imported copy when finished if no profiles, children, or rules
need it. The original palette is unchanged by this trial.

Use uppercase @@texinfo:@kbd{W}@@ when the aim is to retain exact local choice data with
the required palette ancestry. Importing that backup still creates a new,
independent palette; it does not overwrite the original tree. Neither form
contains speech engines or sound-pack audio, and a palette backup is not a
backup of every Emacsvox setting.

** Troubleshooting And Recovery
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Troubleshooting
:ALT_TITLE: Presentation Troubleshooting
:DESCRIPTION: Trace unexpected output and use safe diagnostics.
:END:

#+cindex: Aural Doctor

Use the symptom to choose the shortest diagnostic route:

#+attr_texinfo: :columns 0.43 0.57
| Symptom | First action |
| The current object sounds wrong or too verbose | Press @@texinfo:@kbd{C-e E}@@ and inspect the strongest matching rule. |
| Something heard earlier was wrong | Open Recent Aural Feedback and explain its recorded presentation. |
| A broad optional behavior is unwanted | Inspect Presentation Options and preview or disable the matching option. |
| One narrow exception is unwanted | Open Your feedback rules, preview it, then disable or remove it. |
| A named voice uses the wrong engine or physical voice | Inspect its physical choices in the voice editor, then engine health in Voice Workbench. |
| A cue is missing or inappropriate | Validate and audition the active Sound Pack, then inspect earcon overrides. |
| A saved setup no longer appears active | Check whether the selected Presentation Profile is active or diverged. |
| Voice changes disappear only in some buffers | Compare Voice Lock and explicit face-presentation state. |

Open /Aural Doctor/ from Aural Home or press @@texinfo:@kbd{D}@@ there.  The doctor
checks live bindings, loaded source or byte-code, the compatibility baseline,
options, profiles, personal data, sound resources, spatial fallback, and the
speech backend.  It does not start the speech server or change settings
automatically.  When one row offers a reviewed safe repair, press @@texinfo:@kbd{r}@@
on that row to run it.

Press @@texinfo:@kbd{?}@@ in any Aural interface for its complete current keys.  If
speech itself is absent rather than merely presented incorrectly, follow
@@texinfo:@ref{Backend Diagnostics And Ownership,Backend Diagnostics And Responsibilities}@@; presentation diagnostics assume that a speech route can run.

If an adjustment appears to do nothing, check in this order:

1. Is the palette containing the edit active? Saving to the collection alone
   does not select it. A retained draft is not a saved voice.
2. Does the item actually use that named voice? Explain it with @@texinfo:@kbd{C-e E}@@.
3. Does the physical choice that played have an individual adjustment masking
   the shared one? Inspect /Fallbacks/ and the last sample's result.
4. Does a matching contextual rule replace that field? In the voice editor,
   inspect /Effective sound / Where settings came from/.
5. Does the engine support the requested adjustment? Check the reported
   unsupported fields and compare samples on an available supported voice.

If speech uses another engine, first check explicit choices in the named
voice: they outrank the shared preferred-engine setting. Then inspect engine
availability, disablement, and failure information. A missing custom voice
name is a configuration error. Ordinary speech preserves the text using an
unstyled voice and records a diagnostic; it does not invent the missing
palette entry. Doctor and Explain help locate the unresolved reference.

*** Recover Unfinished Changes
:PROPERTIES:
:TEXINFO_NODE_NAME: Recovering Aural Changes
:ALT_TITLE: Recover Unfinished Changes
:DESCRIPTION: Resume drafts and distinguish saved settings from confirmed application.
:END:

Use @@texinfo:@kbd{h}@@ to leave a working editor through Home without losing
it.  Home's /Resume unfinished changes/ opens the original draft, including
its source and working settings.  In the common voice editor, @@texinfo:@kbd{u}@@ undoes and
@@texinfo:@kbd{q}@@ offers to keep the draft, discard changes, or continue.  Guided feedback
@@texinfo:@kbd{q}@@ goes back one level, then hides and retains the draft at
the top level.  To undo an already applied
rule, open /Your feedback rules/, select it in the appropriate scope, and
use @@texinfo:@kbd{t}@@ to disable it or @@texinfo:@kbd{d}@@ to remove it.

Retained drafts last only until Emacs exits. Discarding a draft abandons
unsaved edits; it does not undo a completed save. A voice editor reports saved
settings separately from successful application to the speech server. Keep
that distinction when deciding whether to retry or to edit the saved voice.

Applying waits for each speech stream to acknowledge its configuration.  If
an Omnivox apply times out, the Workbench reports /server outcome unconfirmed/.
Emacsvox stops that apply and sends no later steps, but changes already sent
may still take effect on the server. A timeout does not undo the saved engine
settings or confirm that the server rejected them. Press @@texinfo:@kbd{r}@@ to reapply
the saved engine settings and obtain a fresh result.  Save or cancel any newer
staged edits before retrying.  A partial result retains the streams that
acknowledged success and identifies those that timed out.

** Voice Lock And Advanced Configuration
:PROPERTIES:
:TEXINFO_NODE_NAME: Voice Lock
:ALT_TITLE: Voice Lock Compatibility
:DESCRIPTION: Understand the established face and personality voice adapter.
:END:

#+cindex: Voice Lock

Voice Lock is one compatibility input to Aural Presentation, not the whole
presentation system.  It maps established Emacs faces and ~personality~ text
properties to voices.  Emacs calls its visual style labels /faces/; Emacsvox
can use those labels without requiring you to see them.

The three related policies are independent:

#+attr_texinfo: :columns 0.28 0.42 0.30
| Policy | What it controls | How to inspect or change it |
| Semantic presentation | Rules based on roles, events, states, and attributes supplied by integrations. | Use @@texinfo:@kbd{C-e E}@@, Presentation options, and Your feedback rules. |
| Explicit face presentation | Aural rules that deliberately match a named Emacs face. | Run ~emacsvox-aural-toggle-face-presentation~ or inspect it in Aural Doctor. |
| Voice Lock | The historical face or personality-to-voice mapping in each buffer. | Use @@texinfo:@kbd{C-e d v}@@ locally or @@texinfo:@kbd{C-e d C-v}@@ globally. |

To find out whether a distinction comes from Voice Lock:

1. Move across two elements that the mode treats differently, such as a comment
   and string in source code or a heading and link in Org.

2. Press @@texinfo:@kbd{C-e d v}@@ to toggle Voice Lock only in that buffer, then
   compare the same elements.

3. Press @@texinfo:@kbd{C-e E}@@ on the element.  The explanation reports the
   Voice Lock and explicit face-presentation state alongside the rules that
   contributed to the result.

Turning Voice Lock off removes only its compatibility voice contribution.  It
does not disable semantic presentation, explicit face rules, auditory cues,
tones, or ordinary spoken status.  The global Voice Lock command updates
existing and new buffers; an individual mode can still opt out when it starts.
Buffer-local Voice Lock state is not saved in a presentation profile.

For new customization, prefer explanation, Aural Home, voice palettes, and
Voice Workbench.  Older configurations can still customize a named legacy
voice's ~-settings~ option, such as ~voice-monotone-settings~.  Customize the
settings option rather than a generated ~acss-...~ voice symbol.  Historical
background is preserved in
@@texinfo:@ref{Audio Formatting And Aural CSS,,,emacsvox-heritage,Emacspeak Heritage}@@.

Named formatting voices such as ~bolden~ and ~annotate~ follow the active
palette. An inherited standard entry may use a personality's ~-settings~
option as its implementation. This is the definition in the explicit standard
root, not a second hidden palette fallback. Explicit styles keep their own
settings, and explicit presentation rules can change the resulting voice.

The [[info:emacsvox#Integration Maintenance][Developer Guide]] covers voice-style metadata, rule authoring contracts,
and integration behavior; [[info:emacsvox#Speech Server Protocols][Speech Server Protocols]] covers delivery.
The generated @@texinfo:@ref{Emacsvox Commands And Options,,,emacsvox-reference,Emacsvox Reference Manual}@@
records exact commands, options, and keymaps. These references complement the
tasks here; they are not prerequisites for using Aural Home.
