* Aural Presentation: Speech, Voices, And Sound
:PROPERTIES:
:TEXINFO_NODE_NAME: Aural Presentation
:ALT_TITLE: Aural Presentation
:DESCRIPTION: Understand and adjust how Emacsvox conveys meaning.
:END:

#+cindex: Aural Presentation

A heading, an unread message, and a warning need not sound alike. Aural
Presentation lets Emacsvox express those differences through speech, voices,
short sounds, tones, pauses, and spatial cues. The application identifies
what happened; presentation rules choose the feedback. The speech server
then produces it with the voices and output capabilities on your machine.

Begin with the item you heard. Press ~C-e E~ to explain its feedback,
~C-e H~ for the settings menu, or ~C-e S~ for the current task's focused
settings where available. These commands open inspection and editing tools.
The everyday workflows below use them rather than hand-edited configuration
files.
For help entering those sequences, see [[*Read the key instructions][Read the key instructions]].

[[*Choose the change you need][Choose the change you need]] helps you pick the right tool. To listen
without making changes, start with [[*Listen without changing settings][the voice-preview exercise]]. The rest of the
chapter explains feedback rules, voices, engines, sounds, output and saved
setups. Each procedure includes its own menu route. Action search at
~C-e H a~ can also select the relevant control before you activate it.

When something is wrong, go directly to [[*Troubleshooting And Recovery][Troubleshooting and recovery]].
In an Aural interface, ~C-c C-i~ opens its manual topic; ~q~ in Info returns
to that interface. In the interface's Help, ~i~ opens the same topic.

** Choose the change you need
:PROPERTIES:
:TEXINFO_NODE_NAME: Choosing A Presentation Change
:DESCRIPTION: Choose between a voice edit, a matching rule, an engine preference, and output settings.
:END:

#+cindex: which voice setting to change
#+cindex: normal reading voice, choosing an operation
#+cindex: rule or palette

Start with the result you want, not with the name of an editor. A voice edit
changes how a shared voice sounds. A rule changes which items receive that
voice or other feedback. Output settings control delivery. The distinctions
below help avoid making a wider change than intended.

*** Change ordinary reading
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Edit the active palette's =default= named voice to change normal text and
labels that do not request an explicit voice. Other entries, such as the
voice used for headings, keep their own settings. Choose this route for a
more comfortable everyday reading voice, not for one exceptional heading.
See [[*Edit A Named Voice][Edit a named voice]].

*** Change one kind of item or one context
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Use a presentation rule when the change belongs to matching headings, prompts,
message fields or events. Inspect a representative item, choose the criteria,
and decide how long the rule should last. A rule for the current buffer can
match several items there; it is not automatically limited to the one under
point. The [[*Walkthrough: Change Headings In One Buffer][heading exercise]] is a reversible starting point.

Use [[*Remap One Item At Point][voice mapping]] to choose a different named voice for those items. Use
[[*Guided Change This Feedback][a guided feedback change]] to add, remove or alter a voice, sound, tone or
spoken label. Neither operation requires retuning the shared named voice.

*** Retune a voice wherever it is used
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Edit a named voice when its other uses in the palette should change too.
For example, adjusting =bolden= affects items that resolve to that entry,
not only the item from which the editor was opened. Inspect its known uses
before saving. For a change limited to the original context, use a rule instead.
See [[*Edit A Named Voice][Edit a named voice]] and [[*Inspect Or Adjust A Voice In Context][voice adjustments in context]].

*** Prefer one physical voice throughout a palette
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Use [[*Use one physical voice across a palette][the palette-wide review]] when you want a physical voice to be preferred
across all its effective named entries while retaining their different
adjustments. Review the proposed result for several entries before saving.
This is a one-time edit, not a policy automatically inherited by future names.
It is broader than editing =default=.

*** Change how an engine is chosen
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Use [[*Set Shared Engine Preferences][engine preference]] when you want to change the shared engine order.
It does not override explicit physical choices already stored in named voices.
If one item still uses another engine, inspect that voice's physical choices
before changing the engine order again. [[*Browse Installed Voices And Choose Engines][Voice availability and activation]] are
separate from preference: an installed or allowed voice is not necessarily ready
to play.

*** Change delivery or one unwanted sound
:PROPERTIES:
:TEXINFO_NODE: no
:END:

For reading speed or punctuation detail, use [[*Set the reading scope, rate, and punctuation][Speech settings]]. For the place
where notifications play, use [[*Understand the main and notification streams][notification routing]]; for their loudness, use
[[*Adjust output volumes][output volumes]]. These controls do not decide which text an application
speaks automatically. Its [[*Adjust an integration's speech settings][focused speech settings]] control that behaviour.

For one unwanted cue, follow [[*Walkthrough: Silence One Cue][Silence one cue]] instead of disabling all sound.
To change the recordings used by a family of cues, choose a [[*Walkthrough: Try A Sound Pack][sound pack]].

After choosing the operation, decide whether to keep a draft, use the result
now or retain it for startup. [[*Choose What Persists][Choose what persists]] explains those choices;
the scope shown in a menu does not make every Save action equivalent.

** Getting Started With Settings Menus
:PROPERTIES:
:TEXINFO_NODE_NAME: Aural Home
:ALT_TITLE: Getting started with settings menus
:DESCRIPTION: Try a voice, navigate settings menus, and return from editors.
:END:

#+cindex: Aural Home

*** Listen without changing settings
:PROPERTIES:
:TEXINFO_NODE_NAME: Previewing An Installed Voice
:DESCRIPTION: Hear an available voice and return without saving or changing selection.
:END:

This exercise previews an installed voice without changing saved settings.
Start in an ordinary working buffer so the menu has a source to return to.

1. Press ~C-e H v b~ to open the engine browser through /Voices and engines/.
2. Select an available engine and press ~v~ to list its voices. ~RET~ on an
   Omnivox engine opens its status, downloads, and settings instead.
3. Move to an available voice and press ~P~ to hear a sample. ~S~ stops it.
4. Use ~q~ to return through the browser's parent views to /Voices and
   engines/. Once back in the menu, ~C-q~ closes the menu sequence. The
   original buffer remains your working context.

Browsing and previewing save nothing. A downloaded but inactive voice may
need enablement and Apply before it can be sampled; choose an already available
voice for this first exercise. If an engine is unavailable, its details explain
why. If speech itself is absent, begin with
[[info:emacsvox#Recovering From No Speech][Recovering From No Speech]].

*** Choose an entry point and preserve your place
:PROPERTIES:
:TEXINFO_NODE_NAME: Returning From Settings
:DESCRIPTION: Understand the captured source and return through menus and editors.
:END:

The Emacsvox menu, ~C-e H~, groups settings by task. ~C-e S~
opens the current buffer's focused integration settings, or general buffer
settings when no focused menu exists. ~C-e H .~ always opens general buffer
settings. A directly opened focused menu captures the buffer on entry; ~q~
closes it and announces the restored buffer and mode with a close earcon.

The menu captures the source item for contextual actions. In Feedback Details,
~q~ returns to the menu with the same item and settings scope; another ~q~
closes that menu. Opening Feedback Details directly keeps its usual return
destination. A changed or deleted source item must be selected again by
reopening the menu. If the source buffer has closed, the menu cannot resume.

Editor and manager ~h~ keys open the Transient settings menu with the original
source item. Closing that menu returns to the editor without saving or
discarding its draft.

The menu continues to refer to the item captured when you opened it, even
if you move point in the source buffer. Use ~C-e H b~ to return to that
position. To work on a different item, close the menu and reopen ~C-e H~
from the new item in an ordinary buffer.

The former Aural Home table remains available through ~M-x emacsvox-aural~
for existing configurations. Its ~C-e H h~ entry has been retired; the
workflows below use the settings menus.

Leave an editor using its own ~q~, ~h~ or finish action before using menu
keys. The same letter can mean something else while the editor still has
focus. Returning does not reverse an applied setting, and keeping an unfinished
draft does not save it. See [[*Choose What Persists][Choose what persists]] before leaving work that
you need in a later session.

**** Navigate menus and read Help
:PROPERTIES:
:TEXINFO_NODE: no
:END:

The settings menus use Transient. Up/down moves through choices, left/right
moves between sections, and ~RET~ activates the selected choice. ~M-RET~
and ~C-j~ also activate choices. A displayed shortcut invokes its item
directly. In Emacsvox's menus, ~q~ or ~C-g~ goes back one menu and ~C-q~
closes the sequence. Changes already made remain in effect. Other applications
using Transient, including Magit, retain their own activation and quit keys.

Menu feedback interrupts previous main-stream speech, including when you
toggle scope or change a setting. Item announcements include the key without
repeating the word "shortcut" or the section name. Under the default
announcement mode, section names are spoken when you enter a section.
Left/right selects its first selectable item and normally speaks it with the
section name and position.

For menu Help, press ~?~ followed by a choice's key, or ~? ?~ for help on
the current menu. ~q~ in that Help resumes the menu, including its parent menus.

***** Choose navigation and announcement preferences
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Press ~C-e H s n~ for Menu navigation. Choose ~c~ for Continuous, which
crosses sections and wraps around the whole menu; ~w~ to wrap within the
current section; or ~s~ to stop at section edges with a boundary earcon.
Left/right moves between sections in every style. Changes apply immediately
to all Transient menus, independently of the current-buffer settings scope.
Wrap within section is the default.

In the Presentation section, choose ~i~ for Item first or ~n~ for Section
first. Item first is the default; Section first speaks the section name and
position before the item.

Choose ~m~ for /By movement: sections or items/. Left/right speaks only the
destination section and its position. Up/down speaks only the item, key, and
relevant value, even when Continuous navigation crosses a section boundary.
Section-change and wrapping earcons remain the same. This option applies to
all three navigation styles and all Transient menus, including Magit; it does
not change the navigation style.

Section arrows still select the first item. In Emacsvox menus, ~RET~ therefore
activates that item even though its name has not been spoken, and the next
Down advances to the second item. Press ~C-u 0 <down>~ to hear the selected
item without moving. Magit's existing activation bindings remain unchanged.

Press ~v~ to toggle Detailed descriptions. When enabled, menu items retain
their labels and values and add a short command explanation. This applies
globally, including Magit; commands without documentation keep their labels,
and Transient's native infix controls keep their usual descriptions. Detailed
descriptions are on by default. Value adjustments still give brief feedback.
Press ~S~ to save the navigation style, presentation order, and descriptions
preference through Customize.

*** Find a setting or an action
:PROPERTIES:
:TEXINFO_NODE_NAME: Finding Settings And Actions
:DESCRIPTION: Search by name, inspect a control, and activate it deliberately.
:END:

Press ~C-e H /~ to find an Emacsvox setting by any part of its name, ignoring
capitalisation. Type =cap= to find /Capitalization indication and camel case/,
/Capital-letter beep/, /All-caps beep/, and /Spatial capabilities/. The aliases
=caps beep= and =allcaps= find both beep controls and only /All-caps beep/, respectively.
Each result appears once under its normal name. Use completion to choose a
result; ambiguous text does not choose one automatically. These matching rules
apply to this search without changing completion elsewhere in Emacs.

~RET~ accepts the choice, opens its menu, and selects the matching control
without changing its value. Press ~RET~ again to activate or edit the control.
The captured source and current settings scope follow the search. ~q~ returns
to the menu where you searched, and cancelling completion keeps that menu open.

Press ~C-e H a~ to find an action such as /Browse voices/, /Your feedback
rules/, or /Aural Doctor/. It uses the same case-insensitive partial-name
matching and two-Enter selection as settings search: choose the destination,
then activate its control. Child views return to their focused menu; another
~q~ returns to the menu where you searched.

Press ~C-e H b~ to close menus and return to the captured source position,
speaking its line. A changed or deleted source item must be captured again.

Press ~C-e H .~ for settings relevant to the captured buffer: speech,
indentation, typing/point feedback, capitalisation, and its major mode's
Customize group when available. This entry starts with buffer scope without
changing the parent's scope. ~A~ opens the advanced Emacsvox Customize group.
In these linked Customize buffers, ~q~ finishes Customize normally and returns
to the menu; use Customize's own Apply and Save commands. See
[[Integration speech settings][Adjust an integration's speech settings]] for application-specific controls.

In table-based managers and editors, the navigation controls are:

/Feedback for this item/ combines explanation, playback, and access to voice
and sound changes. ~C-e H f~ groups its editing routes. ~C-e H r h~ opens
/Semantic vocabulary/; change editors also link it from matching criteria.

The voice editor contains fields and buttons rather than table columns:
left/right changes a numeric value, and ~RET~ edits a field. See
[[info:emacsvox#Editing Named Voices][Edit a Named Voice]]. Keys are local to the view: ~w~ saves a voice in its
editor but exports a palette in the palette manager. Use ~C-c C-a~ to choose
an action by name, or ~?~ for that view's keys.

Panel entry, return, selection, and warning cues accompany their spoken
feedback in one utterance. Returning from a panel announces the destination
and any unfinished draft warning together. These cues follow the icon
setting, sound pack, and cue remapping rules. The voice editor uses the normal
navigation voice for these announcements; auditions still play the working
voice.

Opening settings or Help preserves the selected row and unfinished
edits. Buffer rule editors retain separate drafts for each source buffer;
reopening a modified editor resumes its draft. Reopening the same voice in
the voice editor likewise preserves its working settings. If a prepared remap's
source item changes or disappears, Emacsvox asks you to prepare that change
again before applying it.

Press ~C-e H p d~ to resume a retained draft in its original rule editor,
voice editor, or Workbench engine settings. The draft remains unsaved until
accepted there.
Presentation Profiles capture options, palette, sound pack, and spatial
settings. Physical choices and adjustments belong to named palette voices;
shared engine settings are saved separately. See
[[info:emacsvox#Saving And Startup][Choose What Persists]] before treating a setup as a backup.

** How Aural Presentation Works
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Model
:ALT_TITLE: How aural presentation works
:DESCRIPTION: Follow meaning from an Emacs application to audible output.
:END:

#+cindex: presentation model

Four questions explain the path from an application event to sound:

#+attr_texinfo: :columns 0.22 0.30 0.48
| Layer | Question | Example |
| Meaning | What happened or what is this? | A level-two heading was reached during navigation. |
| Presentation | What should convey that meaning? | Speak the heading in a named voice and play a section cue first. |
| Resources | Which voice and sound realise that request? | Find the named voice in the active palette and the cue in the active sound pack. |
| Output | What can this machine produce? | Route speech to an installed engine and apply supported spatial behaviour. |

An Emacs mode or integration supplies facts about an object or event. A fact
can identify a role such as a heading, an event such as completion, a state
such as unread, or an attribute such as heading level. Context says whether
you are navigating, reading continuously, or receiving a state change. The
same object can therefore receive concise feedback during continuous reading
and more orientation when deliberately reached.

Presentation rules match those facts and the context. A rule can choose a
voice, add speech or a cue, insert a pause or tone, request spatial placement,
or suppress something unhelpful. Several rules can contribute to the same
result. A stronger rule can replace just one part, such as pitch, while
leaving the other contributions in place.

The configuration layers, from weakest to strongest, are:

1. A fixed internal baseline preserving established Emacsvox behaviour.
2. Automatic integration behaviour supplied by the active mode or package.
3. Enabled /Presentation Options/, composed in their stable order.
4. Personal, session, and current-buffer rules for precise overrides.

A presentation profile is not another rule layer. It records selected options,
sound pack, voice palette, and spatial choices so you can switch them together.

For example, an Org integration identifies a level-two heading. A rule requests
=bolden= and a section cue. The active palette supplies =bolden='s settings and
physical choices; the sound pack supplies the cue. The backend plays what it
supports. Changing the rule changes which headings receive the feedback.
Editing =bolden= changes uses of that named entry. Switching sound packs changes
the recording of the cue while preserving its meaning.

When two rules set the same voice field, the stronger explicit value wins;
values are not added. Personal rules are weaker than session rules, which are
weaker than current-buffer rules. Rules can also add actions before or after
content. Use Explain to inspect actual contributors rather than inferring
precedence from the order in which you edited settings.

~C-e H r h~ opens the semantic vocabulary without changing settings.
~C-e H r t~ toggles training explanations across all buffers for this Emacs
session; it does not save a startup default.

*** What You Can Hear
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Modalities
:ALT_TITLE: What you can hear
:DESCRIPTION: Recognize speech, voices, cues, tones, pauses, and spatial output.
:END:

#+cindex: presentation modalities

Aural Presentation combines these forms of feedback:

- /Speech/ conveys content, labels, prompts, results, and status. Added speech
  should explain meaning not already clear from the content.
- /Voice/ changes characteristics of spoken content. Named voices make
  distinctions such as headings, annotations, warnings, or quoted text
  portable across engines.
- /Auditory cues/, also called /earcons/ or /auditory icons/, are short sounds
  associated with events or objects. Sound packs supply recordings for cue names.
- /Tones/ convey compact information using a pitch and duration, without
  requiring sampled sound or a spoken explanation.
- /Pauses/ separate related parts without adding words.
- /Spatial presentation/ places speech or cues across supported output. A
  backend unable to provide requested placement keeps content audible through
  its documented fallback.

These can be ordered around content. Entering a section might play a cue,
speak its heading in a distinctive voice, and leave a pause before body text.
The presentation is one result, not unrelated notifications. Its precise sound
depends on engines, installed voices, sound pack, and hardware. The intended
distinction should remain understandable when a simpler backend offers fewer
voice characteristics or centred output.

** Understand Why Something Sounded That Way
:PROPERTIES:
:TEXINFO_NODE_NAME: Explaining Presentation
:ALT_TITLE: Understand why something sounded that way
:DESCRIPTION: Explain current or recently queued feedback.
:END:

#+cindex: explaining presentation

Use this workflow when feedback is surprising, unclear, or especially useful:

1. Leave point on the object and press ~C-e E~, or open ~C-e H x~ through
   the settings menu. Both open /Feedback Details/ with a brief introduction
   instead of reading the whole report. The menu route uses the Outline
   layout described below.
2. Inspect the object and occasion, matching rules, selected actions, concrete
   voices and sounds, and any backend fallback or degradation.
3. Identify the strongest rule changing the part you care about. This tells
   you whether to inspect an option, personal or temporary rule, named voice,
   sound pack, or Voice Lock contribution.

~C-e H f~ groups current and recent feedback actions. ~x~ explains the captured
item, ~c~ opens a guided change, ~v~ prepares a voice mapping, ~t~ tunes the
named voice used there, and ~e~ prepares an exact cue remap. ~h~ opens recent
feedback, whose changes use the selected frozen record. Tuning a named voice
affects its other uses; a mapping changes which matching items use a voice.

Opening an editor from this menu does not bypass its preview, matching
criteria, scope or Apply/Save steps. On return, the menu selects the same
entry. A guided draft can be resumed later in this session, while leaving a
modified rule list still asks before discarding it. If the captured source
item has been replaced, prepare the change again; the editor does not silently
apply it to a different target.

*** Distinguish a record from a simulation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

When retained feedback matches the source buffer, position, and unchanged
text, the report describes the exact output queued, including the source and
resolved resources. It does not reinterpret old output with your latest
settings. Without an exact record, the report is labelled as a simulation of
what the current rules would produce at point.

A simulation uses captured text and context. /Play simulation/ plays that
baseline, not a recording of earlier sound. It supports field review and draft
previews but is never added to Recent Feedback. A prefix argument with ~C-e E~
selects a simulated occasion explicitly. ~q~ returns to the source or menu
item from which the report was opened.

Expand a field and choose /Edit named voice bolden/, or its reported voice
name, to open the voice editor. Multiple named voices receive separate links.
This edits the entry in the reported palette and affects its uses there.
/Change field/ instead changes the field's feedback rule. Leaving the voice
editor returns to the same link; opening it does not save or apply anything.

*** Inspect recent feedback
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Press ~C-e H f h~ for recent feedback. Each row preserves one recorded
presentation within the history's size limit. Its Content column reads the
preview with captured voice annotations, including changes within the entry;
other columns and titles use the normal interface voice. ~P~ requests replay
with the engine and physical voice recorded for the original delivery.

#+attr_texinfo: :indic kbd :compact t
- RET or e :: Open Feedback Details for the selected presentation.
- P :: Replay retained feedback with recorded voices without adding history.
- c :: Audition only its auditory cues.
- r :: Prepare a voice remap from the selected record.
- R :: Replace, suppress, or restore one exact earcon.
- L :: Change the bounded history limit for this session.
- i :: Include or exclude feedback from Aural interfaces themselves.

To change the same policy from a menu, open ~C-e H f H~. Select /Retained
records/ and use ~RET~ for an exact nonnegative limit, or Shift-left/right to
adjust by one. Lowering the limit immediately discards the oldest excess
records; zero clears and disables history. Increasing it cannot restore those
records. The menu's ~i~ toggles interface recording, and ~w~ saves both defaults
through Customize. Retained feedback itself is never saved by this action.

Aural interface feedback is excluded by default so it does not displace the
feedback being investigated. This includes their prompts, completion choices,
and opening/closing sounds. Ordinary completion elsewhere remains eligible.
Changing the setting affects new recordings, not entries already retained.

*** Read and edit the report's fields
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Feedback Details selects a separate read-only buffer and gives a brief
introduction. It stays attached to its presentation as new feedback arrives;
ordinary Help does not replace it. When opened from Recent Feedback, ~q~
returns to the same row and column.

Where integrations supply semantic fields, the report groups consecutive voice
spans accordingly. Notmuch results, for example, expose /Authors/, /Subject/,
/Date/, /Message count/, and /Tags/. Headings identify recorded logical voices.
Collapsed fields show only headings. Visibility uses configured cues or optional
spoken labels; /expanded/ and /collapsed/ are not inserted into heading text.

~RET~ on a heading exposes its text, playback/change controls, voice source,
sounds, and limitations. Content uses captured voice annotations. Fields with
multiple spans offer /Individual voice spans/ for finer inspection. That heading
announces the section without repeating content. A single-span field shows its
text and controls once and omits a span count. ~RET~ collapses the field again.

Spoken labels such as /indent 2/ have separate /Before speech/ or /After speech/
headings, distinct from content spans. ~RET~ on a label heading, or ~O~ within
it, replays that label using recorded settings. /Edit named voice indent/ opens
the palette voice editor with /indent 2/ as sample text; it changes every use of
that entry in the recorded palette. The report's recording stays frozen: use
the editor's preview for changes. Labels without a named palette voice remain
playable and explain why an editor link is unavailable.

Fields with unapplied drafts announce /unsaved change/. The report also counts
such fields. These indicators update without replacing buttons or return
positions; ~g~ refreshes draft status, for example after killing a draft buffer.
It does not change the recorded or simulated baseline.

The original report layout uses these controls. Outline changes heading and
button navigation as described in the next subsection, not playback semantics.

#+attr_texinfo: :indic kbd :compact t
- n or p :: Move between headings; collapsed fields speak the heading, expanded fields also speak annotated content.
- Up or Down :: Review lines without reading the whole report.
- TAB or Shift-TAB :: Move between action buttons; RET activates or expands.
- O :: Play the original field, span, or label at point, or its labelled simulation.
- P :: Play the full original presentation or labelled simulation.
- C :: Open or resume a field/span change; on a label, edit its named voice.
- r :: Choose a named voice for matching items; on a label, edit its named voice.
- R :: Replace, suppress, or restore an exact sound in the field or span.
- V :: Preview the full presentation with linked draft changes.
- S :: Stop playback.
- g :: Refresh draft status.

For example, select /Subject/, press ~C~, and choose another content voice.
In the editor, ~O~ plays the original field and ~P~ the changed field.
/Play whole original/, also on ~B~, compares with ~V~ for the full presentation
and linked drafts. Both keep you in the editor. The original remains frozen,
including before a change or lifetime is chosen. A simulated report uses
/Play whole simulation/ for its frozen baseline.

Return to the report and choose /Message count/ to add a sound /After content/.
It plays once after the complete count, even if the field contains several
voices. Subject and count keep separate drafts. Their criteria identify field,
integration, mode, and occasion; inspect them before selecting buffer, session,
or saved-personal lifetime. Remapping the field does not retune a shared voice.

/Choose another voice for matching items/ opens the compact voice editor.
Inspect /Applies to/ and choose /How long/ before saving. /Change field/ opens
the full component editor on the same draft. A draft already changing another
component stays in the full editor so that work is not hidden.

/Sound overrides: replace, suppress, or restore/ prepares a separate exact-sound
rule draft restricted to the field. It is not included in linked-field previews.
/Restore inherited behavior/ removes an override made by that workflow in the
selected scope. ~q~ returns to the report.

*** Use the Outline report from the menu
:PROPERTIES:
:TEXINFO_NODE: no
:END:

~C-e H x~ opens the experimental Outline version of Feedback Details. It is
read-only, with a visible summary and initially folded fields. ~TAB~ on a
heading cycles visibility, ~S-TAB~ cycles the whole report, and ~n~/~p~ moves
between visible headings. Standard Outline minor-mode commands are available
under ~C-c @~, including ~C-c @ C-u~ for the parent. Arrows read visible lines.
~RET~ folds a heading or activates an action. Away from a heading, ~TAB~ and
~M-n~ move to the next visible action. Playback and editing use the report
commands above.

~o~ compares Outline with the original layout. Refreshing draft status with
~g~ preserves folds and position; returning from an editor preserves its
button. The report still describes the captured feedback. Reports opened
directly start in the original layout; ~o~ switches their style.

*** Understand playback evidence and limitations
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Original replay uses the recorded engine and physical voice, including
notification voices and fallbacks, with captured tuning even after a palette
change. It synthesises speech again at the current reading speed and host
pronunciation settings. History stores no audio. Cue and pause order remains,
but timing may differ from the first delivery.

Replay requires a completed presentation with complete Omnivox voice receipts.
Older, interrupted, truncated, or unsupported records remain inspectable but
report replay unavailable rather than guessing a voice. Cues positioned inside
speech, or voice changes that cannot be aligned after host text processing,
also prevent original replay. An unavailable recorded voice stops playback
instead of substituting another. Navigate over the source to capture a new
example.

A simulated report labels its baseline throughout the report and change editor.
Proposed playback uses current rules, captured buffer context, and linked drafts
without applying them. A span can be targeted only when its semantic field,
distinct named face, or explicit voice annotation identifies it. Truncated
history cannot supply complete playback or a comparable preview. Records
missing preview inputs remain readable; capture a new example before previewing.

Each field explains the sources of its voices and sounds, such as a face or
personal override, using the contributors actually captured. Unsupported voice
families and other limitations appear beside the affected field.

/Debug details/ opens a separate read-only raw snapshot of facts, rule IDs,
resolved voices, and backend diagnostics. Opening speaks only a short
announcement. ~q~ returns to the same report location with fields and drafts
retained.

~C-e H r t~ toggles /Explain feedback as you navigate/ for this session. It adds
concise semantic explanations after normal presentations, useful for learning
an integration's vocabulary. It is deliberately more verbose than normal use;
turn it off when no longer needed.

*** Walkthrough: Change Headings In One Buffer
:PROPERTIES:
:TEXINFO_NODE_NAME: Heading Voice Walkthrough
:ALT_TITLE: Walkthrough: Change Headings In One Buffer
:DESCRIPTION: Try a heading voice, verify the scope, and undo the rule.
:END:

This experiment changes headings in a temporary Org buffer without altering
palette definitions or saved personal rules.

1. Use ~C-x b~ to create a buffer named =*aural-practice*=. Run ~M-x org-mode~
   and insert:

   #+begin_example
   * Reading notes
   An ordinary paragraph.
   * Next steps
   Another ordinary paragraph.
   #+end_example

2. Move onto the first heading and press ~C-e E~. Identify its named voice
   and heading facts, noting whether the report describes recorded output or
   a simulation. Press ~q~ to return to the source before opening a new menu.

3. Press ~C-e H f c~ for the guided change. Press ~c~, select /Content voice/,
   and choose =annotate= with ~RET~, or =bolden= if =annotate= is already used.
   ~O~ plays the original and ~P~ previews the proposed voice. Only the draft
   has changed.

4. Press ~m~ for /What should match/. Keep the Org module, heading role, and
   heading level if shown. Leave other criteria as shown for this experiment.
   Press ~l~ and select /Current buffer, until it is killed/. This matches
   every qualifying heading in the buffer, not only the original heading.

5. Review the summary, then press ~a~. Open settings with ~h~,
   then press ~b~ to return to the captured item. Move between the two headings
   using the same navigation action. Both matching headings should use your chosen voice; the ordinary
   paragraphs should keep their previous presentation.

6. Press ~C-e E~ on a heading again. Check that the buffer rule supplies the
   selected voice. If the sound is too similar to distinguish, the report
   still shows whether it matched. Compare voices or consult

7. Open ~C-e H r o~ for /Your feedback rules/. Find the rule in buffer scope
   and inspect its target. ~t~ disables it and ~d~ removes it. Revisit the
   heading to check the result. Killing the practice buffer also ends its
   buffer rules; none survives an Emacs restart.

For a lasting change, repeat on a representative item and choose /Saved
personal rule/ at step 4. Review the criteria carefully: that rule can affect
future matching buffers.

*** Guided Change This Feedback
:PROPERTIES:
:TEXINFO_NODE_NAME: Guided Feedback Changes
:ALT_TITLE: Make a guided feedback change
:DESCRIPTION: Change one component, preview its effect, and choose matching criteria and lifetime.
:END:

1. Move to an item and press ~C-e H f c~ to capture /Current item/. For earlier
   feedback, open ~C-e H f h~, select a record, and press ~C~. A multipart
   record expands numbered parts in playback order. Move with ~n~/~p~ to
   hear text in captured voices, ~O~ to replay the part, and ~RET~ to choose
   it. Truncated history cannot provide a complete original/proposed comparison.

2. Press ~c~ to expand component changes and ~RET~ on a choice. /Content
   voice/ expands named voices, identifies original and replacement, and lists
   the original first when available, then alternatives alphabetically.
   Selecting a voice with ~RET~ keeps the panel open for comparison. Changes
   can add a cue, tone, or spoken label, replace a sound, change a tone, or
   suppress a component. A cue can be added when none existed. Choices depend
   on integration facts; they cannot create missing semantic distinctions.

   ~RET~ on /Parts/ reopens the parts; each retains its unfinished choices.
   ~q~ goes up one level, for example from a voice to /Content voice/ and
   then /Change/. The section closes and its parent's name and state are
   announced through the configured cues and labels. At the top, ~q~ leaves
   the panel while preserving its draft.

3. Press ~P~ to preview before choosing a lifetime. ~O~ replays the original
   and ~S~ stops. Proposed preview resolves the example with current rules
   and captured context; it does not apply the draft to live feedback.

4. Press ~m~ or ~RET~ on /What should match/. Facts, states, events, and
   occasions are marked /Included/ or /Excluded/. All included conditions must
   match; excluded conditions are ignored, not forbidden. The captured or
   simulated example's facts are not editable, but can be selected as conditions.
   Opening criteria preserves existing selections; extra facts start excluded.

   A mail action of /select/ describes the operation producing feedback, not
   selection in this editor. Include that action, or an event such as
   /operation failed/, to restrict the rule. ~RET~ toggles each criterion.
   Excluded criteria remain available to restore. Excluding /with state unread/
   while retaining /with role field/, /with field kind authors/, and the
   Notmuch integration matches authors in both read and unread messages.
   Keep at least one criterion. The parent row summarises the match; ~m~
   collapses the criteria. These conditions govern matching items, not one
   document object.

   A shell example may match "Items from the shell integration, in shell
   mode, during navigation, and with text style comint highlight prompt."
   The text style names the Emacs face used to display that text.

5. Press ~l~ for /How long/: source-buffer lifetime, this Emacs session, or
   a saved personal rule. A buffer rule affects every matching item in that
   buffer. Review target, change, criteria, and lifetime together.

6. Press ~a~ or ~C-c C-c~ to apply or save. ~e~ opens the prepared rule in
   the Advanced editor. At the top, ~q~ hides the guided draft. Resume it
   through ~C-e H p d~, which opens the retained draft in its owning editor.
   Aborting a choice or leaving before Apply does not change live rules.
   Failed saves retain the draft and report failure.

Replacing or suppressing a sound targets its identity in a before- or
after-content phase while retaining other components. Existing rule data can
insert only at a phase's beginning or end, so replacing a middle component
asks which edge to use and includes that placement in the summary. Ambiguous
components require the Advanced editor. Current-item changes recheck their
captured source; a changed or killed target must be inspected again. Historical
changes remain tied to the selected record.

** Choose And Manage Voice Palettes
:PROPERTIES:
:TEXINFO_NODE_NAME: Voices And Routing
:ALT_TITLE: Choose And Manage Voice Palettes
:DESCRIPTION: Understand named voices, standard inheritance, and personal palettes.
:END:

#+cindex: voice palettes
#+cindex: acss-default
#+cindex: palette inheritance
#+cindex: voice aliases

A /named voice/, also called a /logical voice/ in detailed views, gives a
reusable name such as =bolden= or =annotate= to a way of speaking. A /voice
palette/ contains these entries. Each includes shared adjustments, ordered
physical choices, and adjustments for individual choices.

A /physical voice/ comes from an installed speech engine. The palette expresses
intended choices; availability and shared engine preferences determine which
can be used. A presentation rule determines when to use a named voice. Editing
that entry changes every use resolving to it; changing a rule changes which
items select it.

This section manages the collection. [[info:emacsvox#Editing Named Voices][Edit a Named Voice]] covers its physical
choices and adjustments; [[info:emacsvox#Installed Voices And Engines][Installed Voices and Engines]] covers browsing and
engine preferences.

Open /Voice Palettes/ with ~C-e H v p~. ~RET~ on a palette browses its voices,
~P~ auditions its sequence, and ~a~ activates it. Built-in palettes remain
intact; editing can open an unsaved personal child in the common editor.

*Upgrading personal palettes.* This version accepts schema 3 only. Before
upgrading older personal palettes, back up palette/routing data and arrange a
reviewed conversion of entries and physical choices. Opening or previewing does
not convert them. Preserve names and profile references, with each personal
parent chain ending at =acss-default=. Shared per-voice routing, migration,
and preset screens have been removed; use the common editor for named-voice
choices and adjustments. Shared engine preference remains separate.

Opening the manager announces its selected palette; entering a palette
announces its name, voice count, selected voice, and main keys. /Kind/
distinguishes personal, built-in, and standard-default palettes. /Parent/
names the inherited source. Read-only =acss-default= is the root: chains such
as =a -> b -> c -> acss-default= are supported. It provides personalities from
Emacsvox and loaded integrations, not a fixed list of all custom names. Only
the root has no parent.

A palette inherits the nearest complete definition of a named voice. Its
style, ordered physical choices and individual tuning come from that one
entry; they are not assembled from several parents. The /Source/ column names
the supplying palette, and capital ~O~ opens it.

Press ~u~ for /Where Used/ before editing a shared entry. This lists known
loaded references, aliases and affected descendant palettes. It cannot inspect
configuration that has not been loaded. Editing a shared entry asks you to
review those known uses and descendants.

An /alias/, such as =voice-bolden= for =bolden=, is a declared alternative
spelling of the same entry. Integrations maintain aliases; the manager does
not edit them as separate voices. Use Copy Voice for an independently
adjustable entry.

~N~ in a voice list creates New Voice and ~c~ copies one into an unsaved
editor draft. Copy preserves the full effective entry, fallback order, and
individual tuning. Editing or copying a built-in voice requests a personal
child palette; saving adds only the requested direct entry. Opening or previewing
writes nothing.

~R~ resets a personal definition to its inherited entry. Confirmation names
the source that will take over and rejects a source changed during confirmation.
Other saved settings remain. ~d~ deletes a direct custom voice with no inherited
replacement; built-in and inherited entries cannot be deleted. Remap known
references first if deletion would leave them unresolved. Finish or discard
voice drafts before deletion. ~o~ returns to the palette manager.

New Palette, ~N~ in the manager, creates a child of the chosen parent. Copy
Palette, ~c~, saves all effective entries independently under =acss-default=;
local physical choices belong to the new palette. The summary and parent action
~E~ inspect or change a personal parent; inheritance cycles are rejected.

To delete a personal palette, select it and press ~d~. Change children and
known references, including saved profiles, and finish/discard its voice drafts
first. Deleting an active palette returns to the standard baseline.

In Voice Palettes, ~a~ activates the selected palette for this session.
To return to following the standard baseline, press ~f~. That clears an
explicit session selection without deleting palette data or changing startup.

Capital ~U~, /Use at Startup/, changes the palette named by the selected
saved Presentation Profile and preserves that profile's other fields. It does
not apply the profile now. With no startup profile, the operation proposes
one captured from the current setup; review it before saving. Its checks cover
saved rules and profile options, not session or buffer rules. An open Profiles
view refreshes to show the saved choice.

*** Walkthrough: Make A Personal Reading Palette
:PROPERTIES:
:TEXINFO_NODE_NAME: Personal Palette Walkthrough
:ALT_TITLE: Walkthrough: Make A Personal Reading Palette
:DESCRIPTION: Create, edit, save, activate, and optionally select a palette for startup.
:END:

Use an unused name; =reading-demo= is an example. Note the currently active
palette so you can restore it.

1. Open ~C-e H v p~. Press ~N~, enter =reading-demo=, describe its purpose
   as ``My reading experiments'', and choose =acss-default= as parent.
   Creation saves but does not activate the palette. Its standard voices
   are inherited.
2. Press ~RET~ to enter it. Find =bolden= and inspect /Source/, which should
   name =acss-default=. ~.~ repeats the column title/value, ~SPC~ reads the
   row, and ~P~ previews the voice.
3. Press ~e~ to edit =bolden=. Check destination and inherited source, then
   set /Average Pitch/ with ~RET~ to =6=, or =5= if already six. ~B~ compares
   opening and edited voices using one sample. Unsupported adjustments remain
   reported; consult [[info:emacsvox#Voice Adjustments][Voice Adjustments]] if the contrast is unclear.
4. Choose /Save to collection without selecting/. After the save result,
   ~q~ returns to the voice list. /Source/ should now name =reading-demo=;
   other inherited entries retain their providers. This is a complete local
   entry, not a pitch-only patch on its parent.
5. Use ~o~ to return to the manager and ~a~ to activate =reading-demo=.
   Check status and revisit content using =bolden=. This changes every use
   resolving to that entry. Explain at the source distinguishes palette
   settings from contextual rules.
6. For startup, press ~U~ on the palette and review the proposal. It changes
   the saved profile's palette selection. If a new profile is proposed,
   review its other settings too. Saving a palette is not startup selection.
7. Restore the original sound by activating the previous palette. If startup
   was changed, use ~U~ on that original too. The saved demo remains for later
   experiments. To remove only its =bolden= override, follow
   [[info:emacsvox#Palette Inheritance Walkthrough][Inheritance, Aliases, and Reset]].

*** Walkthrough: Inheritance, Aliases, And Reset
:PROPERTIES:
:TEXINFO_NODE_NAME: Palette Inheritance Walkthrough
:ALT_TITLE: Walkthrough: Inheritance, Aliases, And Reset
:DESCRIPTION: Follow an entry to its parent and distinguish an alias from a copy.
:END:

Use =reading-demo= from the previous exercise or another personal palette
with =acss-default= as parent.

1. In the manager, create =reading-child-demo= with ~N~ and choose
   =reading-demo= as parent. The chain becomes
   =reading-child-demo -> reading-demo -> acss-default=.
2. Inspect =bolden='s /Source/ in the child. A direct entry in =reading-demo=
   supplies the whole voice; otherwise =acss-default= does. ~O~ opens its
   provider and ~u~ shows known uses, aliases, and descendants.
3. =voice-bolden= is an alias of =bolden=, not a separate adjustable entry.
   Aliases are not created or edited in this view.
4. Copy =bolden= in the child with ~c~ to an unused name, such as
   =reading-heading-demo=. Change pitch, compare, and save to the collection
   without selecting. A rule must choose this name before ordinary content
   uses it; copying does not remap headings.
5. Edit the child's inherited =bolden=, change a field, and save to the
   collection. Its Source becomes the child. Back in the list, press ~R~.
   Confirmation names the parent entry that will take over. After confirming,
   =bolden= remains but its Source returns to the provider.
6. Delete =reading-heading-demo= with ~d~ when it has no inherited replacement
   or known use. Remove/remap a referencing rule first. Reset restores an
   inherited entry; Delete removes a removable custom name.

The root keeps standard voices available after Reset and cannot be deleted
or edited here. Palettes can contain custom names, and loaded integrations can
register more standard names. Copy Palette differs from New Palette: it copies
effective entries and stops following edits to the source while still inheriting
new standard names from =acss-default=. Definitions referring to an existing
personality still follow that personality's settings. A copy is not a sound
recording.

*** Rename Voices And Palettes
:PROPERTIES:
:TEXINFO_NODE_NAME: Renaming Voices And Palettes
:ALT_TITLE: Rename Voices And Palettes
:DESCRIPTION: Rename personal entries while checking their known uses.
:END:

~r~ in the voice list renames a direct custom voice in a personal palette.
Entering the new name saves it with its settings, physical choices, and tuning
intact. Finish/discard voice drafts first. Standard names cannot be renamed;
copy one for a custom entry. An inherited voice must be copied or renamed in
its owning palette.

Renaming updates personal, session, and buffer rules, face mappings, and loaded
global/buffer face maps. Personal rules and the voice are saved together; a
failure leaves the old name and mappings usable. Update face mappings written
in your Lisp configuration there too for future sessions. Maintained integration
rules, Presentation Options, and other voice definitions can block a rename
until their references are updated. Another palette directly defining either
name also blocks it because mappings are shared.

In /Voice Palettes/, ~r~ renames a personal palette and saves immediately.
It retains settings and fallback tuning, updates children and personal
Presentation Profiles, and keeps an active palette selected under its new name.
Finish/discard unfinished voice edits first. Built-ins cannot be renamed, and
maintained integration references can block the change until their owner
updates them.

** Edit A Named Voice
:PROPERTIES:
:TEXINFO_NODE_NAME: Editing Named Voices
:ALT_TITLE: Edit A Named Voice
:DESCRIPTION: Adjust a voice, compare it, and save the complete result.
:END:

#+cindex: voice editor
#+cindex: voice adjustments

Open a palette through ~C-e H v p~, select a voice, and press ~e~. To tune
the voice used by the captured source item, use ~C-e H f t~. This changes the
shared named entry, not a rule for that one item. ~q~ offers to retain unfinished
work and returns to the menu.

Saving an inherited voice creates a complete entry in the destination palette.
Editing a built-in palette requests a personal child. Opening and previewing
do not change live feedback or save settings.

=default= controls ordinary reading and labels without an explicit voice.
Choose it to change normal text's physical voice, fallbacks, or tuning. Each
palette has an effective =default=, inherited until locally edited. Switching
palettes changes it too. Other entries such as =indent= and =bolden= retain
their own settings; editing =default= is not a whole-palette voice change.

*** Adjust and compare one voice
:PROPERTIES:
:TEXINFO_NODE: no
:END:

The editor reads field labels in the normal navigation voice. Move between
fields with ~n~, ~p~, the up/down arrows or ~TAB~. Left/right adjusts a
numeric field and moves between other fields. Press ~RET~ to activate a
control or enter a value.

Lowercase ~d~, or blank numeric input, requests the adapter's default for
that adjustment. Entering zero instead requests an explicit value, such as the
lowest pitch or leftmost pan. A default and zero may sound alike for a
particular effect, but they remain different settings.

/More adjustments and effects/ exposes filters, gain, pan, and optional controls.
Point stays on its button and speech says ``More adjustments shown below'' or
``More adjustments hidden''. Move down or use ~TAB~ to enter exposed controls,
and activate the button again to hide them. Changed fields state earlier values;
unsupported settings stay visible and retained. Field navigation stops at its
ends without wrapping, and numeric limits announce minimum or maximum.

~P~ previews the edited voice; ~B~ compares captured original and edited versions
with the same sample and spoken labels. ~T~ changes sample text and ~S~ stops.
An automatic sample follows adjustments unless /Automatic sample after adjustment/
is off. The value precedes it, for example ``1. The quick brown fox…''.

That toggle announces on/off with distinct cues. /More adjustments and effects/
and /Fallbacks/ use open/close cues and optional state labels on both toggling
and navigation. Navigation stops a sample. ~u~ undoes an edit, including reset.
~q~ returns to the originating view, offering to retain or discard unsaved work.

/Physical voice/ searches engine or voice names. Audition with working adjustments
before accepting; cancellation keeps the earlier choice and returns to the field.
/Fallbacks/ allows replacement, reordering, removal, individual auditions,
appending, or returning to Automatic. Unavailable, engine-default, and property
choices are retained. Shared adjustments supply inherited fields;
/Customize this voice/ provides optional per-choice settings.

*** Tune through the focused menu
:PROPERTIES:
:TEXINFO_NODE: no
:END:

From ~C-e H v p~, select a palette, press ~e~, choose a voice, then press ~m~
in its shared editor. This tuning menu edits the same retained draft. Up/down
selects controls, left/right changes sections, and Shift-left/right adjusts
relative rate, pitch, pitch range, or gain by one unit. ~RET~ enters an exact
value. ~d~ restores the selected adjustment to adapter default, or asks which
one to reset. Zero remains explicit.

~f~ selects an existing fallback, ~h~ returns to shared settings, and the title
identifies scope. For a fallback, ~i~ inherits the shared value and ~d~ requests
adapter default. Play and Compare use the selected scope.

~P~ previews, ~B~ compares original/edited with one sample, ~S~ stops, and ~T~
changes text. These previews are private and exclude contextual rules.
Adjustments speak values without automatic samples here; the full editor's
automatic-sample preference is retained. ~u~ undoes the last draft change.

~e~ opens engine-specific settings, waiting for a qualified runtime catalogue
before permitting edits. Its ~q~ returns to the common editor; ~m~ reopens
focused tuning on the same draft and scope. Physical experiments, individual
fallbacks, and engine controls remain available in the full editor.

~w~ saves and applies; ~c~ saves to the collection without selecting. Existing
destination prompts, inheritance, and recovery remain. ~q~ stops playback and
returns to the editor with the draft. Leaving that editor still offers keep,
discard, or continue choices.

*** Save the draft and check application
:PROPERTIES:
:TEXINFO_NODE: no
:END:

<<voice-saving-procedure>>

~w~ or ~C-c C-c~ saves and applies a complete named-voice draft. Save buttons
follow settings, previews, and change details. /Save to collection without
selecting/ saves an inactive palette without changing selection. The header
separates unsaved changes, partial saves, applying, failures, and saved/applied.

Retry keeps the proposal and records which saving steps already succeeded.
If you make more edits while an earlier Apply is still waiting for a reply,
that reply does not save the later edits. They remain unsaved. If a file or
destination has changed, review the proposal again rather than expecting the
editor to merge those changes automatically.

Complete-choice previews require Omnivox's complete-voice-preview capability.
They do not select the draft or change live settings. Older hosts report this
unsupported; individual physical auditions remain available. Playback evidence
identifies accepted audio when reported, including unsupported adjustments,

~q~ returns to the originating row and column. Keep, discard, or continue with

*** Use one physical voice across a palette
:PROPERTIES:

:DESCRIPTION: Review a preferred physical voice across named entries before saving.

including =default= and inherited entries, are reviewed.

~S~ stops; ~x~ details descendants, retained fallbacks, and playback results.
An unavailable selected physical voice may cause fallback.

only the first moves; the others keep their order. A newly added choice follows
that entry's shared adjustments, while existing choices keep their individual

inherited in the future do not automatically acquire the chosen physical voice.

that pending retry; to use the saved palette later, select it deliberately

undoing its data or changing the selection.

*** Understand Voice Adjustments
:PROPERTIES:
:TEXINFO_NODE_NAME: Voice Adjustments
:ALT_TITLE: Understand Voice Adjustments
:DESCRIPTION: Understand the voice controls and their defaults.
:END:

Change one field at a time and compare with ~B~. Portable controls are not
measurements in Hertz or decibels, and equal values may sound different on
different engines. Most numeric fields use integer levels zero through nine;
Relative Rate is the exception.

- /Relative Rate/ ranges from -20 to 20. Negative requests slower speech,
  positive faster, and zero leaves base rate unchanged. Engine-relative steps
  are not words per minute. A stronger contextual value replaces rather than
  adds to this one.
- /Average Pitch/ requests lower or higher overall pitch. Start with a small
  contrast between voices for related content.
- /Pitch Range/ requests less or more pitch variation; supported low settings
  can sound monotone and higher settings more varied.
- /Stress/ requests emphasis according to the engine's implementation.
- /Richness/ changes tonal character or fullness where supported. Compare
  samples rather than treating it as volume.
- /Gain/ changes output level: five is unchanged, lower reduces, higher raises.
- /Pan/ requests left at zero, centre at five, and right at nine where supported;
  output arrangement also matters.
- /Low-pass Amount/ and /High-pass Amount/ remove high and low frequencies,
  respectively. Zero is neutral and nine strongest.
- /Reverb/ adds reverberation, /Echo/ delayed repeats, and /Chorus/ a doubled
  voice. Zero disables each; higher values increase it.
- /Portable Fallback Family/, where offered, is a compatibility hint. Use
  /Physical voice/ for an installed choice. Family is outside complete Omnivox
  voice preview.

In shared settings, ~d~ or blank input requests /adapter default/ and ~u~ undoes
it. For a physical choice, ~i~ means /use the shared value/. Zero is explicit
in either context. The standard-default palette chooses the collection,
Automatic delegates physical selection, and adapter default delegates one
adjustment: they answer different questions.

Filter amount scales apply to arrows and numeric input in the common editor.
Zero is the neutral cutoff; blank requests adapter default. Existing saved
styles retain their sound and stored low-pass cutoff values keep their original
meaning.

Neutral values are named: gain five /unchanged/, pan five /centre/, and zero
reverb, echo, or chorus /disabled/. Chorus adds bounded doubled-voice modulation
without changing speech duration or marker positions. Omnivox applies it to
buffered audio and reports unsupported routes. Portable levels are translated
into adapter-specific values.

The standard palette includes =telephone=, combining high-pass and low-pass
filtering for a narrow-band sound on buffered Omnivox engines without replacing
the physical voice or changing duration/markers. Preview it in Voice Palettes
or Workbench before assignment. Adapters without post-synthesis filtering keep
the style but cannot apply those filters.

For overall Omnivox pitch contrast (=omnivox-average-pitch-contrast=), open
~C-e H v o~ and select /Omnivox pitch contrast/. Shift-left/right adjusts by =0.1=; ~RET~ enters an exact
value from zero to two. The default =0.5= gives gentler distinctions, =1.0=
restores historical contrast, and zero neutralises average pitch. This scales
all average-pitch levels without changing individual named-voice definitions;
other backends are unaffected.

Changes refresh logical-voice registration for subsequent previews, structured
speech and legacy inline voices. Compare familiar content, then restore the
previous value if needed. The menu's ~w~ saves both contrast and comparison
labels through Customize; it does not save a voice or palette.

*** Choose And Tune Fallback Voices
:PROPERTIES:
:TEXINFO_NODE_NAME: Voice Fallbacks
:ALT_TITLE: Choose And Tune Fallback Voices
:DESCRIPTION: Order physical choices and customize their individual adjustments.
:END:

Shared settings provide a base for the whole voice. Physical choices are tried
in displayed order, subject to availability, engine policy, and synthesis
failure. An empty explicit list means /Automatic/, using shared engine policy.
Availability predicts a possibility; the last sample's result identifies what
played.

Palette inheritance supplies the whole entry. Within that entry, each
physical choice can either inherit a shared adjustment or supply its own.
For example, suppose shared pitch is six, this physical choice specifies four,
and a matching contextual rule requests seven. The resulting request is seven
because the rule overrides the choice. Without that rule it is four. Selecting
/Use shared value/ for the choice then makes it six.

Expand /Fallbacks/ to distinguish rows using shared settings from customised
ones. A row's menu auditions or compares it; comparison follows the same row
after reordering, even where two rows use the same physical voice. A newly
added row has no original yet: audition it or compare the whole voice. Replacing
a customised physical choice asks whether to keep tuning or return to shared.

/Customize this voice/ opens individual tuning. Each field distinguishes shared,
custom, and explicit adapter default. ~RET~ offers all three, left/right sets
numbers, ~d~ requests adapter default, and ~i~ inherits. Zero remains explicit.
Later shared changes affect inherited fields only. /More adjustments and effects/
reveals additional controls. Automatic samples name the value/state and audition
that row; /Play whole fallback chain/ tests normal selection. /Return to shared
settings/ leaves individual tuning within the same draft and Save operation.
Removing a row disables its controls until undo or return to shared settings.

With per-choice support, complete previews retain the chain and each row's
tuning. /Last sample playback started on …/ identifies the engine/voice whose
audio started. Accepted audio or spoken /Original/ and /Edited/ labels do not
prove a start. Stop, text changes, draft changes, or context changes retire
pending previews; retained evidence is labelled /Earlier preview/. Saving and
application status are separate from playback evidence.

/Details and last playback evidence/ explains shared, row, and contextual
contributions to the confirmed sample. The context view offers /Where the last
sample's settings came from/. These explanations use captured settings despite
later edits, identify original versus edited, and distinguish inherited values,
defaults, zero, and unsupported requests. They describe requested settings,
not measured native parameters or sound.

Older servers provide shared-only previews. Customised complete previews need
per-choice support; individual auditions are available only if tuning can be
represented faithfully, including defaults. Saving remains possible when a
preview is unsupported.

**** Work with engine-specific parameters
:PROPERTIES:
:TEXINFO_NODE: no
:END:

/Engine-specific settings/ opens parameters described by the selected worker
within the same voice draft. A worker that can describe but not apply them
shows them read-only. Engine-wide and startup controls also remain read-only
here, with scope identified by Help.

Actions precede expandable parameter groups with value, source, and range.
~RET~ offers /Set value/, /Follow common settings/, /Engine voice default/,
and /Parameter help/. Units and limits belong to the engine. Help explains
default source, relevant common controls, and reported side effects. ~?~ opens
and reads parameter Help; ~q~ returns to the row. Left/right steps a set numeric
value within limits. For inherited or unknown defaults, first choose a value
with ~RET~; the editor does not guess current native state.

~i~ removes an override, ~d~ requests engine voice default, and /Reset
engine-specific settings/ removes native overrides without altering common
adjustments or other choices. ~u~ undoes these edits.

Automatic samples name the parameter/value and share the common editor's
/Automatic sample after adjustment/ preference. Opening, searching, refreshing,
and Help do not audition. ~P~ previews, ~B~ compares, and the normal Save keeps
the draft. ~q~ returns to common settings. /Search controls/ searches names,
identifiers, and Help across folded groups; empty input clears the filter.
/Adjusted controls only/ shows overrides. ~g~ refreshes without restarting;
a busy engine is retried quietly for up to five seconds. Leaving cancels retry.
If still busy, finish speech and retry ~g~. Unrecognised saved fields stay
visible for explicit removal.

/Explain planned settings/ describes the captured draft without speech playback.
Where supported, last-playback details also explain applied sample settings.
Planned, applied, and engine-read-back values are labelled separately. An expired
sample plan cannot be reconstructed by these queries.

*** Inspect Or Adjust A Voice In Context
:PROPERTIES:
:TEXINFO_NODE_NAME: Voices In Context
:ALT_TITLE: Inspect Or Adjust A Voice In Context
:DESCRIPTION: Compare a voice with contextual rules and edit a rule rather than its base entry.
:END:

In the voice editor, choose /Effective sound / Where settings came from/.
It uses the attached source item captured through the entry route or voice list.
If none is attached, choose an ordinary buffer at its current point. The item
must provide inspectable facts or valid retained feedback. /Choose another
source context/ deliberately selects a replacement.

This simulates captured facts and rules, showing the selected voice, matching
rules, requested fields, and their sources. One rule can set pitch and another
richness. A stronger pitch rule can mask a base edit; a rule choosing a different
named voice can make the open entry irrelevant. Competing relative rates also
replace, not add.

~P~ previews the edited voice in context and ~B~ compares original/edited with
the same facts, rules, and text. These voice-only previews omit cues and spatial
placement. Family remains a portable fallback outside full preview. Per-choice
support applies the actual fallback's tuning before context, and an explicit
context value overrides even when numerically equal to shared tuning. Requested
values remain distinct from confirmed starts, accepted audio, and unsupported
adjustments. Changed/deleted sources are rejected. After saving a rule, refresh
facts and rules from the source to capture its contribution. ~q~ returns to
the base editor.

/Adjust for this context/ presents matching criteria and personal, session, or
buffer lifetime. Choose one adjustment and value to prepare the ordinary rule
editor. A richness-only change does not select a different voice. Review criteria
with ~RET~, use ~V~ for another voice field, and save the chosen scope with
~w~. The palette is unchanged. Finish existing rule-editor work before preparing
another contextual rule.

/Inherit/ removes a field so weaker contributions can supply it; removing the
last voice field removes the patch. Existing explicit defaults are shown and
preserved when another field is edited. Zero is not inheritance. Some older
default forms cannot reset underlying tuning on every backend; inspect preview
and explanation. Context changes are saved as rules, not as a palette entry
containing the combined result. The
[[info:emacsvox#Integration Maintenance][Developer Guide]] describes representation and compatibility.

** Name Occasional Emoji In Speech
:PROPERTIES:
:TEXINFO_NODE_NAME: Emoji Speech Names
:ALT_TITLE: Name Occasional Emoji In Speech
:DESCRIPTION: Keep occasional decoration from forcing a different speech engine.
:END:

An emoji can require fallback from a voice such as Eloquence. Naming transforms
speech text before engine selection: =Forecast 🔮= becomes =Forecast crystal
ball=, while source text stays intact. This can keep the preferred voice when
the remaining text is compatible; normal repertoire checks still decide.

Naming is enabled by default. Use ~M-x customize-group RET emacsvox-emoji RET~.
Disable =emacsvox-emoji-naming-enabled= globally or only in a source buffer:

#+begin_src emacs-lisp
(setq-local emacsvox-emoji-naming-enabled nil)
#+end_src

For Org buffers in your configuration:

#+begin_src emacs-lisp
(add-hook 'org-mode-hook
          (lambda () (setq-local emacsvox-emoji-naming-enabled nil)))
#+end_src

All four options support buffer-local values, which override global defaults.
Aural previews use the remembered source policy, and contextual previews its
captured policy. Changes during playback do not change an already submitted
sample.

=emacsvox-emoji-approved-sequences= defaults to =t= for every exact name in
Emacs's emoji table, including seedling =🌱=, flags, keycaps, and joined emoji.
You need not approve each separately; an explicit list restricts eligible
complete sequences. Unknown joined sequences remain intact even if a component
is named.

Arrows and harpoons also receive names in all directions, including diagonal,
double, and curved forms. =← ↑ → ↓= becomes /left arrow up arrow right arrow
down arrow/. Symbols such as =⇒= and =⟶= outside the emoji table use Unicode
names. Text/emoji selectors are supported; unknown joined or accented sequences
remain unchanged. Box-drawing characters use Unicode names too: =│= becomes
/box drawings light vertical/. Light, heavy, double, rounded, dashed, and
junction forms follow the same naming settings and limits; custom names can
shorten frequent ones. Foreign-language letters and unrelated symbols retain
normal fallback, and exact character inspection is unchanged.

=emacsvox-emoji-maximum-count= defaults to 64 occurrences, counting repetition.
=🤔Dinner? 🍕🍕🍕= becomes /thinking face Dinner? pizza pizza pizza/ without
fallback caused by those four emoji. Above the limit, naming is skipped for
the whole item. One captured presentation can contain several voice runs;
a standalone preview is one item. Transport chunk sizes do not change this
limit. Sequences crossing style or positioned-cue boundaries remain unchanged.

Names come from Emacs's bundled emoji/Unicode data and may vary with its version.
Arrows prefer emoji names where available; the four plain arrows share their
emoji equivalents' names. Missing data leaves the sequence to normal fallback;
nothing is downloaded. Names are English and apply even to engines capable of
speaking the original.

Explicit pronunciation entries take precedence. For eligible sequences,
=emacsvox-emoji-custom-names= overrides a bundled name:

#+begin_src emacs-lisp
(setq-local emacsvox-emoji-custom-names '(("🔮" . "prediction")))
#+end_src

Custom names must contain 1–80 characters with no control characters. Empty
names are invalid; use explicit pronunciation to omit content. Restriction and
custom-name lists allow at most 64 entries, with sequences up to 32 characters;
full-table mode has no entry limit. The occurrence limit accepts 0–64.
Invalid settings skip automatic naming with an explanation rather than stop
speech.

Feedback Details (~C-e E~) shows original sequences and names or reasons for
skipping. Voice-editor playback details report sample substitutions. These are
prepared-text evidence, not confirmation of what you heard. /Play original/
retains captured speech text after settings change. Rule proposals change
presentation while retaining that text; capture new source feedback to try
another naming policy.

*** Distinguish installation, enablement, and active speech
:PROPERTIES:
:TEXINFO_NODE: no
:END:

A voice can be installed without being ready to speak. /Installed/ means
it belongs to the library or is supplied by an engine. /Enabled/ records
whether it should be available after the next Apply. /Active/ identifies
eligibility on the main stream, notification stream or both; it does not say
that a model is currently resident in memory.

Library information arrives asynchronously. When worker evidence is missing
or inconsistent, the view reports /Unknown/ rather than guessing whether the
voice is active.

~+~ enables/disables a managed voice, ~a~ reviews Apply, and ~d~ opens downloads.
Downloads start disabled; enable and Apply before auditioning. Engine-managed
voices retain their own selection mechanism. Other adapters retain their
physical-inventory view.

To remove a downloaded Piper, Flite, or MBROLA package, disable its voices,
Apply, then press ~C-c u~ on one voice. Review all speakers sharing it, size,
known palette references, and retained-file reasons. Confirmation removes only
reviewed managed files. Built-in voices, imports, and runtimes remain, as do
saved palette choices for a later redownload. The backend guide describes
supported managed-engine download and removal boundaries in more detail.

Another session may still need the package; files remain until retirement is
confirmed, and older session records may need inspection. Results distinguish
removed bytes, remaining files, and unconfirmed amounts. ~C-c U~ or
=omnivox-library-resume-uninstall= reviews interrupted cleanup on hosts supporting
uninstallation.

Check an engine's /Availability/ before changing its routing policy. A
missing runtime remains listed as unavailable, with /Last failure/ explaining
the problem. /Routing policy: allowed/ permits selection; it does not install
the runtime. An engine being disabled, unhealthy or temporarily failed are
also distinct conditions.

*** Experiment With An Installed Voice
:PROPERTIES:
:TEXINFO_NODE_NAME: Physical Voice Experiments
:ALT_TITLE: Experiment With An Installed Voice
:DESCRIPTION: Try physical voices without saving, then keep a useful experiment.

~t~ on a physical voice opens an experiment with that exact engine/voice,
adapter-default characteristics, current base rate, and neutral audio effects.
Opening, adjusting, and comparing save nothing. Controls match
[[info:emacsvox#Editing Named Voices][Edit a Named Voice]], but ~w~ must first choose a palette destination.

To compare pitch:

1. Open ~C-e H v b~, select an available engine, and press ~v~. Select a
   physical voice and press ~P~; ~B~ can compare with another available voice
   using the same sentence.
2. Press ~t~, set /Average Pitch/ to =3=, listen, then set =7= and listen
   again. An unsupported pitch control remains identified.
3. ~B~ compares the captured starting voice with the edited one, not the
   immediately previous change. ~u~ undoes; ~d~ restores adapter default.
4. Finish with ~q~ and discard, or keep the experiment using the next walkthrough.

~w~ chooses a destination palette and entry. The default keeps /Physical voice
and adjustments — this choice/. Alternatives keep only the physical voice,
only one row's adjustments, or shared settings for inheriting choices. Physical
voices can replace a row, become preferred, or append as fallback. A row-level
keep replaces that row's tuning with the experiment's values and defaults,
preventing unrelated destination shared tuning from changing the base sound.
Use ~i~ afterward for fields intended to inherit.

Other rows/shared settings survive a row-level keep. Replacing only the
physical voice asks whether to keep/reset its tuning. Shared adjustment keeps
affect inherited fields; custom rows override them. An existing destination
draft can accept the changes or resume untouched, retaining other work and
pending save recovery. The destination preview uses the proposed combination,
which can differ because of scope/fallback order. Choosing it has not saved.

*** Walkthrough: Keep An Installed Voice Experiment

existing personal destination. Note the active palette first.

1. In the voice browser, open ~t~, adjust a field, and preview with ~P~/~B~.
   Press ~w~ to keep it.
2. Select the personal destination and named voice =bolden=. Choose /Physical
   voice and adjustments — this choice/, then /Add as preferred/. This places
   the experiment first while retaining alternatives.
3. The common editor opens an unsaved proposal. Expand /Fallbacks/: the new
   first choice is customised, preceding previous explicit choices. ~P~ plays
   the whole proposed voice; inspect its actual reported engine/voice because
   an unavailable preference may fall back.
4. ~w~ saves and applies. Wait for its result and follow
   [[info:emacsvox#Recovering Aural Changes][Recovering Unfinished Changes]] after partial saving or failed application.
   Success selects the destination for this session. Use ~U~ in Voice
   Palettes only to choose it for startup too.
5. Before saving, undo or discard to reverse. After saving, reopen the voice,
   expand fallbacks, choose /Remove/ in the added row's ~RET~ action menu,

   original palette to restore session selection too.

Change one field, audition that row, then test /Play whole fallback chain/.
The custom field overrides shared tuning only for that choice. ~i~ restores
inheritance; reordering carries adjustments with the row.

Rules request cues by semantic name. Sound packs map names to audio assets
and can inherit missing cues. This lets you change the sound of a family of
cues without rewriting rules. For one event, use its feedback rule instead.

To enable or disable earcons in the captured buffer, use ~C-e H r l e~.
In that submenu, ~E~ changes the global default for buffers without a local
override; ~i~ removes the source buffer's override so it follows that default.
Speech remains available when earcons are off, but menu cues also disappear
where the off setting applies. These switches last for the session or buffer
and have no Customize Save action. Toggle again or restore inheritance to
reverse an experiment.

~C-e H o p~ opens /Sound Packs/. Its ~q~ returns to /Sounds and output/ with
the same settings scope, and another ~q~ returns to the main menu. Directly
opened browsers keep their usual returns.

#+attr_texinfo: :indic kbd :compact t
- P :: Audition a representative cue without activating the pack.
- RET :: Browse individual cues and their source or fallback.
- P in the cue browser :: Audition the selected concrete cue; RET shows details.
- v :: Validate resources and report missing/invalid entries.
- a :: Activate the selected pack.

Spatial requests describe placement portably, not a particular device.
~C-e H D s~ reports capabilities and fallbacks; ~C-e H o n~ controls output,
separation, direction, speech, and cues. Unsupported or mono output retains
audible content at the centre. Named tones are separate compact resources,
independent of sampled files and the active pack.

*** Tune line and boundary cues from the menu
:PROPERTIES:
:TEXINFO_NODE: no
:END:

~C-e H o c~ opens /Line and boundary cues/. Blank, whitespace-only, separator,
decorated, and unspeakable-line tones have pitch and integer-duration controls.
Shift-left/right adjusts by 25 Hz or 5 milliseconds; ~RET~ enters exactly.
Boundary/warning and large movement instead choose replacement earcons.
Changing those named earcons affects every use, including warnings elsewhere.

Each cue retains a global preview draft. ~SPC~ auditions it, ~s~ stops,
~n~ silences in the draft, ~r~ restores bundled values, and ~D~ discards edits.
~S~ saves through personal rules while preserving unrelated rules; stronger
presentation rules may override it. ~q~ retains the draft. This changes cue
output, not classification of separators or decorated lines.

*** Walkthrough: Try A Sound Pack
:PROPERTIES:
:TEXINFO_NODE_NAME: Sound Pack Walkthrough
:ALT_TITLE: Walkthrough: Try A Sound Pack
:DESCRIPTION: Preview, activate, retain, and restore a sound pack.
:END:

1. Open ~C-e H o p~ and note the active pack. Select another of kind /sound/
   and press ~P~ to preview without activating.
2. Enter with ~RET~ and inspect /Availability/ and /Provider/. Cues may come
   from the pack, parent, or registered fallback. ~P~ previews and ~S~ stops.
3. Press ~s~ to return to the manager, then ~v~ to validate. Resolve missing

*** Walkthrough: Silence One Cue
:PROPERTIES:
:TEXINFO_NODE_NAME: Changing One Sound
:ALT_TITLE: Walkthrough: Silence One Cue
:DESCRIPTION: Suppress a cue while retaining speech and restore it afterward.
:END:

1. Repeat the action producing the cue, then open ~C-e H f h~. Select the
   record and ~RET~ to explain it. Identify cue name and before/after phase.
2. Return to the list and press ~C~ for /Change this feedback/. Select the

3. Compare ~O~/~P~: speech and other components should remain. Inspect criteria

4. Apply with ~a~ and repeat the source action. Matching feedback should omit
   that cue; other identities or unmatched contexts remain unchanged.
5. Open ~C-e H r o~, find the session rule, and disable with ~t~ or delete
   with ~d~. It also expires when Emacs exits.

To add a missing cue, choose /Add a sound/, /Before content/ or /After content/,
then a registered cue. Preview and review criteria/lifetime. Adding and later
removing use the same rule workflow.

*** Change A Blank-Line Tone
:PROPERTIES:
:TEXINFO_NODE_NAME: Changing Tones
:ALT_TITLE: Change A Blank-Line Tone
:DESCRIPTION: Change a recorded tone and distinguish it from a sampled cue.
:END:

This changes a tone actually present in recorded feedback, not every visually
blank line regardless of its presentation.

1. Navigate onto a blank line and open ~C-e H f h~. Select its record, press
   ~C~, and choose a part if necessary.
2. Press ~c~, /Change a tone/, select the tone, and choose /Pitch and duration/.
   Try =500= Hertz and =80= milliseconds. If it originally lay between other
   components, choose /Before the other feedback/ when asked about placement.
   Review that movement in the summary as well as pitch/duration.
3. Compare ~O~/~P~. Other content should remain. A named tone can be selected
   instead of numeric values.
4. Review criteria with ~m~, choose session lifetime with ~l~, then ~a~.
   Visit another matching blank line to hear the live result.
5. Disable/delete the session rule through ~C-e H r o~ to restore the earlier
   behaviour. It also expires when Emacs exits.

If the record contains a sampled cue, /Change a tone/ is unavailable. Explain
it, then suppress that cue and add a tone with separate rules if appropriate;
remove both to restore. If no record exists, check the history limit and repeat
the action. The interface cannot infer a missing component from appearance.

*** Adjust Spatial Presentation
:PROPERTIES:
:TEXINFO_NODE_NAME: Spatial Presentation Controls
:ALT_TITLE: Adjust Spatial Presentation
:DESCRIPTION: Check stereo support, adjust placement, and restore centered output.
:END:

Open ~C-e H D s~ to inspect reported speech/cue capabilities, then return to
the menu. ~C-e H o n~ opens /Notifications and spatial output/. Enable
presentation, speech, and cues independently. Output follows capabilities or
can be declared mono. Separation ranges from zero (centred) to one (full);
direction can be normal, reversed, or centred for some/all requests.

These spatial controls apply immediately and are global. Shift-left/right
adjusts selected separation by 0.1; ~RET~ enters an exact value. ~SPC~ requests

separately from output-volume saving.

For a gentler layout, note the current settings, select maximum separation,
and enter =0.3=. Repeat feedback that requests spatial placement. Stereo

a placement request cannot demonstrate separation.

Restore the original values afterward. Save deliberately with ~S~ or capture
spatial choices in a Presentation Profile. A voice's Pan effect and notification-device routing are separate from presentation placement.

** Speech Output And Notifications
:PROPERTIES:
:TEXINFO_NODE_NAME: Aural Speech Output
:ALT_TITLE: Speech Output And Notifications
:DESCRIPTION: Set speech rate and understand foreground and background output.
:END:

These settings control reading detail and delivery. They do not replace the
rules choosing content or the palette shaping its voice. Start with rate and

*** Set the reading scope, rate, and punctuation
:PROPERTIES:
:TEXINFO_NODE_NAME: Reading Scope And Punctuation
:DESCRIPTION: Set rate or punctuation for the current buffer and understand saving.
:END:

~C-e H s~ opens Speech settings for the captured buffer. ~g~ switches to global
defaults; ~C-u C-e H~ starts there. Indentation shares this scope with its
parents, including changes made inside its own menu. Opening/closing alone
saves nothing.

Select /Rate/ and adjust with Shift-left/right by the configured step, or use
~RET~/~r~ for an exact value. Speech must be running; Omnivox uses 0–100.
Global rate changes also affect the current buffer. A named voice's relative rate
modifies this base as described in [[info:emacsvox#Voice Adjustments][Voice Adjustments]].

In Speech settings, press ~p~ for the punctuation menu. Choose ~n~ for
none, ~s~ for some or ~a~ for all punctuation. That menu's ~p~ offers the
built-in levels and available named profiles. In buffer scope, ~r~ restores
automatic mode policy. Press ~q~ to return to Speech settings.

The punctuation menu's ~e~ opens the Omnivox pronunciation editor. In that
editor, lowercase ~s~ saves overrides on the speech host and lowercase ~r~
restarts speech after confirmation. Its ~q~ returns to the same punctuation
menu item, retaining the draft and selected character for reopening.

Capital ~S~ in the punctuation menu has a different purpose: it saves the
selected level or profile through Customize. It does not save the pronunciation
editor's host-side draft.

~S~ in Speech settings saves displayed rate and punctuation as startup defaults.
Rate uses the backend's startup option. Saving from buffer scope promotes those
displayed choices to defaults. Mode punctuation policy and explicit buffer
settings still override the saved punctuation default.

**** Use Emacs word and phrase dictionaries
:PROPERTIES:
:TEXINFO_NODE: no
:END:

For word or phrase substitutions managed by Emacs, open ~C-e H s p d~.
This menu is separate from the Omnivox pronunciation editor on ~e~. Its
dictionaries are stored in an Emacs dictionary file, not Customize or the
speech host, and changes need no speech restart. Opening the menu writes
nothing and leaves the source's pronunciation table unchanged.

Press ~d~ to define an entry at the captured source item. Choose buffer, file,
directory or major-mode scope, then enter the term and spoken replacement.
The existing prompt can load saved dictionaries first. Buffer entries last
only in that buffer's current pronunciation table. Other scopes update the
in-memory dictionary collection and need a separate ~w~ Save to persist.

Use ~e~ to choose an existing dictionary and open its widget editor. ~TAB~
moves between fields and buttons; ~RET~ activates them. Field edits update
the in-memory collection. Its Save button writes dictionaries to a chosen
file. Return with ~C-c C-c~ from anywhere, or ~q~ outside editable fields;
inside a field, ~q~ inserts text. Returning retains edits without saving or
rolling them back, and reopening resumes the same editor buffer.

Back in the menu, ~r~ rebuilds and enables the captured source's table from
its dictionaries. This replaces temporary buffer-only entries. ~t~ turns
substitution off or composes the table again when turning it on; turning off
also loses buffer-only entries. Changes to file, directory and mode entries
remain in the collection. To reverse an entry change, edit it back and refresh
the source; save again if you changed the saved dictionary.

Finish and close existing widget editors before loading replacements: their
retained fields are not reloaded. The menu's ~l~ loads a dictionary file into
the collection; refresh the source afterward to use those entries. ~w~ saves file, directory and mode dictionaries,
excluding buffer-only entries. Both actions prompt for a file; Load offers
=emacsvox-pronounce-dictionaries-file=, while Save offers its basename in the
Emacsvox user directory. Saving elsewhere does not change the configured
startup file. Use ~?~ followed by an item's key
for its scope and effects before applying it.

**** Set capitalisation feedback and its beeps

**** Choose spelling feedback
:PROPERTIES:
:TEXINFO_NODE: no

*** Understand the main and notification streams
:PROPERTIES:
:TEXINFO_NODE_NAME: Notification Routing
:DESCRIPTION: Choose where notifications play and distinguish selection from restart.
:END:

#+cindex: speech streams
#+cindex: notification stream
#+vindex: tts-notification-device

The /main stream/ presents current interaction such as movement, buffer entry,
and message opening. Navigation interrupts obsolete main speech. The
/notification stream/ presents asynchronous events without stopping main speech;
normal navigation does not stop a separate notification stream. Both can be
heard concurrently, with each notification's cue and speech delivered together.
Integrations may deliberately route particular asynchronous actions differently:
Notmuch's explicit refresh, for example, uses interruptible main speech.

Open ~C-e H o n~ for routing. ~r~ chooses automatic, left, right, both, main
output, or another device for the next restart. Selecting does not restart.
~N~ previews active output, which may still use the old route; ~R~ restarts
after confirmation. ~h~ inspects a notification-history snapshot, returning
with ~q~. ~S~ saves routing and spatial defaults without a restart.

With Omnivox, Automatic normally uses an independent notification process;
left/right/both choose its route. /Use main output (notifications remain
audible)/ uses the main process instead, where navigation can interrupt it.
It is not a mute option. Other backends use their configured device or fall
back to main speech. In Lisp, =default= or an empty string means main output;
use descriptive labels for ordinary configuration.

After changing the route, ~C-e d C-n~ also initialises the arrangement.
Use notification history to read an announcement you missed. Ordinary
obsolete-main-speech cancellation is local to main; explicit =tts-stop= stops
both streams.

*** Adjust output volumes
:PROPERTIES:
:TEXINFO_NODE_NAME: Output Volumes
:DESCRIPTION: Adjust speech and cue levels without confusing volume with routing.
:END:

~C-e H o~ provides five global Omnivox volumes: main tones and earcons, and
notification speech, tones, and earcons. Each is an integer percentage 0–100;
100 is normal, zero silences that component. For example, notification speech
35 and earcons 70 emphasise brief cues over messages.

Shift-left/right adjusts the selected volume by five; ~RET~ enters exactly.
Changes apply to subsequent audio without restarting; already prepared audio
keeps its old level. ~S~ saves these five volumes, not routing or spatial
settings.
Replacement and reconnected Omnivox processes receive current levels.

Independent notification levels need the separate process selected by Automatic,
Left, Right, or Both channels. Main-output routing/fallback shares main-process
levels. Earcon volume applies to Omnivox-played sounds, not external players or
other speech backends. Zero volume does not disable notification recording.

*** Adjust an integration's speech settings
:PROPERTIES:
:TEXINFO_NODE_NAME: Integration Speech Settings
:DESCRIPTION: Find focused controls and their integration-specific saving boundaries.

<<Integration speech settings>>

~C-e S~ opens focused settings directly where available. Alternatively use
~C-e H j~ or ~C-e H . j~. In that integration menu, ~s~ invokes a local Agent

**** Shell/comint and EAT
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Shell/comint's focused menu toggles automatic speech with ~s~ and background
monitoring with ~b~. Background reading needs autospeak enabled. Both values
belong to the captured buffer for its lifetime; there is no Save action. Arrows
announce values and ~RET~ activates. ~q~ returns to the entry, or closes a
direct focused menu. Search at ~C-e H /~ finds =comint= and =monitoring=.
Choosing Shell/comint from another buffer explains the required context and
leaves its controls unavailable.

EAT's ~s~ toggles foreground speech, ~b~ content-free background cues/counts,
~p~ prompt feedback, and ~d~ automatic detail. Background monitoring is
independent of foreground autospeak and never reads background content.
Changes are local to the terminal, including from frozen review. ~w~ saves all
four displayed defaults; terminals with overrides keep them. ~A~ opens advanced
Customize and ~q~ returns. All controls are searchable. Choice lists start on
the current value; arrows browse, ~RET~ applies, and ~q~ cancels. See

**** Agent Shell, Org, and EWW
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Agent Shell's menu covers temporary session speech, global feedback defaults,
and reading limits. ~w~ saves displayed globals, excluding the session override.
See [[info:emacsvox#Agent Shell][Agent Shell]].

Org's ~c~ chooses cell, header, or combined table-editing feedback and ~w~ saves
that global default. Column headers come from the first row, row headers from
the first column, and local overrides take precedence. ~t~ opens Org table

EWW's ~s~ controls section-navigation autospeak and ~i~ suppresses images on
subsequent rendering. It also updates the shared SHR image default while
preserving local overrides; it does not reload the page. ~w~ saves the two

**** Notmuch and shared choice-list navigation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Notmuch has the same focused menu in Hello, Search, Show, and Tree. ~c~ chooses
adaptive, count-only, cue-only, or silent successful completion; failures remain
audible. ~f~/~b~ set field character/UTF-8 byte limits and ~t~/~B~ total limits.
Shift-left/right steps by 100, ~RET~ accepts a positive integer or =none= for

Org and Notmuch choice lists start on the current global value. Arrows browse
without applying, ~RET~ applies/returns, and ~q~ cancels. ~?~ plus a choice key
explains effect/scope; ~q~ returns to that browsed choice.

inspection. Integrations without focused entries remain accessible through

** Save, Switch, And Share Your Setup
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Profiles
:ALT_TITLE: Save, switch and share your setup
:DESCRIPTION: Save selected settings and distinguish profiles from resource backups.
:END:

#+cindex: presentation profiles

A Presentation Profile records enabled options and their order, sound pack,
voice palette, and portable spatial settings. It switches a coordinated setup
for focused work, leisure reading, or different audio environments. It is not
an Emacs startup configuration profile or a backup of every setting.

~C-e H p p~ opens profiles. The parent ~C-e H p~ also links palettes and
unfinished drafts; each editor retains its own Save/Apply actions. Palette
~w~ exports portable voices, ~W~ backs up full local choices, and ~i~ imports
an independent palette without activation. See
[[info:emacsvox#Sharing Voice Palettes][Export, Back Up, and Import Palettes]].

1. Configure the live options, sound pack, voice palette, and spatial choices.
2. Open ~C-e H p p~ and inspect the fields to be captured.
3. ~N~ saves the live selection as a new named profile.
4. Later, ~a~ applies the selected profile's saved values.
5. To update it from deliberately changed live settings, use ~w~. To discard
   live differences instead, apply with ~a~ and review confirmation.

Only one profile is selected at a time. /Active/ means its saved values match
the live configuration. /Diverged/ means it is still selected, but one or more
live values now differ from its saved values. That status is not a warning
about an unsaved editor draft.

Applying a profile also saves its selection for future sessions. This differs
from activating an individual palette, which selects it only for this session.

Profiles reference palettes and sound packs by name, not private copies.
Editing a shared palette affects every profile using it. Profiles exclude
engine policy, speech rate, notification output, rules themselves, buffer-local
Voice Lock, and current-buffer rules. Those remain in their owning settings
or rule stores.

*** Walkthrough: Switch Reading And Working Setups
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Profile Walkthrough
:ALT_TITLE: Walkthrough: Switch Reading And Working Setups
:DESCRIPTION: Save two selections, switch between them, and understand shared resources.
:END:

Use unused names and note the selected profile first.

1. Open ~C-e H p p~. For a restore point, ~N~ saves =before-demo= with a short
   purpose and selects it. This captures resource/option choices, not rule,
   resource-definition, or engine backups.
2. Use ~C-e H v p~ and ~C-e H o p~ to activate your reading palette and sound
   pack. Choose Presentation Options at ~C-e H r f~ and spatial settings at
   ~C-e H o n~. Return through each view's own navigation before opening the
   next. In profiles, save =reading-setup-demo= with ~N~.
3. Choose a different palette or pack and save =working-setup-demo=. ~RET~
   describes each profile's saved fields.
4. Apply the reading profile with ~a~ and repeat familiar feedback. Inspect
   active resources in their managers, then apply the working profile to
   compare.
5. Change a live option without updating the profile. /Diverged/ indicates the
   difference. ~a~ restores saved values and ~w~ replaces them with current
   choices; read confirmation before discarding either intention.
6. Finish on the profile wanted at startup, because applying saves its
   selection too. Restore the original or =before-demo= when finished.
   Delete unwanted demo profiles with ~d~ only after selecting the retained one.

If both profiles use =reading-demo=, edits to that palette affect both. For
independent voices, Copy Palette and select different resources. A profile's
Copy action copies selections only. To change startup palette while preserving
other profile fields, use ~U~ in Voice Palettes rather than recapturing everything.

*** Choose What Persists
:PROPERTIES:
:TEXINFO_NODE_NAME: Saving And Startup
:ALT_TITLE: Choose what persists
:DESCRIPTION: Distinguish previews, drafts, saved resources, activation, and startup.
:END:

#+cindex: saving aural settings
#+cindex: startup palette

Decide what you want to keep before choosing a Save action. /Scope/ tells
you where a value applies; /persistence/ tells you whether it survives a
restart; /activation/ tells you whether it is in use now. These are separate
questions.

A current-buffer value applies to the captured buffer. A global default is
live, but buffer overrides and mode policy can still take precedence. Changing
it does not automatically save it, and only the command's documented behaviour
tells you whether existing buffers are updated too. Saved startup settings
are retained for later sessions.

**** Try a change or leave it unfinished
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Preview an example to hear a proposal without saving or selecting it. Keep a
retained draft when you intend to resume it during this Emacs session.
[[*Recover Unfinished Changes][Recover unfinished changes]] explains how to return to its editor.
A draft is not a backup: it is lost when Emacs exits, and discarding it does
not undo an earlier completed save.

**** Store a voice without changing today's setup
:PROPERTIES:
:TEXINFO_NODE: no

Use /Save to collection without selecting/ in the voice editor to store a
voice for later use without selecting its destination palette. The detailed
[[voice-saving-procedure][voice-saving procedure]] explains the editor's result and partial-save states.
This is appropriate for an alternative you want to keep, not yet adopt.

**** Use a saved voice or setup now
:PROPERTIES:
:TEXINFO_NODE: no
:END:

/Save and apply/ stores a voice and selects its palette for this session.
/Activate/ in the palette or sound-pack manager instead selects an existing
resource. After applying, check the result and repeat the original task.
Some host changes need a separate confirmed speech restart, and a successful
save does not establish that both speech workers acknowledged the application.
See [[*An Apply result is unconfirmed][An unconfirmed Apply result]] when a result is incomplete.

**** Start the next session with it
:PROPERTIES:
:TEXINFO_NODE: no
:END:

In Voice Palettes, /Use at Startup/ changes the palette in the saved profile
without applying that profile now. A Presentation Profile stores coordinated
options, palette, sound pack and spatial choices, not copies of their resources.
Applying a profile also saves its selection for future sessions. Use
[[*Save, Switch, And Share Your Setup][Presentation Profiles]] to switch such a group of choices.

For an individual control, use its own documented Save action. Speech settings
saves the displayed rate and punctuation; Sounds and output saves five volumes;
a focused integration menu saves only its documented defaults. Linked editors
retain their own Save/Apply actions. No one menu action saves all Emacsvox
settings.

Personal rules persist. Session rules expire when Emacs exits, and buffer
rules expire with their buffer. Saving a profile cannot make temporary rules
or drafts permanent. If a choice disappeared after restarting, follow
[[*A setting disappeared after restarting][the persistence checks]] before recreating or overwriting it.

**** Share a palette or make a backup
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Choose /Export/ for effective portable entries or /Full backup/ when palette
ancestry and local voice choices matter. Neither includes engines, sound-pack
audio or every Emacsvox setting. Import creates an independent palette; it
is not an overwrite or automatic activation. Follow
[[*Export, Back Up, And Import Palettes][Export, back up and import palettes]] for the exact contents and checks.

*** Export, Back Up, And Import Palettes
:PROPERTIES:
:TEXINFO_NODE_NAME: Sharing Voice Palettes
:ALT_TITLE: Export, Back Up, And Import Palettes
:DESCRIPTION: Share portable voices or retain local choices in a backup.
:END:

~w~ in Voice Palettes exports effective portable entries, asking before omitting
machine-local choices. ~W~ backs up full ancestry and referenced local choices.
~i~ imports either as an independent personal palette under an unused name;
it neither replaces ancestry nor activates the result. Missing installed voices
are reported and retained for replacement. Partial import retains its proposal
for Retry or Discard.

For practice, export =reading-demo= with ~w~, review omitted choices, and import
as =reading-import-demo=. Enter and preview before activating. An unavailable
retained choice is a review request, not proof of audio. Delete the imported
copy when no profile, child, or rule needs it; the original is unchanged.

Use ~W~ when local choice data and ancestry matter. Import still creates a
new independent palette, not an overwrite. Neither export contains engines
or sound-pack audio, and neither is a backup of every Emacsvox setting.

** Troubleshooting And Recovery
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Troubleshooting
:ALT_TITLE: Troubleshooting and recovery
:DESCRIPTION: Trace unexpected output and use safe diagnostics.
:END:

#+cindex: Aural Doctor

Start by describing the symptom and the last action that produced it.
Avoid deleting personal data, resetting all settings or reinstalling as a
first diagnostic step. Those changes can remove both useful configuration
and the evidence needed to explain the problem.

If speech has stopped altogether, start with
[[info:emacsvox#Recovering From No Speech][Recovering from no speech]]. The presentation checks below assume a working
speech route. [[*Backend Diagnostics And Responsibilities][Backend diagnostics]] covers further server investigation.
For the keys in a particular Aural interface, use its ~?~ Help.

For a problem with otherwise working speech, choose the closest symptom:

- [[*A saved voice change is not audible][I saved a voice change but cannot hear it]]. Check selection, the named
  voice, overrides and engine support in that order.
- [[*A setting disappeared after restarting][A setting disappeared after restarting]]. Establish what was saved and
  what was only selected for the previous session.
- [[*Feedback differs between buffers][Only one buffer or application sounds different]]. Inspect its local
  settings and rules before changing global defaults.
- [[*An Apply result is unconfirmed][I cannot tell whether Apply succeeded]]. Separate a completed save from
  worker acknowledgements before retrying.
- [[*Recover Unfinished Changes][I left an editor and need my unfinished work]]. Resume its own draft
  without changing unrelated drafts.

For other unexpected feedback, inspect the current item with ~C-e E~ or
an earlier record through ~C-e H f h~. Use a Presentation Option for unwanted
broad optional behaviour, or inspect a narrow exception in /Your feedback
rules/ at ~C-e H r o~. For a missing or inappropriate cue, validate the sound
pack and inspect overrides. For a saved setup that no longer appears active,
compare its /Active/ or /Diverged/ status. Voice distinctions that disappear
in some buffers can also come from Voice Lock or explicit face presentation.

A missing custom voice name is a configuration error. Ordinary speech keeps
the text by using an unstyled voice and records a diagnostic; it does not
invent the missing palette entry. Explain and Aural Doctor can locate that
unresolved reference.

*** A saved voice change is not audible
:PROPERTIES:
:TEXINFO_NODE_NAME: Saved Voice Change Not Audible
:DESCRIPTION: Trace a saved voice from palette selection to the original spoken item.
:END:

#+cindex: saved but unchanged
#+cindex: wrong voice
#+cindex: voice change, not audible

Use one representative item and repeat the same navigation or reading action
for each comparison. A preview and a different action may use different
context, so changing several things at once makes the result harder to explain.

1. Read the editor's save and application status first. A retained draft has
   not been saved; a partial or unconfirmed application needs
   [[*An Apply result is unconfirmed][its own recovery]], not another speculative voice edit.
2. Open Voice Palettes with ~C-e H v p~ and check which palette is active.
   Saving to the collection does not select its destination. Activate that
   palette only if you intend to use it now; otherwise its unchanged live
   sound is expected. Return through the manager and menu to the source.
3. Explain the item with ~C-e E~. Check that it resolves to the named entry
   you edited. A rule may choose a different entry, or this kind of text may
   have an explicit voice rather than using =default=.
4. Inspect the physical choice and last sample result. An explicit choice
   outranks the shared preferred-engine policy, and that choice's individual
   tuning can mask a shared adjustment. Then check availability, disablement
   and failures rather than repeatedly changing the engine order.
5. In the voice editor, inspect /Effective sound / Where settings came from/.
   A contextual rule may override the edited value. Compare samples and
   reported unsupported fields to distinguish an override from an engine
   that cannot express the adjustment.

After correcting the identified cause, return to the original item and repeat
the same action. Confirm both the explanation and what you hear. If the cause
remains unclear, keep the working settings and [[*Prepare a useful problem report][prepare a problem report]]
instead of removing unrelated rules or voices.

*** A setting disappeared after restarting
:PROPERTIES:
:TEXINFO_NODE_NAME: Settings Lost After Restart
:DESCRIPTION: Check the resource and startup action before recreating a missing choice.
:END:

#+cindex: settings, lost after restart
#+cindex: forgot my settings

First establish whether the change was ever meant to survive restarting.
A retained draft, session rule or buffer rule does not. Activating a palette
for a session is also separate from choosing it at startup.

1. Identify the resource you changed: a named voice, rule, profile, speech
   control or host setting. Reopen its own editor or manager and check its
   saved state. Do not assume it is absent merely because it is not active.
2. For a saved palette, inspect the selected startup profile. Use /Use at
   Startup/ only when you intend to change that profile's palette. Applying
   a Presentation Profile also retains its selection; a profile does not
   contain speech rate, engine policy, notification output or temporary rules.
3. For an individual control, check exactly what that menu's Save records.
   The [[*Review changed settings before editing again][changed-settings snapshot]] can compare values known to Customize, but
   it is not a complete inspection of voice, rule or host-side files.
4. If the saved value exists but is not effective, check a mode policy or
   buffer override before saving again. For host-side settings, use the
   owning editor's application or restart procedure, not a voice-palette Save.

Use [[*Choose What Persists][Choose what persists]] to select the intended action. Check the result in
the current session first. A later restart tests startup selection; finish
or deliberately save needed work beforehand because retained drafts will end.
Do not use a restart as the first way to investigate an unfinished draft.

*** Feedback differs between buffers
:PROPERTIES:
:TEXINFO_NODE_NAME: Feedback Differs Between Buffers
:DESCRIPTION: Compare local settings, integration policy and matched rules safely.
:END:

#+cindex: only one buffer sounds different
#+cindex: too much talking
#+cindex: application feedback, unexpected

Different applications deliberately announce different information. Compare
the same kind of item and the same action before treating that difference as
a fault. An explicit request for detail can also speak more than automatic
feedback without ignoring the saved automatic policy.

If the problem is too much speech, first identify what was added. Automatic
application content belongs to its focused speech settings. Training adds
explanations across buffers; inspect its current state in ~C-e H r~ before
changing it. Extra labels can come from Presentation Options or rules. Speech
that arrives independently may be a notification; use
[[*Understand the main and notification streams][notification routing]] to understand that stream rather than treating it as
part of the line you are reading.

1. In the affected buffer, use ~C-e S~ to inspect its focused settings, or
   general buffer settings when no focused integration menu is available.
   Read the current values before toggling anything.
2. Use ~C-e H d~ to compare captured-buffer values with global defaults and
   saved values known to Customize. Return from the snapshot before choosing
   a different buffer and opening a fresh comparison.
3. Explain the affected item with ~C-e E~. Inspect matching buffer or session
   rules, Presentation Options, Voice Lock and explicit face presentation.
   These contributions need not be the same in another buffer.
4. Change only the setting or rule that explains the difference. Return to
   the original item, repeat the action, and check an unaffected buffer too.
   Restore the earlier value if the change does not address the symptom.

[[*Adjust an integration's speech settings][Integration speech settings]] explains the different saving boundaries.
Use the application's own chapter for automatic-speech limits and privacy;
do not assume the same key or background setting has the same effect in EAT,
Shell/comint, Notmuch and Agent Shell.

*** Inspect the system with Aural Doctor
:PROPERTIES:
:TEXINFO_NODE_NAME: Aural Doctor Inspection
:DESCRIPTION: Read configuration and backend evidence without automatic repairs.
:END:

Open Aural Doctor with ~C-e H D d~. It checks live bindings, loaded source
and byte-code, the compatibility baseline, options, profiles, personal data,
resources, spatial fallback and backend. Opening the report neither starts
speech nor changes settings. A row that offers a reviewed safe repair can be
acted on explicitly with ~r~; read the proposed effect first.

Worker rows report current capabilities and the last inventory. Agreement
between configuration identities means the startup identities were acknowledged;
it does not prove that saved files are in use. Missing or retired connections
leave the evidence unknown. A running process or available engine does not
establish audible playback.

In the diagnostics menu, ~s~ reports spatial capabilities and policy.
Lowercase ~m~ and ~n~ open retained local main and notification output,
reporting an absent buffer where appropriate. Press ~q~ in those views to
return to the selected menu item. For reporting and logging precautions,
see [[*Prepare a useful problem report][Prepare a useful problem report]].

*** Review changed settings before editing again
:PROPERTIES:
:TEXINFO_NODE_NAME: Inspecting Changed Settings
:DESCRIPTION: Compare buffer, global and saved values without changing them.
:END:

Press ~C-e H d~ to inspect changes without making another one. The snapshot
separates captured-buffer values, global defaults and saved startup values
known to Customize. It includes loaded Emacsvox, TTS and Omnivox options that
are saved, buffer-local or nonstandard. Saved expressions appear as recorded.
Press ~RET~ to read a complete row with its scope, ~g~ to refresh the
snapshot, and ~q~ to return.

Editor and cue drafts appear separately. The snapshot does not reread files,
query the speech host, establish that saved data is active or include options
from unloaded integrations. Voice, rule and host-pronunciation stores retain
their own saving rules. Return to the owning editor or menu to change, save,
apply or restart anything.

*** Prepare a useful problem report
:PROPERTIES:
:TEXINFO_NODE_NAME: Reporting Speech Problems
:DESCRIPTION: Collect a minimal reproduction and review private data before sharing.
:END:

#+cindex: problem report
#+cindex: diagnostic logging, privacy
#+cindex: speech logs, sensitive text

Record the application and buffer type, the exact keys or action, what you
expected, what you heard and whether the problem repeats. Note the platform,
Emacs and Emacsvox versions and speech backend. Distinguish a reported
success or timeout from an audible result; neither is a substitute for the
other. Prefer a short, non-confidential example that reproduces the problem.

In Aural Doctor, ~y~ copies the report. It does not copy spoken text or log
contents, but it can contain personal paths and configuration. Review that
copy before sharing it. The log row identifies paths without opening files.

Enable detailed logging only for a reproduction whose spoken content you are
prepared to handle as sensitive data. In the diagnostics menu, lowercase ~l~
toggles logging for this session, including complete spoken text. Note its
previous state and restore that state after the reproduction. Capital ~A~
opens log-file, size, retention and buffer-visibility options in Customize.
Apply and Save there are explicit; buffer-naming changes take effect after
speech restarts.

Review logs separately before sharing excerpts. Remove credentials, message
content, personal paths and unrelated text; do not assume a diagnostic file
contains only technical metadata. State which checks you tried and their
results so another person can continue the investigation without repeating
unsafe or inconclusive steps.

*** Recover Unfinished Changes
:PROPERTIES:
:TEXINFO_NODE_NAME: Recovering Aural Changes
:ALT_TITLE: Recover unfinished changes
:DESCRIPTION: Resume drafts and distinguish saved settings from confirmed application.
:END:

Press ~C-e H p d~ to resume a retained draft directly in its owning editor.
When several drafts exist, choose one by name; cancelling keeps the menu open.
Opening the draft preserves its source and working settings and saves nothing.
Finishing returns to the same menu item. Each editor retains its own save and
leave choices: the voice editor offers Keep, Discard, or Continue editing;
a rule editor can ask before discarding an unsaved draft.

In the common editor, ~u~ undoes and ~q~ offers keep, discard, or continue.
Guided feedback ~q~ first goes up through components, then hides/retains the
draft at the top. To reverse an applied rule, use ~C-e H r o~ and disable or
delete it in the correct scope with ~t~/~d~.

Drafts last only until Emacs exits. Discard abandons unsaved edits, not completed
saves. The voice editor distinguishes stored settings from successful worker
application; use that distinction when deciding to retry or make another edit.

If saving finished but application did not, keep the result separate from
an unfinished editor draft. Use the following procedure before retrying.

*** An Apply result is unconfirmed
:PROPERTIES:
:TEXINFO_NODE_NAME: Unconfirmed Speech Changes
:DESCRIPTION: Interpret timeouts and partial results without treating them as rollback.
:END:

#+cindex: timeout, applying speech settings
#+cindex: Apply, unconfirmed result
#+cindex: did my change succeed

Apply waits for acknowledgements from each speech stream. After an Omnivox
timeout, Workbench reports /server outcome unconfirmed/, stops that
transaction and sends no later steps. Requests already sent may still take
effect. A timeout does not undo the saved settings, and it does not tell you
that Omnivox rejected them.

1. Read the result for each stream. Partial results retain acknowledged
   streams and identify timeouts; do not describe both as failed when only
   one is unconfirmed.
2. Check for newer staged edits before retrying. Save them deliberately or
   cancel them; do not mistake an older reply for acceptance of newer work.
3. In Workbench, ~r~ reapplies saved engine settings and requests a new result.
   This is an engine-settings recovery action, not a universal retry key in
   every editor. For a palette review or voice save, use that view's own
   retained proposal and retry action.
4. Inspect the new result and repeat the original speaking task. If the result
   remains unconfirmed, keep that distinction in your problem report rather
   than claiming a rollback or a successful application.

Do not delete the saved resource or discard unrelated drafts merely because
a worker did not answer. [[*Prepare a useful problem report][Prepare a useful problem report]] describes the evidence
and privacy precautions for further investigation.

** Voice Lock And Advanced Configuration
:PROPERTIES:
:TEXINFO_NODE_NAME: Voice Lock
:ALT_TITLE: Voice Lock and advanced configuration
:DESCRIPTION: Understand the established face and personality voice adapter.
:END:

#+cindex: Voice Lock

Voice Lock is one compatibility input to Aural Presentation, not the entire
system. It maps Emacs faces and =personality= text properties to voices.
Faces are visual style labels that Emacsvox can use without requiring sight.

#+attr_texinfo: :columns 0.28 0.42 0.30
| Policy | What it controls | How to inspect or change it |
| Semantic presentation | Integration roles, events, states, and attributes | Explain, Presentation Options, and feedback rules |
| Explicit face presentation | Rules deliberately matching an Emacs face | emacsvox-aural-toggle-face-presentation or Aural Doctor |
| Voice Lock | Historical buffer face/personality mapping | C-e H r l v locally; C-e H r l V globally |

To identify Voice Lock's contribution:

1. Move across differently styled elements, such as a comment/string or Org
   heading/link.
2. Toggle ~C-e d v~ in that buffer and compare the same elements.
3. Explain with ~C-e E~ to inspect Voice Lock/face state and contributing rules.

Turning it off removes only that compatibility contribution. Semantic
presentation, explicit face rules, cues, tones, and spoken status remain.
The global command updates existing and new buffers; a mode can still opt out
on startup. The same controls are available at ~C-e H r l v~ for the captured
buffer and capital ~V~ for global policy. That submenu's ~w~ saves only global
Voice Lock through Customize. Buffer-local Voice Lock is not captured in
Presentation Profiles.

To silence or restore the personality or mapped face at the captured item,
choose ~s~ in that submenu. This uses the existing local suppression command;
it can affect other text using that mapping in the same buffer. It does not
retune the named voice, and a globally inaudible mapping cannot be restored
there. The change lasts for the buffer and is not saved. Close and reopen the
menu from the intended item if its captured source has changed.

For new changes, prefer explanation, settings menus, palettes, and Workbench.
Legacy named voices can still use =-settings= options such as =voice-monotone-settings=. Customise
the option, not a generated =acss-...= symbol. Historical background is in
[[info:emacsvox-heritage#Audio Formatting And Aural CSS][Audio Formatting And Aural CSS]] in /Emacspeak Heritage/.

Named formatting voices such as =bolden= and =annotate= follow the active
palette. An inherited standard entry may be implemented by a personality's
settings option within the explicit root, not a hidden second fallback.
Explicit styles retain their own settings and rules can change the resulting
voice.

The [[info:emacsvox#Integration Maintenance][Developer Guide]] covers voice metadata, rule authoring, and integrations;
[[info:emacsvox#Speech Server Protocols][Speech Server Protocols]] covers delivery. The generated
[[info:emacsvox-reference#Emacsvox Commands And Options][Emacsvox Commands And Options]] records exact commands, options, and keymaps.
These complement the tasks here rather than being prerequisites for them.
