* Aural Presentation: Speech, Voices, And Sound
:PROPERTIES:
:TEXINFO_NODE_NAME: Aural Presentation
:ALT_TITLE: Aural Presentation
:DESCRIPTION: Understand and adjust how Emacsvox conveys meaning.
:END:

#+cindex: Aural Presentation

Aural Presentation is the Emacsvox system that decides /how/ information and
events should be heard.  It can combine spoken text, voice changes, auditory
icons, tones, pauses, and spatial cues in one ordered presentation.  The speech
server delivers that result; it does not decide what a heading, unread message,
completed command, warning, or other object means.

You do not need to configure Aural Presentation before using Emacsvox.  The
built-in baseline and application integrations provide useful defaults.  When
you do want a change, start from the object you heard and use Aural Home rather
than editing configuration data by hand:

#+attr_texinfo: :indic kbd :compact t
- C-e H ::

  Open Aural Home, the spoken control center for understanding, adjusting, and
  diagnosing presentation.

- C-e E ::

  Explain why the object at point received its voices, sounds, and other
  actions.

For a first experiment, press @@texinfo:@kbd{C-e H}@@ and use
@@texinfo:@kbd{/}@@ to find /Browse and try voices/.  Select an engine with
@@texinfo:@key{RET}@@, then a voice with @@texinfo:@kbd{P}@@ to hear it.  Nothing
is saved by browsing or previewing.  To change something you just heard, use
@@texinfo:@kbd{C-e H c}@@ for the current item, or
@@texinfo:@kbd{C-e H H}@@ to select past feedback.  See
[[info:emacsvox#Voices And Routing][Voices And Routing]] for complete examples.

This chapter gives a user-level model of the system and practical workflows for
common changes.  The generated reference provides rule
schemas, transport contracts, and extension development.

** A Practical Model Of Presentation
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Model
:ALT_TITLE: Presentation Model
:DESCRIPTION: Follow meaning from an Emacs application to audible output.
:END:

#+cindex: presentation model

It helps to separate four questions that are often mixed together:

#+attr_texinfo: :columns 0.22 0.30 0.48
| Layer | Question | Example |
| Meaning | What happened or what is this? | A level-two heading was reached during navigation. |
| Presentation | What should convey that meaning? | Speak the heading in a named voice and play a section cue first. |
| Resources | Which voice and sound realize that request? | Resolve the logical voice through the active palette and the cue through the active sound pack. |
| Output | What can this machine produce? | Route speech to an installed engine and apply supported spatial behavior. |

An Emacs mode or Emacsvox integration supplies facts about an object or event.
Facts can describe a role such as a heading, an event such as completion, a
state such as unread, or an attribute such as heading level.  Context also says
whether you are navigating, reading continuously, or receiving a state change.
This allows the same object to receive concise feedback during continuous
reading and more orientation when you move to it deliberately.

Presentation rules match those facts and context.  A rule can choose a voice,
add speech or a cue, insert a pause or tone, request spatial placement, or
suppress something that is unhelpful.  Several matching rules can compose; a
stronger, narrower rule need change only the relevant part rather than repeat
the complete presentation.

The user-visible configuration layers are:

1. A fixed internal baseline that preserves established Emacsvox behavior.

2. Automatic integration behavior supplied by the active mode or package.

3. Enabled /Presentation Options/ that add optional behavior in a stable
   weakest-to-strongest order.

4. Personal, session, and current-buffer /overrides/.  These are the strongest
   layers and are intended for precise changes.

A presentation profile is not another rule layer.  It records a complete set
of selected options, sound pack, voice palette, and spatial choices so you can
switch those choices together.

** What You Can Hear
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Modalities
:ALT_TITLE: Presentation Modalities
:DESCRIPTION: Recognize speech, voices, cues, tones, pauses, and spatial output.
:END:

#+cindex: presentation modalities

Aural Presentation can use one or more of these forms of feedback:

- /Speech/ conveys content, labels, prompts, results, and status.  Added speech
  should explain meaning that is not already clear from the content.

- /Voice/ changes characteristics of spoken content.  Named logical voices
  make distinctions such as headings, annotations, warnings, or quoted text
  portable across speech engines.

- /Auditory cues/ are short recognizable sounds associated with semantic
  events or objects.  A sound pack supplies the concrete audio for those cue
  names.

- /Tones/ convey compact information using a named pitch and duration.  They
  are useful when a short distinction is preferable to speech or a sampled
  sound.

- /Pauses/ separate related parts of a presentation without adding words.

- /Spatial presentation/ can place speech or cues across supported output.
  When the selected backend cannot provide the requested placement, Emacsvox
  keeps the content audible using its documented fallback.

These forms can be ordered around the content.  For example, entering a section
might play a cue, speak the heading in a distinctive voice, and leave a short
pause before body text.  The presentation is one result, not several unrelated
notifications.

The precise sound may vary by speech engine, installed voices, sound pack, and
audio hardware.  The intended distinction should remain understandable even
when a simpler backend uses fewer voice characteristics or centered output.

*** Main And Notification Speech Streams
:PROPERTIES:
:TEXINFO_NODE: no
:END:

#+cindex: speech streams

#+cindex: notification stream

#+vindex: tts-notification-device

Emacsvox assigns speech to one of two streams according to what caused it:

- The /main stream/ presents foreground information produced directly by your
  current interaction, such as movement, entering a buffer, or opening a
  message.  New navigation interrupts obsolete main-stream speech, and you can
  interrupt a longer entry announcement by navigating again.

- The /notification stream/ presents asynchronous events, such as completion
  of background work.  It does not stop main-stream speech, and normal
  navigation does not stop it, so both streams may be heard concurrently.  A
  notification cue and its associated speech are delivered together on this
  stream.

With Omnivox, Emacsvox starts a second server process for the notification
stream by default.  Set ~tts-notification-device~ to ~left~, ~right~, or
~both~ to choose that process's route.  Set it to ~default~ or the empty string
to disable the separate process; notification speech then falls back to the
main process and remains interruptible by navigation.  Other speech backends
may use a configured notification device or fall back to the main stream.

Stopping obsolete main speech is local to the main stream.  An explicit
~tts-stop~ command stops both main and notification speech.

** Begin With Aural Home
:PROPERTIES:
:TEXINFO_NODE_NAME: Aural Home
:ALT_TITLE: Aural Home
:DESCRIPTION: Navigate the spoken presentation control center.
:END:

#+cindex: Aural Home

Open Aural Home from an ordinary buffer with @@texinfo:@kbd{C-e H}@@.  Emacsvox
remembers that source buffer and opening position so contextual actions such
as explanation and remapping operate on the object you were using.  Moving
the source cursor while Home is open does not change this target.  In Home,
@@texinfo:@kbd{C-c C-o}@@ returns to it.  To choose a new target, invoke
@@texinfo:@kbd{C-e H}@@ afresh from that item in an ordinary buffer.

Returning through Home or Help preserves the selected row and unfinished
edits.  Buffer rule editors retain separate drafts for each source buffer;
reopening a modified editor resumes its draft.  Reopening the same voice in
the tuner likewise preserves its working settings.  If a prepared remap's
source item changes or disappears, Emacsvox asks you to prepare that change
again before applying it.

Aural Home begins with five task groups in one spoken table.  Press
@@texinfo:@key{RET}@@ or @@texinfo:@key{TAB}@@ to expand or collapse a group.
Each action names a destination, reports its current status, and describes
its purpose.  @@texinfo:@kbd{/}@@ searches all actions, including collapsed
groups; the matching group opens with your destination selected.  The common controls are:

#+attr_texinfo: :indic kbd :compact t
- n, p, down, up :: Move by row; settings lists speak the name and current state.
- left, right :: Move among the titled columns.
- . :: Speak the current column title and value.
- SPC :: Speak the complete current row.
- RET :: Open a destination, child list, or details. In the tuner, edit a value.
- C-c C-a :: Choose an applicable action by name.
- N :: Create a new item where supported.
- P :: Preview in managers and editors; Home retains its profiles shortcut.
- S :: Stop the preview and its remaining samples.
- ? :: Display and speak help for the current Aural interface.
- h :: Return to Aural Home from a manager or editor.
- q :: Leave the current Aural interface.

The five groups are:

#+attr_texinfo: :columns 0.35 0.65
| Task group | Destinations |
| Understand or change feedback | Current item explanation and remapping, Recent Feedback, semantic vocabulary, and return to source. |
| Choose voices and sounds | Browse and try voices, palettes, sound packs, speech engine and rate, notifications, spatial settings, and the full Voice Workbench. |
| Choose optional feedback | Presentation Options and training explanations. |
| Manage changes and saved setups | Unfinished drafts, overrides, buffer rules, and Presentation Profiles. |
| Troubleshoot | Aural Doctor and Omnivox engine modules. |

Home announces the captured source and unfinished draft count on entry.
Choose /Resume unfinished changes/ to visit the original rule editor, tuner,
or routing Workbench.  The draft is still unsaved until you accept it there.
Presentation Profiles capture options, palette, sound pack, and spatial
settings.  Physical voice routes have their own saved routing profile.

You can press @@texinfo:@key{RET}@@ on a row without memorizing its shortcut.  Aural
Home also provides direct keys for frequent routes, including @@texinfo:@kbd{x}@@ for
explanation, @@texinfo:@kbd{O}@@ for overrides, @@texinfo:@kbd{H}@@ for recent feedback,
@@texinfo:@kbd{P}@@ for profiles, @@texinfo:@kbd{V}@@ for voice palettes, @@texinfo:@kbd{W}@@ for
Voice Workbench, and @@texinfo:@kbd{D}@@ for Aural Doctor.

** Understand Why Something Sounded That Way
:PROPERTIES:
:TEXINFO_NODE_NAME: Explaining Presentation
:ALT_TITLE: Explaining Presentation
:DESCRIPTION: Explain current or recently queued feedback.
:END:

#+cindex: explaining presentation

Use this workflow when feedback is surprising, unclear, or especially useful:

1. Leave point on the object and press @@texinfo:@kbd{C-e E}@@.

2. Read the explanation as a report of the object and occasion, matching
   presentation rules, selected actions, concrete voices and sounds, and any
   backend fallback or degradation.

3. Note the strongest rule that changed the part you care about.  This tells
   you whether to inspect an option, an override, a voice route, a sound pack,
   or the Voice Lock compatibility layer.

When a retained presentation still matches the source buffer, position, and
unchanged source revision, the explanation
describes the exact output that was queued, including its source location and
resolved resources.  It does not reinterpret that old output using your latest
settings.  Without an exact record, Emacsvox labels the explanation as a
simulation of what the current rules would produce at point.

To inspect something heard earlier, open Aural Home and choose /Recent Aural
Feedback/, or press @@texinfo:@kbd{H}@@ there.  Each row is a bounded frozen record.
Useful commands in the feedback browser include:

#+attr_texinfo: :indic kbd :compact t
- RET or e :: Explain the selected retained presentation.
- P :: Replay its complete ordered presentation.
- c :: Audition only its auditory cues.
- r :: Prepare a voice remap from the selected record.
- R :: Replace, suppress, or restore one exact earcon.
- L :: Change the bounded history limit for the current session.

Training Mode, available from Aural Home, speaks concise semantic explanations
after normal presentations.  It can help while learning the vocabulary used by
an integration, but is intentionally more verbose than ordinary operation;
turn it off when you no longer need the additional labels.

** Make A Small Change Safely
:PROPERTIES:
:TEXINFO_NODE_NAME: Adjusting Presentation
:ALT_TITLE: Adjusting Presentation
:DESCRIPTION: Preview, scope, save, and undo presentation changes.
:END:

#+cindex: presentation overrides

Start by choosing the narrowest tool that matches your intention:

#+attr_texinfo: :columns 0.42 0.30 0.28
| Intention | Use | Scope |
| Try an optional behavior supplied by Emacsvox or an integration | Presentation Options | Global configuration |
| Change voice, sound, tone, label, or suppression | Change this feedback | Personal, session, or current buffer |
| Review or remove an existing precise change | Presentation Overrides | Its recorded scope |
| Try rules only in the current work buffer | Current Buffer Rules | Life of that buffer |
| Switch a complete reading or working setup | Presentation Profiles | Saved global configuration |

*** Guided Change This Feedback
:PROPERTIES:
:TEXINFO_NODE: no
:END:

1. Move to a representative item, press @@texinfo:@kbd{C-e H}@@, then
   @@texinfo:@kbd{c}@@.  This captures /Current item/.  For feedback that has
   already happened, use Home's @@texinfo:@kbd{H}@@, select a /Recent Feedback/
   record, and press @@texinfo:@kbd{C}@@.  A record containing several parts
   asks which part to change.  Truncated history cannot supply a complete
   original/proposed comparison.

2. Press @@texinfo:@kbd{c}@@ to choose a component change.  Available choices
   include the content voice, adding a sound or tone, adding a spoken label,
   replacing an existing sound, changing a tone, or suppressing one component.
   You can add a cue when the original has none.  The choices use the facts
   and components supplied by the integration; they cannot add missing
   semantic distinctions.

3. Press @@texinfo:@kbd{P}@@ to hear the proposed change before choosing how
   long to keep it.  @@texinfo:@kbd{O}@@ plays the frozen original example;
   @@texinfo:@kbd{S}@@ stops.  Proposed preview resolves the selected example
   with current rules and its captured buffer context.  It does not apply
   your draft to live feedback.

4. Press @@texinfo:@kbd{m}@@ for /What should match/.  Review the actual facts,
   states, events, and occasion.  When available, the object-kind choice
   omits events and occasion and therefore affects more presentations.
   These are rules for every matching item, not an edit to one object.

5. Press @@texinfo:@kbd{l}@@ for /How long/: the source buffer's lifetime,
   this Emacs session, or a saved personal rule.  A buffer rule affects every
   matching item in that buffer.  Review the spoken summary of target,
   change, matching criteria, and lifetime.

6. Press @@texinfo:@kbd{a}@@ or @@texinfo:@kbd{C-c C-c}@@ to apply or save.
   @@texinfo:@kbd{e}@@ instead opens the prepared rule in the Advanced editor.
   @@texinfo:@kbd{q}@@ hides the guided draft; Home's /Resume unfinished
   changes/ brings it back.  Aborting a choice or leaving before Apply does
   not change live rules.  Failed saves retain the draft and report failure.

Replacing or suppressing a sound targets its identity in its before- or
after-content phase, retaining other components.  Existing rule data can
insert only at the beginning or end of a phase; replacing a middle component
therefore asks which edge to use and includes that placement in the summary.
Ambiguous components require the Advanced editor.  Current-item changes
recheck their captured source before applying; a changed or killed target
must be inspected again.  Historical changes remain tied to the selected
frozen example.

*** Remap One Item At Point
:PROPERTIES:
:TEXINFO_NODE: no
:END:

1. Move to a representative object and press @@texinfo:@kbd{C-e E}@@ so you know what
   currently controls it.

2. Press @@texinfo:@kbd{C-e H}@@.  Use @@texinfo:@kbd{r}@@ to remap its voice or @@texinfo:@kbd{R}@@ to
   remap one exact earcon.

3. Choose the scope deliberately:

   - a /personal/ override persists across Emacs sessions;
   - a /session/ override lasts until this Emacs exits; and
   - a /buffer/ override affects only the remembered live buffer.

4. Review the generated rule in the editor.  It is initially unwritten.  Use
   the editor's @@texinfo:@kbd{?}@@ help, preview when offered, and press @@texinfo:@kbd{w}@@ only
   when the target, scope, and change are correct.

5. Return to the source, repeat the action, and use @@texinfo:@kbd{C-e E}@@ again to
   confirm which rule now wins.

In the rule editor, @@texinfo:@kbd{n}@@ and @@texinfo:@kbd{p}@@ move between
rules.  @@texinfo:@kbd{N}@@ adds a rule, @@texinfo:@kbd{P}@@ previews it, and
@@texinfo:@kbd{S}@@ stops.  These replace the former lowercase Add and Preview
keys.  Saving announces whether the rule was saved or applied temporarily.
@@texinfo:@kbd{q}@@ asks before discarding an unfinished draft.

Open /Presentation Overrides/ to manage these changes together.  There,
@@texinfo:@kbd{P}@@ previews the complete current result, @@texinfo:@kbd{t}@@ temporarily disables
or enables a rule, and @@texinfo:@kbd{d}@@ removes it.  Disabling or deleting an
override restores the next weaker behavior; it does not leave a copied default
behind.

*** Try A Presentation Option
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Presentation Options are maintained additions such as richer heading feedback
or integration-specific cues.  From Aural Home, open /Presentation Options/:

1. Use @@texinfo:@key{TAB}@@ or @@texinfo:@key{RET}@@ on a collection to expand it.

2. Move to an option and press @@texinfo:@kbd{P}@@ to preview it composed with the
   current configuration.  Press @@texinfo:@kbd{C-u P}@@ to preview it in isolation.

3. Press @@texinfo:@kbd{t}@@ to enable or disable it.  Press @@texinfo:@kbd{a}@@ to hear
   enabled options in their exact weakest-to-strongest order.

4. Return to the source and test the original task.  Personal, session, and
   buffer overrides remain stronger than an enabled option.

Avoid reordering options merely to solve one exceptional object.  A narrow
override usually expresses that intention more clearly.

** Save Complete Setups With Profiles
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Profiles
:ALT_TITLE: Presentation Profiles
:DESCRIPTION: Save and switch complete presentation configurations.
:END:

#+cindex: presentation profiles

A presentation profile records a coordinated setup: enabled Presentation
Options and their order, the sound pack, the voice palette, and portable
spatial settings.  This is useful for switching between focused work and
leisure reading, between quiet and information-rich feedback, or between audio
environments.

To save and use a profile:

1. Configure the live options, sound pack, voice palette, and spatial choices
   you want.

2. Open /Presentation Profiles/ from Aural Home or press @@texinfo:@kbd{P}@@ there.

3. Press @@texinfo:@kbd{N}@@ to save the current live configuration as a new named
   profile.

4. Later, select that profile and press @@texinfo:@kbd{a}@@ to apply
   its saved values.

5. If you deliberately change the live configuration and want the selected
   profile to adopt it, press @@texinfo:@kbd{w}@@.  If you instead want to discard the
   live differences, press @@texinfo:@kbd{a}@@ to restore the saved profile; Emacsvox
   asks before replacing the diverged values.

Only one profile identity is selected.  /Active/ means the selected profile's
saved values match the live configuration.  /Diverged/ means the same profile
is still selected but the live values differ; it is a status, not an unsaved
editor warning.

Profiles do not copy presentation rules.  Edit rules in Presentation Options
or Overrides.  They also do not capture buffer-local Voice Lock state or
current-buffer rules, because those belong to an individual buffer rather than
a global setup.

** Choose Voices And Speech Engines
:PROPERTIES:
:TEXINFO_NODE_NAME: Voices And Routing
:ALT_TITLE: Voices And Routing
:DESCRIPTION: Distinguish logical styles, palettes, physical voices, and engines.
:END:

#+cindex: voice palettes

#+cindex: Voice Workbench

Four terms help when adjusting voices:

- A /logical voice/ expresses a purpose such as boldening, annotation, or a
  heading distinction without naming one synthesizer voice.

- A /voice palette/ gives named logical voices portable style characteristics.
  Palettes can inherit from another palette and travel between machines.

- A /physical voice/ is an actual voice reported by an installed speech engine.
  Its exact identifier is usually machine-local.

- An /engine route/ decides which engine and physical voice realize a logical
  voice on the current machine.

Use the /Voice Palettes/ manager when you want to choose or edit the portable
style vocabulary.  Press @@texinfo:@key{RET}@@ on a palette to browse its voices,
use @@texinfo:@kbd{P}@@ to audition the palette sequence before editing, and use @@texinfo:@kbd{a}@@ in the palette manager to
activate a selected palette.  Built-in palettes remain intact; editing can
create a personal copy.

Use /Voice Workbench/ when the question involves installed voices, engines, or
routes.  Open it from Aural Home with @@texinfo:@kbd{W}@@.  Its main views are:

#+attr_texinfo: :indic kbd :compact t
- l :: Logical voices and their current routes.
- v :: Physical voices reported by the engines.
- e :: Engines, preference, fallback, and health.
- s :: Portable styles and effects.

For physical voices, choose /Browse and try voices/ in Home, then press
@@texinfo:@key{RET}@@ on an engine to browse its voices.  @@texinfo:@key{RET}@@
on a voice shows details; @@texinfo:@kbd{P}@@ plays a named sample.  Filters
and each view's selected row and column survive navigation through Home.

The engine list reports /Availability/ before routing preferences.  An engine
with a missing runtime stays visible as /unavailable/, with its reason under
/Last failure/.  /Routing policy: allowed/ means the policy permits using that
engine; it does not mean its runtime is installed.  Disabled policies, health,
and temporary failures are reported separately.

@@texinfo:@kbd{A}@@ plays available matching voices in displayed order,
skipping unavailable rows.  @@texinfo:@kbd{B}@@ starts with the selected voice
as A and offers another matching voice as B.  Choose /Search all engines/
inside that prompt to compare outside the current filters.  Both samples use
the same sentence.  @@texinfo:@kbd{T}@@ edits it, @@texinfo:@kbd{F}@@ filters,
@@texinfo:@kbd{C}@@ clears filters, and @@texinfo:@kbd{R}@@ refreshes inventory.

Labels identify each engine and voice.  Customize
~emacsvox-aural-preview-label-verbosity~ for names, brief letters or numbers,
or no labels.  Labels and samples share one preview sequence:
@@texinfo:@kbd{S}@@ or foreground navigation cancels the remaining samples.
An exact-preview failure is reported instead of accepting a different voice
as the requested one.  Availability and capability reports describe what the
adapter advertises; they are not a listening test of every parameter.

Use @@texinfo:@kbd{a}@@ to assign a physical voice and @@texinfo:@kbd{t}@@ to tune the
selected logical voice on its effective route.  Route changes are staged until
you press @@texinfo:@kbd{w}@@ or @@texinfo:@kbd{C-c C-c}@@ to save and apply them.  Pressing
@@texinfo:@kbd{q}@@ with unsaved route changes warns that they remain staged.

The tuner names neutral effect values instead of speaking an ambiguous number:
gain five is /unchanged/, low-pass nine is /disabled/, high-pass zero is
/disabled/, pan five is /centre/, and reverb, echo, or chorus zero is
/disabled/.  Chorus adds a bounded doubled-voice modulation without changing
speech duration or marker positions.  It is applied by Omnivox to buffered
audio; the tuner reports when the selected route cannot apply it.  These
portable levels are translated to the exact values required by the active
adapter.

The built-in ~acss-default~ palette also includes a ~telephone~ logical voice.
It combines high-pass and low-pass filtering to give any buffered Omnivox
engine a narrow-band telephone sound while preserving its selected physical
voice, duration, and markers.  Preview it in /Voice Palettes/ or /Voice
Workbench/ before assigning it to content.  Adapters without post-synthesis
filtering preserve the portable style but do not apply the filters.

Omnivox average-pitch differences use the customizable
=omnivox-average-pitch-contrast=.  Its default value, =0.5=, keeps palette
distinctions while making them gentler.  Set it to =1.0= for the historical
contrast, or =0= to make average pitch neutral.  Values through =2.0= are
accepted.  Changing it refreshes logical-voice registration, and the same
setting applies to previews, structured speech, and legacy inline voices.

For a quick engine preference, @@texinfo:@kbd{C-e d e}@@ chooses an available engine
for the current Emacs session.  Press @@texinfo:@kbd{C-u}@@ first to save the new
preference.  On a first run with no saved routing profile, the ordinary command
uses the live Omnivox policy as an in-memory baseline and writes no file; the
prefixed command explicitly saves that baseline and the selected preference.
Explicit logical-voice routes still take precedence.

Judge voices in context.  The goal is usually to distinguish nearby kinds of
content, not to identify every named voice in isolation.  Use a portable
palette for the intended distinction and machine routing for the best local
realization.

*** Tune A Physical Voice Temporarily
:PROPERTIES:
:TEXINFO_NODE: no
:END:

In /Browse and try voices/, select a physical voice and press
@@texinfo:@kbd{t}@@.  This opens a temporary experiment with that exact
engine and voice, engine-default speech characteristics, the current speech
rate, and neutral audio effects.  Opening, adjusting, comparing, and
cancelling perform no configuration writes or route assignments.

The experiment uses its working voice for navigation, values, and Help.
@@texinfo:@kbd{n/p}@@ or up/down selects a parameter; left/right adjusts it;
@@texinfo:@key{RET}@@ enters a value; blank retains the current value and
@@texinfo:@kbd{d}@@ explicitly requests the adapter default.  @@texinfo:@kbd{P}@@ plays the working
version.  @@texinfo:@kbd{B}@@ alternates the opening and working versions,
@@texinfo:@kbd{u}@@ undoes, @@texinfo:@kbd{R}@@ restores the opening voice and
parameters, and @@texinfo:@kbd{S}@@ stops.  @@texinfo:@kbd{T}@@ changes the
sample, @@texinfo:@kbd{c}@@ copies an existing style, and @@texinfo:@kbd{v}@@
tries another physical voice while retaining the requested parameters.

For a three-value comparison, select a supported numeric parameter and
choose /Demonstrate the selected parameter/ from @@texinfo:@kbd{C-c C-a}@@,
or press @@texinfo:@kbd{D}@@.  Enter three valid values; each is labelled
before the identical sentence.  This demonstration does not change the
working settings and can be stopped as one sequence.

Engine speech controls and Omnivox audio effects are identified separately.
The Requested column shows your settings.  Playback reports show omissions
or acceptance; adapters do not report exact effective numeric values.  A
failed physical voice is reported explicitly.  If it prevents navigation,
ordinary speech keeps the tuner operable and announces that fallback.

Press @@texinfo:@kbd{w}@@ or @@texinfo:@kbd{C-c C-c}@@ to choose /Keep result/:
parameters as a named style, a physical voice route retaining the existing
style, or both voice and parameters for a named logical voice.  A built-in
palette is copied only when you save the reviewed result.  The review names
the destinations and shows the parameters.  Press @@texinfo:@kbd{C-c C-c}@@
in that review to save and apply them.  Palette selection applies for the
session; a Presentation Profile can retain that choice.  Route and style
files remain separate.  Any partial save or failed apply is reported, and
the review retains completed steps so you can retry without repeating writes.
@@texinfo:@kbd{q}@@ returns from the review; cancelling before Save and apply
leaves configuration unchanged.

**** Browse Eloquence And Compare Pitch
:PROPERTIES:
:TEXINFO_NODE: no
:END:

1. Open @@texinfo:@kbd{C-e H}@@ and search with @@texinfo:@kbd{/}@@ for
   /Browse and try voices/.  Select the installed Eloquence engine and press
   @@texinfo:@key{RET}@@.  Its list shows the voices this installation reports;
   if Eloquence is unavailable, choose another available engine.
2. Use up/down to choose a voice.  @@texinfo:@kbd{P}@@ plays it;
   @@texinfo:@kbd{A}@@ plays the filtered list with spoken names, and
   @@texinfo:@kbd{S}@@ stops.  @@texinfo:@kbd{T}@@ chooses your own sample
   sentence.  For two different voices, @@texinfo:@kbd{B}@@ uses the selected
   voice as A and asks for B.
3. Press @@texinfo:@kbd{t}@@ on one physical voice.  Move to /Average Pitch/.
   Press @@texinfo:@key{RET}@@ and enter @@texinfo:@kbd{3}@@, then
   @@texinfo:@kbd{P}@@.  Enter @@texinfo:@kbd{7}@@ and replay the same sentence.
   @@texinfo:@kbd{u}@@ restores the previous value for another comparison.
   Navigation also uses the working voice, so you can hear it in actual use.
4. For a labelled sequence, press @@texinfo:@kbd{D}@@ on Average Pitch and
   supply three valid values, for example 3, 5, and 7.  This does not change
   the working value.  @@texinfo:@kbd{B}@@ compares the opening and working
   versions; it does not compare the two most recent edits.

**** Keep A Voice Experiment
:PROPERTIES:
:TEXINFO_NODE: no
:END:

From the physical tuner, press @@texinfo:@kbd{w}@@ after finding a useful
setting.  Choose /parameters as a named style/ to keep characteristics while
letting existing routes choose the physical voice; choose /physical voice
route/ to assign that voice while retaining the destination's existing style;
choose /both/ to keep both for the chosen logical voice.

Choose a destination name and, when needed, an editable palette.  Read the
review, including the exact physical route and parameter values, and use
@@texinfo:@kbd{P}@@ to preview that proposal.  Only
@@texinfo:@kbd{C-c C-c}@@ in the review saves and applies it.  Palette selection
is temporary for this session; save a Presentation Profile if you want to
retain that selection.  The route has its own machine-local saved profile.
If a step fails, the review states which writes succeeded and retains the
remaining steps for retry.  @@texinfo:@kbd{q}@@ before saving changes nothing.

**** Change A Heading Voice, Add A Cue, Or Silence One
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Move to a representative heading and open @@texinfo:@kbd{C-e H c}@@.
Press @@texinfo:@kbd{c}@@, choose /Change the content voice/, and select a
named voice such as ~bolden~.  @@texinfo:@kbd{P}@@ previews it.  Use
@@texinfo:@kbd{m}@@ to review the actual heading facts, including level when
supplied by the integration.  Use @@texinfo:@kbd{l}@@ to choose a lifetime,
review the summary, then press @@texinfo:@kbd{a}@@.  A rule matching level-two
headings affects all matching level-two headings within that lifetime's scope.

To add a cue, begin again with a representative item and choose /Add a sound/.
Select before or after content, choose a registered sound, and preview it.
To silence an existing cue, choose /Suppress one component/ and select that
sound by phase and identity.  This retains the spoken content and other
feedback.  Review matching criteria and lifetime before applying either rule.

**** Change A Blank-Line Tone
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Navigate onto a blank line so its feedback enters history.  Open
@@texinfo:@kbd{C-e H H}@@, select that blank-line record, and press
@@texinfo:@kbd{C}@@.  Choose /Change a tone/, select the tone, then choose a
named tone or explicit pitch in Hertz and duration in milliseconds.  Compare
@@texinfo:@kbd{O}@@ and @@texinfo:@kbd{P}@@.  Review the matching facts before
choosing lifetime and applying.

If that record contains a cue instead of a tone, the tone choice is absent.
Use /Explain/ to see which rule supplied the cue; a guided change can suppress
that cue, and a second change can add a tone.  The interface reports the
actual presentation rather than assuming every visually blank line uses the
same feedback.

**** Choose An Engine And Recover Unfinished Work
:PROPERTIES:
:TEXINFO_NODE: no
:END:

For ordinary speech, open Home and search for /Ordinary speech engine/, or
use @@texinfo:@kbd{C-e d e}@@ directly.  Choose an available engine.  This
preference lasts for the session; a prefix argument explicitly saves it.
Existing exact logical-voice routes take precedence over the preference.

Use @@texinfo:@kbd{h}@@ to leave a working editor through Home without losing
it.  Home's /Resume unfinished changes/ opens the original draft, including
its source and working settings.  In a voice tuner, @@texinfo:@kbd{u}@@ undoes
and @@texinfo:@kbd{R}@@ restores the opening settings.  Its
@@texinfo:@kbd{q}@@ asks before discarding changes.  Guided feedback
@@texinfo:@kbd{q}@@ hides and retains the draft.  To undo an already applied
rule, open /Presentation Overrides/, select it in the appropriate scope, and
use @@texinfo:@kbd{t}@@ to disable it or @@texinfo:@kbd{d}@@ to remove it.

From any Aural interface, @@texinfo:@kbd{C-c C-i}@@ opens its offline task
manual and @@texinfo:@kbd{q}@@ returns to the same interface and position.
In Help, @@texinfo:@kbd{i}@@ opens that manual.  @@texinfo:@kbd{C-c C-a}@@
offers named actions; @@texinfo:@kbd{S}@@ stops a preview sequence.

** Choose Sounds And Spatial Cues
:PROPERTIES:
:TEXINFO_NODE_NAME: Sounds And Space
:ALT_TITLE: Sounds And Space
:DESCRIPTION: Audition sound packs and inspect spatial fallback.
:END:

#+cindex: sound packs

#+cindex: spatial presentation

Presentation rules refer to auditory cues by semantic name.  A sound pack maps
those names to concrete audio assets and can inherit missing cues from another
pack.  This separation lets you change the overall sound character without
rewriting every presentation rule.

Open /Sound Packs/ from Aural Home.  In the manager:

#+attr_texinfo: :indic kbd :compact t
- P :: Audition a representative cue without activating the pack.
- RET :: Browse the pack's individual cues and their source or fallback.
- P in the cue browser :: Audition the selected concrete cue; RET shows details.
- v :: Validate the pack and report missing or invalid resources.
- a :: Activate the selected pack.

Use a sound pack when you want to change a family of cues together.  Use
/Remap Earcon At Point/ or Presentation Overrides when one semantic event needs
a different cue, suppression, or restoration.

Spatial requests are portable descriptions rather than assumptions about one
device.  Aural Home separates /Spatial Capabilities/, which reports what the
current route can provide and how it falls back, from /Spatial Settings/, which
controls output, separation, direction, speech, and cues.  Unsupported or mono
output remains audible at the center rather than silently losing content.

Named tones are another compact presentation resource.  They do not require a
sampled sound file and may be used independently of the active sound pack.

** Diagnose Unexpected Presentation
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Troubleshooting
:ALT_TITLE: Presentation Troubleshooting
:DESCRIPTION: Trace unexpected output and use safe diagnostics.
:END:

#+cindex: Aural Doctor

Use the symptom to choose the shortest diagnostic route:

#+attr_texinfo: :columns 0.43 0.57
| Symptom | First action |
| The current object sounds wrong or too verbose | Press @@texinfo:@kbd{C-e E}@@ and inspect the strongest matching rule. |
| Something heard earlier was wrong | Open Recent Aural Feedback and explain its frozen record. |
| A broad optional behavior is unwanted | Inspect Presentation Options and preview or disable the matching option. |
| One narrow exception is unwanted | Open Presentation Overrides, preview it, then disable or remove it. |
| A logical voice uses the wrong engine or physical voice | Inspect its route and engine health in Voice Workbench. |
| A cue is missing or inappropriate | Validate and audition the active Sound Pack, then inspect earcon overrides. |
| A saved setup no longer appears active | Check whether the selected Presentation Profile is active or diverged. |
| Voice changes disappear only in some buffers | Compare Voice Lock and explicit face-presentation state. |

Open /Aural Doctor/ from Aural Home or press @@texinfo:@kbd{D}@@ there.  The doctor
checks live bindings, loaded source or byte-code, the compatibility baseline,
options, profiles, personal data, sound resources, spatial fallback, and the
speech backend.  It does not start the speech server or change settings
automatically.  When one row offers a reviewed safe repair, press @@texinfo:@kbd{r}@@
on that row to run it.

Press @@texinfo:@kbd{?}@@ in any Aural interface for its complete current keys.  If
speech itself is absent rather than merely presented incorrectly, follow
@@texinfo:@ref{Backend Diagnostics And Ownership,Backend Diagnostics And Responsibilities}@@; presentation diagnostics assume that a speech route can run.

** Voice Lock Compatibility
:PROPERTIES:
:TEXINFO_NODE_NAME: Voice Lock
:ALT_TITLE: Voice Lock Compatibility
:DESCRIPTION: Understand the established face and personality voice adapter.
:END:

#+cindex: Voice Lock

Voice Lock is one compatibility input to Aural Presentation, not the whole
presentation system.  It maps established Emacs faces and ~personality~ text
properties to voices.  Emacs calls its visual style labels /faces/; Emacsvox
can use those labels without requiring you to see them.

The three related policies are independent:

#+attr_texinfo: :columns 0.28 0.42 0.30
| Policy | What it controls | How to inspect or change it |
| Semantic presentation | Rules based on roles, events, states, and attributes supplied by integrations. | Use @@texinfo:@kbd{C-e E}@@, Presentation Options, and Overrides. |
| Explicit face presentation | Aural rules that deliberately match a named Emacs face. | Run ~emacsvox-aural-toggle-face-presentation~ or inspect it in Aural Doctor. |
| Voice Lock | The historical face or personality-to-voice mapping in each buffer. | Use @@texinfo:@kbd{C-e d v}@@ locally or @@texinfo:@kbd{C-e d C-v}@@ globally. |

To find out whether a distinction comes from Voice Lock:

1. Move across two elements that the mode treats differently, such as a comment
   and string in source code or a heading and link in Org.

2. Press @@texinfo:@kbd{C-e d v}@@ to toggle Voice Lock only in that buffer, then
   compare the same elements.

3. Press @@texinfo:@kbd{C-e E}@@ on the element.  The explanation reports the
   Voice Lock and explicit face-presentation state alongside the rules that
   contributed to the result.

Turning Voice Lock off removes only its compatibility voice contribution.  It
does not disable semantic presentation, explicit face rules, auditory cues,
tones, or ordinary spoken status.  The global Voice Lock command updates
existing and new buffers; an individual mode can still opt out when it starts.
Buffer-local Voice Lock state is not saved in a presentation profile.

For new customization, prefer explanation, Aural Home, voice palettes, and
Voice Workbench.  Older configurations can still customize a named legacy
voice's ~-settings~ option, such as ~voice-monotone-settings~.  Customize the
settings option rather than a generated ~acss-...~ voice symbol.  Historical
background is preserved in
@@texinfo:@ref{Audio Formatting And Aural CSS,,,emacsvox-heritage,Emacspeak Heritage}@@.
