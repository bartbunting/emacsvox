* Aural Presentation: Speech, Voices, And Sound
:PROPERTIES:
:TEXINFO_NODE_NAME: Aural Presentation
:ALT_TITLE: Aural Presentation
:DESCRIPTION: Understand and adjust how Emacsvox conveys meaning.
:END:

#+cindex: Aural Presentation

Aural Presentation determines how Emacsvox conveys information through speech,
voices, auditory icons, tones, pauses, and spatial cues. An application supplies
the meaning of a heading, unread message, completed command, or warning;
presentation rules choose how to express it. The speech server delivers that
result using the voices and output capabilities available on your machine.

Begin with the item you heard rather than editing configuration data by hand.
~C-e E~ explains its presentation. ~C-e H~ opens the settings menu, and
~C-e S~ opens focused settings for the current task when available. The
walkthroughs below use these menu routes where they are implemented. Aural
Home remains available through ~C-e H h~ for comparison, action search, and
editor or draft workflows that still use it. Its table navigation is different
from the settings menus; the two names are not interchangeable.

Start with the listening exercise. The following sections explain the
presentation model, feedback rules, named voices, installed engines, sounds,
output settings, and saved setups. Menu instructions appear beside their tasks.
In an Aural interface, ~C-c C-i~ opens the relevant manual topic and ~q~ in
Info returns to the interface. In interface Help, ~i~ opens the same topic.

** Getting Started With Aural Home
:PROPERTIES:
:TEXINFO_NODE_NAME: Aural Home
:ALT_TITLE: Getting started with settings menus
:DESCRIPTION: Try a voice, navigate settings, and recognise the remaining Home routes.
:END:

#+cindex: Aural Home

*** Listen without changing settings
:PROPERTIES:
:TEXINFO_NODE: no
:END:

This exercise previews an installed voice without changing saved settings.
Start in an ordinary working buffer so the menu has a source to return to.

1. Press ~C-e H v b~ to open the engine browser through /Voices and engines/.
2. Select an available engine and press ~v~ to list its voices. ~RET~ on an
   Omnivox engine opens its status, downloads, and settings instead.
3. Move to an available voice and press ~P~ to hear a sample. ~S~ stops it.
4. Use ~q~ to return through the browser's parent views to /Voices and
   engines/. Once back in the menu, ~C-q~ closes the menu sequence. The
   original buffer remains your working context.

Browsing and previewing save nothing. A downloaded but inactive voice may
need enablement and Apply before it can be sampled; choose an already available
voice for this first exercise. If an engine is unavailable, its details explain
why. If speech itself is absent, begin with
[[info:emacsvox#Recovering From No Speech][Recovering From No Speech]].

*** Choose an entry point and preserve your place
:PROPERTIES:
:TEXINFO_NODE: no
:END:

The experimental Emacsvox menu, ~C-e H~, groups settings by task. ~C-e S~
opens the current buffer's focused integration settings, or general buffer
settings when no focused menu exists. ~C-e H .~ always opens general buffer
settings. A directly opened focused menu captures the buffer on entry; ~q~
closes it and announces the restored buffer and mode with a close earcon.

The menu captures the source item for contextual actions. In Feedback Details,
~q~ returns to the menu with the same item and settings scope; another ~q~
closes that menu. Opening Feedback Details directly keeps its usual return
destination. A changed or deleted source item must be selected again by
reopening the menu. If the source buffer has closed, the menu cannot resume.

Aural Home remains available with ~C-e H h~ or ~M-x emacsvox-aural~. Editors
that return through ~h~ continue to use Home. Home remembers the source buffer
and opening position for explanation and remapping; moving the source cursor
while Home is open does not select a new target. ~C-c C-o~ in Home returns to
that captured position. To select another item, reopen Home from it in an
ordinary buffer.

A menu return and an editor return are different operations. Use the editor's
own ~q~, ~h~, or finish action before trying menu-navigation keys. Returning
does not reverse an applied setting, and retaining a draft does not save it.
[[info:emacsvox#Saving And Startup][Choose What Persists]] explains those distinctions across the interfaces.

*** Navigate menus and read Help
:PROPERTIES:
:TEXINFO_NODE: no
:END:

The settings menus use Transient. Up/down moves through choices, left/right
moves between sections, and ~RET~ activates the selected choice. ~M-RET~
and ~C-j~ also activate choices. A displayed shortcut invokes its item
directly. In Emacsvox's menus, ~q~ or ~C-g~ goes back one menu and ~C-q~
closes the sequence. Changes already made remain in effect. Other applications
using Transient, including Magit, retain their own activation and quit keys.

Menu feedback interrupts previous main-stream speech, including when you
toggle scope or change a setting. Item announcements include the key without
repeating the word "shortcut" or the section name. Under the default
announcement mode, section names are spoken when you enter a section.
Left/right selects its first selectable item and normally speaks it with the
section name and position.

For menu Help, press ~?~ followed by a choice's key, or ~? ?~ for help on
the current menu. ~q~ in that Help resumes the menu, including its parent menus.

**** Choose navigation and announcement preferences
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Press ~C-e H s n~ for Menu navigation. Choose ~c~ for Continuous, which
crosses sections and wraps around the whole menu; ~w~ to wrap within the
current section; or ~s~ to stop at section edges with a boundary earcon.
Left/right moves between sections in every style. Changes apply immediately
to all Transient menus, independently of the current-buffer settings scope.
Wrap within section is the default.

In the Presentation section, choose ~i~ for Item first or ~n~ for Section
first. Item first is the default; Section first speaks the section name and
position before the item.

Choose ~m~ for /By movement: sections or items/. Left/right speaks only the
destination section and its position. Up/down speaks only the item, key, and
relevant value, even when Continuous navigation crosses a section boundary.
Section-change and wrapping earcons remain the same. This option applies to
all three navigation styles and all Transient menus, including Magit; it does
not change the navigation style.

Section arrows still select the first item. In Emacsvox menus, ~RET~ therefore
activates that item even though its name has not been spoken, and the next
Down advances to the second item. Press ~C-u 0 <down>~ to hear the selected
item without moving. Magit's existing activation bindings remain unchanged.

Press ~v~ to toggle Detailed descriptions. When enabled, menu items retain
their labels and values and add a short command explanation. This applies
globally, including Magit; commands without documentation keep their labels,
and Transient's native infix controls keep their usual descriptions. Detailed
descriptions are on by default. Value adjustments still give brief feedback.
Press ~S~ to save the navigation style, presentation order, and descriptions
preference through Customize.

*** Find a setting or an action
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Press ~C-e H /~ to find an Emacsvox setting by any part of its name, ignoring
capitalisation. Type =cap= to find /Capitalization indication and camel case/,
/Capital-letter beep/, and /All-caps beep/. The aliases =caps beep= and
=allcaps= find both beep controls and only /All-caps beep/, respectively.
Each result appears once under its normal name. Use completion to choose a
result; ambiguous text does not choose one automatically. These matching rules
apply to this search without changing completion elsewhere in Emacs.

~RET~ accepts the choice, opens its menu, and selects the matching control
without changing its value. Press ~RET~ again to activate or edit the control.
The captured source and current settings scope follow the search. ~q~ returns
to the menu where you searched, and cancelling completion keeps that menu open.

Press ~C-e H a~ to search the Home action catalogue, including actions inside
collapsed groups. This route still uses Home: child views keep their normal
returns, and ~q~ from Home returns to the originating menu. It is distinct
from settings search. Within Aural Home itself, ~/~ searches actions.

Press ~C-e H .~ for settings relevant to the captured buffer: speech,
indentation, typing/point feedback, capitalisation, and its major mode's
Customize group when available. This entry starts with buffer scope without
changing the parent's scope. ~A~ opens the advanced Emacsvox Customize group.
In these linked Customize buffers, ~q~ finishes Customize normally and returns
to the menu; use Customize's own Apply and Save commands. See
[[Integration speech settings][Adjust an integration's speech settings]] for application-specific controls.

*** Navigate Aural Home and its editors
:PROPERTIES:
:TEXINFO_NODE: no
:END:

The instructions here apply to the table-based Home, not the Transient menu.
They remain relevant to action search, retained drafts, and editors that
return through Home.

Aural Home begins with six task groups in one spoken table. Press ~RET~ or
~TAB~ to expand or collapse a group. Each action names a destination, reports
its current status, and describes its purpose. ~/~ searches all actions,
including collapsed groups; the matching group opens with the destination
selected.

#+attr_texinfo: :columns 0.35 0.65
| Task group | Destinations |
| Understand and change feedback | Feedback for this item, Recent feedback, and Return to source item. |
| Voices and speech | Voice palettes, Browse voices, Preferred speech engine, Speech rate, Punctuation, and Voice Workbench. |
| Sounds and output | Sound packs, Spatial settings, Audio output, and Review notifications. |
| Optional feedback and rules | Presentation options, Your feedback rules, Current buffer rules, and Explain feedback as you navigate. |
| Saved setups and unfinished changes | Presentation profiles and Resume unfinished changes. |
| Troubleshooting | Aural Doctor and Spatial capabilities. |

Expandable groups announce an open or close cue with their name when you
reach or toggle them. These cues follow the icon setting and sound pack.
For spoken state words, enable /aural-panel-state-labels/ in /Presentation
Options/. This adds ``collapsed'' or ``expanded'' after the control through
the normal presentation rules. Key instructions remain available in Help.

In Home and other Aural tables, the navigation controls are:

#+attr_texinfo: :indic kbd :compact t
- n, p, down, up :: Move by row, retaining and speaking the selected column.
  In the first column, settings lists announce the name and current state.
- left, right :: Move among the titled columns.
- . :: Speak the current column title and value.
- SPC :: Speak the complete current row.
- RET :: Open a destination, child list, or details.
- C-c C-a :: Choose an applicable action by name.
- N :: Create a new item where supported.
- P :: Preview in managers and editors; Home retains its profiles shortcut.
- S :: Stop the preview and its remaining samples.
- ? :: Display and speak help for the current Aural interface.
- h :: Return to Aural Home from a manager or editor.
- q :: Go back or leave; an editor may first offer to retain or discard changes.

Home also provides direct keys for frequent routes: ~x~ for Feedback Details,
~O~ for your feedback rules, ~H~ for recent feedback, ~P~ for profiles, ~V~ for
voice palettes, ~W~ for Voice Workbench, and ~D~ for Aural Doctor.

/Feedback for this item/ combines explanation, playback, and access to voice
and sound changes. Home's ~c~, ~r~, ~T~, and ~R~ open the guided change,
voice-remapping, named-voice, and exact-cue editors. Search also accepts their
existing action names, including /Explain this item/. /Semantic vocabulary/
is available from Home's Help, search, and a change editor's matching criteria.
The direct settings-menu route to that vocabulary is ~C-e H r h~.

The voice editor contains fields and buttons rather than table columns:
left/right changes a numeric value, and ~RET~ edits a field. See
[[info:emacsvox#Editing Named Voices][Edit a Named Voice]]. Keys are local to the view: ~w~ saves a voice in its
editor but exports a palette in the palette manager. Use ~C-c C-a~ to choose
an action by name, or ~?~ for that view's keys.

Panel entry, return, selection, and warning cues accompany their spoken
feedback in one utterance. Returning from a panel announces the destination
and any unfinished draft warning together. These cues follow the icon
setting, sound pack, and cue remapping rules. The voice editor uses the normal
navigation voice for these announcements; auditions still play the working
voice.

Returning through Home or Help preserves the selected row and unfinished
edits. Buffer rule editors retain separate drafts for each source buffer;
reopening a modified editor resumes its draft. Reopening the same voice in
the voice editor likewise preserves its working settings. If a prepared remap's
source item changes or disappears, Emacsvox asks you to prepare that change
again before applying it.

The header identifies the captured source and the number of unfinished drafts.
/Resume unfinished changes/ visits the original rule editor, voice editor, or
Workbench engine settings. The draft remains unsaved until accepted there.
Presentation Profiles capture options, palette, sound pack, and spatial
settings. Physical choices and adjustments belong to named palette voices;
shared engine settings are saved separately. See
[[info:emacsvox#Saving And Startup][Choose What Persists]] before treating a setup as a backup.

** How Aural Presentation Works
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Model
:ALT_TITLE: Presentation Model
:DESCRIPTION: Follow meaning from an Emacs application to audible output.
:END:

#+cindex: presentation model

Four questions explain the path from an application event to sound:

#+attr_texinfo: :columns 0.22 0.30 0.48
| Layer | Question | Example |
| Meaning | What happened or what is this? | A level-two heading was reached during navigation. |
| Presentation | What should convey that meaning? | Speak the heading in a named voice and play a section cue first. |
| Resources | Which voice and sound realise that request? | Find the named voice in the active palette and the cue in the active sound pack. |
| Output | What can this machine produce? | Route speech to an installed engine and apply supported spatial behaviour. |

An Emacs mode or integration supplies facts about an object or event. A fact
can identify a role such as a heading, an event such as completion, a state
such as unread, or an attribute such as heading level. Context says whether
you are navigating, reading continuously, or receiving a state change. The
same object can therefore receive concise feedback during continuous reading
and more orientation when deliberately reached.

Presentation rules match those facts and context. A rule can choose a voice,
add speech or a cue, insert a pause or tone, request spatial placement, or
suppress something unhelpful. Several matching rules can compose. A stronger,
narrower rule need change only the relevant part, not repeat the complete
presentation.

The configuration layers, from weakest to strongest, are:

1. A fixed internal baseline preserving established Emacsvox behaviour.
2. Automatic integration behaviour supplied by the active mode or package.
3. Enabled /Presentation Options/, composed in their stable order.
4. Personal, session, and current-buffer rules for precise overrides.

A presentation profile is not another rule layer. It records selected options,
sound pack, voice palette, and spatial choices so you can switch them together.

For example, an Org integration identifies a level-two heading. A rule requests
=bolden= and a section cue. The active palette supplies =bolden='s settings and
physical choices; the sound pack supplies the cue. The backend plays what it
supports. Changing the rule changes which headings receive the feedback.
Editing =bolden= changes uses of that named entry. Switching sound packs changes
the recording of the cue while preserving its meaning.

When two rules set the same voice field, the stronger explicit value wins;
values are not added. Personal rules are weaker than session rules, which are
weaker than current-buffer rules. Rules can also add actions before or after
content. Use Explain to inspect actual contributors rather than inferring
precedence from the order in which you edited settings.

~C-e H r h~ opens the semantic vocabulary without changing settings.
~C-e H r t~ toggles training explanations across all buffers for this Emacs
session; it does not save a startup default.

*** What You Can Hear
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Modalities
:ALT_TITLE: Presentation Modalities
:DESCRIPTION: Recognize speech, voices, cues, tones, pauses, and spatial output.
:END:

#+cindex: presentation modalities

Aural Presentation combines these forms of feedback:

- /Speech/ conveys content, labels, prompts, results, and status. Added speech
  should explain meaning not already clear from the content.
- /Voice/ changes characteristics of spoken content. Named voices make
  distinctions such as headings, annotations, warnings, or quoted text
  portable across engines.
- /Auditory cues/, also called /earcons/ or /auditory icons/, are short sounds
  associated with events or objects. Sound packs supply recordings for cue names.
- /Tones/ convey compact information using a pitch and duration, without
  requiring sampled sound or a spoken explanation.
- /Pauses/ separate related parts without adding words.
- /Spatial presentation/ places speech or cues across supported output. A
  backend unable to provide requested placement keeps content audible through
  its documented fallback.

These can be ordered around content. Entering a section might play a cue,
speak its heading in a distinctive voice, and leave a pause before body text.
The presentation is one result, not unrelated notifications. Its precise sound
depends on engines, installed voices, sound pack, and hardware. The intended
distinction should remain understandable when a simpler backend offers fewer
voice characteristics or centred output.

** Understand Why Something Sounded That Way
:PROPERTIES:
:TEXINFO_NODE_NAME: Explaining Presentation
:ALT_TITLE: Explaining Presentation
:DESCRIPTION: Explain current or recently queued feedback.
:END:

#+cindex: explaining presentation

Use this workflow when feedback is surprising, unclear, or especially useful:

1. Leave point on the object and press ~C-e E~, or open ~C-e H x~ through
   the settings menu. Both open /Feedback Details/ with a brief introduction
   instead of reading the whole report. The menu route uses the Outline
   layout described below.
2. Inspect the object and occasion, matching rules, selected actions, concrete
   voices and sounds, and any backend fallback or degradation.
3. Identify the strongest rule changing the part you care about. This tells
   you whether to inspect an option, personal or temporary rule, named voice,
   sound pack, or Voice Lock contribution.

~C-e H f~ groups current and recent feedback actions. ~x~ explains the captured
item, ~c~ opens a guided change, ~v~ prepares a voice mapping, ~t~ tunes the
named voice used there, and ~e~ prepares an exact cue remap. ~h~ opens recent
feedback, whose changes use the selected frozen record. Tuning a named voice
affects its other uses; a mapping changes which matching items use a voice.

The editors retain their previews, criteria, scopes, and explicit Apply/Save
steps. Returning restores the menu entry. Guided drafts remain available
through unfinished drafts; a rule list still asks before discarding its
modified draft. A replaced source item is rejected rather than silently
changing the target.

*** Distinguish a record from a simulation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

When retained feedback matches the source buffer, position, and unchanged
text, the report describes the exact output queued, including the source and
resolved resources. It does not reinterpret old output with your latest
settings. Without an exact record, the report is labelled as a simulation of
what the current rules would produce at point.

A simulation uses captured text and context. /Play simulation/ plays that
baseline, not a recording of earlier sound. It supports field review and draft
previews but is never added to Recent Feedback. A prefix argument with ~C-e E~
selects a simulated occasion explicitly. ~q~ returns to the source, menu, or
Home row from which the report was opened.

Expand a field and choose /Edit named voice bolden/, or its reported voice
name, to open the voice editor. Multiple named voices receive separate links.
This edits the entry in the reported palette and affects its uses there.
/Change field/ instead changes the field's feedback rule. Leaving the voice
editor returns to the same link; opening it does not save or apply anything.

*** Inspect recent feedback
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Press ~C-e H f h~ for recent feedback. Aural Home's /Recent feedback/ action
and ~H~ remain alternative entries. Each row preserves one recorded
presentation within the history's size limit. Its Content column reads the
preview with captured voice annotations, including changes within the entry;
other columns and titles use the normal interface voice. ~P~ requests replay
with the engine and physical voice recorded for the original delivery.

#+attr_texinfo: :indic kbd :compact t
- RET or e :: Open Feedback Details for the selected presentation.
- P :: Replay retained feedback with recorded voices without adding history.
- c :: Audition only its auditory cues.
- r :: Prepare a voice remap from the selected record.
- R :: Replace, suppress, or restore one exact earcon.
- L :: Change the bounded history limit for this session.
- i :: Include or exclude feedback from Aural interfaces themselves.

Aural interface feedback is excluded by default so it does not displace the
feedback being investigated. This includes their prompts, completion choices,
and opening/closing sounds. Ordinary completion elsewhere remains eligible.
Changing the setting affects new recordings, not entries already retained.

*** Read and edit the report's fields
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Feedback Details selects a separate read-only buffer and gives a brief
introduction. It stays attached to its presentation as new feedback arrives;
ordinary Help does not replace it. When opened from Recent Feedback, ~q~
returns to the same row and column.

Where integrations supply semantic fields, the report groups consecutive voice
spans accordingly. Notmuch results, for example, expose /Authors/, /Subject/,
/Date/, /Message count/, and /Tags/. Headings identify recorded logical voices.
Collapsed fields show only headings. Visibility uses configured cues or optional
spoken labels; /expanded/ and /collapsed/ are not inserted into heading text.

~RET~ on a heading exposes its text, playback/change controls, voice source,
sounds, and limitations. Content uses captured voice annotations. Fields with
multiple spans offer /Individual voice spans/ for finer inspection. That heading
announces the section without repeating content. A single-span field shows its
text and controls once and omits a span count. ~RET~ collapses the field again.

Spoken labels such as /indent 2/ have separate /Before speech/ or /After speech/
headings, distinct from content spans. ~RET~ on a label heading, or ~O~ within
it, replays that label using recorded settings. /Edit named voice indent/ opens
the palette voice editor with /indent 2/ as sample text; it changes every use of
that entry in the recorded palette. The report's recording stays frozen: use
the editor's preview for changes. Labels without a named palette voice remain
playable and explain why an editor link is unavailable.

Fields with unapplied drafts announce /unsaved change/. The report also counts
such fields. These indicators update without replacing buttons or return
positions; ~g~ refreshes draft status, for example after killing a draft buffer.
It does not change the recorded or simulated baseline.

The original report layout uses these controls. Outline changes heading and
button navigation as described in the next subsection, not playback semantics.

#+attr_texinfo: :indic kbd :compact t
- n or p :: Move between headings; collapsed fields speak the heading, expanded fields also speak annotated content.
- Up or Down :: Review lines without reading the whole report.
- TAB or Shift-TAB :: Move between action buttons; RET activates or expands.
- O :: Play the original field, span, or label at point, or its labelled simulation.
- P :: Play the full original presentation or labelled simulation.
- C :: Open or resume a field/span change; on a label, edit its named voice.
- r :: Choose a named voice for matching items; on a label, edit its named voice.
- R :: Replace, suppress, or restore an exact sound in the field or span.
- V :: Preview the full presentation with linked draft changes.
- S :: Stop playback.
- g :: Refresh draft status.

For example, select /Subject/, press ~C~, and choose another content voice.
In the editor, ~O~ plays the original field and ~P~ the changed field.
/Play whole original/, also on ~B~, compares with ~V~ for the full presentation
and linked drafts. Both keep you in the editor. The original remains frozen,
including before a change or lifetime is chosen. A simulated report uses
/Play whole simulation/ for its frozen baseline.

Return to the report and choose /Message count/ to add a sound /After content/.
It plays once after the complete count, even if the field contains several
voices. Subject and count keep separate drafts. Their criteria identify field,
integration, mode, and occasion; inspect them before selecting buffer, session,
or saved-personal lifetime. Remapping the field does not retune a shared voice.

/Choose another voice for matching items/ opens the compact voice editor.
Inspect /Applies to/ and choose /How long/ before saving. /Change field/ opens
the full component editor on the same draft. A draft already changing another
component stays in the full editor so that work is not hidden.

/Sound overrides: replace, suppress, or restore/ prepares a separate exact-sound
rule draft restricted to the field. It is not included in linked-field previews.
/Restore inherited behavior/ removes an override made by that workflow in the
selected scope. ~q~ returns to the report.

*** Use the Outline report from the menu
:PROPERTIES:
:TEXINFO_NODE: no
:END:

~C-e H x~ opens the experimental Outline version of Feedback Details. It is
read-only, with a visible summary and initially folded fields. ~TAB~ on a
heading cycles visibility, ~S-TAB~ cycles the whole report, and ~n~/~p~ moves
between visible headings. Standard Outline minor-mode commands are available
under ~C-c @~, including ~C-c @ C-u~ for the parent. Arrows read visible lines.
~RET~ folds a heading or activates an action. Away from a heading, ~TAB~ and
~M-n~ move to the next visible action. Playback and editing use the report
commands above.

~o~ compares Outline with the original layout. Refreshing draft status with
~g~ preserves folds and position; returning from an editor preserves its
button. The report still describes the captured feedback. Reports opened
directly start in the original layout; ~o~ switches their style.

*** Understand playback evidence and limitations
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Original replay uses the recorded engine and physical voice, including
notification voices and fallbacks, with captured tuning even after a palette
change. It synthesises speech again at the current reading speed and host
pronunciation settings. History stores no audio. Cue and pause order remains,
but timing may differ from the first delivery.

Replay requires a completed presentation with complete Omnivox voice receipts.
Older, interrupted, truncated, or unsupported records remain inspectable but
report replay unavailable rather than guessing a voice. Cues positioned inside
speech, or voice changes that cannot be aligned after host text processing,
also prevent original replay. An unavailable recorded voice stops playback
instead of substituting another. Navigate over the source to capture a new
example.

A simulated report labels its baseline throughout the report and change editor.
Proposed playback uses current rules, captured buffer context, and linked drafts
without applying them. A span can be targeted only when its semantic field,
distinct named face, or explicit voice annotation identifies it. Truncated
history cannot supply complete playback or a comparable preview. Records
missing preview inputs remain readable; capture a new example before previewing.

Each field explains the sources of its voices and sounds, such as a face or
personal override, using the contributors actually captured. Unsupported voice
families and other limitations appear beside the affected field.

/Debug details/ opens a separate read-only raw snapshot of facts, rule IDs,
resolved voices, and backend diagnostics. Opening speaks only a short
announcement. ~q~ returns to the same report location with fields and drafts
retained.

~C-e H r t~ toggles /Explain feedback as you navigate/ for this session. It adds
concise semantic explanations after normal presentations, useful for learning
an integration's vocabulary. It is deliberately more verbose than normal use;
turn it off when no longer needed. Home retains the same training action.

*** Walkthrough: Change Headings In One Buffer
:PROPERTIES:
:TEXINFO_NODE_NAME: Heading Voice Walkthrough
:ALT_TITLE: Walkthrough: Change Headings In One Buffer
:DESCRIPTION: Try a heading voice, verify the scope, and undo the rule.
:END:

This experiment changes headings in a temporary Org buffer without altering
palette definitions or saved personal rules.

1. Use ~C-x b~ to create a buffer named =*aural-practice*=. Run ~M-x org-mode~
   and insert:

   #+begin_example
   * Reading notes
   An ordinary paragraph.
   * Next steps
   Another ordinary paragraph.
   #+end_example

2. Move onto the first heading and press ~C-e E~. Identify its named voice
   and heading facts, noting whether the report describes recorded output or
   a simulation. Press ~q~ to return to the source before opening a new menu.

3. Press ~C-e H f c~ for the guided change. Press ~c~, select /Content voice/,
   and choose =annotate= with ~RET~, or =bolden= if =annotate= is already used.
   ~O~ plays the original and ~P~ previews the proposed voice. Only the draft
   has changed.

4. Press ~m~ for /What should match/. Keep the Org module, heading role, and
   heading level if shown. Leave other criteria as shown for this experiment.

** Choose And Manage Voice Palettes
:PROPERTIES:
:TEXINFO_NODE_NAME: Voices And Routing
:ALT_TITLE: Choose And Manage Voice Palettes
:DESCRIPTION: Understand named voices, standard inheritance, and personal palettes.
:END:

#+cindex: voice palettes
#+cindex: acss-default
#+cindex: palette inheritance
#+cindex: voice aliases

A /named voice/, also called a /logical voice/ in detailed views, gives a
reusable name such as =bolden= or =annotate= to a way of speaking. A /voice
palette/ contains these entries. Each includes shared adjustments, ordered
physical choices, and adjustments for individual choices.

A /physical voice/ comes from an installed speech engine. The palette expresses
intended choices; availability and shared engine preferences determine which
can be used. A presentation rule determines when to use a named voice. Editing
that entry changes every use resolving to it; changing a rule changes which
items select it.

This section manages the collection. [[info:emacsvox#Editing Named Voices][Edit a Named Voice]] covers its physical
choices and adjustments; [[info:emacsvox#Installed Voices And Engines][Installed Voices and Engines]] covers browsing and
engine preferences.

Open /Voice Palettes/ with ~C-e H v p~. ~RET~ on a palette browses its voices,
~P~ auditions its sequence, and ~a~ activates it. Built-in palettes remain
intact; editing can open an unsaved personal child in the common editor.

*Upgrading personal palettes.* This version accepts schema 3 only. Before
upgrading older personal palettes, back up palette/routing data and arrange a
reviewed conversion of entries and physical choices. Opening or previewing does
not convert them. Preserve names and profile references, with each personal
parent chain ending at =acss-default=. Shared per-voice routing, migration,
and preset screens have been removed; use the common editor for named-voice
choices and adjustments. Shared engine preference remains separate.

Opening the manager announces its selected palette; entering a palette
announces its name, voice count, selected voice, and main keys. /Kind/
distinguishes personal, built-in, and standard-default palettes. /Parent/
names the inherited source. Read-only =acss-default= is the root: chains such
as =a -> b -> c -> acss-default= are supported. It provides personalities from
Emacsvox and loaded integrations, not a fixed list of all custom names. Only
the root has no parent.

Inheritance selects the nearest complete entry: style, ordered physical choices,
and individual tuning stay together, not combined from several parents.
/Source/ identifies the supplying palette. ~O~ opens it; ~u~ shows Where Used,
including known loaded references, aliases, and affected descendants. It cannot
inspect unloaded configuration. Editing a shared entry asks you to review
known affected uses and descendants.

An /alias/, such as =voice-bolden= for =bolden=, is a declared alternative
spelling of the same entry. Integrations maintain aliases; the manager does
not edit them as separate voices. Use Copy Voice for an independently
adjustable entry.

~N~ in a voice list creates New Voice and ~c~ copies one into an unsaved
editor draft. Copy preserves the full effective entry, fallback order, and
individual tuning. Editing or copying a built-in voice requests a personal
child palette; saving adds only the requested direct entry. Opening or previewing
writes nothing.

~R~ resets a personal definition to its inherited entry. Confirmation names
the source that will take over and rejects a source changed during confirmation.
Other saved settings remain. ~d~ deletes a direct custom voice with no inherited
replacement; built-in and inherited entries cannot be deleted. Remap known
references first if deletion would leave them unresolved. Finish or discard
voice drafts before deletion. ~o~ returns to the palette manager.

New Palette, ~N~ in the manager, creates a child of the chosen parent. Copy
Palette, ~c~, saves all effective entries independently under =acss-default=;
local physical choices belong to the new palette. The summary and parent action
~E~ inspect or change a personal parent; inheritance cycles are rejected.

To delete a personal palette, select it and press ~d~. Change children and
known references, including saved profiles, and finish/discard its voice drafts
first. Deleting an active palette returns to the standard baseline.

Activation with ~a~ lasts for this session. ~f~ follows the standard baseline
again, clearing explicit session selection without deleting data or changing
startup. /Use at Startup/, ~U~, changes the palette in the selected saved
Presentation Profile while preserving its other fields. It does not apply the
profile now. With no startup profile, review a new one captured from the current
setup. This checks saved rules and profile options, not session/buffer rules.
An open Profiles view refreshes to show the saved choice.

*** Understand Voice Adjustments
:PROPERTIES:
:TEXINFO_NODE_NAME: Voice Adjustments
:ALT_TITLE: Understand Voice Adjustments
:DESCRIPTION: Understand the voice controls and their defaults.
:END:

Change one field at a time and compare with ~B~. Portable controls are not
measurements in Hertz or decibels, and equal values may sound different on
different engines. Most numeric fields use integer levels zero through nine;
Relative Rate is the exception.

- /Relative Rate/ ranges from -20 to 20. Negative requests slower speech,
  positive faster, and zero leaves base rate unchanged. Engine-relative steps
  are not words per minute. A stronger contextual value replaces rather than
  adds to this one.
- /Average Pitch/ requests lower or higher overall pitch. Start with a small
  contrast between voices for related content.
- /Pitch Range/ requests less or more pitch variation; supported low settings
  can sound monotone and higher settings more varied.
- /Stress/ requests emphasis according to the engine's implementation.
- /Richness/ changes tonal character or fullness where supported. Compare
  samples rather than treating it as volume.
- /Gain/ changes output level: five is unchanged, lower reduces, higher raises.
- /Pan/ requests left at zero, centre at five, and right at nine where supported;
  output arrangement also matters.
- /Low-pass Amount/ and /High-pass Amount/ remove high and low frequencies,
  respectively. Zero is neutral and nine strongest.
- /Reverb/ adds reverberation, /Echo/ delayed repeats, and /Chorus/ a doubled
  voice. Zero disables each; higher values increase it.
- /Portable Fallback Family/, where offered, is a compatibility hint. Use
  /Physical voice/ for an installed choice. Family is outside complete Omnivox
  voice preview.

In shared settings, ~d~ or blank input requests /adapter default/ and ~u~ undoes
it. For a physical choice, ~i~ means /use the shared value/. Zero is explicit
in either context. The standard-default palette chooses the collection,
Automatic delegates physical selection, and adapter default delegates one
adjustment: they answer different questions.

Filter amount scales apply to arrows and numeric input in the common editor.
Zero is the neutral cutoff; blank requests adapter default. Existing saved
styles retain their sound and stored low-pass cutoff values keep their original
meaning.

Neutral values are named: gain five /unchanged/, pan five /centre/, and zero
reverb, echo, or chorus /disabled/. Chorus adds bounded doubled-voice modulation
without changing speech duration or marker positions. Omnivox applies it to
buffered audio and reports unsupported routes. Portable levels are translated
into adapter-specific values.

The standard palette includes =telephone=, combining high-pass and low-pass
filtering for a narrow-band sound on buffered Omnivox engines without replacing
the physical voice or changing duration/markers. Preview it in Voice Palettes
or Workbench before assignment. Adapters without post-synthesis filtering keep
the style but cannot apply those filters.

=omnivox-average-pitch-contrast= defaults to =0.5= for gentler distinctions.
=1.0= restores historical contrast and =0= neutralises average pitch; values
through =2.0= are accepted. Changing it refreshes logical-voice registration
for previews, structured speech, and legacy inline voices alike.

*** Choose And Tune Fallback Voices
:PROPERTIES:
:TEXINFO_NODE_NAME: Voice Fallbacks
:ALT_TITLE: Choose And Tune Fallback Voices
:DESCRIPTION: Order physical choices and customize their individual adjustments.
:END:

Shared settings provide a base for the whole voice. Physical choices are tried
in displayed order, subject to availability, engine policy, and synthesis
failure. An empty explicit list means /Automatic/, using shared engine policy.
Availability predicts a possibility; the last sample's result identifies what
played.

Palette inheritance supplies a whole entry. Within it, individual choices
inherit each shared adjustment independently. For shared pitch six, choice
pitch four, and a matching contextual pitch seven, the request is seven.
Without that rule it is four; /Use shared value/ makes it six.

Expand /Fallbacks/ to distinguish rows using shared settings from customised
ones. A row's menu auditions or compares it; comparison follows the same row
after reordering, even where two rows use the same physical voice. A newly
added row has no original yet: audition it or compare the whole voice. Replacing
a customised physical choice asks whether to keep tuning or return to shared.

/Customize this voice/ opens individual tuning. Each field distinguishes shared,
custom, and explicit adapter default. ~RET~ offers all three, left/right sets
numbers, ~d~ requests adapter default, and ~i~ inherits. Zero remains explicit.
Later shared changes affect inherited fields only. /More adjustments and effects/
reveals additional controls. Automatic samples name the value/state and audition
that row; /Play whole fallback chain/ tests normal selection. /Return to shared
settings/ leaves individual tuning within the same draft and Save operation.
Removing a row disables its controls until undo or return to shared settings.

With per-choice support, complete previews retain the chain and each row's
tuning. /Last sample playback started on …/ identifies the engine/voice whose
audio started. Accepted audio or spoken /Original/ and /Edited/ labels do not
prove a start. Stop, text changes, draft changes, or context changes retire
pending previews; retained evidence is labelled /Earlier preview/. Saving and
application status are separate from playback evidence.

/Details and last playback evidence/ explains shared, row, and contextual
contributions to the confirmed sample. The context view offers /Where the last
sample's settings came from/. These explanations use captured settings despite
later edits, identify original versus edited, and distinguish inherited values,
defaults, zero, and unsupported requests. They describe requested settings,
not measured native parameters or sound.

Older servers provide shared-only previews. Customised complete previews need
per-choice support; individual auditions are available only if tuning can be
represented faithfully, including defaults. Saving remains possible when a
preview is unsupported.

**** Work with engine-specific parameters
:PROPERTIES:
:TEXINFO_NODE: no
:END:

/Engine-specific settings/ opens parameters described by the selected worker
within the same voice draft. A worker that can describe but not apply them
shows them read-only. Engine-wide and startup controls also remain read-only
here, with scope identified by Help.

Actions precede expandable parameter groups with value, source, and range.
~RET~ offers /Set value/, /Follow common settings/, /Engine voice default/,
and /Parameter help/. Units and limits belong to the engine. Help explains
default source, relevant common controls, and reported side effects. ~?~ opens
and reads parameter Help; ~q~ returns to the row. Left/right steps a set numeric
value within limits. For inherited or unknown defaults, first choose a value
with ~RET~; the editor does not guess current native state.

~i~ removes an override, ~d~ requests engine voice default, and /Reset
engine-specific settings/ removes native overrides without altering common
adjustments or other choices. ~u~ undoes these edits.

Automatic samples name the parameter/value and share the common editor's
/Automatic sample after adjustment/ preference. Opening, searching, refreshing,
and Help do not audition. ~P~ previews, ~B~ compares, and the normal Save keeps
the draft. ~q~ returns to common settings. /Search controls/ searches names,
identifiers, and Help across folded groups; empty input clears the filter.
/Adjusted controls only/ shows overrides. ~g~ refreshes without restarting;
a busy engine is retried quietly for up to five seconds. Leaving cancels retry.
If still busy, finish speech and retry ~g~. Unrecognised saved fields stay
visible for explicit removal.

/Explain planned settings/ describes the captured draft without speech playback.
Where supported, last-playback details also explain applied sample settings.
Planned, applied, and engine-read-back values are labelled separately. An expired
sample plan cannot be reconstructed by these queries.

*** Inspect Or Adjust A Voice In Context
:PROPERTIES:
:TEXINFO_NODE_NAME: Voices In Context
:ALT_TITLE: Inspect Or Adjust A Voice In Context
:DESCRIPTION: Learn the controls and scope of this task.
:END:

In the voice editor, choose /Effective sound / Where settings came from/.
It uses the attached source item captured through the entry route or voice list.
If none is attached, choose an ordinary buffer at its current point. The item
must provide inspectable facts or valid retained feedback. /Choose another
source context/ deliberately selects a replacement.

This simulates captured facts and rules, showing the selected voice, matching
rules, requested fields, and their sources. One rule can set pitch and another
richness. A stronger pitch rule can mask a base edit; a rule choosing a different
named voice can make the open entry irrelevant. Competing relative rates also
replace, not add.

~P~ previews the edited voice in context and ~B~ compares original/edited with
the same facts, rules, and text. These voice-only previews omit cues and spatial
placement. Family remains a portable fallback outside full preview. Per-choice
support applies the actual fallback's tuning before context, and an explicit
context value overrides even when numerically equal to shared tuning. Requested
values remain distinct from confirmed starts, accepted audio, and unsupported
adjustments. Changed/deleted sources are rejected. After saving a rule, refresh
facts and rules from the source to capture its contribution. ~q~ returns to
the base editor.

/Adjust for this context/ presents matching criteria and personal, session, or
buffer lifetime. Choose one adjustment and value to prepare the ordinary rule
editor. A richness-only change does not select a different voice. Review criteria
with ~RET~, use ~V~ for another voice field, and save the chosen scope with
~w~. The palette is unchanged. Finish existing rule-editor work before preparing
another contextual rule.

/Inherit/ removes a field so weaker contributions can supply it; removing the
last voice field removes the patch. Existing explicit defaults are shown and
preserved when another field is edited. Zero is not inheritance. Some older
default forms cannot reset underlying tuning on every backend; inspect preview
and explanation. Context changes are saved as rules, not as a palette entry
containing the combined result. The
[[info:emacsvox#Integration Maintenance][Developer Guide]] describes representation and compatibility.

** Name Occasional Emoji In Speech
:PROPERTIES:
:TEXINFO_NODE_NAME: Emoji Speech Names
:ALT_TITLE: Name Occasional Emoji In Speech
:DESCRIPTION: Keep occasional decoration from forcing a different speech engine.
:END:

An emoji can require fallback from a voice such as Eloquence. Naming transforms
speech text before engine selection: =Forecast 🔮= becomes =Forecast crystal
ball=, while source text stays intact. This can keep the preferred voice when
the remaining text is compatible; normal repertoire checks still decide.

Naming is enabled by default. Use ~M-x customize-group RET emacsvox-emoji RET~.
Disable =emacsvox-emoji-naming-enabled= globally or only in a source buffer:

#+begin_src emacs-lisp
(setq-local emacsvox-emoji-naming-enabled nil)
#+end_src

For Org buffers in your configuration:

#+begin_src emacs-lisp
(add-hook 'org-mode-hook
          (lambda () (setq-local emacsvox-emoji-naming-enabled nil)))
#+end_src

All four options support buffer-local values, which override global defaults.
Aural previews use the remembered source policy, and contextual previews its
captured policy. Changes during playback do not change an already submitted
sample.

=emacsvox-emoji-approved-sequences= defaults to =t= for every exact name in
Emacs's emoji table, including seedling =🌱=, flags, keycaps, and joined emoji.
You need not approve each separately; an explicit list restricts eligible
complete sequences. Unknown joined sequences remain intact even if a component
is named.

Arrows and harpoons also receive names in all directions, including diagonal,
double, and curved forms. =← ↑ → ↓= becomes /left arrow up arrow right arrow
down arrow/. Symbols such as =⇒= and =⟶= outside the emoji table use Unicode
names. Text/emoji selectors are supported; unknown joined or accented sequences
remain unchanged. Box-drawing characters use Unicode names too: =│= becomes
/box drawings light vertical/. Light, heavy, double, rounded, dashed, and
junction forms follow the same naming settings and limits; custom names can
shorten frequent ones. Foreign-language letters and unrelated symbols retain
normal fallback, and exact character inspection is unchanged.

=emacsvox-emoji-maximum-count= defaults to 64 occurrences, counting repetition.
=🤔Dinner? 🍕🍕🍕= becomes /thinking face Dinner? pizza pizza pizza/ without
fallback caused by those four emoji. Above the limit, naming is skipped for
the whole item. One captured presentation can contain several voice runs;
a standalone preview is one item. Transport chunk sizes do not change this
limit. Sequences crossing style or positioned-cue boundaries remain unchanged.

Names come from Emacs's bundled emoji/Unicode data and may vary with its version.
Arrows prefer emoji names where available; the four plain arrows share their
emoji equivalents' names. Missing data leaves the sequence to normal fallback;
nothing is downloaded. Names are English and apply even to engines capable of
speaking the original.

Explicit pronunciation entries take precedence. For eligible sequences,
=emacsvox-emoji-custom-names= overrides a bundled name:

#+begin_src emacs-lisp
(setq-local emacsvox-emoji-custom-names '(("🔮" . "prediction")))
#+end_src

Custom names must contain 1–80 characters with no control characters. Empty
names are invalid; use explicit pronunciation to omit content. Restriction and
custom-name lists allow at most 64 entries, with sequences up to 32 characters;
full-table mode has no entry limit. The occurrence limit accepts 0–64.
Invalid settings skip automatic naming with an explanation rather than stop
speech.

Feedback Details (~C-e E~) shows original sequences and names or reasons for
skipping. Voice-editor playback details report sample substitutions. These are
prepared-text evidence, not confirmation of what you heard. /Play original/
retains captured speech text after settings change. Rule proposals change
presentation while retaining that text; capture new source feedback to try
another naming policy.

*** Find and filter installed voices
:PROPERTIES:

A language with one voice shows it directly; several voices form an expandable

*** Distinguish installation, enablement, and active speech
:PROPERTIES:
:TEXINFO_NODE: no
:END:

/Installed/ identifies library membership or engine-supplied voices. /Enabled/
is the desired choice for the next Apply. /Active/ is eligibility on main,
notification, or both streams, not memory residency. Missing/inconsistent worker
evidence appears as /Unknown/. Library data loads asynchronously.

~+~ enables/disables a managed voice, ~a~ reviews Apply, and ~d~ opens downloads.
Downloads start disabled; enable and Apply before auditioning. Engine-managed
voices retain their own selection mechanism. Other adapters retain their
physical-inventory view.

To remove a downloaded Piper, Flite, or MBROLA package, disable its voices,
Apply, then press ~C-c u~ on one voice. Review all speakers sharing it, size,
known palette references, and retained-file reasons. Confirmation removes only
reviewed managed files. Built-in voices, imports, and runtimes remain, as do
saved palette choices for a later redownload. The backend guide describes
supported managed-engine download and removal boundaries in more detail.

Another session may still need the package; files remain until retirement is
confirmed, and older session records may need inspection. Results distinguish
removed bytes, remaining files, and unconfirmed amounts. ~C-c U~ or
=omnivox-library-resume-uninstall= reviews interrupted cleanup on hosts supporting
uninstallation.

Engine /Availability/ precedes policy. A missing runtime remains visible as
unavailable with /Last failure/. /Routing policy: allowed/ permits selection
but does not prove installation. Disablement, health, and temporary failures
remain separate.

*** Experiment With An Installed Voice
:PROPERTIES:
:TEXINFO_NODE_NAME: Physical Voice Experiments
:ALT_TITLE: Experiment With An Installed Voice
:DESCRIPTION: Try physical voices without saving, then keep a useful experiment.
:END:

~t~ on a physical voice opens an experiment with that exact engine/voice,
adapter-default characteristics, current base rate, and neutral audio effects.
Opening, adjusting, and comparing save nothing. Controls match
[[info:emacsvox#Editing Named Voices][Edit a Named Voice]], but ~w~ must first choose a palette destination.

To compare pitch:

1. Open ~C-e H v b~, select an available engine, and press ~v~. Select a
   physical voice and press ~P~; ~B~ can compare with another available voice
   using the same sentence.
2. Press ~t~, set /Average Pitch/ to =3=, listen, then set =7= and listen
   again. An unsupported pitch control remains identified.
3. ~B~ compares the captured starting voice with the edited one, not the
   immediately previous change. ~u~ undoes; ~d~ restores adapter default.
4. Finish with ~q~ and discard, or keep the experiment using the next walkthrough.

~w~ chooses a destination palette and entry. The default keeps /Physical voice
and adjustments — this choice/. Alternatives keep only the physical voice,
only one row's adjustments, or shared settings for inheriting choices. Physical
voices can replace a row, become preferred, or append as fallback. A row-level
keep replaces that row's tuning with the experiment's values and defaults,
preventing unrelated destination shared tuning from changing the base sound.
Use ~i~ afterward for fields intended to inherit.

Other rows/shared settings survive a row-level keep. Replacing only the
physical voice asks whether to keep/reset its tuning. Shared adjustment keeps
affect inherited fields; custom rows override them. An existing destination
draft can accept the changes or resume untouched, retaining other work and
pending save recovery. The destination preview uses the proposed combination,
which can differ because of scope/fallback order. Choosing it has not saved.

*** Walkthrough: Keep An Installed Voice Experiment
:PROPERTIES:

:ALT_TITLE: Walkthrough: Keep An Installed Voice Experiment
:DESCRIPTION: Place an experiment in a named voice and verify the saved combination.

Create =reading-demo= as in [[info:emacsvox#Personal Palette Walkthrough][Make a Personal Reading Palette]], or use an
existing personal destination. Note the active palette first.

1. In the voice browser, open ~t~, adjust a field, and preview with ~P~/~B~.
   Press ~w~ to keep it.
2. Select the personal destination and named voice =bolden=. Choose /Physical
   voice and adjustments — this choice/, then /Add as preferred/. This places
   the experiment first while retaining alternatives.
3. The common editor opens an unsaved proposal. Expand /Fallbacks/: the new
   first choice is customised, preceding previous explicit choices. ~P~ plays
   the whole proposed voice; inspect its actual reported engine/voice because
   an unavailable preference may fall back.
4. ~w~ saves and applies. Wait for its result and follow
   [[info:emacsvox#Recovering Aural Changes][Recovering Unfinished Changes]] after partial saving or failed application.
   Success selects the destination for this session. Use ~U~ in Voice

5. Before saving, undo or discard to reverse. After saving, reopen the voice,
   expand fallbacks, choose /Remove/ in the added row's ~RET~ action menu,

Change one field, audition that row, then test /Play whole fallback chain/.

*** Change A Blank-Line Tone

blank line regardless of its presentation.

1. Navigate onto a blank line and open ~C-e H f h~. Select its record, press

2. Press ~c~, /Change a tone/, select the tone, and choose /Pitch and duration/.

*** Adjust Spatial Presentation
:PROPERTIES:

:ALT_TITLE: Adjust Spatial Presentation
:DESCRIPTION: Check stereo support, adjust placement, and restore centered output.
:END:

Open ~C-e H D s~ to inspect reported speech/cue capabilities, then return to
the menu. ~C-e H o n~ opens /Notifications and spatial output/. Enable
presentation, speech, and cues independently. Output follows capabilities or
can be declared mono. Separation ranges from zero (centred) to one (full);
direction can be normal, reversed, or centred for some/all requests.

These spatial controls apply immediately and are global. Shift-left/right
adjusts selected separation by 0.1; ~RET~ enters an exact value. ~SPC~ requests
left then right cue previews; mono or limited capabilities may centre them.
~x~ stops. ~S~ saves spatial and routing defaults without restarting speech,
separately from output-volume saving.

For a gentler layout, note the current settings, select maximum separation,
and enter =0.3=. Repeat feedback that requests spatial placement. Stereo
headphones help compare it. If everything stays centred, Explain the source
to check its placement request and inspect backend capability. A sample without
a placement request cannot demonstrate separation.

For comparison, select mono and repeat the action; content remains audible.
Restore the original values afterward. Save deliberately with ~S~ or capture
spatial choices in a Presentation Profile. Home's /Spatial settings/ remains
an alternative Customize page using its own Apply/Save actions. A voice's Pan
effect and notification-device routing are separate from presentation placement.

Reading/output settings control detail and delivery independently of the rule

*** Set the reading scope, rate, and punctuation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

~C-e H s~ opens Speech settings for the captured buffer. ~g~ switches to global
defaults; ~C-u C-e H~ starts there. Indentation shares this scope with its
parents, including changes made inside its own menu. Opening/closing alone
saves nothing.

Select /Rate/ and adjust with Shift-left/right by the configured step, or use
~RET~/~r~ for an exact value. Speech must be running; Omnivox uses 0–100.
Global rate changes also affect the current buffer. Home's rate action remains
an alternative, with a prefix for global scope. A named voice's relative rate
modifies this base as described in [[info:emacsvox#Voice Adjustments][Voice Adjustments]].

~p~ opens punctuation: ~n~ none, ~s~ some, ~a~ all, and ~p~ a choice of built-in
levels and available named profiles. In buffer scope, ~r~ restores automatic
mode policy. ~q~ returns to Speech settings.

~e~ opens the pronunciation editor. Its ~q~ returns to the same item, retaining
draft and selected character for reopening. Its ~s~ saves overrides on the
speech host; ~r~ explicitly restarts speech after confirmation. The punctuation
menu's ~S~ saves the selected level/profile through Customize, not that host
draft.

~S~ in Speech settings saves displayed rate and punctuation as startup defaults.
Rate uses the backend's startup option. Saving from buffer scope promotes those
displayed choices to defaults. Mode punctuation policy and explicit buffer
settings still override the saved punctuation default.

*** Adjust indentation feedback
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Open ~C-e H s i~ or directly ~C-e d I~. In global-default scope, ~S~ saves
indentation defaults and tone volume through Customize. Select /Volume/ and
adjust by five percentage points with Shift-left/right, or enter with ~RET~.
Plain left/right changes sections and ~SPC~ previews indentation. Other selected
items give guidance rather than treating every shifted arrow as volume.

~t~ opens pitch-tone settings: base pitch, rise per column, maximum pitch, and
requested duration. Shift-left/right adjusts; ~RET~ enters exactly. ~SPC~
previews four columns without changing presentation or enabling feedback.
~s~ stops. Short durations show the effective blank-line-tone minimum.
~R~ restores the four bundled values in scope. Global changes preserve local
overrides; ~S~ saves global defaults and tone volume. ~q~ retains live changes.

*** Set capitalisation feedback and its beeps
:PROPERTIES:

25 Hz/5 milliseconds with Shift-left/right, or use ~RET~. ~SPC~ previews only
the beep and ~s~ stops. Previewing neither changes reading settings nor enables

~r~ restores bundled values in the draft; save to remove this menu's override.
~D~ discards/rereads, ~q~ returns, and ~C-q~ closes menus while retaining drafts
for this session. Unrelated rules and labels survive, and stronger rules may
override the cue. Finish unsaved personal-rule editors before cue saving. If
saved rules changed elsewhere, discard the cue draft and reopen it.

*** Understand the main and notification streams
:PROPERTIES:
:TEXINFO_NODE: no
:END:

#+cindex: speech streams
#+cindex: notification stream
#+vindex: tts-notification-device

The /main stream/ presents current interaction such as movement, buffer entry,
and message opening. Navigation interrupts obsolete main speech. The
/notification stream/ presents asynchronous events without stopping main speech;
normal navigation does not stop a separate notification stream. Both can be
heard concurrently, with each notification's cue and speech delivered together.
Integrations may deliberately route particular asynchronous actions differently:
Notmuch's explicit refresh, for example, uses interruptible main speech.

Open ~C-e H o n~ for routing. ~r~ chooses automatic, left, right, both, main
output, or another device for the next restart. Selecting does not restart.
~N~ previews active output, which may still use the old route; ~R~ restarts
after confirmation. ~h~ inspects a notification-history snapshot, returning
with ~q~. ~S~ saves routing and spatial defaults without a restart.

With Omnivox, Automatic normally uses an independent notification process;
left/right/both choose its route. /Use main output (notifications remain
audible)/ uses the main process instead, where navigation can interrupt it.
It is not a mute option. Other backends use their configured device or fall
back to main speech. In Lisp, =default= or an empty string means main output;
use descriptive labels for ordinary configuration.

Home's /Audio output/ remains a Customize alternative. After changing its route,
~C-e d C-n~ initialises the arrangement; Customize Save retains it for restart.
Home also offers notification history. Ordinary obsolete-main-speech cancellation
is local to main; explicit =tts-stop= stops both streams.

*** Adjust output volumes
:PROPERTIES:
:TEXINFO_NODE: no
:END:

~C-e H o~ provides five global Omnivox volumes: main tones and earcons, and
notification speech, tones, and earcons. Each is an integer percentage 0–100;
100 is normal, zero silences that component. For example, notification speech
35 and earcons 70 emphasise brief cues over messages.

Shift-left/right adjusts the selected volume by five; ~RET~ enters exactly.
Changes apply to subsequent audio without restarting; already prepared audio
keeps its old level. ~S~ saves these five volumes, not routing or spatial
settings. Home's Audio output Customize page offers the same controls.
Replacement and reconnected Omnivox processes receive current levels.

Independent notification levels need the separate process selected by Automatic,
Left, Right, or Both channels. Main-output routing/fallback shares main-process
levels. Earcon volume applies to Omnivox-played sounds, not external players or
other speech backends. Zero volume does not disable notification recording.

*** Adjust an integration's speech settings
:PROPERTIES:

<<Integration speech settings>>

~C-e S~ opens focused settings directly where available. Alternatively use
~C-e H j~ or ~C-e H . j~. In that integration menu, ~s~ invokes a local Agent
Shell speech-level chooser or EAT/comint autospeak control, ~c~ opens the
source integration's settings, and ~a~ chooses among Shell/comint and installed

Scope and persistence belong to each integration. The summaries below explain
the differences; application chapters contain their detailed workflows.

**** Shell/comint and EAT
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Shell/comint's focused menu toggles automatic speech with ~s~ and background
monitoring with ~b~. Background reading needs autospeak enabled. Both values
belong to the captured buffer for its lifetime; there is no Save action. Arrows
announce values and ~RET~ activates. ~q~ returns to the entry, or closes a
direct focused menu. Search at ~C-e H /~ finds =comint= and =monitoring=.
Choosing Shell/comint from another buffer explains the required context and
leaves its controls unavailable.

EAT's ~s~ toggles foreground speech, ~b~ content-free background cues/counts,
~p~ prompt feedback, and ~d~ automatic detail. Background monitoring is
independent of foreground autospeak and never reads background content.
Changes are local to the terminal, including from frozen review. ~w~ saves all
four displayed defaults; terminals with overrides keep them. ~A~ opens advanced
Customize and ~q~ returns. All controls are searchable. Choice lists start on
the current value; arrows browse, ~RET~ applies, and ~q~ cancels. See
[[info:emacsvox#EAT Terminal Access][EAT Terminal Access]] for prompt integration and safety boundaries.

**** Agent Shell, Org, and EWW
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Agent Shell's menu covers temporary session speech, global feedback defaults,
and reading limits. ~w~ saves displayed globals, excluding the session override.
See [[info:emacsvox#Agent Shell][Agent Shell]].

Org's ~c~ chooses cell, header, or combined table-editing feedback and ~w~ saves
that global default. Column headers come from the first row, row headers from
the first column, and local overrides take precedence. ~t~ opens Org table
options and ~A~ advanced Emacsvox Org settings in Customize, returning with
~q~. This editing feedback is separate from the shared table reader described
in [[*Browsing Structure][Browsing Structure]].

EWW's ~s~ controls section-navigation autospeak and ~i~ suppresses images on
subsequent rendering. It also updates the shared SHR image default while
preserving local overrides; it does not reload the page. ~w~ saves the two
Emacsvox defaults and ~A~ opens advanced settings.

**** Notmuch and shared choice-list navigation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Notmuch has the same focused menu in Hello, Search, Show, and Tree. ~c~ chooses
adaptive, count-only, cue-only, or silent successful completion; failures remain
audible. ~f~/~b~ set field character/UTF-8 byte limits and ~t~/~B~ total limits.
Shift-left/right steps by 100, ~RET~ accepts a positive integer or =none= for
that limit only. ~w~ saves those four limits and completion policy: five
values, not every mail setting.

Org and Notmuch choice lists start on the current global value. Arrows browse
without applying, ~RET~ applies/returns, and ~q~ cancels. ~?~ plus a choice key
explains effect/scope; ~q~ returns to that browsed choice.

Notmuch's ~s~/~m~ open ordered search/message fields and ~i~/~I~ their status
maps. These Customize editors preserve custom formatters and use their own
Apply/Save/Reset. ~p~ opens Presentation Options: enabled
=mail-message-status-cues= owns standard cues, while maps still suppress spoken
status tags. ~A~ exposes advanced options such as separators. ~q~ returns;
opening or returning does not save. [[info:emacsvox#Notmuch Mail][Notmuch Mail]] explains privacy and full
inspection. Integrations without focused entries remain accessible through
major-mode settings and advanced Customize.

** Save, Switch, And Share Your Setup
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Profiles
:ALT_TITLE: Presentation Profiles
:DESCRIPTION: Save selected settings and distinguish profiles from resource backups.
:END:

#+cindex: presentation profiles

A Presentation Profile records enabled options and their order, sound pack,
voice palette, and portable spatial settings. It switches a coordinated setup
for focused work, leisure reading, or different audio environments. It is not
an Emacs startup configuration profile or a backup of every setting.

~C-e H p p~ opens profiles. The parent ~C-e H p~ also links palettes and
unfinished drafts; each editor retains its own Save/Apply actions. Palette
~w~ exports portable voices, ~W~ backs up full local choices, and ~i~ imports
an independent palette without activation. See
[[info:emacsvox#Sharing Voice Palettes][Export, Back Up, and Import Palettes]].

1. Configure the live options, sound pack, voice palette, and spatial choices.
2. Open ~C-e H p p~ and inspect the fields to be captured.
3. ~N~ saves the live selection as a new named profile.
4. Later, ~a~ applies the selected profile's saved values.
5. To update it from deliberately changed live settings, use ~w~. To discard
   live differences instead, apply with ~a~ and review confirmation.

Only one profile identity is selected. /Active/ means its saved values match
live configuration. /Diverged/ means it is still selected but values differ;
this is not an unsaved-editor warning. Applying a profile also saves its
selection for future sessions, unlike session-only palette activation.

Profiles reference palettes and sound packs by name, not private copies.
Editing a shared palette affects every profile using it. Profiles exclude
engine policy, speech rate, notification output, rules themselves, buffer-local
Voice Lock, and current-buffer rules. Those remain in their owning settings
or rule stores.

*** Walkthrough: Switch Reading And Working Setups
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Profile Walkthrough
:ALT_TITLE: Walkthrough: Switch Reading And Working Setups
:DESCRIPTION: Save two selections, switch between them, and understand shared resources.
:END:

Use unused names and note the selected profile first.

1. Open ~C-e H p p~. For a restore point, ~N~ saves =before-demo= with a short
   purpose and selects it. This captures resource/option choices, not rule,
   resource-definition, or engine backups.
2. Use ~C-e H v p~ and ~C-e H o p~ to activate your reading palette and sound
   pack. Choose Presentation Options at ~C-e H r f~ and spatial settings at
   ~C-e H o n~. Return through each view's own navigation before opening the
   next. In profiles, save =reading-setup-demo= with ~N~.
3. Choose a different palette or pack and save =working-setup-demo=. ~RET~
   describes each profile's saved fields.
4. Apply the reading profile with ~a~ and repeat familiar feedback. Inspect
   active resources in their managers, then apply the working profile to
   compare.
5. Change a live option without updating the profile. /Diverged/ indicates the
   difference. ~a~ restores saved values and ~w~ replaces them with current
   choices; read confirmation before discarding either intention.
6. Finish on the profile wanted at startup, because applying saves its
   selection too. Restore the original or =before-demo= when finished.
   Delete unwanted demo profiles with ~d~ only after selecting the retained one.

If both profiles use =reading-demo=, edits to that palette affect both. For
independent voices, Copy Palette and select different resources. A profile's
Copy action copies selections only. To change startup palette while preserving
other profile fields, use ~U~ in Voice Palettes rather than recapturing everything.

*** Choose What Persists
:PROPERTIES:
:TEXINFO_NODE_NAME: Saving And Startup
:ALT_TITLE: Choose What Persists
:DESCRIPTION: Distinguish previews, drafts, saved resources, activation, and startup.
:END:

#+cindex: saving aural settings
#+cindex: startup palette

Scope, persistence, and activation answer different questions. A /current-buffer/
value applies to the captured buffer. A /global default/ is a live default that
may still be overridden locally or by mode policy. /Saved startup settings/
are retained for later sessions. Changing a global value does not automatically
save it; the command's documented action determines whether it also updates
existing buffers.

Saving records data. Applying makes the relevant live configuration use it,
and some host changes require a separate confirmed speech restart. A save result
is not proof that both workers acknowledged an application. Drafts, current
values, and saved values are intentionally displayed separately.

- /Preview/ plays an example without saving or selecting the draft.
- /Retain draft/ keeps unfinished edits in this Emacs session only.
- /Save to collection without selecting/ stores a voice for later use.
- /Save and apply/ stores it and selects its palette for this session.
- Palette or sound-pack /Activate/ selects that existing resource now.
- /Use at Startup/ in Voice Palettes changes the saved profile's palette,
  without applying that profile now.
- /Presentation Profiles/ store coordinated choices, not copies of resources.
  Applying one also saves its selection for future sessions.
- /Export/ and /Full backup/ create separate exchange or backup files with the
  limits described below.

Menu Save actions have deliberately limited scope. For example, Speech settings
saves displayed rate/punctuation, Sounds and output saves five volumes, and a
focused integration menu saves only its documented defaults. Linked editors
keep their own Save/Apply. No one menu action saves all Emacsvox settings.

Personal rules persist; session/buffer rules expire with their session/buffer.
Saving a profile does not make temporary rules or drafts permanent. A retained
draft also does not undo an earlier completed save when discarded.

*** Export, Back Up, And Import Palettes
:PROPERTIES:
:TEXINFO_NODE_NAME: Sharing Voice Palettes
:ALT_TITLE: Export, Back Up, And Import Palettes
:DESCRIPTION: Share portable voices or retain local choices in a backup.
:END:

~w~ in Voice Palettes exports effective portable entries, asking before omitting
machine-local choices. ~W~ backs up full ancestry and referenced local choices.
~i~ imports either as an independent personal palette under an unused name;
it neither replaces ancestry nor activates the result. Missing installed voices
are reported and retained for replacement. Partial import retains its proposal
for Retry or Discard.

For practice, export =reading-demo= with ~w~, review omitted choices, and import
as =reading-import-demo=. Enter and preview before activating. An unavailable
retained choice is a review request, not proof of audio. Delete the imported
copy when no profile, child, or rule needs it; the original is unchanged.

Use ~W~ when local choice data and ancestry matter. Import still creates a
new independent palette, not an overwrite. Neither export contains engines
or sound-pack audio, and neither is a backup of every Emacsvox setting.

** Troubleshooting And Recovery
:PROPERTIES:
:TEXINFO_NODE_NAME: Presentation Troubleshooting
:ALT_TITLE: Presentation Troubleshooting
:DESCRIPTION: Trace unexpected output and use safe diagnostics.
:END:

#+cindex: Aural Doctor

Choose the first diagnostic according to the symptom:

#+attr_texinfo: :columns 0.43 0.57
| Symptom | First action |
| The current object sounds wrong or verbose | Use C-e E to inspect matching rules. |
| Earlier feedback was wrong | Open C-e H f h and explain its record. |
| Broad optional behaviour is unwanted | Preview or disable its Presentation Option. |
| One narrow exception is unwanted | Inspect the appropriate rule at C-e H r o. |
| A named voice uses the wrong engine/voice | Check physical choices, then Workbench health. |
| A cue is missing or inappropriate | Validate the sound pack and inspect overrides. |
| A saved setup no longer appears active | Check the profile's Active or Diverged status. |
| Voice distinctions vanish in some buffers | Compare Voice Lock and explicit face presentation. |

~C-e H D d~ opens Aural Doctor; Home retains its entry. Doctor checks live
bindings, loaded source/byte-code, compatibility baseline, options, profiles,
personal data, resources, spatial fallback, and backend. It neither starts
speech nor changes settings automatically. A row offering a reviewed safe
repair can be acted on explicitly with ~r~.

From diagnostics, ~s~ reports spatial capabilities/policy and ~m~/~n~ retained
local main/notification output, reporting absent buffers where appropriate.
~q~ returns to the selected menu item. ~l~ toggles session logging, explicitly
including complete spoken text. ~A~ opens log-file, size, retention, and buffer-
visibility options in Customize. Apply/Save remain explicit; buffer naming
changes take effect after speech restart.

Worker rows show current capabilities and last inventory. Configuration
agreement refers to acknowledged startup identities, not proof that saved
files are in use. Missing/retired connections give unknown evidence. Processes
or available engines do not prove audible playback. The log row names paths
without opening files. ~y~ copies the report; review personal paths/configuration
before sharing. Speech text and log contents are not included in that copy.

Use ~?~ for an Aural interface's current keys. If no speech is available,
start with [[*Backend Diagnostics And Responsibilities][Backend Diagnostics And Responsibilities]]; presentation diagnostics
assume a working speech route.

For an apparently ineffective adjustment, check:

1. Is the edited palette active? Saving to the collection does not select it;
   retaining a draft does not save it.
2. Does the item use the named entry? Explain it with ~C-e E~.
3. Does individual fallback tuning mask the shared adjustment? Inspect the
   fallback and last sample result.
4. Does a contextual rule override it? Inspect /Effective sound / Where settings
   came from/.
5. Does the engine support it? Compare samples and reported unsupported fields.

Explicit physical choices outrank shared preferred-engine policy. Check them
before availability, disablement, or failure. A missing custom name is a
configuration error: ordinary speech keeps the text using an unstyled voice
and records a diagnostic; it does not invent a palette entry. Doctor and
Explain locate the unresolved reference.

*** Review changed settings before editing again
:PROPERTIES:
:TEXINFO_NODE: no
:END:

~C-e H d~ opens a read-only snapshot separating captured-buffer values,
global defaults, and saved startup values known to Customize. It includes
loaded Emacsvox/TTS/Omnivox options that are saved, local, or nonstandard.
Saved expressions appear as recorded. ~RET~ reads a whole row with scope,
~g~ refreshes, and ~q~ returns.

Editor/cue drafts appear separately. Voice, rule, and host-pronunciation stores
retain their own saving rules. The snapshot does not reread disk, query the
host, prove saved data active, or include unloaded integration options. Return
to the owning editor/menu to change, save, or apply a restart.

*** Recover Unfinished Changes
:PROPERTIES:
:TEXINFO_NODE_NAME: Recovering Aural Changes
:ALT_TITLE: Recover Unfinished Changes
:DESCRIPTION: Resume drafts and distinguish saved settings from confirmed application.
:END:

~C-e H p d~ currently opens Home on /Resume unfinished changes/. Press ~RET~
to choose the original editor with its source and working settings. Return
through Home to the same menu entry. This draft chooser still depends on Home;
editors with an ~h~ return also retain that route.

In the common editor, ~u~ undoes and ~q~ offers keep, discard, or continue.
Guided feedback ~q~ first goes up through components, then hides/retains the
draft at the top. To reverse an applied rule, use ~C-e H r o~ and disable or
delete it in the correct scope with ~t~/~d~.

Drafts last only until Emacs exits. Discard abandons unsaved edits, not completed
saves. The voice editor distinguishes stored settings from successful worker
application; use that distinction when deciding to retry or make another edit.

An apply waits for acknowledgements from each stream. After an Omnivox timeout,
Workbench reports /server outcome unconfirmed/, stops that transaction, and
sends no later steps. Requests already sent may still take effect. Timeout
neither undoes saved policy nor proves rejection. ~r~ reapplies saved engine
settings for a new result after newer staged edits are saved or cancelled.
Partial results retain acknowledged streams and identify timeouts.

** Voice Lock And Advanced Configuration
:PROPERTIES:

:DESCRIPTION: Understand the established face and personality voice adapter.

#+cindex: Voice Lock

Voice Lock is one compatibility input to Aural Presentation, not the entire
system. It maps Emacs faces and =personality= text properties to voices.
Faces are visual style labels that Emacsvox can use without requiring sight.

#+attr_texinfo: :columns 0.28 0.42 0.30
| Policy | What it controls | How to inspect or change it |
| Semantic presentation | Integration roles, events, states, and attributes | Explain, Presentation Options, and feedback rules |
| Explicit face presentation | Rules deliberately matching an Emacs face | emacsvox-aural-toggle-face-presentation or Aural Doctor |
| Voice Lock | Historical buffer face/personality mapping | C-e d v locally; C-e d C-v globally |

To identify Voice Lock's contribution:

1. Move across differently styled elements, such as a comment/string or Org
   heading/link.
2. Toggle ~C-e d v~ in that buffer and compare the same elements.
3. Explain with ~C-e E~ to inspect Voice Lock/face state and contributing rules.

Turning it off removes only that compatibility contribution. Semantic
presentation, explicit face rules, cues, tones, and spoken status remain.
The global command updates existing and new buffers; a mode can still opt out
on startup. Buffer-local Voice Lock is not captured in Presentation Profiles.

For new changes, prefer explanation, settings menus, palettes, and Workbench.
Home remains a compatibility entry to the same editors. Legacy named voices
can still use =-settings= options such as =voice-monotone-settings=. Customise
the option, not a generated =acss-...= symbol. Historical background is in
[[info:emacsvox-heritage#Audio Formatting And Aural CSS][Audio Formatting And Aural CSS]] in /Emacspeak Heritage/.

Named formatting voices such as =bolden= and =annotate= follow the active
palette. An inherited standard entry may be implemented by a personality's
settings option within the explicit root, not a hidden second fallback.
Explicit styles retain their own settings and rules can change the resulting
voice.

The [[info:emacsvox#Integration Maintenance][Developer Guide]] covers voice metadata, rule authoring, and integrations;
[[info:emacsvox#Speech Server Protocols][Speech Server Protocols]] covers delivery. The generated
[[info:emacsvox-reference#Emacsvox Commands And Options][Emacsvox Commands And Options]] records exact commands, options, and keymaps.
