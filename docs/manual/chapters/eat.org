* Speech Access To EAT
:PROPERTIES:
:TEXINFO_NODE_NAME: EAT Terminal Access
:ALT_TITLE: Speech access to EAT
:DESCRIPTION: Use EAT with terminal-aware speech.
:END:

#+cindex: EAT terminal emulator
#+cindex: terminal accessibility
#+cindex: speech access, terminal
#+findex: eat

EAT (Emulate A Terminal) is a third-party terminal emulator, commonly installed
from NonGNU ELPA. Run ~M-x eat~ to start it; a prefix argument creates or
selects another terminal. Follow the [[info:eat#Top][Eat User Manual]] for installation,
terminal setup, and EAT's complete command reference.

EAT emulates the terminal, while the shell, router or other running program
handles input and completion. Emacsvox speaks changes visible in the rendered
screen. It cannot inspect the program's internal state or generate its
completion candidates.

First choose an input mode appropriate to the program. Then use automatic
feedback for current work and explicit review for content you need to examine
again. ~C-e S~ opens focused EAT speech settings; those menu keys apply only
while the menu is open, not to ordinary terminal input.

** Input Modes And Completion Responsibilities
:PROPERTIES:
:TEXINFO_NODE_NAME: EAT Input Modes
:ALT_TITLE: Choose an input mode
:DESCRIPTION: Decide which keys reach Emacs and which reach the terminal program.
:END:

#+cindex: EAT input modes
#+cindex: completion, EAT
#+cindex: Corfu, EAT
#+findex: eat-semi-char-mode
#+findex: eat-char-mode
#+findex: eat-emacs-mode
#+findex: eat-line-mode
#+kindex: C-c C-j (EAT)
#+kindex: C-c M-d (EAT)
#+kindex: C-c C-e (EAT)
#+kindex: C-c C-l (EAT)

EAT has four input modes. Emacsvox announces the mode name when you switch.
The mode determines whether a key edits text in Emacs or reaches the terminal
program.

#+attr_texinfo: :indic asis :compact t
- Semi-character mode ::

  The default. Most keys, including ~TAB~, go to the terminal, while
  prefixes such as ~C-x~, ~C-c~, and ~M-x~ remain available. Use ~C-q~
  before a normally reserved key to send it through. ~C-c C-j~ selects
  this mode.
- Character mode ::

  Supported input keys go to the terminal, useful for programs needing
  Emacs-like keys. Emacsvox's review prefix remains available as described
  under [[info:emacsvox#EAT Screen Review][Review retained terminal output]]. Enter character mode with ~C-c M-d~
  and return to semi-character mode with ~C-M-m~ or ~M-RET~ before using
  ordinary Emacs command entry.
- Emacs mode ::

  Keys stay in Emacs and send no terminal input. Use it for ordinary buffer
  motion and inspection. Enter with ~C-c C-e~.
- Line mode ::

  Edit the pending line locally and send it with ~RET~. ~TAB~ invokes
  Emacs's =completion-at-point=, whose result may be displayed by a front
  end such as Corfu. Enter from semi-character or Emacs mode with ~C-c C-l~.
  Line mode is not available in EAT's embedded Eshell terminal.

Line mode does not create unlimited history. =eat-term-scrollback-size= still
limits retained text by /characters/, not lines; =nil= permits unlimited
retention. The editable draft follows the terminal extent, and changing input
modes does not change this limit.

In semi-character and character modes, ~TAB~ belongs to Bash Readline, a
remote shell, router CLI, or the running terminal program. Corfu is not involved.
In line mode, completion belongs to Emacs and does not query a remote CLI.
Semi-character mode is therefore usually appropriate for SSH and network-device
sessions. If an Emacs completion backend blocks in line mode, ~C-g~ cancels
that Emacs operation; switch to semi-character mode when terminal completion
was intended.

The shell must have its own completion configuration. For example, completing
=git pul= to =git pull= in Bash requires suitable programmable definitions,
often supplied by =bash-completion=. Emacsvox neither installs nor substitutes
for those definitions.

** Automatic Terminal Feedback
:PROPERTIES:
:TEXINFO_NODE_NAME: EAT Automatic Feedback
:ALT_TITLE: Understand automatic terminal feedback
:DESCRIPTION: Follow output, prompts, editing results, and application-screen changes.
:END:

#+cindex: EAT automatic speech
#+cindex: terminal output, speech policy
#+kindex: C-e C-q (EAT)
#+findex: emacsvox-eat-toggle-autospeak
#+vindex: emacsvox-eat-autospeak

~C-e C-q~ toggles automatic foreground feedback for this terminal; it starts
enabled. The same control is ~s~ in the focused settings menu. It covers
routine output, status, automatic metadata, application-screen boundaries,
and process lifecycle feedback. Explicit reading, input and completion
feedback, and the configured terminal bell remain available. Verbosity
(~C-e q v~) and background monitoring (~C-e q m~) are independent preferences.

Automatic speech requires the selected EAT buffer and Emacs keyboard focus.
The selected window must follow the live cursor or edit a line-mode draft
after terminal output. Reviewing scrollback prevents new output from
interrupting you. Another selected terminal or an active minibuffer also
suppresses foreground feedback. In terminal-only Emacs, or when keyboard
focus cannot be reported, selection within Emacs is the available boundary.

Turning autospeak off, leaving the live cursor or changing focus discards
automatic feedback still waiting in Emacs. Speech already sent to Omnivox may
finish. Returning or re-enabling speech starts with fresh output; it does not
replay missed content. Use explicit
review instead. This policy also applies to an embedded Eshell terminal,
without changing ordinary Eshell output.

*** Read output and follow progress
:PROPERTIES:
:TEXINFO_NODE: no
:END:

On the main screen, Emacsvox collects a burst of output before speaking. Complete
new output lines are spoken once, with automatic limits of eight lines and
1,000 characters. Continued input rows and empty terminal placeholders are
omitted without hiding output or rereading earlier rows. Output remains
eligible even if it scrolls beyond the screen, including repeated identical
lines; increasing scrollback is unnecessary for this feedback.

For progress rows, speech omits runs of three or more horizontal box-drawing
strokes separated from surrounding text by spaces, while retaining figures
and labels. A row containing only a horizontal rule, with optional box
corners, uses the separator cue even at =all= punctuation. This applies to
automatic output, explicit screen review, and line reading in EAT and frozen
review buffers. Table junctions, vertical borders, and shorter runs keep their
usual presentation. The buffer text remains intact, so you can inspect
individual characters. Adjust the separator sound through
[[info:emacsvox#Sounds And Space][Line and boundary cues]].

Wrapped output is joined and oversized bursts announce how much was omitted.
Fresh text without a newline also speaks, keeping password requests and
confirmation questions accessible. Carriage-return progress and status
rewrites use rate-limited, replaceable speech. Unchanged repaints and
resize-only updates remain silent. Bells, pastes, input-mode changes, entry
to or exit from an application screen, and process exit have their own cues
or announcements without reading screen content.

*** Recognise and inspect prompts
:PROPERTIES:
:TEXINFO_NODE: no
:END:

#+vindex: emacsvox-eat-prompt-feedback
#+findex: emacsvox-eat-speak-prompt
#+kindex: C-e q p (EAT)

When EAT shell integration identifies a ready prompt, Emacsvox gives a cue
after output instead of reading the prompt text. =emacsvox-eat-prompt-feedback=
defaults to =earcon=; choose =text= to hear the prompt or =silent= to suppress
it. This option can be buffer-local and is independent of verbosity, but
automatic prompt feedback still obeys foreground autospeak eligibility.

Split and multiline prompts are collected until ready. Redisplay and typing
do not repeat them. If several prompts arrive in one burst, feedback describes
the final ready prompt.

~C-e q p~ explicitly reads the last identified prompt, even with autospeak off.
Recognition does not require margin annotations, but it does require shell
integration. An unintegrated remote prompt or question is ordinary output,
read as text; the prompt preference does not silence it. The last identified
prompt may still belong to the local shell. Use ~C-e q l~ for the current
retained cursor row in that situation.

*** Hear input and deletion results
:PROPERTIES:
:TEXINFO_NODE: no
:END:

When the terminal has keyboard focus, ~RET~ stops earlier main speech before
sending a newline in line, semi-character, or character mode. For example,
advancing to the next line in =ed= cuts off the preceding line. Output chunks
within one response still play in order, and notification speech continues
independently. ~RET~ itself adds no spoken text. Sending line input without a
newline or editing scrollback does not trigger this stop.

On the main screen in semi-character and character modes, Emacsvox names the
character reached by rendered left/right movement. After up/down it speaks
the resulting input or history row without the observed shell prompt.
~M-b~, ~M-f~, and modified left/right word movements
speak the rendered text crossed. A boundary key that produces no movement
stays silent.

Line-mode history navigation speaks the recalled command once. EAT's
history-item counter and input-restored message remain visible in the echo
area without speaking over the command on the notification stream.

An echoed Space is named without rereading the prompt or line. For Backspace,
Delete, ~M-d~, and ~C-k~, Emacsvox compares the visible screen before
and after the key. One unambiguous same-row removal is read as the actual
character or text removed. Otherwise only a deletion tone is given; adjacent
prompt or screen text is not guessed as deleted content. Padding and trailing
input blanks do not prevent an otherwise unambiguous word deletion.

When a program does not echo input, there is no visible deletion to announce.
With the default Terminal profile, this editing feedback requires the
selected window to follow the live cursor on the main screen. Entering a
protected password, switching terminals or reviewing scrollback suppresses it.

*** Bells and application-screen changes
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Bells retain EAT's configured sound without speaking "Terminal bell" by default.
An aural rule can add a label by matching module =eat=, role
=command-interaction=, event =command-terminal-bell=, and occasion
=notification=, with speech before or after the event. Bell notifications
remain rate-limited and obey selected-buffer, live-cursor, and secure-input
restrictions.

In full-screen or alternate-screen applications, Emacsvox can announce the row
reached by an arrow key or a small, clearly identified change in selection
highlighting. It does not speak every refresh. Use explicit review when a
screen change is ambiguous: a coloured or inverse-video row alone does not
establish which item is active.

** Terminal-side Completion
:PROPERTIES:
:TEXINFO_NODE_NAME: EAT Terminal Completion
:ALT_TITLE: Hear terminal-side completion
:DESCRIPTION: Hear completed input and inspect retained candidate or help rows.
:END:

#+cindex: completion candidates, terminal
#+cindex: router completion
#+kindex: TAB (EAT terminal completion)

When you press ~TAB~ on the main screen in semi-character or character mode,
Emacsvox compares the screen before and after completion, waiting briefly for
output to settle. An inline completion speaks the newly displayed field;
for example, =~/sr<TAB>= can speak =src slash= after the
shell displays =~/src/=.

When completion prints columns of alternatives or help rows, Emacsvox reads
them together after the input line is redrawn. Small lists speak up to eight
candidates. Router-style help retains its layout and descriptions. Large
lists are counted and shortened for automatic speech. If candidates have
already scrolled beyond the captured screen, the count gives only the number
known to be visible, such as ``at least N visible''.

Identical repeated lists, split output, bells, wrapping, and resizing are
coalesced without repeating the candidate text. This works from rendered
results for local Readline, SSH, and unstructured router help. No visible
change means there is nothing reliable to announce. On an alternate
screen, the default Terminal profile treats ~TAB~ as application navigation.

Use ~C-e q c~ to read the retained candidate/help layout, or open frozen
review with ~C-e q r~ and press ~c~. This is useful for large or multi-column
results and does not ask the terminal to complete again.

With the default speech prefix, ~C-e q~ provides review commands in every
EAT input mode:

#+attr_texinfo: :indic kbd :compact t
- C-e q l :: Speak the cursor row from the latest retained screen.
- C-e q d :: Speak the last classified change.
- C-e q h :: Speak the conservative likely-focus inference and its confidence.
- C-e q c :: Speak retained completion candidates or help rows.
- C-e q s :: Speak a bounded copy of the retained visible screen.
- C-e q r :: Open a read-only frozen copy for line-by-line review.
- C-e q x :: Read the visible Vim selection.
- C-e q t :: Repeat the last retained status, including a Vim message or prompt.
- C-e q p :: Speak the last identified shell prompt.
- C-e q i :: Speak the retained, sanitised title or working-directory change.
- C-e q a :: Choose the application speech profile for this terminal.
- C-e q v :: Cycle terse, normal, and verbose automatic feedback for this terminal.
- C-e q m :: Toggle content-free background monitoring for this terminal.

The reading commands inspect retained snapshots with concealed content
redacted. The profile, verbosity and monitoring commands act on the source
terminal. These commands run locally in Emacs. Review covers the visible
screen at the time of capture. The live display can change while you read.

*** Frozen Screen Review
:PROPERTIES:
:TEXINFO_NODE: no
:END:

#+cindex: frozen EAT review

~C-e q r~ opens a fixed copy of the latest visible screen. It does not
refresh, move the live cursor or send input. The copy retains styling,
positions for the cursor and likely focus, and completion rows. Opening and
closing play distinct object cues and announce the transition.

#+attr_texinfo: :indic kbd :compact t
- n, p; C-n, C-p; down, up ::

  Move by captured terminal row and speak the destination, interrupting the
  previous row announcement.
- SPC, RET, . :: Speak the current captured row.
- a :: Speak a bounded form of the current screen or completion view.
- s, c :: Show captured screen rows or retained completion/help rows.
- C :: Go to the captured terminal cursor.
- h :: Go to retained likely focus when available.
- [, ] ::

  Move among inverse/background-styled, selection-like regions. They are not
  labelled as confirmed focus.
- x :: Read the visible Vim selection copied when review opened.
- t, i :: Speak status or metadata copied when review opened.
- v, m ::

  Change verbosity or monitoring in the source terminal without sending
  terminal input. The copied content stays frozen.
- ? :: Describe frozen review mode.
- q :: Kill the content-bearing review buffer and restore its window.

Entering a password through protected input, resetting or restarting the
terminal, killing its buffer or leaving EAT mode also closes and removes
its frozen review.

** Verbosity And Background Monitoring
:PROPERTIES:
:TEXINFO_NODE_NAME: EAT Feedback Preferences
:ALT_TITLE: Adjust and save terminal feedback
:DESCRIPTION: Choose verbosity, background monitoring, and focused speech defaults.
:END:

#+vindex: emacsvox-eat-verbosity
#+vindex: emacsvox-eat-monitor-background-output

=emacsvox-eat-verbosity= is buffer-local:

#+attr_texinfo: :indic code :compact t
- terse ::

  Retain routine output and metadata for explicit review without speaking
  them automatically. Actionable failures and content-free lifecycle feedback
  remain available.
- normal ::

  The default: bounded command output, progress/status, completion, and
  actionable failures.
- verbose ::

  Also give bounded title and directory changes and successful shell-command
  status when EAT shell integration supplies it.

Background monitoring starts off. With ~C-e q m~ enabled, an unselected
terminal gives only a rate-limited content-free cue. Returning reports the
unread burst count, never the terminal's identity or output. Cursor movement,
style changes, repaint, resize, and process-generation changes do not count.
Unlike Shell/comint background reading, EAT monitoring neither requires
foreground autospeak nor reads background content.

*** Adjust and save focused terminal settings
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Use ~C-e S~ or ~C-e H j c~ from EAT or its frozen review. ~C-e H j a~ opens
the integration chooser, and ~C-e H /~ finds individual controls.

- ~s~ toggles automatic foreground speech.
- ~b~ toggles background cues and unread counts independently.
- ~p~ chooses ready-prompt cue, text, or silence; recognition still requires
  shell integration and automatic delivery obeys foreground autospeak.
- ~d~ chooses terse, normal, or verbose feedback.
- ~a~ chooses the application profile for this terminal session.

Arrows announce values and ~RET~ activates a control. Choice lists start on
the current value; browsing does not apply a choice, ~RET~ applies and returns,
and ~q~ cancels. Confirmations interrupt older main speech. Changes belong to
the captured terminal, including embedded Eshell EAT; from frozen review they
belong to its source terminal.

~q~ returns to the originating menu entry. From direct ~C-e S~, it closes
the menu and announces the restored buffer and mode with a close cue. ~w~
saves the speech, monitoring, prompt and verbosity defaults through Customize.
Terminals with local overrides keep them. Others inherit the new defaults.
~A~ opens advanced EAT settings and ~q~ there returns to the focused menu.

** Shell Integration And Command Status
:PROPERTIES:
:TEXINFO_NODE_NAME: EAT Shell Integration
:ALT_TITLE: Follow shell prompts and command status
:DESCRIPTION: Understand the Bash or Zsh integration and its remote-shell limits.
:END:

#+cindex: EAT shell integration
#+cindex: shell command status

EAT's Bash or Zsh integration supplies prompt annotation, directory tracking,
and per-command running/success/failure status. For Bash, EAT documents:

#+begin_example
[ -n "$EAT_SHELL_INTEGRATION_DIR" ] && \
  source "$EAT_SHELL_INTEGRATION_DIR/bash"
#+end_example

For Zsh, use its script instead:

#+begin_example
[ -n "$EAT_SHELL_INTEGRATION_DIR" ] && \
  source "$EAT_SHELL_INTEGRATION_DIR/zsh"
#+end_example

#+vindex: eat-enable-shell-prompt-annotation

With integration and =eat-enable-shell-prompt-annotation= enabled, Emacsvox
retains running, successful, and failed command status. A failure is eligible
for automatic feedback at every verbosity, subject to foreground autospeak.
Success is automatic only at verbose level after observed command activity;
the initial successful prompt is not announced as a completed command.
Running state stays silent. ~C-e q t~ requests the retained current state.

Status is not guessed from prompt characters. A remote shell or router usually
does not provide this per-command integration. Its output and completion can
still be accessible while individual exit status remains unavailable.

** Passwords And Sensitive Content
:PROPERTIES:
:TEXINFO_NODE_NAME: EAT Passwords And Privacy
:ALT_TITLE: Enter passwords and protect sensitive content
:DESCRIPTION: Use protected password input and understand retained terminal data.
:END:

#+cindex: password input, EAT
#+cindex: terminal privacy
#+findex: eat-send-password

Use ~M-x eat-send-password RET~ for a terminal password. In character mode,
first press ~M-RET~ to return to semi-character mode so command entry reaches
Emacs rather than the terminal program. Enter the secret only in the protected
password prompt. EAT uses Emacs's password reader rather than recording those
keystrokes in command lossage.
Emacsvox suppresses observation and bell speech during the command, clears
content-bearing retained state before and after it, and announces only whether
secure input was sent or cancelled.

Ordinary no-echo input does not establish that boundary. EAT exposes no public
echo-state signal, and a quiet repaint is not evidence of password entry.
Typing a secret through normal terminal input can leave keystrokes in Emacs
lossage. Backspace or Delete may give a content-free deletion tone, but speech
names content only when one unambiguous visible removal is exposed.

Selected foreground output can contain sensitive information and be spoken.
Frozen review is a real in-memory copy until killed, although visually concealed
cells are redacted when captured. Verbose title and directory announcements can
disclose host/path metadata. Background monitoring, by contrast, never reads
content or terminal identity.

** Terminal-Controlled Clipboard Trust
:PROPERTIES:
:TEXINFO_NODE_NAME: EAT Clipboard Trust
:ALT_TITLE: Control terminal access to the clipboard
:DESCRIPTION: Review OSC 52 trust and the two terminal selection-control options.
:END:

#+cindex: clipboard security, EAT
#+cindex: OSC 52, EAT
#+cindex: remote terminal trust
#+vindex: eat-enable-kill-from-terminal
#+vindex: eat-enable-yank-to-terminal

EAT supports terminal selection-control sequences, commonly called OSC 52.
Trust therefore extends to any local program, SSH peer, router, or other output
source that reaches its parser. Displaying an untrusted file through a program
that does not sanitise control sequences can also exercise this interface.

In the audited EAT 0.9.4 release, =eat-enable-kill-from-terminal= defaults to
non-=nil=. Despite its name, this is the terminal-to-Emacs direction: a terminal
program can place text in the kill ring. =eat-enable-yank-to-terminal= defaults
to =nil= for security; enabling it lets a terminal program request current
kill-ring text. Check the installed defaults again after an EAT upgrade.

For output you do not fully trust, disable both directions globally through
Customize or locally in the EAT buffer:

#+begin_src emacs-lisp
(setq-local eat-enable-kill-from-terminal nil
            eat-enable-yank-to-terminal nil)
#+end_src

Evaluate this with ~M-:~ in that buffer before processing untrusted output.
Reserve kill-ring read-back for programs and remote endpoints trusted with
whatever the kill ring currently contains.

Emacsvox changes neither option. A terminal-originated selection payload is not
an accessibility command: its contents are neither spoken nor retained as
terminal screen text. Content-free paste announcements apply to explicit user
paste commands, not these terminal-originated sequences.

** Full-screen Applications And Limitations
:PROPERTIES:
:TEXINFO_NODE_NAME: EAT Full-screen Applications
:ALT_TITLE: Inspect full-screen applications and diagnose silence
:DESCRIPTION: Use retained review and distinguish terminal rendering from speech.
:END:

#+cindex: curses applications, EAT
#+cindex: alternate screen, EAT

Pagers, editors, menus and dashboards often rewrite cells on screen. The
default Terminal profile follows arrow movement and clear changes in selection
highlighting. Each application interprets printable keys. For editing
commands and their spoken feedback, see [[*Vim in EAT][Vim in EAT]].

After a silent update, use ~C-e q l~ to read the cursor row, ~C-e q d~ to
hear what changed or ~C-e q h~ to hear where Emacsvox thinks the focus is.
For line-by-line inspection, open frozen review with ~C-e q r~. You can
also move among regions whose highlighting suggests a selection. Emacsvox
limits automatic speech on rapidly refreshing dashboards. EAT reports text
and styling. Its screen data omits hyperlink targets, image contents
(including sixel graphics), the application's accessibility focus and the
exact cause of an update.

If ordinary output is unexpectedly silent, check the input mode, selected
buffer, live cursor position, foreground autospeak and verbosity. Frozen
review holds the visible screen at the time you open it. For earlier
output, consult the terminal's retained scrollback.

Remote programs also need compatible terminal information. Missing terminfo
on the remote host can break cursor addressing and screen layout. If the
terminal display itself is wrong, consult the [[info:eat#Top][Eat User Manual]].

** Vim in EAT
:PROPERTIES:
:TEXINFO_NODE_NAME: Vim in EAT
:DESCRIPTION: Choose the Vim speech profile and try an edit in an unnamed buffer.
:END:

#+cindex: Vim in a terminal
#+findex: emacsvox-eat-select-application-profile
#+kindex: C-e q a (EAT)

Start EAT with ~M-x eat RET~. Use its default semi-character mode or
switch to character mode. At the shell prompt, run =vim= without a
filename to open an unnamed buffer for practice.

Once Vim opens, press ~C-e q a~. Emacsvox reads the selected application
profile. Use the arrows to find Vim and press ~RET~ to apply it, or ~q~
to cancel. The choice applies to this EAT buffer.

Vim starts in Normal mode, where letters are commands. Press ~i~ to enter
Insert mode. Type =one=, press ~RET~ and type =two=. Emacsvox echoes the
text according to your typing settings. Press Escape to return to Normal
mode. With Vim's usual mode display, you hear both mode changes. Press ~k~
to hear =one= and ~j~ to hear =two=. When you finish practising, type
~:q!~ and press ~RET~ to discard the practice text and return to the shell.

When you open an existing file with a swap-file warning, Emacsvox reads
the available choices even if you select the profile after the warning
appears. Press the letter for your choice. If you press ~R~ to recover
and Vim finds several swap files, you hear their numbers, names and
visible details such as the date and whether a copy was modified. Press
Space if Vim pauses the listing for another page. At the number prompt,
type the number of the copy you want and press ~RET~, or type ~0 RET~
to cancel recovery. Use ~C-e q t~ to hear the prompt again.

*** Move around a file
:PROPERTIES:
:TEXINFO_NODE_NAME: Vim navigation
:ALT_TITLE: Move around a file
:DESCRIPTION: Hear the character, word, line or window you reach.
:END:

#+cindex: Vim cursor movement

In Normal mode, ~j~ moves down a line and ~k~ moves up. Emacsvox reads the
line you reach or plays your usual blank-line cue on an empty line. Move
left with ~h~ or right with ~l~ to hear the character under the cursor.
The arrow keys give the same line and character feedback in both Normal
and Insert modes. On the current line, ~0~ and ~$~ take you to the first
and last characters. Use ~^~ and ~g_~ for the first and last nonblank
characters. Each motion reads the character you reach.

When Vim shows absolute or relative line numbers, Emacsvox reads the
file text following the number margin. To hear its indentation, toggle
indentation feedback with ~C-e d i~. Use ~C-e d c~ to toggle the cues
for a capital letter and an all-caps word. Choose how those indications
sound with ~C-e d I~ for indentation and ~C-e d C~ for capitalisation.

Use ~w~, ~b~ and ~e~ to move by word and hear the word you reach.
If your Vim configuration gives words special characters, run
~:setlocal iskeyword?~ and press ~RET~ in the file you are editing.
This shows Emacsvox the current word characters. For example, after
~:set iskeyword+=-~, moving to =two-part= reads the whole word.
~C-Left~ and ~C-Right~ also move by word in semi-character and character
mode. With Vim's usual settings these keys treat =green,blue= as one word
in Normal mode. In Insert mode they stop on =green=, the comma and =blue=
separately.

Use ~gg~ to go to the first line or ~G~ to go to the last line. As with
~M-<~ and ~M->~ in Emacs, you hear the large-movement cue, the destination
line and a “top” or “bottom” notification. A count such as ~5G~ or ~5gg~
takes you to line 5 and reads its number and text.

Page with ~C-d~, ~C-u~, ~C-f~ or ~C-b~, or move within the screen with
~H~, ~M~ or ~L~, to hear the destination and its position. EAT reserves
~C-u~ in semi-character mode. Press ~C-q C-u~ to send it to Vim.

To find a character on the current line, press ~f~ followed by the
character. A semicolon repeats the find and a comma reverses it. Press ~%~
on a bracket to hear the position and character at the other end of the
pair. A paragraph jump with ~{~ or ~}~ gives the position even on a blank
line. Move back one sentence with ~(~ or forwards with ~)~ to hear the
destination position and the text from there to the end of the screen row.

With ~ma~, you hear where you asked Vim to set mark a. Jump to its line
with ~'a~ or its exact position with a backtick followed by ~a~. Use
~C-o~ and ~C-i~ to move through Vim's jump history.

When you move between Vim windows with ~C-w w~ or the directional window
commands, you hear which way you moved and the row in the destination window.
In side-by-side windows, movement and ~C-e q l~ read your side when Vim
displays a distinctly styled divider. Position announcements use the
line and column shown in the active window's ruler. Use ~:bnext~ to
switch buffers or ~gt~ and ~gT~ to change tabs. You hear the destination
and its current row.

*** Edit text and review selections
:PROPERTIES:
:TEXINFO_NODE_NAME: Vim editing and selection
:ALT_TITLE: Edit text and review selections
:DESCRIPTION: Hear insertions, deletions and the extent or text of a selection.
:END:

#+cindex: Vim selections
#+findex: emacsvox-eat-speak-vim-selection
#+kindex: C-e q x (EAT)

From Normal mode, press ~o~ to open a line below the cursor or ~cw~ to
change the current word. Both enter Insert mode. As Vim displays what you
type, Emacsvox follows your character, word and line echo settings.
Backspace plays your deletion cue and speaks the character removed. ~C-w~
erases a word and ~C-u~ erases the text back to the start of the insertion
or line. You hear the text that disappeared. ~TAB~ reports the column you
reach.

For keyword completion in Insert mode, use ~C-n~ and ~C-p~. For a
filename, start with ~C-x C-f~, then use ~C-n~ and ~C-p~ to hear the
name and match position. ~C-y~ accepts the candidate and ~C-e~ cancels
when sent to Vim. In semi-character mode, use ~C-q C-x C-f~ to start
filename completion, ~C-q C-y~ to accept or ~C-q C-e~ to cancel. In
character mode with the default speech prefix, press ~M-RET~ to return
to semi-character mode, then ~C-q C-e~ to cancel. For other reserved
keys, see
[[*Input Modes And Completion Responsibilities][Choose an input mode]].

In Normal mode, ~x~, ~dw~, ~diw~, ~D~ and ~dd~ use the deletion cue and
read what Vim's redraw identifies. Use ~D~ or ~d$~ to delete from the
cursor to the end of the line. A counted deletion such as ~3dd~ can
report Vim's count and the line now under the cursor. If the original
line was missing from EAT, ~x~ can read the resulting line. With ~yw~ or
~yy~ you hear the word or line you asked Vim to copy. Press ~p~ to paste
it and hear the paste cue and the inserted text.

To replace one character, press ~r~ followed by its replacement. You hear
what changed. The tilde key changes case, ~J~ joins lines and reads the
result, and ~>>~ or ~<<~ reports the new indentation. Repeat a change
with ~.~ or undo it with ~u~ to hear the result. Emacsvox also announces
Replace mode when Vim displays its mode label. With Vim's standard
English mode labels hidden, visible typing and movement can still give
feedback.

To select text in Normal mode, press ~v~ for characters, ~V~ for lines
or ~C-v~ for a rectangular block. As you move the cursor in Visual mode,
you hear the extent of the selection. Press ~o~ to move the other end,
or use ~gv~ in Normal mode to restore the previous selection. For a short selection you also
hear the text, including a selected space or blank line. For a longer
selection, press ~C-e q x~ to read the portion on screen. In frozen
review, ~x~ reads the selection as it appeared when you opened the review.

Create a fold with a motion such as ~zf2j~. When Vim displays the closed
fold, you hear its line count and summary. ~zo~ opens the fold and reads
the exposed line. ~zc~ closes it.

Press ~qa~ to record a macro in register a. Emacsvox announces the
register when Vim displays it and the end of recording when you press ~q~
to stop. Play the macro with ~@a~ or repeat it with ~@@~. Emacsvox
describes the visible result. If it has observed a Normal-mode action and
the replay leaves the screen unchanged, you hear that the replay was
requested.

*** Search and read command results
:PROPERTIES:
:TEXINFO_NODE_NAME: Vim search and command results
:ALT_TITLE: Search and read command results
:DESCRIPTION: Follow matches and substitutions, and repeat a command result or prompt.
:END:

#+cindex: Vim command results

In Normal mode, press ~/~ to search forwards or ~?~ to search backwards.
Type your search and press ~RET~. To search for the word under the cursor,
press ~*~ or ~#~. These searches and the repeat keys ~n~ and ~N~ read the
line containing the match. When the search wraps, you hear Vim's wrap
notice and the destination line together. If EAT initially shows only
the file line number, Emacsvox speaks that number. You hear the text if
it arrives at the same position within three seconds.

For a substitution with confirmation, such as ~:%s/one/two/gc~, listen for
the replacement, match position and available answers. Press ~y~ to
replace the current match or ~n~ to skip it. You hear the next match even
if it is on the same line. ~a~ accepts the remaining matches and ~q~
stops. A count-only substitution reports the number of matches Vim displays.

At a Vim command prompt such as ~:edit~, press ~TAB~ to hear the completed
path. Submit a command with ~RET~. To save a named file, for example,
type ~:w~ and press ~RET~. With ~:ls~, ~:marks~ or ~:registers~, you
hear the visible entries before the continuation prompt. An option query
such as ~:set number?~ reads its displayed value.

To open Vim's own help on movement, type ~:help motion~ and press ~RET~.
Emacsvox reads the help file, position and current line as Vim displays
them. With ~:cnext~ or ~:cprevious~, listen for the quickfix entry number,
position and diagnostic. Use ~C-e q t~ to repeat the last retained result,
including a save confirmation, a failed search, or the error and prompt
when Vim refuses to quit.

*** Use Vim over SSH or inside tmux
:PROPERTIES:
:TEXINFO_NODE_NAME: Vim over SSH or inside tmux
:ALT_TITLE: Use Vim over SSH or inside tmux
:DESCRIPTION: Select the profile locally, recover a missing line and return to shell feedback.
:END:

#+cindex: Vim over SSH

When Vim runs on a remote host or in a =tmux= pane, choose the Vim profile
in the local EAT buffer with ~C-e q a~. Emacsvox follows the keys you send
and the screen EAT receives, so the same profile works with stock Vim on
the remote host. If several letters arrive in one update over SSH, you can
hear them together.

If a search reaches a match but =tmux= has only partly redrawn the line,
press ~C-l~ in Normal mode to ask Vim to redraw and hear the current line.
To read the row EAT already has, press ~C-e q l~. An ambiguous redraw, a
motion that stops at a boundary or a reply arriving more than three
seconds after your last key can stay quiet.

You can run a shell command from Vim with ~:!~ followed by the command
and ~RET~. At Vim's continuation prompt, press ~RET~ to resume editing
with the Vim profile. When you quit Vim and its alternate screen closes,
Emacsvox restores the Terminal profile. Resetting or exiting the terminal
also restores it. Over SSH or inside =tmux=, quitting Vim with ~:q~
can leave the same terminal screen open. When Emacsvox
recognises the returning shell prompt, you hear “Terminal profile”. If the
Vim profile stays active at an unfamiliar shell prompt, press ~C-e q a~
and choose Terminal.

** EAT In Eshell
:PROPERTIES:
:TEXINFO_NODE_NAME: EAT In Eshell
:ALT_TITLE: Use EAT in Eshell
:DESCRIPTION: Understand embedded terminals and visual-command window return.
:END:

#+cindex: Eshell, EAT accessibility
#+findex: eat-eshell-mode
#+findex: eat-eshell-visual-command-mode

With global =eat-eshell-mode= enabled, Emacsvox uses the same screen observer
for EAT's terminal region inside Eshell. Rendered command output follows one
speech path instead of also being repeated by generic Eshell feedback.

With =eat-eshell-visual-command-mode=, a visual command runs in a separate EAT
buffer. Emacsvox announces its start, delivers eligible final output before
process-exit feedback, and identifies the exit as an Eshell visual command.
EAT and Eshell still own window return. In particular,
=eshell-destroy-buffer-when-process-dies= determines whether a successful
visual-command buffer is killed and Eshell restored; Emacsvox does not change it.
