* Speech Backends
:PROPERTIES:
:TEXINFO_NODE_NAME: Speech Backends
:DESCRIPTION: Select, install, and verify a speech server.
:END:

Emacsvox sends speech through a speech server. For a new installation,
use /Omnivox/. The server communicates with the engine that produces speech:
normally eSpeak NG on GNU/Linux, AVSpeechSynthesizer on macOS, and WinRT
SpeechSynthesizer on Windows.

Follow [[*Getting Started: Installation and First Speech][Installation]] if you have not yet obtained speech. This chapter is for
choosing a supported platform route, installing or configuring a different
backend, and diagnosing problems. Omnivox's native build procedures, engine
behaviour, and versioned protocols belong to
[[https://github.com/bartbunting/omnivox][the Omnivox repository]].

The menu routes here describe =ui-experiments=. Release packages can provide
an earlier interface; use the matching manual and keep a working installation
available while testing the development branch.

** Supported Platform Routes
:PROPERTIES:
:TEXINFO_NODE_NAME: Supported Platform Routes
:DESCRIPTION: Choose the maintained route for this machine.
:END:

The following table describes Emacsvox support, not every platform that the
Omnivox project can build. ``Host check required'' means that automated build
and archive verification does not prove playback through your audio device;
an audible =omnivox --check= on that machine remains the acceptance test.

#+attr_texinfo: :columns .18 .31 .51
| Emacs platform | Recommended route | Current support evidence |
|---+---+---|
| GNU/Linux x86-64 with an Ubuntu 24.04-compatible runtime | Omnivox 1.17.0 release archive using eSpeak NG | The published archive is built and verified on Ubuntu 24.04. Compatible glibc, libstdc++, libgcc, and ALSA runtime libraries are required; the audible host check remains required. |
| Other GNU/Linux systems | Source-built Omnivox using eSpeak NG | Use the source route for Linux ARM64, an older distribution ABI, or a host that cannot run the published x86-64 archive. |
| macOS on Apple silicon | Omnivox through the official Homebrew tap, using AVSpeechSynthesizer | Native ARM64 tap checks cover installation, synthesis, reinstall, a packaging-revision upgrade, and removal; audible Emacs acceptance remains required. |
| macOS on Intel | Omnivox through the official Homebrew tap, using AVSpeechSynthesizer | Native Intel tap checks cover installation, synthesis, reinstall, a packaging-revision upgrade, and removal; audible Emacs acceptance remains required. |
| Emacs in WSL2 on x86-64 Windows | Omnivox 1.17.0 Windows x64 release archive using WinRT | The published archive is checksum-protected and release CI verifies its architecture, adjacent data, WinRT and eSpeak synthesis. The audible host check remains required. |
| Emacs in WSL2 on Windows on ARM | Omnivox 1.17.0 Windows ARM64 release archive using WinRT | Release CI verifies the ARM64 archive, adjacent data, WinRT and eSpeak synthesis, and the guided installer selects it automatically. A complete WSL2 host and audible check remains required. |
| Native Windows x64 Emacs 30.2 or newer | Guided PowerShell installation with Omnivox 1.17.0 using WinRT | Supported. Native installer, complete byte-code compilation, fresh-process verification, and two-lane speech checks cover this route. Confirm audible speech on the installed host. Native Windows ARM64 is not yet supported. |

Use Homebrew on macOS, the guided installer under WSL2, or the matching release
archive on GNU/Linux. Manual Mac archive installation remains available.
A bare executable, repository tag, or unpackaged CI artifact is not a complete
installation: keep the release's runtime data and notices beside the executable.
Homebrew preserves that layout for you.

Do not set =OMNIVOX_ENGINE= during initial setup. Its empty value selects
the normal platform engine above. Engine routing and optional Piper,
Eloquence, or DECtalk support are later customisations, not prerequisites for
first speech.

For Emacs running on a remote SSH host, see
[[Remote workstation speech setup][Remote Workstation Speech]].

*** Version and capability requirements
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Omnivox 1.17.0 is the minimum supported release. It supplies named punctuation
profiles, palette-aware character speech and editable engine configuration,
alongside managed voice libraries, eSpeak variants, engine-specific voice
controls, individual fallback tuning and complete voice previews. A newer
compatible release may be used. The manual archive examples and guided
installers pin the 1.17.0 core and matching optional engines exactly; the
macOS Homebrew tap follows its maintained stable formula.

Upgrade an existing Omnivox installation separately; updating Emacsvox does
not replace the selected speech server. Voice-library management uses the
bundled local management route. Remote and direct-native launches do not
acquire the WSL launcher's file or release-management capabilities merely by
connecting to an Omnivox worker. The individual procedures identify their
required host and capabilities.

** Install Omnivox From A Release Binary
:PROPERTIES:
:TEXINFO_NODE_NAME: Installing An Omnivox Release Binary
:DESCRIPTION: Install Omnivox through Homebrew or a verified release archive.
:END:

*** macOS with Homebrew
:PROPERTIES:
:TEXINFO_NODE: no
:END:

On macOS (formerly OS X), install [[https://brew.sh][Homebrew]] and follow its shell setup
instructions. Then install Omnivox from the
[[https://github.com/bartbunting/homebrew-omnivox][official Homebrew tap]]:

#+begin_example
brew install bartbunting/omnivox/omnivox
omnivox_program="$(brew --prefix omnivox)/bin/omnivox"
"$omnivox_program" --version
"$omnivox_program" --check
"$omnivox_program" --list-voices
#+end_example

Homebrew selects the Apple silicon or Intel archive and verifies its checksum.
The version must be 1.17.0 or newer, and the check must produce both a tone and
spoken confirmation. Apple system speech and eSpeak are included. You do not
need a Rust build or Omnivox source checkout. Install Emacs 30.2 or newer
separately; this tap does not install Emacs or Emacsvox.

To select this Homebrew installation persistently for Emacsvox, record the
stable executable path:

#+begin_example
omnivox_config_home="${XDG_CONFIG_HOME:-$HOME/.config}"
omnivox_config_file="${EMACSVOX_OMNIVOX_CONFIG_FILE:-$omnivox_config_home/emacsvox/omnivox-program}"
mkdir -p "$(dirname "$omnivox_config_file")"
printf '%s\n' "$omnivox_program" > "$omnivox_config_file"
#+end_example

This replaces any previous executable selection in that file. The path uses
Homebrew's current-version link and continues to work after upgrades. Do not
substitute a versioned =Cellar/omnivox/...= path. The bundled launcher reads
this file even when Emacs does not inherit the shell's Homebrew =PATH=, as can
happen when starting from Finder. An explicit =OMNIVOX_PROGRAM= override
still takes precedence; remove or update an override selecting another
installation. If using =EMACSVOX_OMNIVOX_CONFIG_FILE= or =XDG_CONFIG_HOME=,
make sure the launching Emacs sees the same location.

Emacsvox uses its bundled Lisp adapter. Do not load Homebrew's
=libexec/omnivox-voices.el=, intended for upstream Emacspeak. Continue with
[[*Build And Start Emacsvox][Quick Installation]] to compile Emacsvox, run =./bin/emacsvox --diagnose=
and =./bin/emacsvox --check=, and start an isolated speaking session.
Confirm the selected server and audible output on your Mac.

To upgrade Omnivox later:

#+begin_example
brew update
brew upgrade omnivox
"$(brew --prefix omnivox)/bin/omnivox" --version
"$(brew --prefix omnivox)/bin/omnivox" --check
#+end_example

Restart Emacsvox after upgrading so both speech processes use the new
executable. Updating Emacsvox alone does not upgrade Homebrew's package.
=brew uninstall omnivox= removes it; select another server before restarting
Emacsvox because the saved executable path remains in your configuration.

Optional Piper, Flite, and RuTTS companions and voice models are separate.
The bundled RHVoice bridge still needs a compatible user-installed runtime
and data; its presence does not establish macOS runtime support. Keep optional
companions, downloaded voices, and configuration outside Homebrew's Cellar,
and use explicit paths as described in the
[[https://github.com/bartbunting/omnivox/blob/main/docs/README.md][Omnivox engine guides]]. Companions must match core release and architecture.
The WSL optional-engine installer is not a Homebrew package manager.

The tap installs published binaries without adding Apple Developer ID signing
or notarisation. If local policy refuses the verified binary, use
[[*Installing Omnivox From Source][Installing Omnivox From Source]]. Native tap checks cover WAV synthesis and
package operations; they do not replace listening acceptance in Emacs or prove
an upgrade between different upstream versions.

*** Manual archive installation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Use this route for GNU/Linux x86-64 with an Ubuntu 24.04-compatible runtime,
macOS on Apple silicon, or macOS on Intel. The
[[https://github.com/bartbunting/omnivox/releases/tag/v1.17.0][Omnivox 1.17.0 release]] supplies:

#+attr_texinfo: :columns .28 .27 .45
| Host | Set =platform= to | Archive |
|---+---+---|
| GNU/Linux x86-64 | =linux-x64= | =omnivox-1.17.0-linux-x64.tar.gz= |
| macOS Apple silicon | =macos-arm64= | =omnivox-1.17.0-macos-arm64.tar.gz= |
| macOS Intel | =macos-x64= | =omnivox-1.17.0-macos-x64.tar.gz= |

On a Mac, =uname -m= identifies =arm64= for Apple silicon or =x86_64= for Intel.
Create a download directory, select the platform, and fetch the archive and
published checksums:

#+begin_example
mkdir -p "$HOME/Downloads/omnivox-1.17.0"
cd "$HOME/Downloads/omnivox-1.17.0"
omnivox_version=1.17.0
platform=linux-x64
archive="omnivox-${omnivox_version}-${platform}.tar.gz"
release_url="https://github.com/bartbunting/omnivox/releases/download/v${omnivox_version}"
curl -fLO "$release_url/$archive"
curl -fLO "$release_url/sha256sums.txt"
#+end_example

Replace =linux-x64= with the appropriate Mac value when needed. Verify before
extraction. On GNU/Linux:

#+begin_example
grep "  $archive$" sha256sums.txt | sha256sum --check -
#+end_example

On macOS:

#+begin_example
grep "  $archive$" sha256sums.txt | shasum -a 256 --check
#+end_example

The command must name the archive and report =OK=. Otherwise remove the
download and do not run it. Extract the verified payload into a versioned
directory, keeping every supplied directory beside the executable:

#+begin_example
install_dir="$HOME/.local/opt/omnivox-${omnivox_version}"
mkdir -p "$install_dir"
tar -xzf "$archive" -C "$install_dir"
chmod 755 "$install_dir/omnivox"
export PATH="$install_dir:$PATH"
#+end_example

Add that =PATH= entry to the shell startup used to launch Emacs for subsequent
sessions. The directory contains =omnivox=, =espeak-ng-data=,
=third-party-licenses=, and =omnivox-voices.el=. Do not load or copy the last
file into Emacsvox, which has its own adapter.

Check the binary before starting Emacsvox:

#+begin_example
omnivox --version
omnivox --check
omnivox --list-voices
#+end_example

The version must be at least 1.17.0 and the check must produce tone and speech.
Mac archives are neither code-signed nor notarised. If security policy refuses
the verified binary, use the source route rather than weakening policy. On
GNU/Linux, missing libraries or incompatible glibc also call for a source build.

For WSL2, use [[*Install An Omnivox Windows Release Under WSL2][Installing An Omnivox Windows Release Under WSL2]], which verifies
a Windows archive without requiring a compiler or Docker.

** Install An Omnivox Windows Release Under WSL2
:PROPERTIES:
:TEXINFO_NODE_NAME: Installing An Omnivox Windows Release Under WSL2
:DESCRIPTION: Use the matching verified Windows archive without a build toolchain.
:END:

This is the ordinary WSL2 route for x86-64 Windows and Windows on ARM. From
the Emacsvox checkout, first inspect without changing anything:

#+begin_example
./bin/emacsvox-wsl-install --check
#+end_example

The doctor detects Windows architecture, selects its Omnivox 1.17.0 archive,
and reports Emacs and per-user paths. Missing Linux packages are reported with
an =apt= command for you to review and run. Working =powershell.exe= and
=wslpath= interoperation are required. Resolve prerequisites, then run:

#+begin_example
./bin/emacsvox-wsl-install
#+end_example

=etc/wsl-install.conf= pins the Omnivox version, release URL, x64/ARM64 archive
names, and both SHA-256 hashes. The installer queries Windows architecture and
verifies the matching published archive; it does not build Omnivox.

The full payload is installed below the Windows user's =LocalAppData=. Its
absolute WSL executable path is recorded in
=$XDG_CONFIG_HOME/emacsvox/omnivox-program=, normally
=~/.config/emacsvox/omnivox-program=. The installer does not invoke =sudo= or
edit shell startup. It compiles Emacsvox, runs a non-audible launcher diagnostic,
and finishes with the audible server check. Confirm both tone and speech.

No Omnivox checkout, Docker, Rust, MinGW, Visual Studio, Windows .NET Framework,
or optional/proprietary runtime is needed. WinRT speech is included in Windows.
Use =./bin/emacsvox-wsl-install --no-audio-check= only for controlled/headless
installation with a separate audible check later.

*** Manual Release Installation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Use this equivalent manual procedure to inspect installer actions, work around
a restriction, or repair one layer. It needs =curl=, =unzip=, =sha256sum=,
=powershell.exe=, and =wslpath=. The example uses Windows x64. On Windows on
ARM, use =windows-arm64= in the archive and installation directory and verify
that archive's checksum.

Download from WSL:

#+begin_example
mkdir -p "$HOME/Downloads/omnivox-1.17.0"
cd "$HOME/Downloads/omnivox-1.17.0"
omnivox_version=1.17.0
archive="omnivox-${omnivox_version}-windows-x64.zip"
release_url="https://github.com/bartbunting/omnivox/releases/download/v${omnivox_version}"
curl -fLO "$release_url/$archive"
curl -fLO "$release_url/sha256sums.txt"
grep "  $archive$" sha256sums.txt | sha256sum --check -
#+end_example

The last command must name the archive and report =OK=. Otherwise remove it
and do not run it. Install all files on the Windows filesystem:

#+begin_example
windows_local_app_data="$(powershell.exe -NoProfile -NonInteractive \
  -Command '[Environment]::GetFolderPath("LocalApplicationData")' | tr -d '\r')"
install_dir="$(wslpath -u "$windows_local_app_data")/Emacsvox/Omnivox/releases/$omnivox_version-windows-x64"
mkdir -p "$install_dir"
unzip -q -o "$archive" -d "$install_dir"
chmod 755 "$install_dir/omnivox.exe"
config_home=${XDG_CONFIG_HOME:-"$HOME/.config"}
mkdir -p "$config_home/emacsvox"
printf '%s\n' "$install_dir/omnivox.exe" > \
  "$config_home/emacsvox/omnivox-program"
#+end_example

Keep =omnivox.exe=, =espeak-ng-data=, and =third-party-licenses= together.
Do not load the archive's =omnivox-voices.el=; Emacsvox supplies its adapter.
This data-only file persists selection without shell initialisation. Respect
=XDG_CONFIG_HOME= when set. =OMNIVOX_PROGRAM= remains an explicit temporary
override with precedence over the file.

Verify through the checkout's launcher:

#+begin_example
./servers/omnivox --version
./servers/omnivox --list-voices
./servers/omnivox --check
#+end_example

Confirm version 1.17.0 or newer, tone, and speech. Release CI verifies archive,
x64 architecture, adjacent eSpeak data, discovery, and headless WinRT/eSpeak
synthesis; only listening checks your audio path. The Windows archive is not
code-signed. Do not weaken Windows security or local policy to install it.

The generic 1.17.0 archive includes TGSpeechBox profiles/language data and a
portable RHVoice helper. RHVoice's runtime and voice/language packages are
separate. Optional Piper, Flite, and RuTTS companions are not required for
WinRT; matching 1.17.0 companions are published separately.

The clean source-build route verifies/stages the official Piper companion and
builds RHVoice, Flite, and RuTTS from matching source. Piper models and the
RHVoice runtime/data are not bundled by that build. A compatible local voice
management service can separately download the reviewed voice packages below;
this does not acquire the RHVoice runtime. Flite/RuTTS need no external runtime
in the source-built bundle. Eloquence/DECtalk runtimes remain separately
licensed and supplied.

*** Optional Omnivox Engines
:PROPERTIES:
:TEXINFO_NODE_NAME: Optional Omnivox Engine Modules
:DESCRIPTION: Install, check, remove, and reinstall optional engines from Emacs.
:END:

The ordinary WSL2 archive is the core, not a claim that every supported engine
is installed. Companion archives provide larger, experimental, or
architecture-specific engines. Some require a separately supplied runtime or
chosen voice data before they can speak.

**** Inspect running engines
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Open ~C-e H v b~ to browse engines. The equivalent command is:

#+begin_example
M-x emacsvox-omnivox-manage-components RET
#+end_example

Home's ~I~ or /Browse voices/ remains an alternative. Opening uses the current
speech inventory without waiting for file checks or fresh discovery. Optional
engines missing from that inventory stay visible as /not reported/ so management
controls remain reachable. ~v~ browses voices; ~RET~ opens details.

Details begin with a short status and voice actions, with /Browse voices/
selected. Matching main/notification evidence is combined and problems remain
near the top. /Startup settings/ and /Diagnostics/ start folded; ~RET~ toggles
sections. Selection and folding are remembered per engine.

/Available/ describes discovery from the current worker. An older check does
not alone make it unavailable. /Previously available/ belongs to a stopped or
replaced worker. Details announce the engine before requesting newer inventory
in the background when its check is over five minutes old or belongs to another
worker. File checks likewise run in the background where requested.
/Streams differ/ identifies different availability, policy, health, or voice
identities. A bridge's presence does not establish its runtime; /Not checked/
does not mean missing. Diagnostics shows each worker's paths, inventory time,
runtime discovery, and health.

/Required runtime/ appears near the top when native libraries are needed.
Successful DECtalk discovery, for example, confirms DLL and dictionary loading.
Matching worker evidence is combined, differences shown separately, and failures
retain their reasons. Disabled does not mean missing, and retired-worker evidence
does not establish current status. Opening/refreshing details uses worker
discovery without invoking the separate release installer.

**** Browse voices and variants
:PROPERTIES:
:TEXINFO_NODE: no
:END:

/Browse voices/ combines reported voices and the installed library, including
disabled downloads. This dedicated browser preserves Workbench's filters and
staged edits. Languages have expandable headings with counts; ~RET~ toggles.
A one-language list starts expanded and selection/folding are remembered.
~RET~ or ~P~ on a voice auditions an exact sample, ~x~ shows details, and ~t~
opens an unsaved experiment. Saving asks for a palette destination; browsing
or previewing changes no palette. ~q~ returns to selected engine details.

Library data loads asynchronously with quiet refresh. /Installed/ identifies
library entries versus supplied voices. /Enabled/ is the desired selection
for the next Apply. /Active/ describes eligibility on both streams, main only,
notification only, or neither. /Unknown/ means missing/inconsistent evidence;
~R~ refreshes. Active does not measure model residency or prove listening.
Samples use main speech; inactive downloads need enablement and Apply first.

/Voice variants/ in eSpeak details lists the running worker's bundled variants.
Choose a base with ~b~, browse with arrows or ~C-n~/~C-p~, and audition with
~P~ or ~RET~. Sorting is alphabetical by displayed name, ignoring capitalisation.
The older ~p~ preview key also remains. Variants require no download, enablement,
saving, or speech restart.

~u~, /Use in palette/, asks for palette and named entry, then opens the voice
editor with the variant preferred, retaining fallbacks and tuning. Preview with
~P~, then ~w~ for Save and apply, or save to the collection without selecting.
Editing a built-in creates a personal copy; /Use at Startup/ remains separate.
For Max as ordinary reading, choose the English base with ~b~, select =Max=,
press ~u~, and select the palette's =default=. Preview/save there. The same
=default= is alongside =indent= and other entries in normal palette editing.

~V~ instead proposes the base/variant for every named voice. Create or update
a personal palette, compare, then save; shared adjustments and existing fallback
tuning survive. [[info:emacsvox#Editing Named Voices][Editing Named Voices]] explains review and recovery. ~q~ returns to variants
with selection retained; ~v~ opens the base browser. Saved references remain
valid. Older workers lacking on-demand variants report the need for an update.

**** Install and activate voice packages
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Installing files, enabling a voice, and activating it are separate steps.
/Get more voices/ in Piper, Flite, MBROLA, or RHVoice details opens the reviewed
catalogue. Piper groups language, voice name, and quality; Flite offers AWB/RMS.
Single-quality voices appear directly under their language, with another group
only for multiple qualities. ~RET~ opens a group/model and ~q~ returns.
~/~ searches all models by name or language beyond the current group.
Details show size, source, terms, and storage. ~s~ shows/hides speakers sharing
a model; it downloads once while individual speakers can be enabled separately.

~i~ installs asynchronously without speaking each progress update. Omnivox
checks files and validates the voice before adding it disabled. In the catalogue,
~e~ toggles enablement, asking which speaker for a shared model, and ~a~ reviews
Apply to both streams. Enablement alone does not restart. Model details also
show these actions near installed/enabled status.

Installation/Apply confirmations offer =yes= and =no= through completion:
~y TAB RET~ confirms, empty ~RET~ declines, and ~C-g~ cancels. ~c~ requests
cancellation; wait for cleanup. The shipped catalogue contains reviewed, pinned,
natively validated models. Unresolved terms or unsupported configurations are
withheld; it is not a live catalogue of every upstream download.

MBROLA offers US1, US2, and US3, with British English en1 included. Downloads
need the updated separately configured development companion on Linux/Windows.
Older hosts keep Piper/Flite catalogues and report missing MBROLA support.
Each database carries its licence and README. Initial installation retains
en1 enabled unless explicitly disabled. Multiple enabled databases can serve
different entries/streams; each request opens its selected database rather
than keeping all enabled databases resident.

RHVoice offers Alan (Scottish English), BDL/CLB (American English), and Ksp
(Indian English), requiring an updated host and separately installed compatible
RHVoice runtime selected in engine settings. Each package contains its English
data and upstream notices. Enable and Apply combines managed voices with external
ones, including SLT. A conflicting external copy is reported, not replaced.
Removal affects the managed package, not external voices or the runtime.

In /Browse voices/, ~+~ changes desired enablement, and ~a~ reviews Apply.
The operation checks both replacement workers, restarts main and notification
speech, and verifies them before committing. Failure restores both previous
configurations. Disabling preserves files and palette references. /Enabled/
changes immediately but /Active/ awaits Apply.

After installation, ~l~ browses, ~+~ enables, and ~a~ reviews managed engines
and both streams. Installation alone neither loads a voice nor changes speech.
Downloads belong to you in Omnivox's per-user storage across executable upgrades.
Failed/interrupted operations retain files for inspection; automatic resume
and package updates are not provided. Uninstall cleanup has its separate
explicit resume action below.

**** Remove or import managed voices
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Disable every speaker in a downloaded Piper, Flite, MBROLA, or RHVoice package
and Apply before ~C-c u~ in its voice browser. Review voices, size, and retained
palette references before confirming. Files still needed by other sessions
remain. Built-in SLT/en1, imported originals, and engine runtimes cannot be
removed here. ~C-c U~ reviews incomplete cleanup for explicit resumption.

The voice browser's ~d~ opens downloads and ~b~ includes built-in Flite SLT.
~i~ imports a completed native-validation operation by ID, initially disabled.
Imported files remain at their validated paths and must stay there. This is
an advanced import, not the catalogue installation or a file-selection wizard.
~C-c r~ shows the last Apply result, ~R~ refreshes, and ~q~ returns.

Apply needs separate main/notification streams from the updated local host.
Clear explicit Piper/Flite file overrides before applying those engines' library
voices. Uncertain native cleanup or commit blocks another Apply and stays
visible in its result.

**** Configure and check an engine
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Under /Startup settings/, /Edit file settings/ opens the bundled local launcher's
engine option in Customize. Piper accepts one ONNX model and matching JSON;
Eloquence/DECtalk accept runtime DLLs; Flite accepts external =.flitevox= files
with individual /Load file/ switches. Use absolute paths as seen by Emacs;
WSL converts them for the selected Windows executable. Keep companion files
beside their runtime/model. Remote settings must be changed on the speech host.

These are explicit overrides, not the complete installed-voice inventory.
No manually selected files can still mean library voices or launcher defaults
are available. A manual Flite file list overrides its installed library.

/Check configured engine/ runs independent discovery using the local launcher's
current configuration, limited to 30 seconds. It retains target, voices, and
diagnostics but neither speaks a sample nor replaces live workers. A failed
Flite file can leave built-in SLT usable; incomplete discovery reports fewer
than the selected files plus SLT. Duplicate external voice names are unsupported.

File settings affect newly started workers. Save in Customize, then explicitly
choose /Restart local speech/ to interrupt this session's two streams when ready.
Refresh live voices afterward. Disabling a Flite file preserves data/references;
new helpers omit it, while existing helpers keep it until restart. Built-in SLT
stays loaded and each worker loads its own enabled external voices. These
switches are not a general per-voice policy or memory measurement.

=OMNIVOX_PIPER_MODEL=, =OMNIVOX_FLITE_VOICES=, runtime environment settings,
and legacy =EMACSVOX_ECI_DLL=/=EMACSVOX_DECTALK_DLL= override file options and
are identified in details. Clearing an option returns to discovery/defaults.
Direct-native executable launches do not consume the bundled launcher's options.

**** Manage the installed Omnivox release
:PROPERTIES:
:TEXINFO_NODE: no
:END:

This manager changes versioned release files, not the running workers or a
voice library's active configuration. On WSL, choose /Manage installed release/
and check /Installation being managed/ and /Location/. That target can differ
from a development build or remote speech server. /Installed engine files/
reports presence; /Check release engine/ tests runtime initialisation and
voice discovery for that release.

Release installation and removal keep current speech running and do not select
another speech server. They do not automatically restart workers. A helper in
use causes removal to fail visibly; close sessions using that release before
retrying. This differs from the library's explicit Apply and the file editor's
/Restart local speech/. Legacy direct-operation restart preferences do not
change the boundary of this explicit installed-release view.

Use /Install engine/ and confirm to verify and install a version-matched
component. Progress belongs to the release view while current-worker status
stays separate. /Refresh release files/ runs a bounded asynchronous file check;
/Check release engine/ discovers voices without auditioning. Refresh after a
changed target before retrying. Completion gives a short notice without
selecting another buffer; /Read last result/ opens retained complete output.

Within details, ~TAB~/~S-TAB~ moves among actions and sections, ~RET~ activates
or toggles, and arrows read visible fields. ~q~ returns to the selected engine
row, ~h~ to Emacsvox settings, and ~?~ to Help. Selection and expansion survive
background refresh. /Refresh status/ or ~g~ in current-worker details asynchronously
requests both live inventories, not a release-file check.

/Uninstall engine/ under /Engine installation/ removes only manager-installed
Flite, RuTTS, Piper, or TGSpeechBox components. It does not remove the core,
built-in engines, or runtime bridges. The whole managed component directory
is removed: move any personal files elsewhere before confirming. External
runtimes/models outside it are untouched and retain their supplier's removal
procedure. Verified downloads remain cached; /Install engine/ reuses a valid
cache for reinstallation.

Operations are asynchronous. The view shows /uninstalling/ or /testing/ and
refreshes on completion or failure. A failed listing retains its last records
and the error while live discovery remains independently available. If a helper
is locked, close the sessions using it and invoke the removal action again.
An interrupted removal with only the expected helper left can resume; directories
containing unrecognised files remain protected.

=etc/omnivox-components.conf= pins names, sizes, and SHA-256 hashes to the
installed core version. The WSL installer rejects mismatched cores, unsafe
archive layout, missing source provenance, and helpers that fail staged
discovery. Components are installed under the same versioned Windows
=LocalAppData= release. It does not invoke =sudo= or edit shell startup.

Component and data boundaries differ:

- Flite includes compact English SLT without an external runtime.
- RuTTS includes compact Russian voices without an external runtime.
- Piper installs engine support; a usable voice also needs a reviewed ONNX
  model and model card, configured separately or through supported library
  management.
- TGSpeechBox is in the Windows x64/ARM64 core with multilingual formant voices,
  calibrated rate, and exact anchors for capitalisation/timed presentation.
  Matching standalone components allow reinstallation.
- RHVoice, Eloquence, and DECtalk bridges do not acquire their external runtimes.
  Supply compatible runtimes under their distribution/licensing terms.
  RHVoice's reviewed catalogue can separately download voice and language
  packages on a supporting local host, as described above. This is distinct
  from runtime acquisition and preserves external installations. Eloquence
  and DECtalk runtime, dictionary, and licence material remain user-supplied.

For terminal management, use =./bin/emacsvox-omnivox-components --list=, then,
for example, =./bin/emacsvox-omnivox-components --install flite=. Multiple
engines can follow =--install= or =--uninstall=.
=./bin/emacsvox-omnivox-components --uninstall flite= removes the managed
directory while retaining its archive. Restart deliberately when the running
session needs newly installed configuration, and use =--test ENGINE= or the
release view's /Check release engine/ to check that target. Direct release
assets remain available for maintenance/recovery, but the manager is the
ordinary component-selection route.

Native Windows x64 is supported with Emacs 30.2 or newer. A development Setup

*** Using a Windows Setup Build
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Run the development Setup executable to install =Emacsvox Windows= for your
account. The wizard identifies Emacsvox and its included Emacs/Omnivox versions.
No administrator privileges or network connection are required. A desktop
shortcut is optional; a Start menu group is created unless disabled for an
unattended installation. The final page explains startup/removal and offers
Test speech for two announcements and Start Emacsvox. Finish runs selected

 development build, closing the Emacsvox using that installation first. Setup
does not close it. Locally edited application files prevent replacement so

retaining personal data by default. Optional cleanup separately lists sizes

*** Guided Windows x64 Installation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

You need PowerShell 5.1 or newer, Git, network access, and working Windows audio
with a speech voice. Put the checkout on a local Windows drive, not a WSL or
network path. To follow this development manual, select its branch:

#+begin_src powershell
git clone --branch ui-experiments https://github.com/bartbunting/emacsvox.git
Set-Location emacsvox
.\bin\emacsvox-install.ps1 -Role Desktop -Check
.\bin\emacsvox-install.ps1 -Role Desktop
#+end_src

Skip cloning for an existing checkout and inspect its branch/local changes
before updating it. The check reports selected Emacs and paths without downloads,
configuration writes, or audio.

The installer reuses native Emacs 30.2 or newer. For a checksum-verified complete
GNU Emacs 31.1 Windows release, use:

#+begin_src powershell
.\bin\emacsvox-install.ps1 -DownloadEmacs -Check
.\bin\emacsvox-install.ps1 -DownloadEmacs
#+end_src

This includes runtime libraries without a compiler/MSYS2. Alternatively select
a separately installed [[https://www.gnu.org/software/emacs/download.html][prebuilt Windows Emacs]] with =-Emacs= and its
=bin/emacs.exe=. =-BuildEmacs= explicitly builds 31.1 through a private MSYS2
UCRT64 toolchain; it can require several gigabytes and substantial downloading.
No source build begins without that choice. The installer then prepares the
pinned Omnivox core and Emacsvox, reusing installed components and verified cache
on later runs.

=-Emacs "C:\path\to\Emacs\bin\emacs.exe"= selects an existing executable.
Explicit =-Emacs=, environment =EMACS=, and =local.mk= must agree and require
native 30.2 or newer. =-DownloadEmacs= and =-BuildEmacs= choose their managed
Emacs instead of saved/PATH selections, reuse a matching complete installation,
and cannot replace an explicit choice. Choose only one.

Per-user defaults are:

- Emacs, Omnivox, isolated profile, and logs under =%LOCALAPPDATA%\Emacsvox\Native=.
- Private build tools under =%LOCALAPPDATA%\Emacsvox\Toolchains\msys2-20260611=.
- Verified archives under =%LOCALAPPDATA%\Emacsvox\Downloads=.
- Data-only =native-install.json= in the checkout, ignored by Git.

=-InstallRoot=, =-ToolchainRoot=, and =-CacheDirectory= choose other local
paths. The MSYS2 tool path must have no spaces; set =-ToolchainRoot= if needed.
Checkout and Emacs paths may contain spaces. Personal initialisation, system
PATH, Windows services, and JAWS settings remain unchanged.

=-Offline -CacheDirectory "C:\path\to\archives"= forbids downloads and verifies
required cached archives before changes. Missing/damaged archives stop it.
Offline supports prebuilt/existing Emacs, not =-BuildEmacs=. Read-only =-Check=
reports the plan without testing cached archives or playing audio.

Source archives are checksum-pinned. MSYS2 compiler packages use signed rolling
repositories, and installed versions are recorded. Managed source builds disable
Lisp native compilation and include runtime DLLs, so launch needs no MSYS2 on PATH.

The final test opens a temporary native Emacs, verifies both streams, speaks
two announcements, and closes that test. Confirm both by listening. After
=-NoAudioCheck=, perform the explicit check before acceptance:

#+begin_src powershell
.\bin\emacsvox.ps1 -Diagnose
.\bin\emacsvox.ps1 -Check
.\bin\emacsvox.ps1
#+end_src

The last command opens the isolated desktop with Windows speech by default.
=OMNIVOX_ENGINE= remains an explicit selection for separately configured
engines. Native optional-engine installation, ARM64, and other native roles
are not supplied by this guided installer.

After source updates, rerun it before launching. It preserves source edits and
refreshes compiled files. Missing/stale compilation stops launch with that
instruction. Keep named build logs after failure. Inspect incomplete installations
before moving or choosing another directory; unknown partial trees are not
overwritten.

Muting JAWS speech does not disable its shortcuts. If ~M-<~ or ~M->~ is
intercepted, try =JAWSKey+3= before the key. Bart's =workstation-config=
repository supplies the separate Emacs-specific JAWS override used on the
test workstation.

*** Manual Native Installation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

This route requires native Emacs 30.2 or newer already installed. It does not
acquire Emacs or replace the guided x64 checks. Set =$Emacsvox= to the absolute

*** Download And Verify Omnivox
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Set =$Platform= for the host. The normal Intel/AMD x64 example is:

#+begin_src powershell
$Version = "1.17.0"
$Platform = "windows-x64" # Use windows-arm64 only on Windows on ARM.
$DownloadDir = Join-Path $env:USERPROFILE "Downloads\omnivox-$Version"
$Archive = "omnivox-$Version-$Platform.zip"
$ReleaseUrl = "https://github.com/bartbunting/omnivox/releases/download/v$Version"

New-Item -ItemType Directory -Force $DownloadDir | Out-Null
$ArchivePath = Join-Path $DownloadDir $Archive
$ChecksumPath = Join-Path $DownloadDir "sha256sums.txt"
Invoke-WebRequest -UseBasicParsing "$ReleaseUrl/$Archive" -OutFile $ArchivePath
Invoke-WebRequest -UseBasicParsing "$ReleaseUrl/sha256sums.txt" -OutFile $ChecksumPath

$Pattern = '\s+\*?' + [regex]::Escape($Archive) + '$'
$ChecksumLine = Get-Content $ChecksumPath |
  Where-Object { $_ -match $Pattern } |
  Select-Object -First 1
if (-not $ChecksumLine) { throw "No published checksum for $Archive" }
$Expected = ($ChecksumLine -split '\s+')[0].ToLowerInvariant()
$Actual = (Get-FileHash -Algorithm SHA256 $ArchivePath).Hash.ToLowerInvariant()
if ($Actual -ne $Expected) { throw "Checksum mismatch for $Archive" }
Write-Host "Checksum OK: $Archive"
#+end_src

Do not extract/run unless the final line reports =Checksum OK=. This unsigned
Windows release may be rejected by policy; stop rather than weakening security.
The existence of an ARM64 Omnivox archive does not extend Emacsvox's supported
native desktop beyond x64.

*** Install And Check The Native Server
:PROPERTIES:
:TEXINFO_NODE: no
:END:

In the same PowerShell, extract everything beneath per-user =LocalAppData=:

#+begin_src powershell
$InstallDir = Join-Path $env:LOCALAPPDATA "Emacsvox\Omnivox\releases\$Version-$Platform"
New-Item -ItemType Directory -Force $InstallDir | Out-Null
Expand-Archive -LiteralPath $ArchivePath -DestinationPath $InstallDir -Force
$Omnivox = Join-Path $InstallDir "omnivox.exe"

foreach ($Required in @(
  $Omnivox,
  (Join-Path $InstallDir "espeak-ng-data\phontab"),
  (Join-Path $InstallDir "third-party-licenses\THIRD-PARTY-NOTICES.md")
)) {
  if (-not (Test-Path -LiteralPath $Required -PathType Leaf)) {
    throw "Incomplete Omnivox installation: $Required"
  }
}

& $Omnivox --version
if ($LASTEXITCODE -ne 0) { throw "Omnivox version check failed" }
& $Omnivox --list-voices
if ($LASTEXITCODE -ne 0) { throw "Omnivox voice discovery failed" }
& $Omnivox --check
if ($LASTEXITCODE -ne 0) { throw "Omnivox audio check failed" }
#+end_src

Require version 1.17.0 or newer, at least one Windows voice, and both tone and
speech. Keep executable, =espeak-ng-data=, and =third-party-licenses= together.
Do not copy/load =omnivox-voices.el= from the archive; that is the upstream
Emacspeak adapter, not Emacsvox's bundled one.

*** Start Native Emacsvox
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Keep the window so =$Omnivox= still identifies the verified binary. Set =$Emacs=
to native =emacs.exe= and =$Emacsvox= if the checkout was not set above:

#+begin_src powershell
$Emacs = "C:\path\to\emacs\bin\emacs.exe"
# If not set above, uncomment and edit the next line:
# $Emacsvox = "C:\path\to\emacsvox"

*** Verify Speech And Report Problems
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Check the isolated native session:

1. Confirm the startup introduction/ready checkpoint is audible.
2. ~C-h v tts-program RET~ should identify the verified executable's absolute path.
3. ~M-x tts-speak-version RET~ speaks the version; ~M-x omnivox-list-voices RET~
   displays Windows voices.
4. ~C-n~/~C-p~ speak line movement, ~C-e s~ stops current speech, and
   ~M-x tts-restart RET~ restores it without process errors.
5. Toggle icons twice with ~M-x emacsvox-toggle-icons RET~. In a session
   starting with icons enabled, the second toggle restores them and plays an
   icon in addition to speech. Preserve the initial preference when testing a
   customised session.

but the server cannot be found in Emacs, confirm the same PowerShell's
=$env:TTS_PROGRAM= is absolute and =Test-Path $env:TTS_PROGRAM= returns =True=.
For a process that exits, retain PowerShell errors, =*Messages*=, Windows
version/architecture, and full =emacs.exe --version= and =omnivox.exe --version=.

After acceptance, put the same selection before setup in your init file:

#+begin_src emacs-lisp
(setenv "TTS_PROGRAM"
        "C:/Users/NAME/AppData/Local/Emacsvox/Omnivox/releases/1.17.0-windows-x64/omnivox.exe")
(load-file "C:/path/to/emacsvox/lisp/emacsvox-setup.el")

Replace both paths. This deliberately starts with an absolute executable.
Adding its directory to =exec-path= is optional until selecting =omnivox= by
short name. Native desktop support remains x64; remote speech is a separate
preview.

** Installing Omnivox From Source
:PROPERTIES:
:TEXINFO_NODE_NAME: Installing Omnivox From Source
:DESCRIPTION: Build when a release archive does not match the host.
:END:

On GNU/Linux/macOS, a source build needs network access for clone, toolchain,
and locked dependencies. Prepare:

- [[https://rustup.rs/][rustup]], with the checked-in =rust-toolchain.toml= selecting Rust.
- Python 3, C/C++, CMake, and Clang/libclang for eSpeak NG and generated data.
- GNU/Linux =pkg-config= and ALSA development headers, commonly
  =libasound2-dev= on Debian/Ubuntu or =alsa-lib-devel= on Fedora.
- macOS Xcode command-line tools, installed with =xcode-select --install=.

Keep Omnivox beside Emacsvox, also matching the WSL layout:

#+begin_example
cd /path/containing/emacsvox
git clone https://github.com/bartbunting/omnivox
cd omnivox
make build
make install
#+end_example

=make build= runs the locked release build and stages matching eSpeak data and
notices. =make install= installs binary/data normally under =~/.cargo/bin=.
Set =OMNIVOX_INSTALL_BIN= only for another Cargo binary directory. A bare
=cargo build= does not produce the complete installation payload.

Make the installed directory visible on =PATH=. No proprietary runtime is
needed for the recommended Linux/Mac route.

** Building Omnivox For WSL2
:PROPERTIES:
:TEXINFO_NODE_NAME: Building Omnivox For WSL2
:DESCRIPTION: Stage the Windows runtime from WSL2.
:END:

This advanced path maintains the reproducible Windows bundle or optional
engine integrations. Ordinary WSL2 installations should use the
[[*Install An Omnivox Windows Release Under WSL2][prebuilt Windows release]]. This source target produces x86-64 Windows.

Requirements are:

- WSL2 with working =powershell.exe= and =wslpath=, plus writable Windows
  =LocalAppData=.
- A Docker client/daemon supporting Linux/AMD64 containers, runnable by the
  WSL user without =sudo=. Docker Desktop's WSL integration is one option.
- Windows .NET Framework 4.7.2 or newer, not merely a modern =dotnet= SDK.
  Visual Studio is unnecessary.
- =git=, GNU =make=, =curl=, =unzip=, =sha256sum=, and standard GNU utilities
  including =awk=, =cmp=, =find=, =readlink=, =sed=, =sort=, and =xargs=.
- Network for the initial Docker image, Rust dependencies, and two
  checksum-pinned NuGet packages. Subsequent builds reuse caches.
- Sibling =emacsvox= and =omnivox= checkouts, or explicit =OMNIVOX_DIR=.
  The clean release target requires the Omnivox source commit recorded for
  the pinned Piper companion in =servers/omnivox-release/toolchain.lock=;
  mismatches fail rather than combining versions. The development route
  accepts current source by omitting Piper. Allow disk space for Docker,
  native/cross builds, and caches.

Rust, MinGW, CMake, Clang/libclang, eSpeak NG, Roslyn, Visual Studio, and .NET
reference assemblies need not be installed in WSL; the controlled toolchain
pins/builds them. Eloquence, DECtalk, and RHVoice runtime/data remain optional
and unnecessary for WinRT.

Check prerequisites with:

#+begin_example
cd /path/to/emacsvox
make verify-windows-omnivox-toolchain
#+end_example

The first run downloads pinned .NET compiler packages, builds the pinned Docker
image, and checks exact Rust, MinGW, libclang, Roslyn, and Framework versions.
It is not a read-only presence check. Failures identify missing host tools or
unsupported Framework before the full build.

With clean Emacsvox and sibling Omnivox tracked files, run:

#+begin_example
cd /path/to/emacsvox
make windows-omnivox
#+end_example

This reproducible release path builds a pinned Windows-GNU executable and
stages a content-addressed runtime under =servers/omnivox-bin=. When the Piper
lock identifies the matching integrations, it includes the checksum-pinned
Piper companion, RHVoice helper without runtime, Flite with CMU US SLT, and
RuTTS with male/female Russian voices. It bundles no Piper model or RuLex.
The payload is also copied to Windows-local storage to avoid WSL filesystem
cost during discovery. It does not download Eloquence, DECtalk, or RHVoice
runtimes or require them for WinRT.

The final live gate starts that exact runtime, discovers Flite SLT and both
RuTTS voices, and requires nonempty WAV synthesis from each helper. Repeat
without rebuilding using =make verify-windows-omnivox-live=.

To register Piper, review its model/card and keep the adjacent =.onnx.json= or
=.json=. Supply the absolute model path while staging:

#+begin_example
OMNIVOX_PIPER_MODEL=/absolute/path/to/voice.onnx make windows-omnivox
#+end_example

Model/configuration are copied to separate content-addressed Windows
=LocalAppData= storage with recorded hashes, not bundled into the runtime.
Omitting that variable installs the companion but leaves Piper unregistered.
After staging, check with a fresh process:

#+begin_example
./servers/omnivox --engine piper --list-voices
#+end_example

Restart both speech processes or Emacs, then inspect running engines with
~C-e H v b~. Piper requires the newly staged server and successfully loaded
model/helper. The direct ~C-e d e~ preference chooser is not a read-only
inventory command; use the browser to inspect without selecting a preference.

For tracked development changes, use the route in
[[*Integration Maintenance][Integration Maintenance]] rather than bypassing the clean-release guard:

#+begin_example
OMNIVOX_RHVOICE_LIBRARY=/mnt/c/path/to/RHVoice.dll \
  OMNIVOX_RHVOICE_DATA=/mnt/c/path/to/RHVoice/data \
  make windows-omnivox-dev
./servers/omnivox --engine flite --list-voices
./servers/omnivox --engine rutts --list-voices
#+end_example

It builds current source, stages RHVoice's helper, Flite SLT, and RuTTS 6.3.3
male/female voices, deliberately omitting the older pinned Piper companion.
RuTTS needs no separate install; RuLex is excluded. RHVoice needs compatible
=RHVoice.dll= and language/voice data. Supplied library/data variables are
validated and Windows path pointers retained beside the local runtime; the
launcher restores them for fresh sessions. Also set =OMNIVOX_RHVOICE_CONFIG=
for a separate configuration directory. These external files are not copied
into the payload. Omnivox's =docs/RHVOICE.md= and =docs/RUTTS.md= give validation
details. Restart after restaging/changing inputs, then inspect with ~C-e H v b~.

Piper tests against newer committed Omnivox use =windows-omnivox-piper-dev=
and a native Windows CI artifact. It requires the published SHA-256 and a
reviewed external model, rejecting dirty or different source. See
[[*Integration Maintenance][Integration Maintenance]] for provenance and the complete command. This does
not alter the reproducible release's pinned companion.

#+begin_example
omnivox --version
omnivox --check
omnivox --list-voices

*** Remote Workstation Speech (Preview)
:PROPERTIES:
:TEXINFO_NODE: no
:END:

<<Remote workstation speech setup>>

Emacs can run on an SSH host while Omnivox, installed voices, and playback stay
on your workstation. This uses Omnivox 1.17.0's =--serve= and Emacsvox's remote
transport. Remote access remains a preview feature.

Create a private token on the workstation. The tool refuses to overwrite or
print an existing token:

#+begin_example
mkdir -p "$HOME/.config/omnivox"
python3 /path/to/omnivox/tools/create_remote_token.py \
    "$HOME/.config/omnivox/remote-token"
#+end_example

Leave the installed server running in a terminal, with the matching Emacsvox
sound-pack directory:

#+begin_example
omnivox --serve --token-file "$HOME/.config/omnivox/remote-token" \
    --sound-root /path/to/emacsvox/sounds
#+end_example

For a Windows service through the WSL launcher, translate both paths:

#+begin_example
/path/to/emacsvox/servers/omnivox --serve \
    --token-file "$(wslpath -w "$HOME/.config/omnivox/remote-token")" \
    --sound-root "$(wslpath -w /path/to/emacsvox/sounds)"
#+end_example

In another workstation terminal, copy the token through verified SSH and open
the reverse forward, replacing =user@emacs-host=:

#+begin_example
ssh user@emacs-host 'mkdir -p ~/.config/omnivox; chmod 700 ~/.config/omnivox'
scp "$HOME/.config/omnivox/remote-token" user@emacs-host:.config/omnivox/remote-token
ssh user@emacs-host 'chmod 600 ~/.config/omnivox/remote-token'
ssh -o ExitOnForwardFailure=yes -o ServerAliveInterval=10 \
    -o ServerAliveCountMax=2 \
    -R 127.0.0.1:6417:127.0.0.1:6417 user@emacs-host
#+end_example

When Omnivox runs on Windows, use Windows OpenSSH for the final connection:
=ssh.exe= from WSL or =ssh= from PowerShell. It must reach Windows loopback;
a WSL client under NAT reaches separate WSL loopback instead. Windows SSH uses
its Windows keys and host-trust configuration.

[[*Installing On A Remote Linux Host][Installing Remote Emacsvox]] provides the remote-only installation and isolated
launcher. =--remote= configures transport before speech starts and needs no
local Omnivox binary. For personal configuration, set before startup:

#+begin_src emacs-lisp
(setq tts-program "omnivox"
      omnivox-remote-host "127.0.0.1"
      omnivox-remote-port 6417
      omnivox-remote-token-file "~/.config/omnivox/remote-token")
#+end_src

~M-x omnivox-remote-connect~ connects/retries, ~M-x omnivox-remote-status~
inspects, and ~M-x omnivox-remote-disconnect~ stops and suspends retries.
Reconnection refreshes voices/routing and discards unfinished speech. Main and
notification retain separate workers. Only one Emacs session owns a service
at a time.

If main connects but notification fails, main remains available while the
missing connection retries. Recovery does not replace working main speech.
=omnivox-remote-auto-reconnect= set to nil disables automatic retry; explicit
disconnect suspends it until another connection. Status retains retry and error
information.

Keep service and forwarded endpoint on loopback; do not enable SSH
=GatewayPorts=. SSH encrypts the transport and the token excludes other remote
host users. To rotate, stop the service, replace both private token files, and
restart. Typing =quit= or interrupting the service terminal stops workers.

Inventory belongs to the workstation; install/manage engines there. Bundled
icons resolve by pack-relative name. Personal sounds outside that directory
and sound uploads are unsupported; no =--sound-root= means no file-based icons.
For an occupied remote port, change the left side of =-R= and match
=omnivox-remote-port=. Authentication failure indicates differing tokens or
excessively broad file permissions; a busy service belongs to another connection.

These retained direct servers support existing installations, not the recommended
first setup or platform matrix:

#+attr_texinfo: :indic code :compact t
- espeak ::

  Direct Linux Tcl server. =make espeak= needs Tclx at runtime, Tcl 8.6
  headers, eSpeak NG development libraries, and C++. Useful for compatibility
  testing; new installations should use Omnivox.
- swiftmac ::

  Direct Swift macOS server, needing Swift 5.9 or newer and =make swiftmac=.
  See =servers/mac-swiftmac/Readme.org= for this alternative to Omnivox's
  AVSpeechSynthesizer engine.
- mac ::

  Legacy Python/PyObjC server. The unset Darwin selector still names it as
  a compatibility default, not an initial-user route. It needs Foundation,
  AppKit, and PyObjCTools.
- outloud ::

  Direct Linux IBM TTS/Eloquence adapter with separately licensed compatible
  runtime. Emacsvox does not distribute it. Voxin availability is described
  at [[https://voxin.oralux.net]].
- dtk-soft ::

  Direct Software DECtalk adapter with separately installed runtime. See
  =servers/software-dtk/Readme.org=. Licensed runtimes are not distributed
  by Emacsvox.

The native Windows audio, standalone Eloquence, and standalone DECtalk bridges
under =servers/= are advanced WSL compatibility paths. Piper is an optional
Omnivox engine/model workflow, not a primary Emacsvox server.

** Backend Diagnostics And Responsibilities
:PROPERTIES:
:TEXINFO_NODE_NAME: Backend Diagnostics And Ownership
:DESCRIPTION: Locate failures and authoritative detail.
:END:

Local server messages/errors remain in diagnostics buffers, hidden from the
ordinary buffer list by default. Use ~C-e H D m~ for main or ~C-e H D n~ for
notification diagnostics, or ~M-x tts-show-diagnostics~ with =Speaker= or
=Notify=. Missing local diagnostics are reported rather than invented.

Set =tts-hide-diagnostic-buffers= to nil in Customize and restart speech to
include them in the ordinary list. Existing diagnostics are retained; custom
buffer switchers may show hidden buffers independently.

Choose the diagnostic at the failed layer:

#+attr_texinfo: :indic asis :compact t
- =omnivox= is not found ::

  In WSL, run =./bin/emacsvox-wsl-install --check= and inspect its saved path.
  On other POSIX systems check =PATH= or an absolute =OMNIVOX_PROGRAM=.
  Keep =espeak-ng-data= and =third-party-licenses= beside the executable.
- =omnivox --check= errors or is inaudible ::

  Diagnose below Emacsvox using Omnivox's
  [[https://github.com/bartbunting/omnivox/blob/main/README.md][build guide]],
  [[https://github.com/bartbunting/omnivox/blob/main/docs/STATUS.md][platform status]], and
  [[https://github.com/bartbunting/omnivox/blob/main/docs/guides/diagnostics.md][diagnostics guide]]. Do not change Emacs configuration before tone/speech work.
- The check passes but Emacsvox is silent ::

  Confirm =TTS_PROGRAM= was =omnivox= before setup loaded, then use
  ~M-x tts-speak-version~. Rerun the WSL installer check for a release
  installation. For development source staging, run
  =make verify-windows-omnivox-runtime= and restart after restaging.
- A process starts and later fails ::

  The POSIX/WSL launcher retains private bounded stderr logs at
  =$XDG_STATE_HOME/emacsvox/omnivox=, normally
  =~/.local/state/emacsvox/omnivox=. Spoken text is excluded unless
  =OMNIVOX_LOG_SYNTHESIS_TEXT= is explicitly enabled; that can expose
  passwords, mail, and documents.
- Speech works but is delayed ::

  ~C-e d D~ enables a private diagnostic log; reproduce one short presentation
  and toggle it off. Default =~/.emacsvox-aural-diagnostics.log= can be changed
  with ~C-u C-e d D~ when enabling. Records =dispatch-sent=,
  =mixer-source-observed=, and =playback-terminal-observed= share a dispatch ID.
  Match it in Omnivox logs to separate submission, queueing, synthesis, and
  mixer-source delay. This Emacs log is off by default because submitted
  speech text is complete. A mixer observation is not physical output;
  device/hardware buffering can add delay. The diagnostics menu's ~l~ also
  exposes the explicit session logging control with its privacy warning.

Emacsvox owns selection, launcher, Windows staging, and its bundled Lisp adapter.
Omnivox owns native builds, engines, CLI, runtime layout, and protocols.
Backend-local READMEs document compatibility adapters and licensed runtimes.
Use those owning references for versioned details instead of duplicating their
contracts in first-installation instructions.
