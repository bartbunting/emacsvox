* Speech Backends
:PROPERTIES:
:TEXINFO_NODE_NAME: Speech Backends
:DESCRIPTION: Select, install, and verify a speech server.
:END:

Emacsvox needs a speech-server process.  For a new installation, use
*Omnivox*.  Omnivox is the server that Emacsvox talks to; the engine
that produces speech underneath it is platform-specific.  The normal engine
is eSpeak NG on GNU/Linux, AVSpeechSynthesizer on macOS, and WinRT
SpeechSynthesizer on Windows.

Omnivox 1.7.0 is the minimum supported release for Emacsvox 2026.9.2.  A
newer compatible Omnivox release may be used, but the binary examples and
guided WSL2 installer below pin the tested 1.7.1 artifacts exactly.

For a first installation, follow the linear procedure in
@@texinfo:@ref{Installation}@@.  Return here when you need platform-specific build
details, compatibility servers, or deeper diagnostics.  Omnivox build
internals, engine behavior, and versioned protocols are documented and
maintained in
[[https://github.com/bartbunting/omnivox][the Omnivox repository]].

** Supported Platform Routes
:PROPERTIES:
:TEXINFO_NODE_NAME: Supported Platform Routes
:DESCRIPTION: Choose the maintained route for this machine.
:END:

The following table describes Emacsvox support, not every platform that the
Omnivox project can build.  ``Host check required'' means that automated build
and archive verification does not prove playback through the user's audio
device; an audible ~omnivox --check~ on that machine remains the acceptance
test.

#+attr_texinfo: :columns .18 .31 .51
| Emacs platform | Recommended route | Current support evidence |
|---+---+---|
| GNU/Linux x86-64 with an Ubuntu 24.04-compatible runtime | Omnivox 1.7.1 release archive using eSpeak NG | The published archive is built and verified on Ubuntu 24.04. Compatible glibc, libstdc++, libgcc, and ALSA runtime libraries are required; the audible host check remains required. |
| Other GNU/Linux systems | Source-built Omnivox using eSpeak NG | Use the source route for Linux ARM64, an older distribution ABI, or a host that cannot run the published x86-64 archive. |
| macOS on Apple silicon | Omnivox 1.7.1 release archive using AVSpeechSynthesizer | The published ARM64 archive is built and verified on a native macOS runner; the audible host check remains required. |
| macOS on Intel | Omnivox 1.7.1 release archive using AVSpeechSynthesizer | The published x64 archive is built and verified on a native macOS runner; the audible host check remains required. |
| Emacs in WSL2 on x86-64 Windows | Omnivox 1.7.1 Windows x64 release archive using WinRT | The published archive is checksum-protected and release CI verifies its architecture, adjacent data, WinRT and eSpeak synthesis.  The audible host check remains required. |
| Emacs in WSL2 on Windows on ARM | Omnivox 1.7.1 Windows ARM64 release archive using WinRT | Release CI verifies the ARM64 archive, adjacent data, WinRT and eSpeak synthesis, and the guided installer selects it automatically.  A complete WSL2 host and audible check remains required. |

Initial users should use WSL2; evaluators can follow the bounded trial below. |

The release-archive routes below are the shortest installation on matching
GNU/Linux, macOS, and WSL2 hosts.  A bare executable, a repository tag, or an
unpackaged CI artifact is not a complete installation: keep the release's
runtime data and notices beside the executable.

Do not set ~OMNIVOX_ENGINE~ during initial setup.  Its empty value selects
the normal platform engine above.  Engine routing and optional Piper,
Eloquence, or DECtalk support are later customizations, not prerequisites for
first speech.

*Remote workstation speech (development builds).*  Emacs can run on an SSH
host while Omnivox, its installed voices, and playback remain on the computer
you are using.  This requires the new ~--serve~ option and the matching
Emacsvox remote transport; the published Omnivox 1.7.1 binary does not include
it.  Keep the ordinary local setup until those development builds are installed.

On your workstation, create a private token once.  The creation tool refuses
to overwrite an existing token or print its contents:

#+begin_example
mkdir -p "$HOME/.config/omnivox"
python3 /path/to/omnivox/tools/create_remote_token.py \
    "$HOME/.config/omnivox/remote-token"
#+end_example

Start your installed Omnivox in a terminal and leave it running.  Give it the
sound directory from the same Emacsvox sound-pack installation used by remote
Emacs:

#+begin_example
omnivox --serve --token-file "$HOME/.config/omnivox/remote-token" \
    --sound-root /path/to/emacsvox/sounds
#+end_example

For a Windows service started through the WSL Emacsvox launcher, translate
both paths for the Windows process:

#+begin_example
/path/to/emacsvox/servers/omnivox --serve \
    --token-file "$(wslpath -w "$HOME/.config/omnivox/remote-token")" \
    --sound-root "$(wslpath -w /path/to/emacsvox/sounds)"
#+end_example

In another workstation terminal, copy the token over your verified SSH
connection and open the reverse forward.  Replace ~user@emacs-host~ with the
machine where Emacs will run:

#+begin_example
ssh user@emacs-host 'mkdir -p ~/.config/omnivox; chmod 700 ~/.config/omnivox'
scp "$HOME/.config/omnivox/remote-token" user@emacs-host:.config/omnivox/remote-token
ssh user@emacs-host 'chmod 600 ~/.config/omnivox/remote-token'
ssh -o ExitOnForwardFailure=yes -o ServerAliveInterval=10 \
    -o ServerAliveCountMax=2 \
    -R 127.0.0.1:6417:127.0.0.1:6417 user@emacs-host
#+end_example

If Omnivox runs on Windows, open the final SSH connection with Windows
OpenSSH (~ssh.exe~ from WSL, or ~ssh~ from PowerShell).  Its forward must
reach Windows loopback.  A WSL SSH client under NAT reaches WSL's separate
loopback instead.  Windows OpenSSH uses your Windows SSH keys and host-trust
configuration.

For a remote-only Linux installation and isolated launch commands, follow
@@texinfo:@ref{Installing Remote Emacsvox}@@.  The ~--remote~ launcher supplies
the connection options before initializing speech and needs no local Omnivox
executable.

For a personal Emacs configuration, set these options before starting Emacsvox:

#+begin_src emacs-lisp
(setq tts-program "omnivox"
      omnivox-remote-host "127.0.0.1"
      omnivox-remote-port 6417
      omnivox-remote-token-file "~/.config/omnivox/remote-token")
#+end_src

Use ~M-x omnivox-remote-connect~ to connect or retry manually,
~M-x omnivox-remote-status~ to inspect the connection, and
~M-x omnivox-remote-disconnect~ to stop it and suspend retries.  After a lost
connection, Emacsvox reconnects with fresh voice and routing information;
unfinished speech is discarded.  Foreground and notification speech retain
separate workers.  Only one Emacs session may own a service at a time.

The service and forwarded endpoint must stay on loopback.  Do not enable SSH
~GatewayPorts~.  SSH encrypts the connection; the private token also excludes
other users on the remote host.  To rotate it, stop the service, replace both
private token files, and restart.  Typing ~quit~ in the service terminal or
interrupting it stops its workers.

The voice inventory describes your workstation.  Install engines and use the
engine-module manager on that workstation.  Bundled icons resolve there by
pack-relative name; personal sounds outside the bundled sound directory and
sound uploads are not supported in this first version.  Omitting
~--sound-root~ disables file-based icons.  If the remote port is occupied,
choose another port on the left side of ~-R~ and set ~omnivox-remote-port~ to
match.  An authentication failure means the token copies differ or their file
permissions are too broad; a busy service still belongs to another connection.

** Install Omnivox From A Release Binary
:PROPERTIES:
:TEXINFO_NODE_NAME: Installing An Omnivox Release Binary
:DESCRIPTION: Install the verified Omnivox 1.7.1 archive.
:END:

Use this route for GNU/Linux x86-64 with an Ubuntu 24.04-compatible runtime,
macOS on Apple silicon, or macOS on Intel.  The
[[https://github.com/bartbunting/omnivox/releases/tag/v1.7.1][Omnivox 1.7.1 release]]
provides these archive names:

#+attr_texinfo: :columns .28 .27 .45
| Host | Set ~platform~ to | Archive |
|---+---+---|
| GNU/Linux x86-64 | ~linux-x64~ | ~omnivox-1.7.1-linux-x64.tar.gz~ |
| macOS Apple silicon | ~macos-arm64~ | ~omnivox-1.7.1-macos-arm64.tar.gz~ |
| macOS Intel | ~macos-x64~ | ~omnivox-1.7.1-macos-x64.tar.gz~ |

Run ~uname -m~ if the Mac architecture is uncertain: ~arm64~ identifies Apple
silicon and ~x86_64~ identifies Intel.  Create a download directory, select the
matching platform value, and fetch both the archive and published checksum
file:

#+begin_example
mkdir -p "$HOME/Downloads/omnivox-1.7.1"
cd "$HOME/Downloads/omnivox-1.7.1"
omnivox_version=1.7.1
platform=linux-x64
archive="omnivox-${omnivox_version}-${platform}.tar.gz"
release_url="https://github.com/bartbunting/omnivox/releases/download/v${omnivox_version}"
curl -fLO "$release_url/$archive"
curl -fLO "$release_url/sha256sums.txt"
#+end_example

Replace ~linux-x64~ with the matching macOS value from the table.  Verify the
selected archive before extracting it.  On GNU/Linux, run:

#+begin_example
grep "  $archive$" sha256sums.txt | sha256sum --check -
#+end_example

On macOS, use its installed ~shasum~ command instead:

#+begin_example
grep "  $archive$" sha256sums.txt | shasum -a 256 --check
#+end_example

The command must name the archive and report ~OK~.  If it does not, remove the
download and do not run it.  Extract the verified payload into a versioned
directory and keep every supplied directory beside the executable:

#+begin_example
install_dir="$HOME/.local/opt/omnivox-${omnivox_version}"
mkdir -p "$install_dir"
tar -xzf "$archive" -C "$install_dir"
chmod 755 "$install_dir/omnivox"
export PATH="$install_dir:$PATH"
#+end_example

Add the same ~PATH~ entry to the shell startup file used to launch Emacs so it
remains available in later sessions.  The extracted directory contains
~omnivox~, ~espeak-ng-data~, ~third-party-licenses~, and
~omnivox-voices.el~.  Emacsvox uses its own bundled Lisp adapter, so do not
load or copy the release's ~omnivox-voices.el~ into Emacsvox.

Now prove the installed binary before starting Emacsvox:

#+begin_example
omnivox --version
omnivox --check
omnivox --list-voices
#+end_example

The version must report 1.7.0 or newer, and the check must produce both its
tone and spoken confirmation.  The macOS archives are not code-signed or notarized; if
local security policy refuses the verified binary, use the source route below
rather than weakening that policy.  On GNU/Linux, a missing runtime library or
incompatible glibc also means that the source route is the appropriate path.

For Emacs running under WSL2, continue to
@@texinfo:@ref{Installing An Omnivox Windows Release Under WSL2}@@.  That route
uses the verified Windows archive without requiring a compiler or Docker.

** Install An Omnivox Windows Release Under WSL2
:PROPERTIES:
:TEXINFO_NODE_NAME: Installing An Omnivox Windows Release Under WSL2
:DESCRIPTION: Use the matching verified Windows archive without a build toolchain.
:END:

This is the recommended WSL2 route for ordinary use on x86-64 Windows and
Windows on ARM.  From the Emacsvox checkout, inspect the planned installation
without changing anything:

#+begin_example
./bin/emacsvox-wsl-install --check
#+end_example

The doctor detects the Windows architecture, chooses the matching Omnivox
1.7.1 archive, and reports the Emacs and per-user paths it will use.  If Linux
packages are missing, it prints one ~apt~ command for you to review and run.
Working ~powershell.exe~ and ~wslpath~ interoperation are required.  After
resolving any reported prerequisite, run:

#+begin_example
./bin/emacsvox-wsl-install
#+end_example

The release manifest ~etc/wsl-install.conf~ pins the Omnivox version, GitHub
release URL, x64 and ARM64 archive names, and both SHA-256 hashes.  The installer
asks Windows for its architecture, chooses that matching published archive, and
verifies its pinned hash; it does not build Omnivox from source.

The installer downloads and checksum-verifies the appropriate Windows archive,
installs the complete payload below the Windows user's ~LocalAppData~, and
records its absolute WSL path in
~$XDG_CONFIG_HOME/emacsvox/omnivox-program~, normally
~~/.config/emacsvox/omnivox-program~.  It does not invoke ~sudo~ or edit a shell
startup file.  It also compiles Emacsvox, runs the non-audible launcher
diagnostic, and finishes with the audible speech-server check.  The normal
acceptance condition is hearing both its tone and speech.

This binary route does not need the Omnivox source checkout, Docker, Rust,
MinGW, Visual Studio, Windows .NET Framework, or an optional/proprietary speech
runtime.  WinRT speech is included in Windows.  Use
~./bin/emacsvox-wsl-install --no-audio-check~ only for a controlled or headless
installation where a separate audible check will be performed later.

*** Manual Release Installation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

The following procedure is the manual equivalent.  Use it when reviewing the
installer's actions, working around a local restriction, or repairing one
layer independently.  It needs ~curl~, ~unzip~, ~sha256sum~, and working
~powershell.exe~ and ~wslpath~ interoperation.  The commands show Windows x64;
on Windows on ARM, use ~windows-arm64~ in both the archive and versioned install
directory and verify that archive's published checksum.

Download the Windows x64 archive and the release checksum file in WSL:

#+begin_example
mkdir -p "$HOME/Downloads/omnivox-1.7.1"
cd "$HOME/Downloads/omnivox-1.7.1"
omnivox_version=1.7.1
archive="omnivox-${omnivox_version}-windows-x64.zip"
release_url="https://github.com/bartbunting/omnivox/releases/download/v${omnivox_version}"
curl -fLO "$release_url/$archive"
curl -fLO "$release_url/sha256sums.txt"
grep "  $archive$" sha256sums.txt | sha256sum --check -
#+end_example

The final command must name the archive and report ~OK~.  If it does not,
remove the download and do not run it.  Install the complete archive in a
versioned directory on the Windows filesystem:

#+begin_example
windows_local_app_data="$(powershell.exe -NoProfile -NonInteractive \
  -Command '[Environment]::GetFolderPath("LocalApplicationData")' | tr -d '\r')"
install_dir="$(wslpath -u "$windows_local_app_data")/Emacsvox/Omnivox/releases/$omnivox_version-windows-x64"
mkdir -p "$install_dir"
unzip -q -o "$archive" -d "$install_dir"
chmod 755 "$install_dir/omnivox.exe"
config_home=${XDG_CONFIG_HOME:-"$HOME/.config"}
mkdir -p "$config_home/emacsvox"
printf '%s\n' "$install_dir/omnivox.exe" > \
  "$config_home/emacsvox/omnivox-program"
#+end_example

Keep ~omnivox.exe~, ~espeak-ng-data~, and ~third-party-licenses~ together in
that directory.  Do not copy or load the archive's ~omnivox-voices.el~;
Emacsvox uses its bundled adapter.  The data-only configuration file makes the
selection persistent without changing shell initialization.  Use
~$XDG_CONFIG_HOME~ instead of ~~/.config~ when it is set.  An explicit
~OMNIVOX_PROGRAM~ remains a temporary override and takes precedence over this
file.

From the Emacsvox checkout, verify the selected release and listen to its
physical audio check:

#+begin_example
./servers/omnivox --version
./servers/omnivox --list-voices
./servers/omnivox --check
#+end_example

The version must report 1.7.0 or newer.  The check must produce both its tone
and spoken confirmation.  Release CI verifies the downloaded archive, Windows x64
architecture, adjacent eSpeak data, voice discovery, and headless synthesis
through both WinRT and eSpeak, but only this audible check proves the local
audio path.  The Windows archive is not code-signed.  If Windows security or
local policy refuses it, do not weaken that policy to complete the install.

The generic Omnivox 1.7.1 archive includes the portable RHVoice helper, but not
the RHVoice runtime, language data, or voices.  It does not contain the optional
Piper, Flite, or RuTTS companions; none is needed for normal WinRT speech.
Omnivox 1.7.1 publishes separate matching companions for those engines.
Emacsvox's clean source-build route below verifies and stages the official
Piper companion and builds RHVoice, Flite, and RuTTS from the matching 1.7.1
source.  A Piper voice model and the RHVoice runtime and voices remain separate
user-supplied files.  Flite and RuTTS need no external runtime installation in
the source-built bundle.  Eloquence and DECtalk remain separately licensed,
user-supplied runtimes.

*** Optional Omnivox Engine Modules
:PROPERTIES:
:TEXINFO_NODE_NAME: Optional Omnivox Engine Modules
:DESCRIPTION: Install, check, remove, and reinstall optional engines from Emacs.
:END:

The ordinary WSL2 archive is the Omnivox core, not a claim that every supported
engine is installed.  It keeps first speech small while matching companion
archives provide engines that are larger, experimental, architecture-specific,
or incomplete without separately chosen data.

From a running Emacsvox session, open:

#+begin_example
M-x emacsvox-omnivox-manage-components RET
#+end_example

You can also press @@texinfo:@kbd{C-e H}@@ for Aural Home and then
@@texinfo:@kbd{I}@@ on /Omnivox engine modules/.  The spoken table reports each
engine as installed, downloadable, unavailable on this architecture, needing a
core update, or needing a separately supplied runtime or model.  /Release
state/ describes the managed release installation.  /Browse and try voices/
reports the active speech server, which can use a different installation, such
as a development runtime or a remote workstation.  Installing a module here
changes the managed release only.  Move to an engine row, then choose the task
you want:

- To install a /not installed/ module, press @@texinfo:@kbd{i}@@ and confirm.  The
  manager downloads the version matched to your Omnivox core, verifies it, and
  announces when installation is complete.  Its state changes to /installing/
  immediately and stays that way if you refresh or reopen the manager.
- To check any engine, press @@texinfo:@kbd{t}@@.  Emacsvox announces how many
  voices Omnivox found and selects an accessible buffer containing the complete
  list.  If the check fails, it announces and displays the actual diagnostic
  instead of only an exit code.  Press @@texinfo:@kbd{q}@@ to return to the
  manager or @@texinfo:@kbd{h}@@ for Aural Home.
- To remove an /installed/ module, press @@texinfo:@kbd{u}@@ and confirm.  This
  is available only for Flite, RuTTS, Piper, and TGSpeechBox modules installed
  by this manager.  It cannot remove the Omnivox core, built-in engines, or
  runtime bridges.

Removal keeps the verified download in the local cache.  If you change your
mind, select the module again---its state will now be /not installed/---and press
@@texinfo:@kbd{i}@@ to reinstall it.  A valid cached download is reused.

The module's whole managed directory is removed.  Move anything you placed
inside that directory somewhere else before confirming.  User-supplied
runtimes and models stored outside it are not touched; remove those separately
using their supplier's instructions.  Before removal, the manager announces
the operation and briefly stops its active Omnivox speech streams so Windows
can release the module helper.  It restores speech when removal finishes,
including after an error.  After a successful installation, it also refreshes
the table and restarts a running Omnivox server.  Operations run asynchronously
so Emacs remains responsive.  The table shows /uninstalling/ during removal and
/testing/ during a voice check.  Completion or failure refreshes the state;
if that refresh fails, the last known state remains with a spoken error.

If a removal reports that its helper is still in use, close any other Emacsvox
or Omnivox session using that release and press @@texinfo:@kbd{u}@@ again.  The
manager safely recognizes an interrupted removal when the expected helper is
the only file left; it continues to refuse directories containing unrecognized
files.

The manager reads =etc/omnivox-components.conf=.  Every archive name, byte size,
and SHA-256 hash is pinned to the same Omnivox version as the installed core.
The WSL2 installer rejects a mismatched core, an unsafe archive layout, missing
source provenance, or a helper that cannot pass its staged voice-discovery
check.  It then installs the module below the same versioned Windows
=LocalAppData= release directory.  It does not invoke =sudo= or edit shell
startup files.

The choices have different boundaries:

- Flite includes its compact English SLT voice and needs no external runtime.
- RuTTS includes its compact Russian voices and needs no external runtime.
- Piper installs native engine support, but appears only after you separately
  review and configure an ONNX voice model and its model card.
- TGSpeechBox is an explicitly experimental multilingual formant engine.  The
  1.7.1 module calibrates rate control to the Eloquence scale and supplies exact
  requested text anchors for capitalization and timed presentation.
- RHVoice, Eloquence, and DECtalk use distributable bridges, but Emacsvox never
  downloads their external runtimes, voices, dictionaries, or licence material.
  Supply those only when you have the appropriate distribution and licence.

For a terminal-only installation, run
=./bin/emacsvox-omnivox-components --list= and then, for example,
=./bin/emacsvox-omnivox-components --install flite=.  Multiple module names may
follow =--install= or =--uninstall=.  For example, use
=./bin/emacsvox-omnivox-components --uninstall flite= to remove the managed
Flite directory while retaining its cached archive.  Restart Omnivox after a
terminal installation or removal, then use =--test ENGINE= or the Emacs
manager's @@texinfo:@kbd{t}@@ command.  The direct Omnivox release assets remain
available for maintainers and recovery, but the manager is the recommended way
to select them.

** Trying Native Windows Emacsvox
:PROPERTIES:
:TEXINFO_NODE_NAME: Trying Native Windows Emacsvox
:DESCRIPTION: Evaluate native Windows Emacs and Omnivox with bounded checks.
:END:

This is a /preview evaluation/, not yet the recommended first installation.
The guided provider supports Windows x64 and runs entirely on Windows.  WSL,
Docker, Rust, and a system MSYS2 installation are not required.

*** Guided Windows x64 Installation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

You need Windows PowerShell 5.1 or newer, Git for cloning, network access, and
working Windows audio with an installed speech voice.  Put the checkout on a
local Windows drive, rather than a WSL or network path.  From PowerShell:

#+begin_src powershell
git clone https://github.com/bartbunting/emacsvox.git
Set-Location emacsvox
.\bin\emacsvox-install.ps1 -Role Desktop -Check
.\bin\emacsvox-install.ps1 -Role Desktop
#+end_src

Skip cloning if you already have a Windows checkout and change into it instead.
The check reports the selected Emacs and planned paths without downloading,
writing configuration, or playing audio.

The installer reuses native Emacs 31 or newer.  If none is selected, it builds
GNU Emacs 31.1 using a private MSYS2 UCRT64 toolchain, then installs the pinned
Omnivox core and prepares Emacsvox.  Allow several gigabytes of disk space and
time for the initial downloads and source build.  Later runs reuse the
installed Emacs and cached archives.  An existing native Emacs does not need
MSYS2 to prepare Emacsvox.

To select an existing Emacs explicitly, add
=-Emacs "C:\path\to\Emacs\bin\emacs.exe"=.  Explicit =-Emacs=, =EMACS= environment,
and =local.mk= selections must agree and require native Emacs 31 or newer.
=-BuildEmacs= selects the managed source build instead of a saved or PATH
selection; it reuses a complete managed build when one exists.  It cannot
replace an explicit selection.

Installation is per-user.  The defaults are:

- Emacs, Omnivox, the isolated profile, and logs below
  =%LOCALAPPDATA%\Emacsvox\Native=.
- Private build tools below =%LOCALAPPDATA%\Emacsvox\Toolchains\msys2-20260611=.
- Verified archive cache below =%LOCALAPPDATA%\Emacsvox\Downloads=.
- A data-only =native-install.json= in this checkout, ignored by Git.

=-InstallRoot=, =-ToolchainRoot=, and =-CacheDirectory= select other local
Windows directories.  The MSYS2 build-tool path must not contain spaces;
choose =-ToolchainRoot= if the default does.  Checkout and installed Emacs
paths may contain spaces.  The installer leaves personal Emacs initialization,
system PATH, Windows services, and JAWS settings alone.

The source archives are checksum-pinned.  MSYS2 compiler packages come from
its signed rolling repositories; their installed versions are recorded with
the build.  Lisp native compilation is disabled in this preview.  The built
Emacs includes its runtime DLLs, so launching it does not need MSYS2 on PATH.

The default final check opens a temporary native Emacs window, verifies both
speech lanes, speaks two announcements, and closes that test window.  Confirm
that you hear both announcements.  =-NoAudioCheck= skips this step when needed;
run the explicit check before accepting speech:

#+begin_src powershell
.\bin\emacsvox.ps1 -Diagnose
.\bin\emacsvox.ps1 -Check
.\bin\emacsvox.ps1
#+end_src

The last command opens the isolated native preview.  It uses Windows speech
by default.  An explicit =OMNIVOX_ENGINE= environment selection remains
available for separately configured engines.  Native optional-engine
installation, ARM64, and other native Windows roles are not provided by this
guided preview.

After pulling source changes, rerun the installer before launching.  It
preserves source changes and refreshes the compiled files.  Missing or stale
compiled files stop launch with instructions to rerun installation.  For a
failed build, retain the logs under the reported build directory.  Inspect an
incomplete installation before moving it aside or selecting a new directory;
the installer does not overwrite an unknown partial tree.

JAWS speech muting does not disable its keyboard shortcuts.  If =M-<= or
=M->= is intercepted, test with =JAWSKey+3= before the shortcut.  Bart's
=workstation-config= repository supplies the separately installed,
Emacs-specific JAWS override used on the test workstation.

*** Manual Native Evaluation
:PROPERTIES:
:TEXINFO_NODE: no
:END:

The following manual procedure remains available for an already installed
native Windows Emacs 31 or newer.  It does not acquire Emacs or replace the
guided x64 checks above.  Set =$Emacsvox= to the checkout's absolute Windows
path and continue in one PowerShell window.

*** Download And Verify Omnivox
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Set ~$Platform~ for the computer.  The example below uses the usual Intel or
AMD Windows x64 archive:

#+begin_src powershell
$Version = "1.7.1"
$Platform = "windows-x64" # Use windows-arm64 only on Windows on ARM.
$DownloadDir = Join-Path $env:USERPROFILE "Downloads\omnivox-$Version"
$Archive = "omnivox-$Version-$Platform.zip"
$ReleaseUrl = "https://github.com/bartbunting/omnivox/releases/download/v$Version"

New-Item -ItemType Directory -Force $DownloadDir | Out-Null
$ArchivePath = Join-Path $DownloadDir $Archive
$ChecksumPath = Join-Path $DownloadDir "sha256sums.txt"
Invoke-WebRequest -UseBasicParsing "$ReleaseUrl/$Archive" -OutFile $ArchivePath
Invoke-WebRequest -UseBasicParsing "$ReleaseUrl/sha256sums.txt" -OutFile $ChecksumPath

$Pattern = '\s+\*?' + [regex]::Escape($Archive) + '$'
$ChecksumLine = Get-Content $ChecksumPath |
  Where-Object { $_ -match $Pattern } |
  Select-Object -First 1
if (-not $ChecksumLine) { throw "No published checksum for $Archive" }
$Expected = ($ChecksumLine -split '\s+')[0].ToLowerInvariant()
$Actual = (Get-FileHash -Algorithm SHA256 $ArchivePath).Hash.ToLowerInvariant()
if ($Actual -ne $Expected) { throw "Checksum mismatch for $Archive" }
Write-Host "Checksum OK: $Archive"
#+end_src

Do not extract or run the archive unless the last line reports ~Checksum OK~.
The Windows release is not code-signed.  If Windows security or local policy
refuses it, stop rather than weakening that policy.

*** Install And Check The Native Server
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Continue in the same PowerShell window.  Extract the complete release into a
versioned directory below the current user's ~LocalAppData~:

#+begin_src powershell
$InstallDir = Join-Path $env:LOCALAPPDATA "Emacsvox\Omnivox\releases\$Version-$Platform"
New-Item -ItemType Directory -Force $InstallDir | Out-Null
Expand-Archive -LiteralPath $ArchivePath -DestinationPath $InstallDir -Force
$Omnivox = Join-Path $InstallDir "omnivox.exe"

foreach ($Required in @(
  $Omnivox,
  (Join-Path $InstallDir "espeak-ng-data\phontab"),
  (Join-Path $InstallDir "third-party-licenses\THIRD-PARTY-NOTICES.md")
)) {
  if (-not (Test-Path -LiteralPath $Required -PathType Leaf)) {
    throw "Incomplete Omnivox installation: $Required"
  }
}

& $Omnivox --version
if ($LASTEXITCODE -ne 0) { throw "Omnivox version check failed" }
& $Omnivox --list-voices
if ($LASTEXITCODE -ne 0) { throw "Omnivox voice discovery failed" }
& $Omnivox --check
if ($LASTEXITCODE -ne 0) { throw "Omnivox audio check failed" }
#+end_src

The version must report 1.7.0 or newer, voice discovery must list at least one
Windows voice, and the final check must produce both a tone and spoken confirmation.
Keep ~omnivox.exe~, ~espeak-ng-data~, and ~third-party-licenses~ together.
Do not copy or load the archive's ~omnivox-voices.el~: it is the adapter for
upstream Emacspeak, while Emacsvox supplies its own adapter.

*** Start Native Emacsvox
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Keep the same PowerShell window so ~$Omnivox~ still identifies the verified
executable.  Set ~$Emacs~ to the native ~emacs.exe~.  If this window did not
create the Emacsvox checkout above, also set ~$Emacsvox~ to that checkout:

#+begin_src powershell
$Emacs = "C:\path\to\emacs\bin\emacs.exe"
# If not set above, uncomment and edit the next line:
# $Emacsvox = "C:\path\to\emacsvox"

& $Emacs --version
if ($LASTEXITCODE -ne 0) { throw "Could not run native Emacs" }
$env:TTS_PROGRAM = $Omnivox
& $Emacs -Q --no-splash --load "$Emacsvox\lisp\emacsvox-setup.el"
#+end_src

The Emacs version must be 31 or newer.  Use ~emacs.exe~, rather than
~runemacs.exe~, for this first trial so startup errors remain visible in the
PowerShell window.  Loading ~emacsvox-setup.el~ directly is intentional: the
repository's ~bin/emacsvox~ launcher is a POSIX shell script.  The guided
native entry point is ~bin/emacsvox.ps1~; this subsection describes the manual
alternative.

*** Accept Or Report The Trial
:PROPERTIES:
:TEXINFO_NODE: no
:END:

A successful trial satisfies every item below:

1. Emacsvox speaks its startup introduction.

2. @@texinfo:@kbd{C-h v tts-program RET}@@ displays the absolute path to the
   verified ~omnivox.exe~.

3. @@texinfo:@kbd{M-x tts-speak-version RET}@@ speaks the Omnivox version
   response, and @@texinfo:@kbd{M-x omnivox-list-voices RET}@@ displays the
   Windows voices.

4. @@texinfo:@kbd{C-n}@@ and @@texinfo:@kbd{C-p}@@ speak ordinary line
   movement, @@texinfo:@kbd{C-e s}@@ stops current speech, and
   @@texinfo:@kbd{M-x tts-restart RET}@@ restores speech without a process
   error.

5. Type @@texinfo:@kbd{M-x emacsvox-toggle-icons RET}@@ twice.  The second
   toggle, which turns icons back on, plays a short auditory icon in addition
   to plain speech.

If the direct ~--check~ fails, diagnose Omnivox or Windows audio before
starting Emacs.  If it succeeds but Emacsvox reports that it cannot find the
speech server, confirm in the same PowerShell window that
~$env:TTS_PROGRAM~ contains the absolute executable path and that
~Test-Path $env:TTS_PROGRAM~ returns ~True~.  If the process starts and then
exits, retain the PowerShell error, the Emacs ~*Messages*~ buffer, Windows
version and architecture, the complete ~emacs.exe --version~ output, and
~omnivox.exe --version~ output.

After a successful trial, the same absolute selection can be placed before
loading Emacsvox in the user's Emacs initialization file:

#+begin_src emacs-lisp
(setenv "TTS_PROGRAM"
        "C:/Users/NAME/AppData/Local/Emacsvox/Omnivox/releases/1.7.1-windows-x64/omnivox.exe")
(load-file "C:/path/to/emacsvox/lisp/emacsvox-setup.el")
#+end_src

Replace both example paths.  This initial configuration deliberately uses an
absolute executable path.  Adding the Omnivox directory to ~exec-path~ is
optional and is needed only when later selecting it by the short name
~omnivox~.  A successful report is evidence for promoting native Windows out
of preview; it does not silently change the support status on its own.

** Installing Omnivox From Source
:PROPERTIES:
:TEXINFO_NODE_NAME: Installing Omnivox From Source
:DESCRIPTION: Build when a release archive does not match the host.
:END:

Use this route on GNU/Linux and macOS.  It requires network access for the
initial clone, Rust toolchain, and locked dependency downloads.

Install these prerequisite classes before building:

- [[https://rustup.rs/][rustup]]; the checked-in
   ~rust-toolchain.toml~ selects the supported Rust release.

- Python 3, a C and C++ toolchain, CMake, and Clang with libclang.  The supported
   build wrapper uses these to build and stage eSpeak NG and its generated data.

- On GNU/Linux, ~pkg-config~ and ALSA development headers.  The ALSA
   package is commonly named ~libasound2-dev~ on Debian or Ubuntu and
   ~alsa-lib-devel~ on Fedora.

- On macOS, the Xcode command-line tools.  Install them with
   ~xcode-select --install~ if they are absent.

Keep the two repositories beside one another; this also matches the WSL2
release layout:

#+begin_example
cd /path/containing/emacsvox
git clone https://github.com/bartbunting/omnivox
cd omnivox
make build
make install
#+end_example

~make build~ performs the locked release build and stages the matching
eSpeak data and third-party notices.  ~make install~ installs the
binary and those adjacent directories, normally below ~~/.cargo/bin~.
Set ~OMNIVOX_INSTALL_BIN~ before ~make install~ only when the Cargo
binary directory is elsewhere.  Do not use a bare ~cargo build~ as the
installation procedure; it does not create the complete staged payload.

Make the install directory visible on ~PATH~ before continuing.  No
proprietary speech runtime is needed for the recommended Linux or macOS path.

** Building Omnivox For WSL2
:PROPERTIES:
:TEXINFO_NODE_NAME: Building Omnivox For WSL2
:DESCRIPTION: Stage the Windows runtime from WSL2.
:END:

Use this advanced route when maintaining the reproducible Emacsvox Windows
bundle or its optional engine integrations.  Ordinary WSL2 users should use
the pre-built release in
@@texinfo:@ref{Installing An Omnivox Windows Release Under WSL2}@@.  This target
builds from source and currently produces an x86-64 Windows runtime.

Before running it, install or configure all of the following:

- A WSL2 distribution with Windows interoperation enabled.  Both
  ~powershell.exe~ and ~wslpath~ must run directly from the WSL shell, and the
  Windows user's ~LocalAppData~ directory must be writable.

- A working Docker client and daemon with Linux/AMD64 container support.  The
  current WSL user must be able to run ~docker~ without adding ~sudo~ because
  the Make target invokes it directly.  Docker Desktop with WSL integration is
  one way to provide this, but it is not the only possible Docker setup.

- Windows .NET Framework 4.7.2 or newer.  This means the Windows-only
  ``.NET Framework'', not merely a modern ~dotnet~ SDK.  Visual Studio is not
  required.

- In WSL, ~git~, GNU ~make~, ~curl~, ~unzip~, ~sha256sum~, and the normal GNU
  shell utilities supplied by a standard distribution.  The build also uses
  commands such as ~awk~, ~cmp~, ~find~, ~readlink~, ~sed~, ~sort~, and
  ~xargs~.

- Network access for the first Docker image build, Rust dependency download,
  and two checksum-pinned NuGet packages.  Later builds reuse the local Docker,
  Cargo, and .NET package caches.

- Emacsvox and Omnivox Git checkouts.  By default they must be sibling
  directories named ~emacsvox~ and ~omnivox~, although maintainers can set
  ~OMNIVOX_DIR~ to an alternate Omnivox checkout.  The Omnivox checkout must
  be at the exact source commit recorded for the checksum-pinned Piper
  companion in ~servers/omnivox-release/toolchain.lock~ when using the clean
  release target.  The preparation target rejects a different revision instead
  of combining unmatched native components.  The development target described
  below accepts current source by omitting Piper.  Both checkouts need enough
  free space for the Docker image, native and cross-compiled build products,
  and caches.

You do /not/ need to install Rust, MinGW, CMake, Clang, libclang, eSpeak NG,
Roslyn, Visual Studio, or the .NET reference assemblies in WSL.  The target
pins or builds those inside its controlled toolchain.  Eloquence and DECtalk
runtimes and the RHVoice runtime and voice data are optional and are not needed
for the normal Windows WinRT voice.

The quickest prerequisite check is:

#+begin_example
cd /path/to/emacsvox
make verify-windows-omnivox-toolchain
#+end_example

This is more than a presence check: on its first run it downloads the pinned
.NET compiler packages, builds the pinned Docker image, and verifies the exact
Rust, MinGW, libclang, Roslyn, and .NET Framework versions.  A failure names the
missing host command or unsupported framework before the full Omnivox build is
attempted.

Clone Omnivox beside Emacsvox as shown in the source-build section.  Then, from
a clean Emacsvox checkout whose sibling Omnivox checkout also has no tracked
changes, run:

#+begin_example
cd /path/to/emacsvox
make windows-omnivox
#+end_example

This is the reproducible release path.  It builds and verifies a pinned
Windows-GNU executable and stages a content-addressed runtime beneath
~servers/omnivox-bin~.  Once the Piper lock identifies an Omnivox revision that
contains these integrations, the payload includes the matching,
checksum-pinned Piper companion, the RHVoice helper without an RHVoice runtime,
the Flite helper with its compiled CMU US SLT voice, and the RuTTS helper with
its built-in male and female Russian voices.  It contains no Piper model and no
RuLex component.  It also copies the runnable payload to a Windows-local
directory so native voice and eSpeak data discovery do not pay the WSL
filesystem cost.  Optional Eloquence, DECtalk, and RHVoice runtimes are not
downloaded by this target or required for normal WinRT speech.

The build does not report success on file checks alone.  Its final live gate
starts the exact Windows-local runtime, discovers Flite's SLT voice and both
RuTTS voices, and requires each helper to synthesize a non-empty WAV.  Repeat
that gate without rebuilding by running ~make verify-windows-omnivox-live~.

To register Piper, review a model and its model card, keep its adjacent
~.onnx.json~ or ~.json~ configuration with it, and supply an absolute path
while staging:

#+begin_example
OMNIVOX_PIPER_MODEL=/absolute/path/to/voice.onnx make windows-omnivox
#+end_example

The target copies the model and configuration into a separate,
content-addressed directory below Windows ~LocalAppData~ and records their
hashes without bundling them into the runtime.  Omitting
~OMNIVOX_PIPER_MODEL~ installs the companion but leaves Piper unregistered.
After a configured build, start a fresh speech process and confirm that the
physical voice is present:

#+begin_example
./servers/omnivox --engine piper --list-voices
#+end_example

In Emacsvox, restart both speech processes or restart Emacs, then press
~C-e d e~.  That command lists the engines reported by the live process, so
Piper appears only after the newly staged server has started and successfully
loaded its model and helper.

Maintainers testing tracked changes should use the development route in
@@texinfo:@ref{Integration Maintenance}@@ rather than weakening the clean-release
guard:

#+begin_example
OMNIVOX_RHVOICE_LIBRARY=/mnt/c/path/to/RHVoice.dll \
  OMNIVOX_RHVOICE_DATA=/mnt/c/path/to/RHVoice/data \
  make windows-omnivox-dev
./servers/omnivox --engine flite --list-voices
./servers/omnivox --engine rutts --list-voices
#+end_example

This route builds current Omnivox source, stages the RHVoice helper, Flite with
its SLT voice, and RuTTS 6.3.3 with its built-in male and female Russian voices,
and deliberately omits the older pinned Piper companion.  RuTTS needs no
separate installation; RuLex is not included.  RHVoice appears only after
installing a compatible Windows ~RHVoice.dll~ plus language and voice data.
When its library and data variables are supplied to the development target,
staging validates them and records Windows path pointers beside that local
runtime; the launcher restores them for later fresh Emacsvox processes.  Also
supply ~OMNIVOX_RHVOICE_CONFIG~ when the installation has a separate
configuration directory.  The library, data, and configuration remain external
and are not copied into the Omnivox payload.  Installation and validation
instructions are in Omnivox's checkout under ~docs/RHVOICE.md~ and
~docs/RUTTS.md~.  Restart both speech processes or Emacs after restaging or
changing those inputs, then use ~C-e d e~ to inspect the engines reported by the
new process.

Piper testing from a newer committed Omnivox revision uses the separate
~windows-omnivox-piper-dev~ target and its native Windows CI artifact.  The
target requires the archive's published SHA-256 and a reviewed external model,
and rejects a dirty or different Omnivox checkout.  See
@@texinfo:@ref{Integration Maintenance}@@ for the complete command and
provenance checks.  This development path does not change the companion pinned
for reproducible releases.

** Selecting And Checking Omnivox
:PROPERTIES:
:TEXINFO_NODE_NAME: Selecting And Checking Omnivox
:DESCRIPTION: Prove speech before starting Emacsvox.
:END:

First test Omnivox without Emacs.  On GNU/Linux or macOS, run the installed
binary:

#+begin_example
omnivox --version
omnivox --check
omnivox --list-voices
#+end_example

Under WSL2, test the Emacsvox launcher.  It selects an explicit
~OMNIVOX_PROGRAM~ first, then the per-user installation recorded by the guided
installer, then a content-addressed source-built runtime, and finally an
~omnivox~ command on ~PATH~:

#+begin_example
./servers/omnivox --check
#+end_example

The check initializes the selected engine and audio output, then plays a tone
and speech.  Success ends with a message saying that everything is working if
both were heard.  Do not continue merely because the command exited zero:
hearing both signals is the backend acceptance condition.

Next select the server before loading Emacsvox:

#+begin_example
export TTS_PROGRAM=omnivox
#+end_example

Make that setting visible in the shell used to launch Emacs.  An
~export~ affects only that shell and its children; placing it in a
shell startup file makes the server choice persistent for later sessions.  On
POSIX systems, Emacsvox's ~servers/omnivox~ launcher also finds an installed
~omnivox~ on ~PATH~.  ~OMNIVOX_PROGRAM~ can name an absolute executable as an
explicit override.  Under WSL2, the guided installer's data-only configuration
file is persistent across launching shells and takes precedence over a
source-built staged runtime.
Native Windows Emacs resolves ~omnivox.exe~ directly through ~exec-path~, or
uses the absolute executable named by ~TTS_PROGRAM~.  That route remains
preview.  For its bounded evaluation procedure, see
@@texinfo:@ref{Trying Native Windows Emacsvox}@@.

Inside a running Emacsvox session, ~M-x omnivox~ selects the same server
temporarily.  Use ~M-x tts-speak-version~ to identify the live adapter
and ~M-x tts-restart~ after changing server configuration.  This backend
contract stops at a proven speech server; the complete isolated Emacs start,
expected startup speech, and no-speech recovery belong to the first-use
procedure.

** Compatibility Speech Servers
:PROPERTIES:
:TEXINFO_NODE_NAME: Compatibility Speech Servers
:DESCRIPTION: Understand the retained direct adapters.
:END:

Emacsvox retains direct speech servers for existing installations.  They are
not the recommended first setup and are outside the initial-user platform
matrix above:

#+attr_texinfo: :indic code :compact t
- espeak ::

  The direct GNU/Linux Tcl server.  Building it with ~make espeak~
  requires Tclx at runtime, Tcl 8.6 development headers, eSpeak NG development
  libraries, and a C++ compiler.  It remains useful for compatibility testing,
  but new users should install Omnivox instead.
- swiftmac ::

  The direct Swift macOS server.  It requires Swift 5.9 or newer and is built
  with ~make swiftmac~.  It remains a compatibility alternative to
  Omnivox's AVSpeechSynthesizer engine; see
  ~servers/mac-swiftmac/Readme.org~.
- mac ::

  The legacy Python/PyObjC macOS server.  The unset runtime selector still names
  it as a compatibility default on Darwin, but it is not the recommended or
  documented initial-user route.  It depends on Foundation, AppKit, and
  PyObjCTools availability.
- outloud ::

  The direct GNU/Linux IBM TTS or Eloquence adapter.  It requires a separately
  licensed compatible runtime, which Emacsvox does not distribute.  Voxin
  availability is documented at [[https://voxin.oralux.net]].
- dtk-soft ::

  The direct Software DECtalk adapter.  Install its runtime separately and see
  ~servers/software-dtk/Readme.org~.  Emacsvox does not distribute licensed
  speech runtimes.

The native Windows audio, standalone Eloquence, and standalone DECtalk bridges
under ~servers/~ are advanced WSL-specific compatibility paths.  Piper is
an optional Omnivox engine and model workflow, not a primary Emacsvox server.

** Backend Diagnostics And Responsibilities
:PROPERTIES:
:TEXINFO_NODE_NAME: Backend Diagnostics And Ownership
:DESCRIPTION: Locate failures and authoritative detail.
:END:

Use the boundary at which speech failed to choose the next diagnostic:

#+attr_texinfo: :indic asis :compact t
- ~omnivox~ is not found ::

  Under WSL2, run ~./bin/emacsvox-wsl-install --check~ and confirm its persistent
  path.  On other POSIX systems, check ~PATH~; an absolute ~OMNIVOX_PROGRAM~ can
  identify the installed executable.  Keep its adjacent ~espeak-ng-data~ and
  ~third-party-licenses~ directories with it.
- ~omnivox --check~ reports an error or is inaudible ::

  The failure is below Emacsvox.  Consult Omnivox's
  [[https://github.com/bartbunting/omnivox/blob/main/README.md][build guide]],
  [[https://github.com/bartbunting/omnivox/blob/main/STATUS.md][platform status]],
  and
  [[https://github.com/bartbunting/omnivox/blob/main/docs/DIAGNOSTICS.md][diagnostics guide]].  Do not diagnose Emacs configuration until the tone and
  speech check passes.
- The check passes but Emacsvox is silent ::

  Confirm that ~TTS_PROGRAM=omnivox~ was present before Emacsvox loaded, then
  use ~M-x tts-speak-version~.  Under WSL2 with a release binary, rerun
  ~./bin/emacsvox-wsl-install --check~.  For a source-built development
  runtime, run ~make verify-windows-omnivox-runtime~ and restart the speech
  process after restaging.
- A process starts and later fails ::

  The Emacsvox POSIX/WSL launcher writes private, bounded stderr logs below
  ~$XDG_STATE_HOME/emacsvox/omnivox~, defaulting to
  ~~/.local/state/emacsvox/omnivox~.  Spoken text is excluded unless
  ~OMNIVOX_LOG_SYNTHESIS_TEXT~ is explicitly enabled; enabling it can expose
  passwords, messages, and document contents.
- Speech works but feels delayed ::

  Press ~C-e d D~ to enable a private diagnostic log, then reproduce one short
  presentation and press ~C-e d D~ again to disable logging.  The default file
  is ~~/.emacsvox-aural-diagnostics.log~; use ~C-u C-e d D~ when enabling to
  choose another file.  Its ~dispatch-sent~, ~mixer-source-observed~, and
  ~playback-terminal-observed~ records share an Omnivox dispatch ID.  Match
  that ID in the ordinary Omnivox session log to separate Emacs submission,
  server queueing, synthesis, and mixer-source delay.  The Emacs log is
  disabled by default because its submission records include complete spoken
  text.  A mixer-source observation is not physical audible output; device and
  hardware buffers can add latency afterward.

Server selection, the POSIX/WSL launcher, Windows staging, and the bundled
Lisp adapter are implemented and documented in Emacsvox.  Native builds,
engines, the command line, runtime data layout, and protocol specifications
are documented in the Omnivox repository.  Backend-local READMEs describe
licensed runtimes and compatibility adapters.  Follow those sources for
versioned details rather than copying their contracts into installation
instructions.
