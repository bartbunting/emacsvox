* Speech Backends
:PROPERTIES:
:TEXINFO_NODE_NAME: Speech Backends
:DESCRIPTION: Select, install, and verify a speech server.
:END:

Emacsvox needs a speech-server process.  For a new installation, use
*Omnivox*.  Omnivox is the server that Emacsvox talks to; the engine
that produces speech underneath it is platform-specific.  The normal engine
is eSpeak NG on GNU/Linux, AVSpeechSynthesizer on macOS, and WinRT
SpeechSynthesizer on Windows.

For a first installation, follow the linear procedure in
@@texinfo:@ref{Installation}@@.  Return here when you need platform-specific build
details, compatibility servers, or deeper diagnostics.  Omnivox build
internals, engine behavior, and versioned protocols are documented and
maintained in
[[https://github.com/bartbunting/omnivox][the Omnivox repository]].

** Supported Platform Routes
:PROPERTIES:
:TEXINFO_NODE_NAME: Supported Platform Routes
:DESCRIPTION: Choose the maintained route for this machine.
:END:

The following table describes Emacsvox support, not every platform that the
Omnivox project can build.  ``Host check required'' means that the source path
is maintained but an audible ~omnivox --check~ on the user's machine
is still the acceptance test.

#+attr_texinfo: :columns .18 .31 .51
| Emacs platform | Recommended route | Current support evidence |
|---+---+---|
| GNU/Linux | Source-built Omnivox using eSpeak NG | Supported source installation; host check required. Omnivox does not currently publish a Linux archive or run a Linux audio-runtime CI job. |
| macOS on Apple silicon | Source-built Omnivox using AVSpeechSynthesizer | Supported source installation; Omnivox CI executes this native target, and the host check remains required. |
| macOS on Intel | Source-built Omnivox using AVSpeechSynthesizer | Available source installation; current Omnivox CI cross-builds this target but does not execute it. Treat the host check as required validation. |
| Emacs in WSL2 on x86-64 Windows | Emacsvox-staged Windows Omnivox using WinRT | Supported advanced deployment; the pinned build verifies its payload, but speech and audio must be accepted on the target Windows host. |
| Native Windows Emacs | Omnivox executable on ~exec-path~, using WinRT | Preview. The executable-resolution path exists, but Emacsvox does not yet publish or fresh-machine test a complete native-Windows setup. Initial users should use the WSL2 route. |

There is no verified public binary-download path in this guide.  Build from
source as described below.  A repository tag, a CI artifact, or an executable
without its adjacent runtime data is not a substitute for a supported install
payload.

Do not set ~OMNIVOX_ENGINE~ during initial setup.  Its empty value selects
the normal platform engine above.  Engine routing and optional Piper,
Eloquence, or DECtalk support are later customizations, not prerequisites for
first speech.

** Installing Omnivox From Source
:PROPERTIES:
:TEXINFO_NODE_NAME: Installing Omnivox From Source
:DESCRIPTION: Install on GNU/Linux or macOS.
:END:

Use this route on GNU/Linux and macOS.  It requires network access for the
initial clone, Rust toolchain, and locked dependency downloads.

Install these prerequisite classes before building:

- [[https://rustup.rs/][rustup]]; the checked-in
   ~rust-toolchain.toml~ selects the supported Rust release.

- Python 3, a C and C++ toolchain, CMake, and Clang with libclang.  The supported
   build wrapper uses these to build and stage eSpeak NG and its generated data.

- On GNU/Linux, ~pkg-config~ and ALSA development headers.  The ALSA
   package is commonly named ~libasound2-dev~ on Debian or Ubuntu and
   ~alsa-lib-devel~ on Fedora.

- On macOS, the Xcode command-line tools.  Install them with
   ~xcode-select --install~ if they are absent.

Keep the two repositories beside one another; this also matches the WSL2
release layout:

#+begin_example
cd /path/containing/emacsvox
git clone https://github.com/bartbunting/omnivox
cd omnivox
make build
make install
#+end_example

~make build~ performs the locked release build and stages the matching
eSpeak data and third-party notices.  ~make install~ installs the
binary and those adjacent directories, normally below ~~/.cargo/bin~.
Set ~OMNIVOX_INSTALL_BIN~ before ~make install~ only when the Cargo
binary directory is elsewhere.  Do not use a bare ~cargo build~ as the
installation procedure; it does not create the complete staged payload.

Make the install directory visible on ~PATH~ before continuing.  No
proprietary speech runtime is needed for the recommended Linux or macOS path.

** Building Omnivox For WSL2
:PROPERTIES:
:TEXINFO_NODE_NAME: Building Omnivox For WSL2
:DESCRIPTION: Stage the Windows runtime from WSL2.
:END:

Use this route when Emacs runs inside WSL2 and speech should play through
Windows.  Clone Omnivox beside Emacsvox as shown above.  The host must provide:

- WSL2 with working ~powershell.exe~ and ~wslpath~ interoperation;

- Docker with Linux/AMD64 container support;

- Windows .NET Framework 4.7.2 or newer; and

- ~curl~, ~unzip~, and ~sha256sum~ in WSL, plus network
   access for the pinned container and .NET toolchain inputs.

From a clean Emacsvox checkout whose sibling Omnivox checkout also has no
tracked changes, run:

#+begin_example
cd /path/to/emacsvox
make windows-omnivox
#+end_example

This is the reproducible release path.  It builds and verifies a pinned
Windows-GNU executable and stages a content-addressed runtime beneath
~servers/omnivox-bin~.  It also copies the runnable payload to a
Windows-local directory so native voice and eSpeak data discovery do not pay
the WSL filesystem cost.  Optional proprietary Eloquence and DECtalk runtimes
are not downloaded or distributed.

Maintainers testing tracked changes should use the development route in
@@texinfo:@ref{Integration Maintenance}@@ rather than weakening the clean-release
guard.

** Selecting And Checking Omnivox
:PROPERTIES:
:TEXINFO_NODE_NAME: Selecting And Checking Omnivox
:DESCRIPTION: Prove speech before starting Emacsvox.
:END:

First test Omnivox without Emacs.  On GNU/Linux or macOS, run the installed
binary:

#+begin_example
omnivox --version
omnivox --check
omnivox --list-voices
#+end_example

Under WSL2, test the content-addressed launcher instead:

#+begin_example
./servers/omnivox --check
#+end_example

The check initializes the selected engine and audio output, then plays a tone
and speech.  Success ends with a message saying that everything is working if
both were heard.  Do not continue merely because the command exited zero:
hearing both signals is the backend acceptance condition.

Next select the server before loading Emacsvox:

#+begin_example
export TTS_PROGRAM=omnivox
#+end_example

Make that setting visible in the shell used to launch Emacs.  An
~export~ affects only that shell and its children; placing it in a
shell startup file makes the choice persistent for later sessions.  On POSIX
systems, Emacsvox's ~servers/omnivox~ launcher finds an installed
~omnivox~ on ~PATH~; ~OMNIVOX_PROGRAM~ can instead name its
absolute executable.  Native Windows Emacs resolves ~omnivox.exe~
directly through ~exec-path~, but that route remains preview.

Inside a running Emacsvox session, ~M-x omnivox~ selects the same server
temporarily.  Use ~M-x tts-speak-version~ to identify the live adapter
and ~M-x tts-restart~ after changing server configuration.  This backend
contract stops at a proven speech server; the complete isolated Emacs start,
expected startup speech, and no-speech recovery belong to the first-use
procedure.

** Compatibility Speech Servers
:PROPERTIES:
:TEXINFO_NODE_NAME: Compatibility Speech Servers
:DESCRIPTION: Understand the retained direct adapters.
:END:

Emacsvox retains direct speech servers for existing installations.  They are
not the recommended first setup and are outside the initial-user platform
matrix above:

#+attr_texinfo: :indic code :compact t
- espeak ::

  The direct GNU/Linux Tcl server.  Building it with ~make espeak~
  requires Tclx at runtime, Tcl 8.6 development headers, eSpeak NG development
  libraries, and a C++ compiler.  It remains useful for compatibility testing,
  but new users should install Omnivox instead.
- swiftmac ::

  The direct Swift macOS server.  It requires Swift 5.9 or newer and is built
  with ~make swiftmac~.  It remains a compatibility alternative to
  Omnivox's AVSpeechSynthesizer engine; see
  ~servers/mac-swiftmac/Readme.org~.
- mac ::

  The legacy Python/PyObjC macOS server.  The unset runtime selector still names
  it as a compatibility default on Darwin, but it is not the recommended or
  documented initial-user route.  It depends on Foundation, AppKit, and
  PyObjCTools availability.
- outloud ::

  The direct GNU/Linux IBM TTS or Eloquence adapter.  It requires a separately
  licensed compatible runtime, which Emacsvox does not distribute.  Voxin
  availability is documented at [[https://voxin.oralux.net]].
- dtk-soft ::

  The direct Software DECtalk adapter.  Install its runtime separately and see
  ~servers/software-dtk/Readme.org~.  Emacsvox does not distribute licensed
  speech runtimes.

The native Windows audio, standalone Eloquence, and standalone DECtalk bridges
under ~servers/~ are advanced WSL-specific compatibility paths.  Piper is
an optional Omnivox engine and model workflow, not a primary Emacsvox server.

** Backend Diagnostics And Responsibilities
:PROPERTIES:
:TEXINFO_NODE_NAME: Backend Diagnostics And Ownership
:DESCRIPTION: Locate failures and authoritative detail.
:END:

Use the boundary at which speech failed to choose the next diagnostic:

#+attr_texinfo: :indic asis :compact t
- ~omnivox~ is not found ::

  Check ~PATH~; on POSIX, an absolute ~OMNIVOX_PROGRAM~ can identify the
  installed executable.  Keep its adjacent ~espeak-ng-data~ and
  ~third-party-licenses~ directories with it.
- ~omnivox --check~ reports an error or is inaudible ::

  The failure is below Emacsvox.  Consult Omnivox's
  [[https://github.com/bartbunting/omnivox/blob/main/README.md][build guide]],
  [[https://github.com/bartbunting/omnivox/blob/main/STATUS.md][platform status]],
  and
  [[https://github.com/bartbunting/omnivox/blob/main/docs/DIAGNOSTICS.md][diagnostics guide]].  Do not diagnose Emacs configuration until the tone and
  speech check passes.
- The check passes but Emacsvox is silent ::

  Confirm that ~TTS_PROGRAM=omnivox~ was present before Emacsvox loaded, then
  use ~M-x tts-speak-version~.  Under WSL2, also run
  ~make verify-windows-omnivox-runtime~ and restart the speech process
  after restaging.
- A process starts and later fails ::

  The Emacsvox POSIX/WSL launcher writes private, bounded stderr logs below
  ~$XDG_STATE_HOME/emacsvox/omnivox~, defaulting to
  ~~/.local/state/emacsvox/omnivox~.  Spoken text is excluded unless
  ~OMNIVOX_LOG_SYNTHESIS_TEXT~ is explicitly enabled; enabling it can expose
  passwords, messages, and document contents.

Server selection, the POSIX/WSL launcher, Windows staging, and the bundled
Lisp adapter are implemented and documented in Emacsvox.  Native builds,
engines, the command line, runtime data layout, and protocol specifications
are documented in the Omnivox repository.  Backend-local READMEs describe
licensed runtimes and compatibility adapters.  Follow those sources for
versioned details rather than copying their contracts into installation
instructions.
