* Hear Structure With Voice Lock
:PROPERTIES:
:TEXINFO_NODE_NAME: Voice Lock
:DESCRIPTION: Hear and adjust face and personality voice changes.
:END:

#+cindex: Voice Lock

Voice Lock makes structure audible by applying different speech personalities
to text properties supplied by Emacs modes and Emacsvox integrations.  Emacs
calls its visual style labels /faces/; Emacsvox can use the same labels without
requiring you to see them.  A comment can sound different from program code, a
heading from body text, or a link from surrounding prose without inserting
extra words into the document.

Voice Lock is enabled automatically in supported buffers.  Its differences are
easiest to hear in source code, Org, Info, or EWW, where the active mode already
marks several kinds of content.

** Try It In One Buffer
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Move across a few elements that the mode treats differently, such as a comment
and a string in source code or a heading and a link in Org.  Then use:

#+attr_texinfo: :indic kbd :compact t
- C-e d v ::

  Toggle Voice Lock in the current buffer.  Comparing the same text before and
  after the toggle is a quick way to confirm that a voice change comes from
  the established face-and-personality layer.

- C-e d C-v ::

  Toggle Voice Lock globally.  Existing and subsequently created buffers
  follow the new global state; an individual mode can still opt out when it
  starts.

- C-e E ::

  Explain the Aural Presentation at point.  The explanation can identify the
  semantic facts, matching rules, voices, sounds, and other actions that
  contributed to what you heard.

Voice Lock controls the compatibility mapping from faces and personality text
properties to voices.  Turning it off does not disable semantic presentation,
auditory icons, tones, or ordinary spoken status.  This distinction makes the
current-buffer toggle a useful diagnostic rather than an all-or-nothing speech
control.

** How Voice Lock Fits The Presentation
:PROPERTIES:
:TEXINFO_NODE_NAME: How It All Works.
:ALT_TITLE: How Voice Lock Fits The Presentation
:DESCRIPTION: Follow a face or personality from the mode to the speech engine.
:END:

The normal path has four parts:

1. The active Emacs mode marks meaningful text with faces.  An Emacsvox
   integration may also attach a named speech personality directly.

2. While Voice Lock is active, the established face-and-personality mapping
   supplies a compatibility voice for the spoken text.

3. Aural Presentation can combine that compatibility voice with semantic
   rules.  Separate visual-face rules can also participate whether Voice Lock
   is on or off.  A voice palette gives the resulting logical voices portable
   characteristics and routes them to available physical voices.

4. The selected speech adapter translates the result for its synthesizer.

The meaning of a distinction can therefore remain stable while its exact sound
varies with the engine and voice inventory.  A high-quality engine may express
several characteristics; a simpler engine can fall back to a smaller set
without changing the document or its mode.

Older help and configuration may show names such as ~voice-bolden~,
~voice-monotone~, or generated ~acss-...~ symbols.  They are compatibility
details below the user-facing presentation system.  Historical background on
their Aural CSS design is preserved in
@@texinfo:@ref{Audio Formatting And Aural CSS,,,emacsvox-heritage,Emacspeak Heritage}@@.

** Adjust Voice Lock In Small Steps
:PROPERTIES:
:TEXINFO_NODE_NAME: What this gives.
:ALT_TITLE: Adjust Voice Lock In Small Steps
:DESCRIPTION: Diagnose a distinction, then change the narrowest relevant setting.
:END:

Start with the object that sounds wrong or is difficult to distinguish:

1. Press @@texinfo:@kbd{C-e E}@@ at that object and read the explanation before changing
   a setting.

2. Toggle Voice Lock only in the current buffer with @@texinfo:@kbd{C-e d v}@@.  If the
   distinction remains, it comes from another presentation rule or action.

3. Open Aural Home with @@texinfo:@kbd{C-e H}@@.  Use its presentation tools and Voice
   Workbench to preview changes before saving them.  You do not need to edit a
   generated voice symbol.

4. Revisit the original buffer and compare the same object.  Keeping the test
   case and the scope small makes it easier to understand the result.

Advanced legacy configurations can still customize a named voice's
~-settings~ option, such as ~voice-monotone-settings~.  Customize the settings
option rather than ~voice-monotone~ itself, because the settings update every
generated voice that depends on that style.  Use this compatibility route only
when maintaining an existing low-level voice setup; prefer Aural Home for new
configuration.

For deliberate style design,
~emacsvox-wizards-generate-voice-sampler~ creates a buffer of characteristic
combinations, while ~emacsvox-wizards-voice-sampler~ applies a selected
personality to the current line and speaks it.  These sampler commands are
advanced auditioning tools, not required for ordinary Voice Lock use.
