* Applications And Integrations
:PROPERTIES:
:TEXINFO_NODE_NAME: Emacs Packages
:ALT_TITLE: Applications and integrations
:DESCRIPTION: Use speech-enabled applications and integrations.
:END:

#+cindex: applications
#+cindex: integrations
#+cindex: packages, speech support

Start an application with its normal Emacs command. Emacsvox prepares speech
support as the relevant libraries load, then presents movement, results, and
state changes through that application's structure. Emacs or the third-party
package still owns its editing, files, network operations, and other actions.

Use ~C-h m~ to learn the active mode, ~C-h b~ to inspect its effective keys,
and ~C-h k~ to explain one binding. For Emacsvox's feedback controls, ~C-e S~
opens the current integration's focused settings when available, otherwise
general buffer settings. ~C-e H j~ also provides integration settings and a
chooser. These controls adjust speech; they do not replace the application's
own setup or preferences. [[*Find Help While You Work][Using Online Help]] explains menu Help and search.

This chapter is a guide to maintained workflows, not a claim that every module
has a complete task guide. The generated
[[info:emacsvox-reference#Emacsvox Commands And Options][Emacsvox Commands And Options]] in the /Emacsvox Reference Manual/ records
public commands and options. Consult both that reference and the application's
manual when diagnosing a problem.

The everyday guides below cover opening and copying files, writing and reviewing
notes, and reading web pages. They use existing speech settings. Start with
[[*Answer a prompt and return to your work][Answer a prompt and return to your work]] if filename entry, completion or
switching from the manual to a working buffer is unfamiliar.

Earlier surveys of W3, Dismal, and scanner/OCR setup remain in the
[[info:emacsvox-heritage#Emacs Packages][Historical Application Survey]] in /Emacspeak Heritage/. They describe their
original period and are not current installation instructions.

** Work with files and directories
:PROPERTIES:
:TEXINFO_NODE_NAME: Working With Files
:DESCRIPTION: Open a document, save a separate working copy and find it again in Dired.
:END:

#+cindex: files, everyday work
#+cindex: directories, browsing
#+cindex: buffer versus file

A file is stored on disk. Visiting it in Emacs opens a /buffer/ containing its
working text; editing changes that buffer until you save. Switching to another
buffer leaves the work open. Closing a buffer does not delete its file.

These tasks use ordinary text files and existing writable directories. They
do not convert Word documents or PDFs into text. Start with speech working and
finish any open menu or prompt. [[*Answer a prompt and return to your work][Answer a prompt and return to your work]]
explains filename entry and the distinction between Emacs and shell input.

*** Open a document and check its identity
:PROPERTIES:
:TEXINFO_NODE_NAME: Opening A Document
:DESCRIPTION: Visit the intended text file and distinguish a new file from an existing one.
:END:

1. Press ~C-x C-f~. At the file prompt, choose the existing text file you
   want to read. Complete or type its path, then press ~RET~. Emacs selects
   the file's buffer; use ~C-e m~ to hear its name and mode.
2. Press ~M-<~, then ~C-e l~ to read its first line. Check that the content
   is what you expected before editing. A missing filename can instead open
   an empty buffer for a new file. Opening that buffer alone has not created
   a saved document: check the name rather than assuming your text was lost.
3. If you need to confirm the full destination, use
   ~C-h v buffer-file-name RET~. This Help shows the pathname visited by the
   source buffer; =nil= means that buffer is not visiting a file. Read Help
   as described in [[*Find Help While You Work][Using Online Help]], then return to the document by
   its buffer name with ~C-x b~. Do not edit while Help is selected.

For reading without accidental text edits, use ~C-x C-r~ in place of
~C-x C-f~. That opens the file read-only. A read-only buffer is different from
a document with unsaved changes; do not remove the protection merely to make
an unfamiliar command work.

When you follow this task from Info or HTML, leave the manual available and
switch to the document before trying its editing commands. In Emacs, ~C-x b~
selects an existing buffer by name; ~C-x C-f~ selects a file by its path.
Those are different questions even when the buffer and file have similar names.

To close a document buffer, use ~C-x k~ and check the name and any unsaved-work
prompt. That is not a file deletion. Unlike a Dired or Help buffer, an ordinary
text buffer does not use ~q~ to quit: typing it normally inserts a letter.

*** Save a separate working copy
:PROPERTIES:
:TEXINFO_NODE_NAME: Saving A Working Copy
:DESCRIPTION: Preserve the original saved file and make later saves go to the intended copy.
:END:

Use this route before editing a document whose original you want to preserve.
It writes the current buffer text, including unsaved edits, to a new filename
and makes that new file the buffer's saving destination.

1. Select the source document and check its identity. Press ~C-x C-w~,
   replace the proposed filename with an unused path such as
   =~/evox-notes-copy.txt=, and press ~RET~. Keep the appropriate extension
   for the document, for example =.org= for Org notes. Cancel an unexpected
   overwrite prompt and choose another name.
2. Read the save result and check the new destination with
   ~C-h v buffer-file-name RET~ when necessary. A permission or write error
   is not a completed save. Keep the buffer open while correcting the problem;
   do not discard the only copy of unsaved text.
3. Return to that document, make the intended changes, and press ~C-x C-s~.
   This saves to the new destination. The old saved file remains at its old
   path. You can open it separately with ~C-x C-f~ to compare it with the copy.

~C-x C-w~ does not keep the buffer attached to both files. After it succeeds,
later ~C-x C-s~ saves update the new file. The old file retains its previously
saved content, not any unsaved changes that were written only to the copy.
Changing the filename is also not a format converter: naming plain text with
=.docx= does not create a Word document.

To duplicate the last saved file while leaving the working buffer's destination
unchanged, use ~M-x copy-file RET~ instead. Answer its source and destination
prompts with paths. It copies the file on disk, not unsaved buffer edits, and
does not switch you into the new copy. Open the destination separately to work
on it. See [[info:emacs#Save Commands][Save commands]] and [[info:emacs#Copying and Naming][Copying and naming files]] in the GNU Emacs
Manual for other saving and copying operations.

If Emacs reports that another program changed the original, do not force a
save or revert simply to clear the warning. Keep your buffer, preserve its
text under an unused filename if needed, and compare the versions before
deciding which changes to keep. [[info:emacs#Simultaneous Editing][Simultaneous editing]] explains that conflict.

*** Find and inspect files with Dired
:PROPERTIES:
:TEXINFO_NODE_NAME: Browsing Files With Dired
:DESCRIPTION: Navigate filenames, request metadata and return without changing files.
:END:

#+cindex: Dired
#+cindex: file size, hearing
#+cindex: file modification time
#+findex: dired
#+findex: emacsvox-dired-speak-file-size
#+findex: emacsvox-dired-speak-file-modification-time

Dired is Emacs's directory browser. Its ordinary listing is not document text:
letters such as ~n~, ~p~ and ~q~ invoke commands rather than being inserted.
Emacsvox normally speaks filenames as you move, leaving detailed metadata for
inspection on request. Voices and cues can distinguish directories, links and
marked entries according to your presentation settings.

1. Press ~C-x d~, enter an existing directory such as =~/=, and press ~RET~.
   In the Dired buffer, press comma, ~,~, to hear the listing header.
2. Move with ~n~ and ~p~ to the next or previous entry. To reach a known name
   in a long listing, use ~C-s~, type part of the filename, and press ~RET~
   to finish searching. Check the filename you reached before acting on it.
3. On an ordinary file, press ~z~ to hear its size, lowercase ~c~ for its
   modification time, and ~/~ for permissions. These inspect the selected
   entry without opening it. Uppercase ~C~ is Dired's Copy command, not a
   second way to hear the time. Size inspection on a directory instead uses
   the external =du= program and may take longer or be unavailable; file-type
   inspection with apostrophe, ~'~, similarly requires the =file= program.
4. Press ~RET~ on the file to visit it in Emacs. On a directory, ~RET~ opens
   that directory's listing. Opening announces the destination; ~C-e m~ lets
   you check the resulting buffer and mode. Use ~RET~ here, not ~C-j~:
   Emacsvox assigns ~C-j~ and Control-Enter to a separate, file-type-aware
   opener which may preview or play a file instead of visiting its text.
5. To return from the document, use ~C-x b~ and select the directory buffer.
   In Dired, ~^~ goes to the parent directory and ~g~ refreshes the listing
   from disk. Refreshing Dired does not save or discard an open document's
   edits. Press ~q~ in Dired to leave the listing; your files remain on disk.

Looking at a file is not the same as marking it for an operation. ~m~ marks
an entry and then moves to the next; its action cue precedes the newly selected
filename. ~u~ unmarks an entry and also advances. If you are inspecting a
listing with existing marks, leave them alone. Dired operations can apply to
marked files rather than the row you are hearing.

This guide does not require deletion, renaming, changing permissions or running
commands on files. In particular, ~d~ flags deletion and ~x~ executes flagged
deletions; do not use either as a way to close a listing. Cancellation after a
file operation and ordinary text undo are not promises of filesystem recovery.
Use [[info:emacs#Dired][Dired]] in the GNU Emacs Manual before performing those operations, and
[[info:emacsvox-reference#emacsvox-dired][emacsvox-dired]] for the complete speech-command reference.

** Document Authoring

#+cindex: document authoring

Open or create a document in its normal Emacs mode. The mode supplies the
format's editing commands; Emacsvox presents movement, edits and structure
through speech. Voice Lock can distinguish useful faces supplied by the mode.
The following task writes a small Org note, then reviews it without relying
on visual formatting. Org comes with Emacs; no mail account or additional
speech engine is required.

For copying an existing document before editing, use
[[*Save a separate working copy][Save a separate working copy]]. Outlines and template fields are covered
under [[*Structured Editing And Templates][Structured editing and templates]], and tables under
[[*Reading Markdown and Org tables][Reading Markdown and Org tables]].

*** Write a note with headings
:PROPERTIES:
:TEXINFO_NODE_NAME: Writing An Org Document
:DESCRIPTION: Create a real text file and organise a short note with Org headings.
:END:

#+cindex: notes, writing
#+cindex: documents, creating
#+cindex: Org, writing a document

Unlike the tutorial's disposable buffer, this task creates a file you can
return to. Use an unused name and a writable directory. The name
=~/evox-notes.org= is an example, not a file the package supplies.

1. Press ~C-x C-f~, enter =~/evox-notes.org= and press ~RET~. If it already
   contains work, choose another name before typing. The =.org= extension
   normally selects Org mode; check with ~C-e m~. If a personal configuration
   selected another mode, run ~M-x org-mode RET~ in this new note.
2. Type or insert the following text in the document buffer, not in the
   minibuffer or the manual. Start each heading at the beginning of its line.
   One asterisk and a space introduce the main heading; two asterisks and a
   space introduce a heading beneath it.

   #+begin_example
   * Project notes
   The draft is ready for review.
   ** Questions
   Check the delivery date.
   ** Decisions
   Keep a separate review copy.
   #+end_example

3. Press ~M-<~ and read with ~C-n~ and ~C-e l~. Verify the heading words
   and body text. Org heading feedback can identify structure without reading
   every leading asterisk; exact character inspection remains available.
4. Press ~C-x C-s~ and read the save result. That writes this Org text to
   the selected file. It does not export a formatted document or change speech
   settings. Keep the file open for the following review, or reopen it later
   with ~C-x C-f~ and its path.

Choose your own heading titles when writing real notes. Org stores the title
and body as plain text, so the structure remains in the file even when parts
of it are folded in the current view. Do not delete a folded heading to try
to reveal its body: folding is a visibility operation, not missing content.

*** Review structure and correct text
:PROPERTIES:
:TEXINFO_NODE_NAME: Reviewing An Org Document
:DESCRIPTION: Read headings, reveal their contents, search and verify an edit before saving.
:END:

Start in the Org document, not in an Info example. Use ~C-e m~ to check the
selected buffer. If the note was reopened with content folded, first press
~M-<~, then ~C-u C-u C-u TAB~: Control-u three times, followed by Tab.
This shows all content without rewriting it. See
[[info:org#Global and local cycling][Global and local cycling]] in the Org manual.

At the first heading, ~C-c C-n~ moves to the next visible heading and
~C-c C-p~ to the previous one. In the example, these let you review Questions
and Decisions without reading every paragraph. Emacsvox announces the heading
you reach. Use ~C-e l~ to repeat it and ~C-n~ to begin reading its body.

On a heading, ~TAB~ cycles that subtree's visibility. Listen to the state
feedback before moving into it. This is different from Tab in a table or at a
completion prompt. The show-all sequence above provides a known starting view
if the current folds become confusing. [[info:org#Motion][Motion]] documents the other heading
commands, while [[*Browsing Structure][Browsing Structure]] explains the speech detail for Org headings.

For a focused text correction in the example:

1. Press ~M-<~, then ~C-s~, type =ready= and press ~RET~ to finish the
   search. Search moves point; the subsequent typing will occur there, not
   in a separate search box. Press ~C-e l~ to confirm the sentence.
2. Point is immediately after =ready=. Press ~M-b~ to move to its beginning,
   then ~M-d~ to remove that word. Type =prepared=. The surrounding text
   should now read =The draft is prepared for review.=.
3. Read the whole line again before saving. If the edit is wrong, press
   ~C-g~ in the document to deactivate any selection, then run
   ~M-x undo-only RET~ and inspect the line. Repeat =undo-only= only as far
   as needed; removing the old word and inserting the new one can be separate
   steps. Unlike ordinary ~C-/~, =undo-only= does not redo an earlier undo
   merely because you paused to read between corrections. See
   [[info:emacsvox#Recovering Text Edits][Recover a text edit before saving]] for the full recovery procedure.
4. Press ~C-x C-s~ only when the text is correct. Switch to another buffer
   and back with ~C-x b~ to continue working; leaving the note does not
   require closing its buffer.

If a search fails, check the text and the starting position. ~RET~ ends the
search at its current position; ~C-g~ can remove a failing suffix before
aborting the search, so listen for whether it is still active. Finish or cancel
search before issuing editing commands. Keep the desired note selected when
saving: a browser page, Help buffer and document do not share Save semantics.

An edit made after a successful save needs another save to replace that file's
contents. Undo also changes the buffer; it does not by itself restore the file
on disk. For a separate review version, use [[*Save a separate working copy][Save a separate working copy]] rather
than renaming the buffer and assuming that changed its destination.

** Browsing Structure
:PROPERTIES:
:TEXINFO_NODE_NAME: Browsing Structure
:END:

#+cindex: structured navigation

Use the active mode's structure when it matches the task: Info has nodes and
menus, Outline has headings and visibility, and EWW exposes HTML headings,
links, lists, tables, and other document elements. The following sections
explain Emacsvox's reading of headings, tables, and application lists. These
reading controls are distinct from commands that edit the underlying content.

*** Reading Org headings
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Reading a whole Org heading omits its leading stars at punctuation levels
=some= and =none=. Heading voices and the optional heading-level announcement
still identify the structure. At =all= punctuation, the stars are counted,
for example, ``3 star'' before a level-three heading. An empty heading is
spoken as ``Empty heading'' when its stars are omitted.

Word reading and partial-line reading count the stars actually selected.
Starting at the second star of a level-three heading therefore says ``2 star''.
Word movement includes the star count when it reaches the first heading word,
in either direction, without changing the usual cursor position. Moving through
the remaining title words does not repeat that count or heading-level
announcement. Character reading and spelling retain the individual stars.
Collapsed headings have a collapse cue at every level; the large-movement cue
belongs to Org structure navigation.

Counts preserve the configured character name without adding a plural ending.
At =all= punctuation, the speech server names =*=, so an active Omnivox
pronunciation of ``asterisk'' produces ``3 asterisk''. Saved punctuation-editor
changes take effect after restarting speech. Explicit word and partial-line
reads at =some= or =none= use =tts-character-to-speech-table=, the Emacs table
also used for character reading.

*** Reading Markdown and Org tables
:PROPERTIES:
:TEXINFO_NODE_NAME: Reading Markdown And Org Tables
:DESCRIPTION: Read cells, rows and columns without editing the source table.
:END:

In a Markdown or Org table, press a Control-Meta arrow to enter table reading
and move immediately. Left/right moves between columns; up/down moves between
logical rows, retaining the column. Every Control-Meta arrow reads the
destination cell. The first movement announces table reading and the destination
together. Table reading starts on demand by default in these source buffers;
you can choose automatic entry in the Tables settings described below.
Outside supported tables, these arrows retain their existing bindings,
including inside code examples.

~C-e C-t C-r~ enters at the current cell with the default speech prefix.
It announces the dimensions and current cell. The equivalent named command is
~M-x emacsvox-table-reader-mode~. Press ~q~ or the same command to restore
ordinary editing keys without moving point. This suspends automatic entry for
the current visit: another explicit entry command, or leaving the table and
returning, can start reading again. From prose, ~C-e C-t ]~ and ~C-e C-t [~
find and enter the next or previous table. Inside table reading, ~t~ and ~T~
do the same; code examples are skipped.

While table reading is active:

- Plain Up/down moves by logical row and reads the complete destination row
  by default. You can select cell speech for these keys. Control-Meta-up/down
  always reads the destination cell; both retain the column.
- Control-Meta-left/right moves between cells. Plain left/right retains
  character movement. ~TAB~ and ~S-TAB~ move between cells without editing;
  ~RET~ or ~SPC~ reads the current cell.
- ~r~ reads the row and ~c~ the column. ~.~ announces coordinates and ~=~
  gives dimensions.
- ~a~ opens Tables settings for titles, order, movement speech, activation
  and optional detail. Browsing settings leaves the table untouched.
- ~w~ or ~k k~ copies the cell, ~k r~ copies the row with tabs between cells,
  and ~k c~ copies the column with newlines between cells.
- Meta-up/down leaves directly for preceding/following prose. Up/down also
  leaves across a vertical table edge when content exists beyond it by default.
  Choose Stop at the edge to retain the cell instead. If no adjacent content
  exists, point stays in the table.

A horizontal edge or a missing cell in a shorter row leaves point unchanged
and announces the boundary. Separators are skipped. A separator immediately
after the first row identifies column titles; otherwise that row is data.
Coordinates distinguish the header from one-based data rows. Empty cells are
spoken as “blank.” Wrapping never shortens a logical cell's speech or copy.

Reading does not align tables, create rows, or evaluate Org formulas. Copies
use cell values: ordinary links become their labels and inline code becomes
its literal text. Use the host mode to copy exact markup or formulas. This
reader covers simple pipe tables; HTML spans, nested tables, and
spreadsheet-specific structures have separate interfaces.

Other editing commands retain their normal meaning. An edit ends reading and
suspends automatic re-entry while you continue typing. Org's native table
editing feedback, including its table Muggle, remains independent; it can
speak after native cell movement without starting this reader. Markdown's
markup-stripping speech preference also remains independent.

Agent Shell uses the same reading preferences and movement units, with automatic
entry as its initial policy. It retains native Tab, Shift-Tab and Return
actions and handles character movement within rendered cells; see
[[*Agent Shell][Agent Shell]].

*** Reading application lists
:PROPERTIES:
:TEXINFO_NODE: no
:END:

In an application built on Tabulated List mode, use a Control-Meta arrow or
~C-e C-t C-r~ to enter shared reading. Ordinary application navigation stays
unchanged until you enter, unless you select automatic entry. Within reading,
plain up/down reads complete logical rows by default, Control-Meta arrows read
cells, and plain left/right inspects characters.
~q~ leaves reading and restores the application's usual navigation.

Application actions take precedence over other shared reader keys. Opening,
refreshing, sorting, searching, and editing keep their commands, including
~RET~ on a button. When a shared key is occupied, use
~M-x emacsvox-table-reader-speak-cell~, ~M-x emacsvox-table-reader-speak-row~,
~M-x emacsvox-table-reader-speak-column~, ~M-x emacsvox-table-reader-speak-context~,
or ~M-x emacsvox-table-reader-speak-dimensions~. The matching
=emacsvox-table-reader-copy-cell=, =emacsvox-table-reader-copy-row= and
=emacsvox-table-reader-copy-column= commands copy logical values.

Speech and copies use complete entry text even when a displayed column is
truncated. Column headings come from the application, not the first item.
Coordinates count visible data rows; hidden rows are excluded and empty cells
say “blank.” Movement stops at the first or last row. A refresh ends reading;
enter again to inspect the refreshed list. Custom table printers, image-only
cells, and duplicate column names are not supported by this reader.

*** Choose table reading preferences
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Open ~M-x emacsvox-table-settings~ from the buffer you want to configure.
While reading a source or Agent Shell table, ~a~ opens the same page. The
speech settings menu provides ~C-e H s T~, and the focused Org and Agent Shell
menus provide ~T~. Settings search at ~C-e H /~ finds table reading, titles,
activation and inheritance. Each route captures the original buffer so moving
through the menu does not redirect your changes.

A control shows its pending choice, its effective value and the source of that
value. Open the control, browse with arrows, then press ~RET~ to stage a
choice and return to that control. Press ~q~ in the choice list to cancel.
Neither browsing nor selecting changes runtime behaviour yet. Press ~?~ and a
choice's key for Help; returning restores the browsed choice. The page's ~h~
explains scopes, migration and host exceptions.

For example, open Titles with ~t~, select Both titles, and press ~SPC~ to
preview a small sample. The sample includes a second row and a blank cell;
it uses the pending speech choices without moving or editing your source.
~s~ stops it. Preview treats pending choices as buffer overrides, so inheritance
uses the current mode settings. Saving inheritance for the mode can resolve
to a different common value; the effective labels refresh after saving.
Try activation and edge behaviour in an actual table after
applying them, since the speech sample does not navigate the source.

Choose one explicit action to use the pending settings:

- ~A~ applies only the changed choices temporarily to the captured buffer.
- ~W~ saves only those choices as common defaults through Customize.
- ~M~ saves only those choices for the captured major mode through Customize.
  Agent Shell's transcript and viewport share one mode setting.

After Apply, choices are labelled applied here, not saved. You can then Save
without selecting them again. Closing keeps applied buffer choices but does
not persist them.

Buffer overrides take precedence over mode overrides, which take precedence
over common defaults. Saving a wider default preserves narrower overrides;
the effective labels show when an override still wins. No titles is an
explicit choice, distinct from inheritance. Select Inherit wider scope and
Apply to release a buffer choice, or Save mode to make that mode follow the
common default. ~I~ stages inheritance for all settings; it still requires
Apply or Save mode. Common defaults cannot inherit. ~D~ discards pending
choices. Closing the page discards choices that were neither applied nor saved.

The controls cover titles, data/title order, plain-arrow speech, activation,
coordinates during movement, entry detail, repeated titles and vertical edges.
Initial defaults retain whole-row plain arrows, full entry detail, repeated
titles, no extra movement coordinates and leaving at vertical edges when
adjacent prose exists. Brief entry still identifies a table and reads its cell.
Suppressing repeated titles affects consecutive cell moves; explicit cell
inspection remains complete. Application lists always stop at their edges.

Activation's Mode defaults choice means automatic entry in Agent Shell and
on-demand entry in Org, Markdown and application lists. A common Automatic or
On demand choice applies wherever there is no narrower override. Quitting
always provides a temporary escape from automatic reading. A redraw or
Agent Shell response update alone cannot undo that quit.

Existing shared title/order settings retain their scope. Older Agent Shell
title/order choices remain effective as Agent Shell overrides, including saved
choices equal to their original defaults. The page identifies their source;
Help lists retained older values even when a newer override takes precedence.
An older value whose origin cannot be determined is preserved and identified
as uncertain. Select a replacement or inheritance explicitly to resolve it.
Opening the page never rewrites configuration. Advanced configuration lives
in the =emacsvox-table-reader= customisation group.

*** Browsing CSV data
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Use =emacsvox-table-find-csv-file= to open a CSV file in the table browser,
or =emacsvox-table-view-csv-buffer= for the current buffer's CSV data. Quoted
commas, doubled quotation marks, and multiline fields remain single logical
cells. Blank records outside quoted fields are skipped; empty fields remain
cells. Empty input or malformed quoting produces an error before creating a
view.

Browsing preserves source text. If the file is already open, the view uses
that buffer's current contents, including unsaved edits, without replacing the
source buffer. Shared table controls are active immediately:

- Up/down and Control-Meta-up/down move by logical row and read the whole row.
- Control-Meta-left/right and ~TAB~/~S-TAB~ move by cell. Plain left/right
  and ~C-b~/~C-f~ move by character; ~C-p~/~C-n~ move by logical row.
- ~RET~ or ~SPC~ reads the cell; ~r~ reads the row and ~c~ the column.
- ~.~ gives coordinates and ~=~ dimensions. The first row supplies column
  titles and is announced separately from data rows.
- ~w~ or ~k k~ copies the cell, ~k r~ copies the row with tabs between cells,
  and ~k c~ copies the column with newlines between cells. ~K~ copies the whole
  table to the clipboard used by =emacsvox-table-paste-from-clipboard=.
- ~a~ changes column titles, row titles, or data order for this view using
  shared reader preferences. ~q~ closes the view.

These replace the old browser cell-arrow, header-reading, automatic-speech,
and single-key table-copy bindings. The old local aliases ~b~, ~n~, ~p~, ~A~,
~B~, ~E~, and ~T~ are removed; speech-prefix table commands remain available.

Search with ~s~, ~R~ for a row, ~C~ for a column, or ~h~ for headers.
~#~ sorts on the current column and ~M-<~/~M->~ jumps to the top or bottom.
At an edge, movement announces the boundary and leaves point in place.

Filters remain on ~f~ for a row and ~g~ for a column; a prefix argument
requests a new filter. Filter indexes and the ~j~ jump prompt retain
zero-based model coordinates, including the header, although spoken
coordinates count data rows and columns from one. For example, the row filter
=(0 "value" 2)= reads the first column, “value”, and the third column.
~M-l~ and ~M-s~ load and save filters. Filters are explicit inspections;
shared row movement always reads the whole row. Sorting preserves filters and
speech preferences. Use ~C-h m~ for the full browser key map.

** Web Browsing With EWW
:PROPERTIES:
:TEXINFO_NODE_NAME: Web Browsing
:ALT_TITLE: Reading web pages with EWW
:DESCRIPTION: Open pages, read their structure, follow links and recover your place.
:END:

#+cindex: EWW
#+cindex: Web browsing
#+findex: eww

EWW is Emacs's built-in text-oriented web browser. Emacsvox adds speech and
navigation using the page's HTML structure. These commands act on the rendered
page, not on the manual you are reading now. Start with a speaking session and
use a public page for practice; a site requiring JavaScript may need your
ordinary external browser instead.

The keys below include Emacsvox's EWW bindings, which differ from unmodified
EWW. In particular, lowercase ~b~ moves to the previous link, lowercase ~s~
requests a readable view, and ~?~ is not the settings menu's Help key. Use
~C-h m~ or ~C-h k~ to inspect the running buffer. Help can select its own
buffer and remove other windows. Return to the page with ~C-x b~ and check
its name with ~C-e m~ before using the browser keys below. The upstream
[[info:emacs#EWW][EWW guide]] and [[info:emacsvox-reference#emacsvox-eww][emacsvox-eww]] reference cover the rest of the interface.

*** Open a page and establish your place
:PROPERTIES:
:TEXINFO_NODE_NAME: Opening A Web Page
:DESCRIPTION: Enter an address, wait for rendering and identify the selected browser buffer.
:END:

#+cindex: web page, opening
#+cindex: EWW, buffer names

1. Run ~M-x eww RET~. At its next prompt, enter a web address, for example
   =https://www.gnu.org/software/emacs/=, and press ~RET~. Text that EWW does
   not recognise as an address is sent to its configured search service;
   do not enter private document text as a practice search.
2. Wait for loading and rendering to finish before navigating the page.
   An opening cue means the command started, not that the server returned the
   expected article. Read the page title and any error or login message.
   Emacsvox normally names the buffer after the page title, so do not assume
   the buffer is called =*eww*=. Press ~C-e m~ to identify it.
3. Press ~M-<~ and use ~C-n~ or ~C-e l~ to read. Keep the browser buffer's
   name in mind when switching to notes or Help. ~C-x b~ returns to that
   existing buffer; running =eww= again starts another browsing operation.

To request a separate browser buffer instead of reusing the default one,
start with ~C-u M-x eww RET~. This is an intentional use of the prefix
argument explained in [[*Read the key instructions][Read the key instructions]]. It lets you keep the earlier
page available while opening another. A title can change after navigation;
check the new buffer name before using it in a later switch.

*** Read by heading, paragraph or search
:PROPERTIES:
:TEXINFO_NODE_NAME: Navigating A Web Page
:DESCRIPTION: Use HTML structure when it is present and text search when it is not.
:END:

#+cindex: web headings
#+cindex: web page, finding text

In the EWW page buffer, period, ~.~, moves to the next supported heading and
comma, ~,~, to the previous one. ~1~ through ~4~ find the next heading at the
corresponding level; ~M-1~ through ~M-4~ go backwards. These are HTML heading
levels, not numbered paragraphs. A page without suitable heading markup
cannot be navigated as though that structure existed.

Use ~]~ and ~[~ to move between paragraphs. ~M-SPC~ requests the contents of
the current HTML element. Section-navigation autospeak can read more than a
heading or a line, depending on your setting; use explicit line or element
reading when you want to control the amount. Stop current speech with ~C-e s~
without disabling later feedback.

For known words, press ~C-s~, type the text, and press ~RET~ to finish at
the match. Repeat ~C-s~ while searching to find another occurrence. This is
Control-s, not the unmodified ~s~ key used for a readable view. Search covers
the current rendered buffer; it does not submit a web search or find text
that was never loaded into the page.

Use the original page when checking whether information is genuinely absent.
A readable or filtered view can omit menus, tables or other useful material.
The recovery procedure below explains restoring the page without treating a
filter as an edit to the website.

*** Follow a link and return to the article
:PROPERTIES:
:TEXINFO_NODE_NAME: Following Web Links
:DESCRIPTION: Inspect a link, follow it and distinguish browser history from buffer selection.
:END:

#+cindex: web links, inspecting
#+cindex: web history, going back
#+cindex: EWW, bookmarks

Use lowercase ~f~ to reach the next link and lowercase ~b~ for the previous
one. Emacsvox presents link navigation; ~C-e l~ reads its surrounding line.
The link's label is not necessarily its destination address.

On a link, ~k~ copies its address to Emacs's kill ring, the text store used by
~C-y~. To inspect that address as text, press ~C-x b~, enter an unused buffer
name such as =evox-web-address=, and press ~RET~. If that name already contains
work, choose another. Run ~M-x text-mode RET~, press ~C-y~ to insert the
address, then ~C-e l~ to read it. Return to the browser by name with ~C-x b~.
This temporary buffer need not be saved. Do not paste into an important document
or a web form merely to inspect a URL. Between copying and pasting, avoid
~C-e a~ and ~C-e f~: repeating a message or reading a filename also adds text
to the kill ring and can replace the address as the next paste. Check the
pasted text; [[info:emacsvox#Choosing Earlier Copied Text][Choose text copied earlier]] explains retrieving an older entry.

To copy the page's own address regardless of point, use
~M-x eww-copy-page-url RET~ instead. Emacsvox's ~k~ is context-sensitive and
means the link address when on a link.

Press ~RET~ on the intended link to follow it. After the new page loads,
press lowercase ~l~ to go back in that EWW buffer's history and ~r~ to go
forward again. Emacsvox announces URL navigation through the page header.
Check your position with line reading; if necessary, search for a distinctive
phrase from the article. History is limited and a page can change, so do not
assume the exact passage is always restored.

To follow a link in a separate buffer, use ~M-RET~. Return to the original
page with ~C-x b~; that is a buffer change rather than a history step in the
new buffer. Use ~q~ in an ordinary EWW page to leave its view. Uppercase ~Q~
is Emacsvox's buffer-killing command and is not required for this task.

To keep a website for a future session, run ~M-x eww-add-bookmark RET~ on the
wanted page. ~M-x eww-list-bookmarks RET~ opens the saved list; select a
bookmark and press ~RET~ to visit it. These are website bookmarks, not the
Emacsvox ebook-position marks on ~m~, and they do not promise to preserve an
exact reading position on a changing page.

*** Recover a cluttered or incomplete page
:PROPERTIES:
:TEXINFO_NODE_NAME: Recovering A Web Page
:DESCRIPTION: Restore a reading view, handle missing content and keep browser settings distinct.
:END:

#+cindex: EWW, readable view
#+cindex: web page, missing content

In a page buffer, lowercase ~s~ runs EWW's readable-view command. It tries to
isolate the main text; it is not the same action as ~s~ inside the focused
settings menu. To return from the filtered view, run
~M-x emacsvox-eww-restore RET~. This restores the retained canonical view
rather than changing the site. The command is also on ~DEL~, but its name
avoids differences in how keyboards report Backspace and Delete.

If the retained view is unavailable or you need fresh content, ~g~ reloads
the current address. Reloading makes a new request and can lose form input or
change the page and reading position. Save needed notes and finish or abandon
forms deliberately before reloading. Search for a known phrase afterwards
rather than assuming the old screen position still identifies the passage.

For content that requires JavaScript or another unsupported browser feature,
use ~M-x eww-browse-with-external-browser RET~ to hand the page to the configured
external browser. The external browser and any screen reader then provide
its controls; Emacsvox's EWW keys do not operate there. Browser configuration,
login state and downloaded-content handling can differ. A failed or inaccessible
website is not in itself a reason to change speech engines or reset voices.

For speech preferences, open ~C-e S~ from EWW. In that focused menu, ~s~
toggles section-navigation autospeak and ~i~ changes image suppression for
subsequent rendering. The latter also changes the shared SHR image default
while preserving buffer-local overrides; it does not reload the current page.
Lowercase ~w~ saves those two Emacsvox defaults, ~A~ opens advanced settings,
and ~q~ returns. These are presentation choices, not EWW's site or account
preferences. Returning does not undo changes you have already made.

The Emacs/W3 and w3m survey is historical. Do not install either on the strength
of the Heritage manual; use EWW unless a separately maintained integration says
otherwise. The GNU Emacs Manual's [[info:emacs#EWW][EWW]] entry provides its general introduction.

*** Magit
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Magit navigation speaks the section or line you reach. Empty and
whitespace-only lines use the normal line tones. Commit hashes are silent by
default; changing the voice assigned to =magit-hash= affects navigation and
explicit reading consistently. Moving the section highlight preserves that
choice.

After successful staging or unstaging in a Magit view, speech reads where point
lands after the refresh. Failures remain explicit. Staging and unstaging from
an ordinary file buffer still confirm their outcome. Branch checkout, branch
and remote renaming, remote removal, and stash creation announce results.
Repository-list fetching reports partial failures. Background completion uses
the notification stream; entering status and navigating use the main stream.

Visibility commands describe collapsed, expanded, or partly expanded sections.
Copying a heading without a value reports that there is nothing to copy rather
than presenting an old kill-ring entry as a new copy.

#+cindex: Magit
#+cindex: Transient menus

Magit uses Transient menus for Push, Fetch, Commit, Branch, and other actions.
Opening one speaks a short introduction and navigation guidance. Its automatic
shortcut list remains visible without being read on the notification stream.

Up/down browses items and left/right moves between sections. The shared
navigation preferences apply to Magit as well as Emacsvox menus: wrapping
within a section is the default, and continuous navigation or stopping at
section edges can be selected. Announcement order can be item first, section
first, or dependent on the movement. Detailed command descriptions are enabled
by default; value adjustments still give brief feedback. Configure these
choices through ~C-e H s n~, as described in
[[info:emacsvox#Aural Home][Getting started with settings menus]].

An item announcement identifies its key, relevant value, and description;
capital keys are named explicitly. Section announcements include the heading
and position according to the selected policy. Do not expect the same
section-name repetition after changing that policy.

Use ~C-j~ or ~M-RET~ to activate a selected Magit item, or type its shortcut.
~?~ followed by the shortcut opens Help. ~C-g~ closes the current menu or
leaves its help mode. Unlike Emacsvox's own settings menus, ~q~ is not a
universal quit key in Transient applications. An unavailable key gives brief
recovery guidance on the main stream.

Browsing only selects an item. Activating an action can perform a Git
operation, while activating a switch changes an argument for the next action.
Listen to the description before activation.

*** OCR And PDF-To-Text With PaddleOCR
:PROPERTIES:
:TEXINFO_NODE: no
:END:

#+cindex: OCR
#+cindex: PaddleOCR
#+cindex: PDF, converting to text
#+cindex: tables, OCR
#+findex: emacsvox-ocr

Emacsvox uses PaddleOCR PP-StructureV3 to turn an image or PDF into UTF-8
Markdown text. It recovers reading order and represents recognised tables as
Markdown or embedded HTML. Keep =.md= output when structure matters; Markdown
is plain text and can be named =.txt= when its lightweight markup is acceptable.

This route is intended for scanned or image-only PDFs. For a born-digital PDF
with a trustworthy text layer, extracting that layer is faster and usually
more exact than OCR. Recognition still depends on scan quality; upright,
high-contrast pages at 300 DPI are a useful starting point.

**** Prepare the isolated OCR environment
:PROPERTIES:
:TEXINFO_NODE: no
:END:

The supported baseline is CPU-only x86-64 WSL2 or GNU/Linux. Paddle's Linux
wheel requires an AVX-capable x86-64 processor and Python 3.9 through 3.13.
Do not use Ubuntu 26.04's Python 3.14 for this environment. The commands below
install Python 3.13 separately without altering Emacsvox, system Python, or
another project's packages. Installation uses about 1.7 GB; the first complete
PP-StructureV3 run downloads approximately another 1.8 GB of models, cached
for later runs.

Follow the [[https://docs.astral.sh/uv/getting-started/installation/][uv installation guide]] if =uv= is unavailable, then create the environment:

#+begin_src sh
uv python install 3.13
uv venv --python 3.13 --seed \
  "$HOME/.local/share/emacsvox/paddleocr-venv"
#+end_src

Install the tested CPU runtime and PaddleOCR's =all= variant, which includes
the document-parsing, table, and formula dependencies:

#+begin_src sh
"$HOME/.local/share/emacsvox/paddleocr-venv/bin/python" -m pip install \
  paddlepaddle==3.3.0 \
  -i https://www.paddlepaddle.org.cn/packages/stable/cpu/
"$HOME/.local/share/emacsvox/paddleocr-venv/bin/python" -m pip install \
  'paddleocr[all]==3.7.0'
#+end_src

From the checkout, verify that the launcher finds both packages:

#+begin_src sh
./bin/emacsvox-paddleocr --check
#+end_src

For a Debian installation, use the installed launcher, here and in the
recognition commands below:

#+begin_src sh
/usr/share/emacsvox/bin/emacsvox-paddleocr --check
#+end_src

The expected report names PaddlePaddle 3.3.0, PaddleOCR 3.7.0, and the CPU
device. A missing =ccache= warning is harmless for normal inference.

oneDNN, formerly MKL-DNN, is an optional CPU execution backend, not an OCR
model. The launcher leaves it disabled because PaddlePaddle 3.3.0 has an
[[https://github.com/PaddlePaddle/Paddle/issues/77340][upstream PIR-to-oneDNN conversion defect]]. In the tested pipeline this aborts
initialisation at the formula model, although that model is not itself at
fault. Standard CPU kernels keep every recognition feature enabled, including
tables and formulas. The trade-off is speed, not capability.

**** Recognise and read a document
:PROPERTIES:
:TEXINFO_NODE: no
:END:

For one image, redirect the clean Markdown result to a file. Model downloads
and progress go to standard error, not the recognised text:

#+begin_src sh
./bin/emacsvox-paddleocr "/path/to/page.png" > page.md
#+end_src

PDF input uses the same command. Paddle renders and recognises every page,
then joins them in reading order:

#+begin_src sh
./bin/emacsvox-paddleocr "/path/to/scanned-document.pdf" > document.md
#+end_src

A large PDF can require substantial CPU time: table, layout, formula,
orientation, and unwarping models are all active by default.

Inside Emacsvox, press ~C-e C-o~ or run ~M-x emacsvox-ocr RET~. In the OCR
buffer, ~o~ selects an image or PDF. Recognition runs asynchronously and adds
its result as a new page when complete. Listen for the completion cue, then
use ~SPC~ to read the current result, ~s~ to save it, or ~w~ to save the
whole OCR buffer. ~[~ and ~]~ move between results. ~d~ opens the per-user
OCR directory. Progress and errors are retained separately in
=*Emacsvox OCR Errors*=.

**** Configure recognition and diagnose the adapter
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Use ~M-x customize-group RET emacsvox-ocr RET~ for ordinary Emacs configuration
rather than shell environment variables. The bundled adapter provides typed
options:

- =emacsvox-ocr-paddleocr-python= selects an exact Python executable; =nil=
  uses the isolated installation above.
- =emacsvox-ocr-paddleocr-language= and =emacsvox-ocr-paddleocr-device= choose
  recognition language and device.
- =emacsvox-ocr-paddleocr-use-table-recognition= and
  =emacsvox-ocr-paddleocr-use-formula-recognition= control the structural
  models; both default to enabled.
- =emacsvox-ocr-paddleocr-use-document-orientation=,
  =emacsvox-ocr-paddleocr-use-document-unwarping=, and
  =emacsvox-ocr-paddleocr-use-text-line-orientation= control image correction.
- =emacsvox-ocr-paddleocr-enable-mkldnn= enables oneDNN/MKL-DNN acceleration,
  not an OCR model. Keep it disabled for the tested PaddlePaddle 3.3.0 CPU
  setup on WSL.

These options apply only when =emacsvox-ocr-engine= names the bundled adapter.
A different engine retains the generic interface. =emacsvox-ocr-engine-options=
is an advanced list of literal arguments; for the bundled adapter it follows,
and can override, the typed options.

For standalone shell or automation use, =EMACSVOX_PADDLEOCR_VENV= changes the
environment directory, =EMACSVOX_PADDLEOCR_PYTHON= selects an executable, and
=EMACSVOX_PADDLEOCR_LANGUAGE= or =EMACSVOX_PADDLEOCR_DEVICE= changes defaults.
See =./bin/emacsvox-paddleocr --help= for switches. These environment settings
are not the primary Emacs configuration interface.

Direct SANE scanner-acquisition commands remain for compatibility but are not
part of this tested WSL baseline. Scan with a Windows application and select
the resulting image or PDF with ~o~ when that is the available acquisition
route. Scanner configuration is independent of PaddleOCR.
