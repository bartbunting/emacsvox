Emacsvox prepares speech support for many Emacs modes as their libraries are
loaded.  Start the application normally; when its buffer appears, use
@@texinfo:@kbd{C-h m}@@ for the active modes and their commands, @@texinfo:@kbd{C-h b}@@ for the
effective bindings, and @@texinfo:@kbd{C-h k}@@ followed by a key to identify one binding.
The generated
@@texinfo:@ref{Emacsvox Commands And Options,,,emacsvox-reference,Emacsvox Reference Manual}@@ records the public Emacsvox commands and options.

This chapter is a curated starting point, not a promise that every module in
the generated reference has a maintained task guide.  Emacs itself or a
third-party package provides the application's general operation; Emacsvox
adds the speech feedback.  Consult both sets of help when diagnosing a problem.

Earlier Emacspeak surveys, including their W3, Dismal, and scanner/OCR setup,
are preserved as historical material in
@@texinfo:@ref{Emacs Packages,Historical Application Survey,,emacsvox-heritage,Emacspeak Heritage}@@.  They are not current setup instructions.

** Document Authoring
:PROPERTIES:
:TEXINFO_NODE_NAME: Document Authoring
:END:

#+cindex: document authoring

Emacs major modes provide the editing commands for each document format.
Emacsvox speaks ordinary movement and editing, applies voice-lock where the
mode exposes useful faces, and adds mode-specific feedback where an integration
exists.  Open or create the document in its normal Emacs mode, then use
@@texinfo:@kbd{C-h m}@@ to discover that mode's workflow.  For outlines and templates, see
@@texinfo:@ref{Structured Editing}@@.

** Structured Editing And Templates
:PROPERTIES:

Emacsvox has maintained integrations for the built-in Outline and Tempo
libraries.  In Outline mode, heading navigation speaks the reached heading and
visibility commands announce what was hidden or exposed.  Start a dedicated
outline with @@texinfo:@kbd{M-x outline-mode}@@, or enable ~outline-minor-mode~ in a
suitable document.  See
@@texinfo:@ref{emacsvox-outline,,,emacsvox-reference,Emacsvox Reference Manual}@@ for the
Emacsvox integration and @@texinfo:@ref{Outline Mode,,,emacs,The GNU Emacs Manual}@@ for
the underlying editor.

Tempo supplies template fields for modes and packages that use it.  Emacsvox
speaks inserted text and the line reached when moving between template marks.
The package that supplied a template also provides its insertion commands;
use that package's mode help, together with
@@texinfo:@ref{emacsvox-tempo,,,emacsvox-reference,Emacsvox Reference Manual}@@.

** Browsing Structure

#+cindex: structured navigation

Use the structure exposed by the active Emacs mode rather than treating every
buffer as plain text.  Info provides node and menu navigation, Outline provides
heading and visibility commands, and EWW exposes HTML headings, links, lists,
tables, and other document elements.  Begin with @@texinfo:@kbd{C-h m}@@ in the buffer;
see @@texinfo:@ref{Using Online Help}@@ for the common discovery commands and
@@texinfo:@ref{Web Browsing}@@ for the maintained Web route.

** Web Browsing With EWW
:PROPERTIES:
:TEXINFO_NODE_NAME: Web Browsing
:ALT_TITLE: Web Browsing
:END:

#+cindex: EWW

#+cindex: Web browsing

#+findex: eww

EWW is the built-in browser supported for current Emacsvox.  Run
@@texinfo:@kbd{M-x eww @key{RET}}@@, enter a URL or search words, and press @@texinfo:@key{RET}@@.
Emacsvox speaks EWW navigation and rendering feedback and adds commands for
moving by HTML structure and filtering the displayed DOM.  In an EWW buffer,
use @@texinfo:@kbd{C-h m}@@ for the live workflow and @@texinfo:@kbd{C-h b}@@ for its effective keys.
See @@texinfo:@ref{EWW,,,emacs,The GNU Emacs Manual}@@ for browser operation and
@@texinfo:@ref{emacsvox-eww,,,emacsvox-reference,Emacsvox Reference Manual}@@ for the
speech integration.

The former Emacs/W3 and w3m survey is historical.  Do not install either one
on the strength of the Heritage manual; use EWW unless a separately maintained
integration says otherwise.

** Development Environment
:PROPERTIES:
:TEXINFO_NODE_NAME: Development Environment
:END:

#+cindex: development tools

Emacs can combine compilation, diagnostics, project navigation, version
control, debuggers, and language servers into a development environment.
Emacsvox supplies speech feedback to many of those components, but their own
manuals remain authoritative for setup and operation.  Verify each component
individually with its mode help before combining it into a larger workflow.

*** Magit
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Magit navigation speaks the reached section or line.  Empty and whitespace-only
lines use the normal line tones.  Commit hashes are silent by default; changing
the voice assigned to the ~magit-hash~ face changes this consistently for both
navigation and explicit reading.  Moving the section highlight preserves that
choice.

Staging and unstaging report their outcome after Git finishes, including
failures.  Branch checkout, branch and remote renaming, remote removal, and
stash creation also announce their results.  Repository-list fetching reports
partial failures when some repositories fail.  Background process completion
uses the notification lane, while entering status and navigating use the main
speech lane.

Section visibility commands describe the resulting collapsed, expanded, or
partly expanded state.  Copying a heading without a value says there is nothing
to copy; it does not repeat an older kill-ring entry as a new copy.

*** OCR And PDF-To-Text With PaddleOCR
:PROPERTIES:
:TEXINFO_NODE: no
:END:

#+cindex: OCR

#+cindex: PaddleOCR

#+cindex: PDF, converting to text

#+cindex: tables, OCR

#+findex: emacsvox-ocr

Emacsvox uses PaddleOCR PP-StructureV3 to turn an image or PDF into UTF-8
Markdown text.  PP-StructureV3 recovers document reading order and represents
recognized tables as Markdown or embedded HTML, so keep the ~.md~ output when
table structure matters.  Markdown is plain text and can instead be named
~.txt~ when its lightweight markup is acceptable.

The supported baseline below is CPU-only x86-64 WSL2 or GNU/Linux.  Paddle's
Linux wheel requires an AVX-capable x86-64 processor and Python 3.9 through
3.13.  In particular, do not use Ubuntu 26.04's Python 3.14 for this environment.
The commands install a separate Python 3.13 so that they do not alter Emacsvox,
system Python, or another project's packages.  The initial installation uses
about 1.7 GB.  The first complete PP-StructureV3 run downloads approximately
another 1.8 GB of models; later runs reuse that cache.

Follow the [[https://docs.astral.sh/uv/getting-started/installation/][official uv installation guide]] if command ~uv~ is not already available,
then create the isolated environment:

#+begin_src sh
uv python install 3.13
uv venv --python 3.13 --seed \
  "$HOME/.local/share/emacsvox/paddleocr-venv"
#+end_src

Install the tested CPU runtime and the PaddleOCR ~all~ variant.  The ~all~
extra includes the document-parsing dependencies needed by PP-StructureV3,
including table and formula support.

#+begin_src sh
"$HOME/.local/share/emacsvox/paddleocr-venv/bin/python" -m pip install \
  paddlepaddle==3.3.0 \
  -i https://www.paddlepaddle.org.cn/packages/stable/cpu/
"$HOME/.local/share/emacsvox/paddleocr-venv/bin/python" -m pip install \
  'paddleocr[all]==3.7.0'
#+end_src

From the Emacsvox checkout, verify that the launcher finds both packages:

#+begin_src sh
./bin/emacsvox-paddleocr --check
#+end_src

The expected line names PaddlePaddle 3.3.0, PaddleOCR 3.7.0, and the CPU
device.  A warning that ~ccache~ is absent is harmless for normal inference.
oneDNN, formerly called MKL-DNN, is Paddle's optional optimized CPU execution
backend; it is not an OCR model.  The launcher deliberately leaves it disabled
because the stable PaddlePaddle 3.3.0 CPU runtime has an
[[https://github.com/PaddlePaddle/Paddle/issues/77340][upstream PIR-to-oneDNN conversion defect]].  In the tested pipeline the defect
aborts initialization when PP-StructureV3 reaches its formula model, but the
model itself is not at fault.  With oneDNN disabled, Paddle uses its standard
CPU kernels and every recognition feature remains enabled, including tables
and formulas.  The trade-off is speed, not recognition capability.

To recognize one image at the shell, redirect the clean Markdown result to a
file.  Paddle downloads its models on the first real command and writes
progress messages to standard error without mixing them into the recognized
text.

#+begin_src sh
./bin/emacsvox-paddleocr "/path/to/page.png" > page.md
#+end_src

PDF input uses the same command.  Paddle renders and recognizes every page,
then joins the pages in reading order:

#+begin_src sh
./bin/emacsvox-paddleocr "/path/to/scanned-document.pdf" > document.md
#+end_src

This route is intended for scanned or image-only PDFs.  For a born-digital PDF
that already has a trustworthy text layer, extracting that layer is faster and
usually more exact than OCR.  OCR quality still depends on scan quality;
300-DPI, upright, high-contrast source pages are a good starting point.  A
large PDF can take substantial CPU time because table, layout, formula,
orientation, and unwarping models are all active by default.

Within Emacsvox, press @@texinfo:@kbd{C-e C-o}@@ or run
@@texinfo:@kbd{M-x emacsvox-ocr @key{RET}}@@.  In the OCR buffer:

- Press ~o~, choose an image or PDF, and wait for the completion cue.  OCR runs
  asynchronously, and the result appears as a new page in the buffer.
- Press @@texinfo:@key{SPC}@@ to read the current result, ~s~ to save it, or ~w~ to
  save the complete OCR buffer.  Press ~[~ and ~]~ to move between results.
- Press ~d~ to open the per-user OCR directory.  Engine progress and errors are
  kept separately in buffer ~*Emacsvox OCR Errors*~.

For ordinary use inside Emacs, customize OCR in Emacs rather than setting shell
environment variables.  Run
@@texinfo:@kbd{M-x customize-group @key{RET} emacsvox-ocr @key{RET}}@@.  The bundled adapter
has typed options for its normal choices:

- ~emacsvox-ocr-paddleocr-python~ selects an exact Python executable when the
  default isolated environment is not appropriate.  Leave it at ~nil~ for the
  installation path used above.
- ~emacsvox-ocr-paddleocr-language~ and ~emacsvox-ocr-paddleocr-device~ select
  the recognition language and Paddle device.
- ~emacsvox-ocr-paddleocr-use-table-recognition~ and
  ~emacsvox-ocr-paddleocr-use-formula-recognition~ control the structural
  models.  Both are enabled by default.
- ~emacsvox-ocr-paddleocr-use-document-orientation~,
  ~emacsvox-ocr-paddleocr-use-document-unwarping~, and
  ~emacsvox-ocr-paddleocr-use-text-line-orientation~ control image correction.
- ~emacsvox-ocr-paddleocr-enable-mkldnn~ enables oneDNN/MKL-DNN acceleration.
  It does not enable or disable any OCR model.  Keep it disabled for the tested
  PaddlePaddle 3.3.0 CPU setup on WSL.

The PaddleOCR options apply only while ~emacsvox-ocr-engine~ names the bundled
adapter.  Selecting a different engine preserves the generic engine interface.
~emacsvox-ocr-engine-options~ remains an advanced list of literal arguments;
for the bundled adapter it follows, and can override, the typed options.

The environment variables are retained for direct shell or automation use of
~bin/emacsvox-paddleocr~, not as the primary Emacs configuration interface.
~EMACSVOX_PADDLEOCR_VENV~ changes the launcher's environment directory,
~EMACSVOX_PADDLEOCR_PYTHON~ selects an exact Python executable, and
~EMACSVOX_PADDLEOCR_LANGUAGE~ or ~EMACSVOX_PADDLEOCR_DEVICE~ changes the
standalone defaults.  See ~./bin/emacsvox-paddleocr --help~ for command-line
switches.

The direct SANE scanner-acquisition commands are retained for compatibility
but are not part of this tested WSL baseline.  It is usually simpler to scan
with a Windows application and choose the resulting image or PDF with ~o~.
Scanner configuration is independent of PaddleOCR.
