* Notmuch Mail
:PROPERTIES:
:TEXINFO_NODE_NAME: Notmuch Mail
:DESCRIPTION: Read and manage Notmuch mail with speech.
:END:

#+cindex: Notmuch mail
#+cindex: mail search, Notmuch
#+cindex: asynchronous search, Notmuch
#+findex: notmuch

Notmuch provides the mail index and Emacs interface. Install compatible
command-line and Emacs components, then configure the mail store and database
using the [[https://notmuchmail.org/doc/latest/notmuch-emacs.html][Notmuch Emacs manual]]. Emacsvox does not fetch or send mail,
create the database, or replace Notmuch's commands. It adds structured speech
to Hello, Search, and Show; Tree has more limited support, described below.

Follow this chapter to search, read, and manage mail with speech, then adjust
which information is spoken automatically. The generated
[[info:emacsvox-reference#emacsvox-notmuch][emacsvox-notmuch]] section in the /Emacsvox Reference Manual/ provides the
complete command and option reference.

** Start Notmuch
:PROPERTIES:
:TEXINFO_NODE_NAME: Starting Notmuch
:ALT_TITLE: Start Notmuch
:DESCRIPTION: Open Hello or start a query with the speech integration loaded.
:END:

#+cindex: starting Notmuch
#+cindex: Notmuch Hello
#+findex: notmuch-search

Run ~M-x notmuch~ to open Hello. With the standard Emacsvox global maps
loaded, ~C-' m~ runs =notmuch-search= directly and asks for a query.
Emacsvox loads its integration when Notmuch loads and marks new Hello, Search,
Show, and Tree buffers with Notmuch semantic context.

Loading speech support does not alter mail, tags, files, or Notmuch
configuration. Notmuch owns database, tag, archive, attachment, and composition
operations; Emacsvox presents the result of the action you invoke.

** Use Hello and start a search
:PROPERTIES:
:TEXINFO_NODE_NAME: Notmuch Hello And Searches
:ALT_TITLE: Use Hello and start a search
:DESCRIPTION: Choose a search and understand asynchronous results and refreshes.
:END:

#+cindex: saved searches, Notmuch
#+cindex: widgets, Notmuch Hello

Moving among Hello widgets speaks each saved search's label and displayed
message count, or identifies the button or link reached. Use these common
Hello commands:

#+attr_texinfo: :indic kbd :compact t
- TAB ::

  =widget-forward= reaches the next search, field, button, or link.
- <backtab> ::

  =widget-backward= reaches the preceding widget.
- RET ::

  =widget-button-press= activates the widget; on a saved search it starts
  the query.
- j ::

  =notmuch-jump-search= chooses a configured search.
- g ::

  =notmuch-refresh-this-buffer= refreshes Hello.
- m ::

  =notmuch-mua-new-mail= starts composition, handled by Message mode and
  the separate =emacsvox-message= integration.

Press ~?~ in a Notmuch view or ~C-h m~ for the bindings supplied by your
installed Notmuch version. A search can display its first result before all
rows finish rendering, so an initial message announcement and a later count
need not arrive together.

*** Understand asynchronous search completion
:PROPERTIES:
:TEXINFO_NODE: no
:END:

#+cindex: search results, asynchronous rendering
#+cindex: notification stream, Notmuch
#+vindex: emacsvox-notmuch-search-completion-style

The default =adaptive= policy gives useful early feedback without rereading
content after you have moved on. For a search you start, other than a refresh,
a progress cue is given while its buffer remains selected. The first complete
result can then be spoken while the search continues, using the same summary,
voices, and status cues as thread navigation. This never moves point or reads
an empty row.

When the new search remains selected, you have issued no command in it, and
no input is pending, the first result is spoken once on the main stream.
Completion reports the final thread count on the notification stream without
repeating that result. If completion occurs before an early result could be
announced, it reports the count and result at point, or a zero-thread summary.

If you navigate, invoke another command, or leave before completion, the later
announcement is only a generic count on the notification stream. It does not
reread the selected row or disclose the query, sender, recipients, subject,
tags, or attachment metadata. Killing the owning search buffer silently
cancels that delivery.

**** Refresh an existing result
:PROPERTIES:
:TEXINFO_NODE: no
:END:

An explicit refresh differs from a new search. It queues only the generic
count on the main stream, without interrupting speech already playing.
Navigation can interrupt this announcement, including after you leave the
search buffer before the refresh finishes. Refresh completion never rereads
the selected row.

**** Choose less automatic feedback
:PROPERTIES:
:TEXINFO_NODE: no
:END:

=summary= gives a generic count and completion cue; =cue= gives only the cue;
=silent= suppresses successful completion. These policies use the same
main-stream selection for refreshes. Other search summaries use the
notification stream. Failures remain audible and generic with every policy;
refresh failures also use the main stream. The deliberate global refresh-all
command remains silent.

Use the focused settings described under [[Notmuch fields and privacy][Notmuch fields and privacy]] to choose
a policy. [[info:emacsvox#Aural Speech Output][Speech Output And Notifications]] explains the general stream behaviour;
the refresh rules above are specific to this integration.

** Navigate and inspect Search results
:PROPERTIES:
:TEXINFO_NODE_NAME: Notmuch Search Results
:ALT_TITLE: Navigate and inspect Search results
:DESCRIPTION: Read thread summaries, inspect full fields, and open a result.
:END:

#+cindex: Notmuch Search
#+cindex: search fields, Notmuch

Thread movement reads configured semantic fields and status cues. At a boundary,
speech identifies the beginning or end instead of repeating the current row.
Emacsvox makes the arrow keys equivalent to Notmuch's next and previous thread
commands.

#+attr_texinfo: :indic kbd :compact t
- n ::

  Run =notmuch-search-next-thread=.
- <down> ::

  Also run =notmuch-search-next-thread=.
- p ::

  Run =notmuch-search-previous-thread=.
- <up> ::

  Also run =notmuch-search-previous-thread=.
- RET ::

  Run =notmuch-search-show-thread=. Show lands on a useful visible body
  line or leaf MIME part and presents the opened message.
- SPC ::

  Run =notmuch-search-scroll-up=. This scrolls the viewport rather than
  selecting a semantic thread.
- C-c C-p ::

  Run =emacsvox-notmuch-speak-search-details= to read all configured fields
  for the result at point without automatic content limits.
- + ::

  Run =notmuch-search-add-tag=.
- - ::

  Run =notmuch-search-remove-tag=.
- * ::

  Run =notmuch-search-tag-all= for the selected results.
- a ::

  Run =notmuch-search-archive-thread=.
- g ::

  Run =notmuch-refresh-this-buffer=; completion follows the interruptible
  refresh policy above.

Search defaults to authors, subject, relative date, matched and total message
counts, and ordinary tags. Status tags assigned auditory cues are not repeated
as words. [[Notmuch fields and privacy][Notmuch fields and privacy]] explains omission and ordering of sensitive fields.

** Read a thread and its MIME parts
:PROPERTIES:
:TEXINFO_NODE_NAME: Notmuch Messages And Attachments
:ALT_TITLE: Read a thread and its MIME parts
:DESCRIPTION: Read messages, inspect attachments, and choose explicit MIME actions.
:END:

#+cindex: Notmuch Show
#+cindex: MIME parts, Notmuch
#+cindex: attachments, Notmuch

Opening a thread selects its newest unread message among the open messages
matching the search. If there is none, Notmuch's initial selection is retained.
Emacsvox speaks the selected message's summary and first visible body line,
skipping hidden alternative bodies. When no body text is visible, point falls
back to a leaf MIME-part button where possible. That button announces a
bounded filename, content type, and size.

Line reading speaks a visible sender row even if the preceding message ends
with folded quoted text; it does not unfold the quote. In a short graphical
window, Down advances through ordinary body text before speaking the next
line, even when the current line is only partly visible. Images or text taller
than the window retain Emacs's partial scrolling.

Tab and Shift-Tab move through the same sequence of links and MIME controls
in either direction. HTML links retain their link voice without a navigation
earcon; MIME controls keep their part descriptions and cues. Link navigation
does not speak the destination URL on the notification stream.

When a row contains one visible MIME control and otherwise only whitespace,
you can use Enter or the part actions below from the indentation or trailing
space. Your reading position stays on that row. Enter shows or hides content
that Notmuch can display; otherwise it uses
=notmuch-show-part-button-default-action=, normally saving the part. Speech
confirms the visibility change or the save/view action once. Rows containing
other text or multiple controls require you to move onto the intended control.

#+attr_texinfo: :indic kbd :compact t
- n ::

  Run =notmuch-show-next-open-message=.
- p ::

  Run =notmuch-show-previous-open-message=.
- N ::

  Run =notmuch-show-next-message=, including closed messages.
- P ::

  Run =notmuch-show-previous-message=, including closed messages.
- SPC ::

  Run =notmuch-show-advance-and-archive=. Within a message, speech reads the
  newly visible page; at a message transition it reads the new message;
  at the thread end it reports the actual archive outcome and destination.
- DEL ::

  Run =notmuch-show-rewind= and read the resulting page or message.
- RET ::

  Activate the button or the single MIME control on its row. Elsewhere,
  run =notmuch-show-toggle-message= and cue the resulting visibility.
- M-RET ::

  Run =notmuch-show-open-or-close-all= to open every message and report the
  state and total, for example ``Opened all 5 messages.'' ~C-u M-RET~ closes
  every message and reports the corresponding total.
- C-c C-p ::

  Run =emacsvox-notmuch-speak-show-position= for the message ordinal, total,
  and full configured details. On a MIME-part button it instead reads the
  complete part description, including its full filename.
- TAB ::

  Run =notmuch-show-next-button= and identify the button or MIME part.
- <backtab> ::

  Run =notmuch-show-previous-button= and identify the button or MIME part.
- w ::

  Run =notmuch-show-save-attachments=. Speech confirms when the command
  returns, but Notmuch exposes no per-attachment result here. The
  confirmation therefore cannot distinguish partial skips.
- . s ::

  Run =notmuch-show-save-part= on the current MIME part.
- . v ::

  Run =notmuch-show-view-part=.
- . o ::

  Run =notmuch-show-interactively-view-part= and choose an external action.
- . m ::

  Run =notmuch-show-choose-mime-of-part=.

These are the ordinary Show bindings. Table reading temporarily changes the
reading keys described below. Viewing, saving, overwriting, or launching a
MIME part is an explicit Notmuch operation. Navigation and detail inspection never open an attachment or an
external viewer by themselves.

*** Read a table in an HTML message
:PROPERTIES:
:TEXINFO_NODE: no
:END:

When you move into a supported data table, Emacsvox announces table reading,
its dimensions and the current cell. The first row supplies column titles.
Use Control-Meta-left/right to change columns and Control-Meta-up/down to
change rows while retaining the column. These keys read the complete cell,
even when its text wraps across several displayed lines. Blank cells say
“blank.” Plain Up/down reads the complete destination row by default.

Press ~SPC~ to repeat the cell, ~r~ for its row, or ~c~ for its column.
~.~ gives coordinates and ~=~ gives dimensions. Tab, Shift-Tab and Enter keep
their usual link and MIME actions. Press ~q~ to leave table reading in place
and restore ordinary mail keys, including reply, archive, attachment saving
and the MIME-part prefix. Another ~q~ then performs Notmuch's usual quit.
Meta-up/down leaves for the content before or after the table. Reading never
changes the message or its tags.

Automatic entry is the initial HTML-mail policy. To change it, press ~a~
inside the table or run ~M-x emacsvox-table-settings~ from the message.
The common, mode and buffer choices work as described under
[[info:emacsvox#Reading Markdown And Org Tables][table reading preferences]]. An explicit On demand choice starts reading only
with Control-Meta arrows or ~C-e C-t C-r~. After quitting, automatic entry
stays suspended until you leave the table and return or explicitly enter
again. A message refresh ends reading; enter again after the refresh.

Supported tables have at least two rows and columns, a header row marked
as headings or bold text, and no merged cells. Layout tables, nested tables
and tables without a recognisable header retain ordinary mail navigation.
For these, you can use normal text reading; the separate
~M-x emacsvox-eww-table-data~ view also remains available for simple tables
when the EWW integration is loaded. A message already displayed before HTML
table support was loaded needs a refresh before it has cell navigation.

** Change tags and archive state
:PROPERTIES:
:TEXINFO_NODE_NAME: Notmuch Tags And Archiving
:ALT_TITLE: Change tags and archive state
:DESCRIPTION: Hear the actual outcome of tag and archive commands.
:END:

#+cindex: tags, Notmuch
#+cindex: archiving, Notmuch

Emacsvox compares displayed tags before and after an interactive change and
reports actual additions and removals. Adding an existing tag or removing an
absent tag reports ``Tags unchanged''. Errors and cancelled commands do not
produce success feedback.

These Show commands receive result-aware feedback:

#+attr_texinfo: :indic kbd :compact t
- + ::

  Run =notmuch-show-add-tag= on the current message.
- - ::

  Run =notmuch-show-remove-tag=.
- * ::

  Run =notmuch-show-tag-all= across the thread.
- a ::

  Run =notmuch-show-archive-message-then-next-or-next-thread=.
- A ::

  Run =notmuch-show-archive-thread-then-next=.

Archive feedback distinguishes a real change, unchanged archive tags, and an
unset =notmuch-archive-tags=. Movement wrappers combine the result instead of
duplicating the feedback of nested tag or archive commands.

** Choose fields, status, and privacy
:PROPERTIES:
:TEXINFO_NODE_NAME: Notmuch Speech And Privacy
:ALT_TITLE: Choose fields, status, and privacy
:DESCRIPTION: Set spoken fields, automatic limits, completion policy, and privacy.
:END:

<<Notmuch fields and privacy>>

#+cindex: privacy, Notmuch speech
#+cindex: fields, Notmuch speech
#+cindex: status cues, Notmuch
#+cindex: automatic speech limits, Notmuch

From a Notmuch buffer, press ~C-e S~ for focused speech settings, or reach it
through ~C-e H j c~. The same menu is available from Hello, Search, Show, and
Tree. Availability of settings in Tree does not add Tree-specific navigation
or message formatting.

~c~ opens explained completion choices. Arrows browse without applying,
~RET~ applies and returns, and ~q~ cancels. ~?~ followed by a choice's key
opens spoken Help; ~q~ returns to that browsed choice. In the parent menu,
~f~ and ~b~ control per-field character and UTF-8 byte limits, while ~t~ and
~B~ control total limits. Shift-left/right adjusts a selected limit by 100;
~RET~ accepts an exact positive integer or =none=. Disabling one limit leaves
the others active. ~w~ saves these four limits and completion policy as the
five displayed global defaults, not every Notmuch option.

For ordered search/message fields, use ~s~ and ~m~. Uppercase ~S~ and ~M~
edit the text separating spoken search and message fields respectively;
punctuation policy affects how that text sounds. ~i~ and ~I~ open the
status-tag and fallback-cue maps. These linked Customize editors retain custom
formatter functions and use their own Apply, Save, and Reset actions. Returning
with ~q~ does not save them. ~p~ opens Presentation Options and ~A~ advanced
settings. Search at ~C-e H /~ finds both separators after Notmuch is loaded.
The full group is also available through
~M-x customize-group RET emacsvox-notmuch RET~. These speech settings do not
alter Notmuch's database or its own display configuration.

*** Choose the information in a spoken summary
:PROPERTIES:
:TEXINFO_NODE: no
:END:

#+attr_texinfo: :indic code :compact t
- emacsvox-notmuch-search-result-fields ::

  Defaults to =(authors subject date count tags)=. Remove sensitive fields,
  reorder them, or add a formatter function.
- emacsvox-notmuch-show-message-fields ::

  Defaults to =(from date to cc tags attachments)=. Show omits the subject
  but includes To and Cc; remove =to=, =cc=, or other fields when privacy
  requires it.
- emacsvox-notmuch-search-field-separator ::
- emacsvox-notmuch-show-field-separator ::

  Set the text between configured fields. Both default to comma and space.
- emacsvox-notmuch-search-status-icons ::
- emacsvox-notmuch-show-status-icons ::

  Map unread, replied, forwarded, flagged, and personal tags to cues or
  silence. Removing an entry makes that status available to ordinary tag
  speech. When =mail-message-status-cues= is enabled in Presentation
  Options, its rules own the shared semantic status cues; the maps still
  suppress the corresponding spoken status tags.
- emacsvox-notmuch-search-completion-style ::

  Select =adaptive=, =summary=, =cue=, or =silent= using the completion
  behaviour described earlier.

*** Understand limits and full inspection
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Automatic Search and Show summaries are bounded before speech and Aural history.
Defaults are 256 characters and 1,024 UTF-8 bytes per field, then 1,000
characters and 4,096 bytes for the complete automatic presentation.

#+attr_texinfo: :indic code :compact t
- emacsvox-notmuch-automatic-field-character-limit ::
- emacsvox-notmuch-automatic-field-byte-limit ::

  Bound each automatic field before formatting and submission.
- emacsvox-notmuch-automatic-total-character-limit ::
- emacsvox-notmuch-automatic-total-byte-limit ::

  Bound the final automatic Notmuch presentation.
- emacsvox-notmuch-mime-node-limit ::
- emacsvox-notmuch-mime-depth-limit ::

  Default to 4,096 cons nodes and depth 64, limiting inspection of malformed,
  cyclic, broad, or deeply nested MIME metadata. An incomplete scan reports
  a conservative attachment lower bound, not a claim that no attachment exists.

A shortened Search or Show announcement explains what was omitted and points
to ~C-c C-p~ for full configured details. A shortened Hello item points to
~RET~. Explicit Search and Show inspection deliberately bypasses automatic
content limits; use it only when speaking the full configured fields is
appropriate. Body-line and table reading speak the content you navigate to;
summary limits do not shorten their cells or rows. These limits are not a
general privacy guarantee for every
explicit command or another application's output.

*** Understand retained and notification content
:PROPERTIES:
:TEXINFO_NODE: no
:END:

#+cindex: Aural history, mail privacy

Main-stream Notmuch presentations can enter bounded Aural history. By default,
Emacsvox retains at most 20 presentations and 4,096 UTF-8 bytes of speech
preview per record. Records contain frozen data, source names, and positions,
but never retain source buffers. Inspect them through ~C-e H f h~ or
~M-x emacsvox-aural-list-recent-feedback~. Set
=emacsvox-aural-presentation-history-limit= to zero to disable this history.

Generic asynchronous completion contains no query or message metadata, but a
notification-stream completion may be retained by the notification subsystem.
Choose =cue= or =silent= if even a generic thread count is unwanted. Review
notification-device and logging settings separately from mail field choices.

** Know the support boundaries
:PROPERTIES:
:TEXINFO_NODE_NAME: Notmuch Support Boundaries
:ALT_TITLE: Know the support boundaries
:DESCRIPTION: Distinguish supported views, limited Tree support, and composition.
:END:

#+cindex: Notmuch Tree support
#+cindex: message composition, Notmuch

#+attr_texinfo: :indic asis :compact t
- Hello ::

  Widget navigation, view lifecycle, and searches have Notmuch-specific feedback.
- Search ::

  Results, asynchronous lifecycle, tags, archiving, opening, and configured
  detail inspection have Notmuch-specific feedback.
- Show ::

  Messages, HTML data tables, MIME parts, pages, visibility, tags, archiving,
  and explicit inspection have Notmuch-specific feedback.
- Tree ::

  Receives =emacsvox-aural-module= context only. Core speech can operate,
  but this module has no Tree-specific row formatter, navigation, mutation,
  visibility, or asynchronous lifecycle.
- Composition ::

  Standard Message mode owns composition. Speech after new-mail, reply,
  forward, or resume transitions belongs to =emacsvox-message=, not the
  Notmuch integration.

There is no independent Notmuch speech-disable or unload command. Its advice,
hooks, and Search arrow bindings remain installed for the Emacs session after
loading. Repeated loading is idempotent and does not duplicate them.

** Troubleshoot the live integration
:PROPERTIES:
:TEXINFO_NODE_NAME: Notmuch Troubleshooting
:ALT_TITLE: Troubleshoot the live integration
:DESCRIPTION: Check live keys, package identity, and the speech diagnostics.
:END:

#+cindex: troubleshooting, Notmuch
#+cindex: byte-code, Notmuch integration

Use ~?~ or ~C-h m~ in the affected view to check its current keys and
~M-x notmuch-version~ to identify the package. Consult Notmuch's own manual
for its behaviour before treating a database or display problem as a speech
problem.

For bindings, loaded source versus byte-code, presentation rules, sounds, or
backend issues, open Aural Doctor through ~C-e H D d~ or
~M-x emacsvox-aural-doctor~. Recent feedback at ~C-e H f h~ or
~M-x emacsvox-aural-list-recent-feedback~ shows the bounded presentation
submitted for an action. These diagnostics do not query or modify mail.

For source-level work, [[*Integration Maintenance][Integration Maintenance]] contains the build, test,
renderer, and asynchronous lifecycle contracts.
