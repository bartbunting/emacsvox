* Agent Shell
:PROPERTIES:
:TEXINFO_NODE_NAME: Agent Shell
:DESCRIPTION: Use Agent Shell with structured spoken feedback.
:END:

#+cindex: Agent Shell

#+cindex: artificial intelligence agents

Agent Shell is an Emacs package for interactive AI-agent sessions. Emacsvox
adds speech and structured navigation to its prompts, responses, permissions,
and other activity. Agent Shell remains responsible for providers, sessions,
prompt editing, and permission decisions. Install and configure Agent Shell
using [[https://github.com/xenodium/agent-shell][its own documentation]]; Emacsvox requires version 0.85.3 or newer.

This chapter follows a session from writing a prompt through receiving and
reviewing an answer, then explains speech choices and recovery. The generated
[[info:emacsvox-reference#emacsvox-agent-shell][emacsvox-agent-shell]] section in the /Emacsvox Reference Manual/ lists the
complete Emacsvox command and option interfaces.

** Start and control a session
:PROPERTIES:
:TEXINFO_NODE_NAME: Starting An Agent Shell Session
:ALT_TITLE: Start and control a session
:DESCRIPTION: Write prompts, follow responses, steer work, and manage queued input.
:END:

Load Emacsvox and start Agent Shell with ~M-x agent-shell~.  Emacsvox loads
its integration after Agent Shell and activates both new and already existing
shell buffers.  Run ~M-x emacsvox-agent-shell-enable~ only when manually
re-enabling support after it was disabled or while diagnosing a live reload.

*** Write and edit prompts
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Compose and submit prompts with Agent Shell's normal editing commands.  The
live prompt retains Emacs undo. Interactive text yanks speak the inserted
text, including when a prefix argument selects a different kill-ring entry.
Image attachment keeps Agent Shell's existing feedback. Submitted transcript
text is history rather than editable prompt input.  Press ~C-c C-c~ to ask Agent Shell to interrupt
an active request; its normal confirmation setting still applies.

With Agent Shell's persistent prompt enabled, you can keep typing while the
agent works.  Brackets and navigation letters remain ordinary input at
that prompt.  Reading the live prompt says “Agent busy” while the agent works.
A pending permission is announced
as “Waiting for permission”; a pending question says “Waiting for an answer.”
These cues also precede the first line of a draft;
later lines keep ordinary reading feedback.  “Ready for input” is reserved for
an empty prompt when the agent is idle.

Quoting a selected region, sending source context,
dropping files, and inserting shell-command output can add to that live draft
while the agent works. These insertions do not submit the draft. If there is
no live prompt while busy, Agent Shell offers its queue editor instead.
Use ~M-x yank-media~ to attach a clipboard image on a display that supports
native clipboard access. Image previews survive queueing and steering.
The animated busy marker does not add repeated speech; reading the prompt
continues to give its current state.

In the viewport prompt editor, continuing a list announces its bullet or next
number and indentation.  Indenting and dedenting announce the new indentation;
leaving an empty list item announces that the list ended.

*** Follow a response and steer a running turn
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Emacsvox speaks routine content only at complete turn boundaries.  A network
pause does not make a partial answer sound complete.  A cancelled, refused, or
failed turn reports its outcome without replacing the last successfully
completed response.

In the viewport editor, Emacsvox announces whether a prompt was
submitted, queued, or sent for steering, and whether the editor stays open.
The normal and override send commands follow Agent Shell's configured busy
routes, including queueing when the provider does not support steering.
“Steering sent” confirms dispatch; the agent's acceptance or refusal follows
separately.

When you use ~M-x agent-shell-prompt-steer~, Emacsvox confirms whether the
agent accepted the steer, declined it, or started a separate turn.  A separate
turn is announced as still in progress; it is not reported as complete until
Agent Shell supplies a completion boundary.  Server-pushed turns, when
supported by the provider, follow the same completed-response speech policy.

*** Work with queued prompts
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Queued prompts announce when they start and how many remain. Recent Agent Shell
versions merge queued prompts into one turn by default; Emacsvox announces how
many prompts started together. Set =agent-shell-prompt-queue-merge= to nil to
send them one turn at a time. After cancellation, Agent Shell asks whether to
continue with the queue. If you decline, or a failed turn leaves prompts waiting,
the queue announcement gives its count and the command
~M-x agent-shell-prompt-queue-resume~. Queue-start feedback
follows the session's speech level; paused-queue warnings follow
=emacsvox-agent-shell-signal-processing=.
Agent Shell also asks before killing a shell or exiting Emacs when queued
prompts would be lost. Declining that question keeps the prompts available.

*** Check session settings and status
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Model, mode, thought-level, and other session setting changes announce their
confirmed values.  Background setting announcements identify the session.
When grouped choices share a name, confirmation includes the group shown by
Agent Shell's completion menu.

Use ~M-x emacsvox-agent-shell-speak-header~ to hear the full session header.
When =agent-shell-show-cost-indicator= is enabled and the provider reports a
positive cost, this includes the cumulative cost with Agent Shell's currency
and rounding.  Brief announcements when entering a session stay concise.

** Answer an agent's question
:PROPERTIES:
:TEXINFO_NODE_NAME: Answering Agent Questions
:ALT_TITLE: Answer an agent's question
:DESCRIPTION: Review and complete an optional structured question form.
:END:

Some providers ask you to complete a structured form rather than answer in
ordinary prompt text. Agent Shell's form support is experimental and off by
default. To try it, set =agent-shell-elicitation--experimental-feature-enabled=
to non-nil after loading Agent Shell and start a new session so the agent learns
that forms are supported. This upstream experimental setting may change.

When a form arrives, Emacsvox announces that an answer is needed and reads the
question. Automatic question feedback follows the session's speech level;
=quiet= suppresses it. Explicit reading and actions still speak.

Use ~TAB~ and ~S-TAB~ to move between controls in the shell or viewport.
Emacsvox reads the field name, whether it is required, and its current value or
selection state. Press ~RET~ to select an option, toggle a checkbox, or edit a
text or number field. Changes are confirmed after they take effect. When an
option has a preview, ~?~ opens or closes it; opening it reads its contents.
The preview key applies only to controls that offer a preview.

Choose /Submit/ to send the answers or /Decline/ to decline the question.
Missing required answers are reported without announcing successful submission.
~C-c C-c~ interrupts the running request, including any pending form. To return
to the latest question, use ~M-x agent-shell-elicitation-jump-to-latest-form~.
The next-field and previous-field commands are also available through ~M-x~.

** Choose automatic speech and privacy
:PROPERTIES:
:TEXINFO_NODE_NAME: Agent Shell Speech And Privacy
:ALT_TITLE: Choose automatic speech and privacy
:DESCRIPTION: Choose session feedback, background disclosure, and automatic limits.
:END:

The focused session defaults to =response=: completed answers and routine
completion feedback are presented, while thought, plan, and tool chatter is
suppressed.  An unfocused session defaults to =notify=: its notification
names the session but does not disclose response or tool content.

#+attr_texinfo: :indic code :compact t
- full ::

  Speak responses plus configured thought, plan, and tool detail.  Full tool
  output can contain commands, file contents, or other sensitive provider data.
- response ::

  Speak completed agent responses while suppressing routine thought, plan, and
  tool content.
- notify ::

  Present routine completion without reading the response body.
- quiet ::

  Suppress routine automatic feedback.  Explicit inspection remains available.
- auto ::

  Use =emacsvox-agent-shell-foreground-speech-level= or
  =emacsvox-agent-shell-background-speech-level= according to focus.

Press ~C-c C-q~ to run
=emacsvox-agent-shell-select-speech-level= and choose the current
session's level, including =auto=.  Press ~C-c C-S-q~ to run
=emacsvox-agent-shell-select-background-speech-level= and change the
shared background default.
~M-x emacsvox-agent-shell-cycle-speech-level~ cycles toward less routine
speech; use a prefix argument to restore =auto=.

*** Adjust speech in the settings menu
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Press ~C-e S~ in an Agent Shell buffer or its viewport for focused Emacsvox
settings. The same menu is available through ~C-e H j c~ and the integration
chooser. ~s~ opens choices for the temporary session override. ~f~ and ~b~
open foreground and background defaults; ~t~ and ~o~ open thought and tool-output
choices. Each list starts on the current value and explains its choices.
Browse with arrows, press ~RET~ to apply and return, or ~q~ to cancel. Press
~?~ followed by a choice's key for its effect and scope; ~q~ returns from
Help. ~? ?~ opens the menu overview.

The ~p~, ~c~ and ~l~ controls toggle permission speech, tool-call announcements
and processing cues. Thought and tool content still depend on the effective
speech level.

~T~ opens the shared Tables settings page described in
[[*Reading Markdown and Org tables][Reading Markdown and Org tables]]. It has separate buffer Apply, common Save
and mode Save actions.

The ~a~, ~n~ and ~k~ controls set automatic-content, line-navigation and
block-navigation character limits. ~RET~ accepts an exact positive integer or
=none=; Shift-left/right adjusts by 100. For line navigation, =none= restores
the core long-line policy. For the other limits it allows complete content.
~w~ saves the displayed global defaults through Customize, excluding the
session override. ~A~ opens advanced settings; ~q~ returns. From the direct
~C-e S~ entry, ~q~ closes the menu and leaves you in the captured buffer.

Thought content defaults to an icon under
=emacsvox-agent-shell-speak-thought-process=.  Tool feedback is separately
controlled by =emacsvox-agent-shell-speak-tool-calls= and
=emacsvox-agent-shell-tool-output-verbosity=.  Selecting background
=response= or =full=, thought =speak=, or full tool output is an
explicit disclosure choice.

At =full= speech level, tool verbosity =full= reads the tool's rendered output,
including Codex command output and textual diffs.  Changed output can be read
even when the tool's status has not changed; identical updates are suppressed.
Tool verbosity =status= plays status cues as tools start and finish.
Tool updates, steering outcomes, queue changes, and confirmed setting changes
use the notification lane, leaving navigation speech independent.

*** Understand automatic speech limits
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Automatic response, tool, error, permission, and similar text is limited by
=emacsvox-agent-shell-automatic-content-max-characters=, which defaults to
2,000 characters.  A shortened presentation gives exact omitted character and
line counts and tells you where to inspect the full content.  The complete text
rendered by Agent Shell stays in its buffer; Emacsvox limits the automatic
announcement rather than editing that displayed text. Agent Shell separately shortens tool
output lines longer than 32,768 characters, keeping their beginning and end with
an omitted-character count. Full tool speech reads that notice; the removed
middle is not available by reading the buffer.

** Respond to urgent permissions
:PROPERTIES:
:TEXINFO_NODE_NAME: Agent Shell Permissions
:ALT_TITLE: Respond to urgent permissions
:DESCRIPTION: Find and decide a permission request without confusing routine speech.
:END:

Permission requests are separate from routine speech levels because they can
block the agent and require a decision.  With
=emacsvox-agent-shell-speak-permissions= enabled, a request interrupts the
appropriate speech stream, identifies the session and requested operation, and
announces its choices.  Provider-controlled descriptions and choice labels are
bounded, but the actual permission controls remain in Agent Shell.

If the provider supplies new operation details after asking permission,
Emacsvox announces the changed description or input.  Identical updates and
routine output do not repeat the warning.  The permission controls remain the
place to inspect and decide the request.

If the request belongs to another session, switch to the named buffer.  Use
~M-x agent-shell-jump-to-latest-permission-button-row~ to find its latest
permission row, or use Agent Shell's ~TAB~ and ~S-TAB~ item navigation.
Move among the buttons and press ~RET~, or use a direct choice key displayed
by Agent Shell.  Choice keys are supplied by Agent Shell and the provider, so
the visible permission row is authoritative.

Error blocks remain exceptional feedback rather than routine transcript
chatter.  Lifecycle error announcements follow
=emacsvox-agent-shell-signal-processing=; rendered error content remains
available in the transcript even when routine response speech is quiet.

** Inspect a response on demand
:PROPERTIES:
:TEXINFO_NODE_NAME: Reading Agent Responses
:ALT_TITLE: Inspect a response on demand
:DESCRIPTION: Read a completed response in full or request a structural overview.
:END:

These commands work from the shell and its associated viewports:

#+attr_texinfo: :indic kbd :compact t
- C-c r ::

  Run =emacsvox-agent-shell-speak-last-response=.  It reads the latest
  successfully completed response in full without moving point.  This deliberate
  operation does not inherit the automatic 2,000-character limit.  While a new
  turn is busy it explicitly identifies and reads the prior completed response.
- C-c R ::

  Run =emacsvox-agent-shell-speak-response-overview=.  It reports line,
  heading, source-block, and table counts plus a bounded opening preview.

These commands remain usable at =notify= and =quiet=.  If no turn has
completed, they say that no completed response is available rather than
presenting a streaming partial or failed answer.

** Navigate transcript blocks
:PROPERTIES:
:TEXINFO_NODE_NAME: Agent Shell Transcript Navigation
:ALT_TITLE: Navigate transcript blocks
:DESCRIPTION: Move among responses, prompts, headings, links, tools, and errors.
:END:

Agent Shell responses contain semantic prompt, response, thought, activity,
tool, plan, permission, error, source-block, and table locations.  Emacsvox
navigation reports the block type, visibility, and a bounded body preview.

Up and Down play the ellipses cue when you enter a collapsed heading, such as
Capabilities, Models, or Notices. Wrapped continuation rows do not repeat the
cue; leaving and returning to the heading plays it again. The optional block
visibility cue replaces this default cue. Reading the current line with
~C-e l~ continues to indicate hidden content.

#+attr_texinfo: :indic kbd :compact t
- h / H ::

  Use ~h~ (=emacsvox-agent-shell-next-heading=) or
  ~H~ (=emacsvox-agent-shell-previous-heading=).
  Move to the next or previous visible Markdown heading and speak its text.
- k / K ::

  Use ~k~ (=emacsvox-agent-shell-next-source-block=) or
  ~K~ (=emacsvox-agent-shell-previous-source-block=).
  Move to the next or previous source block and announce its language and
  line count. Inside a table, lowercase ~k~ remains the table
  copy prefix; use ~M-x emacsvox-agent-shell-next-source-block~ to jump forward
  to code from there.
- u / U ::

  Use ~u~ (=emacsvox-agent-shell-next-user-prompt=) or
  ~U~ (=emacsvox-agent-shell-previous-user-prompt=).
  Move to the next or previous submitted user prompt, skipping the live editor.
- j / J ::

  Use ~j~ (=emacsvox-agent-shell-next-response=) or
  ~J~ (=emacsvox-agent-shell-previous-response=).
  Move to the next or previous agent response and speak its bounded body
  preview. These keys skip intervening thoughts, tools, and other block types.
  From code or a table inside an answer, they skip that enclosing answer.
- l / L ::

  Use ~l~ (=emacsvox-agent-shell-next-link=) or
  ~L~ (=emacsvox-agent-shell-previous-link=).
  Move to the next or previous visible rendered link and speak its label and
  Return action together. The cursor hint remains visible without a second
  voice repeating it.
  Press ~RET~ to follow the link.
- e / E ::

  Use ~e~ (=emacsvox-agent-shell-next-error=) or
  ~E~ (=emacsvox-agent-shell-previous-error=).
  Move to the next or previous error or failed tool call. Failed tools are
  identified by Agent Shell's error styling in their status label, rather than
  by words in their output.
- ] ::

  Run =emacsvox-agent-shell-next-block-at-point= to find the next block of
  the current semantic type.
- [ ::

  Run =emacsvox-agent-shell-previous-block-at-point= to find the preceding
  block of the current semantic type.
- C-c ] ::

  Run =emacsvox-agent-shell-next-block-of-type=, choose a type, and move to
  its next occurrence.
- C-c [ ::

  Run =emacsvox-agent-shell-previous-block-of-type=, choose a type, and move
  to its preceding occurrence.

After a successful typed jump, ~]~ and ~[~ repeat in that direction.
At an editable live prompt or viewport editor, bare brackets and navigation
letters insert themselves instead of taking over prompt editing.

** Read and copy source blocks
:PROPERTIES:
:TEXINFO_NODE_NAME: Agent Shell Source Blocks
:ALT_TITLE: Read and copy source blocks
:DESCRIPTION: Read logical code, copy it, and open a change review.
:END:

Use ~k~ or ~K~, or typed block navigation, to
reach a source block, then:

#+attr_texinfo: :indic kbd :compact t
- C-c C-b ::

  Run =emacsvox-agent-shell-speak-source-block= to read the complete rendered
  source block with its language and line count.
- C-c C-y ::

  Run =emacsvox-agent-shell-copy-source-block= to copy the logical source
  through Agent Shell's public copy operation.

The source commands are explicit operations and do not use the automatic
content limit.  Ordinary line navigation retains its separate bounded speech
policy.

*** Review proposed changes
:PROPERTIES:
:TEXINFO_NODE: no
:END:

Opening an Agent Shell change review announces its file and hunk counts and,
for a single file, its name.  The normal Diff Mode hunk navigation remains
available; opening the review does not accept or reject changes.

These events can have their own presentation rules. You can customise speech,
voices and earcons for steering outcomes, queue changes, list editing, setting
changes, updated tool output and change-review entry. Use
[[info:emacsvox#Explaining Presentation][Feedback Details]] to inspect a representative event before changing it.

** Navigate and copy rendered tables
:PROPERTIES:
:TEXINFO_NODE_NAME: Agent Shell Tables
:ALT_TITLE: Navigate and copy rendered tables
:DESCRIPTION: Read table cells, rows, and columns, and understand local key conflicts.
:END:

Agent Shell reads rendered Markdown tables through the shared table controls.
By default, moving into a table activates its contextual map and announces
the dimensions and current cell. Choose automatic or on-demand activation,
headings and speech detail in the common Tables page; see
[[*Reading Markdown and Org tables][Reading Markdown and Org tables]]. Older Agent Shell title and order choices
remain scoped to Agent Shell until you explicitly replace them or select
inheritance.

Control-Meta arrows enter reading on demand and move to the next cell.
~C-e C-t C-r~ or ~M-x emacsvox-table-reader-mode~ enters without moving.
Press ~q~ to leave reading in place. Automatic entry stays suspended until
you explicitly enter again or navigate out of the table and return; rendering
updates and resizing do not cancel that suspension. Leaving restores ordinary
Agent Shell keys. Tab, Shift-Tab and Return retain Agent Shell's native actions
throughout reading.

Plain Left and Right, or ~C-b~ and ~C-f~, move by character within the current
cell. ~M-b~ and ~M-f~, or Control-Left and Control-Right, move by word. These
commands follow wrapped text within the same cell, skipping borders, padding,
and neighbouring columns. At the beginning or end of the cell, they stop and
announce the boundary. Use Control-Meta-Left and Control-Meta-Right to move
between columns. Control-Meta-Up and Control-Meta-Down move between logical
rows in the current column and read only the destination cell. Plain Up and
Down make the same move and read the entire destination row by default;
the Tables page can select cell speech for these plain arrows. Wrapped cells
are read in full, using your table title settings.

~C-n~ and ~C-p~ retain ordinary line movement. They can move through wrapped
cell text, but do not stay within the logical cell or skip other columns.
Use character and word movement to follow the cell's text in order.

Outside editable input, press ~t~ for the next table or
~T~ for the previous table. These keys skip the current table
and announce the destination table and cell. Like the bracket navigation keys,
they insert themselves in a live prompt or viewport editor, including while
the agent is working.

*** Understand table key conflicts
:PROPERTIES:
:TEXINFO_NODE: no
:END:

In viewport view mode, ~t~ takes the place of Agent Shell's thought-level
shortcut; use ~M-x agent-shell-viewport-set-session-thought-level~ for that
action. Inside a table, ~r~, ~c~, and ~a~ read rows, read columns, and open
Tables settings. To invoke the displaced viewport actions there,
use ~M-x agent-shell-viewport-reply~, ~M-x agent-shell-viewport-reply-continue~,
or ~M-x agent-shell-viewport-reply-again~. In the shell transcript, table ~r~
replaces quoting; use ~M-x agent-shell-quote-region~ with a selected region.
Leaving reading restores these ordinary bindings. In a viewport, table ~q~
leaves reading rather than closing the view; a second ~q~ runs =bury-buffer=.
~M-x bury-buffer~ remains available directly.

Outside tables, ~C-M-<up>~ and ~C-M-<down>~ do nothing in Agent Shell,
including its viewport and prompt editor. Repeating a row key after leaving
a table therefore keeps point at the exit. These two keys also do nothing
in ordinary ~shell-mode~ buffers. For structural movement there, use
~M-x backward-up-list~ or ~M-x down-list~. Source-code buffers keep their
usual bindings.

Continuous speech and response-block reading omit rendered table borders and
keep the cell text. Decorative borders therefore do not force a switch to a
different speech engine. Literal box-drawing characters in prose or code remain
available to symbol naming and exact character inspection.

** Recover from interruption or failure
:PROPERTIES:
:TEXINFO_NODE_NAME: Agent Shell Recovery
:ALT_TITLE: Recover from interruption or failure
:DESCRIPTION: Interrupt work, inspect the previous response, and recover the session.
:END:

If a request is taking the wrong path, press ~C-c C-c~ and confirm the
Agent Shell interrupt.  A failed or interrupted partial response is not cached
as complete.  Press ~C-c r~ for the preceding completed response, or
~C-c R~ for its overview.  Read the error block in the transcript for the
provider's details and edit the live prompt before resubmitting.

Use ~M-x agent-shell-restart~ when Agent Shell itself needs a fresh process
for the same project.  Use ~M-x emacsvox-agent-shell-enable~ to reinstall
speech hooks after deliberately disabling them.  Neither recovery command
discards transcript files or project work.

If you are changing the integration rather than using it, see
[[*Integration Maintenance][Integration Maintenance]] for its public event, renderer, and
compatibility contracts.
