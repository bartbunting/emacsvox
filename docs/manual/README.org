#+title: Emacsvox User Manual Authoring
#+startup: content

* Source layout

[[file:emacsvox.org][emacsvox.org]] is the canonical master for the maintained
Emacsvox user manual.  It supplies document metadata and includes the chapter
files below [[file:chapters/][chapters/]] and the final developer guide below
[[file:../developer/][docs/developer/]].  Edit those Org files; do not edit the generated
=info/emacsvox-body.texi= or =info/emacsvox.info= files directly.  ADR 0004
defines the audience boundary: user tasks and recovery stay in =chapters/=;
protocols, integration contracts, source-level tests, and release mechanics
belong in =docs/developer/=.

The generated command/key reference and the historical heritage manuals remain
Texinfo.  They do not benefit from hand conversion to Org.

* Fast authoring loop

Edit one or more Org chapters, then run:

#+begin_example
make docs-org-preview
#+end_example

This uses the Emacs selected by =local.mk=, runs Org lint, exports the complete
manual, and builds Info plus a single-page HTML preview.  It does not load or
compile Emacsvox.  Ignored output lives below =.docs-preview/org-manual/=.

When the text is ready, update the tracked export and Info artifact:

#+begin_example
make docs-update
#+end_example

Before review, merge, or publication, run the non-mutating release gate:

#+begin_example
make docs-release-check
#+end_example

That gate independently exports Org, rejects a stale generated Texinfo body,
checks the accepted Info-node inventory in [[file:nodes.txt][nodes.txt]], and runs the
full documentation validation.  Public HTML continues through the separately
reviewed =gh-pages= worktree.

* Plain-text export

To read the complete manual outside Emacs, export it as one UTF-8 text file:

#+begin_example
make docs-org-text
#+end_example

The file is written to =.docs-preview/org-manual/emacsvox.txt= unless
=DOCS_ORG_TEXT= names another path. The manual uses ordinary Org markup;
the standard Org ASCII backend retains keys, literals and link descriptions.
Like the preview, this export does not load or compile Emacsvox. Its default
output is ignored; choose an untracked destination when overriding the path.

* Export conventions

- =TEXINFO_NODE_NAME= preserves a stable Info node name when it differs from
  the Org heading.
- =TEXINFO_NODE: no= creates a structural heading without an Info node.
- =ALT_TITLE= gives a friendly printed heading while preserving the node name.
- =DESCRIPTION= supplies an Info menu description.
- Normal Org lists, tables, links, examples, source blocks, emphasis, and
  inline code are preferred over raw Texinfo.
- Reserve code markup (~C-x C-f~, for example) for key sequences. The maintained
  Texinfo exporter writes =@kbd= and preserves named-key notation for ~RET~,
  ~TAB~ and similar keys. Standard Org text and HTML exports retain the same
  key text without a special backend.
- Use verbatim markup (=local.mk=, for example) for filenames, Lisp symbols,
  shell commands and other literals. An Emacs command invocation such as
  ~M-x term RET~ is a key sequence; a shell command is literal text.
- Use Org heading links for sections in this manual and =info:= links with
  descriptions for other manuals. Keep stable =TEXINFO_NODE_NAME= properties
  when the printed heading differs from its existing Info node.
- Write acronyms and punctuation as ordinary text. Raw Texinfo remains only
  for block-level compatibility material such as the Info index.

Changing an accepted node name or removing a node is a navigation compatibility
change: update =nodes.txt= deliberately and review inbound links before doing
so.
