8.13.6 Prepare a useful problem report ¶

Record the application and buffer type, the exact keys or action, what you expected, what you heard and whether the problem repeats. Note the platform, Emacs and Emacsvox versions and speech backend. Distinguish a reported success or timeout from an audible result; neither is a substitute for the other. Prefer a short, non-confidential example that reproduces the problem.

In Aural Doctor, y copies the report. It does not copy spoken text or log contents, but it can contain personal paths and configuration. Review that copy before sharing it. The log row identifies paths without opening files.

Enable detailed logging only for a reproduction whose spoken content you are prepared to handle as sensitive data. In the diagnostics menu, lowercase l toggles logging for this session, including complete spoken text. Note its previous state and restore that state after the reproduction. Capital A opens log-file, size, retention and buffer-visibility options in Customize. Apply and Save there are explicit; buffer-naming changes take effect after speech restarts.

Review logs separately before sharing excerpts. Remove credentials, message content, personal paths and unrelated text; do not assume a diagnostic file contains only technical metadata. State which checks you tried and their results so another person can continue the investigation without repeating unsafe or inconclusive steps.
