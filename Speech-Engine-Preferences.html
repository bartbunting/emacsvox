6.7.3 Set Shared Engine Preferences ¶

For a quick engine preference, C-e d e chooses an available engine for the current Emacs session. Use C-u C-e d e to save the new preference. On a first run with no saved engine settings, the ordinary command uses the live Omnivox policy as an in-memory baseline and writes no file; the prefixed command explicitly saves that baseline and the selected preference. Explicit physical choices in named palette voices still take precedence.

All named voices use the common editor and the same complete palette model. Workbench engine policy is shared across palettes: O toggles preferred engines and [ / ] reorder them; f toggles fallback engines and { / } reorder those. D enables or disables an engine, and K requests a recovery probe. These are staged policy edits; w saves and applies them. Physical choices for a named voice are saved in that voice’s editor.

Tables put voice or engine names first. Detailed adapter capabilities, native identifiers and registration information are available with x for Details. Availability, failure reasons, predicted selection and observed playback remain distinct. Inventory predictions do not prove that audio played.

Saving engine policy is separate from saving a named voice or a Presentation Profile. If an apply fails or is unconfirmed, see Recovering Unfinished Changes. Installation and optional engine modules are covered in Optional Omnivox Engine Modules.
