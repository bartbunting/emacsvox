6.6.2 Choose And Tune Fallback Voices ¶

Shared settings provide the base for the whole voice.

Physical choices are tried in their displayed order, subject to availability, engine policy, and synthesis failures. An empty explicit list means Automatic: use the shared engine policy. Availability predicts a possible choice; the last sample’s result identifies what actually played.

There are two distinct kinds of inheritance. A parent palette supplies a whole named entry. Inside that entry, an individual physical choice can inherit each shared adjustment separately. For example, shared pitch six, choice pitch four, and a matching contextual rule setting pitch seven result in a requested pitch of seven. Without that rule, the choice requests four. Returning the choice field to Use shared value makes it request six.

Expand Fallbacks to see which rows use shared settings and which are customized. A row’s action menu can audition that row or compare its original and edited versions. Comparison follows the same row after reordering, including two rows mapped to the same physical voice. A newly added row has no original to compare yet; audition it or compare the complete voice instead. Replacing a customized physical voice asks whether to keep its settings or return to shared settings.

Choose Customize this voice in that row’s menu for optional individual tuning. The panel names the physical voice it edits. Each field says use shared value, custom value, or explicit adapter default. ‘RET’ offers all three states; left/right sets a number, ‘d’ restores adapter default, and ‘i’ returns the field to its shared value. Zero is an explicit setting. Later shared edits affect only inherited fields. More adjustments and effects reveals the additional controls. Automatic samples speak the value or state before the sample and audition this row. Play whole fallback chain checks normal selection. Use Return to shared settings to leave individual tuning; all edits belong to the same voice draft and the same Save action. Removing a row disables its controls until undo or a return to shared settings.

With Omnivox’s per-choice tuning support, complete previews retain the full fallback chain and each row’s settings. Last sample playback started on … identifies the engine and physical voice whose audio started. Audio merely accepted for playback, or the spoken label Original or Edited, does not confirm that the sample started. Stop and text, draft or context changes retire pending previews; retained results are labelled Earlier preview. Saving and application status remain separate from playback evidence.

Details and last playback evidence explains the shared setting, actual row’s override and contextual override for each field in the last confirmed sample. The context view offers Where the last sample’s settings came from after a preview. Explanations use that sample’s captured settings, even after editing, and identify whether it was an original or edited sample. They distinguish inherited values, explicit defaults, zero and unsupported requests. These are requested settings, not measurements of the engine’s native values or sound.

Older Omnivox servers retain shared-only previews. Customized complete previews require per-choice support; an individual audition is available only when its settings can be represented faithfully, including adapter defaults. Saving remains available when that preview is unavailable.
