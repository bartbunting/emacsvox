The working prototype is one foreground iPhone app. You connect to your
existing WSL Emacs, edit files, use the minibuffer and work in a running
Codex conversation. The phone speaks its own frame locally, including
Emacsvox navigation, tones, earcons and permission announcements.

The Expo Go baseline is on the local Emacsvox branch =prototype/iphone-speech=.
The native experiment builds on it on =prototype/iphone-native-audio=. Make reusable Rust changes on a separate Omnivox
feature branch when the audio experiment calls for them. Use a named test
Emacs server until phone and desktop routing pass together. Record a date,
revision and short result under each milestone when its acceptance test passes.
Use a fixed sample for listening tests and keep spoken text out of routine logs.

The earlier local branches named above are stages of this checkout. Emacsvox
revisions in the build notes point to the corresponding commits in this
history. The private signed builds predate the removal of local setup details.

On 22 November 2026, with receiver =e532818dd= in Expo Go, a second =C-n=
promptly cut off the old line on the iPhone. Opening the compose editor
played the Accent Open Object sound and spoke “Compose prompt”. Stop Speech
silenced a long phrase straight away during an eight-second relay pause.
Two moves while disconnected stayed silent on reconnect. The next =C-n=
spoke its line. All 13 WSL tests passed, and a fresh graphical Emacs
sent the configured cue before the compose announcement.

On headphones, Eloquence at 1.5 times normal speed had a small,
acceptable delay. The built-in iPhone speaker felt a little quicker.
These are listening impressions. Keypress-to-sound timing and the
source of the delay have yet to be measured.

** NEXT Use the iPhone as a full Emacs terminal

This work can start in WSL during the audio trials. Test SSH authentication,
host-key verification, interactive terminal allocation and resize against
the isolated server. Try SwiftNIO SSH and SwiftTerm in the signed app.
Keep the SSH key in the iOS Keychain. Run =emacsclient -t -s SERVER= and
keep terminal input and local speech available in the same foreground app.

The [[file:README.org::*Exercise the SSH transport in WSL][WSL SSH test]] on =prototype/iphone-ssh= uses the Swift transport against
a temporary loopback OpenSSH server. On 22 November 2026 it attached to
an existing Agent Shell sample, dispatched the destination line through
Emacsvox, resized the Emacs frame, saved UTF-8 input and reattached to
the same buffer. The phone-facing SSH endpoint, Keychain storage,
terminal display and accessible input still need implementation or testing.

On the phone, open and save a file using Braille Screen Input, use =M-x=
completion and =C-g=, browse Dired, then switch to the running Codex buffer.
Check Control and Meta sequences with the external keyboard and accessible
modifier controls with touch. Typed text should arrive once and VoiceOver
should let you reach both the terminal and Stop Speech. The [[file:README.org::*Full terminal Emacs on the iPhone][editing walkthrough]]
gives the keys.
