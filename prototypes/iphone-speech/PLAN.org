The goal is one foreground iPhone app. With an external
keyboard connected to the phone, you edit files in your existing WSL
Emacs, use the minibuffer and work in a running
Codex conversation. The phone speaks its own frame locally, including
Emacsvox navigation, tones, earcons and permission announcements.

The Expo Go baseline is on the local Emacsvox branch =prototype/iphone-speech=.
The native experiment builds on it on =prototype/iphone-native-audio=. Make reusable Rust changes on a separate Omnivox
feature branch when the audio experiment calls for them. Use a named test
Emacs server until phone and desktop routing pass together. Record a date,
revision and short result under each milestone when its acceptance test passes.
Use a fixed sample for listening tests and keep spoken text out of routine logs.

The earlier local branches named above are stages of this checkout. Emacsvox
revisions in the build notes point to the corresponding commits in this
history. The private signed builds predate the removal of local setup details.

** NEXT 5. Prove native audio with Eloquence on the phone

Build a small Swift audio module in the same Expo app. Ask iOS for Reed's
speech samples, start playback as samples arrive, and mix one generated
tone and one preloaded earcon. On Stop, clear scheduled audio immediately
and discard later callbacks for the cancelled utterance. Use the existing
relay and PC keyboard so this experiment changes only the phone audio path.

Use the signed app from slice 4. Start with “Test iPhone Voice”, then
activate “Use native mixer” and “Test mixed audio”. The device build
includes the JavaScript and both playback modes. [[https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer/write%28_%3Atobuffercallback%3A%29][Apple speech buffers]].

Compare keypress to audible cue, keypress to first word, and Stop to
silence for direct speech and the mixer. Use one recording clock for the
key and the audible result. For each output route, record first use,
typical and slow repeated moves, and any stale speech or cues heard during
rapid replacement. Label internal callback timings separately.
Use direct Expo Go speech on the same output route as the baseline.
With VoiceOver active, the mixer should cut off the old line, start the new
one and respond to Stop at least as promptly. Cancelled audio must stay
silent. If Reed's samples arrive too late, keep direct speech and separate
cues usable while investigating.

The [[file:README.org::*Native mixer experiment][native mixer experiment]] includes direct and mixed playback, cancellation,
a fixed tone and the Accent recording. On 22 November 2026 the
hosted simulator build of =dd21276ef= succeeded. The downloaded iOS
Simulator app contained the compiled Swift mixer. All 14 WSL receiver and
relay tests passed. Eloquence sample delivery and acoustic timing on
speaker and headphones still need a physical check.

A hosted simulator build of =838ad97f5= also packaged the separate
permission synthesizer, cancellable generated tones, SwiftTerm and SSH.
The inclusion of these components was checked in the downloaded app.

On the first signed build, a single 480 ms Emacs tone sounded broken in
about six places. Both audio modes gave the same impression. WSL counted
one tone and one dispatch. The revised player renders that cue in one
23,040-frame buffer. On 23 November the tones worked on the second device
build. Response still felt slightly slower. The next comparison covers
the first tone after connecting and subsequent tones on the same output
device. The [[file:README.org::*Check keyboard speech and permissions on the signed app][phone checks]] also cover the VoiceOver swipe order,
interruption, pending permissions and lock recovery.

On build 3 both half-second tones in Diagnostics started promptly. The
same 660 Hz tone felt delayed on both invocations of =M-x iphone-test-tone=
over SSH. From entry to that Emacs command to its tone write took under
1 ms in both trials. On WSL alone, nine single-key trials from SSH input
to the tone packet at a loopback receiver took 3.9 to 25.4 ms, with a
median of 6.5 ms. Neither measurement includes iPhone playback. Compare a
single Return press after the minibuffer has gone quiet, then measure
handset input and output separately if the delay persists.

The desktop visual-line chime in =C-e m= uses SoX directly. In the two-frame
check, two mode-line reads started it 0.75 seconds apart. Rendering its
675 ms waveform to a silent output on WSL took 3.17 seconds with the
default worker count and 0.094 seconds with one worker. Both produced
identical samples in the file comparison. The single prerecorded cue
sounded clear through WSL and slightly clearer through native Windows.
The chime now uses one SoX worker. This cue still needs a phone-side
equivalent when visual-line mode is enabled on the phone frame.

** Compare interruption and an earcon in Expo Go

1. With the PC keyboard and VoiceOver on, press =C-n= halfway through a
   long line. Stop a long reply on the phone during a network stall.
   Disconnect, move twice in Emacs, reconnect and move once more. Listen
   for a prompt cutoff, silence on reconnect and just the new line.
2. Open Agent Shell's compose editor in the isolated profile to trigger
   the Accent =open-object= cue. Forward the cue selected by Emacsvox and
   preload its recording on the phone. Check the trigger and cue order in
   WSL. Listen for the cue once at the same action on desktop and phone.
   Check that the next navigation command still interrupts. [[https://docs.expo.dev/versions/v58.0.0/sdk/audio/][Expo Audio]].
3. Record the voice, rate, output route, and how the cue and interruption
   felt on the phone speaker and your usual headphones. Use this comparison
   to set the latency target for the native experiment.

On 22 November 2026, with receiver =e532818dd= in Expo Go, a second =C-n=
promptly cut off the old line on the iPhone. Opening the compose editor
played the Accent Open Object sound and spoke “Compose prompt”. Stop Speech
silenced a long phrase straight away during an eight-second relay pause.
Two moves while disconnected stayed silent on reconnect. The next =C-n=
spoke its line. All 13 WSL tests passed, and a fresh graphical Emacs
sent the configured cue before the compose announcement.

On headphones, Eloquence at 1.5 times normal speed had a small,
acceptable delay. The built-in iPhone speaker felt a little quicker.
These are listening impressions. Keypress-to-sound timing and the
source of the delay have yet to be measured.
