#+title: Listen to Emacsvox on an iPhone

Track the path from this speech receiver to a full terminal in the
[[file:PLAN.org][iPhone prototype plan]].

The next native build includes an opt-in Omnivox worker. From the
phone frame you can list and apply installed iOS voices and play
Omnivox tones and earcons. See [[file:OMNIVOX.org][Omnivox on iPhone]] for the controls,
launch commands and WSL verification.

* Listen from the PC keyboard

The test Emacs runs Codex in WSL. Its speech server sends text and
interruption commands to the foreground Expo Go app over Tailscale.
The iPhone synthesises each utterance locally. Your desktop Emacs keeps
its own speech process and conversation.

1. Install [[https://apps.apple.com/app/expo-go/id982107779][Expo Go]] on your iPhone. This prototype targets Expo SDK 58.
   In Expo Go, open the account button and sign in with a free Expo account.
   Connect Tailscale on both devices. In Tailscale on the phone, find
   the phone's own 100.x IPv4 address. Turn Silent Mode off and check
   media volume. [[https://docs.expo.dev/versions/latest/sdk/speech/][Expo Speech on physical iOS devices]].
2. In WSL, enter the prototype directory. Run =npm ci= to install the
   pinned JavaScript dependencies before starting the relay.

   #+begin_src sh
   cd "$(git rev-parse --show-toplevel)/prototypes/iphone-speech"
   npx expo login
   read -rp 'iPhone Tailscale IPv4 address: ' phone
   ./start-relay "$phone"
   #+end_src

   Use the same Expo account in WSL and on your phone. If the relay is
   already running, you can run the login command in another WSL terminal,
   then activate “Try Again” on the phone. [[https://docs.expo.dev/troubleshooting/expo-go-sign-in-required/][Expo Go sign-in help]].

3. Wait for Metro to print “Waiting on http://localhost:8786”. Open
   the HTTP address printed for the iPhone in Safari.
   Use VoiceOver's Links rotor or swipe to “Open receiver in Expo Go”.
   Activate the link and confirm Open. Allow local network access if iOS
   asks. Bundling can take a moment on the first launch. Find and
   activate Connect. Swipe to the connection status and check that it
   reads “Connected”. Keep the receiver in the foreground.
4. In a second WSL terminal start the isolated graphical Emacs with Node
   and Codex ACP on your PATH. The launcher uses Emacs from local.mk, the existing ELPA
   packages and the Agent Shell checkout. It creates a private scratch
   project and a fresh Emacs directory under XDG_RUNTIME_DIR. Codex uses
   your normal login.

   #+begin_src sh
   cd "$(git rev-parse --show-toplevel)/prototypes/iphone-speech"
   ./test-session
   #+end_src

5. In that new Emacs, type =M-x agent-shell-openai-start-codex RET=.
   Ask for three paragraphs about a lighthouse. In the rendered reply,
   move point just above a line you want to hear. Press =C-n=. Press it
   again while the line is speaking. Listen for the old line to cut off
   and the next row to begin. Wrapped rows follow Emacsvox's usual visual
   line setting. Try =C-f= to hear character feedback.
   To hear an Emacsvox earcon, run =M-x agent-shell-prompt-compose RET=
   from the transcript. Listen for the Accent Open Object sound and
   “Compose prompt”. Use =C-c C-k= to cancel the empty editor.
6. While a long utterance is playing, activate Stop Speech on the phone.
   Try =M-x tts-stop RET= from the test Emacs as well. Activate Disconnect,
   move twice in Emacs, then activate Connect. Wait for “Connected”.
   Listen for silence until you move again. To repeat the stall test from
   an interactive WSL shell, start a long line and press =Ctrl-Z= in the
   relay terminal. Activate Stop Speech on the phone while the relay is
   suspended. Type =fg= in the same terminal to resume the relay. If the
   receiver timed out, activate Connect.
7. Exit the test Emacs with =C-x C-c=, activate Disconnect on the phone,
   and press =Ctrl-C= in the relay terminal. Switch to your original Emacs
   window for desktop speech.

* Connection and recovery

The shell launcher binds the relay and Expo forwarder to WSL's Tailscale
IPv4 address. Only the specified iOS peer address can open the receiver
page, load the bundle or subscribe to speech. Metro listens on loopback.
Ports 8787 and 8788 must be reachable from that peer through your tailnet
policy. The relay uses the source address of the connection, so connect
directly over Tailscale. There is no public tunnel or audio stream.
If Safari fails to load the page, check the peer address, Tailscale and
those ports. If the page opens but the app fails to load, check the Metro
output and the Expo Go SDK version. If status reports a timeout, activate
Connect after restoring the network. If you hear silence, open Diagnostics
in the signed app and activate “Test iPhone Voice”. This speaks a short phrase locally even while
disconnected. “Test Open Object Sound” plays the same recording used by
Agent Shell. The playback status follows these controls in VoiceOver order.

The private Unix socket accepts one Emacs producer. Speech is delivered
only to the current foreground receiver. Each new phone connection drops
unfinished records and invalidates the old queue. The app stops iOS speech
on disconnect, backgrounding or heartbeat timeout. A local Stop calls iOS
immediately and ignores older in-flight messages until the relay confirms
a reset. A stop from Emacs invalidates pending native callbacks before
admitting fresh speech. Relay and receiver logs omit speech payloads.
The test profile disables Aural diagnostic logging, ACP traffic logging and
Agent Shell transcript files. Codex keeps its own ordinary conversation
history. Emacsvox's interactive feedback histories are local to the session.

* Trace from the key to the phone

The checkouts used for the trace were Emacsvox d289925d5 and Omnivox
7879419. In an Agent Shell response, the effective =C-n= command is
=next-line=. The advice in =emacsvox-agent-shell-motion.el= runs the move,
normalises display-only rows, then calls
=emacsvox-agent-shell--present-current-navigation-line=. That selects
=emacsvox-speak-visual-line= or =emacsvox-speak-line=. The reader extracts
the destination text and submits it to Aural with navigation context.
Aural owns the interruption and lowers the presentation according to the
destination process's capabilities.

With the desktop Omnivox backend, =tts-initialize= opens the speaker and,
when configured, a notification process. =omnivox--negotiate-process= sends
a base64 JSON capabilities request and marks the process pending.
Acknowledged features govern inventory, routing, framed delivery, structured
timelines and playback tracking. Protocol readiness and initial routing
readiness have separate hooks. The foreground process owns navigation stops,
and explicit interactive Stop also targets a distinct notification process.

The first PC-keyboard trial selects =phone-backend= via =TTS_PROGRAM= in the test
process environment. =voice-setup= selects the existing plain voice adapter.
This standalone server uses the legacy protocol from its first command and
advertises zero Omnivox extensions. It never acknowledges synthesis or
playback. =tts-notification-device= selects main output. Automatic replies
and permission announcements use the existing Agent Shell handlers. A
focused permission request uses urgent delivery, and ordinary navigation can
subsequently interrupt it on the shared stream.

In the graphical test, each interactive =C-n= produced a stop and a
dispatch containing the destination row on the WebSocket. On the stdio
side, =q {text}= adds text, =d= dispatches and clears the batch, and =s=
clears pending text and stops playback. =l= interrupts and reads a
character, including common punctuation names. =tts_say= also interrupts.
The receiver prefers English Eloquence Reed at 1.5 times normal speed.
Connect and Test iPhone Voice both check the voices available on your phone.
If Reed is unavailable, the receiver tries Eddy, Rocko and Grandpa, then
Daniel, Aaron and Lee. It uses the iPhone default if none are available.
The current voice and rate appear below the connection status. These
settings apply to receiver speech, including characters. Expo Go can play
the bundled Accent recording. The routed signed app also accepts speech
rates and generated tones. A tone-only line is silent in Expo Go.

The isolated profile selects the bundled Accent pack. Its
[[file:../../sounds/packs/accent/open-object.ogg][Open Object recording]] is the first supported earcon. The relay recognises
that recording's resolved path in the legacy =a= and =p= commands. When
you attach another Emacs installation, its phone frame identifies the
bundled Accent file by its SHA-256 digest and sends the standard
=omnivox-icon:packs/accent/open-object.ogg= resource ID. A different
recording at the same path in that installation keeps its own identity.
=a= queues the cue in order until =d=. The receiver can start following
speech as the sound plays. =p= plays the sound immediately. A hard stop,
disconnect or background transition silences both speech and sound.
Character speech and immediate speech can interrupt voice independently.
Only the cue name travels to the phone. Expo Audio loads the local WAV
when the receiver opens. To regenerate it from the prototype directory,
run =sox -D ../../sounds/packs/accent/open-object.ogg -b 16 assets/open-object.wav=.
The [[file:../../sounds/packs/accent/README.org][Accent notes]] describe the original pack.

With visual-line mode enabled locally in a buffer, =C-e m= starts a rising
chime and reads the mode line. In a phone frame the updated relay sends
that indicator to the handset. Signed build 3 speaks “Visual lines”.
The updated receiver plays the bundled chime once its player is ready.
The desktop continues to play the configured SoX chime on its own output.
To regenerate the phone's recording from the =sox-chime 2 2= recipe in
[[file:../../lisp/aural/sox-gen.el][sox-gen.el]], run this in the prototype directory.

#+begin_src sh
OMP_NUM_THREADS=1 sox -q -R -D -r 48000 -n -r 44100 -c 1 -b 16 assets/visual-line.wav \
  synth -j 3 sin %3 sin %-2 sin %-5 sin %-9 sin %-14 sin %-21 \
  fade h .01 2 1.5 delay 1.3 1 .76 .54 .27 remix - fade h 0 2.7 2.5 \
  norm -1 channels 2 tempo 2 speed 2 rate 44100 channels 1
#+end_src

For the full protocol see [[file:../../docs/developer/speech-server-protocols.org][Speech Server Protocols]] and the Omnivox checkout's
=docs/protocols/{control,legacy,remote}.md=.

* Exercise the SSH transport in WSL

The =prototype/iphone-ssh= branch contains a Swift package in =ssh/=.
It connects to a chosen SSH endpoint, checks its public host key against
a pin supplied by the caller and authenticates with an Ed25519 key.
The server must accept both a PTY and the command that starts
=emacsclient -t= on an explicitly named Emacs server. The client sets
=C.UTF-8= for that command so accented input reaches the terminal frame.
A missing Emacs socket returns a failed command exit. The transport
delivers the terminal's bytes to the caller and accepts input bytes,
window size changes and disconnect. The signed app uses this transport with
SwiftTerm and an iOS Keychain identity. [[https://github.com/apple/swift-nio-ssh][SwiftNIO SSH]].

The integration check starts a temporary OpenSSH listener on a random
loopback port, a dedicated graphical Emacs under Xvfb and a phone speech
backend that records only whether the test line was dispatched. It creates
fresh keys and a rendered Agent Shell reply. It closes its listener and
removes its keys on exit. The phone trial below opens a separate listener
on the WSL Tailscale address.

In WSL, build the test client with Docker from the
worktree. The static Swift runtime lets the probe run directly in WSL.

#+begin_src sh
cd "$(git rev-parse --show-toplevel)/prototypes/iphone-speech/ssh"
mkdir -p .build/swift-home
docker run --rm -u "$(id -u):$(id -g)" -e HOME=/work/.build/swift-home \
  -v "$PWD:/work" -w /work swift:6.3-noble \
  swift build -j 4 --static-swift-stdlib --product SessionProbe
cd ..
#+end_src

When =/usr/sbin/sshd= is installed, run the test from that directory with
=python3 test/ssh-terminal.py --emacsclient "$(command -v emacsclient)"=.
The test launches its own instance. Ubuntu provides the
server and matching helpers as a downloadable package. To use that copy
without installing a service, run the following commands.

#+begin_src sh
server_dir=$(mktemp -d)
(cd "$server_dir" && apt download openssh-server && dpkg-deb -x ./*.deb .)
python3 test/ssh-terminal.py --sshd "$server_dir/usr/sbin/sshd" \
  --emacsclient "$(command -v emacsclient)"
#+end_src

* Route each frame to its own speaker

Use this mode to hear your PC on its usual Omnivox voice and the phone
on its local iOS voice. Both frames use the same Agent Shell buffer.
Start the test server and relay together in WSL.

#+begin_src sh
cd "$(git rev-parse --show-toplevel)/prototypes/iphone-speech"
read -rp 'iPhone Tailscale IPv4 address: ' phone
./start-relay --routed "$phone"
#+end_src

1. On the iPhone, open the host’s Tailscale address on port 8797 in Safari using HTTP. Activate
   “Open receiver in Expo Go”, “Connect” and then “Emacs keyboard”.
2. In “Emacsvox Routed Draft” on the PC, navigate the rendered response
   with =C-n=. On the phone keyboard, move through the same response.
   Check that you hear each command on the device where you pressed it.
   Try =M-x tts-stop RET= on either keyboard during speech on the other.
3. While the phone displays the conversation, its automatic replies and
   permission requests follow its frame. Moving to a different Agent
   Shell conversation changes the subscription. Rapid navigation
   preserves a permission announcement. To review and answer a request,
   use =M-x agent-shell-jump-to-latest-permission-button-row RET=, move to
   the intended choice and activate it. Stop Speech silences local audio
   immediately. Reconnecting reads pending requests from Emacs.
4. Activate Disconnect to close the phone frame. The PC keeps the draft.
   Press Control+C in the launcher to close the isolated test server.

The routed relay creates a private speech socket for each new terminal
frame. Emacs runs its ordinary line and character readers, with a
separate main speech process for that frame. Emacsvox queues deferred
speech by process. The relay carries permission identity and the reset
acknowledgement alongside the plain speech commands. The receiver advertises
no Omnivox extensions. Expo Go protects permissions using one synthesizer.
The signed app has a dedicated iOS synthesizer for permissions, plus
generated tones and the optional PCM mixer. A phone listening check
is still needed for simultaneous playback and mixed Eloquence.

* Full terminal Emacs on the iPhone

The private signed app runs SwiftTerm and SwiftNIO SSH in the foreground.
It stores the phone's private Ed25519 key in the iOS Keychain. Tailscale
carries both SSH and the speech WebSocket. The relay offers a fresh frame
ID and server path. SSH checks the pinned WSL host key and runs
=emacsclient -t= with that ID. Emacs sends “attached” over the matching
speech socket before the receiver reports Connected.

The WSL speech and SSH listeners negotiate a TCP segment size of at most
1120 bytes. This leaves room for Tailscale on a 1280-byte WSL uplink.
Without that space, small messages can reach the phone while a larger
voice registration or terminal redraw stalls. During voice registration,
the app shows “Finding iPhone voices”.

** Use the bottom tabs

Build 4 opens on Terminal. The tabs along the bottom, from left to right,
are Terminal, Diagnostics and Settings. Select Diagnostics for audio tests
or Settings for connection and keyboard preferences. Changing tabs keeps
your SSH frame open. Return to Terminal to resume typing at the same point.
Stop Speech is available on Terminal and Diagnostics.

You can switch tabs while editing a setting. Return to Settings to continue
your edit. Save settings applies it. Cancel restores the saved values. Both
actions return to Terminal.

On the iPhone, check that VoiceOver identifies the selected tab and reads
only the visible page and the tab bar. In an Emacs draft, switch to
Diagnostics, then Settings, then Terminal. Press =C-n= on the external
keyboard and listen for the next line in that same buffer.

** Resume after locking the iPhone

“Keep awake while connected” starts enabled for the signed app. It prevents
automatic screen lock while the receiver is connected in the foreground.
Disconnect restores the normal idle timer. You can still lock the phone with
the side button. Locking or switching apps stops local audio and releases
the phone frame. Emacs, its buffers and Codex keep running in WSL.

To use your keyboard with the display dark and the app active, turn on
VoiceOver Screen Curtain with a three-finger triple-tap. Use a three-finger
quadruple-tap if Zoom is also on. Repeat the gesture to restore the display.
[[https://support.apple.com/guide/iphone/keep-the-screen-off-iph756788a12/ios][Apple’s Screen Curtain guide]].

Unlock and return to the app. It reconnects a previously active session,
opens the last live phone buffer at its saved position and refreshes any
still-pending permission. The next navigation command speaks fresh output.
If that buffer has been killed, the terminal opens the subscribed conversation
if it is still live. If iOS terminated the app, launch it and activate Connect.
An explicit Disconnect stays disconnected. [[https://developer.apple.com/documentation/xcode/configuring-background-execution-modes][Apple’s background execution guide]].

** Keep the same WSL host key between trials

The listener looks for a dedicated Ed25519 key under your WSL state
directory. Keeping the current key there preserves the pin already saved
on the phone. To create a host identity for the first time, run this in WSL.

#+begin_src sh
key_dir="${XDG_STATE_HOME:-$HOME/.local/state}/emacsvox/iphone-ssh"
install -d -m 700 "$key_dir"
test -e "$key_dir/host" || ssh-keygen -q -t ed25519 -N '' -f "$key_dir/host"
#+end_src

The ordinary =./phone-sshd= command now uses this identity. For a newly
created key, compare the public key printed by WSL and save it on the phone
once. To select another existing key, pass =--host-key /path/to/key=.
Control+C ends the listener.

** Use Control and Meta on the external keyboard

With the default VoiceOver modifier, send =C-M-f= by pressing Escape,
releasing it, then pressing Control+f. In an Emacs Lisp buffer this moves
forward one expression. For physical Control+Option chords in the updated
Emacs keyboard field, choose Caps Lock as your only VoiceOver modifier in
iPhone Settings, Accessibility, VoiceOver, Typing, Modifier Keys. Then enable
“Send Control+Option to Emacs” in the app settings and save. Press
Control+Option+f to move one expression. The app leaves Command shortcuts
to iOS. On terminals that share key codes, the usual Emacs prefix =C-x @=
can supply individual modifiers, including =C-x @ s= for Super.
[[https://support.apple.com/guide/iphone/iph6c494dc6/ios][Apple's external keyboard guide]].

If your keyboard has Mac and Windows layouts, check its manual for the
position of Option or Alt. iOS interprets the Alt key as Option.

In an editable Agent Shell draft, Shift+Return inserts a newline. On
build 4, use =M-x newline RET= if the keyboard sends ordinary Return.
In the transcript, =j= moves to the next response and =J= to the previous
one. At the editable prompt they insert letters.

If iOS also speaks a letter, you can give this app its own VoiceOver
typing feedback. Open Settings, Accessibility, VoiceOver, Activities, and
choose Add Activity. Set Typing Feedback to Nothing for the hardware
keyboard if that choice is available. Under Automatic Switching, choose
Apps and select Emacsvox Speech. Emacs still uses your usual typing echo.
[[https://support.apple.com/guide/iphone/iphfa3d32c50/ios][Apple's VoiceOver Activities guide]].

** Check keyboard speech and permissions on the signed app

1. In Diagnostics, activate “Test half-second tone”. Listen for one steady
   pitch. Try “Test three-second tone” and interrupt it with Stop Speech.
   Both controls work offline and use the same player as an Emacs tone.
   For a timing comparison, try the half-second tone twice. Return to Terminal
   and run =M-x iphone-test-tone RET= twice in the isolated phone frame.
   Both paths play 660 Hz for 480 ms. Keep the same speaker or headphones
   and compare the pause between activation and the start of the sound.
   To compare a single keypress, run =C-u M-x iphone-test-tone RET=. In the
   read-only tone buffer, wait for quiet, then press Return again. Press
   =q= to close the comparison and return to your editing buffer.
   Receivers with “Test visual-line chime” in Diagnostics can also compare
   that local recording with =C-e m= in a visual-line buffer.
2. On the main screen, connect and focus the Emacs keyboard field. Type a
   lowercase =j= and an uppercase =J= with ordinary Emacs typing echo on.
   Listen for one echo per key and a higher pitch on the capital. In an
   editable draft, press Shift+Return between two words and check that
   they occupy separate lines. In the transcript, press =j= and =J= and
   listen for the response navigation without a separate letter echo.
   In an Agent Shell response, press =C-n= twice during a line and compare
   the cutoff on speaker and headphones.
3. In the isolated test session, run =C-u M-x iphone-test-permission RET=
   from the phone. Stay in your editing buffer. Press =C-n= to start a
   practice request to read the lighthouse notes. As soon as you hear
   “lighthouse”, press =C-n= again. Listen for your new line and the end
   of the request, “Choice 2, Reject”. Run =M-x iphone-test-permission RET=
   without the prefix argument to visit the pending choices.
   Press =y= for Allow once, or move to Reject and press Return. You can
   repeat the exercise with the prefix argument at any time. The sample
   uses a local Agent Shell client and performs no file operation. Stop
   Speech silences both speech streams and leaves the choice pending.
4. Visit a second buffer with an unsaved edit, note point and lock the phone.
   Unlock and reopen the app. Check the saved position, type one character and
   listen for fresh feedback. Repeat after explicitly disconnecting to check
   the phone stays quiet.
5. With “Use Emacs keyboard field” enabled, swipe forward from the keyboard
   to Settings, then swipe back. Listen for your usual VoiceOver voice.
   “Review terminal screen” opens a snapshot you can read one visible row
   at a time. Activate Done to return. When you turn the keyboard field off,
   SwiftTerm also appears directly in the swipe order.
6. From the phone, press =C-e=, pause for the prefix help, then press =m=.
   Listen for the help and the mode line on the phone. Repeat on the PC to
   hear its own mode line on the desktop.
7. Arrow onto an =a= on the phone and pause for the configured phonetic
   delay (one second by default). Both “a” and “alpha” should come from the
   phone. Move twice quickly to check that only the last letter gets a
   phonetic name. Try it on the PC to hear the same feedback there.

** Attach to an existing conversation

After listening on both devices in the isolated test, you can choose an
existing Emacs server with a local desktop Omnivox process. In the target
conversation, =M-: (buffer-name) RET= gives the buffer name and
=M-: (expand-file-name server-name server-socket-dir) RET= gives the socket.
Run the same temporary SSH listener as above. Replace the standalone relay
with the following command in its own WSL terminal.

#+begin_src sh
cd "$(git rev-parse --show-toplevel)/prototypes/iphone-speech"
export EMACSCLIENT="$(command -v emacsclient)"
read -rp 'Emacs server socket: ' socket
read -rp 'Agent Shell buffer name: ' conversation
read -rp 'iPhone Tailscale IPv4 address: ' phone
./start-relay --existing "$phone" "$socket" "$conversation"
#+end_src

Connect from the signed app. The new terminal opens the chosen buffer.
Disconnect closes the phone frame. Control+C in the relay releases
its speech hooks and leaves the chosen Emacs server running. On the
physical iPhone, the external keyboard could navigate the existing
conversation, hear it in the phone voice and send a message to the same
thread. After unlocking the phone, focus the Emacs keyboard again.
In the listening check the same conversation reopened and only the next
navigation line spoke. A disposable graphical test also exercises release
and reattachment.

After restarting WSL, start your usual Emacsvox profile and open the
conversation again. If you have its session ID, =M-x agent-shell-resume-session=
can reopen it with Codex. Once its buffer exists, start the SSH listener
and the existing-server relay with the socket and buffer of this Emacs.
Connect using the saved iPhone settings. Locking only the phone leaves
the WSL Emacs process running.

** Reproduce routing and the hosted build

#+begin_src sh
npm test
node test/navigation.cjs
node test/keyboard-terminal.cjs
IPHONE_TEST_SSHD=/usr/sbin/sshd \
  node test/shared-frame.cjs --routed
#+end_src

Append =--time-tones= to the routed check to compare seven pairs of final
Return presses. It alternates the minibuffer and the quiet tone buffer,
using the Swift SSH client and a loopback receiver. Each result gives
milliseconds until the matching tone packet and the number of intervening
Stop packets. Listen on the phone to assess audible onset.

Use =./stage-ios-build= in this worktree to stage the committed app only.
In the printed directory, run =npm ci=, then
=export EAS_NO_VCS=1 EAS_PROJECT_ROOT="$PWD"=. The =simulator-private=
profile compiles and embeds JavaScript without device signing. The
=device= profile builds a private installable app. Apple requires the
distribution certificate with its matching private key, the registered
iPhone, and an Ad Hoc profile for =org.emacsvox.iphone.speech=.
For the Apple website signing route, save the downloaded profile in Windows
Downloads. In the prototype directory run these commands. The staging helper
uses the prepared WSL signing directory, checks the app ID, iPhone, expiry
and certificate, and prints a private build directory. EAS reads the
signing identity separately from the source archive.

#+begin_src sh
(
  set -e
  cd "$(git rev-parse --show-toplevel)/prototypes/iphone-speech"
  read -rp 'Full WSL path of downloaded .mobileprovision: ' profile
  stage=$(./stage-device-build "$profile")
  cd "$stage"
  npm ci
  export EAS_NO_VCS=1 EAS_PROJECT_ROOT="$PWD"
  npx --yes eas-cli@27.11.0 build --platform ios --profile device-local
)
#+end_src

The EAS build page provides the device install link when signing succeeds.
[[https://developer.apple.com/help/account/provisioning-profiles/create-an-ad-hoc-provisioning-profile/][Apple Ad Hoc provisioning]]
and [[https://docs.expo.dev/build/internal-distribution/][Expo internal distribution]].
