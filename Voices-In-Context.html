6.6.3 Inspect Or Adjust A Voice In Context ¶

In the common named-voice editor, choose Effective sound / Where settings came from. It uses the source item captured when you entered Aural Home or the voice list. If none is attached, choose an ordinary buffer at its current point. The item must have inspectable presentation facts or a valid retained presentation. Choose another source context selects a new item explicitly.

This is a simulation using captured facts and rules. It shows the selected named voice, matching rules, requested values and each dimension’s source. A rule can override pitch while another supplies richness. A stronger pitch rule can hide a base pitch edit; a rule selecting a different named voice can make the open base voice irrelevant to this item. Rates follow precedence too: competing relative-rate values do not add together.

P plays the edited voice in this context; B compares original and edited using the same captured facts, rules and text. These voice-only previews omit cues and spatial placement. Family remains a portable fallback outside full preview. On a server with per-choice support, the actual fallback’s settings are applied before the captured context. An explicit rule value still overrides that row when it happens to equal the shared value. Requested values are separate from confirmed sample starts, accepted audio and unsupported adjustments. A changed or deleted source is rejected. After saving a rule, use Refresh facts and rules from this source item to capture its new contribution. q returns to the base editor.

Adjust for this context presents the matching criteria and asks whether the rule lasts always (personal), for this Emacs session, or for this buffer. Choose one adjustment and its value. It opens the ordinary rule editor with that field prepared; changing richness alone produces a richness-only patch and does not select a different named voice. Review the rule’s match with RET, use V to adjust another voice field, and save that scope with w. Palette definitions are unchanged. Existing unsaved work in that rule editor must be completed before preparing another contextual rule.

In the scoped field control, Inherit removes the field so weaker contributions can supply its value. Removing the final voice field removes the voice patch. Existing explicit default values are shown separately and preserved when you edit another field. Use Inherit to remove a contextual adjustment; zero is a value, not a request to inherit. Some older explicit defaults cannot reset an underlying voice setting on every backend. Check the preview and use the explanation to identify that limitation. Contextual changes are saved as rules; they do not replace the palette entry with the combined result. The Developer Guide explains the representation and compatibility details.
