#+title: Emacsvox EAT Accessibility Implementation Plan
#+date: 2026-08-23
#+options: toc:2 num:nil

* Objective

Resolve the EAT correctness, lifecycle, accessibility, performance, privacy, and
speech-interference issues that can be addressed inside Emacsvox without
requiring major EAT changes.

The evidence baseline and design rationale are in
[[file:eat_review_report.org][eat_review_report.org]].  Work is delivered as
small commits.  Source, tests, documentation, and compiled-code verification are
kept distinct so each behavioral change remains reviewable.

* Constraints

- Preserve all pre-existing tracked and untracked work.
- Do not modify the user's Emacs configuration or existing live terminal
  sessions.
- Use the Emacs selected by ~local.mk~.
- Run ~make check-emacs~ and ~make bytecode-check~ before compiler diagnosis.
- Run ~make bytecode~ after ordinary Lisp changes and verify in a fresh Emacs.
- Use ~make bytecode-rebuild~ after macro/public-interface changes, branch
  switches, or pulls.
- Do not introduce dependencies or rely on unstable EAT internals without an
  explicit decision.
- Pause for a user decision before a broad refactor, public API change, or
  materially different user-facing default.

** Final validation record

The final 2026-08-24 validation used GNU Emacs 31.0.90 selected by ~local.mk~.
It produced these results:

- ~make check-emacs~ and ~make bytecode-check~ pass; all live Emacsvox
  byte-code is current for the selected Emacs;
- all 170 EAT tests pass from source and again after explicitly reloading
  ~emacsvox-eat.elc~, including real terminal-model navigation and deletion,
  Bash/readline, router-help, completion, lifecycle, prompt, OSC 52,
  deterministic TUI, and visual-command fixtures;
- the full 2,530-test suite has 2,527 expected results, one existing skip, and
  only the two previously recorded unrelated failures:
  ~emacsvox-agent-shell-live-chat-prompt-announces-editability~ and
  ~emacsvox-cider-advice-is-current-and-direct~ (the installed CIDER lacks
  ~cider-inspect-last-sexp~);
- compiled aural parity, normal build-tree aural startup, and all 27 semantic
  traces pass;
- a fresh Emacs reloads ~emacsvox-eat.elc~ after defining the test fixtures,
  verifies the defining file is compiled, and passes advice registration,
  silent Return, observed Left/Up, real Backspace/Delete byte transport and
  redisplay, timeout fallback, privacy, and alternate-screen safety;
- split and no-split manuals build, and Emacs Info loads the generated
  ~EAT Terminal Access~ node;
- Org lint and whitespace checks are clean, and a source scan finds no private
  ~eat--…~ reference in the integration.

During the final full-suite run, the two real Eshell fixtures initially started
Omnivox while ~eshell-mode~ emitted its unrelated banner.  That leaked a live
speech-process capability into five later TTS/voice tests.  Running the full
suite without EAT tests reduced it to the two baseline failures; the isolated
EAT, TTS, and voice suites also passed.  Commit ~ce1b33f78~ now suppresses only
banner speech/icons during fixture setup.  The full suite again has exactly the
baseline result, and production behavior is unchanged.

No unresolved defect supported by the audit evidence remains solely actionable
inside Emacsvox without relaxing a privacy/conservatism decision or inventing
terminal semantics.  The residual capability table above and API-01/API-02
identify the remaining EAT, application, shell/device, and user-configuration
work.
