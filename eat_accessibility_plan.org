#+title: Emacsvox EAT Accessibility Implementation Plan
#+date: 2026-08-23
#+options: toc:2 num:nil

* Objective

Resolve the EAT correctness, lifecycle, accessibility, performance, privacy, and
speech-interference issues that can be addressed inside Emacsvox without
requiring major EAT changes.

The evidence baseline and design rationale are in
[[file:eat_review_report.org][eat_review_report.org]].  Work is delivered as
small commits.  Source, tests, documentation, and compiled-code verification are
kept distinct so each behavioral change remains reviewable.

* Constraints

- Preserve all pre-existing tracked and untracked work.
- Do not modify the user's Emacs configuration or existing live terminal
  sessions.
- Use the Emacs selected by ~local.mk~.
- Run ~make check-emacs~ and ~make bytecode-check~ before compiler diagnosis.
- Run ~make bytecode~ after ordinary Lisp changes and verify in a fresh Emacs.
- Use ~make bytecode-rebuild~ after macro/public-interface changes, branch
  switches, or pulls.
- Do not introduce dependencies or rely on unstable EAT internals without an
  explicit decision.
- Pause for a user decision before a broad refactor, public API change, or
  materially different user-facing default.

** TODO Phase 2: Public-API screen observer and pure diff

Issues:

- F-02 lost multiline output;
- resize/output/reset indistinguishable;
- no previous cursor/screen/style state;
- bounded-performance requirement.

Planned slices:

1. immutable bounded visible-screen snapshot from public EAT getters;
2. pure logical-row/text/style diff;
3. update generations, resize/alternate-state comparison, and quiescence;
4. deterministic unit and real-terminal ERT.

Acceptance:

- work is bounded by visible terminal size;
- arbitrary output chunk splits converge on the same quiesced diff;
- unchanged repaint and resize-only events are classified without content

** TODO Phase 3: Semantic foreground output

Issues:

- F-02 multiline output loss;
- F-03 arbitrary/flooding speech;

Planned slices:

1. native EAT aural facts and delivery roles;
2. bounded complete-line output;
3. prompt-redraw and unchanged-repaint suppression;
4. progress/status coalescing and rate limiting;
5. selected/follow-live policy.

Acceptance:

- rapid repaint cannot flood or repeatedly stop unrelated speech;
- resize-only/unchanged repaint stays quiet;
- selected scrollback review is not interrupted by live output;
- punctuation and voice information survive presentation.

** TODO Phase 4: Terminal-side completion transaction

Planned slices:

2. unique completion from logical screen change;

* Deferred to upstream EAT

These do not block conservative Emacsvox implementations:

- structured update causes and dirty text/style ranges;
- public input-mode getter/hooks;
- additive bell/title/CWD/alternate-screen events;
- semantic prompt/OSC 133 API;
- OSC 8 hyperlink support;
- remote TERM/terminfo fixes;
- synchronized-output and terminal parser/performance fixes.
