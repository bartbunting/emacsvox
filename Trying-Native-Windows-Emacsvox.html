4.4 Installing Native Windows Emacsvox ¶

Native Windows x64 is a supported desktop installation with Emacs 30.2 or newer. The guided PowerShell installer runs entirely on Windows. WSL, Docker, Rust, and a system MSYS2 installation are not required.

4.4.1 Guided Windows x64 Installation ¶

You need Windows PowerShell 5.1 or newer, Git for cloning, network access, and working Windows audio with an installed speech voice. Put the checkout on a local Windows drive, rather than a WSL or network path. From PowerShell: 

git clone https://github.com/bartbunting/emacsvox.git
Set-Location emacsvox
.\bin\emacsvox-install.ps1 -Role Desktop -Check
.\bin\emacsvox-install.ps1 -Role Desktop

Skip cloning if you already have a Windows checkout and change into it instead. The check reports the selected Emacs and planned paths without downloading, writing configuration, or playing audio.

The installer reuses native Emacs 30.2 or newer. If none is selected, it offers a prebuilt Windows Emacs first. Install a release at least 30.2 and select its bin/emacs.exe with -Emacs. Alternatively, choose -BuildEmacs to build GNU Emacs 31.1 using a private MSYS2 UCRT64 toolchain. No source build starts without that option. It then installs the pinned Omnivox core and prepares Emacsvox. Allow several gigabytes of disk space and time for the initial downloads and source build. Later runs reuse the installed Emacs and cached archives. An existing native Emacs does not need MSYS2 to prepare Emacsvox.

To select an existing Emacs explicitly, add ‘-Emacs "C:\path\to\Emacs\bin\emacs.exe"’. Explicit ‘-Emacs’, ‘EMACS’ environment, and ‘local.mk’ selections must agree and require native Emacs 30.2 or newer. ‘-BuildEmacs’ selects the managed source build instead of a saved or PATH selection; it reuses a complete managed build when one exists. It cannot replace an explicit selection.

Installation is per-user. The defaults are:

  • Emacs, Omnivox, the isolated profile, and logs below ‘%LOCALAPPDATA%\Emacsvox\Native’.
  • Private build tools below ‘%LOCALAPPDATA%\Emacsvox\Toolchains\msys2-20260611’.
  • Verified archive cache below ‘%LOCALAPPDATA%\Emacsvox\Downloads’.
  • A data-only ‘native-install.json’ in this checkout, ignored by Git.

‘-InstallRoot’, ‘-ToolchainRoot’, and ‘-CacheDirectory’ select other local Windows directories. The MSYS2 build-tool path must not contain spaces; choose ‘-ToolchainRoot’ if the default does. Checkout and installed Emacs paths may contain spaces. The installer leaves personal Emacs initialization, system PATH, Windows services, and JAWS settings alone.

The source archives are checksum-pinned. MSYS2 compiler packages come from its signed rolling repositories; their installed versions are recorded with the build. Lisp native compilation is disabled in the managed source build. The built Emacs includes its runtime DLLs, so launching it does not need MSYS2 on PATH.

The default final check opens a temporary native Emacs window, verifies both speech lanes, speaks two announcements, and closes that test window. Confirm that you hear both announcements. ‘-NoAudioCheck’ skips this step when needed; run the explicit check before accepting speech: 

.\bin\emacsvox.ps1 -Diagnose
.\bin\emacsvox.ps1 -Check
.\bin\emacsvox.ps1

The last command opens the isolated native desktop. It uses Windows speech by default. An explicit ‘OMNIVOX_ENGINE’ environment selection remains available for separately configured engines. Native optional-engine installation, ARM64, and other native Windows roles are not provided by this guided installer.

After pulling source changes, rerun the installer before launching. It preserves source changes and refreshes the compiled files. Missing or stale compiled files stop launch with instructions to rerun installation. For a failed build, retain the logs under the reported build directory. Inspect an incomplete installation before moving it aside or selecting a new directory; the installer does not overwrite an unknown partial tree.

JAWS speech muting does not disable its keyboard shortcuts. If ‘M-<’ or ‘M->’ is intercepted, test with ‘JAWSKey+3’ before the shortcut. Bart’s ‘workstation-config’ repository supplies the separately installed, Emacs-specific JAWS override used on the test workstation.

4.4.2 Manual Native Installation ¶

The following manual procedure remains available for an already installed native Windows Emacs 30.2 or newer. It does not acquire Emacs or replace the guided x64 checks above. Set ‘$Emacsvox’ to the checkout’s absolute Windows path and continue in one PowerShell window.

4.4.3 Download And Verify Omnivox ¶

Set $Platform for the computer. The example below uses the usual Intel or AMD Windows x64 archive: 

$Version = "1.10.0"
$Platform = "windows-x64" # Use windows-arm64 only on Windows on ARM.
$DownloadDir = Join-Path $env:USERPROFILE "Downloads\omnivox-$Version"
$Archive = "omnivox-$Version-$Platform.zip"
$ReleaseUrl = "https://github.com/bartbunting/omnivox/releases/download/v$Version"

New-Item -ItemType Directory -Force $DownloadDir | Out-Null
$ArchivePath = Join-Path $DownloadDir $Archive
$ChecksumPath = Join-Path $DownloadDir "sha256sums.txt"
Invoke-WebRequest -UseBasicParsing "$ReleaseUrl/$Archive" -OutFile $ArchivePath
Invoke-WebRequest -UseBasicParsing "$ReleaseUrl/sha256sums.txt" -OutFile $ChecksumPath

$Pattern = '\s+\*?' + [regex]::Escape($Archive) + '$'
$ChecksumLine = Get-Content $ChecksumPath |
  Where-Object { $_ -match $Pattern } |
  Select-Object -First 1
if (-not $ChecksumLine) { throw "No published checksum for $Archive" }
$Expected = ($ChecksumLine -split '\s+')[0].ToLowerInvariant()
$Actual = (Get-FileHash -Algorithm SHA256 $ArchivePath).Hash.ToLowerInvariant()
if ($Actual -ne $Expected) { throw "Checksum mismatch for $Archive" }
Write-Host "Checksum OK: $Archive"

Do not extract or run the archive unless the last line reports Checksum OK. The Windows release is not code-signed. If Windows security or local policy refuses it, stop rather than weakening that policy.

4.4.4 Install And Check The Native Server ¶

Continue in the same PowerShell window. Extract the complete release into a versioned directory below the current user’s LocalAppData: 

$InstallDir = Join-Path $env:LOCALAPPDATA "Emacsvox\Omnivox\releases\$Version-$Platform"
New-Item -ItemType Directory -Force $InstallDir | Out-Null
Expand-Archive -LiteralPath $ArchivePath -DestinationPath $InstallDir -Force
$Omnivox = Join-Path $InstallDir "omnivox.exe"

foreach ($Required in @(
  $Omnivox,
  (Join-Path $InstallDir "espeak-ng-data\phontab"),
  (Join-Path $InstallDir "third-party-licenses\THIRD-PARTY-NOTICES.md")
)) {
  if (-not (Test-Path -LiteralPath $Required -PathType Leaf)) {
    throw "Incomplete Omnivox installation: $Required"
  }
}

& $Omnivox --version
if ($LASTEXITCODE -ne 0) { throw "Omnivox version check failed" }
& $Omnivox --list-voices
if ($LASTEXITCODE -ne 0) { throw "Omnivox voice discovery failed" }
& $Omnivox --check
if ($LASTEXITCODE -ne 0) { throw "Omnivox audio check failed" }

The version must report 1.10.0 or newer, voice discovery must list at least one Windows voice, and the final check must produce both a tone and spoken confirmation. Keep omnivox.exe, espeak-ng-data, and third-party-licenses together. Do not copy or load the archive’s omnivox-voices.el: it is the adapter for upstream Emacspeak, while Emacsvox supplies its own adapter.

4.4.5 Start Native Emacsvox ¶

Keep the same PowerShell window so $Omnivox still identifies the verified executable. Set $Emacs to the native emacs.exe. If this window did not create the Emacsvox checkout above, also set $Emacsvox to that checkout: 

$Emacs = "C:\path\to\emacs\bin\emacs.exe"
# If not set above, uncomment and edit the next line:
# $Emacsvox = "C:\path\to\emacsvox"

& $Emacs --version
if ($LASTEXITCODE -ne 0) { throw "Could not run native Emacs" }
$env:TTS_PROGRAM = $Omnivox
& $Emacs -Q --no-splash --load "$Emacsvox\lisp\emacsvox-setup.el"

The Emacs version must be 30.2 or newer. Use emacs.exe, rather than runemacs.exe, for this first launch so startup errors remain visible in the PowerShell window. Loading emacsvox-setup.el directly is intentional: the repository’s bin/emacsvox launcher is a POSIX shell script. The guided native entry point is bin/emacsvox.ps1; this subsection describes the manual alternative.

4.4.6 Verify Speech And Report Problems ¶

Verify the installation with these checks:

  1. Emacsvox speaks its startup introduction.
  2. C-h v tts-program RET displays the absolute path to the verified omnivox.exe.
  3. M-x tts-speak-version RET speaks the Omnivox version response, and M-x omnivox-list-voices RET displays the Windows voices.
  4. C-n and C-p speak ordinary line movement, C-e s stops current speech, and M-x tts-restart RET restores speech without a process error.
  5. Type M-x emacsvox-toggle-icons RET twice. The second toggle, which turns icons back on, plays a short auditory icon in addition to plain speech.

If the direct --check fails, diagnose Omnivox or Windows audio before starting Emacs. If it succeeds but Emacsvox reports that it cannot find the speech server, confirm in the same PowerShell window that $env:TTS_PROGRAM contains the absolute executable path and that Test-Path $env:TTS_PROGRAM returns True. If the process starts and then exits, retain the PowerShell error, the Emacs *Messages* buffer, Windows version and architecture, the complete emacs.exe --version output, and omnivox.exe --version output.

After successful verification, the same absolute selection can be placed before loading Emacsvox in the user’s Emacs initialization file: 

(setenv "TTS_PROGRAM"
        "C:/Users/NAME/AppData/Local/Emacsvox/Omnivox/releases/1.10.0-windows-x64/omnivox.exe")
(load-file "C:/path/to/emacsvox/lisp/emacsvox-setup.el")

Replace both example paths. This initial configuration deliberately uses an absolute executable path. Adding the Omnivox directory to exec-path is optional and is needed only when later selecting it by the short name omnivox. Native Windows support covers the x64 desktop route above; remote workstation speech remains a separate preview feature.
