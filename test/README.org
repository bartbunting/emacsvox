#+title: Emacsvox Tests

* Start here

Emacsvox supports Emacs 30.2 and newer on every platform.  Select the executable
in the repository's ignored =local.mk= before running Emacs-dependent checks:

#+begin_src sh
make check-emacs
make core-test
make trace-test
#+end_src

For example, =local.mk= can contain =EMACS=/path/to/emacs/bin/emacs=.  The core
commands above need no optional Emacs packages and do not build Emacsvox.
Use a separate checkout for each Emacs version, and preserve existing work
when a check reports a missing prerequisite or stale build.

| Target | What it establishes | Build and preparation effects |
|--------+---------------------+-------------------------------|
| =core-test=, =trace-test= | Core speech/transport contracts and recorded command outcomes. | Disposable test fixtures; no in-tree compilation or configuration. |
| =compat-test= | Focused runtime, startup, input, reading, Org, and installer contracts without optional packages. | Runs =config= first, including regeneration of ignored autoloads. |
| =unit-test= | The broad ERT suite, including installed optional integrations. | Requires generated autoloads; temporary fixtures, with no automatic in-tree rebuild or dependency installation. |
| =integration-test= | Agent Shell, Notmuch, and EAT against the reviewed lock. | Requires =test-deps= first; verifies the prepared tree, without downloading or rebuilding it. |
| =compiled-notmuch-test= | Notmuch behaviour with the explicitly verified compiled adapter. | Requires current in-tree byte-code and the Notmuch package; does not rebuild it. |
| =compiled-aural-test= | Compiled Aural parity in a fresh child Emacs. | Compiles into a temporary directory; leaves in-tree byte-code untouched. |
| =build-aural-test= | Aural behaviour from the ordinary build tree. | Builds Aural byte-code under =lisp/=, then verifies it in a fresh Emacs. |
| =test= | Version/headers, source archive fixtures, =unit-test=, both compiled checks above, =build-aural-test=, and traces. | Includes the in-tree Aural build; needs current byte-code before its Notmuch preflight. |

Tests set =load-prefer-newer= and some explicitly load implementation sources.
A passing source suite does not establish that a live profile's compiled
dependencies are current.  In an existing tree, current compiled dependencies
can still be loaded.  Use =make bytecode-check= as the non-mutating preflight;
use =make bytecode= after ordinary Lisp edits, or =make bytecode-rebuild= after
branch changes or macro/public-interface changes, then verify in a fresh Emacs.
See [[file:../docs/developer/integration-maintenance.org::*Source checkout and byte-code lifecycle][the developer guide]] for the complete lifecycle and supported-version policy.

* Full suite prerequisites and results

=make unit-test= and =make test= require many optional packages in addition to
the core toolchain.  These include Agent Shell (with ACP and shell-maker), EAT
(with compat), Notmuch, Markdown Mode, Company, Helm, Magit, Consult, Corfu,
Vertico, and the other adapters selected by [[file:run-tests.el][the full runner]].  Their test files'
=require= forms identify the package features needed by each integration;
install the corresponding packages and their dependencies in the test profile.
Emacs 30 also needs the external =lua-mode= package; Emacs 31 includes it.
The six-package lock below prepares only its focused integration job, not this
entire package set.  No test target installs packages into your personal profile.

The full runner also loads =lisp/emacsvox-loaddefs.el= for documentation tests.
Run =make config= before =make unit-test= in an unconfigured source checkout;
configuration generates this index without compiling modules.  The =bytecode=
command in the full-gate example below performs configuration and compilation.

On Unix, keep Python 3, GNU Make, Git, =sh=, Bash, =cat=, and Tcl (=tclsh=)
available for the existing subprocess and installer fixtures.  Individual
platform or optional-library tests can have further prerequisites.  Inspect
their skip explanations rather than treating missing tools as coverage.

Once the optional packages are available, a checkout with ordinary source edits
can run the full gate with:

#+begin_src sh
make check-emacs
make bytecode
make test
#+end_src

Use =bytecode-rebuild= instead after changing branches or public interfaces.
For a machine without the optional package set, start with the core commands
or =make compat-test=; for the three pinned integrations, use the next sections.

Missing required packages abort full-suite loading before ERT runs, often with
“Cannot open load file”.  Some integrations, such as Mu4e, deliberately skip
when unavailable.  ERT prints the selected count, unexpected results, and skips
at the end.  Ordinary ERT runners can succeed with skips; the pinned integration
gate rejects every skip.  A successful run with skips proves only the executed
cases.  Keep the command, selected Emacs version, final counts, and failure/skip
details when reporting results.  Run a failing target directly to retain its
diagnostics instead of rebuilding or regenerating baselines to hide the failure.

The trace tests replace low-level speech and sound functions temporarily; they
do not start a speech server or play audio.  Automated speech assertions check
events and editor state, not pronunciation, audible timing, or device routing.

Use =make trace= to print the current structured core trace without comparing
it to the committed baseline.

* Core speech CI

Run the core speech, voice, transport, Voice Workbench, and startup regressions
without optional Emacs packages:

#+begin_src sh
make core-test
make trace-test
make compiled-aural-test
#+end_src

These checks require Emacs 30.2 or newer, GNU Make, Git, a POSIX shell (=sh=),
and Tcl (=tclsh=).  The core runner checks these prerequisites before loading
tests; missing Make or Tcl must not silently skip their regression cases.
The tests capture speech events and use disposable subprocesses and files.
They do not need a speech server or audio device.

The =core-speech= CI job runs these commands on Emacs 30.2 and 31.1 in a fresh
checkout with a private home directory, so the core tests and traces exercise
source without personal packages or in-tree byte-code.  The last command
compiles the Aural subsystem in a temporary directory and verifies it in a
fresh child Emacs.  ERT lists failures and skipped tests in the job log.
The separate compatibility job still builds every maintained module.

=make core-test= neither regenerates autoloads nor rebuilds local byte-code.
In an existing checkout it prefers newer source, but can load current compiled
dependencies.  Use =make bytecode-check= separately before using a live profile.
This core job does not cover the optional Agent Shell, Notmuch, or EAT suites;
the separate pinned integration job below covers them.

* Pinned integration CI

Run Agent Shell, Notmuch, and EAT tests with reviewed dependency snapshots:

#+begin_src sh
make test-deps-test
make test-deps
make integration-test
#+end_src

These targets use the selected Emacs (30.2 or newer), Python 3, GNU Make, Git,
=sh=, Bash, and =cat=.  Preparation downloads the six archives recorded in
=test/integration-dependencies.json=: Agent Shell, ACP, shell-maker, EAT,
compat, and Notmuch.  Each has an exact upstream commit and archive SHA-256.
It does not consult the current package archive index or your personal packages.
The offline =test-deps-test= checks preparation, reuse, autoloads, corruption,
unsafe archives, and failure cleanup with disposable fixtures.

=make test-deps= caches verified archives below ignored =.test-deps-cache/=,
extracts sources below ignored =.test-deps/=, and generates dependency autoloads
with the selected Emacs.  Notmuch uses only its =emacs/= subtree; two Agent Shell
documentation symlinks are explicitly excluded in the lock.  Dependency Lisp
is not byte-compiled.  =TEST_DEPS_DIR= and =TEST_DEPS_CACHE= override these paths.
Preparation stages a new tree before placing it at the destination.  Reuse
verifies all file hashes and executable bits, the lock, preparer, and Emacs
version.  It refuses to overwrite an unprepared or altered directory.  After
a pin, preparer, or Emacs change, choose a new directory, for example:

#+begin_src sh
make test-deps TEST_DEPS_DIR=/tmp/emacsvox-test-deps-next
make integration-test TEST_DEPS_DIR=/tmp/emacsvox-test-deps-next
#+end_src

Use a separate checkout for each Emacs version.  The runner verifies preparation
again before loading dependency code and fails on missing prerequisites,
unexpected results, skipped tests, or an empty test run.  It never downloads
packages.  Update pins deliberately: review upstream changes, record the new
commit and verified archive hash together, and rerun both CI matrix versions
with fresh dependency directories.  A checksum failure is a reason to inspect
the downloaded artifact, not to automatically accept a new hash.

The =integrations= CI job runs these commands on Emacs 30.2 and 31.1 in a fresh
checkout with a private home directory.  Tests capture speech and agent/mail
events; EAT also exercises disposable terminal subprocesses.  They require no
live agent, mailbox, speech server, or audio device.  They do not establish
audible timing or complete compiled integration parity.  Local runs prefer
newer source but may load current compiled dependencies; the fresh CI checkout
contains no Emacsvox byte-code.  =make compiled-notmuch-test= remains a separate
local check after bringing byte-code current.

* Pinned Emacspeak Reference

The original reference is Emacspeak revision:

#+begin_example
7482f8e2713b5b8ea87132d9d2fcea6664ff4037
#+end_example

This is the fixed comparison baseline and the parent immediately before the
Emacsvox conversion tooling was introduced.  It is intentionally not advanced
with current upstream.  Create an isolated checkout:

#+begin_src sh
git clone https://github.com/tvraman/emacspeak.git ~/src/emacspeak-reference
git -C ~/src/emacspeak-reference switch --detach \
  7482f8e2713b5b8ea87132d9d2fcea6664ff4037
#+end_src

No build or =make config= step is required for the core reference scenarios.
The runner deliberately rejects a different revision, a dirty reference
worktree, or compiled Lisp in its =lisp/= directory.

Run the optional comparison with:

#+begin_src sh
make reference-test \
  EMACSPEAK_DIR=/path/to/emacspeak-reference
#+end_src

The pinned legacy checkout produces many expected Emacs 31 obsolescence
warnings while loading.  The final line reports whether all semantic traces
match.

* Trace Data

=scenarios/emacsvox-core-scenarios.el= contains implementation-neutral command
scenarios.  Golden output is stored under =golden/=.  Each result records:

- semantic speech, letter, icon, tone, silence, stop, rate, notification, and
  message events;
- command return value;
- final text, point, mark, modified state, and kill ring.

Do not refresh a golden file merely to make a failure disappear.  Review the
event and editor-state difference first, then update the appropriate Emacsvox
baseline only when the behaviour change is intentional.  The pinned Emacspeak
golden remains an independent reference.
