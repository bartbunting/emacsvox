2.2 Before You Begin ¶

Install git so you can obtain the Emacsvox checkout. Emacsvox requires Emacs 30.2 or newer, but WSL2 users do not need to find a separate Emacs package before beginning. The guided installer below uses an existing supported Emacs, suggests a suitable package, or offers an explicit source build.

On GNU/Linux and macOS, install Emacs 30.2 or newer and make. Omnivox 1.10.0 or newer is the supported speech-server baseline. Installing its release archive also requires curl and either sha256sum on GNU/Linux or shasum on macOS, plus tar. GNU Texinfo is needed only when building or editing the documentation, not for an ordinary installation.

Ubuntu 26.04 provides Emacs 30.2 as a distribution package, which satisfies this requirement. The same minimum applies to native Windows. On Emacs 30, install lua-mode separately if you use Lua; on Emacs 31 it is built in. Corfu on an Emacs 30 text terminal also needs corfu-terminal; Emacs 31 supports its terminal popup directly.

To check the Emacs found by your shell, run: 

emacs --version

The reported version must be 30.2 or newer. If the command is not found or reports an older version, install a supported Emacs or locate its executable. You can check a specific executable in the same way: 

/path/to/emacs-31/bin/emacs --version

The Linux x86-64 archive requires an Ubuntu 24.04-compatible glibc, libstdc++, libgcc, and ALSA runtime. If the archive does not match the host, the Omnivox source route requires Rust, Python 3, a C and C++ toolchain, CMake, and Clang with libclang. It additionally requires pkg-config and ALSA development headers on GNU/Linux or the Xcode command-line tools on macOS. These are not requirements for the recommended WSL2 binary route. Docker and Windows .NET Framework are needed only for the advanced reproducible source-build route in Building Omnivox For WSL2.

Run the clone from a Linux or WSL terminal and keep the checkout on the Linux filesystem. The following concrete location works for an ordinary per-user installation: 

mkdir -p ~/src
cd ~/src
git clone https://github.com/bartbunting/emacsvox
cd emacsvox

The Emacsvox checkout is the installation directory. It builds in place and does not create a second tree to copy elsewhere. Do not put the ordinary WSL2 checkout below a Windows-mounted path such as /mnt/c; Windows filesystem semantics can interfere with Unix executable permissions and build tools. Clone Omnivox beside Emacsvox only when following the Omnivox source-build or reproducible WSL2 build route.

If this machine will send speech to another workstation, use Installing On A Remote Linux Host instead of installing a local speech server. For a local WSL2 desktop, first ask the guided installer to inspect the machine without changing it: 

cd ~/src/emacsvox
./bin/emacsvox-wsl-install --check

If Emacs is missing, the report checks the available apt version and suggests sudo apt install emacs only when that candidate satisfies 30.2. Older or unavailable candidates are identified without being recommended. You can refresh apt metadata and check again, or choose the pinned source build with ./bin/emacsvox-wsl-install --build-emacs. Add --check to inspect that build’s prerequisites first. The installer never begins a source build by default.

With Emacs selected, the report names it, the matching Omnivox Windows archive, and the per-user installation paths. If source-build packages are missing, it prints one apt command for you to review and run. The installer never invokes sudo itself. After resolving any reported prerequisite, run: 

./bin/emacsvox-wsl-install

If you chose --build-emacs, it prepares the pinned stable Emacs for your user. It then downloads and verifies the matching Omnivox 1.10.0 Windows archive, records its path without editing a shell startup file, compiles Emacsvox, runs a diagnostic, and plays the final speech-server check. The Emacs build can take a while on a fresh machine; later runs reuse it and the verified downloads. Routine compiler output is kept below $XDG_CACHE_HOME/emacsvox/logs, normally ~/.cache/emacsvox/logs. If a build fails, the installer shows its final log lines and the complete log path. Continue only after hearing both the final tone and speech. You can then skip to the last step in Build And Start Emacsvox and start Emacsvox.

After the core installation works, optional speech engines are available from M-x emacsvox-omnivox-manage-components RET. The same manager is the Omnivox engine modules row in Aural Home, opened with C-e H and then I. It distinguishes engines already included in the core, downloadable modules, and bridges that still need a user-supplied runtime. Press i on a downloadable row to confirm, checksum-verify, install, and validate that module without ‘sudo’. Press u on a manager-installed module to confirm and remove it while retaining the verified download cache; press i to reinstall it later. The manager never removes core engines or separately supplied runtimes. See Optional Omnivox Engine Modules explains the choices and licensing boundaries.
