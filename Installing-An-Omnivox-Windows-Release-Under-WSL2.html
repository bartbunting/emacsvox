4.3 Install An Omnivox Windows Release Under WSL2 ¶

This is the recommended WSL2 route for ordinary use on x86-64 Windows and Windows on ARM. From the Emacsvox checkout, inspect the planned installation without changing anything: 

./bin/emacsvox-wsl-install --check

The doctor detects the Windows architecture, chooses the matching Omnivox 1.6.4 archive, and reports the Emacs and per-user paths it will use. If Linux packages are missing, it prints one apt command for you to review and run. Working powershell.exe and wslpath interoperation are required. After resolving any reported prerequisite, run: 

./bin/emacsvox-wsl-install

The installer downloads and checksum-verifies the appropriate Windows archive, installs the complete payload below the Windows user’s LocalAppData, and records its absolute WSL path in $XDG_CONFIG_HOME/emacsvox/omnivox-program, normally ~/.config/emacsvox/omnivox-program. It does not invoke sudo or edit a shell startup file. It also compiles Emacsvox, runs the non-audible launcher diagnostic, and finishes with the audible speech-server check. The normal acceptance condition is hearing both its tone and speech.

This binary route does not need the Omnivox source checkout, Docker, Rust, MinGW, Visual Studio, Windows .NET Framework, or an optional/proprietary speech runtime. WinRT speech is included in Windows. Use ./bin/emacsvox-wsl-install --no-audio-check only for a controlled or headless installation where a separate audible check will be performed later.

4.3.1 Manual Release Installation ¶

The following procedure is the manual equivalent. Use it when reviewing the installer’s actions, working around a local restriction, or repairing one layer independently. It needs curl, unzip, sha256sum, and working powershell.exe and wslpath interoperation. The commands show Windows x64; on Windows on ARM, use windows-arm64 in both the archive and versioned install directory and verify that archive’s published checksum.

Download the Windows x64 archive and the release checksum file in WSL: 

mkdir -p "$HOME/Downloads/omnivox-1.6.4"
cd "$HOME/Downloads/omnivox-1.6.4"
omnivox_version=1.6.4
archive="omnivox-${omnivox_version}-windows-x64.zip"
release_url="https://github.com/bartbunting/omnivox/releases/download/v${omnivox_version}"
curl -fLO "$release_url/$archive"
curl -fLO "$release_url/sha256sums.txt"
grep "  $archive$" sha256sums.txt | sha256sum --check -

The final command must name the archive and report OK. If it does not, remove the download and do not run it. Install the complete archive in a versioned directory on the Windows filesystem: 

windows_local_app_data="$(powershell.exe -NoProfile -NonInteractive \
  -Command '[Environment]::GetFolderPath("LocalApplicationData")' | tr -d '\r')"
install_dir="$(wslpath -u "$windows_local_app_data")/Emacsvox/Omnivox/releases/$omnivox_version-windows-x64"
mkdir -p "$install_dir"
unzip -q -o "$archive" -d "$install_dir"
chmod 755 "$install_dir/omnivox.exe"
config_home=${XDG_CONFIG_HOME:-"$HOME/.config"}
mkdir -p "$config_home/emacsvox"
printf '%s\n' "$install_dir/omnivox.exe" > \
  "$config_home/emacsvox/omnivox-program"

Keep omnivox.exe, espeak-ng-data, and third-party-licenses together in that directory. Do not copy or load the archive’s omnivox-voices.el; Emacsvox uses its bundled adapter. The data-only configuration file makes the selection persistent without changing shell initialization. Use $XDG_CONFIG_HOME instead of ~/.config when it is set. An explicit OMNIVOX_PROGRAM remains a temporary override and takes precedence over this file.

From the Emacsvox checkout, verify the selected release and listen to its physical audio check: 

./servers/omnivox --version
./servers/omnivox --list-voices
./servers/omnivox --check

The version must report 1.6.4 or newer. The check must produce both its tone and spoken confirmation. Release CI verifies the downloaded archive, Windows x64 architecture, adjacent eSpeak data, voice discovery, and headless synthesis through both WinRT and eSpeak, but only this audible check proves the local audio path. The Windows archive is not code-signed. If Windows security or local policy refuses it, do not weaken that policy to complete the install.

The generic Omnivox 1.6.4 archive includes the portable RHVoice helper, but not the RHVoice runtime, language data, or voices. It does not contain the optional Piper, Flite, or RuTTS companions; none is needed for normal WinRT speech. Omnivox 1.6.4 publishes separate matching companions for those engines. Emacsvox’s clean source-build route below verifies and stages the official Piper companion and builds RHVoice, Flite, and RuTTS from the matching 1.6.4 source. A Piper voice model and the RHVoice runtime and voices remain separate user-supplied files. Flite and RuTTS need no external runtime installation in the source-built bundle. Eloquence and DECtalk remain separately licensed, user-supplied runtimes.
