10.2 Use Hello and start a search ¶

Moving among Hello widgets speaks each saved search’s label and displayed message count, or identifies the button or link reached. Use these common Hello commands:

TAB

widget-forward reaches the next search, field, button, or link.

<backtab>

widget-backward reaches the preceding widget.

RET

widget-button-press activates the widget; on a saved search it starts the query.

j

notmuch-jump-search chooses a configured search.

g

notmuch-refresh-this-buffer refreshes Hello.

m

notmuch-mua-new-mail starts composition, handled by Message mode and the separate emacsvox-message integration.

Press ? in a Notmuch view or C-h m for the bindings supplied by your installed Notmuch version. A search can display its first result before all rows finish rendering, so an initial message announcement and a later count need not arrive together.

10.2.1 Understand asynchronous search completion ¶

The default adaptive policy gives useful early feedback without rereading content after you have moved on. For a search you start, other than a refresh, a progress cue is given while its buffer remains selected. The first complete result can then be spoken while the search continues, using the same summary, voices, and status cues as thread navigation. This never moves point or reads an empty row.

When the new search remains selected, you have issued no command in it, and no input is pending, the first result is spoken once on the main stream. Completion reports the final thread count on the notification stream without repeating that result. If completion occurs before an early result could be announced, it reports the count and result at point, or a zero-thread summary.

If you navigate, invoke another command, or leave before completion, the later announcement is only a generic count on the notification stream. It does not reread the selected row or disclose the query, sender, recipients, subject, tags, or attachment metadata. Killing the owning search buffer silently cancels that delivery.

  1. Refresh an existing result

    An explicit refresh differs from a new search. It queues only the generic count on the main stream, without interrupting speech already playing. Navigation can interrupt this announcement, including after you leave the search buffer before the refresh finishes. Refresh completion never rereads the selected row.

  2. Choose less automatic feedback

    summary gives a generic count and completion cue; cue gives only the cue; silent suppresses successful completion. These policies use the same main-stream selection for refreshes. Other search summaries use the notification stream. Failures remain audible and generic with every policy; refresh failures also use the main stream. The deliberate global refresh-all command remains silent.

    Use the focused settings described under Notmuch fields and privacy to choose a policy. Speech Output And Notifications explains the general stream behaviour; the refresh rules above are specific to this integration.
