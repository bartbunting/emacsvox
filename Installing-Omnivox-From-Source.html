14.5 Installing Omnivox From Source ¶

On GNU/Linux/macOS, a source build needs network access for clone, toolchain, and locked dependencies. Prepare:

  • rustup, with the checked-in rust-toolchain.toml selecting Rust.
  • Python 3, C/C++, CMake, and Clang/libclang for eSpeak NG and generated data.
  • GNU/Linux pkg-config and ALSA development headers, commonly libasound2-dev on Debian/Ubuntu or alsa-lib-devel on Fedora.
  • macOS Xcode command-line tools, installed with xcode-select --install.

Keep Omnivox beside Emacsvox, also matching the WSL layout: 

cd /path/containing/emacsvox
git clone https://github.com/bartbunting/omnivox
cd omnivox
make build
make install

make build runs the locked release build and stages matching eSpeak data and notices. make install installs binary/data normally under ~/.cargo/bin. Set OMNIVOX_INSTALL_BIN only for another Cargo binary directory. A bare cargo build does not produce the complete installation payload.

Make the installed directory visible on PATH. No proprietary runtime is needed for the recommended Linux/Mac route.
