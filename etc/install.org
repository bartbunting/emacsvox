* Installation:

To install a specific version of Emacsvox:

  1. Choose a permanent directory for Emacsvox, clone the repository there,
     and check out the desired tag or commit.  The checkout itself is the
     installation directory; run the remaining steps from that directory.
  2. Run =make all= to configure and build Emacsvox.
  3. Install and smoke-test the recommended Omnivox server by following the
     [[file:../docs/manual/chapters/speech-backends.org][Speech Backends guide]].
  4. From the source tree, run =./bin/emacsvox --check= and continue only after
     hearing both the test tone and speech.  Then run =./bin/emacsvox= to prove
     first speech in an isolated Emacs that does not load personal init files.
     =./bin/emacsvox --diagnose= reports the selected Emacs, backend, and paths
     without producing audio or starting interactive Emacs.
  5. Keep the built checkout in that location; there is no separate copy or
     install step.  For normal customized starts, export
     =TTS_PROGRAM=omnivox= and load =lisp/emacsvox-setup.el= from that checkout
     in the user's Emacs init file.  For example, a checkout at
     =~/.local/share/emacsvox= uses:

     #+BEGIN_SRC elisp
     (load-file "~/.local/share/emacsvox/lisp/emacsvox-setup.el")
     #+END_SRC

Direct eSpeak, Outloud, SwiftMac, macOS Python, and DECtalk servers are retained
compatibility paths.  Their prerequisites and support boundary are owned by
the Speech Backends guide rather than this installation summary.

Emacsvox requires Emacs 31 or newer.  When that is not the system =emacs=,
create the ignored machine-local =local.mk= in the repository root:

#+BEGIN_SRC makefile
EMACS=/path/to/emacs-31/bin/emacs
#+END_SRC

All build and test targets then use that compiler without repeating
=EMACS=...= on every invocation.  =make check-emacs= verifies the selection.
The portable =bin/emacsvox= launcher uses the same simple =EMACS= assignment,
unless its process has an explicit =EMACS= environment override, and rejects
an older executable before startup.

** Source checkouts and byte-code

After changing branches or pulling changes, discard ignored byte-code from the
previous tree and rebuild it from the repository root:

#+BEGIN_SRC sh
make bytecode-rebuild
#+END_SRC

For an ordinary Lisp edit, an incremental rebuild is sufficient:

#+BEGIN_SRC sh
make bytecode
#+END_SRC

=make bytecode-check= is a non-mutating preflight for startup or deployment.
It reports missing, stale, orphaned, or wrong-Emacs source-tree byte-code.

During development, load the setup source explicitly:

#+BEGIN_SRC elisp
(load-file "/path/to/emacsvox/lisp/emacsvox-setup.el")
#+END_SRC

The setup entry point checks the files used by aural startup.  If a source is
newer than its matching byte-code, it warns and prefers newer source for that
startup.  This is a safe fallback, not a replacement for rebuilding.

An installed copy should contain current =.elc= files produced by the normal
build, including every =emacsvox-aural-*= manager and integration.  In that
stable installed copy, =(load-library "emacsvox-setup")= may be used.  Do not
use =load-library= as the first load after modifying a source checkout:
Emacs can select an old =emacsvox-setup.elc= before the checker in the newer
source has had a chance to run.  Either rebuild first or use =load-file= on
=emacsvox-setup.el=.
