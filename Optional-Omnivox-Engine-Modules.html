4.3.2 Optional Omnivox Engines ¶

The ordinary WSL2 archive is the Omnivox core, not a claim that every supported engine is installed. It keeps first speech small while matching companion archives provide engines that are larger, experimental, architecture-specific, or incomplete without separately chosen data.

From a running Emacsvox session, open: 

M-x emacsvox-omnivox-manage-components RET

You can also press C-e H for Aural Home and then I, or choose Browse voices. These routes open the same engine list. Opening speaks the selected engine using the current speech inventory, without waiting for file checks or fresh discovery. Optional engines absent from that inventory remain visible as not reported, so their installation controls are still reachable. Press v to browse an engine’s voices directly, or RET for engine details. Details start with a short status summary and the voice actions, with Browse voices selected. Matching main and notification status is combined. Problems remain visible near the top. Startup settings and Diagnostics start collapsed; press RET on a section to expand or collapse it. Each engine remembers its expanded sections and selection.

Available describes discovery from the current running worker. An older check does not by itself make the engine unavailable. Previously available means the evidence belongs to a stopped or replaced worker. Details announce the engine before requesting newer inventory in the background when its check is over five minutes old, or belongs to another worker. File checks also run in the background. Streams differ means the workers report different availability, policy, health or voice identities. A bridge’s presence alone never establishes that its runtime is usable. Not checked is not a claim that the runtime is missing. Diagnostics contains each stream’s status, worker paths, inventory time, runtime discovery, and health.

Required runtime appears near the top for engines that need native libraries. For example, successful DECtalk discovery reports that its DLL and dictionary loaded. Matching main and notification evidence is combined; differences are shown separately. Missing files and load failures retain the worker’s reason. A disabled engine does not imply missing files, and evidence from a replaced worker does not establish the new worker’s runtime status. Opening or refreshing engine details uses speech-worker discovery without invoking the release installer.

On WSL, Manage installed release explicitly opens the separate release installer. Installation being managed and Location identify the versioned release affected by its actions. This may differ from a development build or remote speech server. Installed engine files reports file presence; Check release engine tests runtime initialization and voice discovery for that release. Installation and removal keep current speech running and do not select a different speech server. If a helper is still in use, removal fails visibly; stop the sessions using that release before retrying. Press q to return to the current engine with its selection retained.

  • Browse voices combines that engine’s reported voices with its installed library, including disabled downloads. This separate browser keeps the general Voice Workbench’s filters and staged edits intact. Languages form expandable headings with voice counts; RET expands or collapses a heading. A single-language list starts expanded, and the browser remembers groups and the selected voice. On a voice, RET or P speaks an exact sample; x shows details; t opens the existing voice editor for an unsaved experiment. Saving there asks for a palette destination. Browsing and auditioning do not change a palette. q returns to the selected engine detail. Library information loads in the background; the browser refreshes quietly. Installed distinguishes library entries from engine-supplied voices. Enabled is the desired selection for the next Apply. Active reports current eligibility on both streams, main only, notification only, or neither. Unknown means current worker evidence is missing or inconsistent; press R to refresh. Active does not mean a model is resident in memory, and is not a listening test. Samples use main speech; an inactive downloaded voice must be enabled and applied before sampling.
  • Under Startup settings, Edit file settings for the bundled local Omnivox launcher opens the selected engine’s file option in Customize. Piper accepts one local ONNX model with its matching JSON file. Eloquence and DECtalk accept their runtime DLL paths. Flite accepts external ‘.flitevox’ files, each with a Load file switch. Use absolute paths as seen by Emacs; WSL converts them for the chosen Windows executable. Keep required companion files beside their runtime or model. Remote speech settings must be changed on the speech host. These are manual overrides. Having no manual files selected does not mean there are no downloaded voices: the installed voice library or launcher defaults apply. A manual Flite file list overrides its installed library.
  • In Browse voices, manage installed Piper and Flite voices on the local speech host. Press + to enable or disable a voice in the desired configuration, then a to review and Apply. Apply checks both replacements, restarts main and notification speech, and verifies both before committing. If a replacement fails, it restores both previous configurations. Disabling keeps the files and saved palette references. Changing Enabled leaves Active unchanged until Apply.
  • Voice variants in eSpeak details lists the bundled variants reported by the running speech worker. Choose a base voice with b, then use the arrow keys or C-n/C-p to browse variants. The whole list is alphabetical by displayed name, ignoring capitalization. Press P or RET to hear the selected combination immediately. Variants need no enabling, settings save, download or speech restart. The existing p preview shortcut also remains available. Press u for Use in palette, then choose a palette and named voice. The voice editor adds the variant as its preferred choice, retaining existing fallbacks and tuning. Press P to hear it with the palette’s settings, then w to Save and apply, or choose Save to collection without selecting to keep it for later. Editing a built-in palette creates a personal copy. Use at Startup in Voice Palettes controls which palette is selected next time. q returns to the variants list with its selection retained; v opens the base-voice browser. Existing saved variant references remain valid. An older Omnivox worker must be updated once to provide on-demand variants; the screen reports missing support explicitly.
  • Get more voices in Piper, Flite, MBROLA or RHVoice details opens the reviewed download catalogue. Piper is grouped by language, voice name and quality; Flite offers AWB and RMS. Voices with one quality appear directly in their language group; only voices with several qualities need another group. Press RET to open a group or model, and q to return. / searches all models by name or language, including outside the current group. Model details show download size, source, licence information and storage location. s shows or hides the speakers sharing that model. A model with several speakers downloads once; each speaker can be enabled separately after installation. Press i to install. The download runs in the background without speaking each progress update. Omnivox checks each file and validates the voice before adding it disabled. Stay in the catalogue and press e to enable or disable the installed voice, then a to review and Apply to both speech streams. For a shared model, e asks which speaker to change. Enabling alone does not restart speech. These actions also appear near the top of model details, alongside the installed and enabled status. Installation and Apply confirmations offer ‘yes’ and ‘no’ through completion. Type y TAB RET to confirm; an empty RET declines, and C-g cancels. Press c to request cancellation and wait for cleanup. The shipped collection contains reviewed, pinned models that passed native validation. Models with unresolved terms or unsupported configurations are withheld; the catalogue is not a live listing of every upstream download.
  • MBROLA offers US1, US2 and US3; British English en1 is already included. These downloads require the updated, separately configured development companion on Linux or Windows. Older runtimes keep their Piper and Flite catalogues and report that MBROLA downloads need an update. The individual database licence and README accompany each download; review the terms in its details. The first installation retains en1 as an enabled included voice, unless it was explicitly disabled. Enable several MBROLA voices to assign them to different palette choices or speech streams. Each request opens its selected database; enabled databases do not all remain loaded.
  • RHVoice offers Alan (Scottish English), BDL and CLB (American English), and Ksp (Indian English). These downloads require an updated Omnivox build and a separately installed compatible RHVoice runtime, selected in engine settings. Each voice includes its own English language data and upstream notices. Review its terms before installing. Enable and Apply adds the downloaded voice alongside your externally installed voices, including SLT. A conflicting external installation of the same voice is reported rather than replaced. Uninstallation removes only the managed package; it preserves your external voices and RHVoice runtime.
  • After installation, press l to browse voices, + to enable the voice, and a to review Apply. Review covers the managed engines and both speech streams. Installation alone does not load the voice or change speech. Downloaded files belong to you and stay in Omnivox’s per-user voice storage across executable upgrades. Failed and interrupted operations retain files for inspection; automatic resume and package updates are not provided yet.
  • To uninstall a downloaded Piper, Flite, MBROLA or RHVoice package, disable all its speakers and Apply, then press C-c u in the voice browser. Review its affected voices, size and retained palette references before confirming. Files still needed by other sessions are retained. Built-in SLT and MBROLA en1, imported files and engine runtimes cannot be removed here. C-c U reviews incomplete cleanup for resumption.
  • In the voice browser, d opens the download catalogue and b includes built-in Flite SLT explicitly. i installs a completed native validation operation by its identifier; imported voices initially remain disabled. Their files stay at the validated paths and must remain there. This advanced import action is separate from catalogue installation; a file-selection wizard is not yet provided. C-c r shows the last Apply result, R refreshes, and q returns to details. Apply requires separate main and notification streams started with the updated local Omnivox build. Explicit Piper or Flite file overrides must be cleared before applying that engine’s installed voices. An uncertain native cleanup or commit blocks further Apply and remains visible in the result.
  • Check configured engine runs separate voice discovery using the local launcher’s current configuration, with a 30 second limit. It retains the executable target, voice list and diagnostic output. It neither speaks a sample nor replaces live workers. A failed Flite file can leave built-in SLT usable; the check reports incomplete discovery when fewer than the selected files plus SLT are found. Duplicate external voice names are not supported.
  • File settings take effect in newly started workers. Save through Customize to retain them, then explicitly choose Restart local speech when ready; this interrupts this session’s main and notification speech. Refresh live voices afterward to inspect both workers. Turning off a Flite file keeps its data and palette references, but new helpers omit it. Existing helpers keep it loaded until restarted. Built-in SLT remains loaded, and each speech worker loads its own copy of enabled external voices. These file switches do not provide a general per-voice policy or a memory measurement.
  • Explicit ‘OMNIVOX_PIPER_MODEL’, ‘OMNIVOX_FLITE_VOICES’ and runtime environment settings override these options; details identify such overrides. The legacy ‘EMACSVOX_ECI_DLL’ and ‘EMACSVOX_DECTALK_DLL’ overrides also remain effective. Clearing an option returns to existing discovery or launcher defaults. Direct native executable launches do not consume the bundled launcher’s file options.
  • To refresh discovery, press g or use Refresh status in details. Both worker inventories are requested asynchronously.
  • To install an engine, choose Manage installed release and check the displayed installation and location. If its files are available to download, activate Install engine with RET, then confirm. The manager verifies the version-matched download. The table shows its operation in progress while the current engine’s status stays separate.
  • In the installed-release view, Refresh release files runs a bounded background file check. Check release engine lists voices in that release without playing a sample. A changed installation target requires refreshing before retrying. Completion produces a short notice without selecting another buffer. The last result remains in the release view; Read last result opens its complete output.
  • In details, TAB moves to the next action or section; S-TAB moves to the previous one. RET activates an action or toggles a section. Arrow keys read visible fields and values. q returns to the selected engine row and h opens Aural Home, and ? opens help. Background refresh preserves selection and expanded sections.
  • To remove an installed engine, expand Engine installation, activate Uninstall engine, and confirm. This is available only for Flite, RuTTS, Piper, and TGSpeechBox engines installed by this manager. It cannot remove the Omnivox core, built-in engines, or runtime bridges.

Removal keeps the verified download in the local cache. If you change your mind, open its details again and choose Install engine to reinstall it. A valid cached download is reused.

The engine’s whole managed directory is removed. Move anything you placed inside that directory somewhere else before confirming. User-supplied runtimes and models stored outside it are not touched; remove those separately using their supplier’s instructions. Before removal, the manager announces the operation and briefly stops its active Omnivox speech streams so Windows can release the engine helper. It restores speech when removal finishes, including after an error. After a successful installation, it also refreshes the table and restarts a running Omnivox server. Operations run asynchronously so Emacs remains responsive. The table shows uninstalling during removal and testing during a voice check. Completion or failure refreshes the view. If the managed listing fails, its last known records remain with the error in details; live discovery remains available independently.

If a removal reports that its helper is still in use, close any other Emacsvox or Omnivox session using that release and press u again. The manager safely recognizes an interrupted removal when the expected helper is the only file left; it continues to refuse directories containing unrecognized files.

The manager reads ‘etc/omnivox-components.conf’. Every archive name, byte size, and SHA-256 hash is pinned to the same Omnivox version as the installed core. The WSL2 installer rejects a mismatched core, an unsafe archive layout, missing source provenance, or a helper that cannot pass its staged voice-discovery check. It then installs the engine below the same versioned Windows ‘LocalAppData’ release directory. It does not invoke ‘sudo’ or edit shell startup files.

The choices have different boundaries:

  • Flite includes its compact English SLT voice and needs no external runtime.
  • RuTTS includes its compact Russian voices and needs no external runtime.
  • Piper installs native engine support, but appears only after you separately review and configure an ONNX voice model and its model card.
  • TGSpeechBox is an explicitly experimental multilingual formant engine. The 1.12.0 engine calibrates rate control to the Eloquence scale and supplies exact requested text anchors for capitalization and timed presentation.
  • RHVoice, Eloquence, and DECtalk use distributable bridges, but Emacsvox never downloads their external runtimes, voices, dictionaries, or licence material. Supply those only when you have the appropriate distribution and licence.

For a terminal-only installation, run ‘./bin/emacsvox-omnivox-components --list’ and then, for example, ‘./bin/emacsvox-omnivox-components --install flite’. Multiple engine names may follow ‘--install’ or ‘--uninstall’. For example, use ‘./bin/emacsvox-omnivox-components --uninstall flite’ to remove the managed Flite directory while retaining its cached archive. Restart Omnivox after a terminal installation or removal, then use ‘--test ENGINE’ or the Emacs manager’s t command. The direct Omnivox release assets remain available for maintainers and recovery, but the manager is the recommended way to select them.
