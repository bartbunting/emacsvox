8.11.2 Understand the main and notification streams ¶

The main stream presents current interaction such as movement, buffer entry, and message opening. Navigation interrupts obsolete main speech. The notification stream presents asynchronous events without stopping main speech; normal navigation does not stop a separate notification stream. Both can be heard concurrently, with each notification’s cue and speech delivered together. Integrations may deliberately route particular asynchronous actions differently: Notmuch’s explicit refresh, for example, uses interruptible main speech.

Open C-e H o n for routing, then r for Automatic, Left, Right, Both channels or Main output. The configured choice is focused and marked. Arrows browse without applying; RET chooses and returns to the Route control. q or C-g cancels the list.

With a supporting local Omnivox worker, the menu says applies live. Left, Right and Both change subsequent notification speech, tones and earcons without restarting either speech worker. Audio already submitted keeps its previous route. Main output retires only the notification worker; choosing a separate route again starts that worker while main speech stays running. Automatic uses a separate worker on both channels. Engine choices and physical output selections are retained.

Press N to preview the active route. Choose the previous route to reverse an experiment; S separately saves routing and spatial defaults for startup. If a change is reported as unconfirmed, choose its route again before saving. h inspects a notification-history snapshot, returning with q.

Older Omnivox workers, remote speech and other backends retain the next restart menu. There, selecting only sets the next route; N still previews the active arrangement and R restarts speech after confirmation. That menu also offers Other device for an existing device name; cancelling its prompt retains the previous choice and stays in the list.

For physical devices on a supporting Windows Omnivox build, D opens main outputs and M opens notification outputs. Press d to browse their Transient choices. Selecting a candidate, applying it and saving it are separate actions, described in Selecting And Checking Omnivox.

With Omnivox, Automatic normally uses an independent notification process; left/right/both choose its route. Use main output (notifications remain audible) uses the main process instead, where navigation can interrupt it. It is not a mute option. Other backends use their configured device or fall back to main speech. In Lisp, default or an empty string means main output; use descriptive labels for ordinary configuration.

C-e d C-n explicitly reinitialises the notification arrangement when needed. Use notification history to read an announcement you missed. Ordinary obsolete-main-speech cancellation is local to main; explicit tts-stop stops both streams.
