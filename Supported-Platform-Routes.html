4.1 Supported Platform Routes ¶

The following table describes Emacsvox support, not every platform that the Omnivox project can build. “Host check required” means that automated build and archive verification does not prove playback through the user’s audio device; an audible omnivox --check on that machine remains the acceptance test.

Emacs platformRecommended routeCurrent support evidence
GNU/Linux x86-64 with an Ubuntu 24.04-compatible runtimeOmnivox 1.7.1 release archive using eSpeak NGThe published archive is built and verified on Ubuntu 24.04. Compatible glibc, libstdc++, libgcc, and ALSA runtime libraries are required; the audible host check remains required.
Other GNU/Linux systemsSource-built Omnivox using eSpeak NGUse the source route for Linux ARM64, an older distribution ABI, or a host that cannot run the published x86-64 archive.
macOS on Apple siliconOmnivox 1.7.1 release archive using AVSpeechSynthesizerThe published ARM64 archive is built and verified on a native macOS runner; the audible host check remains required.
macOS on IntelOmnivox 1.7.1 release archive using AVSpeechSynthesizerThe published x64 archive is built and verified on a native macOS runner; the audible host check remains required.
Emacs in WSL2 on x86-64 WindowsOmnivox 1.7.1 Windows x64 release archive using WinRTThe published archive is checksum-protected and release CI verifies its architecture, adjacent data, WinRT and eSpeak synthesis. The audible host check remains required.
Emacs in WSL2 on Windows on ARMOmnivox 1.7.1 Windows ARM64 release archive using WinRTRelease CI verifies the ARM64 archive, adjacent data, WinRT and eSpeak synthesis, and the guided installer selects it automatically. A complete WSL2 host and audible check remains required.

Native installer, complete byte-code compilation, fresh-process verification, and two-lane speech checks cover this route. Confirm audible speech on the installed host. Native Windows ARM64 is not yet supported.

The release-archive routes below are the shortest installation on matching GNU/Linux, macOS, and WSL2 hosts. A bare executable, a repository tag, or an unpackaged CI artifact is not a complete installation: keep the release’s runtime data and notices beside the executable.

Do not set OMNIVOX_ENGINE during initial setup. Its empty value selects the normal platform engine above. Engine routing and optional Piper, Eloquence, or DECtalk support are later customizations, not prerequisites for first speech.

Remote workstation speech (preview). Emacs can run on an SSH host while Omnivox, its installed voices, and playback remain on the computer you are using. This requires the new --serve option and the matching Emacsvox remote transport; the published Omnivox 1.7.1 binary does not include it. Keep the ordinary local setup until those development builds are installed.

On your workstation, create a private token once. The creation tool refuses to overwrite an existing token or print its contents: 

mkdir -p "$HOME/.config/omnivox"
python3 /path/to/omnivox/tools/create_remote_token.py \
    "$HOME/.config/omnivox/remote-token"

Start your installed Omnivox in a terminal and leave it running. Give it the sound directory from the same Emacsvox sound-pack installation used by remote Emacs: 

omnivox --serve --token-file "$HOME/.config/omnivox/remote-token" \
    --sound-root /path/to/emacsvox/sounds

For a Windows service started through the WSL Emacsvox launcher, translate both paths for the Windows process: 

/path/to/emacsvox/servers/omnivox --serve \
    --token-file "$(wslpath -w "$HOME/.config/omnivox/remote-token")" \
    --sound-root "$(wslpath -w /path/to/emacsvox/sounds)"

In another workstation terminal, copy the token over your verified SSH connection and open the reverse forward. Replace user@emacs-host with the machine where Emacs will run: 

ssh user@emacs-host 'mkdir -p ~/.config/omnivox; chmod 700 ~/.config/omnivox'
scp "$HOME/.config/omnivox/remote-token" user@emacs-host:.config/omnivox/remote-token
ssh user@emacs-host 'chmod 600 ~/.config/omnivox/remote-token'
ssh -o ExitOnForwardFailure=yes -o ServerAliveInterval=10 \
    -o ServerAliveCountMax=2 \
    -R 127.0.0.1:6417:127.0.0.1:6417 user@emacs-host

If Omnivox runs on Windows, open the final SSH connection with Windows OpenSSH (ssh.exe from WSL, or ssh from PowerShell). Its forward must reach Windows loopback. A WSL SSH client under NAT reaches WSL’s separate loopback instead. Windows OpenSSH uses your Windows SSH keys and host-trust configuration.

For a remote-only Linux installation and isolated launch commands, follow Installing On A Remote Linux Host. The --remote launcher supplies the connection options before initializing speech and needs no local Omnivox executable.

For a personal Emacs configuration, set these options before starting Emacsvox: 

(setq tts-program "omnivox"
      omnivox-remote-host "127.0.0.1"
      omnivox-remote-port 6417
      omnivox-remote-token-file "~/.config/omnivox/remote-token")

Use M-x omnivox-remote-connect to connect or retry manually, M-x omnivox-remote-status to inspect the connection, and M-x omnivox-remote-disconnect to stop it and suspend retries. After a lost connection, Emacsvox reconnects with fresh voice and routing information; unfinished speech is discarded. Foreground and notification speech retain separate workers. Only one Emacs session may own a service at a time.

If startup connects main speech but the notification connection fails, Emacsvox keeps main speech available and retries the missing notification connection automatically. Recovery does not replace the working main connection. Set omnivox-remote-auto-reconnect to nil to disable automatic retries; an explicit disconnect also suspends them until you connect again. The status command reports the pending retry and latest connection error.

The service and forwarded endpoint must stay on loopback. Do not enable SSH GatewayPorts. SSH encrypts the connection; the private token also excludes other users on the remote host. To rotate it, stop the service, replace both private token files, and restart. Typing quit in the service terminal or interrupting it stops its workers.

The voice inventory describes your workstation. Install engines and use the engine-module manager on that workstation. Bundled icons resolve there by pack-relative name; personal sounds outside the bundled sound directory and sound uploads are not supported in this first version. Omitting --sound-root disables file-based icons. If the remote port is occupied, choose another port on the left side of -R and set omnivox-remote-port to match. An authentication failure means the token copies differ or their file permissions are too broad; a busy service still belongs to another connection.
