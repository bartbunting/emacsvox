2.1 Supported Platform Routes ¶

The following table describes Emacsvox support, not every platform that the Omnivox project can build. “Host check required” means that the source path is maintained but an audible omnivox --check on the user’s machine is still the acceptance test.

Emacs platformRecommended routeCurrent support evidence
GNU/LinuxSource-built Omnivox using eSpeak NGSupported source installation; host check required. Omnivox does not currently publish a Linux archive or run a Linux audio-runtime CI job.
macOS on Apple siliconSource-built Omnivox using AVSpeechSynthesizerSupported source installation; Omnivox CI executes this native target, and the host check remains required.
macOS on IntelSource-built Omnivox using AVSpeechSynthesizerAvailable source installation; current Omnivox CI cross-builds this target but does not execute it. Treat the host check as required validation.
Emacs in WSL2 on x86-64 WindowsEmacsvox-staged Windows Omnivox using WinRTSupported advanced deployment; the pinned build verifies its payload, but speech and audio must be accepted on the target Windows host.
Native Windows EmacsOmnivox executable on exec-path, using WinRTPreview. The executable-resolution path exists, but Emacsvox does not yet publish or fresh-machine test a complete native-Windows setup. Initial users should use the WSL2 route.

There is no verified public binary-download path in this guide. Build from source as described below. A repository tag, a CI artifact, or an executable without its adjacent runtime data is not a substitute for a supported install payload.

Do not set OMNIVOX_ENGINE during initial setup. Its empty value selects the normal platform engine above. Engine routing and optional Piper, Eloquence, or DECtalk support are later customizations, not prerequisites for first speech.
