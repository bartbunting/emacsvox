11.1 Start and control a session ¶

Load Emacsvox and start Agent Shell with M-x agent-shell. Emacsvox loads its integration after Agent Shell and activates both new and already existing shell buffers. Run M-x emacsvox-agent-shell-enable only when manually re-enabling support after it was disabled or while diagnosing a live reload.

  • Write and edit prompts
  • Follow a response and steer a running turn
  • Work with queued prompts
  • Check session settings and status

11.1.1 Write and edit prompts ¶

By default, reaching the live prompt lets you type immediately. The Input activation setting offers an explicit editing step if you prefer to keep browsing at the end of the transcript. Open C-e S i, choose Automatic or Explicit, and press w in the parent menu to save. Settings search also finds Agent Shell input activation. The choice applies to existing and new shells; buffer-local overrides take precedence.

With Explicit selected, J, U and the other navigation letters keep their navigation meanings at the live prompt. Press RET on its label, on blank padding immediately above it, or anywhere in the draft to activate editing, or C-c i (emacsvox-agent-shell-edit-input) from anywhere in the shell to focus the draft. From the transcript or prompt label, this moves to the end of the draft; within input it preserves point. By default, Emacsvox says “Editing.” Ordinary typing, paste and editing commands then work, and submission uses Agent Shell’s normal commands. RET on links, permission buttons and question controls retains its existing action; only the inactive live prompt uses it to start editing.

The C-c i and C-c e bindings apply only to inline shells using Explicit activation. Emacsvox’s Org support can assign C-c i globally to link insertion; Explicit mode uses it for input focus instead. Use M-x org-insert-link for that action while editing, or choose Automatic to restore the ordinary binding.

Press C-c e (emacsvox-agent-shell-browse) to return to browsing at point without sending or discarding the draft. Emacsvox says “Browsing.” Moving out of the live input also returns to browsing and keeps the destination’s navigation speech; moving between its lines keeps editing active. While editing, M-< moves to the beginning of the draft and reads its first line without leaving editing. To reach the top of the transcript, press C-c e followed by M-<. Automatic input and viewport editors retain their ordinary M-< binding. A successful submission or queueing returns to browsing, while a rejected submission keeps its draft editable. The mode line shows Agent browse or Agent edit. Reading the first input line says “Input” along with the agent’s busy or waiting status. Browsing protects the draft from ordinary typing, paste and deletion.

For sound-only feedback when activating editing or returning to browsing, open C-e S e and choose Earcon. Speech is the default; Both combines speech and sound. Editing uses 08-pop-and-collapse-on and browsing uses 08-pop-and-collapse-off. These recordings are bundled with Emacsvox as the agent-input-on and agent-input-off cues, available with every sound pack. You can assign different recordings to those cues in a personal pack. Auditory icons must be enabled to hear these sounds. With Earcon or Both selected, arrowing out of the input field also plays the browsing sound without replacing the destination’s speech or adding “Browsing.” Moving between lines within the field does not play it. The choice applies immediately; buffer-local overrides take precedence. Press w in the parent menu to save the global default. Submission confirmations remain separate from this setting.

The live prompt retains Emacs undo across these transitions. Interactive text yanks speak the inserted text, including when a prefix argument selects a different kill-ring entry. Image attachment keeps Agent Shell’s existing feedback. Submitted transcript text is history rather than editable prompt input. Press C-c C-c to ask Agent Shell to interrupt an active request; its normal confirmation setting still applies.

With Agent Shell’s persistent prompt enabled, you can keep typing while the agent works. Brackets and navigation letters are ordinary text while editing that prompt. Reading the live prompt says “Agent busy” while the agent works. A pending permission is announced as “Waiting for permission”; a pending question says “Waiting for an answer.” These cues also precede the first line of a draft; later lines keep ordinary reading feedback. “Ready for input” is reserved for an empty prompt when the agent is idle and input activation is Automatic.

Quoting a selected region, sending source context, dropping files, and inserting shell-command output can add to that live draft while the agent works, including in Explicit browse mode. These insertions do not submit the draft or activate editing. If there is no live prompt while busy, Agent Shell offers its queue editor instead. Use M-x yank-media to attach a clipboard image on a display that supports native clipboard access. Image previews survive queueing and steering. The animated busy marker does not add repeated speech; reading the prompt continues to give its current state.

The dedicated viewport prompt editor always opens ready for typing, regardless of the inline input setting. M-x agent-shell-prompt-compose transfers the inline draft to that editor. Continuing a list announces its bullet or next number and indentation. Indenting and dedenting announce the new indentation; leaving an empty list item announces that the list ended.

11.1.2 Follow a response and steer a running turn ¶

Emacsvox speaks routine content only at complete turn boundaries. A network pause does not make a partial answer sound complete. A cancelled, refused, or failed turn reports its outcome without replacing the last successfully completed response.

In Explicit inline input and the viewport editor, Emacsvox announces whether a prompt was submitted, queued, or sent for steering. Inline input returns to browsing without another state announcement. The viewport also reports whether its editor stays open. The normal and override send commands follow Agent Shell’s configured busy routes, including queueing when the provider does not support steering. “Steering sent” confirms dispatch; the agent’s acceptance or refusal follows separately.

When you use M-x agent-shell-prompt-steer, Emacsvox confirms whether the agent accepted the steer, declined it, or started a separate turn. A separate turn is announced as still in progress; it is not reported as complete until Agent Shell supplies a completion boundary. Server-pushed turns, when supported by the provider, follow the same completed-response speech policy.

11.1.3 Work with queued prompts ¶

With Agent Shell 0.94.1 or newer, you can redirect the most recently queued prompt into the running turn. Leave the live prompt empty and press M-RET (agent-shell-submit-override). With the default queue and steering routes, Agent Shell asks before steering that prompt; earlier prompts stay queued. Declining leaves the queue unchanged, and a failed send restores the prompt. The agent must still be busy and support steering. Custom busy-send routes can change or disable this action through agent-shell-busy-submit-reroute-function.

This works while browsing with Explicit input activation and keeps you in browse mode. An unsent draft still requires entering edit mode before sending; M-RET does not redirect queued input when the live prompt contains a draft.

Queued prompts announce when they start and how many remain. Recent Agent Shell versions merge queued prompts into one turn by default; Emacsvox announces how many prompts started together. Set agent-shell-prompt-queue-merge to nil to send them one turn at a time. After cancellation, Agent Shell asks whether to continue with the queue. If you decline, or a failed turn leaves prompts waiting, the queue announcement gives its count and the command M-x agent-shell-prompt-queue-resume. Queue-start feedback follows the session’s speech level; paused-queue warnings follow emacsvox-agent-shell-signal-processing. Agent Shell also asks before killing a shell or exiting Emacs when queued prompts would be lost. Declining that question keeps the prompts available.

11.1.4 Check session settings and status ¶

Model, mode, thought-level, and other session setting changes announce their confirmed values. Background setting announcements identify the session. When grouped choices share a name, confirmation includes the group shown by Agent Shell’s completion menu.

Use M-x emacsvox-agent-shell-speak-header to hear the full session header. When agent-shell-show-cost-indicator is enabled and the provider reports a positive cost, this includes the cumulative cost with Agent Shell’s currency and rounding. Brief announcements when entering a session stay concise.
