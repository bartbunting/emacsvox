#+title: DTK to TTS Namespace Modernization

Status: completed on 2026-07-25.  This file retains the initial inventory and
phase plan as a migration record.  Historical branch names, counts, and
transitional compatibility steps are not current contributor instructions;
the completion status near the end and =make tts-audit= are authoritative.

* Purpose

The original Emacspeak speech server was DECtalk, so the generic speech
interface acquired the =dtk-= prefix.  Emacsvox now supports eSpeak, Outloud,
Mac, SwiftMac, cloud, and other engines through the same interface.  This
migration gives the engine-independent layer a TTS name while retaining
DECtalk as a supported backend.

This work is separate from the native-advice migration and is developed on the
=tts-modernization= branch.

* Initial Inventory

The read-only inventory on 2026-07-24 found:

- approximately 135 =dtk-= definitions in =lisp/dtk-speak.el=;
- 729 references in 126 other Lisp modules;
- 196 references in 75 test files;
- 47 active references to legacy =DTK_*= environment variables;
- 262 tracked, non-archive files containing a =dtk-= or =DTK_= name;
- a stale tracked copy at =lisp/dtk-speak.el.final-warn= (removed in the
  first migration slice).

Run the syntax-aware Lisp inventory with:

#+begin_src sh
make tts-audit
#+end_src

The audit is now a zero-legacy gate.  It parses =lisp/= forms and also scans
tracked active non-Lisp text, while excluding explicit historical archives,
tests that assert removal of the old API, and this migration record.  The exact
backend strings =dtk-exp= and =dtk-soft= are allowed; other =dtk-*= strings
still fail the gate.

* Naming Policy

Generic Lisp APIs use =tts-=:

| Legacy                         | Canonical                    |
|--------------------------------+------------------------------|
| =dtk-speak.el=                 | =tts-speak.el=               |
| =dtk-speak=                    | =tts-speak=                  |
| =dtk-stop=                     | =tts-stop=                   |
| =dtk-tone=                     | =tts-tone=                   |
| =dtk-notify=                   | =tts-notify=                 |
| =dtk-program=                  | =tts-program=                |
| =dtk-speaker-process=          | =tts-speaker-process=        |
| =dtk-set-rate=                 | =tts-set-rate=               |
| =dtk-punctuation-mode=         | =tts-punctuation-mode=       |
| =dtk-interp-*=                 | private =tts--protocol-*=    |
| =dtk-unicode-*=                | =tts-unicode-*=              |
| =emacsvox-dtk-submap=          | =emacsvox-tts-submap=        |
| =DTK_PROGRAM=                  | =TTS_PROGRAM=                |

Names that identify an actual DECtalk backend remain valid, including
=dectalk-voices.el=, =servers/dtk-exp=, =servers/dtk-soft=,
=servers/software-dtk=, and =cloud-dtk=.

* Breaking-Change Policy

Repository code moves completely to canonical names.  Legacy generic function,
variable, file, and feature names are removed rather than retained in a
compatibility module.  In particular, there is no =dtk-speak.el= loader and no
=dtk-speak= feature after the file rename.

The aliases introduced to keep the branch runnable during migration are
strictly transitional development scaffolding.  They are removed as canonical
definitions take ownership, and are not part of the completed migration.

The prefix-map rename is an intentional immediate break:
=emacsvox-dtk-submap= has no compatibility alias.  User configuration must use
=emacsvox-tts-submap= instead; the default =C-e d= key sequence is unchanged.

The environment variable =DTK_PROGRAM= is also removed; configuration must use
=TTS_PROGRAM=.

These are intentional breaking changes.  User configuration must replace
=dtk-*= generic names with their =tts-*= equivalents and require =tts-speak=
instead of =dtk-speak=.  Names that identify the DECtalk backend itself remain
valid as described above.

* Test Gates

Before changing the implementation:

1. Test exact commands sent over the speech-server protocol.
2. Test engine selection and voice adapter configuration.
3. Test dynamic and buffer-local TTS state.
4. Test primary and notification process routing.
5. Test that =TTS_PROGRAM= is honored and =DTK_PROGRAM= is ignored.
6. Teach semantic traces to normalize old Emacspeak and new Emacsvox APIs.

Every migration commit must pass the Emacs 31 ERT suite, semantic traces,
complete Lisp byte compilation, startup smoke test where applicable, and the
TTS namespace audit.

* Migration Slices

** 1. Inventory and tests

Add the syntax-aware audit, protocol contract tests, state tests, backend
configuration tests, and environment selection tests.

** 2. Canonical namespace foundation

Introduce canonical state variables and a canonical public facade.  Preserve
legacy entry points while callers still use them.

** 3. Core runtime

Convert low-level protocol operations, text preparation, audio formatting,
speech, notification, Unicode handling, and process lifecycle code.

** 4. Central consumers

Convert =emacsvox-speak.el=, =emacsvox-advice.el=, =emacsvox.el=,
=emacsvox-keymap.el=, =emacsvox-sounds.el=, =voice-setup.el=, and all engine
voice adapters.

** 5. Remaining Lisp consumers

Convert first-party support and third-party integration modules in small,
alphabetical or behavioural batches.  Update the matching tests in each
commit.

** 6. Environment, servers, and documentation

Migrate launchers and generic server configuration from =DTK_*= to =TTS_*=,
without a legacy fallback.  Update source documentation and regenerate
derived manuals separately.

** 7. File, feature, and compatibility removal

Move the generic implementation to =tts-speak.el=, provide only =tts-speak=,
remove transitional aliases, and require a zero legacy audit outside files
that describe real DECtalk backends or historical archives.

* Adapter Voice Capability Interface

The generic TTS layer exposes =tts-voice-capabilities=.  The selected adapter
installs =tts-voice-capabilities-function= when it is configured, just as it
installs its voice compiler.  The returned plist describes:

- the adapter and whether the data is static, discovered, or a compatibility
  fallback;
- whether inline base-voice selection is =enumerated=, =free-form=, or
  =unsupported=;
- enumerated native identifiers, aliases, labels, and portable traits;
- supported normalized ACSS dimensions and their parameter ranges.

=tts-voice-family-id= resolves an exact native identifier or alias first, then
a portable characteristic such as =male=, =female=, or =child=.  Callers save
the portable request and resolve it at compilation time.  Consequently, a
=female= palette style selects Outloud's first female preset when Eloquence is
active and Betty when DECtalk is active.  An exact engine identifier remains
exact and degrades visibly to the adapter default if it is not available
after a synth change.

The descriptor is returned through a function so a future adapter can discover
voices dynamically.  Current catalogues are static because the speech-server
protocol sends commands from Emacs but has no general response channel for
enumerating installed voices.

* Completion Criteria

- All generic runtime and consumer code uses =tts-= names.
- DECtalk remains functional as an engine-specific backend.
- eSpeak startup and protocol behavior remain unchanged.
- The Emacs 31 suite, semantic traces, full build, and startup smoke pass.
- Generic server configuration uses only =TTS_*= variables.
- Remaining =dtk-= names identify DECtalk itself or are explicitly historical.
- The breaking namespace and feature changes are documented.

* Completion Status

The migration completed on 2026-07-25.

- The canonical implementation is =lisp/tts-speak.el= and provides
  =tts-speak=; no generic DTK compatibility loader, aliases, functions, or
  variables remain.
- =emacsvox-loaddefs.el= remains generated by =make config= and ignored by
  Git.
- All generic Lisp consumers, launchers, shared Tcl configuration, support
  files, personal configuration examples, source manuals, generated manuals,
  and published HTML use the canonical namespace.
- Actual DECtalk backend identifiers such as =dtk-exp= and =dtk-soft= remain
  unchanged.
- =make tts-audit= reports 0 legacy Lisp files, definitions, symbols, strings,
  and active-text occurrences; a negative fixture exits with status 1.
- =make name-audit= rejects removed =emacspeak-*= APIs, =EMACSPEAK_*=
  environment names, and legacy installation paths in active tracked files,
  while preserving explicit historical and upstream-comparison material.
- The Emacs 31 suite passes 1065 of 1066 tests, with the one Mu4e dependency
  test skipped as expected, and all 27 semantic traces match.
- The complete Lisp and Info builds pass.  Info generation retains its
  pre-existing node-order warnings.
- A startup smoke test reaches a live =log-null= speech process, and launcher
  syntax and default =TTS_PROGRAM= selection pass.
- Tcl checks confirm =TTS_OS=, =TTS_PORT=, and =TTS_DEBUG= are honored and the
  removed =DTK_*= variables are ignored.
