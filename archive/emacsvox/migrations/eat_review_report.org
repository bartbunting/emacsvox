* Executive summary

This audit found that EAT itself has a capable terminal model, but the current
Emacsvox integration does not use enough of that model to provide reliable
terminal accessibility.  Its automatic output path is a deliberately small
heuristic: after any selected-buffer EAT update, speak either the character
before EAT's cursor or the whole physical line when that character is a space.
The same hook is called for process output, reset, and resize, and supplies no
reason or changed range.  As a result, speech can be present yet omit the useful
content, describe an arbitrary character or row, repeat stale content, or flood
on a refreshing display.

The most important conclusions are:

1. *A confirmed nil-cursor correctness bug can abort the update hook.*  An
   empty terminal, alternate-screen transition, and interactive ~eat-reset~
   reproduced ~wrong-type-argument number-or-marker-p nil~.  In the reset case
   this prevents the existing after-advice from announcing success.  The direct
   cause is ~((= char 32) ...)~ with ~char~ nil at
   [[file:../../../lisp/emacsvox-eat.el::270][emacsvox-eat.el:270]].
2. *Ordinary output is not reliably conveyed.*  A real Python REPL printed
   ~42~, but Emacsvox spoke only the redrawn ~>>> ~ prompt.  Multiline shell
   output likewise loses all but the cursor context.  ~less~ and Vim content
   was effectively silent; ~top~ produced noisy, arbitrary fragments.
3. *The recent unique-completion fix works for its narrow case.*  In a real
   Bash/readline PTY, ~~/sr<Tab>~ spoke ~src/~ and ~git pul<Tab>~ spoke ~pull~.
   It does not handle ambiguous lists: ~git pu<Tab><Tab>~ displayed ~pull~ and
   ~push~ in columns but spoke only the unchanged final ~u~ on each update.
4. *Completion state is timing-fragile.*  The snapshot is cleared by the first
   update.  Output split across two EAT batches, a resize-only update, or a bell
   after completion can consume state or cause duplicate fallback speech.
   Physical line-number and shell-token heuristics fail across wrapping,
   quoting, escaped spaces, and shell metacharacters.
5. *Terminal styling and focus are mostly inaudible.*  EAT represents bold,
   faint, italic, underline, inverse video, crossed-out text, colors, and
   cursor state.  Emacsvox maps only two terminal faces plus three prompt
   annotation faces.  More importantly, inverse video, underline, strike, and
   colors are normally folded into anonymous face property lists, which the
   current source-face capture does not retain semantically.  A whiptail menu
   happened to speak the selected row because EAT's cursor followed it; that is
   incidental, not robust highlight tracking.
6. *The selected-buffer guard fixed a real speech-interference problem*, but it
   is not a complete focus policy.  It suppresses terminals not in the selected
   window and also suppresses output during minibuffer use.  It cannot
   distinguish a user reviewing scrollback from one following live output, and
   its decision is made when a delayed EAT batch is processed, not when bytes
   arrived.
7. *EAT is not part of stock Emacs.*  The loaded EAT is the signed NonGNU ELPA
   0.9.4 package at release commit ~c91451f2d174~.  Upstream master is
   ~c8d54d649872~, six small commits past that tag.  The last upstream master
   commit was 2025-02-06.  Issues and pull requests remain active in 2026, but
   the maintainer says limited time and the cost of re-learning the internals
   impede non-trivial changes.  Depending on undocumented internals is
   therefore especially risky.

The recommended direction is not to speak every update.  Emacsvox should keep a
buffer-local snapshot of the visible terminal, cursor, size, alternate-screen
state, title, working directory, and normalized style runs; coalesce updates
until briefly quiescent; classify the change; and submit semantic speech with
deduplication, priorities, and application-sensitive rate limits.  EAT's
existing public getters are enough for a useful first version.  Exact
classification and reliable style/bell semantics would benefit from new,
additive public EAT events.

The smallest next patch should only make the current update hook nil-safe and
add real empty-terminal/reset regression tests.  It should not mix in the
completion redesign.

* Scope, method, and evidence vocabulary

The review was performed on 2026-08-23 (Australia/Sydney).  It was read-only
except for this report.  No source, user configuration, existing EAT buffer,
live terminal process, or Git state was changed.  Tests used fresh Emacs
processes, disposable EAT buffers, local pseudo-terminals, and temporary files.
No SSH or other external network session was opened.  Calls to speech entry
points, aural submissions, icons, and ~ding~ were captured programmatically;
results do not depend only on listening.

The report uses these evidence labels:

- *Reproduced*: a controlled local experiment produced the behavior.
- *Observed*: direct inspection of the loaded process, artifact, buffer, or
  repository established the fact.
- *Inferred*: the behavior follows from a traced code path but was not driven
  end-to-end in this environment.
- *Possible*: a plausible risk that needs a dedicated test before being called
  a defect.

“Spoken” means that a speech call or native aural transaction was submitted.  It
does not imply that the information was useful, timely, audible at the physical
device, or safe to disclose.

** Installation and provenance

EAT is a third-party package, not a library shipped with GNU Emacs.  The
installed package descriptor is signed, and ~package-archive-contents~ associates
version 0.9.4 at ~c91451f2d174~ with the ~nongnu~ archive.  Together with the
standard ~/home/bart/.emacs.d/elpa/eat-0.9.4/~ layout, this is strong evidence of
a ~package.el~ installation from NonGNU ELPA; it is not absolute proof that no
one subsequently copied files into that directory.  The official
[[https://elpa.nongnu.org/nongnu/eat.html][NonGNU ELPA package page]] lists
0.9.4 as latest and dates its tarball 2024-03-31.  The upstream release commit
itself is dated 2023-12-15.

The live server has loaded byte-code, not source, for both EAT and
~emacsvox-eat~.  The source and byte-code file timestamps are respectively
2026-07-24 for EAT and 2026-08-23 for Emacsvox.  ~make bytecode-check~ confirms
the Emacsvox byte-code matches the configured Emacs.  Source-based ERT results
below are useful behavior checks but are not, by themselves, proof that a live
server is using current compiled code.

The inspected user configuration is relevant only to line-mode completion.  It
explicitly starts Corfu at the prompt in EAT and removes Windows-mounted
directories from EAT's local ~exec-path~ for responsiveness
([[file:/home/bart/emacs/site-lisp/emacsvox-config.org::133][emacsvox-config.org:133-171]]).
It does not alter Bash/readline completion in semi-character mode.  The audit
did not modify or tangle that configuration.

* Architecture and event-flow description

** Integration history

Emacsvox EAT support began in commit
~13af80b40ec938fbe995cfc9fe0407c186165a26~ on 2023-11-14.  The update hook
arrived the next day in
~ad02970bec5981061b447c59aab28bc71cefbae4~, whose subject accurately called it
“simple, chatty.”  Commit
~d587b31acfd662c431cb76dc4eda903d4397af33~ on 2023-11-16 introduced the
preceding-character/space-line form and described it as “restored semi-working
update handler.”  The nil-character risk dates to that shape.

The advice was migrated and tests first added on 2026-07-24.  The current
selected-buffer guard and same-line completion tracking are commit
~199c853ea7f731bfb1cfec4437b517639e63029a~, dated 2026-08-23.  That recent
change correctly fixed the reported narrow completion and background-speech
cases, but its six tests deliberately do not claim general terminal output or
ambiguous completion support.

** EAT's update pipeline

#+begin_example
keyboard event
  |-- line mode: Emacs edit/CAPF -> eat-line-send-input -> PTY
  `-- semi/char mode: eat-self-input/eat-input-char -> PTY

PTY bytes -> eat--filter
          -> 8--33 ms EAT batching
          -> eat-term-process-output
          -> terminal buffer/model redisplay
          -> eat-update-hook
          -> Emacsvox selected-buffer guard
          -> completion heuristic OR char-before/physical-line heuristic
          -> mixed TTS/aural compatibility transactions
#+end_example

EAT exposes public getters for terminal bounds, visible display beginning,
cursor position/type, size, title, and alternate-display state at
[[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::4149][eat.el:4149-4247]].
It also exposes terminal parameters/callbacks at
[[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::4028][eat.el:4028-4147]].
That is enough to take stable post-update snapshots without reading the private
~eat--t-*~ structs.

The public ~eat-update-hook~ is documented only as running after a terminal is
updated ([[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::465][eat.el:465-468]]).
In both installed 0.9.4 and current upstream master, it is called from exactly
three normal-EAT paths:

| Invocation | Origin | What Emacsvox is told |
|------------+--------+------------------------|
| [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::5010][eat-reset, lines 5010-5017]] | Explicit terminal reset | No cause, old state, or changed range |
| [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::6769][output queue, lines 6769-6814]] | One batched group of process bytes | No byte/chunk boundary, reason, or changed cells |
| [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::6892][window resize, lines 6892-6911]] | Terminal resize/redisplay | Indistinguishable from output |

EAT's Eshell path instead calls ~eat-eshell-update-hook~ at
[[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::7286][eat.el:7286-7307]].
The live value of that hook is nil.

The output filter intentionally batches bytes for at least 8 ms and at most
33 ms by default
([[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::608][eat.el:608-628]] and
[[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::6816][eat.el:6816-6839]]).
The official [[https://elpa.nongnu.org/nongnu/doc/eat.html][EAT manual]]
explains that the final output chunk cannot in general be identified.  Network
delay or application flush boundaries can therefore produce several valid
updates for one logical completion, menu redraw, or command response.

** Emacsvox integration

The integration has four independent mechanisms:

1. Face-to-voice mappings for three shell-prompt annotation faces plus bold and
   italic terminal faces
   ([[file:../../../lisp/emacsvox-eat.el::62][emacsvox-eat.el:62-68]]).
2. Installation of the Emacsvox prefix key in EAT's mode maps
   ([[file:../../../lisp/emacsvox-eat.el::71][emacsvox-eat.el:71-80]]).
3. Native after-advice for two yank commands, reset/reload, mode switches, and
   opening EAT
   ([[file:../../../lisp/emacsvox-eat.el::120][emacsvox-eat.el:120-184]]).
4. Before-advice on ~eat-self-input~ to capture a Tab snapshot, and one
   ~eat-update-hook~ implementation
   ([[file:../../../lisp/emacsvox-eat.el::186][emacsvox-eat.el:186-273]]).

The quoted list at [[file:../../../lisp/emacsvox-eat.el::84][emacsvox-eat.el:84-118]]
is data, not executable advice registration.  Commands named there but absent
from ~emacsvox-eat--advice-targets~ receive no EAT-specific speech.

The current update hook:

#+begin_src emacs-lisp
(let* ((cursor (eat-term-display-cursor eat-terminal))
       (char (and cursor (char-before cursor))))
  (unless (emacsvox-eat--speak-same-line-completion cursor)
    (cond
     ((= char 32) (emacsvox-speak-line))
     (t (emacsvox-speak-this-char char)))))
#+end_src

This samples terminal state after the update; it does not describe the update.
No previous screen, previous cursor, changed range, output generation, or input
correlation is retained.

** Speech transaction behavior

The fallback mixes speech paths with different semantics:

- ~emacsvox-speak-this-char~ at
  [[file:../../../lisp/emacsvox-speak.el::1532][emacsvox-speak.el:1532]] sends character
  feedback without an EAT-specific role or deduplication key.
- ~emacsvox-speak-line~ at
  [[file:../../../lisp/emacsvox-speak.el::1291][emacsvox-speak.el:1291]] goes through
  native source capture and a navigation occasion, which is replaceable.
- Completion calls bare ~tts-speak~ at
  [[file:../../../lisp/emacsvox-eat.el::244][emacsvox-eat.el:244]].  Its default occasion
  is continuous
  ([[file:../../../lisp/tts-speak.el::2816][tts-speak.el:2816-2832]]), while the
  compatibility delivery path normally stops current speech because
  ~tts-stop-immediately~ defaults to true
  ([[file:../../../lisp/tts-speak.el::1790][tts-speak.el:1790-1793]] and
  [[file:../../../lisp/tts-speak.el::2891][tts-speak.el:2891-2905]]).

Consequently, a rapid sequence may combine queued characters, replaceable
navigation lines, and hard-interrupting completions.  It has no common terminal
generation, semantic role, priority, or replacement key.  Captured tests
confirmed ordering and duplication; physical audibility remains dependent on
the speech server and device.

** F-01: nil terminal cursor aborts the update path

- *Severity / impact:* High correctness and accessibility severity.  A valid
  empty terminal update signals an error; interactive reset can fail before its
  completion announcement.
- *Evidence status:* Reproduced in isolated EAT terminals for an initially empty
  display, alternate-screen entry, and ~eat-reset~.
- *Reproduction and evidence:* Create an isolated terminal with
  ~eat-term-make~, select its buffer, capture speech calls, and run
  ~emacsvox-eat-update-hook~ before inserting a cell.  The result is
  ~wrong-type-argument number-or-marker-p nil~.  Calling interactive
  ~eat-reset~ on the same terminal reaches EAT's update hook at
  [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::5010][eat.el:5010-5017]]
  and produces the same error, so the after-advice at
  [[file:../../../lisp/emacsvox-eat.el::140][emacsvox-eat.el:140-143]] does not run.
- *Exact cause:* ~cursor~ can be nil, so ~char~ is nil at
  [[file:../../../lisp/emacsvox-eat.el::265][emacsvox-eat.el:265-267]], but
  [[file:../../../lisp/emacsvox-eat.el::270][line 270]] calls numeric ~=~ on it.
- *Upstream relevance:* EAT's public cursor getter is behaving within the state
  observed during an empty display; this integration must tolerate nil.  The
  getter was made public following
  [[https://codeberg.org/akib/emacs-eat/issues/90][EAT issue 90]].
- *Recommended remedy:* Guard ~char~ before comparison and produce no automatic
  speech for an empty update.  Keep reset's explicit state-change announcement.
- *Regression tests required:* Real empty ~eat-term-make~ buffer; direct update;
  interactive reset; empty alternate-screen enter/exit; cursor at terminal
  beginning; no speech and no error.  Run against compiled code in a fresh
  Emacs as well as source ERT.
- *Compatibility risk:* Low.  The change only suppresses invalid nil-character
  feedback and lets existing advice complete.

** F-02: meaningful multiline output is lost

- *Severity / impact:* High.  Command results, errors, REPL values, and help can
  be completely missed even while a prompt is spoken.
- *Evidence status:* Reproduced with real Bash/readline, Python 3.14 REPL,
  multiline fixtures, router-style help, and candidate displays.
- *Reproduction and evidence:* In an isolated Bash EAT, start Python and submit
  ~print(6 * 7)~.  The terminal displayed ~42~ followed by ~>>> ~; captured

  had the same last-cursor-context behavior.
- *Exact references:* The sole automatic path reads only
  ~char-before cursor~ and at most ~emacsvox-speak-line~
  ([[file:../../../lisp/emacsvox-eat.el::261][emacsvox-eat.el:261-271]]).  It never
  records EAT's display bounds or previous contents, although public getters
  exist at

  batches, classify prompt redraw separately, and speak bounded complete new

** F-03: cursor-driven and refreshing applications produce misleading or
disruptive speech

- *Severity / impact:* High for interactive terminal use.  Navigation may be
  silent, while high-frequency applications can repeatedly interrupt useful
  speech with arbitrary fragments.
- *Evidence status:* Reproduced with ~less~, Vim, ~top~, carriage-return
  progress, direct cursor-motion/style fixtures, and whiptail.
- *Reproduction and evidence:* ~top -d 0.2~ generated six captured feedback
  events in roughly one second, including newline, isolated ~d~ and ~+~, and an

- *Exact references:* All update types converge on
  [[file:../../../lisp/emacsvox-eat.el::261][emacsvox-eat.el:261-271]].  EAT's output
  batching is only 8--33 ms
  ([[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::608][eat.el:608-628]]),

- *Root cause:* There is no screen diff, cursor-delta classification,
  repaint suppression, rate limiter, or replaceable TUI/progress transaction.
- *Recommended remedy:* Introduce a classifier and distinct policies for

- *Regression tests required:* Fixed-rate full repaint; cursor-only row change;

** F-04: ambiguous completion displays candidates but speaks no candidates

- *Severity / impact:* High for shell, SSH, and router workflows.  A blind user
  cannot choose among visible alternatives.
- *Evidence status:* Reproduced with Bash/readline columns, a 200-candidate
  fixture, and router-like candidate/help output.
- *Reproduction and evidence:* At a deterministic Bash prompt, type
  ~git pu<Tab><Tab>~.  The terminal shows:

  #+begin_example
  AUDIT> git pu
  pull   push
  AUDIT> git pu
  #+end_example

  Captured events are the unchanged character ~u~ for each Tab.  The first Tab
  also rings the terminal bell.  A 200-item, 32-line/3037-character fixture
  likewise yielded only the final prompt character.  Router-style
  ~route  routing-table~ columns and ~?~-help descriptions were silent except
  for the redrawn prompt.
- *Exact references:* The implementation explicitly rejects another physical
  line at [[file:../../../lisp/emacsvox-eat.el::229][emacsvox-eat.el:229-245]].  The

  [[file:../../../test/emacsvox-eat-tests.el::68][emacsvox-eat-tests.el:68-90]].
- *Root cause:* The code recognizes only strict same-line token growth and
  immediately discards its snapshot.  It assumes ordinary fallback will make a
  candidate display accessible, but F-02 disproves that assumption.
- *Recommended remedy:* Use a pre-Tab screen snapshot and post-quiescence
  screen diff.  Extract the newly inserted rows between the old prompt and
  redrawn prompt without assuming shell grammar; preserve row/column text and

- *Regression tests required:* Single/double Tab; no common prefix; columns;
  descriptions; small/large lists; duplicate Tab; bell before/in/after list;
  remote-like delay and chunking; prompt without shell integration.
- *Compatibility risk:* Medium.  Screen layouts are unstructured.  Extraction
  must fail closed to “N changed lines; review candidates” rather than invent

** F-05: the completion snapshot is consumed by the first unrelated or partial
update

- *Severity / impact:* Medium-high.  Valid completion is intermittently silent
  under load, remote latency, bells, and resize.
- *Evidence status:* Reproduced with split terminal updates and a resize-only
  update; inferred for equivalent remote chunk boundaries.
- *Reproduction and evidence:* Capture ~~/sr~ before Tab, deliver an update that
  leaves the token unchanged, then deliver the expansion to ~~/src/~.  Events
  are the old ~r~ then slash, never ~src/~.  Replacing the first update with a
  terminal resize gives the same result.  Completion and BEL in one batch
  produced bell then ~src/~; a later separate BEL produced completion, bell,
  then duplicate slash fallback.
- *Exact references:* The snapshot is set at
  [[file:../../../lisp/emacsvox-eat.el::203][emacsvox-eat.el:203-218]] and unconditionally
  cleared before determining whether the update completes the transaction at
  [[file:../../../lisp/emacsvox-eat.el::234][emacsvox-eat.el:234-245]].  EAT explicitly
  batches arbitrary process chunks at
  [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::6816][eat.el:6816-6839]]

  [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::6892][eat.el:6892-6911]].

- *Regression tests required:* Every byte split; empty first batch; resize;

** F-06: token and physical-line parsing is not shell-safe

- *Severity / impact:* Medium.  Feedback becomes verbose, incomplete, or wrong
  for normal filenames and wrapped prompts.
- *Evidence status:* Reproduced against the pure parser and real Bash
  programmable/file completion.
- *Reproduction and evidence:*

  [[file:../../../lisp/emacsvox-eat.el::193][emacsvox-eat.el:193-201]]; snapshot identity

  [[file:../../../lisp/emacsvox-eat.el::203][lines 203-208]]; matching requires longer

* Completion and multi-candidate analysis

** What completion mechanism is active in each EAT mode

In *line mode*, EAT binds Tab to Emacs ~completion-at-point~ and installs shell
completion variables
([[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::5813][eat.el:5813-5833]] and
[[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::6700][eat.el:6700-6702]]).
The inspected live buffer has Corfu and
~(comint-completion-at-point t)~.  This completes local Emacs-known commands and
files.  It does *not* invoke Bash programmable completion, remote-host
completion, or a router CLI's ~?~/Tab behavior.  Emacsvox's Corfu integration is
substantially richer: it submits semantic candidate facts, counts, annotations,
selection/acceptance events, and deduplicated navigation at
[[file:../../../lisp/emacsvox-corfu.el::182][emacsvox-corfu.el:182-249]] and
[[file:../../../lisp/emacsvox-corfu.el::277][emacsvox-corfu.el:277-459]].

In *semi-character and character modes*, Tab is sent through the PTY.  The
underlying program owns completion.  Bash/readline can therefore provide
~git pull~, SSH can use the remote shell's completion, and a router can render
its native alternatives/help.  Corfu cannot see a structured candidate list in
that path.  Emacsvox must interpret the terminal screen rather than pretending
that Bash or the remote device supplied an API.

In *Emacs mode*, the terminal is read-only and keys are Emacs commands; there is
no terminal-side completion until the user switches mode.

The user's Bash startup file loads Bash completion, so ~git pul<Tab>~ can work
in a normal Bash.  EAT's separate shell integration is not required for
readline completion; it supplies CWD tracking, prompt navigation/status,
history, and optional mode switching.  EAT 0.9.4 officially supports that
integration for Bash and Zsh, not arbitrary router shells.  The package exports
~EAT_SHELL_INTEGRATION_DIR~ to children at
[[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::6963][eat.el:6963-6972]], but
the child shell must source the appropriate script.

** Safety of the current implementation

- *Token parsing:* Not safe as a semantic shell word parser.  It is acceptable
  only as a best-effort label for a strict, already-confirmed screen change.
- *Line-number tracking:* Not safe.  Numeric buffer lines change with scrollback
  growth, EAT's wrap representation, and terminal reflow.  ~line-number-at-pos~
  also scans from the accessible beginning; with EAT's default bounded
  scrollback this is usually tolerable but avoidable work on every Tab/update.
- *Output timing:* Not safe.  EAT's batch is a visual latency window, not
  logical completion quiescence.  Remote and router output makes split batches
  more likely.
- *Snapshot clearing:* Not safe.  First-update consumption loses valid
  completions; longer retention without a generation and timeout would create
  stale false positives.
- *Nil cursor:* Unsafe independently of completion (F-01).
- *Bash dependence:* The unique algorithm does not directly call Bash, but its
  word assumptions resemble a small subset of shell syntax.  Dash proves that
  the terminal peer may not complete at all; routers may print help rather than
  insert text.

** Recommended ambiguous-completion transaction

1. On terminal-side Tab, capture a bounded public snapshot: visible text,
   normalized style runs, cursor row/column, width/height, alternate-screen
   state, process generation, and time.  Also retain the logical displayed input
   rows, without parsing them as Bash.
2. Mark the interaction pending and restart a short Emacsvox quiescence timer
   after every compatible EAT update.  A practical initial window is 40--75 ms,
   with an absolute cap near 250 ms; these values need PTY/remote-delay tests.
3. At quiescence, compare old and new screens:
   - If only the input was extended, speak the smallest unambiguous meaningful
     suffix or resulting logical input.
   - If rows appeared and the prompt/input was redrawn, retain those rows as a
     candidate/help presentation.
   - If the layout cannot be classified, announce a bounded changed-line count
     and make it manually reviewable instead of fabricating candidates.
4. Preserve rows and descriptions.  Column splitting may be offered as a
   convenience only when spacing is consistent; router output such as
   ~show — Display system information~ is a row with description, not two
   unrelated candidates.
5. For a small list (a configurable default such as at most 8), announce the
   count and all items.  For a larger list, announce total item/row count,
   speak the first configurable subset, say that it was truncated, and retain
   the full snapshot for review.  Impose character and row caps before speech.
6. Deduplicate repeated Tab against the retained normalized snapshot.  A repeat
   can say “same 27 candidates” or open/revisit review depending on verbosity.
7. Clear the transaction on non-Tab terminal input, reset/reload, process
   generation change, exit, hard timeout, or buffer destruction.  A resize
   should update coordinates and restart quiescence, not silently consume it.

This design works for local Bash, delayed SSH, and router CLIs because its input
is the terminal presentation.  Where line mode/Corfu supplies structured
candidates, Emacsvox should continue using the Corfu semantic path instead of
screen inference.

* EAT update-model audit

** What an update can mean

An ~eat-update-hook~ call after process bytes may contain any combination of:

- newly printed text;
- deletion or carriage-return replacement;
- cursor-only CSI movement;
- full or partial repaint;
- text with changed styling but equal characters;
- screen clear/scroll;
- alternate-screen entry or exit;
- title, CWD, cursor visibility/style, mouse, or selection control;
- bell;
- one fragment of a longer asynchronous response.

Reset and resize call the same hook independently.  EAT does not pass the raw
output, cause, old/new cursor, changed cells, or flags.  A post-hook observer can
infer differences but cannot know with certainty whether equal final state came
from output, repaint, resize, or reset.

EAT's terminal model is more expressive than its notification.  Its upstream
~eat-tests.el~ contains 57 ERT tests with extensive parser coverage for cursor
motion, scrolling, resizing, SGR colors/styles, alternate display, and bell.
It does not test ~eat-update-hook~ causality, real PTY batching, shell
completion, background selection, speech, or interactive application policy.
That is not a criticism of the parser suite; it explains why Emacsvox needs its
own integration layers.

** Selected-buffer guard scenarios

| Scenario | Current result | Evaluation |
|----------+----------------+------------|
| Another ordinary buffer selected | Silent and clears completion | Correct safe default |
| Minibuffer active | EAT buffer not selected, so silent | Correctly prevents shell prompt leaking into minibuffer speech |
| Two windows show same EAT buffer | Speaks if the selected window shows it | Reasonable, but no per-window follow state |
| EAT merely visible in another window | Silent | Correct default |
| EAT visible on another frame | Normally silent unless its window is globally selected; actual OS frame focus is not checked | Possible daemon/window-system mismatch |
| User reviews EAT scrollback in selected window | Guard passes even when window point is not live cursor | Inferred interference defect |
| Output arrives, then focus changes before EAT timer runs | Decision uses focus at processing time | Can silence formerly foreground output or speak output that arrived before selection |
| Rapid buffer/minibuffer change during Emacsvox quiescence | No current quiescence; future design must recheck | Must preserve privacy at presentation time |

The right rule is two-stage: capture source/focus metadata when observing, then
recheck authorization and relevance immediately before speaking.  A terminal
must be selected and following live output for automatic foreground output.
Background monitoring should be an explicit per-buffer option with a separate,
rate-limited policy.

** Dependence on EAT internals

The current production integration declares and reads private
~eat--semi-char-mode~ at
[[file:../../../lisp/emacsvox-eat.el::50][emacsvox-eat.el:50]] and
[[file:../../../lisp/emacsvox-eat.el::214][line 214]].  That is the only material private
dependency in the recent completion change.  EAT offers interactive mode
commands but no stable mode predicate/hook; upstream
[[https://codeberg.org/akib/emacs-eat/issues/158][issue 158]] requests public
mode hooks.

The proposed Emacsvox screen observer does not need ~eat--t-cur~,
~eat--t-disp~, ~eat--t-face~, or ~eat--t-term~.  It should use public bounds,
cursor, size, title, alternate-screen state, and buffer text properties.  Reading
private wrap or prompt properties may improve heuristics, but should be kept in
small optional adapters with feature/version tests, not made architectural.

** Interpretation

The whiptail result is useful evidence but not a success criterion.  Its menu
places EAT's terminal cursor on the selected row even though the cursor type is
~:invisible~; the current “character before cursor/line on space” rule therefore
happened to select the right row.  Other curses applications keep a hidden
cursor at a fixed location, highlight several regions, or use a status row.
Vim and less demonstrate those counterexamples.

The refreshing-display result is also not solved by merely increasing EAT's
latency.  Visual batching at 33 ms would still permit about 30 speech decisions
per second.  Accessibility needs semantic coalescing: unchanged repaints
produce nothing, cursor navigation replaces prior navigation speech, progress
uses thresholds and a minimum interval, and a full-screen refresh yields at
most a concise status summary unless explicitly reviewed.

* Highlight and focus-tracking analysis

** What EAT represents

EAT's parser maintains private cursor, display, face, and terminal structures,
then materializes terminal cells as Emacs buffer text with faces and private
layout properties.  Publicly, Emacsvox can obtain:

- visible display bounds and terminal bounds;
- display cursor position and cursor type;
- width/height;
- title and alternate-display state;
- final buffer text and text properties.

At [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::2504][eat.el:2504-2706]],
EAT recognizes foreground/background colors, inverse video, bold, faint,
italic, underline variants/color, slow/fast blink, conceal, crossed-out text,
and alternate fonts.  In observed buffer properties:

| Italic | named inherited ~eat-term-italic~ | Mapped to ~voice-smoothen~ |
| Faint | named inherited ~eat-term-faint~ | No EAT voice map |
| Blink | named slow/fast face; optional timers remap it | No EAT voice map; timer changes have no update hook |
| Underline | anonymous ~:underline~ plist | Semantic attribute lost by named-face capture |
| Inverse video | foreground/background swapped into anonymous plist | Cannot be identified simply as “inverse” afterward |
| Crossed-out | anonymous ~:strike-through t~ | Not voiced |
| Foreground/background colors | literal resolved colors/anonymous plist | Not semantically voiced |
| Conceal | rendered using background relationship | Must not be automatically disclosed as visible text |

| Hyperlink OSC 8 | EAT 0.9.4 displayed plain text with nil link properties | No link semantics |

[[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::4818][eat.el:4818-4907]]
without running ~eat-update-hook~.  This is appropriate—speech should not follow
visual blink frames—but confirms that “every visual style change causes an
update” is false.  EAT disables blink presentation by default and its manual
explicitly discusses the accessibility concern.

** What can and cannot identify an active item

- *Terminal cursor:* Strong evidence when it moves with recent Up/Down/Tab
  input and lands on a compact changed row.  It is not sufficient: the cursor
  can be invisible, fixed in an input field, off by one due application or
  rendering behavior, or unrelated to a mouse/highlight selection.
- *Inverse video:* Useful evidence only when a small region gains it while a
  previous nearby region loses it.  It is not sufficient: headers, status bars,
  buttons, search matches, and entire panes may all be inverse.
- *Background-color change:* Similar evidence to inverse, particularly for
  whiptail, but theme resolution and application palettes make absolute colors
  unreliable.
- *Bold/underline/face differences:* Supporting evidence for controls,
  highlights, links, and matches, never sufficient alone.
- *Screen difference:* Identifies what changed but not why.  A full redraw can
  reproduce every cell without changing semantic focus.
- *Private EAT model:* Contains richer pre-render attributes, but directly using
  ~eat--t-face~ or ~eat--t-disp~ would couple Emacsvox to unstable internals and
  still would not reveal application semantics.

** Robust probabilistic focus design

Normalize each visible row into text plus style runs.  A style signature should
retain semantic categories where recoverable (bold, faint, italic, underline,
strike, inverse-like foreground/background swap, conspicuous background,
conceal, link) without treating literal theme colors as stable identities.

For every quiesced navigation generation, score compact candidate regions:

1. region newly gained a selection-like style;
2. a nearby old region simultaneously lost that style;
3. public cursor is within or adjacent to the region;
4. cursor moved in the direction implied by the recent input;
5. change happened promptly after a navigation key;
6. region is one/few rows, not a whole pane;
7. text differs from static borders, headings, or persistent status rows;
8. the same application pattern was consistent in recent generations.

Penalize or reject large inverse areas, unchanged persistent headers, multiple
unrelated highlights, and changes during an uncorrelated refresh.  Require a
confidence threshold.  Below it, say “screen changed” at verbose settings or
remain silent and let the user invoke review.  A less search match can be
announced as a *changed highlight near the cursor*, not asserted to be a menu
selection.  This explicitly avoids the false rule “inverse video means focus.”

The retained focus object should include text, row/column bounds, style facts,
confidence, terminal generation, and screen generation.  Navigation speech
should be replaceable and deduplicated by that identity.

- *Severity / user impact:* Medium-high design gap; blocks reliable menu and
  search navigation.
- *Evidence status:* Reproduced inputs plus inferred design; the proposed score
  itself remains unvalidated.
- *References:* EAT SGR composition
  [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::2504][eat.el:2504-2706]],
  public cursor API
  [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::4149][eat.el:4149-4198]],
  upstream cursor/highlight
  [[https://codeberg.org/akib/emacs-eat/issues/248][issue 248]].
- *Root cause:* No previous style snapshot or input correlation exists in
  Emacsvox; EAT offers no public changed-style event.
- *Recommended remedy:* Implement conservative scoring from public snapshots;
  seek an upstream normalized changed-cell/style API for precision.
- *Regression tests:* Static inverse header; whiptail selection; less match;
  invisible/fixed cursor; two highlights; style-only move; theme change; resize.
- *Compatibility risk:* High if treated as certainty.  Expose confidence,

* Security and privacy risks

Terminal accessibility observes an untrusted byte stream and may verbalize
information outside the visual user's current attention.  The design must
therefore treat privacy and denial-of-speech as first-class policy.

** S-01: password input can enter Emacs command lossage

- *Severity / impact:* Medium confidentiality risk.
- *Evidence status:* Observed in official documentation; no password was entered
  during this audit.
- *Evidence and references:* The installed manual warns that ordinary terminal
  keystrokes are recorded in Emacs lossage and recommends the password command
  at [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.texi::459][eat.texi:459]].
  The real command is ~eat-send-password~ at
  [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::5752][eat.el:5752-5758]].
  Installed 0.9.4's manual uses the wrong name; upstream fixed it on 2024-03-15
  in [[https://codeberg.org/akib/emacs-eat/commit/25989bf714dd][25989bf714dd]].
- *Root cause:* Semi/character input is an Emacs command event before it is PTY
  input.
- *Recommended remedy:* Document and make ~eat-send-password~ easy to invoke;
  announce entry/exit of its secure minibuffer without speaking content.  Do
  not automatically echo no-echo terminal input.
- *Regression tests:* Stub ~read-passwd~; verify only a secure-input fact/icon,
  never secret text; verify snapshots are cleared at the boundary.
- *Compatibility risk:* Low if implemented as additive advice/documentation.

** S-02: future snapshots could retain or disclose secrets

- *Severity / impact:* High if implemented carelessly; currently only a
  possible design risk because the existing snapshot retains a short token.
- *Evidence status:* Possible.
- *References:* Current buffer-local completion state is defined at
  [[file:../../../lisp/emacsvox-eat.el::186][emacsvox-eat.el:186-187]].
- *Root cause:* Screen snapshots necessarily include terminal text, which may
  contain passwords, tokens, private paths, router configuration, or pasted
  secrets.
- *Recommended remedy:* Keep snapshots buffer-local, bounded, ephemeral, and
  never serialized into messages, traces, history, crash reports, or debug logs
  by default.  Release references on timeout, no-echo/secure input, process
  generation change, and buffer death; overwrite mutable copies where feasible
  but do not promise memory zeroization in Emacs Lisp.  Manual candidate review
  should copy only explicitly classified completion rows.
- *Regression tests:* Secret sentinel strings never reach speech/log/history;
  reset/exit/timeouts clear state; large buffers remain bounded.
- *Compatibility risk:* Low for data minimization; debugging becomes less
  convenient and should require explicit redacted opt-in.

** S-03: untrusted output can hijack or deny speech

- *Severity / impact:* Medium-high availability/social-engineering risk.
- *Evidence status:* Reproduced for speech flooding with ~top~; auditory
  spoofing is inferred.
- *References:* The unclassified speech path is
  [[file:../../../lisp/emacsvox-eat.el::261][emacsvox-eat.el:261-271]] and the hard-stop
  compatibility behavior is
  [[file:../../../lisp/tts-speak.el::2891][tts-speak.el:2891-2905]].
- *Root cause:* Arbitrary terminal output can trigger high-priority-looking
  speech and repeatedly interrupt other modules; it has no terminal source role
  or rate budget.
- *Recommended remedy:* Label every submission ~:module 'eat~ with terminal
  buffer/process identity, use a distinct terminal voice/earcon, sanitize
  nonprinting content, cap text/rate, and never allow routine refresh output to
  interrupt urgent desktop speech.  Terminal text must not be treated as a
  trusted Emacs message.
- *Regression tests:* Hostile rapid repaint, very long line, control
  characters, text mimicking security prompts, output during minibuffer and
  urgent speech.
- *Compatibility risk:* Medium; overly strict rate limiting can suppress real
  errors, so retain manual review and an explicit verbose monitor.

** S-04: EAT accepts terminal-controlled selection and UI metadata

- *Severity / impact:* Medium upstream trust-boundary concern, not a confirmed
  Emacsvox defect.
- *Evidence status:* Observed statically.
- *Evidence and references:* ~eat-enable-kill-from-terminal~ defaults true,
  allowing OSC 52 to set Emacs selection/kill data; terminal read-back is
  disabled by default through ~eat-enable-yank-to-terminal~
  ([[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::138][eat.el:138-155]] and
  [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::5048][eat.el:5048-5069]]).

  [[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::3674][eat.el:3674-3704]].
- *Root cause:* These are intentional terminal features crossing the child
  process/Emacs boundary.
- *Recommended remedy:* Document the settings for untrusted SSH/router use.
  Emacsvox should not speak clipboard contents or execute/interpret UIC payloads
  as accessibility commands.  Title/CWD announcements must be low-priority,
  sanitized metadata.
- *Regression tests:* OSC 52 set/query under both settings; hostile title/CWD;
  UIC ignored/allowed configurations; no clipboard speech.
- *Compatibility risk:* Changing EAT defaults belongs upstream/user policy and
  may break workflows; Emacsvox should not silently change them.

* Recommended Emacsvox architecture

** Three layers

1. *Observer:* On normal EAT and EAT-Eshell updates, capture only the public
   visible terminal state plus normalized buffer properties.  Observe
   exec/exit, input intent, reset/reload, and callbacks.  Never speak directly
   from this layer.
2. *Classifier:* Compare snapshots and recent input to produce semantic facts:
   typed echo, unique completion, candidate/help rows, new output lines,
   cursor-only navigation, likely focus/highlight, status/progress, repaint,
   resize, alternate-screen/lifecycle, bell, title/CWD, or unknown change.
3. *Presenter:* Apply selection/privacy, verbosity, deduplication, coalescing,
   truncation, priority, and interruption policy; submit through
   ~emacsvox-aural-submit~ with ~:module 'eat~ and stable roles/events.

This isolates uncertain terminal inference from speech delivery and makes each
piece testable.  The current Corfu implementation demonstrates the target
pattern: candidate facts and lifecycle are separate from presentation at
[[file:../../../lisp/emacsvox-corfu.el::182][emacsvox-corfu.el:182-215]].

** Buffer-local state

Keep one bounded state object per EAT terminal:

- terminal/process generation and lifecycle state;
- previous visible text as logical rows, screen width/height, display bounds;
- normalized style runs/signatures;
- public cursor row/column/type;
- alternate-screen state, title, and CWD;
- recent input event/category/time, never raw secure input;
- pending completion transaction and retained candidate/help snapshot;
- last changed region and likely focus object;
- quiescence timer and hard deadline;
- per-role last presentation key/time and rate budget;
- foreground/follow-live/monitoring and verbosity policy.

Markers should not be retained where EAT's public docs say callers should query
positions afresh
([[file:/home/bart/.emacs.d/elpa/eat-0.9.4/eat.el::4166][eat.el:4166-4182]]).
Store row/column/generation identifiers, then resolve against a fresh snapshot.

** Quiescence and generation rules

EAT should remain visually responsive at its own 8--33 ms latency.  Emacsvox
should independently restart a speech timer after related updates.  Start with
40--75 ms idle and a 250 ms absolute cap, then tune from PTY fixtures.  A
generation closes on:

- non-compatible user input;
- process exec/exit;
- reset/reload;
- buffer death;
- hard timeout;
- alternate-screen transition when the pending interaction cannot span it.

Resize changes geometry but should not itself produce content speech.  It may
force re-snapshot/reflow before classification.  Every pending presentation
must recheck selected/follow state and privacy just before submission.

** Coherent speech policy

| Event class | Default policy | Delivery/interruption | Dedup/rate behavior |
|-------------+----------------+-----------------------+---------------------|
| Typed printable echo | Speak only when correlated echoed cells confirm recent input | Edit occasion; short, replace/queue according to existing echo policy | Suppress duplicate PTY echo when line mode already spoke insertion |
| No-echo/password input | Announce secure input state, never characters | High-confidence state-change, no content | Clear snapshots; never retain raw key |
| Unique completion | Speak concise resulting component/suffix, preserving punctuation | State-change, ordered after relevant typed echo | One per completion generation; same result on repeated Tab suppressed |
| Ambiguous small list | “N candidates” plus bounded rows/items and descriptions | State-change/list; should not hard-stop unrelated urgent speech | Deduplicate normalized list; configurable maximum |
| Ambiguous large list | Count, first N, “truncated; use review command” | Concise state-change | Hard row/character cap; repeated Tab says same count |
| New ordinary output | Speak complete new/changed logical lines, excluding a pure redrawn prompt | Ordered terminal-output batch | Coalesce chunks; cap lines/chars; retain full changed region for review |
| Cursor/focus navigation | Speak current row/control or character with direction/focus facts | Replaceable navigation | Replace earlier navigation in same terminal; boundary cue on no movement |
| Likely highlight | Speak text plus cautious role (“highlight” unless confidence supports selection) | Replaceable navigation | Identity is region/text/style/screen generation |
| Status line | Speak only on meaningful text change or explicit command | Low-priority replaceable status | Minimum interval and equality/threshold filtering |
| Progress/CR rewrite | Extract changing value where conservative; otherwise periodic “progress updated” | Replaceable progress | Percentage thresholds or minimum 1--2 s interval; always announce completion/failure |
| Full repaint | Normally silent if semantic text/style/cursor unchanged | None | Hash rows/styles; rate-limit uncertain summaries |
| Alternate screen/app entry | Concise “alternate screen” or inferred app title at normal/verbose level | State-change | Once per transition |
| Exit/return to shell | Process/app exited plus status when known; then prompt if useful | State-change, higher than routine output | Once per process generation |
| Bell | Earcon/urgent fact; speak “bell” only by verbosity policy | Urgent, but do not automatically replay prompt | Deduplicate burst within short interval |
| Title/CWD | Silent by default; announce relevant changes in verbose/monitor mode | Low-priority metadata | Equality and rate limit |
| Background terminal | Silent by default; optional “terminal X has output”/exit count | Separate monitoring occasion; never include content unless explicitly enabled | Per-buffer debounce and unread count |
| Unknown screen change | Silent at terse level; concise changed-row count at verbose level | Low priority | Retain for manual review |

Punctuation and voices must be preserved by submitting prepared text/facts, not
flattening everything through ~message~ or ad hoc raw ~tts-speak~.  Terminal
content needs its own source voice so that a malicious line cannot sound like
trusted editor UI.  Candidate annotations, status, and counts should use
different personalities exactly as the Corfu path does.

** Verbosity

Offer at least three per-terminal or global modes:

- *Terse:* typed echo, unique completion, focused navigation, bell, process
  lifecycle; large output summarized.
- *Normal:* bounded new output, small candidate lists, focus/status changes,
  alternate-screen transitions.
- *Verbose/monitor:* more changed rows, candidate descriptions, title/CWD and
  uncertain change summaries, still rate-limited.

A fourth “automatic output off” toggle can leave typed echo and explicit review
available.  These settings should be buffer-local with a global default.

** Manual review commands

The automatic policy can never infer every TUI correctly.  Provide stable
commands on the Emacsvox prefix:

- speak terminal row at EAT's cursor;
- speak the last changed region;
- speak the likely active/highlighted item and confidence/role;
- speak/review the retained completion candidate/help list;
- enter a terminal-screen review mode and move by logical row;
- jump between changed rows or styled regions;
- speak status/title/CWD/process state;
- toggle automatic output monitoring for this terminal;
- cycle terminal verbosity;
- repeat the last terminal announcement without recomputing it.

Screen review should use a frozen snapshot by default so a repaint cannot move
content under the reviewer.  It should offer an explicit refresh command and
announce when the live terminal has changed since the snapshot.

** Ownership: Emacsvox versus EAT

| Work | Owner | Reason |
|------+-------+--------|
| Nil-safe update hook and tests | Emacsvox | Direct integration defect |
| Screen snapshots/diffs, completion inference, quiescence | Emacsvox | Can be built from current public API and is speech-policy-specific |
| Aural facts, priorities, voices, interruption, dedup/rate limits | Emacsvox | Accessibility presentation responsibility |
| Manual review UI and verbosity/monitoring commands | Emacsvox | User-facing speech feature |
| Exec/exit and alternate-state use | Emacsvox | Public EAT hooks/getter already sufficient |
| Normalized rendered face-property adapter | Emacsvox initially | Enables progress without upstream dependency |
| Public mode getter/hooks | EAT | Avoids ~eat--semi-char-mode~ dependency; broadly useful |
| Structured update cause/dirty text/style/cursor ranges | EAT | EAT alone knows precise parser/model mutations efficiently |
| Additive bell/title/CWD/alt events | EAT | Avoids replacing single callback slots and duplicated inference |
| Semantic prompt API/OSC 133 | EAT and shells | Transport/model semantics, not speech-specific |
| Remote TERM/terminfo and terminal emulation bugs | EAT | Transport/parser correctness |

* Phased roadmap

** Immediate low-risk fixes

1. Fix F-01 only: make nil cursor/character a quiet no-op, and add real
   empty-terminal/reset/alternate-screen ERT.
2. Add public exec/exit observation and clear all completion state on process
   generation changes; announce exit without parsing terminal output.
3. Add an explicit bell aural fact while preventing the same no-change update
   from replaying prompt/character.  If callback wrapping is judged too fragile,
   defer until an upstream hook rather than replacing behavior.
4. Replace raw mode command symbols with human labels.
5. Document the distinction between line-mode Corfu completion, Bash/readline
   completion, and EAT Bash/Zsh shell integration.  Do not silently edit the
   user's shell startup file.

Risks are low except callback wrapping.  Each patch should be separate and
compiled with the configured Emacs.

** Medium-sized improvements

1. Introduce public-state visible-screen snapshots and pure text/style diffing.
2. Replace one-update completion tracking with a generation/quiescence
   transaction, including ambiguous rows, count/truncation, and review command.
3. Present bounded multiline shell/REPL output while suppressing pure prompt
   redraw and resize-only events.
4. Add explicit selected/follow-live state and optional background monitoring.
5. Add process/alternate-screen lifecycle and title/CWD state comparison.
6. Wire EAT-Eshell through the shared observer only after duplicate Eshell
   speech tests pass.
7. Move all EAT speech to semantic native aural submissions.

Risks are moderate: output verbosity, stale-state retention, and false
candidate extraction.  Ship behind conservative defaults and measure captured
transactions, not only buffer diffs.

** Larger structural work

1. Develop highlight/focus scoring and TUI navigation policy from deterministic
   fixtures, then validate against less, Vim/nano, menus, and refreshing apps.
2. Add progress/status classification, per-role rate budgets, and frozen screen
   review.
3. Work upstream on structured update records, dirty/style ranges, public mode
   hooks, additive callbacks, and semantic prompts.
4. Add optional application profiles only where generic evidence remains
   insufficient.  Profiles must refine, not replace, the generic model.
5. Add hyperlink semantics when EAT supports OSC 8 and a policy for
   images/Sixel regions.

Risks are higher because terminal applications are not semantically
standardized.  Confidence thresholds, manual review, privacy caps, and
versioned fixtures are non-negotiable.

* Detailed automated and manual test plan

** Assessment of current tests

[[file:../../../test/emacsvox-eat-tests.el::1][test/emacsvox-eat-tests.el]] contains six
ERT tests:

1. advice inventory;
2. target-aware yank feedback;
3. mode feedback;
4. same-line directory completion;
5. multiline completion falling back to slash;
6. background update silence.

They are fast and useful regression tests for commit ~199c853ea~, but all
terminal state is mocked with a symbol and a point marker.  They do not create
an EAT terminal, parse terminal bytes, run a PTY, wait for output batching, or
exercise native aural facts/delivery.  The multiline test explicitly codifies
the inaccessible result rather than testing candidates.  There is no nil
cursor, reset, resize, exit, alternate screen, style, bell, title/CWD,
chunk-split, wrap, Unicode, shell, or interactive-app coverage.

The test file explicitly loads source at
[[file:../../../test/emacsvox-eat-tests.el::8][emacsvox-eat-tests.el:8-10]].  Six passing
tests therefore do not prove the live ~emacsvox-eat.elc~ is current.  The
project's byte-code checks and a fresh compiled Emacs verification are separate
required layers.

Upstream EAT master has 57 terminal-model ERT tests.  They deeply exercise many
escape-sequence and SGR behaviors, cursor position, resize, alternate display,
and bell.  They do not replace Emacsvox integration tests because they do not
cover EAT's update-hook timing, PTY shell behavior, focus, speech, or policy.

** Layer 1: pure unit tests

Keep these independent of EAT and TTS processes:

- logical screen snapshot and row normalization;
- text and style-run diff under insertion, deletion, CR replacement, clear,
  scroll, and full repaint;
- wrap/reflow reconciliation at several widths;
- conservative changed-suffix labeling;
- candidate/help row extraction with columns and descriptions;
- count/truncation and character/row caps;
- fallback token labels for spaces, single/double quotes, backslashes,
  variables, Unicode, punctuation, slashes, pipes, redirections, parentheses,
  ampersands, and semicolons;
- style signature normalization for every SGR category and anonymous plist;
- likely-focus scoring, including static inverse headers and multiple matches;
- quiescence/generation transitions, cancellation, deduplication, and rate
  budgets;
- progress value/threshold handling;
- privacy clearing and redaction.

Use table-driven tests and property-style generation where practical.  Feed
every byte/string input split at every boundary to state machines.

** Layer 2: ERT with real terminal model and mocked presentation

Create ~eat-term-make~ in a temporary buffer, feed
~eat-term-process-output~, call redisplay/update as production does, and capture
~emacsvox-aural-submit~, compatibility icons, line/char helpers, and ~ding~.
Cover:

- empty terminal/cursor and reset;
- cursor at beginning/end and invisible cursor;
- single/multiline output and prompt redraw;
- cursor-only and style-only changes;
- all SGR attributes and combinations;
- resize-only update and terminal-width reflow;
- alternate screen enter/exit;
- title, CWD, bell, and OSC 52 policy;
- completion snapshot lifecycle through arbitrary updates;
- normal/Eshell hook parity without duplicated generic Eshell speech;
- selected/unselected buffer, active minibuffer, two windows, two frames,
  visible-but-not-selected, scrollback review, and rapid focus changes;
- process exec/exit/restart and stale timer cancellation.

Do not mock ~eat-term-display-cursor~ in the nil/reset tests: the purpose is to
exercise the real public API state that failed.

** Layer 3: pseudo-terminal integration tests

Run a real local Bash with deterministic environment:

- fixed ~PS1~, ~TERM~, dimensions, locale, and temporary working directory;
- shell integration both absent and explicitly sourced;
- Bash completion absent/present;
- ~~/sr<Tab>~, ~git pul<Tab>~, ambiguous ~git pu<Tab><Tab>~;
- actual filenames with spaces, all quoting/escaping forms, Unicode,
  punctuation, trailing slash, and same-length candidate substitutions;
- candidates in columns and a generated large candidate set;
- commands containing pipes, redirections, parentheses, and semicolons;
- long/wrapped/multiline input;
- repeated Tab and bell ordering;
- output delivered in every arbitrary chunk split and with scheduled delays;
- resize and selection changes between chunks;
- unrelated asynchronous output during a completion;
- command exit statuses with shell prompt integration.

Test Dash as a non-readline baseline.  If Zsh or Fish is later available, add it
as a separate capability profile rather than assuming Bash semantics.  A local
SSH-like delay proxy may split fixture bytes without opening a network
connection.

** Layer 4: deterministic terminal-application fixtures

Build small local fixtures that emit known ANSI sequences and accept named key
inputs:

- router CLI with prompt, unique insertion, columns, ~?~ help descriptions,
  pagination, and delayed chunks;
- menu with cursor-following selection;
- menu with fixed invisible cursor and moving inverse/background highlight;
- multiple simultaneous highlights;
- alternate-screen editor with status line;
- pager with search and highlighted match;
- full and partial repaint at controlled frequency;
- CR progress and a status-line-only update;
- synchronized and unsynchronized output frames;
- hyperlink and image-region placeholders.

Fixtures make failures deterministic and safe.  Keep representative real-app
smoke tests for ~less~, Vim or nano, whiptail/dialog, ~top~/htop, and a REPL,
but do not make their version-specific screen layouts the sole oracle.

** Layer 5: fresh-Emacs compiled-code verification

For every ordinary Lisp change:

1. run ~make check-emacs~;
2. run ~make bytecode-check~ as non-mutating preflight;
3. run the relevant source ERT and full test target;
4. run ~make bytecode~ (or ~make bytecode-rebuild~ after macro/public-interface
   changes, branch switches, or pulls);
5. start a fresh Emacs 31+ process/profile that loads the resulting
   ~emacsvox-eat.elc~ and confirm ~locate-library~, hashes/version, hooks, and
   the representative PTY tests.

Never infer compiled correctness from source-loaded ERT or from reloading one
file into a server whose dependents are already resident.

** Layer 6: manual speech acceptance

With an isolated fresh profile and disposable sessions, a screen-reader user
should verify:

- typing/editing in all four EAT modes;
- secure password entry with a harmless no-echo fixture;
- unique/ambiguous/large completions and candidate review;
- multiline command and error output;
- Bash with and without EAT shell integration;
- local router fixture and delayed-output fixture;
- less paging/search, Vim/nano navigation/status, menu navigation, REPL,
  progress, and refreshing display;
- entering/leaving alternate screen and process exit/restart;
- selected/background/minibuffer/two-window behavior;
- every manual screen/highlight/change/candidate review command;
- terse/normal/verbose/output-off policies;
- interruption: terminal output must not erase urgent unrelated speech, while
  navigation remains responsive.

Record both semantic aural facts/transactions and the human judgment.  A TTS
submission alone is not an acceptance pass.

** Coverage gate

Before calling the redesigned integration complete, require:

- all output chunk boundaries and terminal widths produce equivalent semantic
  results after quiescence;
- resize-only and unchanged repaint produce no content announcement;
- alternate-screen, reset, and nil cursor never error;
- candidate lists remain reviewable even when automatic speech truncates;
- style-only focus changes work without treating static inverse video as focus;
- no background/minibuffer or secure-input leakage;
- no unbounded snapshot, speech text, candidate count, or refresh rate;
- fresh compiled Emacs behavior matches the source test result.

* Recommended smallest next patch

The next patch should address only F-01.

Conceptually, change the fallback to test that a character exists before using
numeric comparison or speaking it:

#+begin_src emacs-lisp
(cond
 ((eq char ?\s) (emacsvox-speak-line))
 (char (emacsvox-speak-this-char char)))
#+end_src

Using ~eq~ for a character and omitting the final unconditional branch makes an
empty terminal a quiet no-op.  The exact spelling can follow project style.
Add tests that use a real ~eat-term-make~ for:

1. selected empty terminal update: no error, no speech;
2. interactive ~eat-reset~ on an empty terminal: no error and the existing
   reset state-change announcement occurs;
3. empty alternate-screen entry/exit: no error;
4. existing nonempty line/character, completion, and background behavior
   remains unchanged.

- *Severity addressed:* High correctness/accessibility.
- *Evidence:* Reproduced (F-01).
- *Root cause:* Numeric ~=~ applied to nil at
  [[file:../../../lisp/emacsvox-eat.el::270][emacsvox-eat.el:270]].
- *Compatibility risk:* Low.
- *Why this is the smallest patch:* It removes a concrete exception without
  changing output verbosity, timing, completion classification, public APIs, or
  user configuration.  Completion and screen-diff work should follow in
  separately reviewable patches with the larger test harness.

No implementation was made during this audit.

* Audit limitations

- External SSH and real router sessions were intentionally not used.  Remote
  findings combine local delayed/router-shaped fixtures, EAT source/manual, and
  upstream remote issues; device-specific behavior remains to be validated.
- Physical speech-device output was not used as the sole oracle.  Programmatic
  call/transaction capture establishes what Emacsvox requested, not what a
  particular synthesizer/device ultimately rendered.
- Only software available in the environment was exercised: Bash, Dash, less,
  top, Vim, whiptail, and Python.  Nano was not needed because the requirement
  allowed Vim or nano; htop and other shells were not available.
- EAT 0.9.4 is the loaded target.  Current master was inspected for relevant
  changes and update-hook call sites but was not substituted into the live
  configuration.
- Several focus/window results are explicitly labelled inferred because
  headless/daemon frame focus cannot faithfully reproduce every graphical
  desktop arrangement.
