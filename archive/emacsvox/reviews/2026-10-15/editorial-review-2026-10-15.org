* Cross-chapter decisions and corrections

** Primary interface and remaining Home dependencies

=C-e H= is the general settings menu. =C-e S= opens a focused integration menu
where available, otherwise general buffer settings. =C-e H .= always selects
general buffer settings. Direct reading keys remain valid shortcuts rather
than a second configuration system.

The updated walkthroughs prefer implemented menu routes: =v b= for engines,
=v p= for palettes, =o p= for sound packs, =p p= for profiles, =f c= for guided
feedback changes, =f v= for voice remapping, =f t= for shared named-voice tuning,
=f h= for recent feedback, =r o= for combined rules, and =r f= for options.
These suffixes follow =C-e H=.

Home is not claimed to be retired. Action search, the retained-editor chooser
at =C-e H p d=, and certain editor/source-return paths still use it. Keeping
those routes is deliberate. The current UI plan still requires listening
acceptance and further implementation before removal.

Keys are local to the interface. Menu =q=, editor =q=, terminal input, and a
third-party Transient application's quit commands cannot be treated as one
universal action. A walkthrough must finish the current child view before
starting another menu from the intended source.

** Scope, persistence, and observed effects

Current-buffer state, live global defaults, and saved startup settings are
separate. Some global commands update the source buffer while preserving other
local overrides; each control's actual semantics remain authoritative.

Preview does not save. Retaining a draft keeps it only in the Emacs session.
Save records data; Apply may be a separate live action or require a confirmed
worker restart. Saved data is not proof that both speech workers acknowledged
it. Discarding an unsaved draft does not undo an earlier save.

Presentation Profiles refer to resources rather than copying them. Applying
one also saves its selection for future sessions, unlike session-only palette
activation. Profiles do not capture speech rate, engine policy, notification
output, the rules themselves, or buffer-local state. They are not general
Emacs configuration profiles or full backups.

Menu Save actions retain only their documented values: five output volumes,
four focused EAT preferences, or Notmuch's four limits and completion policy,
for example. Linked Customize or host editors have independent Save/Apply
operations. No single settings-menu Save covers all Emacsvox data.

** Application-specific differences

Shared Markdown/Org table reading presents whole rows on vertical table
movement. Agent Shell's Control-Meta vertical movement instead presents the
destination cell; plain vertical arrows present its row. Similar keys do not
guarantee identical spoken units.

EAT requires foreground selection, keyboard focus where available, and live-
cursor eligibility for automatic foreground output. Its background monitoring
is independently enabled and content-free. Shell/comint background reading
requires autospeak and can read output. Term's automatic speech instead depends
on its buffer being displayed. EAT frozen review is immutable; Term's review
pointer works with its live buffer.

Notmuch explicit refresh uses interruptible main speech rather than the
normal separate notification path of a new asynchronous search. Automatic mail
limits do not constrain explicit full-detail inspection. Tree's availability
of focused settings does not add unimplemented Tree navigation or formatting.

** Backend ownership

The contradictory automatic-restart promise in installed-release management
was removed. The explicit release view retains current speech and changes its
reported target's files, as required by
[[file:../../../../docs/adr/0021-current-engine-details-and-explicit-release-management.org][ADR 0021]]. Library Apply and /Restart local speech/ remain distinct,
explicit operations. A locked engine helper can still prevent file removal.

The blanket statement that RHVoice voices are never downloaded was narrowed.
The compatible local catalogue supports reviewed voice/language packages,
while the RHVoice runtime and external installations remain independently
supplied, as described by [[file:../../../../docs/adr/0023-managed-rhvoice-voices.org][ADR 0023]]. This is not permission to acquire
proprietary runtimes or arbitrary upstream models.

The preference chooser =C-e d e= is no longer described as a read-only engine
inventory. The inventory instructions use =C-e H v b= instead.

* Acceptance before publication

Use a checkout with the project's configured Emacs/toolchain and preserve any
uncommitted work. Inspect the branch and diff first. Follow =AGENTS.md= for
required compilation/preflight before a gate that consumes byte-code.

For the settled prose, run the existing authoring workflow:

#+begin_example
make docs-org-preview
make docs-update
make docs-release-check
#+end_example

Commit the generated artifacts with the validated source. Do not hand-edit
Info/Texinfo to remove errors. Inspect cross-manual links, fuzzy heading links,
the named remote-workstation anchor, all prior named nodes, and table/keyboard
formatting. A heading or anchor failure must be fixed in Org and regenerated.

Perform at least these representative live tasks before claiming acceptance:

1. Start from an ordinary buffer, browse an installed voice through the new
   menus, cancel a preview, and return to the source without saving.
2. Change one temporary heading rule, compare it, verify matching scope, and
   undo it. Test changed/killed source handling and editor-return paths.
3. Save a voice without selecting, then apply it, then choose startup separately.
   Retain/discard a draft and confirm the completed save is not undone.
4. Compare global defaults and buffer overrides, including Notmuch's limited
   Save, EAT's independent background monitoring, and Term's mode escapes.
5. Inspect a release target without stopping current speech; test package
   activation separately in a controlled session with recovery available.
6. Navigate the assembled Info manual using headings, menus, cross-references,
   indexes, and return actions, and listen to the revised learning sequence.

Website publication and release tagging remain separate explicitly authorised
operations. This review neither performs nor authorises them.
