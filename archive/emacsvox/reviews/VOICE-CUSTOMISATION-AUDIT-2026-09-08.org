There is no automatic rewrite of already bound voice options in a live Emacs:
those values cannot reliably be distinguished from explicit personal choices.
Restart after updating to load the new defaults. Personal assignments remain

* Original findings

The early-evaluation mismatch is widespread. In the audited working tree,
107 references across 30 Lisp files evaluate built-in voice variables before
palette resolution: 93 text-formatting sites, 12 cached defaults, and two
calls to the low-level voice-speaking function. Of these, 29 evaluate
voice-bolden specifically. This excludes the already corrected nonincremental
search advice, which now retains the symbol 'voice-bolden.

These are source-level occurrences, not 107 independently reproduced audible
failures. Some belong to optional or retained integrations. Actual output
also depends on Voice Lock, semantic rules, the active palette, and adapter
capabilities. Four isolated behavioural probes confirm the underlying
mechanisms; integrations were not all activated or tested with audio.

The initial audit changed no production code or live Emacs settings.
The resolution above records the subsequent implementation.

* What users can and cannot customise

Palette selections such as the bolden entry in the Aural Voice Workbench
are bypassed at these sites. The statement that users cannot customise
voices at all would be too broad:

- Legacy voice-bolden-settings customisation still updates the voice-bolden
  variable through the defvoice setter. A later direct evaluation of that
  variable can therefore use the new legacy preset.
- A separate variable initialised with (defvar option voice-bolden) captures
  the preset at initialisation. Later changes to voice-bolden do not update
  that copy. Text already given the generated personality has the same issue.
- Quoted face-to-voice mappings retain names and can use customised palette
  entries through the native planner. They do not have this early-evaluation
  defect, although other presentation policy can legitimately override them.
- Deliberate explicit ACSS styles and physical voice samples are a separate
  use case; they should not automatically be converted to named palette roles.

* Root cause and evidence

In [[file:lisp/voice-setup.el::(defmacro defvoice][defvoice]], a variable such as
voice-bolden holds a generated ACSS symbol. Its custom setter replaces that
value when the legacy settings change. The default bolden value is
acss-a4-s6.

#+begin_src emacs-lisp
;; Loses the named role before the planner sees it:
(propertize "hit" 'personality voice-bolden)
;; Preserves the role so the active palette can resolve it:
(propertize "hit" 'personality 'voice-bolden)
#+end_src

[[file:lisp/emacsvox-aural-compiler.el::(defun emacsvox-aural--palette-voice-definition][Palette resolution]]
recognises voice-bolden as the legacy alias for the portable bolden entry.
It does not reconstruct bolden from acss-a4-s6. That reverse inference would
be unreliable: multiple named voices may share an identical generated style.

This loss can also affect named routing preferences. The native transport
uses the compiled request as its logical voice identity; an ACSS request and
a named bolden request are different identities. See
[[file:lisp/emacsvox-aural-transport.el::(defun emacsvox-aural--timeline-logical-voice][timeline logical voice selection]].

* Priority findings

** Search and completion feedback

[[file:lisp/emacsvox-advice.el::(defun emacsvox--advice-isearch-search-after][Isearch]]
still has five early evaluations: match speech, the shortened search string,
the match following deletion, yanked text, and history-item speech.
The isolated isearch probe confirms that its matched text still carries the
generated ACSS symbol. Existing tests had asserted that same value, so they
accepted the mismatch.

[[file:lisp/emacsvox-corfu.el::(defun emacsvox-corfu--candidate-with-annotation][Corfu]]
has ten occurrences, including candidates, annotations, completion counts,
expansion feedback, and completed text. Its --voice helper copies the
supplied personality into text without preserving or recovering the name.
Helm update feedback has another occurrence.

** Common speech and editing feedback

emacsvox-speak.el has 22 occurrences, including its paragraph default,
mode/header-line summaries, line numbers, spelling, mark/kill context,
window descriptions, and selective-display feedback.

Other examples include spelling suggestions (ispell), widget selections,
RefTeX highlighting, package summaries, colour descriptions, error feedback,
and buffer summaries for Dired, Org, Notmuch, Magit, Python and Transient.
Magit alone has 12 occurrences, chiefly annotate and summary voices.

** Cached defaults

Twelve defvar initialisers copy generated presets in Calendar, Eterm, EUDC,
Forms, Hide, paragraph speech, and Speedbar. These can miss both palette
selection and subsequent legacy-setting changes. Fixing a default in source
will not automatically replace an already bound value in a live Emacs.
Any migration needs to preserve explicit user choices.

** Low-level speech bypass

[[file:lisp/tts-speak.el::(defun tts-speak-using-voice][tts-speak-using-voice]]
resolves a bound symbol directly to its value and queues backend voice codes,
without the native palette compiler. Therefore merely quoting its argument
is insufficient. Direct application callers are Calendar marked-date speech,
CPerl indentation, and etable indentation. The last two are included in the
107 occurrences; Calendar reaches this path through its cached default.
The legacy fallback branch of tts-audio-format also calls this helper;
prepared native text takes the concrete-plan branch instead.

** Additional sites outside the 107 direct references

[[file:lisp/emacsvox-extras.el::(defun emacsvox-wizards-show-voices][The legacy named-voice sampler]]
uses (symbol-value v) in two text properties. Thus it demonstrates legacy
preset values rather than current named palette voices. Its desired role
needs to be made explicit before changing it: its current text also displays
the generated preset name.

[[file:lisp/emacsvox-preamble.el::(defun emacsvox-get-revision][Revision speech]]
uses the literal acss-s4-r6. It cannot follow a named role's palette override.
This is a related hard-coded style, not an early-evaluated voice variable;
the intended semantic role must be decided rather than guessed.

* Repair approach

1. Preserve built-in personality names at text-emission sites, beginning
   with search, completion, core speech, and widget feedback. Test final
   prepared voice requests against a deliberately distinct custom palette.
2. Handle the 12 cached defaults separately. Preserve user-assigned values,
   and provide a deliberate strategy for already running sessions.
3. Migrate the three direct low-level application callers to native
   presentation, or design a compatible low-level change after checking
   transaction and adapter requirements. A blanket quote replacement does
   not address this path.
4. Decide whether the old named-voice sampler should show legacy presets or
   active palette voices. Keep explicit ACSS experiment samplers intentional.
5. Add an audit check for newly introduced early evaluations and cover
   legacy settings, palette overrides, routing identity, and Voice Lock.
   Do not try to globally reverse-map arbitrary ACSS symbols to named roles.

This was the proposed repair sequence. All repository ADRs were read before
the subsequent implementation; see Resolution for the completed changes.
